# VECTOR Basic API pointer extension tests

Scope: **85 API names / 256 workbook signatures / 20 headers**. `scope.json` contains the workbook signatures and rows; `signature_matrix.csv` records the selected call forms, dtypes, shapes and architecture applicability. Its source/log references describe the archived validation run; the logs and generated project copies are delivered separately, not tracked in this code branch.

## Requirements

Device tests target Ascend 950PR / dav-3510. Acceptance validation of commit `a3313b6ead63f3e8ad4ad2b9e6187c452a2ca375` used CANN 9.2.0-beta.2; earlier development runs used CANN 9.1. Source the installed CANN `set_env.sh` so `ASCEND_HOME_PATH`, `bisheng` and the runtime libraries are available. Official samples also require CMake and Python 3 with NumPy. The optional CPU mock test requires g++ with C++17. Run all commands from the repository root.

The integration branch incorporates upstream commit `d378849769f9ee610af9d0ac38db2b3b6bed3209`. Its scope-preservation and host-adapter checks were rerun locally; the archived device results apply to the acceptance commit above, not to a fresh NPU run of this integration branch.

## Scope and host checks

```sh
python3 tests/api/basic_api/vector_pointer/check_scope.py
python3 tests/api/basic_api/vector_pointer/test_host_adapters.py --compiler g++
```

The scope check reads integration baseline commit `d378849769f9ee610af9d0ac38db2b3b6bed3209` from Git (fetch history if using a shallow checkout). An exported baseline may instead be supplied with `VECTOR_BASELINE_ROOT`. It checks preserved Tensor declarations/bodies without requiring archived logs or writing coverage results. The host test extracts adapters into a temporary mock Tensor/CPU backend; it never modifies production headers and does not replace NPU validation.

## Compile and device tests

```sh
bash tests/api/basic_api/vector_pointer/run_target_headers.sh /tmp/vector-headers
bash tests/api/basic_api/vector_pointer/run_target_negative.sh /tmp/vector-negative
bash tests/api/basic_api/vector_pointer/run_target_regressions.sh /tmp/vector-runtime
bash tests/api/basic_api/vector_pointer/run_cpu_address.sh /tmp/vector-cpu
python3 tests/api/basic_api/vector_pointer/run_signature_extensions.py --output /tmp/vector-signatures
python3 tests/api/basic_api/vector_pointer/run_precision_regressions.py --output /tmp/vector-precision
```

These scripts include the compilation commands and produce build/run logs in the chosen output directories. The eight runtime programs are under `examples/01_simd_cpp_api/03_basic_api/01_memory_vector_compute/element_wise_arithmetic/`. Additional signature and precision programs are generated by the corresponding runners before compilation. Device 0 must be available.

| Test group | Purpose |
| --- | --- |
| Header fixtures | Compile the target interfaces and verify the compiler uses the modified headers |
| Negative operands | One valid control; reject const output, wrong address space and inconsistent element types |
| Runtime suites | Arithmetic, conversion, comparison, indexing, layout, sorting, transpose and special interfaces; Tensor/pointer permutations |
| CPU_DEBUG address | GetAbsAddr member/free forms in UB/L1 at multiple offsets |
| Signature extensions | Explicit element types, shift counts, comparison masks and Select level-0 forms |
| Precision instrumentation | Per-case parameters, mixed-tolerance match ratio, maximum error and exact-type checks; see precision_metrics.h |

The matrix covers representative valid configurations: 236 active device entries, 2 CPU_DEBUG entries and 18 inactive legacy-architecture entries. It does not claim exhaustive dtype/configuration coverage. Use legal domains for logarithm/division and legal block sizes for sorting, transpose and interleave. Performance tests: no additional task metric; no performance benchmark claim.

## Official sample comparison

For integration testing, prepare an unmodified checkout at baseline commit `d378849769f9ee610af9d0ac38db2b3b6bed3209`, then run (the archived acceptance comparison used `639b2b5c1031188107d23d785d52b935f1b4f13b`):

```sh
python3 tests/api/basic_api/vector_pointer/run_official_samples.py --root . --baseline /path/to/baseline --output /tmp/vector-official
python3 tests/api/basic_api/vector_pointer/finalize_official_samples.py --output /tmp/vector-official
```

The runners compare baseline Tensor, modified Tensor and pointer variants with original CMake/data/verification scripts. Common CANN 9.1 harness adjustments use explicit Basic API includes, initialize TPipe when required and omit optional device printf. Input/output hashes establish identical data. The reduce sample's explicit verification messages are checked because its exit code alone is insufficient. See each scenario's result and logs; additional out-of-scope scenarios are not counted as in-scope passes.
