# 系统缓存概述<a name="ZH-CN_TOPIC_0000002594407823"></a>

## Cache类型<a name="zh-cn_topic_0000002583420201_section112105011415"></a>

Cache（缓存）的主要作用是在搬运单元与外部存储之间提供一层高速缓冲，以降低数据访问延迟并提高带宽利用率。通常情况下，被频繁访问的数据会写入 Cache，搬运单元在执行过程中优先从 Cache 中读取数据；当 Cache 未命中时，再从外部存储加载数据并更新到 Cache 中。产品中包含三种不同类型的Cache：L2 Cache、DCache 和 ICache。表1详细阐述了这三类 Cache 的具体功能。

**表 1**

| Cache 类型 | 说明 |
|------------|------|
| L2 Cache | L2 Cache 作为二级缓存，专门用于存储频繁访问的数据，以便减少对GM的读写。<br>&bull; 通过MTE2单元读取GM时，优先从L2 Cache 中读取数据；当L2 Cache 未命中时，再从GM加载数据并更新到L2 Cache 中。<br>&bull; 通过Scalar单元读取GM时，优先从DCache 中读取数据；当DCache 未命中时，再从L2 Cache 中读取数据。当L2 Cache 也未命中时，再从GM加载数据并更新到L2 Cache和DCache中。 |
| DCache | DCache（Data Cache）用于缓存Scalar计算单元近期可能被重复访问的数据段。<br>通过Scalar单元读取GM时，优先从DCache 中读取数据；当DCache 未命中时，再从L2 Cache 中读取数据。当L2 Cache 也未命中时，再从GM加载数据并更新到L2 Cache和DCache中。 |
| ICache | ICache（Instruction Cache）用于缓存最近或频繁使用的指令。<br>通过Scalar单元读取GM指令时，优先从ICache 中读取指令；当ICache 未命中时，再从L2 Cache 中读取指令。当L2 Cache 也未命中时，再从GM加载指令并更新到L2 Cache和ICache中。 |

## Cache 容量与 Cache Line 大小<a name="zh-cn_topic_0000002583420201_section2339145717205"></a>

Cache Line（缓存行）是缓存的最小操作单元。访问内存时，会将相邻数据作为一个Cache Line加载到缓存中，利用空间局部性提升访问效率。Cache Line 大小决定了Cache中地址的对齐要求，若数据跨两个Cache Line，会触发多次缓存访问。

## Cache 操作及使用场景<a name="zh-cn_topic_0000002583420201_section054554323117"></a>

以下表格详细介绍了缓存的四种基础操作及其核心功能。

**表 3**

| 操作名称 | 功能说明 |
|---------|---------|
| Prefetch | 将预期访问的数据预先加载到缓存，提升后续访问速度。 |
| Preload | 主动预加载数据到缓存，为即将到来的读写操作做准备 |
| Invalid | &bull; 将指定地址范围的Cache Line从缓存中移除，标记为"无效"。<br>&bull; 保证下一次访问这些内存地址时，会从GM重新加载数据，而不是使用可能过期的缓存数据。 |
| Clean | 将缓存中被修改过的数据（脏数据，Dirty Data）写回到GM中，避免数据丢失。 |

## Cache 写策略与Cache一致性问题<a name="zh-cn_topic_0000002583420201_section053731716357"></a>

当向GM写入数据，并且使能Cache时，存在以下两种Cache写策略：延迟写回（Write-Back）和直写（Write-Through）。

当向GM写数据时采取延迟回写策略，工作原理如下：

- 开发者预期向GM写入数据，硬件实际行为是：
    - 当数据被修改时，只在缓存中更新数据。
    - 缓存中的数据标记为"脏"（dirty），表示该数据已被修改但尚未写回到GM。
    - 当该Cache Line被替换时数据才会真正写回GM，Cache Line何时被替换由硬件决定。

- 替换Cache Line数据时：
    - 当缓存空间不足需要替换数据时，检查被替换的数据是否为"脏"。
    - 如果是"脏"数据，先将其写回到GM，然后再将该Cache Line替换出缓存。

当向 GM 写入数据时，若采用直写（Write-Through） 策略，其工作原理如下：

- 开发者预期向GM写入数据，硬件实际行为是：
    - 当数据被修改时，立即在缓存和GM中更新数据。
    - 缓存行无需标记为"脏"。

- 替换Cache Line数据时：

    由于每次写数据都同步更新 GM，因此缓存中的数据不存在"脏"状态，也无需在替换时额外写回GM。

由于数据并没有及时更新到GM，因此延迟回写策略会可能导致不同核中缓存的数据不一致的问题。
Cache一致性是多核中确保数据正确性的核心机制。简单来说，当多个核各自拥有独立的Cache时，它们可能同时缓存相同的数据。如果某个核修改了缓存中的数据，其他核的缓存副本就会变得"过时"，如果不及时同步，就会导致多个核间的数据不一致，进而引发计算错误。
