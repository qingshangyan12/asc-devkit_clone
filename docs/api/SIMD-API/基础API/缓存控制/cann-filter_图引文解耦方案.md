# cann-filter 图引文解耦方案

好的，让我总结一下你的问题：

## 问题总结
1. 三种 Cache（L2 Cache、DCache、ICache）是所有产品版本（A2、A3、950 等）都支持的 ，因此这部分内容（表 1 的 Cache 类型说明） 不应该加 cann-filter 标签过滤 ，所有标签的用户都应该看到。
2. 图 1 是 A2/A3 产品特有的架构示意图 ，并不适用于所有版本（比如 950PR/950DT 没有对应的图），所以图 1 必须加 cann-filter 标签，只对 A2/A3 用户展示。
3. 但你的文档里是用图 1 来引出三种 Cache 的——文中有 "结合图1所示的硬件架构"、"如图1所示" 这样的描述， 文本和图之间存在依赖关系 。如果图 1 被标签过滤掉了（比如 950 用户看不到图 1），那么文字引用就会断裂，读者看到 "如图1所示" 却找不到图，体验很差。
4. 你的核心诉求是： 如何在不依赖特定产品架构图的前提下，丝滑地引出所有产品都通用的三种 Cache 概念，同时又能保留 A2/A3 架构图作为辅助说明。

## 问题场景

技术手册中，用户通过设置产品标签只看部分产品的内容。不设置 `cann-filter` 标签的内容为所有产品版本通用内容。

文档中有一段内容：通过一张 A2/A3 产品特有的架构图（图1）引出三种 Cache 类型（L2 Cache、DCache、ICache），文字中包含了"如图1所示"、"结合图1所示的硬件架构"等引用。

## 关键矛盾

| 内容 | 适用范围 | 应否过滤 |
|------|---------|---------|
| 图 1（A2/A3 架构图） | 仅 A2/A3 | 应加 `cann-filter` 过滤 |
| 文字"如图1所示"/"结合图1" | 引用图1 | 非A2用户看到会困惑 |
| 三种 Cache 类型说明 | 所有产品版本 | 不应过滤 |

**核心矛盾**：图1 须加 `cann-filter`，但文字引用了图1。对于非 A2/A3 用户（如 950），文字说"如图1所示"但看不到图，体验很差。

## 解决方案：分层引入

| 层级 | 内容 | 是否过滤 | 说明 |
|------|------|---------|------|
| 第1层 | Cache 通用概念介绍 | 不过滤 | 所有产品可见，不依赖图 |
| 第2层 | 图1（A2/A3 架构图） | 用 `cann-filter` 过滤 | 分别对 A3 和 910b 展示 |
| 第3层 | "产品中包含三种 Cache" + 表1 | 不过滤 | 所有产品可见 |

### 核心原则

1. **解耦文字与图的依赖**：删除 `如图1所示`、`结合图1所示的硬件架构` 等强制引用
2. **图作为可选补充素材**：图只用 `cann-filter` 标签包围，作为架构示意图的辅助说明
3. **引出三种 Cache 的文字不走标签**：不绑定任何特定产品名（如"Atlas A2/A3"），改为通用表述（如"产品中"）

## 改写示例

### 改写前

```markdown
## Cache类型

**图 1**  Atlas A2/A3硬件架构中包含的三种Cache示意图
![](figures/...拼的三种Cache示意图.png)

如图1所示，Cache(缓存)的主要作用是...
结合图1所示的硬件架构，Atlas A2/A3中包含三种不同类型的Cache：L2 Cache、DCache 和 ICache。
```

### 改写后

```markdown
## Cache类型

Cache（缓存）的主要作用是在搬运单元与外部存储之间提供一层高速缓冲...

<cann-filter npu-type="A3">

![](figures/...三种Cache示意图.png)

</cann-filter>

<cann-filter npu-type="910b">

**图 1**  Atlas A2/A3硬件架构中包含的三种Cache示意图
![](figures/...三种Cache示意图.png)

</cann-filter>

产品中包含三种不同类型的Cache：L2 Cache、DCache 和 ICache。

```

## 各产品标签下的阅读效果

| 产品标签 | 看到的内容 | 体验 |
|---------|-----------|------|
| A3 / 910b | Cache概念 → 图1（补充插图）→ 三种Cache → 表1 | 完整，有图辅助 |
| 950 / 其他 | Cache概念 → 三种Cache → 表1 | 无断裂，虽然无图但逻辑完整 |

## 适用范围

此方案适用于任何 **部分产品特有的图/素材被通用文字引用** 的场景，核心思路始终是：**图文解耦，图降级为可选补充**。
