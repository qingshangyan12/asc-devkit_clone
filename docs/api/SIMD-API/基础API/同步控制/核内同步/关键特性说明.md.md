# 自动同步<a name="ZH-CN_TOPIC_0000002555780804"></a>

- Vector计算单元
    - 单流水同步：PIPE\_V由编译器自动完成同步插入，PIPE\_MTE2/PIPE\_MTE3在搬运地址有重叠的情况下需要开发者插入同步（具体示例请参考[约束说明](../核内同步/PipeBarrier(ISASI).md)）。
    - 多流水同步：PIPE\_V、PIPE\_MTE2、PIPE\_MTE3、PIPE\_S之间的多流水同步，都是双向的，如下图所示，黄色线条表示的同步由编译器自动完成同步插入，剩余的同步由Ascend C框架完成。例外情况：使用涉及标量计算的原子操作接口（如[AtomicAdd](../../原子操作/AtomicAdd.md)）时，如果标量计算单元和搬运单元（MTE2/MTE3）在读写GM时存在数据依赖，开发者需要根据实际情况插入同步。详细内容参见具体的API说明。

        ![](../../../../figures/图1-AI-Core内部并行计算架构抽象示意图-43.png)

- Cube计算单元

    Cube侧所有流水同步都由Ascend C框架完成，不需要算子开发者插入同步。

## 约束说明<a name="zh-cn_topic_0000002521905636_section56111955113614"></a>

- AscendC框架不会自动插入单流水同步指令，在搬运地址有重叠的情况下需要开发者手动插入同步，参考[调用示例](PipeBarrier.md#zh-cn_topic_0000002549838971_section088124295117)。
- 在TPipe/TQue编程模型下，如果开发者手动插入了编译器或AscendC框架本已自动插入的同步指令，将导致同步指令被重复插入，可能导致程序逻辑异常或性能下降。
- AIC和AIV之间不支持使用[SetFlag/WaitFlag](SetFlag-WaitFlag.md#ZH-CN_TOPIC_0000002555780802)进行同步，可能会出现硬件未定义情况，参考[调用示例](https://gitcode.com/cann/asc-devkit/pull/739/diffs)。AIC和AIV之间的同步控制属于核间同步，需要调用[CrossCoreSetFlag](CrossCoreSetFlag.md#ZH-CN_TOPIC_0000002555621174)和[CrossCoreWaitFlag](CrossCoreWaitFlag.md#ZH-CN_TOPIC_0000002555780806)进行同步。
