(1)生成的图片格式是svg格式，并且生成的图片必须能够通过draw.io编辑。
（2）字体必须使用方正兰亭黑简体
（3）框的可用的背景颜色应该按照顺序从以下颜色中取用（RGB格式）：（194,212,254,）、（176,240,226），（185,233,252），（254,226,186），（223,225,230），（83,119,251），（38,196,177）。最后两种颜色对应的框中，字体为白色，其余颜色对应的框中字体为黑色。
（4）线条统一为黑色
（5）图片整体大小的约束：宽度为840px/520px/220px，可根据图形大小设置接近的宽度。高度没有限制，请根据绘图实际情况等比例缩放
（6）图片的背景颜色必须是白色，否则图片渲染后在夜间模式下会变得透明。
（7）生成的SVG文件中不得包含OpenAI API Key、访问令牌、密码等敏感信息或其他隐私内容。
（8）文本框、线条和文字之间不得相互重叠或遮挡，所有文字必须完整显示在对应区域内。
（9）布局检查必须同时计算或保守估算文字的包围盒，不能只检查矩形等图形元素。文字包围盒与非所属矩形框、线条及其他文字之间应至少保留6px间距，文字与所属矩形框边界之间应至少保留6px内边距。
（10）连线不得穿过文字或文字说明区域。连线说明优先放入对应节点框内；确需在线条旁标注时，应为说明文字预留独立空白区域，并检查文字完整包围盒与线段、箭头及相邻图形均不相交。
（11）交付前必须按SVG实际尺寸进行渲染预览，并联合检查“文字与文字、文字与框、文字与线条、框与框、线条与非目标框”五类碰撞。不得仅凭元素坐标或仅检查矩形框之间是否重叠就判定布局合格。

## 图类型选择与绘制原则

（1）绘图前必须先分析用户提供的文字描述，识别其表达重点、参与对象、执行顺序、判断分支、并发关系、状态变化、模块关系和部署关系，再选择最合适的图类型。不得先确定图类型后强行套用文字内容。

（2）必须严格依据用户提供的文字描述绘图。可以对原文进行归纳、分组和精简，但不得虚构原文未说明的参与者、步骤、调用关系、判断条件、状态迁移、同步关系或技术结论。原文存在歧义或缺少绘图所必需的信息时，应先向用户确认。

（3）根据文字描述按以下规则选择图类型：

| 图类型 | 适用的文字描述 | 主要表达内容 |
| --- | --- | --- |
| 程序流程图 | 函数或算法内部存在顺序执行、输入输出、条件判断、循环、异常处理或返回路径 | 程序或算法的具体执行步骤。程序流程图属于通用技术图，不属于UML图 |
| UML活动图 | 描述业务流程、跨函数或跨模块流程、多角色协作、并行处理或同步汇合 | 动作、判断、循环、并行、汇合和泳道责任 |
| UML时序图 | 描述多个对象、模块、线程、核或设备之间按照时间顺序发生的调用、消息和返回 | 参与者、生命线、消息方向和交互先后顺序 |
| UML状态机图 | 描述对象具有明确状态，并由事件或条件触发状态迁移 | 状态、事件、迁移条件和生命周期 |
| UML用例图 | 描述系统边界、用户角色以及角色可以使用的系统能力 | 参与者、用例和系统边界 |
| UML类图 | 描述类、数据结构、接口以及继承、关联、组合或依赖关系 | 类、属性、方法和静态关系 |
| UML对象图 | 描述某一时刻具体实例的属性值及实例之间的关系 | 对象实例及其快照关系 |
| UML组件图 | 描述软件模块、服务、库、接口以及组件依赖 | 组件划分、接口和依赖关系 |
| UML包图 | 描述大型工程的分层、命名空间、目录模块或包依赖 | 包的组织结构和依赖关系 |
| UML部署图 | 描述软件在设备、服务器、芯片、进程或运行节点上的部署关系 | 节点、制品、进程和网络连接 |
| UML组合结构图 | 描述类或组件内部的部件、端口及连接方式 | 内部结构和连接器 |
| UML通信图 | 强调对象之间的连接关系，同时需要表达带编号的消息 | 对象关系和消息协作关系 |
| UML交互概览图 | 需要总览并组织多个复杂交互或时序片段 | 交互片段之间的控制流程 |
| UML定时图 | 描述实时系统、硬件信号、状态或数值随精确时间发生的变化 | 时间约束、持续时间和信号变化 |
| UML轮廓图 | 需要为特定领域扩展UML元素和语义 | stereotype、标签值和约束 |

（4）当多种图均可表达同一段文字时，应根据主要表达目标选择：强调函数内部控制路径时使用程序流程图；强调跨模块流程或并发责任时使用UML活动图；强调调用和消息的时间顺序时使用UML时序图；强调状态及其迁移时使用UML状态机图。必要时可以组合使用两种图，但每张图应保持单一、明确的表达重点。

（5）选定图类型后，应从原始文字中提取图形元素及其关系，建立“原文描述到图形元素”的对应关系，再进行布局和绘制。图中的标题、节点名称、条件、消息、状态和注释应能够在原始文字中找到依据。
