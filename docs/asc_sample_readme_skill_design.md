# Ascend C样例README生成Skill设计文档

## 背景

Ascend C样例目录中的`README.md`用于说明样例功能、支持产品、目录结构、输入输出规格、实现流程以及编译运行步骤。当前README由不同样例作者维护，容易出现章节顺序不一致、必选内容缺失、编译运行说明不完整、性能优化样例描述粒度不统一等问题。

为降低样例文档编写和评审成本，需要设计一个资料样例skill，使Codex在生成、重写或检查样例`README.md`时，能够严格遵循统一规范，并结合样例源码推断文档内容。

## 目标

该skill用于生成、重写和审查Ascend C样例`README.md`，确保文档满足以下要求：

- 章节顺序固定，必选章节完整。
- 内容风格与仓库现有中文样例文档一致。
- 普通样例与性能优化样例使用不同的说明粒度。
- 编译运行步骤包含环境变量、build目录、cmake编译、执行、结果验证、CPU运行模式、sim运行模式和日志查看说明。
- 不编造代码中无法确认的硬件产品、输入输出规格、shape、性能数据或场景参数。
- 通过确定性校验脚本发现结构性问题。

## 非目标

该skill不负责以下事项：

- 生成或修改样例源码。
- 采集真实性能数据。
- 判断硬件产品实际支持范围，除非样例目录或已有文档已明确说明。
- 代替人工确认无法从源码和现有文档推断的信息。
- 发布GitCode issue或修改仓库议题流程。

## Skill名称与触发描述

推荐skill名称：

```yaml
---
name: asc-sample-readme
description: Generate, rewrite, or review Ascend C sample README.md files according to the standardized sample documentation template, including required section order, product support, directory tree, sample description, specification tables, compile/run steps, CPU/sim mode notes, log links, and special progressive optimization requirements for performance samples.
---
```

触发场景包括：

- 用户要求“帮我写某个样例README”。
- 用户要求“按规范改写README.md”。
- 用户要求“检查这个README是否符合样例文档规范”。
- 用户要求“为性能优化样例补充递进式Case说明”。
- 用户提供样例目录，希望自动生成目录结构、样例规格和编译运行步骤。

## 推荐目录结构

```text
asc-sample-readme
├── SKILL.md
├── references
│   ├── readme-standard.md
│   ├── performance-readme-standard.md
│   └── common-snippets.md
├── assets
│   ├── readme-template.md
│   └── performance-readme-template.md
└── scripts
    └── validate_readme.py
```

## 模块设计

### SKILL.md

`SKILL.md`只保留核心工作流和资源选择规则，避免把完整README规范全部写入主文件。Codex触发skill后，先读取`SKILL.md`，再按任务类型加载对应reference。

建议包含以下内容：

- 任务范围：生成、重写、审查Ascend C样例`README.md`。
- 输入收集流程：读取样例目录、现有README、`CMakeLists.txt`、`scripts/`、`.asc`、`.h`等文件。
- 文档模式选择：普通样例读取`readme-standard.md`，性能优化样例额外读取`performance-readme-standard.md`。
- 事实约束：不能编造无法确认的信息，必要时使用`TODO`标记。
- 校验流程：生成后运行`validate_readme.py`，并根据结果修正。

### references/readme-standard.md

存放普通样例README标准。内容应包括必选章节、章节顺序和每个章节的写作要求：

1. 名称
2. 概述
3. 支持产品
4. 目录结构介绍
5. 样例描述
6. 编译运行

其中“样例描述”至少包含：

- 样例功能
- 样例规格
- 样例实现

“编译运行”至少包含：

- 编译选项说明
- 配置环境变量
- 样例执行
- CPU运行模式说明
- sim运行模式说明
- 框架执行日志查看说明

### references/performance-readme-standard.md

存放性能优化样例特别规范。性能优化样例的“样例实现”应采用递进式说明，从基础功能实现开始，逐步引入优化手段。

每个Case必须包含：

- 优化目标
- 核心实现
- 关键代码
- 优化手段
- 性能数据
- 分析

文档末尾还应包含：

- 性能对比总结
- 调优建议

### references/common-snippets.md

存放多个README可复用的公共片段，例如：

- CANN环境变量配置说明。
- 默认路径root用户安装命令。
- 默认路径非root用户安装命令。
- 指定路径安装命令。
- CPU运行模式说明。
- sim运行模式说明。
- 框架执行日志说明。
- 常见支持产品表达方式。

### assets/readme-template.md

普通样例README模板，保留固定章节和占位符。Codex生成新README时以该模板为基础填充内容。

### assets/performance-readme-template.md

性能优化样例README模板，除普通样例章节外，还包含Case递进说明、性能对比总结和调优建议占位符。

### scripts/validate_readme.py

校验脚本用于检查结构性规则，避免依赖模型主观判断。建议支持以下检查：

- 必选章节是否存在。
- 章节顺序是否正确。
- 是否包含支持产品列表。
- 是否包含目录结构代码块。
- 是否包含样例规格表格。
- 是否包含编译选项说明。
- 是否包含环境变量配置。
- 是否包含build目录创建命令。
- 是否包含cmake命令。
- 是否包含执行程序命令。
- 是否包含结果验证说明。
- 是否包含CPU运行模式说明。
- 是否包含sim运行模式说明。
- 是否包含日志查看说明。
- 性能样例中每个Case是否包含规定字段。

脚本输出应区分错误和警告：

- 错误：缺少必选章节、章节顺序错误、缺少编译运行核心步骤。
- 警告：缺少图示、性能数据为空、存在`TODO`等需要人工确认的信息。

## 工作流

### 生成README

1. 读取目标样例目录。
2. 如果存在旧版`README.md`，先提取已有可复用信息。
3. 读取`CMakeLists.txt`，识别编译目标、可执行程序名和编译选项。
4. 读取`scripts/`，识别数据生成和结果验证命令。
5. 读取`.asc`、`.h`等实现文件，识别样例功能、输入输出、shape、数据类型、核函数名、场景参数。
6. 判断是否为性能优化样例。
7. 选择对应模板生成README。
8. 运行校验脚本。
9. 修复结构性问题。
10. 输出变更摘要和仍需人工确认的信息。

### 重写README

1. 保留旧README中可确认的样例事实。
2. 按标准章节顺序重排。
3. 删除重复、过时或与源码不一致的描述。
4. 补齐缺失的必选章节。
5. 对无法确认的信息使用`TODO`。
6. 运行校验脚本并修复问题。

### 审查README

1. 读取README和样例目录。
2. 使用校验脚本检查结构规则。
3. 人工式审查内容一致性，包括命令、shape、输入输出、支持产品和场景参数。
4. 按严重程度输出问题列表。
5. 不直接修改文件，除非用户明确要求修复。

## README标准结构

生成的普通样例README必须按以下顺序组织：

```markdown
# 样例名称

## 概述

## 支持产品

## 目录结构介绍

## 样例描述

- 样例功能
- 样例规格
- 样例实现

## 编译运行

- 编译选项说明
- 配置环境变量
- 样例执行
```

性能优化样例在“样例实现”中增加递进式Case说明：

```markdown
### Case 0: 基础功能实现

**优化目标**：

**核心实现**：

**关键代码**：

**优化手段**：

**性能数据**：

**分析**：
```

## 内容生成原则

### 样例名称

名称应简洁说明样例主题，例如：

- 归约类接口多场景示例
- Matmul最佳实践样例
- Matmul使用SplitM策略直调样例

### 概述

概述控制在1到2段，说明样例主要功能、特点、解决的问题和达成目的。涉及版本差异时，应明确写出版本边界。

### 支持产品

支持产品必须来自已有文档、源码注释、CMake配置或用户明确输入。无法确认时，不能自行补全。

推荐表达：

```markdown
- Ascend 950PR/Ascend 950DT
- Atlas A3 训练系列产品/Atlas A3 推理系列产品
- Atlas A2 训练系列产品/Atlas A2 推理系列产品
```

### 目录结构介绍

目录结构使用树状代码块，排除README文件。每个文件或目录应附带简短注释。

### 样例功能

样例功能应说明：

- 实现的具体功能。
- 对应应用场景。
- 核心计算公式或接口调用方式。
- 关键实现原理。
- 必要时添加图示或图示占位。

### 样例规格

样例规格使用表格展示，至少包含：

- 样例类型或OpType。
- 输入名称。
- 输入shape。
- 输入数据类型。
- 输入format。
- 输出名称。
- 输出shape。
- 输出数据类型。
- 输出format。
- 核函数名。

### 样例实现

普通样例应说明实现流程。可以使用编号步骤、流程图或代码架构图。

可选补充约束条件，例如：

- shape限制。
- 数据类型限制。
- 对齐要求。
- 支持运行模式。
- 硬件架构限制。

### 编译选项说明

编译选项说明使用表格，至少列出选项、可选值和说明。常见选项包括：

- `CMAKE_ASC_RUN_MODE`
- `CMAKE_ASC_ARCHITECTURES`
- 样例自定义场景参数，例如`SCENARIO_NUM`

### 配置环境变量

必须提供不同安装路径下的环境变量配置命令：

```bash
source /usr/local/Ascend/cann/set_env.sh
source $HOME/Ascend/cann/set_env.sh
source ${install_path}/cann/set_env.sh
```

### 样例执行

样例执行必须包含：

- 创建并进入`build`目录。
- `cmake`编译命令。
- `make`命令。
- 测试数据生成命令，若样例需要。
- 可执行程序执行命令。
- 结果验证命令。
- 成功输出示例。
- 多场景样例的场景参数设置方式，若样例需要。
- CPU运行模式说明。
- sim运行模式说明。
- 框架执行日志查看说明。

## 性能优化样例特别规范

性能优化样例应从基础实现到最终优化逐步展开。每个Case代表一个独立优化步骤，不应把多个优化手段混在一个Case中。

每个Case的内容要求如下：

| 字段 | 要求 |
|------|------|
| 优化目标 | 说明当前步骤解决的性能问题或引入的优化方向 |
| 核心实现 | 用条目说明具体实现方法 |
| 关键代码 | 展示10行以内核心代码片段 |
| 优化手段 | 解释优化原理，必要时添加示意图 |
| 性能数据 | 使用表格展示性能指标 |
| 分析 | 对比上一Case，说明收益、瓶颈和下一步优化方向 |

性能对比总结应覆盖：

- 总体优化效果。
- 关键指标提升。
- 端到端耗时变化。
- 计算和带宽瓶颈分析。
- 所有Case性能指标汇总表。

调优建议应总结可复用经验，例如：

1. 从小规模开始验证功能正确性。
2. 按Case顺序逐步引入优化手段。
3. 多核切分时兼顾负载均衡和地址对齐。
4. 优先使用成熟模板能力。
5. 固定shape场景可考虑常量Tiling。
6. 根据瓶颈决定是否启用UnitFlag等流水优化。

## 校验规则

### 必须通过的规则

- README存在且文件名为`README.md`。
- 一级标题存在。
- 必选二级章节完整。
- 必选二级章节顺序正确。
- 目录结构介绍中存在树状代码块。
- 样例规格存在表格。
- 编译运行存在环境变量配置和样例执行命令。
- 样例执行包含build目录创建、cmake、make、运行和验证。
- CPU和sim运行模式说明存在。
- 日志查看说明存在。

### 建议检查的规则

- 目录树未包含README文件。
- 样例规格中的输入输出与源码或脚本一致。
- 编译目标名与`CMakeLists.txt`一致。
- 数据生成和验证命令与`scripts/`一致。
- 代码片段不超过10行。
- 性能数据表字段完整。
- 文档中没有未解释的`TODO`。

## 测试策略

### 正向测试

选择现有合规README作为输入，运行校验脚本，预期通过结构检查。

推荐样例：

- 普通Matmul类库样例。
- 带`scripts/gen_data.py`和`scripts/verify_result.py`的样例。
- 性能优化样例。

### 负向测试

构造以下不合规README，确认校验脚本能报错：

- 删除“支持产品”章节。
- 调换“目录结构介绍”和“样例描述”顺序。
- 删除样例规格表。
- 删除`cmake`命令。
- 删除CPU运行模式说明。
- 性能样例中删除某个Case的“分析”字段。

### 行为测试

使用skill处理真实样例目录，验证输出README是否：

- 保持固定章节顺序。
- 使用仓库中文技术文档风格。
- 未编造无法确认的信息。
- 能指出需要人工确认的事实。
- 能通过校验脚本。

## 后续落地步骤

1. 使用`skill-creator`初始化`asc-sample-readme` skill目录。
2. 编写`SKILL.md`，保留核心流程和资源导航。
3. 编写通用README规范reference。
4. 编写性能优化样例reference。
5. 编写公共片段reference。
6. 编写普通样例和性能样例模板。
7. 实现`validate_readme.py`。
8. 使用现有README做正向和负向测试。
9. 根据测试结果收敛规范和校验规则。
