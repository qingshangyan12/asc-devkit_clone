
› 20行、102行、169行都介绍了反向同步，它们之间是有重复吗？如果没有，那么它们在逻辑上是什么关系？


• 有一定重复，但不是完全重复。三处的逻辑层级不一样：

  第 20 行附近是概念引入。
  它在“适用场景”里先告诉读者：这个问题里有两类同步，正向同步和反向同步分别是什么。这里应该写得简洁，作用是建立阅读背景。

  第 102 行附近是Mutex 原理解释。
  它承接前面的概念，重点说明反向同步在 Mutex 下为什么可以被同一个 mutexId 表达：mutexId 绑定 Buffer，Lock<当前pipe> 等待同一 mutexId 此前所有流水的 Unlock。这里可以
  比第 20 行展开更多。

  第 169 行附近是与 SetFlag/WaitFlag 的对比。
  它不是再单独介绍反向同步本身，而是说明如果不用 Mutex、改用 SetFlag/WaitFlag，需要显式维护 V -> MTE2、MTE3 -> V 等事件和循环边界判断，从而凸显 Mutex 的简化点。

  第20行：反向同步是什么
  第102行：Mutex 怎么表达反向同步
  第169行：SetFlag/WaitFlag 表达反向同步为什么更复杂

  现在的问题是第 102 行和第 169 行都重复解释了“反向同步发生在 Buffer 复用时”，第 20 行和第 102 行也都列了 PIPE_V -> PIPE_MTE2、PIPE_MTE3 -> PIPE_V。如果想更干净，可
  以压缩第 102 行，把它改成“基于上述反向依赖，Mutex 的处理方式如下”，避免重新定义一遍。
