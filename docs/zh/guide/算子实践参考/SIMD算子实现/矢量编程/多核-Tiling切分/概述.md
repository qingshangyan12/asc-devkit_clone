# 概述<a name="ZH-CN_TOPIC_0000002500468232"></a>

Ascend C核函数是在Device侧执行的并行函数，上述介绍的[基础矢量算子](../基础矢量算子.md)与[TBuf的使用](../TBuf的使用.md)样例均为在单核上运行的算子，不涉及Host侧Tiling实现。矢量算子实现的组成如下图所示。

为了提高算子的执行效率，通常在算子中实现多核并行计算，即对输入数据进行切分，并将不同的数据块分配到不同的核上处理。此外，由于单个核上内部存储Local Memory大小有限，存在无法一次完整地容纳算子的输入和输出数据的场景，因此需要每次搬运一部分输入进行计算然后搬出，再搬运下一部分输入进行计算，直到获得最终的完整结果，这个数据切分、分块计算的过程称之为**Tiling**。切分数据的算法称为Tiling算法或者Tiling策略。根据算子的shape等信息来确定数据切分算法相关参数（比如每次搬运的块大小，以及总共循环多少次）的计算程序，称之为**Tiling实现**，也叫Tiling函数（Tiling Function）。由于Tiling实现中完成的均为标量计算，AI Core并不擅长，所以我们将其独立出来放在Host侧CPU上执行。核函数内部通过解析Host侧传入的Tiling结构体获取Tiling信息，根据Tiling信息控制数据搬入、搬出Local Memory的流程；通过调用计算、数据搬运、内存管理、任务同步API，实现算子逻辑。

由于硬件限制，在对输入数据进行数据切分时应遵循以下几个原则：

1. 由于AI Core中Unified Buffer上的物理限制，要求Unified Buffer上数据搬运和矢量计算过程需要32字节对齐。
    - 输入数据不满足32字节对齐时，需要取输入数据长度向上对齐到32字节的长度作为输入数据总长度。
    - 进行Tiling有关计算时，以32字节为最小单位进行计算。

2. 尽可能最大利用Unified Buffer空间。

    AI Core与外部存储交互时会产生性能开销，频繁的进行数据搬运会导致性能瓶颈，因此应尽可能充分利用Unified Buffer空间，减少从Global Memory上搬运数据的次数。

3. AI处理器包含多个AI Core，应该充分均衡利用多核计算能力，将计算均衡分配到多个AI Core上。

本章基于[矢量计算多核Tiling切分策略样例](../../../../../../examples/01_simd_cpp_api/02_features/02_tiling_selector/vector_tiling_strategy/README.md)，以两个一维Tensor相加的Add矢量算子为例，对多核Tiling切分的典型场景进行说明。样例实现文件为[vector_tiling_strategy.asc](../../../../../../examples/01_simd_cpp_api/02_features/02_tiling_selector/vector_tiling_strategy/vector_tiling_strategy.asc)。

数据切分示意如上图所示，将长度为`totalLength`的算子输入分配到多个AI Core上进行计算。Host侧Tiling先将输入数据量按DataBlock对齐，再按主块长度`MAIN_TILE_LENGTH`在各AI Core上分配相同数量的主块，随后把剩余DataBlock尽量均衡地分配到各AI Core。各AI Core处理的数据长度可能相同，也可能分为整核数据长度`formerLength`和尾核数据长度`tailLength`两类。对于单个AI Core的计算数据，核内先处理若干个长度为`MAIN_TILE_LENGTH`的主块；如果最后剩余的数据长度不足一个主块，则通过`lastTileLength`记录尾块长度。

本章涉及如下概念：

- 主块：基于Local Memory可用空间确定的单个AI Core一次处理的最大数据块。主块长度使用`MAIN_TILE_LENGTH`表示。
- 尾块：单个AI Core内最后一个长度小于`MAIN_TILE_LENGTH`的数据块。尾块长度使用`lastTileLength`表示。
- 整核：核间数据无法完全均分时，处理数据量较多的AI Core。
- 尾核：核间数据无法完全均分时，处理数据量较少的AI Core。

根据数据切分的情况，有如下几种场景：

1.  主块均分：输入数据可以按参与计算的AI Core数量和主块长度均匀切分。完成主块分配后没有剩余数据，各AI Core处理的数据量相同，且核内只包含主块。该场景对应[主块均分](主块均分.md)。
2.  主块-尾块：完成主块分配后仍有剩余数据，但剩余数据可以按DataBlock粒度均匀分配到每个AI Core。各AI Core处理的数据量相同，核内除主块外还存在等长尾块。该场景对应[主块-尾块](主块-尾块.md)。
3.  主块-尾核：完成主块分配后剩余数据较少，无法继续均匀分配到每个AI Core，只能按DataBlock粒度分配给部分AI Core。获得额外DataBlock的AI Core为整核，其余为尾核；尾核内只包含主块。该场景对应[主块-尾核](主块-尾核.md)。
4.  尾块-尾核：完成主块分配后剩余数据较多，各AI Core都可以继续分配到若干DataBlock，但仍有少量DataBlock只能分配给部分AI Core。此时既存在处理数据量更多的整核，尾核也需要处理尾块。该场景对应[尾块-尾核](尾块-尾核.md)。
