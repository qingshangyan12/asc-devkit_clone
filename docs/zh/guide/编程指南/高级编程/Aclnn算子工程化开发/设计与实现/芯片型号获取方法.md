# 芯片型号获取方法

aclnn算子工程中会出现完整SoC型号、Short SoC型号、工程编译单元和NPU架构等名称。它们描述的层级不同，不能混用，本文主要说明各字段的获取方法。

## 1. 获取完整 SoC 型号

在安装AI处理器的服务器上查询完整`SoC_version`。不同产品系列的查询命令和取值方式如下。

| 产品系列 | 查询命令 | 完整`SoC_version`的组成方式 |
|---|---|---|
| Atlas A2训练系列、Atlas A2推理系列、Atlas 200I/500 A2推理产品、Atlas推理系列、Atlas训练系列 | `npu-smi info` | 读取`Name`，按`Ascend{Name}`组成，例如`Name`为`910B4`时得到`Ascend910B4` |
| Atlas A3训练系列、Atlas A3推理系列 | `npu-smi info -t board -i <id> -c <chip_id>` | 读取`Chip Name`和`NPU Name`，按`{Chip Name}_{NPU Name}`组成 |
| Ascend 950PR、Ascend 950DT | `npu-smi info -t board -i <id>` | 读取`Chip Name`和`NPU Name`，按`{Chip Name}_{NPU Name}`组成 |

其中：

- `id`是设备ID，通过`npu-smi info -l`查询。
- `chip_id`是芯片ID，通过`npu-smi info -m`查询。

例如，`Chip Name`为`Ascend950PR`、`NPU Name`为`9599`时，完整SoC型号为`Ascend950PR_9599`。

## 2. 获取 Short SoC 和工程编译单元

`Short_SoC_version`记录在当前CANN安装包的平台配置文件中。根据系统架构打开对应目录下的`<SoC_version>.ini`文件：

| 系统架构 | 平台配置文件路径 |
|---|---|
| ARM | `${ASCEND_HOME_PATH}/aarch64-linux/data/platform_config/<SoC_version>.ini` |
| x86 | `${ASCEND_HOME_PATH}/x86_64-linux/data/platform_config/<SoC_version>.ini` |

文件名使用完整`SoC_version`。例如Ascend 910B4对应`Ascend910B4.ini`。打开文件后，在`[version]`节查看`Short_SoC_version`：

```ini
[version]
SoC_version=Ascend910B4
Short_SoC_version=Ascend910B
```

aclnn工程配置使用`Short_SoC_version`的全小写形式。以`Ascend910B`为例，工程配置值为`ascend910b`，使用位置如下：

| 使用位置 | 作用 | 示例 |
|---|---|---|
| `ASCEND_COMPUTE_UNIT` | 指定算子工程需要编译的芯片系列 | `set(ASCEND_COMPUTE_UNIT ascend910b)` |
| `AICore().AddConfig()` | 在算子原型中声明支持的芯片系列 | `this->AICore().AddConfig("ascend910b");` |
| CMake接口的`COMPUTE_UNIT`参数 | 指定Kernel源码或编译选项生效的芯片系列 | `COMPUTE_UNIT ascend910b` |

完整`SoC_version`和`Short_SoC_version`不能混用。例如`ASCEND_COMPUTE_UNIT`和`AddConfig`中不填写`Ascend910B4`或`Ascend910B`。

## 3. 查询 NPU Arch

`__NPU_ARCH__`是Device侧AI Core代码中的预处理宏，用于标识NPU架构版本。产品型号和NPU架构版本的对应关系可查看[__NPU_ARCH__](../../../语言扩展层/SIMD-BuiltIn关键字.md#table65291052154114)。

普通Kernel不需要手工定义`__NPU_ARCH__`。构建工具会根据目标芯片选择编译架构，并由编译器提供该宏；只有Kernel确实需要按架构选择不同实现时才读取它。

## 4. 常见型号对照

以下值取自对应CANN平台配置文件：

| 完整`SoC_version` | `Short_SoC_version` | 工程编译单元 | `NpuArch` |
|---|---|---|---|
| `Ascend910B4` | `Ascend910B` | `ascend910b` | `2201` |
| `Ascend310P3` | `Ascend310P` | `ascend310p` | `2002` |
| `Ascend950PR_9599` | `Ascend950` | `ascend950` | `3510` |

平台字段可能随新增芯片型号扩展。开发者应读取当前CANN安装包中的配置文件，不应把本表作为完整支持列表。

## 5. 使用约束

1. 芯片型号和工程配置值区分大小写，应按对应使用位置填写。
2. `SoC_version`描述具体型号，工程编译单元描述可复用二进制的芯片系列，二者不能混用。
3. 多设备服务器上可能存在不同型号的设备，需要针对实际运行设备获取`SoC_version`。
4. 交叉编译时应查询目标设备型号，不能使用编译服务器本机的设备型号。
5. Short SoC应从目标CANN软件包的平台配置文件获取，NPU Arch应按对应关系查询。
6. 普通Kernel不需要使用`__NPU_ARCH__`；只有确实存在架构差异且公共API无法屏蔽时才增加条件编译。
