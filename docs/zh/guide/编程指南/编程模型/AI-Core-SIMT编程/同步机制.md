# 同步机制<a name="ZH-CN_TOPIC_0000002554691683"></a>

SIMT是一种单指令多线程的programming_model，该programming_model旨在通过多线程并发执行达到隐藏访存延迟，提升计算吞吐量的目的。SIMTprogramming_model中，一个Thread Block内的多个Thread并行执行，不同Thread的执行进度和内存访问到达顺序可能不同。当线程之间存在数据依赖时，需要使用sync_interface或memory_fence约束执行顺序和内存可见性，避免读到未完成写入的数据。sync_interface主要分为两类：

- **同步屏障（barrier）**：要求同一作用范围内的线程都到达指定位置后，程序才能继续执行。
- **内存栅栏（memory fence）**：约束调用线程在栅栏前后的内存访问顺序，使栅栏前的内存操作按指定范围对其他线程可见。内存栅栏不会等待其他线程到达同一位置。

## 接口overview

| 类型 | 代表接口 | 典型用途 |
| --- | --- | --- |
| 同步屏障 | `asc_syncthreads` | Thread Block内阶段同步，例如先写Unified Buffer，再统一读取。 |
| 内存栅栏 | `asc_threadfence_block`、`asc_threadfence` | 发布数据或标志前，约束当前Thread的内存访问顺序和可见性。 |

sync_interface和memory_fence的详细语义、作用范围、使用示例及注意事项，请参见[sync_and_memory_fence_intro](../../../../api/SIMT-API/sync_and_memory_fence/sync_and_memory_fence_intro.md)。

## 使用建议

- 需要Thread Block内所有Thread完成某一阶段后再继续执行时，使用同步屏障。
- 只需要保证当前Thread的内存写入顺序和可见性时，使用内存栅栏。
- 不要将内存栅栏当作同步屏障使用。内存栅栏不会等待其他Thread，也不保证其他Thread已经执行到同一位置。
- 不要将同步屏障当作跨Thread Blocksync_interface使用。不同Thread Block之间如需共享状态，应结合Global Memory、atomic_operations和内存栅栏设计同步协议。
- 多个Thread并发写同一地址时，同步屏障和内存栅栏都不能替代atomic_operations；需要避免写冲突，可使用[atomic_operations](atomic_operations.md)保证读改写过程的原子性。
