# 3510迁移9201指导

本节提供3510算子迁移至9201的适配方法。建议先完成核配比、数据流和同步的功能适配，再处理资源占用、精度和性能问题。

**表1** 兼容性问题索引

| 接口层级 | 主要兼容性问题 | 迁移指导 |
|----------|----------------|----------|
| 基础API | Scalar原子配置失效；1:2改为1:1后的搬运、核索引与同步变化；SSBuffer和UB容量变化 | [基础API迁移指导](./basic_api_migration.md) |
| Regbase API | 归约、交织和移位的软仿资源开销；负移位和b8标量移位；fp16 Exp精度 | [Regbase API迁移指导](./reg_api_migration.md) |
| SIMD C API | 对应硬件能力变化及公开原型差异，需要逐项核对重载和参数 | [C API迁移指导](./c_api_migration.md) |
| 高阶API、Tensor API | Matmul切分策略、激活函数精度及Copy的dualdst依赖 | [高阶API及Tensor API迁移指导](./advanced_api_migration.md) |
| 编译与验证 | 目标架构、MIX执行配置、Host产品分派、Tiling及资源验证 | [算子编译迁移指导](./op_compilation_migration.md) |

## 迁移步骤

1. 确认配套SDK和编译器支持9201，记录3510版本的输入范围、精度标准、Tiling和性能基线。
2. 排查`__mix__(1, 2)`、AIV0/AIV1分工、`/ 2`和`% 2`核索引换算、第二个AIV的同步和dualdst搬运。按1:1重新分配任务与缓冲区。
3. 排查Scalar原子配置、SSBuffer硬编码偏移、UB容量硬编码和间接寻址索引位宽。
4. 排查归约、交织、移位和fp16 Exp调用。记录具体重载、数据类型、参数范围以及是否实际进入对应路径。
5. 为9201重新生成Tiling和二进制，检查编译资源报告，再进行精度、同步、内存边界和性能回归。

## 兼容性结论的使用

**表2** 兼容性分类与处理原则

| 兼容情况 | 判断方法 | 处理原则 |
|----------|----------|----------|
| 功能不兼容 | 依赖已删除的能力、旧核配比、旧地址布局或逐位一致的fp16结果 | 按对应章节修改算法、数据流或精度路径。不能仅通过重新编译解决。 |
| 软仿兼容 | 配套SDK使用软件实现保持原接口语义 | 先验证功能，再检查寄存器、UB溢出和耗时；必要时缩短寄存器活跃区间或调整切分。 |
| 条件性性能风险 | b8运行时标量移位需要范围判断，或软仿使寄存器压力跨越限制 | 结合优化后代码和资源报告判断，不能只按接口名称认定有额外开销。 |
| 接口兼容、算法仍需复核 | UB容量查询等接口保留，但返回值或可用资源变化 | 重新计算Tiling、循环和边界，避免沿用旧容量常数。 |

文中的迁移示例主要说明需要修改的核心逻辑；其中标注为伪代码的搬运和同步流程，需要结合实际算子的流水、数据布局和公开API补全，不能直接作为完整内核编译运行。
