# 算子编译迁移指导

将3510算子迁移至9201，需要使用支持目标产品的配套SDK和编译器，重新编译Device代码并生成对应Tiling及分派配置。不能直接复用3510二进制。

## 编译目标与执行配置

**兼容方案**：

- 异构编译场景，将编译命令或CMake中的`--npu-arch=dav-3510`调整为`--npu-arch=dav-9201`，并核对工具链确实支持该目标。
- 对依赖MIX执行配置的内核，按目标SDK支持的方式将1:2协作改为1:1，同时修改数据流和同步。若采用语言扩展的`__mix__`声明，应核对并使用目标编译器支持的1:1声明，不能仅替换编译目标而保留旧参与者假设。
- 自定义算子工程中，更新CMakePresets.json的`ASCEND_COMPUTE_UNIT`及AddConfig注册，并按实际产品的SocVersion分派Host实现。`9201`是架构编号，不应直接推导产品型号字符串或注册名称。
- 更新JIT代码生成、编译选项、缓存目录或缓存键，确保架构、SDK及代码变化后不会加载旧的3510产物。重新生成Tiling和工作区大小。

**迁移示例**：使用支持ASC语言的工程配置目标架构。

```cmake
target_compile_options(demo PRIVATE
    $<$<COMPILE_LANGUAGE:ASC>:--npu-arch=dav-9201>
)
```

具体编译环境和工程配置请参考[AI Core算子编译](../../../programming_guide/compilation_and_execution/operator_compilation/ai_core_operator_compilation.md)。不要通过修改`impl`目录的内部实现来使旧代码通过编译。

## 多架构代码组织

**说明**：Device侧使用`__NPU_ARCH__`隔离特定架构逻辑，Host侧通过产品能力和SocVersion选择对应配置。Host普通C++编译不应假定能够获得Device侧的`__NPU_ARCH__`值。

**迁移示例**：以下片段表示Device侧按架构选择通信布局的写法。两个分支内仍需实现各自完整的数据流与同步。

```cpp
#if defined(__NPU_ARCH__) && (__NPU_ARCH__ == 9201)
// 使用1:1的核协作、SSBuffer布局及数据切分。
#elif defined(__NPU_ARCH__) && (__NPU_ARCH__ == 3510)
// 使用3510对应的核协作和数据切分。
#else
#error "Unsupported NPU architecture for this kernel"
#endif
```

能通过资源查询和公开接口表达的容量、参与者数量，应优先使用查询结果，避免分散硬编码。必须隔离的dualdst策略、公开原型差异及通信布局，再使用架构分支处理。

## 编译资源检查

1. 检查目标版本是否公开所用接口和重载，重点关注移位量类型、新版本归约/重排接口及版本条件。不要通过强制转换掩盖数据范围问题。
2. 在计划发布的优化配置下生成资源报告，检查寄存器使用和UB溢出。归约、交织及b64移位的软仿开销可能使原本接近上限的内核溢出。
3. 对超过寄存器限制或溢出空间限制的内核，缩短活跃区间、减少展开或调整tile后重新编译。UB物理容量扩大不能解除寄存器溢出空间限制。
4. 对b8标量移位常量2/4等场景，检查范围判断是否已在内联和常量传播后消除。只有仍然保留的运行时逻辑才应计入该项性能开销。
5. 记录实际使用的编译器版本、SDK版本、架构、优化选项和Tiling，保证回归结果可复现。

## 功能与性能回归

**表1** 迁移验证重点

| 检查项 | 需要覆盖的场景 | 验收重点 |
|--------|----------------|----------|
| 核索引与任务覆盖 | 最小/最大启动规模、单任务、多任务及尾块 | 每份数据只处理一次，不依赖不存在的AIV1。 |
| 搬运与布局 | L0C到UB、UB与L1、单/多级缓冲及轮转 | 无dualdst依赖、无遗漏、无重叠写、无越界。 |
| 核间同步 | 空任务、条件分支、提前返回、多轮复用 | 通知与等待匹配，无死锁，缓冲区复用前消费者已完成。 |
| Scalar原子操作 | 多核并发更新、与搬运混合、缓存访问 | 更新无丢失，返回值语义、数据可见性和缓存一致性正确。 |
| SSBuffer与UB | 2KB SSBuffer边界、实际UB预算、SIMD与SIMT混合、间接寻址 | 布局和容量合法，索引无截断，Host和Device预算一致。 |
| 归约与重排 | SUM/MAX/MIN、不同mask/位宽、双输出、特殊值 | 结果和索引语义符合要求，布局正确。 |
| 移位 | 非负量0、位宽边界、255/256；常量与运行时量；有符号/无符号数据；b64 | 无负移位依赖，无窄化回绕，填充语义正确。 |
| 精度 | fp16 Exp及相关激活、高精度路径、极值和真实数据分布 | 满足算子约定的ULP、绝对误差或相对误差，区分跨架构逐位差异。 |
| 性能与资源 | 代表性Shape及极端Shape、寄存器峰值、UB溢出、端到端耗时 | 在功能通过后判断性能变化，保留可复现的报告。 |

建议先逐项验证搬运、同步和计算，再进行完整算子的回归。仅通过静态扫描或编译不能确认目标设备上的精度、同步和性能均已满足要求。
