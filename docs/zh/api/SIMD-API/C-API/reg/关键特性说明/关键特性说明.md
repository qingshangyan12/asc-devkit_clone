# Reg矢量计算关键特性说明

## 硬件循环

满足编码约束的Vector Function循环可由编译器转换为Hardware Loop，减少Scalar控制开销。

- 最多支持4层嵌套Hardware Loop，也支持多个串行Hardware Loop。
- 迭代变量使用`uint16_t`，初值为0，每次递增1。
- 循环执行期间不能修改计数或边界。
- 循环体中的控制流可能阻止Hardware Loop生成，应避免`switch`、`do-while`、`while`以及不能被编译器消除的跳转。
- 使用外层计数作为内层边界时，应先将外层计数保存到标量变量。

## 指令双发

不存在数据依赖且执行单元允许时，处理器可在同一周期发射两条指令。接口能力参见[Reg矢量计算接口指令单双发汇总](../../../../附录/Reg矢量计算接口指令单双发汇总.md)，优化方法参见[指令双发优化](../../../../../guide/算子实践参考/SIMD算子性能优化/矢量计算/VF性能优化/指令双发优化.md)。

当VF过长、寄存器依赖过多或包含频繁同步时，可拆分循环、调整指令顺序或适量将中间结果写回UB，降低寄存器等待和ICache压力。

## VF融合

编译选项`--cce-simd-vf-fusion=true`允许编译器在合法且有收益时融合控制流等价的VF。融合后编译器可能插入保守同步，并继续外提或合并指令。详细要求参见[VF融合优化](../../../../../guide/算子实践参考/SIMD算子性能优化/矢量计算/VF性能优化/VF融合优化.md)。

## 数据搬运优化

| 场景 | 接口 |
| --- | --- |
| UB连续对齐搬入 | [asc_loadalign](../reg_load/asc_loadalign.md) |
| UB连续非对齐搬入 | [asc_loadunalign](../reg_load/asc_loadunalign.md) |
| 索引离散搬入 | [asc_gather](../reg_load/asc_gather.md) |
| DataBlock离散搬入 | [asc_gather_datablock](../reg_load/asc_gather_datablock.md) |
| 连续对齐搬出 | [asc_storealign](../reg_store/asc_storealign.md) |

数据类型位宽变化时，可选择带unpack或pack能力的搬入、搬出重载，避免额外的数据重排。连续非对齐场景参见[连续非对齐场景优化](../../../../../guide/算子实践参考/SIMD算子性能优化/矢量计算/VF性能优化/连续非对齐场景优化.md)。

Vector Function内部的内存依赖应按[asc_mem_bar](../sync_control/asc_mem_bar.md)约束处理。
