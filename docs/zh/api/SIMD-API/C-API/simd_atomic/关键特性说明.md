# 关键特性说明

## 搬运随路原子操作

1. 根据目的数据类型调用[asc_set_atomic_add](asc_set_atomic_add.md)、[asc_set_atomic_max](asc_set_atomic_max.md)或[asc_set_atomic_min](asc_set_atomic_min.md)文档中列出的具体配置符号。
2. 调用支持原子写GM的搬运接口。搬运长度参数的单位以该接口文档为准；`size`参数应按字节传入。
3. 原子写阶段结束后调用[asc_set_atomic_none](asc_set_atomic_none.md)，避免后续无关搬运继续使用原子模式。

原子配置是当前执行上下文的状态。配置接口、原子搬运和关闭接口之间不能插入会错误继承该状态的GM写操作。

## Scalar单点原子操作

Scalar原子接口适合计数器、状态字或锁等单地址更新。选择接口时需要核对返回值语义、目标指针类型、地址对齐、数据类型和产品支持情况。

## 多核同步和缓存

- 原子性只保证单次读改写不可被拆分，不等于所有参与Core已经到达同一执行阶段。
- 需要阶段同步时，应根据参与者范围使用[asc_sync_block](../sync/asc_sync_block_arrive.md)、[asc_sync_subblock](../sync/asc_sync_subblock_arrive.md)、[asc_sync_intra](../sync/asc_sync_intra_arrive.md)或[asc_sync_inter](../sync/asc_sync_inter_arrive.md)接口族。
- Scalar通过DCache访问普通GM信号或数据时，应使用[asc_dcci](../cache_ctrl/asc_dcci.md)执行单接口文档要求的Clean、Invalid或Clean and Invalid操作。
- 发送同步信号前应保证生产数据已经对其他Core可见；等待同步信号后，如本Core可能缓存旧数据，应在读取前使对应Cache Line失效。

示例应完整声明GM指针、长度单位和同步参与者，并在目标架构上编译验证。不要在纯Cube Core路径中使用仅Vector Core可访问的UB搬运接口。
