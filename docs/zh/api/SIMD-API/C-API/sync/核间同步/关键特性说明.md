# 关键特性说明

## 接口选择

核间同步接口应按实际参与者选择，不能通过模板模式参数在同一接口上切换同步范围：

- block与subblock同步：使用`asc_sync_block_arrive(pipe, flag_id)`和`asc_sync_block_wait(pipe, flag_id)`。
- subblock之间同步：使用`asc_sync_subblock_arrive(pipe, flag_id)`和`asc_sync_subblock_wait(pipe, flag_id)`。
- 不同group之间同步：使用`asc_sync_inter_arrive(pipe, flag_id)`和`asc_sync_inter_wait(pipe, flag_id)`。
- block与指定subblock同步：使用`asc_sync_intra_arrive(pipe, sync_id)`和`asc_sync_intra_wait(pipe, sync_id)`。

C API的同步范围由不同接口族区分，不通过C++模板模式参数选择。

## 配对规则

- 到达接口和等待接口必须选择同一接口族，并使用匹配的ID。
- `pipe`表示到达接口等待的前序流水或等待接口阻塞的后续流水，合法取值以单接口文档为准。
- 同一个ID对应硬件计数器，重复发送、提前复用或参与者数量不匹配可能导致错误同步或永久等待。
- 2201架构上的部分核间同步场景需要Host侧提供硬件同步基地址；3510架构是否需要该地址以单接口约束为准。
- Kernel类型、block/subblock组织方式及启动核数必须与所选同步范围一致。

完整函数原型、ID范围和示例请从[同步控制](../同步控制.md)进入对应单接口文档查询。
