# 系统同步能力概述<a name="ZH-CN_TOPIC_0000002586323695"></a>

在编程中，同步是指协调多个执行单元（如线程、进程等）对共享资源的访问顺序和时机来确保程序的正确性。如果没有同步来严格控制执行顺序，则会出现结果不一致、行为不可预测等多种问题。

AI Core的同步，总共分成3类：核内同步、核间同步、任务间同步。各类同步对应的接口如下。

**表1**  核内同步接口

| 接口名称 | 功能简述 | 同步类别 |
| --- | --- | --- |
| [asc_sync_notify](asc_sync_notify.md)/[asc_sync_wait](asc_sync_wait.md) | 多流水同步：同一核内不同流水之间的同步指令。asc_sync_notify负责发送通知，asc_sync_wait负责阻塞直到asc_sync_notify发送通知。 | 硬件同步 |
| [asc_sync_pipe](asc_sync_pipe.md) | 单流水同步：同一核内相同流水之间的同步指令（不支持PIPE_S单流水同步）。 | 硬件同步 |
| [asc_sync_data_barrier](asc_sync_data_barrier.md) | 阻塞后续的指令执行，直到所有之前的内存访问指令（需要等待的内存位置可通过参数控制）执行结束。 | 硬件同步 |
| [asc_lock](asc_lock.md)/[asc_unlock](asc_unlock.md) | 用于核内异步流水指令之间的同步处理，其功能类似于传统CPU中的锁机制。通过锁定指定流水再释放流水来完成流水间的同步依赖。 | 硬件同步 |

**表2**  核间同步接口

| 接口名称 | 功能简述 | 同步类别 |
| --- | --- | --- |
| [asc_sync_block_arrive](asc_sync_block_arrive.md)/[asc_sync_block_wait](asc_sync_block_wait.md) |多个AIC或AIV之间的同步控制。asc_sync_block_arrive负责发送通知，asc_sync_block_wait负责阻塞直到asc_sync_block_arrive发送通知。<br>支持以下同步场景：<br>&bull;同步等待全部AIC或者同步等待全部AIV执行结束。<br>&bull;单个AI Core内，全部AIV之间的同步。<br>&bull;单个AI Core内，AIC与全部AIV之间的同步。 | 硬件同步 |
| [asc_sync_inter_arrive](asc_sync_inter_arrive.md)/[asc_sync_inter_wait](asc_sync_inter_wait.md) | 被等待核发送到达通知，等待核阻塞至对应核间事件完成。 | 硬件同步 |
| [asc_sync](asc_sync.md) | 用于多个核之间的同步控制，支持以下同步场景：<br>&bull;纯Vector算子的全核同步，可参考[asc_sync_block_arrive的模式0](核间同步/关键特性说明.md)。<br>&bull;融合算子的全核同步，一次性实现三个核间同步能力（参考[asc_sync_block_arrive的关键特性说明](核间同步/关键特性说明.md)）：首先完成单个AI Core内，AIC与全部AIV之间的同步（AIC等AIV）；接着完成多个AI Core间，所有AIC的同步；最后完成单个AI Core内，所有AIV与AIC同步（AIV等AIC）。 | 硬件同步 |
| [asc_sync](asc_sync.md) | 仅支持纯Vector算子的多核（参与同步的核数可通过入参指定）同步。每一个AIV都向全局内存对应位置写入信号值1，接着每一个AIV都持续轮询全局内存中所有AIV对应的信号值，直到所有AIV核对应的信号值都变为1。 | 软件同步 |

**表3**  任务间同步接口

| 接口名称 | 功能简述 | 同步类别 |
| --- | --- | --- |
| SuperKernel后续任务并行控制 | 在SuperKernel的子Kernel中设置后续任务开始点，设置点之后的指令可以和后续其他子Kernel并行执行，以提升整体性能。当前公开C API目录未提供同名直接接口。 | 硬件同步 |
| SuperKernel前序任务等待控制 | 在SuperKernel的子Kernel中设置前序任务结束等待点，设置点之前的指令可以和前序其他子Kernel并行执行，以提升整体性能。当前公开C API目录未提供同名直接接口。 | 硬件同步 |
