# 核内同步能力概述

核内同步用于约束同一Core上流水之间或流水内部的执行顺序。

## 全流水同步

[asc_sync](../asc_sync.md)等待当前Core此前提交到所有流水的操作完成。该接口同步范围最大，通常只在无法用更精确同步表达依赖时使用。`asc_sync`不等待其他AI Core到达同步点。

## 流水间同步

[asc_sync_notify](../asc_sync_notify.md)和[asc_sync_wait](../asc_sync_wait.md)配对使用，通过相同事件ID建立源流水到目的流水的先后关系。两个接口的`pipe`、`tpipe`和`id`必须按单接口约束匹配。

## 单流水同步

[asc_sync_pipe](../asc_sync_pipe.md)保证指定流水的前序指令完成数据读写后，才继续执行该流水的后序指令。Scalar流水由硬件保证顺序，`asc_sync_pipe`不支持`PIPE_S`。

## 专用同步接口

[asc_sync_mte2](../asc_sync_mte2.md)、[asc_sync_mte3](../asc_sync_mte3.md)和[asc_sync_vec](../asc_sync_vec.md)用于单接口文档指定的流水同步场景。无参数的`asc_sync_vec`已废弃，应使用[asc_sync](../asc_sync.md)；带事件ID的重载是否适用以单接口文档为准。

流水类型和合法同步组合参见[关键特性说明](关键特性说明.md)。
