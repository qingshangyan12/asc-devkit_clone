# 关键特性说明

## 选择同步接口

| 依赖关系 | 推荐接口 |
| --- | --- |
| 同一流水的前后指令访问重叠地址 | [asc_sync_pipe](../asc_sync_pipe.md) |
| 一条流水生产数据、另一条流水消费数据 | [asc_sync_notify](../asc_sync_notify.md)和[asc_sync_wait](../asc_sync_wait.md) |
| 必须等待当前Core全部流水结束 | [asc_sync](../asc_sync.md) |

例如，GM->UB搬运位于`PIPE_MTE2`，矢量计算位于`PIPE_V`。计算依赖搬入结果时，可先在`PIPE_MTE2`上调用`asc_sync_notify`，再在`PIPE_V`上调用`asc_sync_wait`。计算结果写回GM时，可使用另一事件ID建立`PIPE_V`到`PIPE_MTE3`的依赖。

## 使用约束

- `asc_sync_notify`和`asc_sync_wait`必须使用相同的源流水、目的流水和事件ID。
- 事件ID不能在前一组同步尚未完成时被无保护地复用。
- `asc_sync_pipe`只约束指定流水，不建立不同流水之间的数据依赖。
- `asc_sync`只等待当前Core，不具备组内或组间Core同步语义。
- 流水类型及允许组合以相关单接口文档为准，不应从基础API的队列同步模型推导C API行为。
