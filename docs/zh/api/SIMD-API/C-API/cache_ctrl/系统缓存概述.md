# 系统缓存概述

缓存用于降低AI Core访问GM或指令存储的延迟。不同NPU架构可能包含L2 Cache、DCache、ICache、SIMT DCache和NDDMA Cache，具体支持情况以相关单接口文档为准。

| Cache类型 | 主要作用 | C API入口 |
| --- | --- | --- |
| L2 Cache | 缓存MTE或Scalar访问的GM数据。 | [asc_load_l2_cache_mode](../enum/asc_load_l2_cache_mode.md)及包含L2 Cache模式参数的搬运接口。 |
| DCache | 缓存Scalar访问的GM数据。 | [asc_datacache_preload](asc_datacache_preload.md)、[asc_dcci](asc_dcci.md)、[asc_dci](asc_dci.md) |
| ICache | 缓存Scalar执行的指令。 | [asc_icache_preload](asc_icache_preload.md)、[asc_get_icache_preload_status](asc_get_icache_preload_status.md) |
| NDDMA Cache | 缓存多维搬运所需数据。 | 当前C API单接口文档未提供独立的NDDMA Cache控制入口。 |

## 常用操作

- Preload：主动把即将访问的数据或指令加载到缓存。
- Clean：把脏Cache Line写回GM，Cache Line仍保持有效。
- Invalid：使Cache Line失效，后续访问重新从下层存储获取数据。对脏Cache Line直接执行Invalid可能丢失尚未写回的数据。
- Clean and Invalid：先写回脏数据，再使Cache Line失效。

## 多核数据可见性

DCache和部分专用Cache为每个Core独立维护。一个Core通过Scalar更新GM数据时，其他Core可能仍看到旧的缓存副本。常见顺序如下：

1. 生产Core完成数据写入，并按[asc_dcci](asc_dcci.md)约束执行Clean或Clean and Invalid。
2. 生产Core发送与场景匹配的核间同步信号。
3. 消费Core等待同步信号。
4. 消费Core在读取前按约束执行Invalid或Clean and Invalid，避免命中旧副本。

同步接口只建立执行顺序，不替代缓存维护；缓存维护也不替代参与Core之间的同步。

## DCache整体失效

[asc_dci](asc_dci.md)使整个数据缓存失效，不会写回脏Cache Line。调用前必须先按接口约束使用[asc_sync_data_barrier](../sync/asc_sync_data_barrier.md)等待内存访问完成。存在尚未写回的数据时，直接调用可能造成数据丢失。
