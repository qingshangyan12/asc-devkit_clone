# 关键特性说明<a name="ZH-CN_TOPIC_0000002555780804"></a>

## 自动同步概述

[C API编程方式](https://gitcode.com/cann/asc-devkit/blob/master/docs/zh/guide/编程指南/编程模型/AI-Core-SIMD编程/基于指针的C语言编程/C语言编程概述.md)下，毕昇编译器（后续简称编译器）可自动插入部分同步，C API同时提供显式同步接口，用于处理编译器无法自动识别的流水依赖。本章节介绍编译器支持的自动同步类型、C API显式同步方式、自动同步使用约束及编译器自动同步debug日志功能。

## C API编程方式和编译器自动同步支持情况<a name="zh-cn_topic_0000002521905636_section_auto_sync"></a>

C API编程方式下，编译器对Vector计算单元和Cube计算单元的自动同步支持情况如下：

- Vector计算单元
    - 单流水同步：PIPE\_V由编译器自动完成同步插入，PIPE\_MTE2/PIPE\_MTE3在搬运地址有重叠的情况下需要开发者插入同步（具体示例请参考[约束说明](../../sync/同步控制.md)）。C API编程方式不支持插入单流水同步。
    - 多流水同步：PIPE\_V、PIPE\_MTE2、PIPE\_MTE3、PIPE\_S之间的多流水同步都是双向的。如下图所示，**黄色线条表示的同步由编译器自动插入**，黑色线条表示开发者需通过`asc_sync_notify`和`asc_sync_wait`显式建立的依赖。
        ![](../../../../figures/aiv_auto_insert_sync_diagram.png)
        > [!CAUTION]注意
        > 例外情况：当标量原子操作接口（包括[asc_atomic_add](../../scalar_compute/asc_atomic_add.md)、[asc_atomic_cas](../../scalar_compute/asc_atomic_cas.md)、[asc_atomic_exch](../../scalar_compute/asc_atomic_exch.md)、[asc_atomic_max](../../scalar_compute/asc_atomic_max.md)和[asc_atomic_min](../../scalar_compute/asc_atomic_min.md)）与搬运单元（MTE2/MTE3）在读写GM时存在数据依赖时，编译器无法自动插入同步，开发者需根据实际情况显式同步。

- Cube计算单元
    Cube侧编译器不支持自动插入任何类型的同步，开发者需根据流水依赖显式同步。

以[NPU架构2201](https://gitcode.com/cann/asc-devkit/blob/master/docs/zh/guide/编程指南/语言扩展层/SIMD-BuiltIn关键字.md#npu-arch)为例，该硬件架构下AIV和AIC中不同流水线的同步情况分别如表1和表2所示。编译器能够自动插入部分同步，以解决写后读（WAR，Write-After-Read）和读后写（RAW，Read-After-Write）两类数据依赖；表中标为“C API显式同步”的位置需调用[asc_sync_notify](../../sync/asc_sync_notify.md)和[asc_sync_wait](../../sync/asc_sync_wait.md)，同一流水内的依赖需调用[asc_sync_pipe](../../sync/asc_sync_pipe.md)。

**表1**  C API编程方式下AIV中不同流水线的同步情况 <a name="zh-cn_topic_0000002521905636_table13753342164113"></a>

| 源流水\\目的流水 | PIPE_S | PIPE_V | PIPE_MTE2 | PIPE_MTE3 |
| --- | --- | --- | --- | --- |
| PIPE_S | 不涉及 | 编译器自动同步 | 编译器自动同步 | 编译器自动同步 |
| PIPE_V | 编译器自动同步 | 手动调用`asc_sync_pipe` | C API显式同步 | C API显式同步 |
| PIPE_MTE2 | 编译器自动同步 | C API显式同步 | 手动调用`asc_sync_pipe` | C API显式同步 |
| PIPE_MTE3 | 编译器自动同步 | C API显式同步 | C API显式同步 | 手动调用`asc_sync_pipe` |

**表2**  C API编程方式下AIC中不同流水线的同步情况 <a name="zh-cn_topic_0000002521905636_table169315822914"></a>

| 源流水\\目的流水 | PIPE_S | PIPE_M | PIPE_MTE1 | PIPE_MTE2 | PIPE_MTE3 | PIPE_FIX |
| --- | --- | --- | --- | --- | --- | --- |
| PIPE_S | 不涉及 | 不涉及 | 不涉及 | 不涉及 | 不涉及 | 不涉及 |
| PIPE_M | 不涉及 | 手动调用`asc_sync_pipe` | C API显式同步 | C API显式同步 | 不涉及 | C API显式同步 |
| PIPE_MTE1 | 不涉及 | C API显式同步 | 手动调用`asc_sync_pipe` | C API显式同步 | C API显式同步 | C API显式同步 |
| PIPE_MTE2 | 不涉及 | C API显式同步 | C API显式同步 | 手动调用`asc_sync_pipe` | C API显式同步 | 暂无应用场景 |

NPU架构3510支持使用[asc_lock](../../sync/asc_lock.md)和[asc_unlock](../../sync/asc_unlock.md)按“锁定-释放”方式处理多流水依赖；`asc_sync_notify`和`asc_sync_wait`仍可用于兼容场景。详细规则请参考[C API编程同步控制](https://gitcode.com/cann/asc-devkit/blob/master/docs/zh/guide/编程指南/语言扩展层/SIMD语言扩展层C-API.md)。

## 自动同步使用约束说明<a name="zh-cn_topic_0000002521905636_section56111955113614"></a>

- 可通过编译选项“--cce-auto-sync”或“--cce-auto-sync=on”开启编译器自动同步功能，Kernel直调算子工程、自定义算子开发工程以及异构编译`<<<>>>`直调已默认开启该编译选项。如需关闭，开发者可手动设置“--cce-auto-sync=off”。
  > [!CAUTION]注意
  > C API无法自动表达的流水依赖需要开发者管理。编译器能够自动插入的同步见表1和表2；其余依赖需调用`asc_sync_pipe`、配对调用`asc_sync_notify`和`asc_sync_wait`，或在NPU架构3510下配对调用`asc_lock`和`asc_unlock`。

- Kernel函数中调用的所有函数需为inline函数，编译器才能自动插入同步。
- 正确使用C API地址与流水模型才能保证编译器自动同步功能正常运作。若代码绕开已知接口直接读写地址，编译器可能无法识别依赖，此时需按数据通路手动插入同步。
- C API编程方式不会自动插入单流水同步指令，在搬运地址有重叠的情况下需要开发者手动插入同步，参考asc_sync_pipe约束说明。
- 在C API编程方式下，如果开发者手动插入了编译器或C API编程方式本已自动插入的同步指令，将导致同步指令被重复插入，可能导致程序逻辑异常或性能下降。
- AIC和AIV之间不支持使用[asc_sync_notify/asc_sync_wait](../../sync/asc_sync_notify.md)进行同步，可能会出现硬件未定义情况。AIC和AIV之间的同步控制属于核间同步，需要调用[asc_sync_block_arrive](../../sync/同步控制.md)和[asc_sync_block_wait](../../sync/同步控制.md)进行同步。
<!-- npu="A3,910b" id2 -->

- 以下接口与其他指令之间的同步由硬件保证，无需自动插入同步或手动插入同步，该说明针对如下型号生效：
    <!-- npu="A3" id3 -->
    - Atlas A3 训练系列产品/Atlas A3 推理系列产品
    <!-- end id3 -->
    <!-- npu="910b" id4 -->
    - Atlas A2 训练系列产品/Atlas A2 推理系列产品
    <!-- end id4 -->

  > [!CAUTION]注意
  > 调用`asc_set_vector_mask`、`asc_set_mask_count`和`asc_set_mask_norm`时不需要手动插入同步。
  > 调用`asc_set_atomic_add_*`、`asc_set_atomic_max_*`、`asc_set_atomic_min_*`、`asc_set_atomic_none`和`asc_set_store_atomic_config_v1`时不需要手动插入同步。
  > 调用CTRL寄存器相关的指令不需要手动插入同步。

## 编译器自动同步Debug日志功能

毕昇编译器提供“--cce-auto-sync-log=<file>”编译选项可以输出同步插入信息到<file>文件中，帮助开发者显式地识别编译器在算子文件中插入的同步指令信息。需debug模式（添加-g编译选项）编译算子，用于获取算子代码文件行号。

- 直接使用毕昇编译器的场景，可以直接在编译命令中添加该编译选项。
- 使用Ascend C kernel直调算子工程，可以通过ascendc_compile_options添加该编译选项。
- 使用Ascend C自定义算子开发工程，可以通过add_ops_compile_options添加该编译选项。

如下的代码文件sync_log_test.h：

```cpp
__ubuf__ T* dst_local;
T ave_tmp = 0;
vector_op1(dst_local, params);
ave_tmp = dst_local[0];
vector_op2(dst_local, params);
for (int i = 0; i < ave_tmp; ++i) {
    dst_local[i] = 0;
}
```

开启自动同步后，同步指令的插入位置如下：

```cpp
__ubuf__ T* dst_local;
T ave_tmp = 0;
vector_op1(dst_local, params);
asc_sync_notify(PIPE_V, PIPE_S, EVENT_ID0);
asc_sync_wait(PIPE_V, PIPE_S, EVENT_ID0);
ave_tmp = dst_local[0];
asc_sync_pipe(PIPE_V);
asc_sync_notify(PIPE_S, PIPE_V, EVENT_ID0);
asc_sync_wait(PIPE_S, PIPE_V, EVENT_ID0);
vector_op2(dst_local, params);
asc_sync_notify(PIPE_V, PIPE_S, EVENT_ID0);
asc_sync_wait(PIPE_V, PIPE_S, EVENT_ID0);
for (int i = 0; i < ave_tmp; ++i) {
    dst_local[i] = 0;
}
```
