# 概述<a name="ZH-CN_TOPIC_0000002573904727"></a>

复合计算通常指的是在数学或编程中对复合函数或运算的处理。

**表1**  复合指令功能说明

| API | 数学表达 |
| :--- | :--- |
| [asc_axpy](../../../vector_compute/asc_axpy.md) | $dst_j=scalar \times src_i + dst_i$ |
| [asc_fma](../../../vector_compute/asc_fma.md) | $dst_j=src0_i \times src1_i + dst_i$ |
| [asc_mul_cast_half2int8/asc_mul_cast_half2uint8](../../../vector_compute/Memory矢量计算.md) | $dst_i=Cast(src0_i \times src1_i)$ |
| 标量乘法后类型转换 | 当前C API需根据目标数据类型组合标量乘法与类型转换接口，$dst_i=Cast(src_i \times scalar)$。 |
| [asc_add_relu](../../../vector_compute/asc_add_relu.md) | $dst_i=asc_relu(src0_i + src1_i)$ |
| [asc_add_relu](../../../vector_compute/asc_add_relu.md) | $dst_i=Cast(asc_relu(src0_i + src1_i))$ |
| [asc_sub_relu](../../../vector_compute/asc_sub_relu.md) | $dst_i=asc_relu(src0_i - src1_i)$ |
| [asc_sub_relu](../../../vector_compute/asc_sub_relu.md) | $dst_i=Cast(asc_relu(src0_i - src1_i))$ |
| [asc_abs_sub](../../../reg/compound_compute/asc_abs_sub.md) | $dst_i=\lvert src0_i - src1_i\rvert$ |
| 减法后指数计算 | 当前Memory矢量C API需组合`asc_sub`与`asc_exp`，$dst_i=e^{src0_i - src1_i}$。 |
| [asc_mul_add](../../../vector_compute/asc_mul_add.md) | $dst_j=src0_i \times dst_i + src1_i$ |
| [asc_mul_add_relu](../../../vector_compute/asc_mul_add_relu.md) | $dst_i=asc_relu(src0_i \times dst_i + src1_i)$ |
| [asc_deq_int162b8/asc_deq_int322half](../../../vector_compute/Memory矢量计算.md) | • 输入数据类型为int16_t时可执行量化和类型转换。<br>• 输入类型为int32_t时可按接口定义执行量化、舍入和类型转换。 |
| 加法、反量化与激活组合 | 根据目标数据类型组合`asc_add`、反量化和`asc_relu`接口，$dst_i=asc_relu(Deq(src0_i + src1_i))$。 |

## 推荐使用场景<a name="zh-cn_topic_0000002558185995_section23771839304"></a>

- UB资源紧张场景。

  使用复合指令能在不修改源操作数原有数据的同时，减少UB空间的使用。

- 高性能场景。

  在不考虑bank冲突等其它因素的情况下，由于使用复合指令能够减少计算指令的数量，能够带来性能提升。

- 高精度场景。

  对于源操作数和目的操作数类型一致的情况，使用复合指令不提升精度；

  对于目的操作数数据类型精度高于源操作数的情况，使用复合指令有精度提升（如源操作数数据类型为half，目的操作数数据类型为float），如`asc_axpy`、`asc_fma`。

## 关键特性说明

### 精度转换

乘法转换、加法激活转换、减法激活转换和标量乘法转换包含类型转换操作，转换规则参考下表：

**表2**  精度转换规则

| 源操作数的数据类型 | 目的操作数的数据类型 | 类型转换模式介绍 |
| :----------------- | :------------------- | :--------------- |
| float | half | 将源操作数按照CAST_NONE模式取到half所能表示的数，以half格式（溢出默认按照饱和处理）存入目的操作数中。 |
| half | int8_t | 将源操作数按照CAST_NONE模式取整，以int8_t格式（溢出默认按照饱和处理）存入目的操作数中。 |
| half | uint8_t | 将源操作数按照CAST_NONE模式取整，以uint8_t格式（溢出默认按照饱和处理）存入目的操作数中。 |
| int16_t | int8_t | 将源操作数按照CAST_NONE模式取到int8_t所能表示的数，以int8_t格式（溢出默认按照饱和处理）存入目的操作数中。 |
| int64_t | float | 将源操作数按照CAST_NONE模式取到float所能表示的数，以float格式（溢出默认按照饱和处理）存入目的操作数中。 |
| int64_t | int32_t | 将源操作数以int32_t格式（溢出默认按照饱和处理）存入目的操作数中 |

### 量化计算

反量化相关接口涉及量化参数的设置，需要结合[asc_set_deq_scale](../../../vector_compute/asc_set_deq_scale.md)使用。

### 三操作数读取

对于`asc_fma`、`asc_mul_add`和`asc_mul_add_relu`，若三个操作数均不重叠，将存在三读一写情况（其中目的操作数上既有读操作又有写操作）。由于硬件最多支持两读一写，指令的理论并行度将在原有基础上减半，可通过重叠操作数减少读操作来恢复原并行度。
