# 概述
Reg矢量计算API是面向Reg矢量计算架构开发的API，用户可以通过该API直接对芯片中涉及Vector计算的寄存器进行操作，实现更大的灵活性和更好的性能。Reg矢量计算API与Memory矢量计算API功能相似，但与Memory矢量计算API输入和输出数据必须为片上存储地址不同，Reg矢量计算API的输入或输出数据均为Reg矢量计算寄存器。对于计算类API，其功能是从给定的寄存器获取数据，进行计算，并将结果保存在给定的寄存器。对于搬运类API，其功能是实现UB和寄存器的数据搬运。由此可见，Reg矢量计算API相较于Memory矢量计算API，将数据搬运和Reg计算过程交给用户自主控制，从而实现更大的开发自由度。

## 如何使用Reg矢量计算API
基于寄存器的编程模型是指将数据从片上存储地址通过Reg搬运指令（Reg数据搬入）加载到寄存器中，进行复杂的数学计算Compute后通过Reg搬运指令（Reg数据搬出）搬出到片上存储地址中，所有的计算逻辑均在寄存器中完成，从而减少片上存储地址间的数据搬运，大大提升了整体性能，具体流程如下所示：

以[Reg矢量计算编程示例](#reg矢量计算编程示例)为例，完整的VectorFunction计算过程由以下几部分组成：
- 编写和调用VectorFunction（向量函数）。这些函数使用`__simd_vf__`标记，并由调用方直接调用；
- 定义矢量数据寄存器[矢量数据寄存器](../../../reg/reg.md)、掩码寄存器[vector_bool](../../../reg/reg.md)；
- 编写for循环映射到硬件循环（[HardwareLoop](关键特性说明.md#硬件循环hardwareloop)）；[asc_update_mask](../../../reg/reg_data_types/asc_update_mask.md#mask设置方式)函数用于更新参与计算的mask，每次循环都会消耗一个VL长度的元素。
- 循环内调用Reg数据搬入接口连续对齐搬入（[asc_loadalign](../../../reg/reg_load/asc_loadalign.md)）从UB中搬入单个VL长度数据；
- 循环内调用Reg计算接口Add完成单次Repeat计算；
- 循环内调用Reg数据搬出接口连续对齐搬出（[asc_storealign](../../../reg/reg_store/asc_storealign.md)）往UB中搬出计算后的数据；

## Reg矢量计算编程示例

```cpp
__simd_vf__ inline void add_vf(__ubuf__ half* dst_addr, __ubuf__ half* src0_addr,
    __ubuf__ half* src1_addr, uint32_t count, uint16_t one_repeat_size, uint16_t repeat_times)
{
    vector_half src_reg0;
    vector_half src_reg1;
    vector_half dst_reg;
    vector_bool mask;
    for (uint16_t i = 0; i < repeat_times; ++i) {
        mask = asc_update_mask_b16(count);
        asc_loadalign(src_reg0, src0_addr + i * one_repeat_size);
        asc_loadalign(src_reg1, src1_addr + i * one_repeat_size);
        asc_add(dst_reg, src_reg0, src_reg1, mask);
        asc_storealign(dst_addr + i * one_repeat_size, dst_reg, mask);
    }
}

__aicore__ inline void compute(__ubuf__ half* dst_addr, __ubuf__ half* src0_addr,
    __ubuf__ half* src1_addr, uint32_t count, uint16_t one_repeat_size, uint16_t repeat_times)
{
    // GM数据搬运至UB地址src0_addr及src1_addr
    ...
    // 直接调用vf函数
    add_vf(dst_addr, src0_addr, src1_addr, count, one_repeat_size, repeat_times);
    // UB地址dst_addr数据搬运至GM
    ...
}
```

>[!NOTE]说明
>- GM与UB间的数据搬运需通过[GM与UB数据搬运](../../../reg/reg.md)完成；
>- Vector Function的流水类型为PIPE_V，Vector Function内部的同步依赖通过[asc_mem_bar](../../../reg/sync_control/asc_mem_bar.md)接口插入。
