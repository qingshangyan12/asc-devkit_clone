# 数据搬运导览（C API）

> 本页保留为公共概述入口。按基础API原目录层级完整迁移的12份文档见[数据搬运导览目录](数据搬运导览/数据搬运导览.md)。

数据搬运负责在GM、UB、L1 Buffer、L0A Buffer/L0B Buffer/L0C Buffer及BiasTable Buffer/Fixpipe Buffer之间传递数据。C API通过`__gm__`、`__ubuf__`、`__cbuf__`、`__ca__`、`__cb__`、`__cc__`和专用地址空间数组表达存储位置；接口对应的流水由各接口文档的“流水类型”定义。

## 选择接口前的共性规则

- 以[通用说明和约束](../通用说明和约束.md)和目标接口的约束为准；接口自己的对齐、长度、stride和地址重叠约束优先。
- DataBlock通常为32 B，但不同接口的长度单位可能是字节、DataBlock或矩阵分形；不得按Basic API参数单位直接套用。
- 异步生产者—消费者链路必须显式建立依赖。例如GM->UB完成后由UB->GM消费，应使用[asc_sync_notify](../sync/asc_sync_notify.md)和[asc_sync_wait](../sync/asc_sync_wait.md)连接`PIPE_MTE2->PIPE_MTE3`；同流水重叠写入可使用[asc_sync_pipe](../sync/asc_sync_pipe.md)。
- `dav-3510`的支持通路和接口形态与其他架构不同。尤其是[asc_copy_l12gm](../cube_datamove/asc_copy_l12gm.md)在该架构文档中不支持；需要可观测回写时，应依据实际数据路径选择受支持的中转或搬出接口。

| UB->GM | MTE3 | [asc_copy_ub2gm](../vector_datamove/asc_copy_ub2gm/asc_copy_ub2gm.md)、[asc_copy_ub2gm_align](../vector_datamove/asc_copy_ub2gm_align/asc_copy_ub2gm_align.md) | DataCopy/DataCopyPad；同一CCE指令或指令族。 |
| UB->UB | Vector | [asc_copy_ub2ub](../vector_datamove/asc_copy_ub2ub.md)、[asc_copy](../vector_compute/asc_copy.md) | DataCopy/Copy；语义相近但须按掩码、repeat和数据路径区分。 |

## 格式转换、Padding与配置

- GM->L1 Buffer的ND2NZ/DN2NZ路径在调用前需要按文档配置[asc_set_gm2l1_nz_para](../sys_var/asc_set_gm2l1_nz_para.md)。
- 多维GM->UB路径使用[asc_ndim_copy_gm2ub](../vector_datamove/asc_ndim_copy_gm2ub.md)，并通过[asc_set_ndim_loop_stride](../vector_datamove/asc_set_ndim_loop_stride.md)、[asc_set_ndim_pad_count](../vector_datamove/asc_set_ndim_pad_count.md)和[asc_set_ndim_pad_value](../vector_datamove/asc_set_ndim_pad_value.md)配置。
- GM↔UB非对齐与Padding路径使用`*_align`接口及[asc_set_copy_pad_val](../vector_datamove/asc_set_copy_pad_val.md)，不应把连续搬运的参数解释复用于非对齐路径。
- L0C Buffer搬出前，NZ2ND、量化或激活配置分别参阅[asc_set_l0c2gm_nz2nd](../cube_compute/asc_set_l0c2gm_nz2nd.md)、[asc_set_l0c2gm_config](../cube_compute/asc_set_l0c2gm_config.md)和[asc_copy_l0c2gm](../cube_datamove/asc_copy_l0c2gm/asc_copy_l0c2gm.md)。

更多名称级Basic API/C API/CCE对应关系见[dav-3510 CCE指令索引](../../implementation_indexes/dav_3510/cce_instruction_index.json)。
