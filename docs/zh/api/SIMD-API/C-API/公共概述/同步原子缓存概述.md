# 同步、原子与缓存概述（C API）

## 同步控制

基础API的“系统同步能力、核内同步、核间同步和任务间同步”在C API中按硬件流水和作用域拆分。先确定生产者写入的存储单元、消费者读取的存储单元和两者对应流水，再选择接口：

| 场景 | C API入口 |
|---|---|
| 流水间生产者—消费者依赖 | [asc_sync_notify](../sync/asc_sync_notify.md)、[asc_sync_wait](../sync/asc_sync_wait.md) |
| 流水内完成等待/地址重叠串行化 | [asc_sync_pipe](../sync/asc_sync_pipe.md)、[asc_sync_mte2](../sync/asc_sync_mte2.md)、[asc_sync_mte3](../sync/asc_sync_mte3.md)、[asc_sync_vec](../sync/asc_sync_vec.md) |
| 核内/子块协作 | [asc_sync_intra_arrive](../sync/asc_sync_intra_arrive.md)、[asc_sync_intra_wait](../sync/asc_sync_intra_wait.md)、[asc_sync_subblock_arrive](../sync/asc_sync_subblock_arrive.md)、[asc_sync_subblock_wait](../sync/asc_sync_subblock_wait.md) |
| 核间协作与内存屏障 | [asc_sync_inter_arrive](../sync/asc_sync_inter_arrive.md)、[asc_sync_inter_wait](../sync/asc_sync_inter_wait.md)、[asc_sync_data_barrier](../sync/asc_sync_data_barrier.md) |

`set_flag`/`wait_flag`/`pipe_barrier`等Basic API直接CCE实现与C API的同步接口在`dav-3510`上存在对应，但事件ID、流水组合和跨核语义必须按C API文档配置。`PIPE_ALL`会收敛全部流水，通常只应在核结束或确有全局收敛需求时使用。

## 原子操作

基础API公共概述区分“搬运随路原子”和“Scalar单点原子”；C API同样分为两组：

- 搬运随路原子：使用[asc_set_atomic_add](../simd_atomic/asc_set_atomic_add.md)、[asc_set_atomic_max](../simd_atomic/asc_set_atomic_max.md)、[asc_set_atomic_min](../simd_atomic/asc_set_atomic_min.md)、[asc_set_atomic_none](../simd_atomic/asc_set_atomic_none.md)及[asc_set_store_atomic_config_v1](../simd_atomic/asc_set_store_atomic_config_v1.md)配置后续搬出。
- Scalar单点原子：使用[标量计算](../scalar_compute/标量计算.md)中的[asc_atomic_add](../scalar_compute/asc_atomic_add.md)、[asc_atomic_cas](../scalar_compute/asc_atomic_cas.md)、[asc_atomic_max](../scalar_compute/asc_atomic_max.md)等直接操作GM地址。

两类原子操作的影响范围不同：前者改变后续搬运的写入行为，后者只作用于该次Scalar操作。不能把配置接口当作立即执行的Scalar原子操作。

## 缓存控制

基础API缓存公共概述中的DCache、ICache、预取/失效和多核可见性概念，在C API中由[缓存控制](../cache_ctrl/缓存控制.md)的以下入口表达：

- [asc_datacache_preload](../cache_ctrl/asc_datacache_preload.md)：数据预加载。
- [asc_dcci](../cache_ctrl/asc_dcci.md)和[asc_dci](../cache_ctrl/asc_dci.md)：按接口定义执行缓存维护。
- [asc_icache_preload](../cache_ctrl/asc_icache_preload.md)和[asc_get_icache_preload_status](../cache_ctrl/asc_get_icache_preload_status.md)：指令预加载及状态查询。

缓存维护不替代数据依赖同步。多核读写同一GM区域时，应同时审查原子性、同步顺序、缓存维护范围和每个接口的产品支持。
