# 数据搬运概念<a name="ZH-CN_TOPIC_0000002534880720"></a>

## 搬运功能分类总览

数据搬运类接口提供了全面的数据搬运功能，覆盖从最基础的连续搬运到复杂的随路转换和量化激活。按照功能复杂度递增，搬运能力可以分为以下几个类别：基础数据搬运、高维切分搬运、切片搬运、随路格式转换搬运、随路量化激活搬运、非对齐搬运、UB内部搬运（asc_copy）、矩阵分形搬运和多维数据搬运NDDMA。每一类在后续章节中都有对应的详细接口说明。

## 基础数据搬运（连续搬运）

最简单的搬运模式。将源地址处一段连续内存的数据原封不动地搬运到目的地址。数据在传输过程中格式和内容保持不变，不执行任何转换或计算操作。C API连续搬运接口通过`uint32_t size`参数指定搬运数据量，单位为字节。

**适用场景**：已知数据在源和目的地址均连续存放，且地址满足对齐要求时的快速搬运。典型用于矢量计算前的批量数据加载（GM->UB）和计算后的结果回写（UB->GM）。参考[asc_copy_gm2ub/asc_copy_ub2gm](../../vector_datamove/数据搬运导览/GM与UB数据搬运.md#ZH-CN_TOPIC_0000002382908021)、[asc_copy_gm2l1](../../cube_datamove/数据搬运导览/GM与L1或L0数据搬运.md#ZH-CN_TOPIC_0000002574022813)等章节。

## 高维切分数据搬运

当源或目的操作数在内存中存在固定间隔的非连续分布时，需要使用高维切分模式。C API数据搬运接口通过以下显式标量参数描述分块搬运：

- **n_burst**：待搬运的连续传输数据块个数。
- **len_burst**：每个连续传输数据块的长度。
- **src_gap/dst_gap或src_stride/dst_stride**：相邻连续传输数据块在源端和目的端的间隔。

不同接口及NPU架构版本下，`len_burst`和间隔参数的单位可能是字节或DataBlock（32字节），应以对应接口文档为准。UB内部的`asc_copy`接口则使用`repeat`、`src_block_stride`、`dst_block_stride`、`src_repeat_stride`和`dst_repeat_stride`配置分块与重复搬运。

**适用场景**：Conv、Matmul等算子中常见的分块（Tiling）数据搬运，数据按固定步长在源或目的端非连续分布。参考[asc_copy_gm2ub/asc_copy_ub2gm](../../vector_datamove/数据搬运导览/GM与UB数据搬运.md#ZH-CN_TOPIC_00000023829080211)、[asc_copy_gm2l1](../../cube_datamove/数据搬运导览/GM与L1或L0数据搬运.md#ZH-CN_TOPIC_0000002543262916)等章节。

## 切片数据搬运

切片搬运支持从一个多维Tensor中提取子区域进行搬运。C API通过loop0_size至loop4_size、loop0_lp_count、loop0_rp_count、padding_mode和l2_cache_mode等显式标量参数配置1\~5维搬运、填充与Cache策略。切片搬运本质上是一种特殊的高维非连续搬运。

**适用场景**：从大型特征图中提取ROI（Region of Interest）子区域、Pad模式下提取有效数据区域等。参考[asc_ndim_copy_gm2ub](../../vector_datamove/数据搬运导览/GM与UB数据搬运.md#ZH-CN_TOPIC_0000002568770166)章节。

## 随路格式转换搬运（ND2NZ/DN2NZ）

在昇腾的矩阵计算流程中，数据通常需要从ND（Standard Normal Data，标准数据排列，即NHWC/NCHW等常规格式）转换为NZ（Normal Normal Data，分形矩阵排列，即按小矩阵块组织的行列排布）格式。C API在GM到L1 Buffer的数据搬运中提供随路转换能力，无需额外的转换指令。

- **ND2NZ搬运**：数据从Global Memory搬运到L1 Buffer的同时，将ND格式转换为NZ格式。通过`asc_copy_gm2l1_nd2nz`的维度与stride参数配置源矩阵的分形维度信息。参考[asc_copy_gm2l1_nd2nz](../../cube_datamove/数据搬运导览/GM与L1或L0数据搬运.md#ZH-CN_TOPIC_0000002573902841)章节。
- **DN2NZ搬运**：从深度卷积的DN格式到NZ格式的转换搬运。参考[asc_copy_gm2l1_dn2nz](../../cube_datamove/数据搬运导览/GM与L1或L0数据搬运.md#ZH-CN_TOPIC_0000002573902899)章节。

## 随路量化激活搬运

矩阵计算（Cube单元）的输出结果存放在L0C Buffer中，通常需要经过量化（Quantize）、反量化（Dequantize）、ReLU激活等后处理才能供后续计算使用。`asc_copy_l0c2gm`、`asc_copy_l0c2l1`和`asc_copy_l0c2ub`在搬运L0C Buffer数据的同时，可以按接口能力执行量化类型转换和激活操作，实现“搬运+计算”的融合，大幅减少额外的计算指令开销。

**适用场景**：Matmul/Conv算子中矩阵乘累加结果（float/int32_t）向半精度/int8_t输出的转换与搬出。参考[asc_copy_l0c2gm](../../cube_datamove/数据搬运导览/GM与L1或L0数据搬运.md#ZH-CN_TOPIC_0000002573902843)章节。

## 非对齐数据搬运

标准搬运接口要求源和目的操作数的起始地址满足对齐约束（如UB要求32Byte对齐）。当实际数据长度不满足对齐要求时（例如搬运17个half元素，共34字节，不是32的整数倍），需要根据通路使用`asc_copy_gm2ub_align`、`asc_copy_ub2gm_align`或`asc_copy_gm2l1_align`。接口允许搬运非对齐长度，并可按参数配置填充（Padding）值和填充模式，使搬运后的目的地址满足后续访问要求。

**适用场景**：数据总长度不满足32Byte对齐要求时的搬运，以及需要在搬运时对尾部数据补Pad的场景。参考[asc_copy_gm2ub_align](../../vector_datamove/数据搬运导览/GM与UB数据搬运.md#ZH-CN_TOPIC_0000001894460401)、[asc_copy_gm2l1_align](../../cube_datamove/数据搬运导览/GM与L1或L0数据搬运.md#ZH-CN_TOPIC_0000002543262891)等章节。

## UB内部搬运（asc_copy）

`asc_copy`是Unified Buffer内部专用的数据搬运指令，源操作数和目的操作数均位于Unified Buffer。与`asc_copy_ub2ub`不同，`asc_copy`支持mask操作（可以按位控制哪些元素参与搬运）和DataBlock间隔控制，适用于矢量计算内部的数据重排和中间结果暂存。参考[asc_copy（UBToUB连续数据搬运）](../../vector_datamove/数据搬运导览/UB与UB数据搬运.md#ZH-CN_TOPIC_0000002575088175)、[asc_copy（UBToUB掩码式高维数据搬运）](../../vector_datamove/数据搬运导览/UB与UB数据搬运.md#ZH-CN_TOPIC_0000002575088175)等章节。

## 矩阵分形搬运

`asc_copy_l12l0a`和`asc_copy_l12l0b`是专用于矩阵计算通路的2D/3D格式分形搬运接口，负责将L1中的矩阵数据按照Cube计算单元所需的特殊分形格式（如NZ排列）搬运到L0A Buffer/L0B Buffer。这类接口可以伴随转置操作（`asc_copy_l12l0a_transpose`、`asc_copy_l12l0b_transpose`），并支持稀疏权重矩阵的加载（`asc_copy_l12l0b_sparse`）。参考[L1ToL0A 2D格式分形矩阵搬运](../../cube_datamove/数据搬运导览/L1与L0数据搬运.md#ZH-CN_TOPIC_0000002573902845)、[L1ToL0A 3D格式分形矩阵搬运](../../cube_datamove/数据搬运导览/L1与L0数据搬运.md#ZH-CN_TOPIC_0000002574022819)等章节。

## 多维数据搬运NDDMA（asc_ndim_copy_gm2ub）

NDDMA（N-Dimensional DMA）是一种更灵活的按维度配置的数据搬运方式，支持Global Memory到Unified Buffer之间的多维搬运。与通过`n_burst`、`len_burst`和间隔参数配置的分块搬运不同，`asc_ndim_copy_gm2ub`使用C API的显式参数配置1\~5维搬运：

- **loop0_size至loop4_size**：配置各维的处理元素个数。
- **loop0_lp_count/loop0_rp_count**：配置最内层左侧和右侧的Padding元素个数。
- **padding_mode**：选择常数填充或最近值填充；常数填充值由`asc_set_ndim_pad_value`设置。
- **l2_cache_mode**：配置数据在L2 Cache中的管理策略。

各维的源和目的步长通过`asc_set_ndim_loop0_stride`至`asc_set_ndim_loop4_stride`设置，用于实现跨步搬运、Transpose转置、Broadcast广播等效果。具体参数范围和缓存一致性约束以`asc_ndim_copy_gm2ub`接口文档为准。

**适用场景**：需要自由控制多维搬运模式的场景，如多维数据的Padding填充、Transpose转置搬运、Broadcast广播搬运、Slice子矩阵截取等。参考[asc_ndim_copy_gm2ub](../../vector_datamove/数据搬运导览/GM与UB数据搬运.md#ZH-CN_TOPIC_0000002544407954)章节。
