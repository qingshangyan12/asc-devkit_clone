# 数据搬运概念

Ascend C API通过带有地址空间限定符的指针描述源操作数和目的操作数。常用限定符包括Global Memory对应的`__gm__`、Unified Buffer对应的`__ubuf__`、L1 Buffer对应的`__cbuf__`、L0A Buffer对应的`__ca__`、L0B Buffer对应的`__cb__`、L0C Buffer对应的`__cc__`、BiasTable Buffer对应的`__bt__`和Fixpipe Buffer对应的`__fbuf__`。接口声明中的限定符决定了该参数允许使用的存储位置，不能用基础API中的`TPosition`值替代。

## 连续搬运

连续搬运接口通常使用`dst`、`src`和`size`三个参数。`size`表示搬运字节数，不表示元素个数。调用时应根据数据类型计算字节数，例如搬运128个`half`元素时，`size`应为`128 * sizeof(half)`。

## 分块搬运

部分接口提供`n_burst`、`len_burst`及源、目的间隔参数，用于描述多段非连续数据。各参数的单位和取值范围与接口及NPU架构有关，应以对应单接口文档为准，不能套用其他编程接口的参数模型。

## 多维搬运

[asc_ndim_copy_gm2ub](../../vector_datamove/asc_ndim_copy_gm2ub.md)支持GM->UB的多维搬运。调用前通过以下配置接口设置各维度的步长及Padding信息：

- [asc_set_ndim_loop_stride](../../vector_datamove/asc_set_ndim_loop_stride.md)：设置各维度源、目的步长。
- [asc_set_ndim_pad_count](../../vector_datamove/asc_set_ndim_pad_count.md)：设置首维左右Padding元素个数。
- [asc_set_ndim_pad_value](../../vector_datamove/asc_set_ndim_pad_value.md)：设置Padding填充值。

`asc_ndim_copy_gm2ub`的`loop0_size`至`loop4_size`用于描述各维度循环次数，`loop0_lp_count`和`loop0_rp_count`用于描述首维Padding。多维配置通过公开的标量参数和配置接口完成。

多维搬运的L2 Cache策略通过`l2_cache_mode`配置。其他缓存维护要求以[asc_ndim_copy_gm2ub](../../vector_datamove/asc_ndim_copy_gm2ub.md)及相关缓存接口文档为准。

## 非对齐搬运

[asc_copy_gm2ub_align](../../vector_datamove/asc_copy_gm2ub_align/asc_copy_gm2ub_align.md)和[asc_copy_ub2gm_align](../../vector_datamove/asc_copy_ub2gm_align/asc_copy_ub2gm_align.md)用于处理不能直接满足普通搬运对齐要求的场景。不同NPU架构提供的重载和Padding、stride、L2 Cache控制参数不同，调用前应进入对应架构的单接口文档核对完整原型。

## 同步要求

数据搬运和计算位于不同流水时，应根据真实的数据依赖使用[asc_sync_notify/asc_sync_wait](../../sync/asc_sync_notify.md)建立流水间同步。相同流水上存在地址重叠时，按单接口约束使用[asc_sync_pipe](../../sync/asc_sync_pipe.md)。仅在确实需要等待当前核所有流水完成时使用[asc_sync](../../sync/asc_sync.md)。
