# 总体约束说明

本节汇总DAV_3510数据搬运的通用检查项。具体接口文档给出的对齐、容量、参数取值或执行范围更严格时，以具体接口为准。

## 地址对齐

| 存储单元 | 架构基线对齐 |
| --- | --- |
| GM | 1字节 |
| UB、L1 | 32字节 |
| L0A、L0B | 512字节 |
| L0C | 64字节 |
| BiasTable、Fixpipe Buffer | 64字节 |

架构基线不等同于每个接口的合法对齐。例如L1到Fixpipe Buffer的随路量化参数目的地址要求128字节对齐；Reg加载、存储的部分元素或掩码模式允许按数据类型、8字节或16字节对齐。

## 参数单位

- `size`通常以字节为单位，但部分接口会向下取整到硬件搬运粒度。
- `len_burst`、`src_gap`、`dst_gap`可能以32字节DataBlock、64字节或分形为单位。
- Reg接口的偏移可能以元素、字节或DataBlock为单位。

同名参数在不同接口中的单位不一定相同。计算地址跨度时，应先按接口文档将参数换算为字节。

## 容量与越界

DAV_3510的UB容量上限为256 KB，L1为512 KB，L0A和L0B各为64 KB，L0C为256 KB，BiasTable为4 KB。用户实际可用UB空间会受编译选项和编程场景影响。所有源、目的地址加实际访问跨度均不得超过已分配范围；涉及随路转换时，应按转换后的目的数据量检查边界。

## 执行范围

- Cube搬运接口通常仅在AIC生效，Vector搬运接口通常仅在AIV生效。
- Reg加载、存储仅在AIV的Vector Function（`__simd_vf__`标记的函数）内使用。
- 通过宏区分AIC和AIV代码路径时，应确保接口只在其支持的路径中执行。

## 地址重叠与同步

源、目的有效搬运区域是否允许重叠由具体接口决定。例如DAV_3510的UB内部复制要求实际搬运的源、目的DataBlock不重叠。不要假定硬件搬运等价于支持重叠区域的`memmove`。

不同PIPE上的生产者与消费者可以并行执行。存在读写依赖时，需要使用[同步控制](../../sync/system_sync_overview.md)接口建立顺序；Reg指令间存在UB地址冲突时，按对应Reg接口要求使用`asc_mem_bar`。不要仅依赖源码书写顺序推断跨流水执行顺序。

## 初始化与配置状态

- Kernel入口建议先调用[asc_init](../../utils/sys_init/asc_init.md)，清理可能由前序任务保留的控制状态。
- 搬运配置接口通常影响其后的搬运指令。复用硬件配置前，应确认循环次数、步长、Padding和转换参数已按当前任务设置。
- 多核可能读取同一块GM且该数据可能被其他核更新时，应在NDDMA前按[asc_ndim_copy_dci](../../vector_datamove/asc_ndim_copy_dci.md)要求刷新NDDMA DataCache。

存储空间和C API通用规则请参见[通用说明和约束](../../general_description_and_constraints.md)。
