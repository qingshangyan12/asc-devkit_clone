# 数据搬运概念

C API通过不同函数原型直接表达搬运形态。选择接口时，先确定源、目的存储单元，再根据数据是否连续、地址是否对齐、是否需要格式转换选择具体模式。

## 连续数据搬运

连续搬运从起始地址开始处理一段连续数据，通常只需传入总字节数`size`。适合源、目的均连续且不需要跨行跳转的场景。`size`是否需要按32字节或其他粒度对齐，应以具体接口文档为准。

## 高维切分数据搬运

高维切分搬运通常使用`n_burst`、`len_burst`以及源、目的间隔描述多个数据块。部分GM到L1、GM与UB接口还通过配置接口设置外层循环次数和步长。参数单位可能是字节、32字节DataBlock或分形块，不能在不同接口间直接套用。

## 随路转换

部分搬运通路可在传输过程中完成格式或数值转换，减少额外计算：

- GM到L1支持ND2NZ、DN2NZ等格式转换。
- L0C搬出支持NZ2ND、NZ2DN、量化、类型转换或随路ReLU等能力，具体组合受接口约束。
- L1到BiasTable可将`bfloat16_t`转换为`float`，并可按配置处理`half`到`float`的转换。

随路转换会改变目的端数据量、排布或对齐要求，地址范围应按转换后的结果计算。

## 非对齐数据搬运

GM与UB、GM到L1均提供专用的非对齐接口。非对齐接口用于起始地址或有效长度不满足普通接口对齐要求的场景，可能通过Normal或Compact模式处理边界。不要通过扩大普通搬运范围来访问未分配地址；应选择`*_align`接口并遵守其填充值、有效数据长度和尾块约束。

Reg与UB之间也提供非对齐加载、存储接口。此类接口使用`vector_load_unalign`或`vector_store_unalign`保存中间状态，要求按规定的调用序列复用同一个非对齐寄存器。

## 分形数据搬运

矩阵计算的数据通常以分形为基本粒度。GM到L1的二维分形搬运，以及L1到L0A/L0B的二维、三维、转置或MX搬运，均要求源数据布局与目的分形匹配。分形大小和步长单位由数据类型及接口形态决定，应结合矩阵输入内存结构说明和具体接口参数计算。

## NDDMA

[asc_ndim_copy_gm2ub](../../vector_datamove/asc_ndim_copy_gm2ub.md)支持最多五维的GM到UB搬运，可配置各维循环步长和Padding。多核可能读取同一块GM且该数据可能被其他核更新时，应在NDDMA前按[asc_ndim_copy_dci](../../vector_datamove/asc_ndim_copy_dci.md)文档刷新NDDMA DataCache。NDDMA仅覆盖GM到UB方向，不能代替其他存储单元之间的搬运接口。
