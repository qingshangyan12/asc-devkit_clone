# 原子操作同类接口约束说明一致性对比分析

> 根据 `同类接口约束说明一致性要求.md`，将原子操作接口分为 **3 大操作 × 2 种数据类型 = 6 类**，同类接口的约束说明部分必须保持一致。
>
> 约定：<span style="color:red">**红色文字**</span> 表示该类内部不一致之处。

---

## 1. 原子累加 - 整数类型

**涉及接口**：`asc_set_atomic_add_int`、`asc_set_atomic_add_int16`、`asc_set_atomic_add_int8`

### 通用约束

1. 本接口设置的控制寄存器位在AIC与AIV上均生效，AIC与AIV均可调用。
2. 调用本接口时不需要手动插入同步，本接口走Scalar流水写配置寄存器，与后续搬运指令分属不同流水，本接口与紧邻的后续搬运指令之间的同步由硬件保证。
3. 本接口仅对后续目的地址为Global Memory的搬出搬运指令生效，对其他搬运动作不生效。 <span style="color:red">⚠️ **add_int 未提及此条约束**</span>
4. 后续搬出搬运指令的累加数据类型需与本接口设置的数据类型一致，否则累加结果与预期不符（硬件不报错）。 <span style="color:red">⚠️ **add_int 未提及此条约束**</span>
5. 本接口配置写入后对后续所有目的地址为Global Memory的搬运指令生效，直至再次调用本类原子操作配置接口覆盖配置；调用后如需切换为其他数据类型的原子累加、改用原子比较接口或关闭原子操作，须显式调用对应接口覆盖配置。
6. 开启原子累加前的普通搬运指令与开启原子操作后的搬运指令之间若发生乱序，会导致Global Memory上已完成原子累加的数据被普通搬运的数据覆盖。若需保证确定性的累加顺序，开发者需在开启原子累加的指令前插入核内同步，确保Global Memory初始值符合预期。
7. 头文件`atomic.h`不能与编译选项`--enable-simt`同时使用，否则编译报错。

### 确定性计算约束

1. 整数加法满足结合律，多条带随路原子操作的搬运指令乱序不会因结合律问题产生非确定性结果；但仍需保证指令执行顺序符合预期以避免数据覆盖，若需保证确定性的累加顺序，开发者需在相邻两次带随路原子累加的搬运指令之间插入核内同步。
2. 当整个原子累加跨多个核执行时，各核累加操作由硬件保证原子性，但累加顺序不可预期；如需控制多核间的累加顺序，须通过核间同步方案确保各核搬运按预期顺序执行。 <span style="color:red">⚠️ **add_int 未提及此条约束**</span>

### 差异汇总

| 不一致项 | 缺失文件 |
|----------|----------|
| "仅对GM搬出生效" 约束 | `asc_set_atomic_add_int.md` |
| "累加数据类型一致性" 约束 | `asc_set_atomic_add_int.md` |
| "多核同步" 约束 | `asc_set_atomic_add_int.md` |

## 2. 原子累加 - 浮点类型

**涉及接口**：`asc_set_atomic_add_float`、`asc_set_atomic_add_bfloat`、`asc_set_atomic_add_float16`

### 通用约束

1. 本接口仅对后续目的地址为Global Memory的搬出搬运指令生效，对其他搬运动作不生效。
2. 调用本接口时不需要手动插入同步，本接口与其他指令之间的同步由硬件保证。
3. 后续搬出搬运指令的累加数据类型需与本接口设置的数据类型一致，否则累加结果与预期不符。
4. 如需在累加完成后关闭随路原子操作，需调用配套接口关闭原子操作状态，否则后续所有搬出到Global Memory的搬运指令都会执行原子累加。

<span style="color:red">⚠️ **AIC/AIV 生效范围不一致**</span>

| 接口 | 生效范围描述 |
|------|-------------|
| `add_float` | **未提及** |
| `add_bfloat` | "本接口**仅在AIC上生效**，非AIC调用直接返回。" |
| `add_float16` | **未提及** |

<span style="color:red">⚠️ **add_float16 通用约束结构不同**：其他两个接口将"开启原子累加前的乱序覆盖"和"浮点不满足结合律"放在确定性计算约束中，add_float16 将这两条放在了通用约束中。</span>

<span style="color:red">⚠️ **add_float16 多了 "本接口配置仅作用于随路原子操作，不会对后续搬运指令的搬运行为本身产生影响，也不会单独触发对Global Memory的访问。"**</span>

### 确定性计算约束

1. 当原子累加的数据类型为浮点数且带随路原子操作的搬运指令达到3条及以上时，由于浮点数加法不满足结合律，搬运指令乱序会导致Global Memory上最终累加结果与预期存在偏差。若需保证确定性计算，开发者需在多条带随路原子操作的搬运指令之间插入核内同步，控制搬运指令的执行顺序。
2. 开启原子累加前的普通搬运指令与开启原子操作的搬运指令之间若发生乱序，会导致Global Memory上已完成原子累加的数据被普通搬运的数据覆盖。若需保证确定性计算，开发者需在开启原子累加的指令前插入核内同步，确保Global Memory初始值符合预期。 <span style="color:red">⚠️ **add_float16 将此项放在通用约束中**</span>
3. 当整个原子累加跨多个核执行时，需通过核间同步控制各核执行顺序，相关同步方案按纯Vector算子、纯Cube算子、Mix算子三种场景分别选择。

<span style="color:red">⚠️ **add_float16 的确定性计算约束结构与 float/bfloat 不同**，且 add_float16 没有独立的"确定性计算约束"子标题，而是将相关内容写入了"通用约束"中。</span>

### 差异汇总

| 不一致项 | 详情 |
|----------|------|
| AIC/AIV 生效范围 | `float`/`float16` 未提及，`bfloat` 写"仅AIC生效"，三者矛盾 |
| 约束章节结构 | `add_float16` 无独立"确定性计算约束"子标题，混入"通用约束" |
| 多余内容 | `add_float16` 多一条"不会单独触发对GM的访问" |

## 4. 原子取最小值 - 浮点类型

**涉及接口**：`asc_set_atomic_min_float`、`asc_set_atomic_min_bfloat`、`asc_set_atomic_min_float16`

### 通用约束

1. 本接口设置的控制寄存器位在AIC与AIV上均生效，AIC与AIV均可调用。 <span style="color:red">⚠️ **min_float16 未提及此条约束**</span>
2. 本接口仅对后续目的地址为Global Memory的搬出搬运指令生效，对其他搬运动作不生效。
3. 调用本接口时不需要手动插入同步，本接口与后续搬运指令之间的同步由硬件保证。
4. 后续搬出搬运指令的比较数据类型需与本接口设置的数据类型一致，否则比较结果与预期不符。
5. 调用本接口后 / 本接口配置写入后，后续所有目的地址为Global Memory的数据搬运均执行原子取最小值，直至调用配套接口关闭原子操作状态 / 覆盖配置。
6. 开启原子取最小值前的普通搬运指令与开启原子操作的搬运指令之间若发生乱序，会导致Global Memory上已完成原子比较的数据被普通搬运的数据覆盖。若需保证确定性计算，开发者需在开启原子取最小值的指令前插入核内同步，确保Global Memory初始值符合预期。

<span style="color:red">⚠️ **min_float16 多了 "头文件atomic.h不能与编译选项--enable-simt同时使用，否则编译报错。"**</span>

### 确定性计算约束

<span style="color:red">⚠️ **重大不一致 - NaN/±0 约束**</span>

| 接口 | 确定性计算约束核心描述 |
|------|----------------------|
| `min_float` | "由于浮点数比较在**NaN / ±0 / 符号位**等场景下不满足完全等价关系，搬运指令乱序可能导致Global Memory上最终结果与预期存在偏差。" |
| `min_bfloat` | "由于浮点数比较在**NaN / ±0 / 符号位**等场景下不满足完全等价关系，搬运指令乱序可能导致Global Memory上最终结果与预期存在偏差。" |
| `min_float16` | "**最小值运算满足结合律与交换律**，本接口原子比较数据类型为`half`，多条带随路原子操作的搬运指令乱序不会因结合律问题产生非确定性结果" |

<span style="color:red">⚠️ **min_float / min_bfloat 声明 NaN/±0 会导致非确定性；min_float16 却声明满足结合律与交换律。两者矛盾，需确认 half 类型的硬件行为并统一描述。**</span>

多核同步约束：
- `min_float` / `min_bfloat`：需通过核间同步控制各核执行顺序，相关同步方案按纯Vector算子、纯Cube算子、Mix算子三种场景分别选择。
- `min_float16`：各核比较操作由硬件保证原子性，但比较顺序不可预期；如需控制多核间的比较顺序，须通过核间同步方案确保各核搬运按预期顺序执行。

### 差异汇总

| 不一致项 | 详情 |
|----------|------|
| AIC/AIV 生效范围 | `min_float16` 未提及 |
| NaN/±0 vs 结合律 | `float`/`bfloat` 强调 NaN/±0 非确定性；`float16` 声称满足结合律 — **根本矛盾** |
| `--enable-simt` 互斥 | `min_float16` 有，`float`/`bfloat` 无 |
| 多核同步方案描述 | `float`/`bfloat` 按 Vector/Cube/Mix 三种场景；`float16` 为通用描述 |

## 总结

### 一致 ✅
- **原子取最小值 - 整数**（第 3 类）
- **原子取最大值 - 整数**（第 5 类）

### 存在不一致 ⚠️（4 类）

| 类别 | 不一致严重程度 | 核心问题 |
|------|:---:|------|
| 原子累加 - 整数 | 低 | `add_int` 缺失 3 条约束 |
| 原子累加 - 浮点 | 中 | AIC/AIV 生效范围矛盾；`float16` 结构不同 |
| 原子取最小值 - 浮点 | **高** | `float`/`bfloat` 写 NaN/±0 非确定性 vs `float16` 写满足结合律 — **根本矛盾** |
| 原子取最大值 - 浮点 | **高** | `float` 写 NaN/±0 非确定性 vs `bfloat` 缺失此条 vs `float16` 写满足结合律 — **三者矛盾** |

### 建议优先处理

1. **确认 half/bfloat16 浮点 min/max 的硬件行为**：究竟是否受 NaN/±0 影响？如果受影响，`float16` 的 min/max 文档需改为与 `float` 一致的 NaN/±0 约束；如果不受影响，`float` 文档也需补充说明与 half/bfloat 的区别。
2. **统一 AIC/AIV 生效范围描述**：需确认各接口在 AIC 和 AIV 上的实际支持情况并统一。
3. **补充缺失约束**：整数累加的 `add_int`、浮点最大值的 `max_bfloat` 需补齐。
4. **统一 `--enable-simt` 互斥约束**：`float16` 系列有、`float`/`bfloat` 系列无，需统一。

## 附：全部原子操作接口视为一类的统一约束说明

> 本章节将全部 18 个 `asc_set_atomic_*` 接口视为同一大类，提取所有通用约束项合并去重。
> 确定性计算约束因整数与浮点有本质差异，分开展示。
> 约定：<span style="color:red">**红色文字**</span> 表示该约束仅在部分接口文档中出现，其余接口缺失。

### 涉及接口

`asc_set_atomic_add_int`、`asc_set_atomic_add_int16`、`asc_set_atomic_add_int8`、`asc_set_atomic_add_float`、`asc_set_atomic_add_bfloat`、`asc_set_atomic_add_float16`、`asc_set_atomic_min_int`、`asc_set_atomic_min_int16`、`asc_set_atomic_min_int8`、`asc_set_atomic_min_float`、`asc_set_atomic_min_bfloat`、`asc_set_atomic_min_float16`、`asc_set_atomic_max_int`、`asc_set_atomic_max_int16`、`asc_set_atomic_max_int8`、`asc_set_atomic_max_float`、`asc_set_atomic_max_bfloat`、`asc_set_atomic_max_float16`

### 通用约束（应全部接口一致）

1. 本接口设置的控制寄存器位在AIC与AIV上均生效，AIC与AIV均可调用。 <span style="color:red">⚠️ **缺失接口**：`add_float`、`add_float16`、`min_float16`、`max_bfloat`、`max_float16`、`add_bfloat`（`add_bfloat` 写的是"仅在AIC上生效"，与其他接口矛盾）</span>
2. 本接口仅对后续目的地址为Global Memory的搬出搬运指令生效，对其他搬运动作不生效。 <span style="color:red">⚠️ **缺失接口**：`add_int`</span>
3. 调用本接口时不需要手动插入同步，本接口走Scalar流水写配置寄存器，与后续搬运指令分属不同流水，本接口与紧邻的后续搬运指令之间的同步由硬件保证。
4. 后续搬出搬运指令的操作数据类型需与本接口设置的数据类型一致，否则操作结果与预期不符（硬件不报错）。 <span style="color:red">⚠️ **缺失接口**：`add_int`</span>
5. 本接口配置写入后对后续所有目的地址为Global Memory的搬运指令生效，直至再次调用本类原子操作配置接口覆盖配置；调用后如需切换为其他数据类型的原子操作、改用其他原子操作配置或关闭原子操作，须显式调用对应接口覆盖配置。
6. 开启原子操作前的普通搬运指令与开启原子操作后的搬运指令之间若发生乱序，会导致Global Memory上已完成原子操作的数据被普通搬运的数据覆盖。若需保证确定性的执行顺序，开发者需在开启原子操作的指令前插入核内同步，确保Global Memory初始值符合预期。
7. 头文件`atomic.h`不能与编译选项`--enable-simt`同时使用，否则编译报错。 <span style="color:red">⚠️ **缺失接口**：`add_float`、`add_bfloat`、`add_float16`、`min_float`、`min_bfloat`、`max_float`、`max_bfloat`</span>

### 确定性计算约束（按数据类型区分）

#### 整数类型（add/min/max 的 int / int16 / int8，共 9 个接口）

1. 整数加法/取最小值/取最大值满足结合律，多条带随路原子操作的搬运指令乱序不会因结合律问题产生非确定性结果；但仍需保证指令执行顺序符合预期以避免数据覆盖，若需保证确定性的执行顺序，开发者需在相邻两次带随路原子操作的搬运指令之间插入核内同步。 <span style="color:red">⚠️ **缺失接口**：`add_int`（多核同步约束缺失）</span>
2. 当整个原子操作跨多个核执行时，各核操作由硬件保证原子性，但执行顺序不可预期；如需控制多核间的执行顺序，须通过核间同步方案确保各核搬运按预期顺序执行。 <span style="color:red">⚠️ **缺失接口**：`add_int`</span>

#### 浮点类型（add/min/max 的 float / bfloat / float16，共 9 个接口）

1. 当原子操作的数据类型为浮点数且带随路原子操作的搬运指令达到3条及以上时，由于浮点数加法/比较在NaN / ±0 / 符号位等场景下不满足完全等价关系，搬运指令乱序可能导致Global Memory上最终结果与预期存在偏差。若需保证确定性计算，开发者需在多条带随路原子操作的搬运指令之间插入核内同步，控制搬运指令的执行顺序。 <span style="color:red">⚠️ **缺失/矛盾接口**：`min_float16`（写成"满足结合律与交换律"）、`max_float16`（写成"满足结合律与交换律"）、`max_bfloat`（完全缺失此条）</span>
2. 开启原子操作前的普通搬运指令与开启原子操作的搬运指令之间若发生乱序，会导致Global Memory上已完成原子操作的数据被普通搬运的数据覆盖。若需保证确定性计算，开发者需在开启原子操作的指令前插入核内同步，确保Global Memory初始值符合预期。
3. 当整个原子操作跨多个核执行时，需通过核间同步控制各核执行顺序，相关同步方案按纯Vector算子、纯Cube算子、Mix算子三种场景分别选择。 <span style="color:red">⚠️ **描述不一致**：`float16` 系列（min_float16、max_float16、add_float16）写的是通用版描述（"各核操作由硬件保证原子性，但顺序不可预期"），而非按三种场景的描述。</span>
