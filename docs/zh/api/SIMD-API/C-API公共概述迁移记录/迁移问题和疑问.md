# 基础API公共概述迁移问题和疑问

## 记录原则

公共概述中的“对应”仅表示功能导航或同一CCE实现证据，不表示两个公开API的原型、参数、数据类型、架构支持或性能完全等价。使用时以目标C API文档为准。

## 已确认的差异

| 项目 | 现象与处理 |
|---|---|
| Basic API对象模型与C API数组模型 | Basic API常用`LocalTensor`、`TPosition`、`TPipe/TQue`和模板参数；C API以地址空间限定数组、裸指针和显式参数表达。公共概述保留存储/流水概念，但全部链接改指向C API，未转换对象接口。 |
| 同一CCE不等于公开API等价 | `vadd`、`vsub`、`mad`、`load_cbuf_to_ca/cb`等可建立直接或指令族映射；格式转换、量化、对齐、B64/complex和复合计算可能包含多条CCE或软件分支。索引以`exact/family/composite/candidate`标注，不应只按名称迁移调用代码。 |
| `dav-3510`数据通路差异 | 基础API导览指出3510删除L1 Buffer->GM和GM->L0A Buffer/L0B Buffer通路；C API的[asc_copy_l12gm](../C-API/cube_datamove/asc_copy_l12gm.md)也标为3510不支持。公共导览保留该限制，不提供替代的“直接L1 Buffer->GM”映射。 |
| 文档与实现优先级 | 当文档产品支持与实现中可见的封装/指令发生冲突时，公共概述遵循文档声明；实现只用于证明当前代码版本的CCE关系。 |
| 图片文件名 | 全部迁移图片链接均已验证可解析到`docs/zh/api/figures/`下的实际文件。源文档已有11个图片文件名包含中文或大写字母，本次保留原资源名和链接，未复制或重命名共享图片资源。 |

## 未建立C API对应的基础API章节

以下内容主要是Basic API的框架、对象管理或其他编程模型能力，未找到以同一CCE指令为依据的C API公共章节，因此仅在覆盖清单中保留导航，不强行迁移为C API功能：

- 资源管理（`TPipe`、`TQue`、`TBuf`、`LocalMemAllocator`等）。
- Kernel Tiling、工具接口和TensorAPI数据结构。
- 调试接口、CPU孪生调试和上板打印。
- Cube分组管理（ISASI）、GroupBarrier、KfcWorkspace等。

## 待后续确认

- 是否需要把C API尚未覆盖的Basic API框架能力另建“非C API能力说明”目录；当前不建议放入C API导航，以免暗示存在可调用的C API。
- 复合、软实现和候选映射若用于自动代码迁移，仍需逐API补充数据类型、掩码、对齐、同步和架构支持规则；现有CCE索引只适合作为检索入口。
- 源基础API文档与当前工作仓可能不处于同一提交版本；如后续需要逐段文字级同步，应先锁定两个仓的版本并重新核对链接和产品支持。
