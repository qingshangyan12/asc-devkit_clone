# Host侧空指针校验接口最新设计方案

## 1. 设计目标

新增Host侧通用条件检查接口`ASC_HOST_CHECK_CONDITION(condition, violation_message)`，统一C API调用示例中的条件检查方式。接口归入Utils API的调测接口目录。

设计目标：使用带Host侧前缀的公共宏，统一失败输出和处理方式，避免与其他检查宏冲突，并且只检查Host侧资源申请结果。

## 2. 接口设计

公共接口名称为：

```cpp
ASC_HOST_CHECK_CONDITION(ptr != nullptr, "error ptr is nullptr");
```

建议头文件：

```text
include/utils/debug/check_condition.h（公共声明）
impl/utils/debug/check_condition_impl.h（内部实现）
```

头文件只面向 Host 侧代码，不引入 Device 侧 Tensor、Buffer 或 Kernel 类型。

建议使用宏保留指针表达式、源文件名和行号：

```cpp
#define ASC_HOST_CHECK_CONDITION(condition, violation_message) \
    AscendC::check_condition((condition), (violation_message), __FILE__, __LINE__)
```

接口行为如下：

- `condition`为真时不输出信息，调用方继续执行；
- `condition`为假时输出自定义错误信息、源文件名和行号；
- 校验失败时调用 `std::exit(EXIT_FAILURE)` 终止当前示例进程，避免继续使用无效资源；
- `ptr` 表达式只求值一次，不允许在表达式中执行有副作用的操作。

失败输出示例：

```text
ASC_HOST_CHECK_CONDITION failed: error src0_device is nullptr, file=asc_add.cpp, line=123
```

### 2.4 参考代码实现

建议在公共头文件`include/utils/debug/check_condition.h`中提供声明和宏，在内部头文件`impl/utils/debug/check_condition_impl.h`中提供Host侧实现：

```cpp
#ifndef IMPL_UTILS_DEBUG_CHECK_CONDITION_IMPL_H
#define IMPL_UTILS_DEBUG_CHECK_CONDITION_IMPL_H

#include <cstdlib>
#include <cstdio>

namespace AscendC {

inline void check_condition(bool condition, const char *violation_message,
    const char *file, int line)
{
    if (condition) {
        return;
    }
    std::fprintf(stderr, "ASC_HOST_CHECK_CONDITION failed: %s, file=%s, line=%d\n",
        violation_message, file, line);
    std::exit(EXIT_FAILURE);
}

} // namespace AscendC

#endif
```

实现要求：

- `check_condition`只接收Host侧条件和告警信息，不依赖Device侧类型；
- 宏参数在调用点只求值一次；
- 失败日志输出指针表达式、文件名和行号；
- 使用 `std::exit(EXIT_FAILURE)` 终止当前示例，避免依赖调用函数的返回类型。`EXIT_FAILURE` 的具体数值由 C++ 标准库实现定义，接口不得依赖其具体数值；
- 头文件应提供 C++ 编译环境下的类型检查，禁止将该接口用于 Device 侧编译单元。

如果需要支持带类型的对象指针，宏中的 `static_cast<const void *>(ptr)` 应在实际编译验证后确定；对于不能直接转换为 `const void *` 的句柄类型，应由接口实现提供对应的重载或明确排除，不应通过隐式转换规避类型检查。

## 4. 调用范围

Host侧代码中，凡是由内存申请、Stream/Event创建等接口通过输出参数返回，且后续参与数据搬运、Kernel启动、同步、释放或销毁的指针或句柄，都需要在申请成功后立即调用`ASC_HOST_CHECK_CONDITION(ptr != nullptr, violation_message)`。

以 `asc_add.md` 为例，`src0_device`、`src1_device` 和 `dst_device` 均应在申请后调用：

```cpp
ASC_HOST_CHECK_CONDITION(src0_device != nullptr, "error src0_device is nullptr");
ASC_HOST_CHECK_CONDITION(src1_device != nullptr, "error src1_device is nullptr");
ASC_HOST_CHECK_CONDITION(dst_device != nullptr, "error dst_device is nullptr");
```

普通栈变量、常量、标量、`std::vector` 等 RAII 对象本身，以及 Device 侧 `LocalTensor`、`GlobalTensor`、UB 数组等 Kernel 内部对象不需要调用。

## 5. 示例迁移方案

改造 `asc_add.md` 时：

1. 删除文档内本地定义的空指针检查宏。
2. 引入`check_condition.h`。
3. 在三个设备指针申请成功后立即调用公共接口。
4. 保持数据拷贝、Kernel 启动和资源释放流程不变。
5. 其他 C API 文档按相同规则逐步迁移。

| TC01 | 条件为真时检查通过 | 传入`ptr != nullptr`等成立条件 | 不输出错误信息，后续代码正常执行 |
| TC02 | 条件为假时检查失败 | 传入`ptr == nullptr`等不成立条件 | 标准错误流输出自定义错误信息、源文件名和行号，当前示例以`EXIT_FAILURE`退出 |

| TC04 | 申请失败后的保护 | 构造内存申请失败场景，使返回指针为空 | 校验立即失败，不继续执行数据搬运或 Kernel 启动 |
| TC05 | 资源句柄校验 | 对Stream或Event创建接口返回的句柄调用`ASC_HOST_CHECK_CONDITION` | 非空句柄通过，空句柄按统一格式报告并以`EXIT_FAILURE`退出 |

| TC08 | 普通对象不增加校验 | 检查栈数组、标量、常量和 `std::vector` 相关代码 | 不增加无意义的空指针校验，代码行为不变 |

| TC11 | 公共头文件实现可编译 | 编译仅包含`check_condition.h`的Host侧最小程序 | 头文件、内部函数和宏展开均可编译，条件为真时正常运行 |

### 6.1 UT目录与接入方式

新增公共头文件时，需要同步新增以下UT目录和测试文件：

```text
tests/api/utils/debug/CMakeLists.txt
tests/api/utils/debug/test_check_condition.cpp
```

并在`tests/api/utils/CMakeLists.txt`中增加`debug`子目录。该接口为纯Host侧逻辑，UT不需要启动Device Kernel，也不需要按NPU架构重复验证。空指针分支会退出进程，使用GoogleTest死亡测试验证退出状态和标准错误输出，不在普通测试进程中直接触发。

UT至少覆盖以下分支：

- 传入成立条件时正常返回，不产生错误输出；
- 传入不成立条件时以`EXIT_FAILURE`退出，错误输出包含自定义错误信息、源文件名和行号；
- 使用带计数副作用的指针表达式验证宏参数只求值一次；
- 使用不同对象指针类型验证到`const void *`的合法转换；
- 对不支持转换为`const void *`的句柄类型执行编译检查，确认接口行为与文档约束一致。
