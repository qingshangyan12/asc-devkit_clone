# Ascend C资料贡献指南

## 概述

Ascend C资料体系包含四份核心文档，开发者可以通过提交PR对资料进行改进和贡献：

| 文档 | 内容 | 文档目录 |
|------|------|---------|
| 编程指南（含入门教程） | 编程模型、编程范式、编译运行、硬件架构、高级编程 | `docs/guide/编程指南` |
| API参考手册 | 接口参数、约束、示例、API关联 | `docs/api/` |
| 算子实践参考 | 算子实现、性能优化、调优案例 | `docs/guide/算子实践参考/` |
| 跨代迁移兼容性指南 | API兼容策略、架构变更映射、迁移步骤 | `docs/guide/跨代迁移兼容性指南/` |

在阅读本文档前，请确保您已了解昇腾AI处理器硬件架构，学习过Ascend C编程相关文档。推荐先阅读[Ascend C编程指南](https://www.hiascend.com/document/redirect/CannCommunityOpdevAscendC)。

---

## 贡献场景

### 文档纠错

如果您在资料中发现描述错误、参数值不准确、约束遗漏等问题：

1. 按照社区指引新建 `Documentation | 文档反馈` 类Issue，指出对应文档的问题
2. 在评论框中输入 `/assign` 或 `/assign @yourself` 将该Issue分配给您
3. 修复后提交PR

### 文档补充

如果您发现某些内容在资料中缺失或不够完整（如缺少示例、缺少约束说明、缺少关联API说明）：

1. 新建 `Requirement | 需求建议` 类Issue，描述需要补充的内容
2. 按照本指南的"编写规范"完成补充
3. 提交PR

### 性能优化案例贡献

如果您有Ascend C算子性能优化的实战经验愿意分享：

1. 参考 `算子实践参考/优秀实践/` 目录下已有的调优案例结构
2. 按照本指南的"性能优化案例编写规范"编写文档
3. 提交PR

## 编写规范

Ascend C资料遵循《Ascend C资料DFX设计文档》的三个维度要求：可获取性、可读性、完备性。以下是针对常见编写场景的具体规范。

### 通用规范

| 规则 | 要求 | 错误示例 | 正确示例 |
|------|------|---------|---------|
| 术语分层 | 高层章节用抽象名，低层章节首次出现硬件名时关联高层名 | 概述文档直接写"数据通过UB搬入VEC" | 概述文档写"数据从外部存储搬入片上存储"，低层文档写"数据从Global Memory搬入UB（片上存储）" |
| 易混概念区分 | 名称相近的概念必须用对比表区分，不能靠读者自行推断 | 只说"四步法"不区分 Tiling流程和TPipe流水 | 用表格区分：四步法=编程流程，TPipe四步=流水管理范式 |
| 约束前置醒目 | 硬件约束在概念首次出现时标注，不放在后续章节或仅靠编译报错暴露 | 32B对齐约束只在assert中出现 | 在参数说明前用独立段落标注"约束与限制" |
| 首次引入加链接 | 提到其他文档负责的内容时，首次出现加链接，后续不重复 | 每次提到DataCopy都加链接 | 仅首次提到DataCopy时加链接到API参考手册 |
| 不逆序阅读 | 概念B依赖概念A时，A先出现或B处有明确引用链接 | API页面直接用TPipe概念但未铺垫 | API页面开头放"前置知识"段，链接到编程指南对应章节 |

### 编程指南编写规范

编程指南是**概念权威源**，其他文档遇到概念问题都链接回编程指南。

**文件职责**：

| 文件类型 | 职责 | 禁止 |
|---------|------|------|
| 概述/总览文件 | 导航页：列出子主题+一句话概述+链接 | 展开技术细节 |
| 概念介绍文件 | 定义概念、解释原理、给出约束 | 重复其他文件内容（改为引用） |
| 操作指南文件 | 代码片段+操作步骤+注意事项 | 重复概念定义（链接到概念文件） |

**编程指南到其他文档的链接方向**：
- 首次提到某个API名称 → 链接到API参考手册
- 首次提到优化/实践话题 → 链接到算子实践参考
- 提到架构版本差异 → 链接到跨代迁移指南

### API参考页面编写规范

API参考手册是**接口详情权威源**，每个API页面必须包含以下要素（按顺序）：

#### 页面结构总览（按出现顺序）

| 序号 | 节标题 | 是否必须 | 说明 |
|------|--------|----------|------|
| 1 | 产品支持情况 | ✅ 必须 | 页面最顶部，表格列出每个芯片对每个函数原型的支持情况 |
| 2 | 功能说明 | ✅ 必须 | 一段总述 + 头文件 + 数学公式 + 图示/示意图 |
| 3 | 函数原型 | ✅ 必须 | 所有重载原型，按功能分支分组（如支持bias/不支持bias） |
| 4 | 参数说明 | ✅ 必须 | 主参数表 + 嵌套结构体参数表 |
| 5 | 返回值说明 | ✅ 可选 | 返回值数据类型说明 |
| 6 | 数据类型 | ✅ 必须 | 分产品系列列出支持的类型组合表 |
| 8 | 约束说明 | ✅ 必须 | 全部使用约束，含代码示例和阈值公式 |
| 9 | 理论性能说明 | 推荐 | 计算公式 + 分产品系列的并行度/参数表 |
| 10 | 调用示例 | ✅ 必须 | 链接到样例库 + 场景分类表 |
| 11 | 关联API | ✅ 推荐 | 互斥API + 功能相近API |

---

**1. 产品支持情况**

**格式要求**：表格列出所有产品系列对每个函数原型的支持状态。

**样板写法**（以Mmad为例）：

```
## 产品支持情况

| 产品 | 是否支持（不传入bias的原型） | 是否支持（传入bias的原型） |
|------|---------------------------|---------------------------|
| Atlas A3 训练系列产品/Atlas A3 推理系列产品 | √ | √ |
| Atlas A2 训练系列产品/Atlas A2 推理系列产品 | √ | √ |
| Ascend 950PR/Ascend 950DT | √ | √ |
```


废弃API用醒目标注：

```
> **已废弃**（vX.X起），替代方案见迁移指南
```

---

**2. 功能说明**

**格式要求**：3要素必须齐全——总述段落 + 头文件 + 数学表达式。

**样板写法**：

```
## 功能说明

头文件为: `#include "basic_api/kernel_operator_mm_intf.h"`

Mmad接口是AscendC面向昇腾 AI 芯片的矩阵乘加核心计算接口，专为高性能算子开发设计，
封装了昇腾 NPU 硬件的矩阵乘加计算能力...

如下图所示，Mmad接口实现昇腾NPU矩阵乘计算能力，其数学表达式为：
C = A × B + Bias
[示意图/公式图片]

完整示例请参考：[Mmad示例](链接)
```

**编写要求**：
- **头文件**必须写明具体include路径
- 总述段说明API的定位（面向什么场景、封装了什么硬件能力）
- 数学公式必须给出（不能只用文字描述）
- 如有示意图/数据流图，嵌入图片并标注图序号
- 完整示例链接到样例仓库

---

**3. 函数原型**

**格式要求**：按功能分支分组列出所有重载。每组先给概述，再列模板签名。

**样板写法**：

```cpp
// 不支持bias
template <typename T, typename U, typename S>
__aicore__ inline void Mmad(const LocalTensor<T>& c, const LocalTensor<U>& a,
    const LocalTensor<S>& b, const MmadParams& mmadParams)

// 支持bias
template <typename T, typename U, typename S, typename V>
__aicore__ inline void Mmad(const LocalTensor<T>& c, const LocalTensor<U>& a,
    const LocalTensor<S>& b, const LocalTensor<V>& bias, const MmadParams& mmadParams)

// 不传入bias（BitMode版本）
template <typename T, typename U, typename S>
__aicore__ inline void Mmad(const LocalTensor<T>& c, const LocalTensor<U>& a,
    const LocalTensor<S>& b, const MmadBitModeParams& mmadParams)

// 传入bias（BitMode版本）
template <typename T, typename U, typename S, typename V>
__aicore__ inline void Mmad(const LocalTensor<T>& c, const LocalTensor<U>& a,
    const LocalTensor<S>& b, const LocalTensor<V>& bias, const MmadBitModeParams& mmadParams)
```

**编写要求**：
- 每个模板参数（T, U, S, V...）必须在参数说明中标注其对应关系
- `__aicore__` 修饰符必须保留
- 参数按输入顺序列出：先输出（c），再输入（a, b, bias），最后参数结构体
- 如有BitMode版本（位域联合体参数），与常规版本并列列出

---

**5. 约束说明**

在函数原型之后、参数说明之前，用独立段落列出全部约束：

- 数据类型限制（列出支持的完整数据类型）
- 地址对齐要求（对齐字节数和方向）
- 元素数量范围（最小值、最大值、对齐粒度）
- 格式限制（ND/NZ等）
- 使用模式限制
- API组合限制（互斥、必需搭配）

**6. 参数说明**

每个参数说明其含义和取值范围。复杂参数（stride、layout、mask类）必须配图解。判断标准：纯文字需要3句以上才能解释清楚的参数，必须配图。

**7. 代码示例**

每个API提供1个最小可运行示例（Minimal），在示例中覆盖常用参数组合：

| 定位 | 篇幅 | 要求 |
|------|------|------|
| 最小可运行示例 | <30行核心代码 | 复制即编译运行，覆盖常用参数组合 |

示例必须可复制编译运行。片段末尾链接到样例库完整示例。

**8. 关联API**

说明同一版本内API之间的组合关系：

- 互斥API（用 `> **警告**` 框标注）
- 功能相近API（提供选择指引）

跨版本的迁移关系不在本段描述，由跨代迁移指南负责。

**API页面到其他文档的链接方向**：
- 前置概念 → 链接回编程指南
- API有跨版本差异 → 链接到跨代迁移指南
- 代码示例 → 链接到样例库

### 算子实践参考编写规范

算子实践参考是**实践案例源**，负责展开编程指南点到为止的实践和优化内容。

**文档结构模板**：

```markdown
# <算子名> 算子实践参考

## 前置说明
阅读本文档前，您需要了解：xxx概念（链接到编程指南）、xxx API（链接到API参考）。

## 算子实现
### 基础版本
（代码片段 + 说明 + 链接到样例库完整示例）

### 进阶版本
（如适用：性能优化版本、多数据类型版本等）

## 性能优化
（如适用：列出针对此算子的优化手段，链接到对应优化专题）

## 常见问题
（如适用：开发过程中容易踩的坑）
```

**关键要求**：
- 有多种实现方案（如MemBase vs RegBase）的算子，开头放方案差异表+选择建议
- 代码中首次出现的API加链接到API参考手册，后续不重复
- 优化方案如果因架构版本不同，标注 `[适用版本：仅xxx]` 并链接到跨代迁移指南

### 跨代迁移页面编写规范

跨代迁移指南是**兼容性权威源**，负责说明架构版本间的差异和迁移路径。

**迁移映射条目格式**：

```markdown
## <遗留API名> → <新API名>

### 变更说明
（一句话说明为什么变更、什么时候变更的）

### 参数差异对照

| 参数 | 旧接口 | 新接口 | 差异说明 |
|------|--------|--------|---------|
| ... | ... | ... | ... |

### 约束差异
（列出对齐、数据类型、元素数量等方面的差异）

### 迁移代码示例
（展示旧写法和新写法的对比）

### 迁移验证
（迁移后如何验证功能和性能）
```

**关键要求**：
- 每个映射条目必须链接到新旧API的API参考手册详情页
- 概念变更必须链接回编程指南对应章节
- 使用统一的 `[适用版本：xxx]` 标注格式

## 代码示例编写规范

### 代码片段要求

| 要求 | 说明 |
|------|------|
| 精简聚焦 | 只展示当前讲解相关的代码，用 `// ... 其他初始化` 省略无关部分 |
| 可理解 | 每个片段配2-3行文字说明这段代码做了什么 |
| 可追踪 | 片段末尾链接到样例库完整示例 |
| 关键字注释 | Ascend C特有关键字（`__aicore__`、`__ubuf__`、`__simd_vf__`等）必须行内注释 |
| 参数覆盖 | 覆盖常用参数组合，不仅展示单一用法 |

### 示例中的关键字注释

```cpp
__aicore__ inline void ExampleKernel(__gm__ uint8_t* x) {  // __aicore__=核函数修饰符, __gm__=Global Memory地址空间
    // ...
}
```

## 提交PR前的自检清单

提交资料PR前，请逐项检查：

**内容正确性**：
- [ ] 所有硬件参数值（容量、粒度、范围）与芯片规格说明书一致
- [ ] "固定值"等绝对性描述已经核实（很多"固定值"实际由配置参数决定）
- [ ] 数据通路描述与实际路径一致（不与其他文档矛盾）

**约束完备性**：
- [ ] 每个API的支持数据类型列表完整
- [ ] 地址对齐要求已明确（字节数和方向）
- [ ] 元素数量范围（最小值、最大值、对齐粒度）已说明
- [ ] API组合限制（互斥、必需搭配）已标注
- [ ] 跨版本差异已用 `[适用版本：xxx]` 标注

**链接规范**：
- [ ] 首次提到其他文档负责的API/概念时已加链接
- [ ] 同一概念/API后续重复出现不重复加链接
- [ ] API页面的"前置知识"段已链接到编程指南
- [ ] 涉及版本差异时已链接到跨代迁移指南

**可读性**：
- [ ] 术语使用与章节抽象层级匹配（高层用抽象名，低层首次出现时关联）
- [ ] 易混概念用对比表区分（不用纯文字暗示）
- [ ] 代码片段精简聚焦，有文字说明，有样例库链接
- [ ] Ascend C特有关键字有行内注释

**示例质量**：
- [ ] 每个API至少有1个最小可运行示例
- [ ] 示例可复制编译运行
- [ ] 覆盖多数据类型/多参数组合（不只有单一用法）

## 资料体系与链接关系

四份文档之间通过交叉链接形成导航网络，遵循"谁提到别人负责的内容，谁就加链接"原则：

```
编程指南 ──首次引入API──→ API参考手册
        ──首次引入优化──→ 算子实践参考
        ──版本差异────→ 跨代迁移指南

API参考手册 ──前置概念──→ 编程指南
            ──版本差异──→ 跨代迁移指南

算子实践参考 ──首次使用API──→ API参考手册
            ──编程概念────→ 编程指南
            ──跨架构优化──→ 跨代迁移指南

跨代迁移指南 ──概念定义──→ 编程指南
            ──新API详情──→ API参考手册
```

样例库（`asc-devkit/examples/`）不属于资料体系，但四份文档中的代码示例均可链接到样例库。
