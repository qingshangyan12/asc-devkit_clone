# 公共构建基础能力设计

## 1. 目标

在不改变现有对外行为的前提下，减少 JIT 资源打包、注册和 Kernel 常量化编译中的文件系统与子进程
操作重复代码。

公共层只提供操作系统相关的基础能力。Manifest 语义、资源发现、常量化处理、ACL 错误码映射、诊断信息
以及编译流程决策仍由各自模块负责。

## 2. 当前重复实现

当前存在三套职责重叠的基础能力实现：

- `asc_compile_exporter` 自己管理 `BuildWorkspace`，通过 `FileUtils` 操作文件，通过 `ProcessRunner`
  执行 `make`。
- `ResourceRegistry` 独立创建和清理资源物化目录，并自行完成资源文件落盘。
- Kernel 常量化编译独立管理资源 worktree、原子修改源码、发布 ELF，并完整实现了带输出捕获和超时控制的
  子进程生命周期。

重复内容主要包括临时目录所有权、文件创建与替换、子进程启动、超时处理、进程组清理和执行结果表达。

## 3. 设计原则

1. 公共代码不得依赖 JSON、Manifest 对象、`aclError`、Kernel 模式或诊断类。
2. 公共接口的命名应在调用点明确表达所有权与外部副作用。
3. 命令必须直接通过参数数组执行，禁止调用 Shell。
4. 各模块负责在调用公共层之前校验自己的外部输入。
5. 公共层只校验自身接口前置条件，并检查操作系统调用结果。
6. 由当前进程生成的文件通过 UT 和集成测试保证正确，不在内部模块之间重复校验。
7. 每迁移一个调用方前，先通过测试固化现有行为。
8. 公共源码必须支持 C++11，因为 `asc_compile_exporter` 当前固定使用该语言标准。

## 4. 公共组件

### 4.1 ProcessExecutor

在 `tools/build/common` 中提供统一的 `ProcessExecutor`，替代 `ProcessRunner` 以及常量化编译模块中与
操作系统交互的命令执行实现。

执行请求包含：

- 完整参数数组，其中 argv[0] 为可执行文件；
- 可选的环境变量覆盖项；
- 可选的待移除环境变量名；
- 单条命令执行超时时间和进程终止宽限时间；
- 可选的输出捕获字节数上限。

执行结果包含：

- 终止类型：正常退出、信号终止、执行超时或基础设施错误；
- 适用时返回退出码或终止信号；
- 有界的 stdout/stderr 合并输出；
- 输出是否被截断；
- 命令执行耗时。

`ProcessExecutor` 负责创建子进程及独立进程组、读取输出管道、检测超时、执行 SIGTERM/SIGKILL
升级处理并最终回收子进程。它不包含编译命令的超时策略，也不负责将执行结果转换为 `aclError` 或
`bool`。

打包模块使用现有的 30 分钟超时，移除 Make 递归调用相关环境变量，并将退出码为 0 的正常退出转换为
现有 `bool` 结果。常量化编译模块为每条命令构造执行请求，compile 命令使用 5 分钟超时，objcopy/link
命令使用 1 分钟超时，再由本模块将公共执行结果转换为诊断信息和 `aclError`。

### 4.2 TemporaryDirectory

在 `tools/build/common` 中增加只允许移动的 `TemporaryDirectory`，支持两种创建方式：

- 在已解析的父目录下创建唯一子目录；
- 接管资源物化接口返回的已有目录。

除非显式释放目录所有权用于保留诊断信息，否则对象析构时删除其持有的目录。创建或接管失败时对象保持
为空；移动操作保证清理责任只转移一次。

打包模块使用新对象替代 `BuildWorkspace`。资源注册模块在物化过程中临时持有该对象，全部文件物化成功后
释放路径；物化失败时默认清理目录，但开启保存 kernel meta 后释放路径并保留失败现场。常量化编译模块
接管 Lookup 返回的路径，仅当
`ASCEND_OP_COMPILE_SAVE_KERNEL_META=1` 时保留该目录。

资源注册模块仍负责定义资源查找和物化语义，`TemporaryDirectory` 只表达目录所有权。

### 4.3 FileUtils

保留 `FileUtils` 现有的路径检查和基础文件操作。首先让各调用方复用已有的路径处理、有界文件读取、文件
复制和目录清理能力。只有至少两个调用方需要完全相同的行为约束时，才新增公共原语。当前候选能力包括：

- 完整写入新文件，并检查 flush 或 close 失败；
- 完整复制普通文件，并准确报告源文件或目标文件错误；
- 使用已准备好的同文件系统文件原子替换目标文件。

以下包含业务流程语义的操作不放入 `FileUtils`：

- 应用常量源码 patch；
- 创建仅供常量化编译使用的排他同目录临时文件；
- 决定何时必须删除 worktree；
- 选择最终链接 ELF 或资源包产物；
- 编排跨文件系统发布流程；
- 生成诊断回放脚本。

该边界用于避免 `FileUtils` 逐渐变成无关高层操作的集合。

## 5. 各模块职责

### 5.1 打包模块

- 保持当前完整收集并校验 Manifest 集合的流程。
- 使用 `TemporaryDirectory` 管理生成的构建文件。
- 使用 `ProcessExecutor` 执行 `make`，保持现有环境变量处理和超时行为。
- 保持同文件系统 rename，以及跨文件系统 copy 后 rename 的发布行为。
- 保持 `--keep-temp` 行为不变。

### 5.2 注册模块

- 保留 ABI 校验、动态库加载、资源优先级、资源发现、大小限制以及 Manifest 所有权字段解析。
- 物化期间使用公共目录所有权对象，默认清理失败产生的未完成产物；开启保存 kernel meta 时保留失败现场。
- 在不改变现有无软链接和大小限制约束的前提下，复用公共完整文件写入能力。
- 保持每次 Lookup 返回唯一物化路径，并按现有约定将路径所有权转移给调用方。

### 5.3 常量化编译模块

- 保留请求归一化、选中 Manifest 子树解析、占位符展开、命令构造、常量 patch 计划、命令顺序、诊断
  信息以及 ACL 错误码映射。
- 将 `CompilationPlanExecutor` 缩减为编译策略和 `ProcessExecutor` 结果映射层。
- 保留 `KernelCompilationWorkspace`，使其继续负责 patch 应用以及发布前删除 worktree 的业务规则；
  目录生命周期和通用文件操作下沉到公共层。
- 保持当前最终 ELF 发布点和保存 kernel meta 的行为。

## 6. 错误与日志约定

公共层记录基础设施错误，日志必须包含可执行文件或路径以及操作系统错误信息。公共层不输出有关 Manifest
字段或编译选项的用户修正建议。

各调用方补充领域上下文：

- 打包模块说明资源包生成阶段；
- 注册模块说明 resource ID、资源来源类型和资源文件；
- 常量化编译模块说明 Manifest object、命令索引，并在开启时保存诊断信息。

除非清理是提交产物前必须完成的步骤，否则清理失败只记录 warning。命令超时属于正常可表达的执行结果，
不作为基础设施异常处理。

## 7. 迁移顺序

1. 增加行为保持测试，固化当前公共文件和进程执行行为。
2. 在 `tools/build/common` 中增加 `ProcessExecutor` 测试并完成实现。
3. 迁移常量化编译的子进程实现，保持结果映射和诊断测试不变。
4. 迁移打包模块并删除 `ProcessRunner`。
5. 增加 `TemporaryDirectory` 测试，依次迁移打包、注册和常量化编译的目录所有权处理。
6. 增加具备实际复用价值的 `FileUtils` 原语并迁移重复文件操作。
7. 删除被替代的代码，运行三个模块的完整测试。

每迁移一个调用方，都必须先确保其原有测试全部通过，再修改下一个调用方。

## 8. 验证要求

必须完成以下自动化验证：

- 公共进程测试：空 argv、环境变量覆盖和移除、非 0 退出、信号退出、超时、忽略 SIGTERM 的后代进程、
  输出截断、exec 失败以及 wait/poll 失败；
- 公共目录测试：唯一目录创建、移动所有权、接管、释放、正常清理和清理失败；
- 公共文件测试：短读写、排他临时文件创建、原子替换和失败清理；
- 现有打包测试，包括保留临时目录、环境隔离、超时和跨文件系统发布；
- 现有注册测试，包括物化失败清理和 Lookup 唯一路径；
- 现有常量化编译测试，包括不真实等待的 5 分钟/1 分钟超时选择、输出诊断、worktree 保留与删除、
  常量 patch 和 ELF 发布；
- 使用 `-Werror` 构建生产目标 `asc_compile_exporter` 和 `acl_rtc`；
- 对全部修改文件执行格式化检查和 `git diff --check`。

本次重构不新增公共 C API，也不新增动态库导出符号。
