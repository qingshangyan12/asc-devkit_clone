# 概述<a name="ZH-CN_TOPIC_0000002535192325"></a>

Ascend C的核心设计目标之一是实现跨代兼容。然而，每一代芯片在微架构上都存在独特的硬件特性，因此无法保证所有接口仅通过重编译就能达成完全的跨代兼容。基于这一前提，本手册旨在为Ascend C算子开发者提供系统化指导，帮助将算子Kernel代码从当前芯片平滑移植到目标代际芯片上运行，实现高效、可控的迁移。

如[SIMD-BuiltIn关键字](../编程指南/语言扩展层/SIMD-BuiltIn关键字.md) 中所述，\_\_NPU\_ARCH\_\_是Device侧AI Core代码中的一个预处理宏，用于标识AI处理器的架构版本。例如，Ascend 950PR/Ascend 950DT的\_\_NPU\_ARCH\_\_为3510，而Atlas A2 训练系列产品/Atlas A2 推理系列产品和Atlas A3 训练系列产品/Atlas A3 推理系列产品的\_\_NPU\_ARCH\_\_则为2201。因此，后续章节将以\_\_NPU\_ARCH\_\_为主线，重点介绍相邻代际芯片间的平滑迁移方法。

> [!NOTE]
> 为保证兼容性，建议开发者在开发过程中尽量避免使用以下接口或编程方式，否则需自行保证兼容性：
> - 非 Ascend C 公开接口、结构体，例如 `impl` 目录下的接口、结构体等；
> - 对芯片规格进行硬编码，例如：
>   ```cpp
>   constexpr uint32_t MAX_UB_SIZE = 256 * 1024;  
>   // 建议获取方式：
>   // ascendcPlatform.GetCoreMemSize(platform_ascendc::CoreMemType::UB, MAX_UB_SIZE);
>   ...
>   ```
> - 编译器内置 API（BuiltIn API），例如：
>   ```cpp
>   copy_gm_to_ubuf(input_1_local_UB, input_1, 0, 1, 8, 0, 0);
>   ```

建议开发者采用以下实践：
- 使用兼容的 API 接口。
- 若涉及特定领域的扩展特性，应在 Device 侧通过 [`__NPU_ARCH__` 编译宏](../编程指南/语言扩展层/SIMD-BuiltIn关键字.md)进行隔离，在 Host 侧通过 `SocVersion` 进行隔离。
- 使用 `<<<>>>` 直调或 [Tiling 模板编程](../编程指南/高级编程/高级特性/Aclnn算子工程化开发/Host侧Tiling实现/Tiling模板编程.md)。

## 推荐的编程范式<a name="ZH-CN_TOPIC_0000003021458967"></a>

为了提升算子跨代迁移的稳定性和性能，建议开发者采用以下现代化的编程范式。

### 使用 `__vector__` / `__cube__` 声明核函数类型

在声明核函数时，建议显式使用 [`__vector__` 或 `__cube__` 属性](../编程指南/语言扩展层/SIMD-BuiltIn关键字.md)来标识执行单元，而不是仅依赖 `__aicore__`。这能让编译器做更精准的优化，也使得核函数的执行单元一目了然：

```cpp
__vector__ __global__ void add_custom(...) { ... }   // 矢量核函数
__global__ __cube__ void matmul_custom(...) { ... }  // 矩阵核函数
```

> [!NOTE]
> 在耦合模式的硬件架构上，`__vector__`/`__cube__` 修饰符不生效。详见 [SIMD BuiltIn关键字](../编程指南/语言扩展层/SIMD-BuiltIn关键字.md#函数执行空间限定符)。

### 推荐使用静态Tensor编程

相比基于 `TPipe`/`TQue` 的传统方式（需要 InitBuffer→AllocTensor→EnQue→DeQue→FreeTensor 等繁琐步骤），[静态Tensor编程](../编程指南/编程模型/AI-Core-SIMD编程/基于Tensor的C++编程/静态Tensor编程.md) 通过 `LocalTensor(TPosition::VECCALC, addr, size)` 直接指定地址和存储位置来构造Tensor，避免 TPipe 初始化开销（约数百纳秒），并获得完全自主的内存和同步控制权。

```cpp
// 静态Tensor：一行完成创建，无需 InitBuffer/AllocTensor/EnQue/DeQue
AscendC::LocalTensor<half> srcLocal(AscendC::TPosition::VECCALC, xAddr, DATA_COUNT);
```

| 维度 | 静态Tensor（推荐） | TPipe/TQue（传统） |
|:---|:---|:---|
| 内存分配 | `LocalTensor(TPosition, addr, size)` | `InitBuffer` + `AllocTensor` |
| 同步管理 | 手动 `SetFlag`/`WaitFlag` | 框架自动 `EnQue`/`DeQue` |
| 初始化要求 | 必须显式调用 `InitSocState()` | 由 TPipe 自动完成 |
| 跨版本兼容 | 不保证（ISASI接口） | 框架保证 |
| 运行时开销 | 低 | 较高（约数百纳秒） |
| 灵活性 | 高（完全自主管理） | 中（框架封装约束） |

> [!WARNING]
> 静态Tensor编程使用 ISASI（Instruction Set Architecture Special Interface，硬件体系结构相关的接口）底层同步接口，**不保证跨硬件版本兼容**。开发者需在「性能收益」和「跨代兼容性」之间权衡：性能优先用静态Tensor，兼容性优先用 TPipe/TQue。详见 [静态Tensor编程 - 使用约束和限制](../编程指南/编程模型/AI-Core-SIMD编程/基于Tensor的C++编程/静态Tensor编程.md#使用约束和限制)。
