# 1. Introduction to Ascend C

## 1.1 Introduction

**Ascend C API and High-Performance Computing**

Ascend C API is a low-level programming interface for Ascend NPU (Neural Processing Unit) developed by Huawei. It enables dramatic increases in computing performance by harnessing the power of the AI Core, the specialized computational unit in Ascend NPU. Ascend C API provides direct, fine-grained control over hardware resources through C-language function calls, making it ideal for performance-critical applications in deep learning, scientific computing, and high-performance computing (HPC).

Unlike high-level frameworks that abstract hardware details, Ascend C API exposes the underlying AI Core architecture directly to developers. This provides maximum flexibility and control, allowing developers to:

- Optimize memory hierarchy usage (Global Memory → UB → Registers)
- Control data movement between memory levels explicitly
- Utilize specialized computational units (AI Vector for SIMD, AI Cube for matrix)
- Implement custom synchronization and pipeline strategies
- Achieve peak performance for specific algorithms

**Who Should Read This Guide**

This guide is designed for developers who want to:

- Understand how Ascend NPU executes code
- Write high-performance kernels using Ascend C API
- Optimize memory usage and data movement
- Implement custom operators for deep learning
- Port algorithms from other platforms (CUDA, OpenCL) to Ascend NPU

**Key Features of Ascend C API**

- **Direct Hardware Access**: Function calls map directly to hardware instructions
- **Transparent Memory Control**: Explicit control over Global Memory, UB, L0/L1/L2/L3
- **SIMD Vector Computing**: High-performance vector operations on AI Vector unit
- **Matrix Acceleration**: Hardware-accelerated matrix multiplication on AI Cube unit
- **Pipeline Execution**: Concurrent data movement and computation
- **Synchronization Mechanisms**: Fine-grained control over execution flow

**Ascend C API vs High-Level Frameworks**

| Feature | Ascend C API | High-Level Frameworks |
|---------|--------------|----------------------|
| **Abstraction Level** | Low-level, hardware-facing | High-level, user-facing |
| **Memory Control** | Explicit, manual | Automatic, managed |
| **Performance** | Maximum, optimized | Good, but limited |
| **Flexibility** | Maximum control | Limited to predefined ops |
| **Learning Curve** | Steeper, requires hardware knowledge | Easier, abstracted |
| **Use Case** | Custom operators, performance optimization | Standard operators, rapid development |

**Terminology**

Throughout this guide, we use these key terms:

- **AI Core**: Ascend NPU's computational unit, analogous to CUDA's SM
- **Kernel**: Entry function executing on AI Core
- **Block**: Execution unit in Ascend C, analogous to CUDA's thread block
- **Global Memory (GM)**: Off-chip DRAM, analogous to CUDA's global memory
- **Unified Buffer (UB)**: On-chip memory for vector operations, analogous to CUDA's shared memory
- **AI Vector**: SIMD computation unit for vector operations
- **AI Cube**: Matrix computation unit for matrix multiplication
- **Pipeline**: Concurrent execution of data movement and computation
- **Sync**: Synchronization mechanisms to coordinate execution
