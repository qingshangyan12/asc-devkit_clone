# 算子子验证说明

本文档面向AscendC算子开发者，提供单算子融合进SuperKernel的验证样例。算子开发完成后，可通过本文档中的样例自行验证算子是否支持融合进SuperKernel，包括功能正确性与精度对齐。

当前SuperKernel特性的使能路径有两条——GE入图路径和aclgraph（npugraph_ex）路径，两条路径在前端使能方式上有所不同。开发者通常只需选择其中一条进行验证；如需在两条路径下均验证算子兼容性，可以分别参考下文样例。

## 验证思路

通用的单算子子验证思路如下：

1. **构造一个仅包含待验证算子的`torch.nn.Module`**：构造一个原始版本（不开启SuperKernel）和一个SuperKernel版本（在算子调用处标定SuperKernel范围）。
2. **分别用图模式编译并执行两个模型**：原始版本作为基准，SuperKernel版本作为目标。
3. **比对两个版本的输出**：若数值完全相等（或在可接受误差范围内），则证明算子在SuperKernel下功能与精度正确。

>[!NOTE]说明
>SuperKernel范围内只包含一个算子时，框架不会真正执行融合（融合至少需要两个子Kernel），但**编译流程仍会按SuperKernel路径处理**，可以充分检验算子是否符合SuperKernel开发约束（例如标量读写、全核同步、TPipe析构等）。如需触发实际融合并观察Profiling，可以将同一算子在Module内连续调用两次或多次。

## GE入图路径验证样例

GE入图路径通过`torchair.scope.super_kernel`作用域标定融合范围，编译后端使用`tng.get_npu_backend()`返回的`npu_backend`。

### 示例代码

以下示例以`torch_npu.npu_ffn`为例，演示单算子在GE入图路径下的SuperKernel验证：

```python
#!/usr/bin/python3
# -*- coding: utf-8 -*-

import torch
import torch_npu
import torchair
import torchair as tng
from torchair.configs.compiler_config import CompilerConfig
import numpy as np
import os
import sys


if __name__ == "__main__":
    config = CompilerConfig()
    npu_backend = tng.get_npu_backend(compiler_config=config)

    # 原始模型：不标定SuperKernel范围
    class ModelOrigin(torch.nn.Module):
        def __init__(self):
            super().__init__()

        def forward(self, x, weight1, weight2, bias1, bias2):
            out = torch_npu.npu_ffn(x, weight1, weight2,
                                    bias1=bias1, bias2=bias2,
                                    activation="gelu", inner_precise=1)
            return out

    # SuperKernel模型：用torchair.scope.super_kernel标定融合范围
    class ModelSuperKernel(torch.nn.Module):
        def __init__(self):
            super().__init__()

        def forward(self, x, weight1, weight2, bias1, bias2):
            with torchair.scope.super_kernel("sp1", ""):
                out = torch_npu.npu_ffn(x, weight1, weight2,
                                        bias1=bias1, bias2=bias2,
                                        activation="gelu", inner_precise=1)
            return out

    # 构造输入数据
    x = torch.tensor(np.random.uniform(0.01, 1, (111, 123))).to(torch.float16)
    weight1 = torch.tensor(np.random.uniform(0.01, 1, (123, 123))).to(torch.float16)
    weight2 = torch.tensor(np.random.uniform(0.01, 1, (123, 123))).to(torch.float16)
    bias1 = torch.tensor(np.random.uniform(0.1, 1, (123,))).to(torch.bfloat16)
    bias2 = torch.tensor(np.random.uniform(1, 5, (123,))).to(torch.bfloat16)

    # 清理缓存（可选）
    os.system("rm -rf /root/atc_data/*")
    os.system("rm -rf ./kernel_meta")

    # 运行原始模型
    print("------------------- run without SuperKernel ---------------------")
    try:
        model_no_sk = torch.compile(ModelOrigin(), backend=npu_backend, dynamic=False)
        out_no_sk = model_no_sk(x.npu(), weight1.npu(), weight2.npu(),
                                bias1.npu(), bias2.npu())
    except Exception as e:
        print(f"运行 ModelOrigin 失败: {e}")
        sys.exit(2)

    # 运行SuperKernel模型
    print("------------------- run with SuperKernel ------------------------")
    try:
        model_sk = torch.compile(ModelSuperKernel(), backend=npu_backend, dynamic=False)
        out_sk = model_sk(x.npu(), weight1.npu(), weight2.npu(),
                          bias1.npu(), bias2.npu())
    except Exception as e:
        print(f"运行 ModelSuperKernel 失败: {e}")
        sys.exit(2)

    # 精度比对
    a = out_no_sk.cpu().numpy()
    b = out_sk.cpu().numpy()
    if np.array_equal(a, b):
        print("测试通过：算子在GE路径下成功融合进SuperKernel，且精度对齐。")
        sys.exit(0)
    else:
        unequal = np.where(a != b)
        print("告警：算子在SuperKernel下与原始结果存在精度差异。")
        print(f"差异索引：{unequal}")
        sys.exit(1)
```

### 关键点说明

- `torchair.scope.super_kernel("sp1", "")`：第一个参数为该范围的SuperKernel名称（`scope_name`），相同名称代表相同的融合范围；第二个参数为可选的编译选项串，可以传入空字符串。
- `torch.compile(model, backend=npu_backend, dynamic=False)`：通过GE路径下发图，仅支持静态图（`dynamic=False`）。
- 是否启用SuperKernel融合优化由`CompilerConfig`中的相关配置控制，详细配置项请参见《Ascend Extension for PyTorch》中“TorchAir > max-autotune模式功能 > 图内标定SuperKernel范围”章节。

## aclgraph（npugraph_ex）路径验证样例

aclgraph路径通过`torch.npu.super_kernel_scope_begin/end`一对接口标定融合范围，编译后端使用`"npugraph_ex"`，并在`options`中显式传入`super_kernel_optimize=True`。

### 示例代码

以下示例以`torch_npu.npu_quant_matmul`后接`torch_npu.npu_dequant_swiglu_quant`为例，演示在aclgraph路径下的SuperKernel验证。若只想验证单个算子，将SuperKernel范围内只保留一个算子调用即可（参见前文“验证思路”中关于单算子的说明）：

```python
#!/usr/bin/python3
# -*- coding: utf-8 -*-

import torch
import torch_npu
import numpy as np
import os
import sys


if __name__ == "__main__":

    # 原始模型：不标定SuperKernel范围
    class ModelOrigin(torch.nn.Module):
        def __init__(self):
            super().__init__()

        def forward(self, x1, x2, scale, offset, bias, pertoken_scale, weight_scale):
            quant_matmul_res = torch_npu.npu_quant_matmul(
                x1, x2, scale, offset=offset, bias=bias,
                pertoken_scale=pertoken_scale, output_dtype=torch.bfloat16)
            swiglu_res = torch_npu.npu_dequant_swiglu_quant(
                quant_matmul_res, weight_scale=weight_scale)
            return swiglu_res, quant_matmul_res

    # SuperKernel模型：用torch.npu.super_kernel_scope_begin/end标定融合范围
    class ModelSuperKernel(torch.nn.Module):
        def __init__(self):
            super().__init__()

        def forward(self, x1, x2, scale, offset, bias, pertoken_scale, weight_scale):
            torch.npu.super_kernel_scope_begin("sk1")
            quant_matmul_res = torch_npu.npu_quant_matmul(
                x1, x2, scale, offset=offset, bias=bias,
                pertoken_scale=pertoken_scale, output_dtype=torch.bfloat16)
            swiglu_res = torch_npu.npu_dequant_swiglu_quant(
                quant_matmul_res, weight_scale=weight_scale)
            torch.npu.super_kernel_scope_end("sk1")
            return swiglu_res, quant_matmul_res

    # 设置随机种子
    seed = 1236
    torch.manual_seed(seed)
    np.random.seed(seed)

    # 构造输入数据
    m, k, n = 864, 7168, 4096
    cpu_x1 = torch.randint(-10, 10, (m, k), dtype=torch.int8)
    cpu_x2 = torch.randint(-10, 10, (n, k), dtype=torch.int8)
    cpu_x2 = torch_npu.npu_format_cast(cpu_x2.npu().transpose(1, 0).contiguous(), 29)
    scale = torch.randn((n,), dtype=torch.float32)
    pertoken_scale = torch.randn((m,), dtype=torch.float32)
    weight_scale = torch.randn((m, n), dtype=torch.float32)

    # 清理缓存（可选）
    os.system("rm -rf /root/atc_data/*")
    os.system("rm -rf ./kernel_meta")

    # 运行原始模型
    print("------------------- run without SuperKernel ---------------------")
    try:
        model_no_sk = torch.compile(ModelOrigin(), backend="npugraph_ex", dynamic=False)
        out_no_sk = model_no_sk(cpu_x1.npu(), cpu_x2, scale.npu(), None, None,
                                pertoken_scale.npu(), weight_scale.npu())
    except Exception as e:
        print(f"运行 ModelOrigin 失败: {e}")
        sys.exit(2)

    # 运行SuperKernel模型
    print("------------------- run with SuperKernel ------------------------")
    try:
        model_sk = torch.compile(
            ModelSuperKernel(), backend="npugraph_ex",
            options={"static_kernel_compile": True, "super_kernel_optimize": True},
            dynamic=False)
        out_sk = model_sk(cpu_x1.npu(), cpu_x2, scale.npu(), None, None,
                          pertoken_scale.npu(), weight_scale.npu())
    except Exception as e:
        print(f"运行 ModelSuperKernel 失败: {e}")
        sys.exit(2)

    # 精度比对（注意ModelOrigin/ModelSuperKernel返回tuple）
    swiglu_no_sk = out_no_sk[0]
    swiglu_sk = out_sk[0]
    if isinstance(swiglu_no_sk, tuple):
        all_equal = True
        for i in range(len(swiglu_no_sk)):
            if not np.array_equal(swiglu_no_sk[i].cpu().numpy(),
                                  swiglu_sk[i].cpu().numpy()):
                all_equal = False
        if all_equal:
            print("测试通过：算子在aclgraph路径下成功融合进SuperKernel，且精度对齐。")
            sys.exit(0)
        else:
            print("告警：算子在SuperKernel下与原始结果存在精度差异。")
            sys.exit(1)
    else:
        if np.array_equal(swiglu_no_sk.cpu().numpy(), swiglu_sk.cpu().numpy()):
            print("测试通过：算子在aclgraph路径下成功融合进SuperKernel，且精度对齐。")
            sys.exit(0)
        else:
            print("告警：算子在SuperKernel下与原始结果存在精度差异。")
            sys.exit(1)
```

### 关键点说明

- `torch.npu.super_kernel_scope_begin(scope_name)`/`torch.npu.super_kernel_scope_end(scope_name)`：成对出现，配对的`scope_name`必须一致。相同的`scope_name`代表相同的融合范围，由用户控制。若传入`None`，则该范围内的算子不进行SuperKernel融合。
- `torch.compile(model, backend="npugraph_ex", options={...}, dynamic=False)`：通过npugraph_ex后端下发图，仅支持静态图（`dynamic=False`）。`super_kernel_optimize=True`是开启SuperKernel融合优化的必要开关；其他融合优化与调试参数（如`stream_fusion`、`debug_sync_all`、`debug_op_exec_trace`等）请参见torchair仓库`docs/zh/npugraph_ex/advanced/superkernel.md`。
- 推荐在验证阶段同时开启`debug_op_exec_trace=1`和`debug_cross_core_sync_check=1`，可以辅助定位算子级执行异常和硬同步错误。

## 单算子触发实际融合的小技巧

如前所述，SuperKernel范围内只有一个算子时，框架不会真正执行融合。若希望在Profiling中观察到实际的SuperKernel融合效果，可以采用以下方法：

- 在`forward`中将待验证算子**连续调用两次或多次**（输入可以构造为前后串联）。
- 或者将待验证算子与一个已知支持SuperKernel的简单算子（如`add`、`mul`）一起放入SuperKernel范围内。

例如：

```python
# 在GE路径下让单算子触发实际融合
with torchair.scope.super_kernel("sp1", ""):
    y1 = torch_npu.my_custom_op(x)
    y2 = torch_npu.my_custom_op(y1)

# 在aclgraph路径下让单算子触发实际融合
torch.npu.super_kernel_scope_begin("sk1")
y1 = torch_npu.my_custom_op(x)
y2 = torch_npu.my_custom_op(y1)
torch.npu.super_kernel_scope_end("sk1")
```

## 验证常见问题

- **编译失败**：检查算子是否满足[算子适配说明](算子适配说明.md)中的开发约束，特别关注核数获取接口、全核同步约束以及TPipe析构。对于`<<<>>>`算子，还需额外参考[`<<<>>>`算子额外适配说明](<<<>>>算子额外适配说明.md)完成入口适配。
- **运行卡住/超时**：通常与全核同步约束有关。请确认算子启动核数与SuperKernel启动核数的关系，并核对`SyncAll`、`CrossCoreSetFlag`/`CrossCoreWaitFlag`的使用方式。aclgraph路径下可以使能`debug_op_exec_trace=1`定位卡住的子算子。
- **精度差异**：通常与标量读写时的Cache一致性有关。请确认所有对GM的标量读写都已正确使用`GetValue`/`SetValue`接口，或在必要位置手动插入`DataCacheCleanAndInvalid`指令。
