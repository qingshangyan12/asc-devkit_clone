# 编程界面差异<a name="ZH-CN_TOPIC_0000002593910001"></a>

## 编程定位差异<a name="zh-cn_topic_0000002593910001_section_programming_position"></a>

SIMD编程、AI-Core SIMT编程和SIMD与SIMT混合编程面向的算子特征不同。SIMD编程适合连续、规整、可向量化的密集计算；AI-Core SIMT编程适合复杂控制流、离散访存、线程级索引计算等不规则计算；混合编程用于同一算子中同时存在规整密集计算和局部不规则逻辑的场景，通过SIMD承担主要向量计算，通过SIMT补充处理分支判断、索引映射、离散访存等片段。

| 编程模型 | 适用场景 | 性能特点 |
| --- | --- | --- |
| SIMD编程 | 连续规整访存、向量或矩阵密集计算、数据搬运形态稳定的算子。 | 充分利用向量计算吞吐，适合承担算子中的主要计算路径。 |
| AI-Core SIMT编程 | 复杂控制流、离散访存、线程级索引映射、数据访问模式不规则的算子。 | 编程灵活性较高，可降低不规则逻辑的表达成本，但对连续密集计算的吞吐利用通常不如SIMD编程。 |
| SIMD与SIMT混合编程 | 同一算子内既包含连续密集计算，又包含局部不规则计算的复合场景。 | 在保持SIMD主要计算吞吐的基础上，引入SIMT处理局部不规则逻辑，减少全算子改用SIMT带来的吞吐损失。 |

因此，混合编程不是对SIMD编程或SIMT编程的简单替代，而是在两类编程模型之间进行分工：将高吞吐、规整的计算路径保留在SIMD侧，将难以向量化或控制流复杂的局部逻辑放到SIMT侧。由于这种分工方式，混合编程在核函数定义、执行配置、SIMT代码组织、函数调用关系以及内存同步接口上均与单独使用SIMD编程或AI-Core SIMT编程存在差异，下文将围绕这些编程界面展开说明。

## 核函数定义差异<a name="zh-cn_topic_0000002593910001_section_kernel_definition"></a>

| 对比项 | AI-Core SIMT编程 | SIMD与SIMT混合编程 |
| --- | --- | --- |
| 核函数定位 | 核函数直接表示SIMT并行执行入口。 | 核函数作为Device侧入口，负责协调SIMT VF、SIMD VF以及其他Device侧函数执行。 |
| 函数修饰符 | 使用`__global__`标识核函数。 | AIV核内混合编程场景使用`__global__ __vector__`标识核函数；更通用的AI Core入口可使用`__global__ __aicore__`。 |
| 并行粒度 | 核函数按Grid、Block、Thread层次直接组织线程并行。 | Host侧核函数启动配置到AI Core粒度；SIMT线程并行粒度由核函数内的SIMT VF调用配置。 |
| SIMT内置变量使用位置 | 在`__global__`核函数内使用`threadIdx`、`blockIdx`、`blockDim`、`gridDim`等内置变量。 | 在`__simt_vf__`函数内使用`threadIdx`、`blockIdx`、`blockDim`、`gridDim`等内置变量。 |

AI-Core SIMT编程核函数定义示例：

```cpp
__global__ void kernel_name(float* input, float* output, uint32_t len)
{
    uint32_t idx = blockIdx.x * blockDim.x + threadIdx.x;
    if (idx < len) {
        output[idx] = input[idx];
    }
}
```

SIMD与SIMT混合编程核函数定义示例：

```cpp
__global__ __vector__ void kernel_name(__gm__ float* input, __gm__ float* output, uint32_t len)
{
    // 在核函数内部调用SIMT VF或SIMD VF完成具体计算。
}
```

## 执行配置差异<a name="zh-cn_topic_0000002593910001_section_launch_config"></a>

AI-Core SIMT编程在Host侧核函数调用符中同时配置Grid规模和Block内线程数：

```cpp
kernel_name<<<blocks_per_grid, threads_per_block, dyn_ubuf_size, stream>>>(args...);
```

SIMD与SIMT混合编程在Host侧核函数调用符中配置启动核数、动态UB大小和流；SIMT线程数通过核函数内部的`asc_vf_call`配置：

```cpp
kernel_name<<<block_num, dyn_ub_size, stream>>>(args...);

asc_vf_call<simt_func>(dim3(thread_count), arg1, arg2, ...);
```

| 对比项 | AI-Core SIMT编程 | SIMD与SIMT混合编程 |
| --- | --- | --- |
| Host侧`<<<>>>`参数 | `blocks_per_grid`、`threads_per_block`、`dyn_ubuf_size`、`stream`。 | `block_num`、`dyn_ub_size`、`stream`。 |
| 线程数配置位置 | `threads_per_block`在Host侧核函数启动时指定。 | `thread_count`在Device侧调用SIMT VF时通过`asc_vf_call`第一个参数指定。 |
| Grid/Block配置语义 | Host侧配置完整SIMT执行层次。 | Host侧配置AI Core启动规模；SIMT VF调用配置当前核内的SIMT线程块规模。 |
| 动态内存参数 | `dyn_ubuf_size`表示每个线程块动态分配的共享内存大小。 | `dyn_ub_size`表示核函数启动时配置的动态UB空间大小。 |

## SIMT代码组织差异<a name="zh-cn_topic_0000002593910001_section_simt_code"></a>

AI-Core SIMT编程中，SIMT计算逻辑直接写在`__global__`核函数内，核函数本身就是SIMT线程并行的执行主体。

```cpp
__global__ void simt_kernel(float* input, float* output, uint32_t len)
{
    uint32_t idx = blockIdx.x * blockDim.x + threadIdx.x;
    if (idx < len) {
        output[idx] = input[idx] + 1.0f;
    }
}
```

SIMD与SIMT混合编程中，SIMT计算逻辑需要封装为`__simt_vf__`函数，并通过`asc_vf_call`从核函数或`__aicore__`函数中调用。

```cpp
constexpr uint32_t thread_count = 1024;

__simt_vf__ __launch_bounds__(thread_count) inline void simt_func(
    __gm__ float* input, __ubuf__ float* output, uint32_t len)
{
    uint32_t idx = threadIdx.x;
    if (idx < len) {
        output[idx] = input[idx];
    }
}

__global__ __vector__ void hybrid_kernel(__gm__ float* input, __gm__ float* output, uint32_t len)
{
    AscendC::LocalMemAllocator<AscendC::Hardware::UB> ub_allocator;
    AscendC::LocalTensor<float> ub_output = ub_allocator.Alloc<float>(len);

    asc_vf_call<simt_func>(dim3(thread_count), input, (__ubuf__ float*)ub_output.GetPhyAddr(), len);
}
```

## 函数调用关系差异<a name="zh-cn_topic_0000002593910001_section_call_relation"></a>

| 对比项 | AI-Core SIMT编程 | SIMD与SIMT混合编程 |
| --- | --- | --- |
| Host侧入口 | Host侧通过`<<<>>>`直接调用`__global__`核函数。 | Host侧通过`<<<>>>`调用`__global__ __vector__`或`__global__ __aicore__`核函数。 |
| Device侧函数层级 | 核函数可调用`__aicore__`等Device侧辅助函数。 | 核函数可调用`__aicore__`函数，也可通过`asc_vf_call`调用SIMT VF或SIMD VF。 |
| SIMT子函数 | 通常由核函数或Device侧辅助函数组织SIMT逻辑。 | SIMT VF内只能调用`__simt_callee__`函数或`__callee__`函数。 |
| SIMD子函数 | 不涉及SIMD VF调用层级。 | SIMD VF内只能调用`__simd_callee__`函数或`__callee__`函数。 |
| 公共函数 | 按AI-Core SIMT编程的Device侧函数约束使用。 | `__callee__`可作为SIMT VF和SIMD VF的公共子函数。 |

## 内存与同步接口差异<a name="zh-cn_topic_0000002593910001_section_memory_sync"></a>

| 对比项 | AI-Core SIMT编程 | SIMD与SIMT混合编程 |
| --- | --- | --- |
| GM访问 | SIMT核函数可通过GM指针直接访问Global Memory。 | SIMT VF、SIMD VF及核函数可按各自接口约束访问GM；SIMT VF参数中的GM指针需使用`__gm__`修饰。 |
| UB访问 | 通过SIMT编程模型中的共享内存机制使用动态或静态共享内存。 | UB可在Main Scalar、SIMT VF、SIMD VF和MTE搬运之间共享，VF入参中的UB指针需使用`__ubuf__`修饰。 |
| 内存分配位置 | 动态共享内存大小由Host侧核函数调用符中的`dyn_ubuf_size`指定。 | 动态UB大小由Host侧核函数调用符中的`dyn_ub_size`指定；核函数内部可通过`LocalMemAllocator`等接口管理UB空间。 |
| 同步关注点 | 主要关注SIMT线程间同步及内存访问边界。 | 除SIMT线程级同步外，还需关注SIMT VF、SIMD VF、MTE搬运和Main Scalar之间的执行顺序及数据可见性。 |

混合编程将SIMT线程级计算嵌入AI Core核函数执行流程中，因此编程界面上需要同时配置Host侧核函数启动、Device侧VF调用以及VF之间的数据传递与同步。开发者在迁移AI-Core SIMT代码到混合编程时，应重点调整核函数启动参数、SIMT计算逻辑封装位置、VF函数修饰符和UB/GM指针修饰方式。
