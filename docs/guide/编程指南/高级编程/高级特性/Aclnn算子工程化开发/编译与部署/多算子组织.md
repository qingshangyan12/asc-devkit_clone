# 多算子组织

> 类型：扩展

当有多个算子需要开发时，需要决策：所有算子放在一个算子包中，还是拆分到多个算子包中？

## 单算子包 vs 多算子包

一个算子包可以包含多个算子。默认情况下，所有算子放在同一个算子包中即可。只有当算子之间存在以下差异时，才需要考虑拆分。

### 优先级策略不同

自定义算子包的优先级始终高于 CANN 内置算子包——当两者存在相同 OpType 的算子时，运行时加载自定义版本。

当存在多个自定义算子包时，若多个包中存在相同 OpType 的算子，需要通过 `load_priority` 配置包之间的相对优先级，以优先级高的包中的算子为准。

**示例**：
- 高性能优化算子包：对内置算子的优化实现，优先级高
- 实验性算子包：尚在验证中的优化版本，优先级低

### 更新频率不同

基础算子稳定后很少更新，而实验性算子或业务定制算子需要频繁迭代。拆分到不同算子包可以独立编译和部署，避免每次修改都重新编译整个算子库。

**示例**：
- 基础算子包：稳定的通用算子，更新频率低
- 业务定制算子包：特定业务场景的算子，更新频率高

## 优先级配置

当存在多个自定义算子包时，可以通过 `load_priority` 配置它们之间的相对优先级，控制相同 OpType 的算子以哪个包的实现为准。详细配置方法请参考[配置自定义算子优先级](./基本流程.md#配置自定义算子优先级)。

## 决策参考

| 场景 | 推荐策略 | 说明 |
|------|---------|------|
| 少量算子，统一管理 | 单算子包 | 所有算子放在一个包中 |
| 需要覆盖内置算子 | 自定义算子包即可 | 自定义算子包优先级天然高于内置算子包，同名算子自动覆盖 |
| 基础算子 + 实验算子 | 多算子包 | 拆分为基础包（稳定）和实验包（频繁迭代） |
| 不同业务团队维护 | 多算子包 | 每个团队维护独立的算子包，通过优先级配置集成 |
