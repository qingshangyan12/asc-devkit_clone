# 基本流程

> 类型：基础

本章节介绍 host 侧 Tiling 在接入 CANN 框架时的编程模式和 API 使用。

**Tiling 概念回顾：** Ascend C 算子在 AI Core 上执行时，由于 Local Memory（UB）容量有限，无法一次性加载全部输入数据，需要每次搬运一部分输入进行计算然后搬出，再搬运下一部分输入进行计算，直到得到完整的最终结果。这个数据切分和分块调度的过程就是 **Tiling**。根据算子的 shape 等信息来确定数据切分算法相关参数（比如每次搬运的块大小，以及总共循环多少次）的计算程序，称之为 **Tiling 实现**。

Tiling 实现完成后，获取到的 Tiling 切分算法相关参数会传递给 kernel 侧，用于指导并行数据的切分。由于 Tiling 实现中完成的均为标量计算，AI Core 并不擅长，所以将其独立出来在 host CPU 上执行。

**图 1** Tiling 实现的输入输出

![](../../../../../../figures/Tiling实现的输入输出.png "Tiling实现的输入输出")

如上图所示，Tiling 实现即为根据算子 shape 等信息来确定切分算法相关参数的过程。这里的算子 shape 等信息可以理解为是 **Tiling 实现的输入**，切分算法相关参数可以理解为是 **Tiling 实现的输出**。输入和输出都通过 Tiling 函数的参数（TilingContext\* context 上下文结构）来承载。也就是说，开发者可以从上下文结构中获取算子的输入、输出以及属性信息（即 Tiling 实现的输入），经过 Tiling 计算后，获取到 TilingData 数据结构（切分算法相关参数）、numBlocks 变量、用于选择不同 kernel 实现分支的 TilingKey、算子 workspace 的大小（即 Tiling 实现的输出），并将这些输出设置到上下文结构中。

## TilingData 定义方式

在开始编写 Tiling 实现之前，首先需要定义 TilingData 结构体，用于存储切分算法相关参数。AscendC 推荐使用**标准 C++ 语法**定义 Tiling 结构体，这种方式更符合 C++ 开发习惯，支持 bool 类型和数组，且允许不同算子使用同名结构体。

> [!NOTE] 何时使用宏定义方式
> 宏定义方式（BEGIN_TILING_DATA_DEF）仅在以下场景需要使用：
> - 使用高阶 API（如 MultiCoreMatmulTiling、TCubeTiling）时，**必须**使用宏定义方式，因为需要通过 `TILING_DATA_FIELD_DEF_STRUCT` 嵌套框架预定义的结构体
> - 维护使用宏方式开发的旧项目
>
> 关于高阶 API 场景的详细说明，请参考[使用高阶 API 时配套的 Tiling 实现](./使用高阶API时配套的Tiling实现.md)。

本文档以标准 C++ 语法为主线介绍 Tiling 实现的基本流程。

## 核心概念

TilingData、numBlocks、TilingKey、workspace 这些概念的具体解释如下：

- **TilingData**：切分算法相关参数，比如每次搬运的块大小以及总共循环多少次，通过结构体存储，由开发者自行设计。使用标准 C++ 语法定义 TilingData 结构体，头文件放在 op_kernel 目录下。Tiling 实现函数中通过 `context->GetTilingData<T>()` 获取结构体指针并赋值，框架自动处理序列化和保存。标准 C++ 方式支持 bool 类型、数组、以及同名结构体隔离。完整定义方法、示例代码和使用约束，请参考下方"步骤一"和"使用约束"章节。

- **numBlocks**：规定核函数启动的逻辑 Block 数量，通过 `context->SetBlockDim()` 设置。numBlocks 是逻辑 Block 概念，取值范围为 \[1, 65535\]，一般设置为硬件平台的逻辑 Block 数或其倍数。关于 numBlocks 在 Kernel 侧的运行机制、耦合/分离模式差异等详细说明，请参考 [Kernel 侧算子实现](../Kernel侧算子实现/基本流程.md)。

- **TilingKey（可选）**：用于区分不同的 Kernel 实现分支，通过数字标识将 Kernel 代码拆分为多个独立入口函数。Host 侧通过 `SetTilingKey` 设置分支。详细原理、Kernel 侧使用方法和完整示例请参考[多分支策略](../多分支策略.md)。

- **WorkspaceSize**：workspace 是设备侧 Global Memory 上的一块内存，在 Tiling 函数中通过 `context->GetWorkspaceSizes()` 设置大小。workspace 内存包括 Ascend C API 预留内存（通过 [GetLibApiWorkSpaceSize](https://gitcode.com/cann/asc-devkit/blob/master/docs/api/Utils-API/平台信息获取/PlatformAscendC/GetLibApiWorkSpaceSize.md) 获取）和算子自定义内存（按需）两部分。关于 workspace 在 Kernel 侧的获取和使用方法，请参考 [Kernel 侧算子实现](../Kernel侧算子实现/基本流程.md)。

    在 Tiling 函数中设置方法如下：

    ```cpp
    auto workspaceSizes = context->GetWorkspaceSizes(1); // 只使用1块workspace
    workspaceSizes[0] = sysWorkspaceSize + usrWorkspaceSize;
    ```

下面从一个简单的 Add 算子为例介绍 Tiling 的实现流程。本样例中待处理数据的 Shape 大小可以平均分配到每个 Block 上，并且可以对齐到一个 datablock（32B）的大小。

### 步骤一：定义 TilingData 结构体

首先完成算子 TilingData 结构定义头文件的编写，该文件命名为"算子名称\_tiling.h"，位于算子工程的 op_kernel 目录下。样例代码如下：

```cpp
#ifndef ADD_CUSTOM_TILING_H
#define ADD_CUSTOM_TILING_H
#include <cstdint>

struct AddCustomTilingData {
    uint32_t totalLength;  // 总计算数据量
    uint32_t tileNum;      // 每个Block上总计算数据分块个数
};
#endif // ADD_CUSTOM_TILING_H
```

具体的编写步骤如下：

1. 代码框架编写：需要增加 #ifndef... 的判断条件，防止头文件的重复包含；需要包含 `<cstdint>` 头文件以使用 `uint32_t` 等固定宽度整数类型。

2. TilingData 参数设计：TilingData 参数本质上是和并行数据切分相关的参数。本示例算子使用了 2 个 tiling 参数：totalLength、tileNum。totalLength 是指需要计算的数据量大小，tileNum 是指每个 Block 上总计算数据分块个数。比如，totalLength 这个参数传递到 kernel 侧后，可以通过除以参与计算的 Block 数，得到每个 Block 上的计算量，这样就完成了多 Block 数据的切分。

3. TilingData 结构定义：使用标准 C++ struct 语法定义 TilingData 结构体，直接声明成员变量即可。与宏定义方式不同，不需要显式注册宏。

> [!NOTE] 头文件位置说明
> 标准 C++ 方式的头文件必须放在 op_kernel 目录下，因为该目录下的文件会被打包进算子包，供在线编译场景使用。若放在其他目录，可能导致在线编译因找不到相关文件而失败。

### 步骤二：实现 Tiling 函数

完成算子 host 实现 cpp 文件中 Tiling 函数实现，该文件命名为"算子名称.cpp"，位于算子工程的 op_host 目录下。Tiling 函数的原型是固定的，接受一个 TilingContext 作为输入，在此 context 上可以获取到输入、输出的 Shape 指针等内容。注册的 Tiling 函数由框架调用，调用时会传入 TilingContext 参数。

使用标准 C++ 方式时，通过 `context->GetTilingData<T>()` 获取 TilingData 指针，直接对成员变量赋值即可，**不需要手动调用 SaveToBuffer**。样例代码如下：

```cpp
#include "../op_kernel/add_custom_tiling.h"  // 包含TilingData结构体定义

namespace optiling {
const uint32_t NUM_BLOCKS = 8;
const uint32_t TILE_NUM = 8;

static ge::graphStatus TilingFunc(gert::TilingContext *context)
{
    // 1. 获取TilingData指针（框架自动处理序列化）
    AddCustomTilingData *tiling = context->GetTilingData<AddCustomTilingData>();
    
    // 2. 获取输入shape信息
    // GetInputShape(0)：获取第 0 个输入的 shape 指针
    // GetOriginShape()：获取原始（未经 padding 等操作修改的）shape
    // GetShapeSize()：计算所有维度的乘积，即总元素数
    uint32_t totalLength = context->GetInputShape(0)->GetOriginShape().GetShapeSize();
    
    // 3. 直接赋值TilingData成员变量
    tiling->totalLength = totalLength;
    tiling->tileNum = TILE_NUM;
    
    // 4. 设置numBlocks
    context->SetBlockDim(NUM_BLOCKS);
    
    // 5. （可选）设置workspace
    size_t *currentWorkspace = context->GetWorkspaceSizes(1);
    currentWorkspace[0] = 0;
    
    return ge::GRAPH_SUCCESS;
}
} // namespace optiling
```

TilingFunc 的关键步骤：获取 TilingData 指针 → 获取 shape 信息 → 计算并赋值 TilingData 成员 → 设置 Block 数 → （可选）设置 TilingKey 和 workspace。各 API 的详细说明和约束请参考 [TilingContext API 文档](https://gitcode.com/cann/asc-devkit/blob/master/docs/api/Utils-API/TilingAPI/TilingContext/TilingContext.md)。

### 步骤三：Kernel 侧使用 TilingData

Tiling 函数完成 TilingData 的填写后，Kernel 侧需要通过 `REGISTER_TILING_DEFAULT`（标准 C++ 方式）或 `REGISTER_TILING_DATA_CLASS`（宏定义方式）注册 TilingData 结构体，并通过 `GET_TILING_DATA` 解析获取 TilingData 实例。

Kernel 侧的 TilingData 注册和获取方法的完整说明，包括 TilingKey 场景下多 TilingData 的注册方式，请参考[Kernel 侧算子实现 — TilingData 处理](../Kernel侧算子实现/基本流程.md#tilingdata-处理)。

## 使用约束

使用标准 C++ 语法定义 Tiling 结构体时，需要注意以下约束：

1. **不支持成员函数**：Tiling 结构体 Device 侧和 Host 侧共用，成员函数存在 `__aicore__` 修饰符差异，会导致编译或执行问题。

    ```cpp
    class TilingData {
    public:
        uint32_t xxx;
        __aicore__ funcA() { ... }  // 错误：host 侧不支持 __aicore__
        void func() { ... }         // 错误：device 侧缺少 __aicore__
    };
    ```

2. **不支持指针、引用类型**：此类数据类型会导致 Host→Device 数据解析异常。

    ```cpp
    class TilingData {
    public:
        uint32_t* totalLength;  // 不支持
        uint32_t& tileNum;       // 不支持
    };
    ```

3. **仅支持 POD 类型**：不支持虚函数、虚继承、模板类。`GetTilingData<T>()` 的类型参数必须与实际类型完全匹配：

    ```cpp
    class A { public: uint32_t totalLength; };
    class B: public A { public: uint32_t xxx; };

    // 错误：不支持多态
    B *tiling = context->GetTilingData<A>();
    // 正确：类型精确匹配
    B *tiling = context->GetTilingData<B>();
    ```

4. **GetTilingData 不自动初始化**：获取的 TilingData 成员变量不保证有初值，必须显式赋值。

    ```cpp
    TilingData *tiling = context->GetTilingData<TilingData>();
    // 此时 totalLength、tileNum 为不确定值，需显式赋值
    tiling->totalLength = totalLength;
    tiling->tileNum = TILE_NUM;
    ```

5. **Kernel 侧多模板参数的写法**：当 Tiling 结构体使用多个模板参数时（如 `template<int32_t sizeA, int32_t sizeB>`），Kernel 侧宏函数中逗号会导致编译异常，需使用 `using` 别名：

    ```cpp
    template<int32_t sizeA, int32_t sizeB>
    class A { public: uint32_t totalLength; uint32_t dataArray[sizeA]; };

    // Kernel 侧
    using ATiling = A<3,5>;
    REGISTER_TILING_DEFAULT(ATiling);  // 多模板参数时必须用 using
    ```

6. **bool/数组/同名隔离特性**：标准 C++ 方式支持 bool 类型、数组（包括多维数组和结构体数组）、以及不同算子使用同名但结构不同的 TilingData。宏定义方式不支持 bool 类型和同名隔离。

    ```cpp
    class TilingData {
    public:
        bool enableFeature;           // 宏方式不支持 bool
        uint32_t tileSizes[2][128];   // 支持多维数组
    };
    ```

## 高阶 API 场景

当算子需要使用高阶 API（如 MultiCoreMatmulTiling、TCubeTiling 等）时，高阶 API 预定义的结构体（如 TCubeTiling）需要嵌套到 TilingData 中，可通过宏定义方式或标准 C++ 方式实现。关于高阶 API 的完整使用说明，包括 TilingData 定义、TilingFunc 实现和 Kernel 侧使用，请参考[使用高阶 API 时配套的 Tiling 实现](./使用高阶API时配套的Tiling实现.md)。
