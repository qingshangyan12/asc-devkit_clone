# Kernel侧算子实现

> 类型：基础

在[核函数](../../../../../编程模型/AI-Core-SIMD编程/核函数.md)（介绍 `__aicore__` 函数声明、参数传递等基础编程概念的外部文档）章节已经介绍了 kernel 侧算子核心的实现方法，本章节侧重于介绍接入 CANN 框架时编程模式和 API 使用的差异。如果尚未阅读该文档，建议先了解核函数的基本概念。

**Kernel 侧编程核心概念：** Ascend C 的 Kernel 在 AI Core 上执行，采用 SIMD（单指令多数据）编程模型。由于 AI Core 的 Local Memory（UB）容量有限，Kernel 需要遵循"搬运-计算-搬运"的三段式执行模式：通过 `DataCopy` 将数据从 Global Memory 搬运到 UB，在 UB 上执行向量计算，再将结果搬回 Global Memory。多个 AI Core 可以并行执行，通过 Block 索引实现数据切分和多核并行。

## Kernel 函数格式

### 命名规则

核函数名称必须与算子类型（OpType）保持对应关系。算子类型采用**大驼峰**命名，核函数名称采用**下划线**命名，框架在编译和运行时自动完成转换。

| 算子类型（大驼峰） | 核函数名（下划线） |
|---|---|
| AddCustom | add\_custom |
| MatmulCustom | matmul\_custom |
| ReduceMaxCustom | reduce\_max\_custom |
| Conv2DCustom | conv2d\_custom |
| GatherV2Custom | gather\_v2\_custom |

完整的转换规则和更多示例请参考[命名转换规则对照表](../../附录/命名转换规则对照表.md)。

### 函数形式

核函数支持两种定义形式：

**C 风格**：使用 `extern "C"` 修饰，适用于单 Kernel 或 TilingKey 划分 Kernel 场景。msopgen 工具自动生成的模板即为此形式。

```cpp
extern "C" __global__ __aicore__ void add_custom(GM_ADDR x, GM_ADDR y, GM_ADDR z,
                                                  GM_ADDR workspace, GM_ADDR tiling)
{
    REGISTER_TILING_DEFAULT(AddCustomTilingData);
    GET_TILING_DATA(tilingData, tiling);
    KernelAdd op;
    op.Init(x, y, z, tilingData.totalLength, tilingData.tileNum);
    op.Process();
}
```

**C++ 模板风格**：不使用 `extern "C"`，通过模板参数实现编译期分支控制。适用于 kernel 代码需要在基础算子开发方式（<<<>>>）和 aclnn 算子工程化场景共用的情况。

```cpp
template<typename D_T_X, typename D_T_Y, typename D_T_Z, int TILE_NUM>
__global__ __aicore__ void add_custom(GM_ADDR x, GM_ADDR y, GM_ADDR z,
                                      GM_ADDR workspace, GM_ADDR tiling)
{
    GET_TILING_DATA(tilingData, tiling);
    KernelAdd<D_T_X, D_T_Y, D_T_Z> op;
    op.Init(x, y, z, tilingData.totalLength, TILE_NUM);
    op.Process();
}
```

C++ 模板风格的完整说明和模板参数定义方法请参考[多分支策略](../多分支策略.md#kernel-模板命名参数替代)。

### 参数顺序

核函数参数必须按照"**输入、输出、workspace、tiling**"的顺序排布，开发者不应调整其顺序。框架在调用核函数时会按照原型定义中的输入输出顺序依次传入参数，workspace 和 tiling 是框架自动追加的参数，必须放在最后。

> [!NOTE] 输入输出同名场景
> 算子原型定义中的输入和输出同名时，msopgen 自动生成的核函数中，输出参数增加 `ref` 后缀予以区分。示例：
> ```cpp
> extern "C" __global__ __aicore__ void add_custom(GM_ADDR x, GM_ADDR y,
>                                                   GM_ADDR x_ref, GM_ADDR workspace,
>                                                   GM_ADDR tiling);
> ```

## TilingData 处理

### 注册 TilingData

注册 TilingData 是为了告知框架该 kernel 入口使用的 TilingData 结构体类型。根据 TilingData 的定义方式不同，注册方法如下：

**标准 C++ 方式**：在 kernel 函数体内使用 `REGISTER_TILING_DEFAULT` 注册。

```cpp
extern "C" __global__ __aicore__ void add_custom(GM_ADDR x, GM_ADDR y, GM_ADDR z,
                                                  GM_ADDR workspace, GM_ADDR tiling)
{
    REGISTER_TILING_DEFAULT(AddCustomTilingData);  // 注册标准 C++ 结构体
    GET_TILING_DATA(tilingData, tiling);
    // ...
}
```

**宏定义方式**：在 Host 侧使用 `BEGIN_TILING_DATA_DEF` / `REGISTER_TILING_DATA_CLASS` 注册（定义方法参考[Host 侧 Tiling 实现](../Host侧Tiling实现/基本流程.md)），Kernel 侧无需注册，直接使用 `GET_TILING_DATA` 获取。

```cpp
// Kernel 侧（无需 REGISTER_TILING_DEFAULT）
extern "C" __global__ __aicore__ void my_add(GM_ADDR x, GM_ADDR y, GM_ADDR z,
                                              GM_ADDR workspace, GM_ADDR tiling)
{
    GET_TILING_DATA(tilingData, tiling);  // 直接使用
    // ...
}
```

**带 TilingKey 的场景**：当算子使用 TilingKey 区分不同 kernel 分支时，可通过 `REGISTER_TILING_DATA_CLASS` 为不同 TilingKey 注册不同的 TilingData 结构体。

```cpp
// 注册默认 TilingData（未指定 tiling_key 或 tiling_key 不匹配时使用）
REGISTER_TILING_DATA_CLASS(AddCustom, AddStruct)
// 注册 tiling_key = 1 时的 TilingData（参数格式：opType_tilingKey）
REGISTER_TILING_DATA_CLASS(AddCustom_1, AddStructSample1)
```

> `REGISTER_TILING_DATA_CLASS` 中第一个参数为 `${opType}` + `_` + `tiling_key`。若指定 tiling_key 未注册匹配的 TilingData，则回退使用默认结构体。

TilingData 的定义方式和选择建议请参考[Host 侧 Tiling 实现](../Host侧Tiling实现/基本流程.md)。

### 获取 TilingData

在 kernel 函数中通过 `GET_TILING_DATA` 宏将框架传入的 tiling 参数反序列化为 TilingData 结构体实例：

```cpp
extern "C" __global__ __aicore__ void add_custom(GM_ADDR x, GM_ADDR y, GM_ADDR z,
                                                  GM_ADDR workspace, GM_ADDR tiling)
{
    REGISTER_TILING_DEFAULT(AddCustomTilingData);
    GET_TILING_DATA(tilingData, tiling);  // tilingData 为 AddCustomTilingData 类型的实例

    KernelAdd op;
    op.Init(x, y, z, tilingData.totalLength, tilingData.tileNum);
    op.Process();
}
```

`GET_TILING_DATA` 展开后根据注册方式的不同，将 tiling 原始数据解析为对应的结构体或结构体指针。

> 当使用 TilingKey 区分多个 kernel 分支时，可通过 `TILING_KEY_IS` 在 kernel 内选择执行路径。完整说明请参考[多分支策略](../多分支策略.md)。

## 信息获取

### 获取算子输入输出数据类型和格式

在核函数中可通过 `DTYPE_<Arg>`、`ORIG_DTYPE_<Arg>`、`FORMAT_<Arg>` 三种宏获取输入输出的数据类型和格式信息。

**宏名映射规则**：`<Arg>` 由核函数参数名（即原型定义中 Input/Output 的 `name` 字段）转换为**全大写形式**生成。例如参数名为 `input_data`，则宏名为 `DTYPE_INPUT_DATA`。

| 原型定义 name | 核函数参数名 | 宏名 |
|---|---|---|
| x | x | DTYPE\_X |
| y | y | DTYPE\_Y |
| z | z | DTYPE\_Z |
| input\_data | input\_data | DTYPE\_INPUT\_DATA |
| output\_result | output\_result | DTYPE\_OUTPUT\_RESULT |

**三种宏的含义**：

- **DTYPE\_\<Arg\>**：Device 侧实际可使用的 C++ 数据类型，如 `half`、`float`、`int32_t` 等。可直接用于变量声明和模板参数。
- **ORIG\_DTYPE\_\<Arg\>**：Host 侧原型定义时指定的数据类型枚举值，如 `ge::DT_FLOAT16`、`ge::DT_FLOAT`、`ge::DT_INT32` 等。用于与枚举值比较的分支判断。
- **FORMAT\_\<Arg\>**：Host 侧原型定义时指定的数据格式枚举值，如 `ge::FORMAT_ND`、`ge::FORMAT_NZ` 等。

> **DTYPE_X 和 ORIG_DTYPE_X 的关键区别**：当原型定义 `DataType({ge::DT_FLOAT16})` 时，`DTYPE_X` 的值为 `half`（C++ 类型，可直接用于计算），`ORIG_DTYPE_X` 的值为 `ge::DT_FLOAT16`（枚举值，用于条件判断）。

使用示例：

```cpp
extern "C" __global__ __aicore__ void add_custom(GM_ADDR x, GM_ADDR y, GM_ADDR z,
                                                  GM_ADDR workspace, GM_ADDR tiling)
{
    GET_TILING_DATA(tilingData, tiling);

    DTYPE_X temp;                     // 声明与 x 同类型的变量
    func<DTYPE_Z>();                  // 以 z 的类型作为模板参数

    if (FORMAT_Y == FORMAT_ND) {      // 根据 y 的格式分支
        // ND 格式处理逻辑
    }
    if (ORIG_DTYPE_Y == DT_FLOAT) {   // 根据 y 的原始类型分支
        // float 类型处理逻辑
    }
}
```
