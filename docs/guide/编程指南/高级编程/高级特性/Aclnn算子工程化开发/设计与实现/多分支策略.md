# 多分支策略

> 类型：扩展

当一个算子在不同场景下需要走不同的算法逻辑时（如不同的 shape 范围、不同的数据类型），可以将 Kernel 代码拆分为多个独立入口函数以减少 icache miss，或通过模板参数化提升多分支场景的可读性和类型安全。本文介绍两种方式：TilingKey（数字标识分支）和 Kernel 模板（命名参数替代）。

## TilingKey：数字标识分支

### 基本原理

TilingKey 使用数字标识不同的 Kernel 实现分支。其核心价值在于**减少 icache miss 和 scalar 耗时**，优化单次 Kernel 调用性能。

假设有如下 kernel 代码：

```cpp
if (condition) {
  ProcessA();
} else {
  ProcessB();
}
```

如果 ProcessA、ProcessB 是较大的函数，编译后 Kernel 代码体积会很大。每次运行只走其中一个分支，但条件判断和跳转在代码大到一定程度（16-32K，不同芯片存在差异）后会出现 **icache miss**，影响性能。

通过 TilingKey 可以将两个分支拆分为独立的 Kernel 入口函数：

```cpp
if (TILING_KEY_IS(1)) {
  ProcessA();    // TilingKey = 1 时编译为独立入口
} else if (TILING_KEY_IS(2)) {
  ProcessB();    // TilingKey = 2 时编译为独立入口
}
```

编译时框架会自动识别 TilingKey 并编译多个 Kernel 入口函数，将条件判断进行**常量折叠**，消除运行时的分支判断开销。

### Host 侧设置

在 TilingFunc 中通过 `SetTilingKey` 设置当前场景对应的 TilingKey 值：

```cpp
static ge::graphStatus TilingFunc(gert::TilingContext* context)
{
    // ... 获取 shape 信息 ...

    if (condition) {
        context->SetTilingKey(1);  // 场景A：走 ProcessA
    } else {
        context->SetTilingKey(2);  // 场景B：走 ProcessB
    }

    context->SetBlockDim(NUM_BLOCKS);
    // ... 设置 TilingData ...

    return ge::GRAPH_SUCCESS;
}
```

### Kernel 侧使用

在核函数中通过 `TILING_KEY_IS(key)` 宏判断当前执行的是哪个分支：

```cpp
extern "C" __global__ __aicore__ void my_op(GM_ADDR x, GM_ADDR y, GM_ADDR z,
                                             GM_ADDR workspace, GM_ADDR tiling)
{
    GET_TILING_DATA(tilingData, tiling);

    if (TILING_KEY_IS(1)) {
        // 场景A的处理逻辑
        ProcessA(tilingData);
    } else if (TILING_KEY_IS(2)) {
        // 场景B的处理逻辑
        ProcessB(tilingData);
    }
}
```

> [!NOTE] 说明
> TILING_KEY_IS 是编译期常量判断，编译器会将未命中的分支完全移除（常量折叠），因此不存在运行时开销。

### 完整示例

以下示例展示一个算子根据输入数据量选择不同的处理策略：

**Host 侧：**

```cpp
// TilingData 结构体定义（op_kernel/tiling_data.h）
struct TilingData {
    uint32_t totalLength;  // 总计算数据量
    uint32_t tileNum;      // 分块数
};

namespace optiling {
const uint32_t SHAPE_THRESHOLD = 1024;
const uint32_t NUM_BLOCKS = 8;  // 逻辑 Block 数

static ge::graphStatus TilingFunc(gert::TilingContext *context)
{
    uint32_t totalLength = context->GetInputShape(0)->GetOriginShape().GetShapeSize();

    TilingData *tiling = context->GetTilingData<TilingData>();
    tiling->totalLength = totalLength;

    // 根据数据量选择不同的 Kernel 分支
    if (totalLength <= SHAPE_THRESHOLD) {
        context->SetTilingKey(1);  // 小数据量：单块处理
        tiling->tileNum = 1;
    } else {
        context->SetTilingKey(2);  // 大数据量：多块切分处理
        tiling->tileNum = NUM_BLOCKS * 8;
    }

    context->SetBlockDim(NUM_BLOCKS);

    size_t *currentWorkspace = context->GetWorkspaceSizes(1);
    currentWorkspace[0] = 0;

    return ge::GRAPH_SUCCESS;
}
} // namespace optiling
```

**Kernel 侧：**

```cpp
extern "C" __global__ __aicore__ void my_op(GM_ADDR x, GM_ADDR y, GM_ADDR z,
                                             GM_ADDR workspace, GM_ADDR tiling)
{
    GET_TILING_DATA(tilingData, tiling);
    KernelMyOp op;
    op.Init(x, y, z, tilingData.totalLength, tilingData.tileNum);

    if (TILING_KEY_IS(1)) {
        op.ProcessSmall();   // 小数据量：单次处理全部数据
    } else if (TILING_KEY_IS(2)) {
        op.ProcessLarge();   // 大数据量：分块循环处理
    }
}
```

### 编译加速

开发调试时，可以通过 `--tiling_key` 编译选项仅编译指定的 TilingKey 分支，加速编译过程：

```cmake
npu_op_kernel_options(ascendc_kernels MyOp COMPUTE_UNIT Ascend910B OPTIONS --tiling_key=1)
```

关于编译选项的完整说明，请参考[基本流程](../编译与部署/基本流程.md)中的编译选项部分。

## Kernel 模板

### 为什么需要 Kernel 模板

TilingKey 使用数字标识分支，在分支数量较多时存在可读性问题：

- 数字本身没有语义，需要开发者记忆"TilingKey 1 对应什么场景"
- 分支增多后，Host 侧和 Kernel 侧的数字对应关系难以维护

Kernel 模板用命名参数（如 `TILE_NUM`、`IS_SPLIT`）替代数字标识，提升可读性和维护性。

完整样例请参考 [Kernel 模板编程样例](https://gitcode.com/cann/asc-devkit/tree/master/examples/01_simd_cpp_api/02_features/99_acl_based/00_acl_compilation/custom_op/add_custom_template)。

### 步骤一：定义模板参数

在算子工程的 op_kernel 目录下，新增头文件定义模板参数和模板参数组合。本示例中头文件命名为 `tiling_key_add_custom.h`。

该头文件中需要包含模板头文件 `ascendc/host_api/tiling/template_argument.h`，定义模板参数 `ASCENDC_TPL_ARGS_DECL` 和模板参数组合 `ASCENDC_TPL_ARGS_SEL`。具体 API 参考见[模板参数定义](https://gitcode.com/cann/asc-devkit/blob/master/docs/api/Utils-API/Tiling模板编程/模板参数定义.md)。

Kernel 模板编程涉及以下宏：

| 宏类别 | 宏名称 | 功能 |
|--------|--------|------|
| 声明入口 | ASCENDC_TPL_ARGS_DECL | 定义模板参数列表 |
| 类型参数 | ASCENDC_TPL_DATATYPE_DECL | 声明数据类型模板参数 |
| 整数参数 | ASCENDC_TPL_UINT_DECL | 声明无符号整数模板参数 |
| 布尔参数 | ASCENDC_TPL_BOOL_DECL | 声明布尔模板参数 |
| 选择入口 | ASCENDC_TPL_SEL | 定义模板参数组合列表 |
| 单组组合 | ASCENDC_TPL_ARGS_SEL | 定义一组模板参数组合 |
| 选择约束 | ASCENDC_TPL_DATATYPE_SEL 等 | 在组合中约束参数取值 |

```cpp
#include "ascendc/host_api/tiling/template_argument.h"

// 模板参数
ASCENDC_TPL_ARGS_DECL(AddCustomTemplate, // 算子OpType
ASCENDC_TPL_DATATYPE_DECL(D_T_X, C_DT_FLOAT, C_DT_FLOAT16, ASCENDC_TPL_INPUT(0)),  // DataType类型的模板参数定义：输入参数x的数据类型，取值范围为float16/float32, ASCENDC_TPL_INPUT(0)说明对应Kernel侧第0个输入
ASCENDC_TPL_DATATYPE_DECL(D_T_Y, C_DT_FLOAT, C_DT_FLOAT16, ASCENDC_TPL_INPUT(1)),  // DataType类型的模板参数定义：输入参数y的数据类型，取值范围为float16/float32, ASCENDC_TPL_INPUT(1)说明对应Kernel侧第1个输入
ASCENDC_TPL_DATATYPE_DECL(D_T_Z, C_DT_FLOAT, C_DT_FLOAT16, ASCENDC_TPL_OUTPUT(0)), // DataType类型的模板参数定义：输入参数z的数据类型，取值范围为float16/float32, ASCENDC_TPL_OUTPUT(0)说明对应Kernel侧第0个输出
// ASCENDC_TPL_UINT_DECL 参数说明：参数1=模板参数名, 参数2=位宽标识(8位), 参数3=类型标识, 参数4~=可选取值列表
ASCENDC_TPL_UINT_DECL(TILE_NUM, ASCENDC_TPL_8_BW, ASCENDC_TPL_UI_MIX, 2, 0, 2, 3, 5, 10, 12, 13, 9, 8),// 自定义UINT类型（无符号整形）的模板参数定义
ASCENDC_TPL_BOOL_DECL(IS_SPLIT, 0, 1), // 自定义bool类型的模板参数定义
);

// 模板参数组合
ASCENDC_TPL_SEL(
    ASCENDC_TPL_ARGS_SEL(
    ASCENDC_TPL_KERNEL_TYPE_SEL(ASCENDC_TPL_AIV_ONLY),
    ASCENDC_TPL_DATATYPE_SEL(D_T_X, C_DT_FLOAT16),
    ASCENDC_TPL_DATATYPE_SEL(D_T_Y, C_DT_FLOAT16),
    ASCENDC_TPL_DATATYPE_SEL(D_T_Z, C_DT_FLOAT16),
    ASCENDC_TPL_UINT_SEL(TILE_NUM, ASCENDC_TPL_UI_LIST, 1, 8),
    ASCENDC_TPL_BOOL_SEL(IS_SPLIT, 0, 1)
    ),
    ASCENDC_TPL_ARGS_SEL(
    ASCENDC_TPL_KERNEL_TYPE_SEL(ASCENDC_TPL_AIV_ONLY),
    ASCENDC_TPL_DATATYPE_SEL(D_T_X, C_DT_FLOAT),
    ASCENDC_TPL_DATATYPE_SEL(D_T_Y, C_DT_FLOAT),
    ASCENDC_TPL_DATATYPE_SEL(D_T_Z, C_DT_FLOAT),
    ASCENDC_TPL_UINT_SEL(TILE_NUM, ASCENDC_TPL_UI_LIST, 1, 8),
    ASCENDC_TPL_BOOL_SEL(IS_SPLIT, 0, 1)
    ),
);
```

### 步骤二：Host 侧配置

Host 侧调用 `ASCENDC_TPL_SEL_PARAM` 接口自动生成并配置 TilingKey。输入参数为模板参数的具体值，传入时需要与定义模板参数的头文件中的模板参数顺序保持一致。

```cpp
#include "tiling_key_add_custom.h"
static const uint32_t NUM_BLOCKS = 8;
static const uint32_t MIN_LENGTH_FOR_SPLIT = 1024;
static const uint32_t DEFAULT_TILE_NUM = 8;

static ge::graphStatus TilingFunc(gert::TilingContext *context)
{
    TilingData tiling;
    uint32_t totalLength = context->GetInputShape(0)->GetOriginShape().GetShapeSize();
    ge::DataType dtype_x = context->GetInputDesc(0)->GetDataType();
    ge::DataType dtype_y = context->GetInputDesc(1)->GetDataType();
    ge::DataType dtype_z = context->GetOutputDesc(0)->GetDataType();  // z 是第 0 个输出
    uint32_t D_T_X = static_cast<int>(dtype_x), D_T_Y = static_cast<int>(dtype_y), D_T_Z = static_cast<int>(dtype_z), TILE_NUM = 1, IS_SPLIT = 0;
    if(totalLength< MIN_LENGTH_FOR_SPLIT){
        IS_SPLIT = 0;
        TILE_NUM = 1;
    }else{
        IS_SPLIT = 1;
        TILE_NUM = DEFAULT_TILE_NUM;
    }
    context->SetBlockDim(NUM_BLOCKS);
    // 宏定义方式使用 setter 方法赋值（标准 C++ 方式直接赋值 tiling->totalLength = ...）
    tiling.set_totalLength(totalLength);
    // 宏定义方式需要手动调用 SaveToBuffer 序列化
    tiling.SaveToBuffer(context->GetRawTilingData()->GetData(), context->GetRawTilingData()->GetCapacity());
    context->GetRawTilingData()->SetDataSize(tiling.GetDataSize());
    ASCENDC_TPL_SEL_PARAM(context, D_T_X, D_T_Y, D_T_Z, TILE_NUM, IS_SPLIT);
    size_t *currentWorkspace = context->GetWorkspaceSizes(1);
    currentWorkspace[0] = 0;
    return ge::GRAPH_SUCCESS;
}
```

### 步骤三：Kernel 侧实现

Kernel 实现文件中包含模板参数定义头文件，核函数添加 template 模板，参数顺序需要与定义模板参数的头文件中的模板参数顺序保持一致。通过对模板参数的分支判断，选择不同的 kernel 侧实现。

```cpp
#include "tiling_key_add_custom.h"

template<typename D_T_X, typename D_T_Y, typename D_T_Z, int TILE_NUM, int IS_SPLIT>
 __global__ __aicore__ void add_custom_template(GM_ADDR x, GM_ADDR y, GM_ADDR z, GM_ADDR workspace, GM_ADDR tiling)
{
    GET_TILING_DATA(tiling_data, tiling);
    KernelAdd<D_T_X, D_T_Y, D_T_Z> op;
    op.Init(x, y, z, tiling_data.totalLength, TILE_NUM);
    if constexpr (std::is_same_v<D_T_X, float> && std::is_same_v<D_T_Y, float> && std::is_same_v<D_T_Z, float>) {
        op.Process1();
    } else if constexpr (std::is_same_v<D_T_X, half> && std::is_same_v<D_T_Y, half> && std::is_same_v<D_T_Z, half>){
        if (IS_SPLIT == 0) {
            op.Process1();
        } else if(IS_SPLIT == 1) {
            op.Process2();
        }
    }
}
```

### 编译加速

Kernel 模板编程场景下，编译时可以通过 `--kernel-template-input` 编译选项配置仅编译指定的模板参数组合相关的 Kernel 代码，用于加速编译过程。关于编译选项的完整说明，请参考[基本流程](../编译与部署/基本流程.md)。

## 如何选择

**决策准则：**

1. Kernel 代码需要在基础算子开发方式（<<<>>>）和 aclnn 算子工程化场景共用时，使用 Kernel 模板方式。
2. 分支较多、需要提升分支规则可读性时，使用 Kernel 模板方式。
3. 其他场景，按需选择 TilingKey 或 Kernel 模板。
