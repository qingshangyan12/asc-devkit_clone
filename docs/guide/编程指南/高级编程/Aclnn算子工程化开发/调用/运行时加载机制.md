# 运行时加载机制

> 类型：扩展

本文说明自定义算子编译部署后，单算子 API 调用和算子包优先级相关的基本机制。这里仅描述开发者需要关注的接口调用、workspace 申请、部署路径和优先级配置，不展开框架内部调度细节。

## 1 单算子 API 的两段式调用

完成自定义算子编译后，工程会自动生成单算子 API。接口一般分为两段：

```cpp
aclnnStatus aclnnXxxGetWorkspaceSize(const aclTensor *src, ..., aclTensor *out,
                                     uint64_t *workspaceSize,
                                     aclOpExecutor **executor);
aclnnStatus aclnnXxx(void *workspace, uint64_t workspaceSize,
                     aclOpExecutor *executor, aclrtStream stream);
```

第一段接口用于计算本次调用需要的 workspace 大小，并返回执行所需的 `aclOpExecutor`：

```cpp
uint64_t workspaceSize = 0;
aclOpExecutor *executor = nullptr;
CHECK_ACL(aclnnXxxGetWorkspaceSize(input0, input1, output,
                                   &workspaceSize, &executor));
```

如果 `workspaceSize` 大于 0，开发者需要按该大小申请 NPU 侧 Global Memory：

```cpp
void *workspaceDeviceMem = nullptr;
if (workspaceSize > 0) {
    CHECK_RTL(aclrtMalloc(&workspaceDeviceMem, workspaceSize,
                          ACL_MEM_MALLOC_HUGE_FIRST));
}
```

第二段接口提交算子执行：

```cpp
CHECK_ACL(aclnnXxx(workspaceDeviceMem, workspaceSize, executor, stream));
CHECK_RTL(aclrtSynchronizeStream(stream));
```

`Xxx` 对应算子原型注册时传入的算子类型。完整调用流程请参考[单算子API调用](./单算子API调用.md)。

## 2 Workspace 与 Tiling 的关系

Host 侧 Tiling 函数可以通过 `context->GetWorkspaceSizes()` 设置 workspace 大小。设置后：

- 单算子 API 调用场景下，开发者通过第一段接口获取 `workspaceSize`，再自行申请对应大小的 NPU Global Memory。
- 算子入图场景下，框架会根据设置的大小申请对应的 Global Memory。

申请到 workspace 后，Kernel 侧可以按算子实现逻辑使用该内存。workspace 大小应按实际需求计算，避免过度预留。

## 3 算子包部署后的加载路径

算子包默认安装时，不配置 `--install-path`，安装成功后会将自定义算子相关文件部署到：

```text
${INSTALL_DIR}/opp/vendors/<vendor_name>
```

其中 `${INSTALL_DIR}` 为 CANN 软件安装路径，root 用户默认路径为 `/usr/local/Ascend/cann`；`<vendor_name>` 来自 `CMakePresets.json` 中的 `vendor_name` 配置，默认值为 `customize`。

默认安装后的关键目录包括：

```text
opp/vendors/<vendor_name>
├── op_api      // 单算子 API 头文件和 libcust_opapi.so
├── op_impl     // Kernel 二进制、Tiling 动态库等实现文件
├── op_proto    // 算子原型库
└── framework   // AI 框架适配插件
```

指定目录安装时，执行：

```bash
./custom_opp_<target os>_<target architecture>.run --install-path=<path>
```

安装成功后，文件会部署到：

```text
<path>/vendors/<vendor_name>
```

使用该目录下的自定义算子前，需要执行：

```bash
source <path>/vendors/<vendor_name>/bin/set_env.bash
```

该脚本会将当前自定义算子包安装路径追加到 `ASCEND_CUSTOM_OPP_PATH`，使该算子包在当前环境中生效。

## 4 多算子包优先级

多算子包共存时，如果不同算子包目录下存在相同 OpType 的自定义算子，则以优先级高的算子包目录下的算子为准。

### 4.1 默认安装场景

默认安装到 `${INSTALL_DIR}/opp/vendors` 的多个自定义算子包，可通过 `opp/vendors/config.ini` 配置优先级：

```ini
load_priority=vendor_name1,vendor_name2,vendor_name3
```

`load_priority` 后面的厂商名按优先级从高到低排列。

### 4.2 指定目录安装场景

指定目录安装时，如果需要多个自定义算子包同时生效，分别执行各算子包安装路径下的 `set_env.bash`。每次执行脚本都会将当前算子包安装路径追加到 `ASCEND_CUSTOM_OPP_PATH` 的最前面，因此脚本执行顺序越靠后，算子包优先级越高。

```bash
source <path>/vendors/vendor_name1/bin/set_env.bash  # 先执行，优先级较低
source <path>/vendors/vendor_name2/bin/set_env.bash  # 后执行，优先级较高
```

此时 `ASCEND_CUSTOM_OPP_PATH` 类似：

```text
ASCEND_CUSTOM_OPP_PATH=<path>/vendors/vendor_name2:<path>/vendors/vendor_name1:
```

指定目录安装场景下安装的算子包优先级高于默认方式安装的算子包。

## 5 动态库编译场景

使用算子动态库和静态库编译时，会在 `${CMAKE_INSTALL_PREFIX}` 下生成单算子调用头文件、算子原型定义头文件、算子库以及 CMake 配置文件。当前 `npu_op_package` 流程中，常见目录如下：

```text
${CMAKE_INSTALL_PREFIX}
├── include
│   ├── aclnn_<op>.h
│   └── op_proto.h
└── lib
    ├── libcust_opapi.so      // TYPE SHARED 模式生成
    ├── lib${vendor_name}.a   // TYPE STATIC 模式生成
    └── cmake/${vendor_name}
```

单算子调用场景下，应用可通过 `find_package(${vendor_name} REQUIRED PATHS ${CUST_PKG_PATH} NO_DEFAULT_PATH)` 集成动态库或静态库。

算子入图场景下，可将动态库路径追加到 `ASCEND_CUSTOM_OPP_PATH`：

```bash
export ASCEND_CUSTOM_OPP_PATH=${CMAKE_INSTALL_PREFIX}/lib/:${ASCEND_CUSTOM_OPP_PATH}
```

动态库编译和算子包编译功能同时使用时，动态库编译生成的产物优先级更高。
