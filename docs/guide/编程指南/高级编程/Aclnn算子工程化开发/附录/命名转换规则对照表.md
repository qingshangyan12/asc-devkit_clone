# 命名转换规则对照表

本文说明aclnn自定义算子工程中算子类型、实现文件名和Kernel函数名之间的命名转换规则。

## 1. 转换规则概述

自定义算子工程中，算子类型通常使用大驼峰命名，例如`AddCustom`；算子实现文件名和Kernel函数名通常使用下划线命名，例如`add_custom.cpp`和`add_custom`。

从大驼峰命名转换为下划线命名时，通常按以下规则处理：

1. 首字符为大写字母时，直接转换为小写字母。
2. 当前字符为大写字母，前一个字符为小写字母或数字时，在当前字符前插入下划线，并将当前字符转换为小写字母。
3. 当前字符为大写字母，前一个字符为大写字母，后一个字符为小写字母时，在当前字符前插入下划线，并将当前字符转换为小写字母。
4. 其他大写字母直接转换为小写字母，小写字母和数字保持不变。

## 2. 常见转换示例

| 算子类型 | 文件名/Kernel函数名 | 转换说明 |
|---|---|---|
| `AddCustom` | `add_custom` | `Add`转为`add`，`Custom`前插入下划线 |
| `ReduceMaxCustom` | `reduce_max_custom` | `Max`和`Custom`前插入下划线 |
| `MatmulCustom` | `matmul_custom` | `Matmul`转为`matmul`，`Custom`前插入下划线 |
| `BatchNormCustom` | `batch_norm_custom` | `Norm`和`Custom`前插入下划线 |
| `Conv2DCustom` | `conv2_d_custom` | `D`前一个字符为数字`2`，`D`和`Custom`前插入下划线 |
| `SoftmaxCustom` | `softmax_custom` | `Softmax`转为`softmax`，`Custom`前插入下划线 |
| `ReluCustom` | `relu_custom` | `Relu`转为`relu`，`Custom`前插入下划线 |
| `LayerNormCustom` | `layer_norm_custom` | `Norm`和`Custom`前插入下划线 |
| `SliceCustom` | `slice_custom` | `Slice`转为`slice`，`Custom`前插入下划线 |
| `GatherV2Custom` | `gather_v2_custom` | `V`和`Custom`前插入下划线 |
| `SplitVCustom` | `split_v_custom` | `V`和`Custom`前插入下划线 |
| `TransposeCustom` | `transpose_custom` | `Transpose`转为`transpose`，`Custom`前插入下划线 |
| `OneHotCustom` | `one_hot_custom` | `Hot`和`Custom`前插入下划线 |
| `TopKCustom` | `top_k_custom` | `K`和`Custom`前插入下划线 |

## 3. 特殊情况说明

### 3.1连续大写字母

算子类型中包含连续大写字母时，需要结合前后字符判断是否插入下划线。

| 算子类型 | 转换结果 | 说明 |
|---|---|---|
| `AbcAAc` | `abc_a_ac` | 第一个`A`前一个字符为小写`c`，插入下划线；第二个`A`后一个字符为小写`c`，插入下划线 |
| `GRUCell` | `gru_cell` | `GRU`作为连续大写段转为`gru`，`Cell`前插入下划线 |
| `NMSCustom` | `nms_custom` | `NMS`作为连续大写段转为`nms`，`Custom`前插入下划线 |

### 3.2首字母大写

首字母大写时直接转为小写，前面不插入下划线。

| 算子类型 | 转换结果 |
|---|---|
| `Add` | `add` |
| `Reduce` | `reduce` |

### 3.3数字与字母相邻

数字保持不变。数字前后的大写字母是否插入下划线，仍按前后字符关系判断。

| 算子类型 | 转换结果 | 说明 |
|---|---|---|
| `GatherV2` | `gather_v2` | `V`前一个字符为小写`r`，插入下划线 |
| `Conv2D` | `conv2_d` | `D`前一个字符为数字`2`，在`D`前插入下划线 |
| `TopK2Custom` | `top_k2_custom` | `K`前插入下划线，数字`2`保持不变，`Custom`前插入下划线 |

## 4. 工程中的命名关系

默认情况下，开发者需要保持算子类型、实现文件名和Kernel函数名之间的转换关系一致。

| 项目 | 命名方式 | 示例 |
|---|---|---|
| 算子类型 | 大驼峰 | `AddCustom` |
| `OP_ADD`参数 | 大驼峰 | `OP_ADD(AddCustom)` |
| Kernel实现文件名 | 下划线 | `add_custom.cpp` |
| Kernel函数名 | 下划线 | `add_custom` |

使用`msopgen`创建算子工程时，只需在原型定义json文件中将算子类型设置为大驼峰命名，工具会生成符合下划线命名规则的文件名和Kernel函数名。手工编写或调整工程结构时，需要自行保证命名关系一致。

如果需要为不同AI处理器型号使用不同的Kernel实现文件，可以在`CMakeLists.txt`中通过`npu_op_kernel_sources`指定Kernel入口文件。相关编译配置见[算子工程编译拓展](../算子工程编译拓展.md)。

更多原型定义相关内容见[算子原型定义](../设计与实现/算子原型定义.md)。
