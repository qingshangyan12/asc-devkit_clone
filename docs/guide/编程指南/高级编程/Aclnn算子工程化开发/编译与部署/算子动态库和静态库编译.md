# 算子动态库和静态库编译

> 类型：扩展

## 支持的型号

算子动态库和静态库编译目前支持以下 AI 处理器型号：

| 产品系列 | 典型 soc_version | 支持状态 |
|---------|-----------------|---------|
| Ascend 950PR / Ascend 950DT | Ascend950PR / Ascend950DT | ✅ 支持 |
| Atlas A3 训练系列产品 / Atlas A3 推理系列产品 | Ascend910B | ✅ 支持 |
| Atlas A2 训练系列产品 / Atlas A2 推理系列产品 | Ascend910A | ✅ 支持 |
| Atlas 推理系列产品 | Ascend310P | ✅ 支持 |

## 算子库编译

算子动态库和静态库编译是将算子实现代码及相关文件编译为动态库和静态库的过程。相比自定义算子包编译，动态库和静态库编译能够显著简化集成与部署流程。

编译过程包括：
- 将算子 Kernel 实现、Host 侧 Tiling 实现、[入图适配文件](../../算子入图开发/基本开发流程.md) 以及 [自动生成的单算子调用实现代码](../调用/单算子API调用.md) 编译链接成动态库和静态库
- 自动生成单算子调用 aclnn 头文件（用于单算子调用场景）
- 自动生成算子原型定义头文件（用于算子入图场景）

### 编译步骤

1. 修改工程目录下的 `CMakePresets.json`，将 `ASCEND_PACK_SHARED_LIBRARY` 设置为 `True`：

```json
"ASCEND_PACK_SHARED_LIBRARY": {
    "type": "BOOL",
    "value": "True"
}
```

2. 执行编译命令：

```bash
./build.sh
```

编译成功后，会在 `${CMAKE_INSTALL_PREFIX}/op_api` 目录生成以下文件：

| 文件 | 用途 |
|------|------|
| `aclnn_optype*.h` | 单算子调用头文件 |
| `op_proto.h` | 算子原型定义头文件 |
| `libcust_opapi.so` | 算子动态库 |
| `lib${vendor_name}.a` | 算子静态库 |
| `${vendor_name}-config.cmake` | CMake 配置文件 |
| `${vendor_name}-targets.cmake` | CMake 构建目标定义 |

**目录结构**：

```
├── op_api
│   ├── include
│       ├── aclnn_optype1.h                  // 单算子调用aclnn头文件
│       └── aclnn_optype2.h
│       └── aclnn_optypexxx.h
│       └── op_proto.h                       // 算子原型定义头文件
│   ├── lib
│       ├── cmake
│         └── ${vendor_name}
│            ├──${vendor_name}-config.cmake  // 安装文件，定义了项目中的配置选项和变量
│            └──${vendor_name}-targets.cmake // 安装文件，定义静态库和动态库的构建目标
│       ├── libcust_opapi.so                 // 算子动态库
│       └── lib${vendor_name}.a              // 算子静态库
```

## 关键变量说明

在使用算子库时，需要理解以下变量的含义和关系：

| 变量 | 含义 | 来源 |
|------|------|------|
| `${vendor_name}` | 厂商名称，算子 package 的标识符 | 编译时在 CMakePresets.json 中配置 |
| `${CMAKE_INSTALL_PREFIX}` | 编译产物存放路径 | 编译时在 CMakePresets.json 中配置 |
| `${CUST_PKG_PATH}` | 算子 package 的查找路径 | 运行时由用户指定，通常指向 `${CMAKE_INSTALL_PREFIX}/op_api` 目录 |

**关系说明**：

- `${CMAKE_INSTALL_PREFIX}` 决定了编译产物生成到哪个目录
- `${CUST_PKG_PATH}` 在运行时指向该目录（或该目录下的 `op_api` 子目录）
- `${vendor_name}` 用于在 CMake 中查找和使用对应的算子库

## 算子库集成和使用

### 单算子调用场景

#### 动态库集成

```cmake
find_package(${vendor_name} REQUIRED     # ${vendor_name}为编译生成的算子package名称
    PATHS ${CUST_PKG_PATH}               # ${CUST_PKG_PATH}为编译生成的算子package的存放路径
    NO_DEFAULT_PATH
)
target_link_libraries(op_runner PRIVATE
    ...
    ${vendor_name}::shared               # 已自动包含相关的target依赖
    ...
)
```

#### 静态库集成

```cmake
find_package(${vendor_name} REQUIRED     # ${vendor_name}为编译生成的算子package名称
    PATHS ${CUST_PKG_PATH}               # ${CUST_PKG_PATH}为编译生成的算子package的存放路径
    NO_DEFAULT_PATH
)

target_link_libraries(op_runner PRIVATE
    ...
    ${vendor_name}::static                # 已自动包含相关的target依赖
    ...
)
```

#### 静态库和动态库混合使用

```cmake
find_package(${vendor_name1} REQUIRED     # ${vendor_name1}为编译生成的算子package名称
    PATHS ${CUST_PKG_PATH_1}              # ${CUST_PKG_PATH_1}为编译生成的算子package的存放路径
    NO_DEFAULT_PATH
)
find_package(${vendor_name2} REQUIRED     # ${vendor_name2}为编译生成的算子package名称
    PATHS ${CUST_PKG_PATH_2}              # ${CUST_PKG_PATH_2}为编译生成的算子package的存放路径
    NO_DEFAULT_PATH
)

target_link_libraries(op_runner PRIVATE
    ...
    ${vendor_name1}::static                 # 已自动包含相关的静态库target依赖
    ${vendor_name2}::shared                 # 已自动包含相关的动态库target依赖
    ...
)
```

**完整示例**：

参考 [静态库集成和使用样例](https://gitcode.com/cann/asc-devkit/tree/master/examples/01_simd_cpp_api/02_features/00_compilation/custom_op_static_lib)。

### 多厂商算子库集成

如果需要将多个厂商的算子库集成到一个项目中，需要注意动态库名称冲突问题。由于所有算子工程生成的动态库名称都是固定的 `libcust_opapi.so`，建议通过不同的安装路径进行区分：

```cmake
# 分别指定不同厂商的算子库路径
find_package(${vendor_name1} REQUIRED
    PATHS ${CUST_PKG_PATH_1}              # 指向厂商1的算子库安装路径
    NO_DEFAULT_PATH
)
find_package(${vendor_name2} REQUIRED
    PATHS ${CUST_PKG_PATH_2}              # 指向厂商2的算子库安装路径
    NO_DEFAULT_PATH
)

target_link_libraries(op_runner PRIVATE
    ...
    ${vendor_name1}::shared
    ${vendor_name2}::shared
    ...
)
```

> [!IMPORTANT] 注意
> 动态库文件名 `libcust_opapi.so` 由编译系统固定生成，**不支持通过修改编译配置改变输出文件名**。
>
> 如果应用程序需要引用特定名称的动态库（如 `libvendor1.so`），可在安装路径下创建软链接：
> ```bash
> cd ${CUST_PKG_PATH_1}/lib
> ln -s libcust_opapi.so libvendor1.so
> ```

### 算子入图场景

#### 环境变量配置方式

配置 `ASCEND_CUSTOM_OPP_PATH` 环境变量：

```bash
export ASCEND_CUSTOM_OPP_PATH=${CMAKE_INSTALL_PREFIX}/op_api/lib/:${ASCEND_CUSTOM_OPP_PATH}
```

> [!NOTE] 说明
> - 动态库编译和算子包编译功能同时使用时，动态库编译生成的优先级更高
> - 示例：`ASCEND_CUSTOM_OPP_PATH=<path1>/vendor_name1:<path2>/op_api/lib/:<path3>/vendor_name3:<path4>/op_api/lib/`，优先级为 path2 > path4 > path1 > path3

#### 动态库链接方式

如果通过 Ascend Graph 进行图开发，也可以直接在应用程序的编译文件中链接动态库 `libcust_opapi.so`，该方式的 so 加载优先级高于环境变量配置方式。

Ascend Graph 图开发的相关信息请参考 [《图引擎开发指南》](https://www.hiascend.com/document/redirect/CannCommunityGraphguide)。
