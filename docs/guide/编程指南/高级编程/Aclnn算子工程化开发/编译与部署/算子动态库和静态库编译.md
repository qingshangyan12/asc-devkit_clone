# 算子动态库和静态库编译

> 类型：扩展

## 1 支持的型号

算子动态库和静态库编译目前支持以下 AI 处理器型号：

| 产品系列 | 典型 soc_version | 支持状态 |
|---------|-----------------|---------|
| Ascend 950PR / Ascend 950DT | Ascend950PR / Ascend950DT | ✅ 支持 |
| Atlas A3 训练系列产品 / Atlas A3 推理系列产品 | Ascend910B | ✅ 支持 |
| Atlas A2 训练系列产品 / Atlas A2 推理系列产品 | Ascend910A | ✅ 支持 |
| Atlas 推理系列产品 | Ascend310P | ✅ 支持 |

## 2 算子库编译

相比自定义算子包（.run），动态库和静态库能显著简化集成与部署流程。编译过程包括：
- 将算子 Kernel 实现、Host 侧 Tiling 实现、[入图适配文件](../../算子入图开发/基本开发流程.md) 以及 [自动生成的单算子调用实现代码](../调用/单算子API调用.md) 编译链接成动态库和静态库
- 自动生成单算子调用 aclnn 头文件（用于单算子调用场景）
- 自动生成算子原型定义头文件（用于算子入图场景）

### 2.1 编译步骤

本节基于[基本流程](./基本流程.md)中 `find_package(ASC)` 和 `npu_op_package` 的工程写法说明。动态库和静态库的产物形态需分别指定：动态库设 `TYPE SHARED`，静态库设 `TYPE STATIC`。

**动态库配置示例**：

```cmake
npu_op_package(${package_name}
    TYPE SHARED
    CONFIG
        ENABLE_SOURCE_PACKAGE True
        ENABLE_BINARY_PACKAGE True
        INSTALL_PATH ${CMAKE_BINARY_DIR}/
)
```

**静态库配置示例**：

```cmake
npu_op_package(${package_name}
    TYPE STATIC
    CONFIG
        ENABLE_SOURCE_PACKAGE True
        ENABLE_BINARY_PACKAGE True
        INSTALL_PATH ${CMAKE_BINARY_DIR}/
)
```

> [!NOTE] 说明
> 在当前 `npu_op_package` 流程中，产物形态由 `TYPE RUN`、`TYPE SHARED` 或 `TYPE STATIC` 决定。

执行编译和安装命令：

```bash
cmake -S . -B build_out --preset=default
cmake --build build_out --target binary install -j$(nproc)
```

使用工程自带 `build.sh` 时，需要确认脚本的最终构建目标是 `install`。如果脚本固定执行 `package` 目标，可按上面的 cmake 命令手工构建库形态产物。

编译成功后，会在 `${CMAKE_INSTALL_PREFIX}` 目录生成以下文件：

| 文件 | 用途 |
|------|------|
| `aclnn_optype*.h` | 单算子调用头文件 |
| `op_proto.h` | 算子原型定义头文件 |
| `libcust_opapi.so` | `TYPE SHARED` 模式生成的算子动态库 |
| `lib${vendor_name}.a` | `TYPE STATIC` 模式生成的算子静态库 |
| `${vendor_name}-config.cmake` | CMake 配置文件 |
| `${vendor_name}-targets.cmake` | CMake 构建目标定义 |

**目录结构**：

```
├── include
│   ├── aclnn_optype1.h                  // 单算子调用 aclnn 头文件
│   ├── aclnn_optype2.h
│   └── op_proto.h                       // 算子原型定义头文件
└── lib
    ├── cmake
    │   └── ${vendor_name}
    │       ├── ${vendor_name}-config.cmake
    │       └── ${vendor_name}-targets.cmake
    ├── libcust_opapi.so                 // TYPE SHARED 模式生成
    └── lib${vendor_name}.a              // TYPE STATIC 模式生成
```

## 3 关键变量说明

使用算子库前，先了解这几个关键变量：

| 变量 | 含义 | 来源 |
|------|------|------|
| `${vendor_name}` | 厂商名称，算子 package 的标识符 | 编译时在 CMakePresets.json 中配置 |
| `${CMAKE_INSTALL_PREFIX}` | 编译产物存放路径 | 编译时在 CMakePresets.json 中配置 |
| `${CUST_PKG_PATH}` | 算子 package 的查找路径 | 集成时由用户指定，指向 `${CMAKE_INSTALL_PREFIX}/lib/cmake/${vendor_name}` |

**关系说明**：

- `${CMAKE_INSTALL_PREFIX}` 决定了编译产物生成到哪个目录
- `${CUST_PKG_PATH}` 在集成时指向 `${vendor_name}-config.cmake` 所在目录
- `${vendor_name}` 用于在 CMake 中查找和使用对应的算子库

> [!NOTE] 说明
> 建议将 `${CUST_PKG_PATH}` 指向 `${CMAKE_INSTALL_PREFIX}/lib/cmake/${vendor_name}`。不要直接指向 `${CMAKE_INSTALL_PREFIX}` 根目录，避免误匹配到构建过程中生成的中间 config 文件。

## 4 算子库集成和使用

### 4.1 单算子调用场景

#### 4.1.1 动态库集成

```cmake
find_package(${vendor_name} REQUIRED     # ${vendor_name}为编译生成的算子package名称
    PATHS ${CUST_PKG_PATH}               # ${CUST_PKG_PATH}为编译生成的算子package的存放路径
    NO_DEFAULT_PATH
)
target_link_libraries(op_runner PRIVATE
    ...
    ${vendor_name}::${vendor_name}       # TYPE SHARED 模式下导入动态库
    ...
)
```

#### 4.1.2 静态库集成

```cmake
find_package(${vendor_name} REQUIRED     # ${vendor_name}为编译生成的算子package名称
    PATHS ${CUST_PKG_PATH}               # ${CUST_PKG_PATH}为编译生成的算子package的存放路径
    NO_DEFAULT_PATH
)

target_link_libraries(op_runner PRIVATE
    ...
    ${vendor_name}::${vendor_name}        # TYPE STATIC 模式下导入静态库
    ...
)
```

#### 4.1.3 静态库和动态库混合使用

```cmake
find_package(${vendor_name1} REQUIRED     # ${vendor_name1}为编译生成的算子package名称
    PATHS ${CUST_PKG_PATH_1}              # ${CUST_PKG_PATH_1}为编译生成的算子package的存放路径
    NO_DEFAULT_PATH
)
find_package(${vendor_name2} REQUIRED     # ${vendor_name2}为编译生成的算子package名称
    PATHS ${CUST_PKG_PATH_2}              # ${CUST_PKG_PATH_2}为编译生成的算子package的存放路径
    NO_DEFAULT_PATH
)

target_link_libraries(op_runner PRIVATE
    ...
    ${vendor_name1}::${vendor_name1}        # 例如 TYPE STATIC 模式生成的库
    ${vendor_name2}::${vendor_name2}        # 例如 TYPE SHARED 模式生成的库
    ...
)
```

**完整示例**：

参考 [静态库集成和使用样例](https://gitcode.com/cann/asc-devkit/tree/master/examples/01_simd_cpp_api/02_features/99_acl_based/00_acl_compilation/custom_op_static_lib)。

### 4.2 多厂商算子库集成

多个厂商的算子库集成到一个项目时，要注意动态库名称冲突：所有算子工程生成的动态库名称都是 `libcust_opapi.so`，建议通过不同的安装路径区分：

```cmake
# 分别指定不同厂商的算子库路径
find_package(${vendor_name1} REQUIRED
    PATHS ${CUST_PKG_PATH_1}              # 指向厂商1的算子库安装路径
    NO_DEFAULT_PATH
)
find_package(${vendor_name2} REQUIRED
    PATHS ${CUST_PKG_PATH_2}              # 指向厂商2的算子库安装路径
    NO_DEFAULT_PATH
)

target_link_libraries(op_runner PRIVATE
    ...
    ${vendor_name1}::${vendor_name1}
    ${vendor_name2}::${vendor_name2}
    ...
)
```

> [!NOTE] 说明
> - `find_package(${vendor_name} ...)` 导入的目标名为 `${vendor_name}::${vendor_name}`。该目标在 `TYPE SHARED` 模式下指向 `libcust_opapi.so`，在 `TYPE STATIC` 模式下指向 `lib${vendor_name}.a`。
> - 不同算子工程默认生成的动态库名称均为 `libcust_opapi.so`。如果需要将多个动态库集成到同一个公共动态库或同一应用中，可在编译前修改 `op_host/CMakeLists.txt`，为 `cust_opapi` 设置不同输出名：
>
> ```cmake
> set_target_properties(cust_opapi PROPERTIES
>     OUTPUT_NAME ${vendor_name}
> )
> ```
>
> 如果修改输出名，应重新生成并安装 CMake 配置文件，保证 `${CMAKE_INSTALL_PREFIX}/lib/cmake/${vendor_name}/${vendor_name}-targets.cmake` 中记录的动态库名称与实际文件一致。

### 4.3 算子入图场景

#### 4.3.1 环境变量配置方式

配置 `ASCEND_CUSTOM_OPP_PATH` 环境变量：

```bash
export ASCEND_CUSTOM_OPP_PATH=${CMAKE_INSTALL_PREFIX}/lib/:${ASCEND_CUSTOM_OPP_PATH}
```

> [!NOTE] 说明
> - 动态库编译和算子包编译功能同时使用时，动态库编译生成的优先级更高
> - 对于 `TYPE SHARED` 模式生成的库，路径通常为 `${CMAKE_INSTALL_PREFIX}/lib/`
> - 示例：`ASCEND_CUSTOM_OPP_PATH=<path1>/vendor_name1:<path2>/lib/:<path3>/vendor_name3:<path4>/lib/`，优先级为 path2 > path4 > path1 > path3

#### 4.3.2 动态库链接方式

通过 Ascend Graph 进行图开发时，也可以直接在应用程序中链接 `libcust_opapi.so`，该方式的 so 加载优先级高于环境变量配置。

Ascend Graph 图开发的相关信息请参考 [《图引擎开发指南》](https://www.hiascend.com/document/redirect/CannCommunityGraphguide)。
