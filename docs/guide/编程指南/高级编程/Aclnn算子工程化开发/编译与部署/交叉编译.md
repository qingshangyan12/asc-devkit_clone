# 交叉编译

> 类型：扩展

**适用读者**：需要在不同架构平台间编译算子的开发者

## 1 概述

完成算子代码实现后，如果当前编译平台架构和目标运行平台架构一致，可直接参考[基本流程](基本流程.md)进行编译。如果需要实现算子包的交叉编译（即编译平台架构与运行平台架构不同），可参考本文档的流程。

交叉编译的典型场景：
- 在 x86_64 开发机上编译，部署到 aarch64 边缘设备
- 在 aarch64 服务器上编译，部署到 x86_64 服务器

## 2 交叉编译工具下载

以 Ubuntu 系列操作系统为例，交叉编译工具下载命令如下表所示。其他操作系统请替换为实际的下载命令。

| 当前平台架构 | 运行环境平台架构 | 编译工具下载命令 |
|---|---|---|
| x86_64 | aarch64 | `sudo apt-get install -y g++-aarch64-linux-gnu` |
| aarch64 | x86_64 | `sudo apt-get install -y g++-x86-64-linux-gnu` |

安装完成后，可通过以下命令验证工具是否可用：

```bash
# x86_64 → aarch64
aarch64-linux-gnu-g++ --version

# aarch64 → x86_64
x86_64-linux-gnu-g++ --version
```

## 3 CMakePresets.json 配置

交叉编译需修改算子工程目录下 CMakePresets.json 的两个配置项：

### 3.1 使能交叉编译

将 `ENABLE_CROSS_COMPILE` 设置为 `True`：

```json
"ENABLE_CROSS_COMPILE": {
    "type": "BOOL",
    "value": "True"
}
```

### 3.2 指定交叉编译工具路径

将 `CMAKE_CROSS_PLATFORM_COMPILER` 设置为交叉编译工具的安装路径：

```json
"CMAKE_CROSS_PLATFORM_COMPILER": {
    "type": "PATH",
    "value": "/usr/bin/aarch64-linux-gnu-g++"
}
```

**路径说明**：
- x86_64 → aarch64 场景：路径为 `/usr/bin/aarch64-linux-gnu-g++`
- aarch64 → x86_64 场景：路径为 `/usr/bin/x86_64-linux-gnu-g++`

如果交叉编译工具安装在非标准路径，请使用 `which` 命令查找实际路径：

```bash
which aarch64-linux-gnu-g++
```

### 3.3 完整配置示例

```json
{
    "version": 1,
    "cmakeMinimumRequired": {
        "major": 3,
        "minor": 16,
        "patch": 0
    },
    "configurePresets": [
        {
            "name": "default",
            "displayName": "Cross Compile Config",
            "generator": "Unix Makefiles",
            "binaryDir": "${sourceDir}/build_out",
            "cacheVariables": {
                "ASCEND_COMPUTE_UNIT": {
                    "type": "STRING",
                    "value": "ascendxxx"
                },
                "vendor_name": {
                    "type": "STRING",
                    "value": "customize"
                },
                "ENABLE_CROSS_COMPILE": {
                    "type": "BOOL",
                    "value": "True"
                },
                "CMAKE_CROSS_PLATFORM_COMPILER": {
                    "type": "PATH",
                    "value": "/usr/bin/aarch64-linux-gnu-g++"
                }
            }
        }
    ]
}
```

## 4 执行交叉编译

交叉编译 kernel 二进制时，编译框架需要先加载本机架构可执行的 Tiling 动态库来获取编译参数。因此 `ENABLE_CROSS_COMPILE=True` 且 `ENABLE_BINARY_PACKAGE=True` 时，不能只执行一次普通 configure/build；需要先在本机模式下生成 `libcust_opmaster_rt2.0.so`，再通过 `HOST_NATIVE_TILING_LIB` 传给交叉编译阶段。

### 4.1 方式一：使用 build.sh 脚本

如果工程自带的 `build.sh` 已经包含交叉编译处理逻辑，可直接执行：

```bash
./build.sh
```

脚本需要至少完成以下动作：

1. 使用 `-DENABLE_CROSS_COMPILE=False` 先构建本机 Tiling 库。
2. 找到本机 Tiling 库 `libcust_opmaster_rt2.0.so`。
3. 重新 configure 交叉编译工程，并传入 `-DHOST_NATIVE_TILING_LIB=<本机Tiling库绝对路径>`。
4. 构建 `binary` 和 `package` 目标。

如果脚本只是简单执行 `cmake --preset=default` 和 `cmake --build`，需要按方式二手工执行，或更新脚本。

### 4.2 方式二：使用 cmake 命令

**步骤 1：本机模式生成 Tiling 库**

```bash
cmake -S . -B build_native_tiling --preset=default -DENABLE_CROSS_COMPILE=False
cmake --build build_native_tiling --target customize_ascendc_cust_optiling -j$(nproc)
HOST_NATIVE_TILING_LIB=$(realpath build_native_tiling/op_host/libcust_opmaster_rt2.0.so)
```

其中 `customize` 来自 `vendor_name` 配置。如果 `vendor_name` 不是默认值，目标名对应为 `<vendor_name>_ascendc_cust_optiling`。

**步骤 2：执行交叉编译**

确保 `CMakePresets.json` 中已将 `ENABLE_CROSS_COMPILE` 设置为 `True`，且 `CMAKE_CROSS_PLATFORM_COMPILER` 指向目标平台对应的交叉编译器，然后执行：

```bash
cmake -S . -B build_out --preset=default -DHOST_NATIVE_TILING_LIB=${HOST_NATIVE_TILING_LIB}
cmake --build build_out --target binary package -j$(nproc)
```

编译成功后，会在 `build_out` 目录下生成自定义算子安装包，例如：
- x86_64 编译 aarch64 目标：`custom_opp_ubuntu_aarch64.run`
- aarch64 编译 x86_64 目标：`custom_opp_ubuntu_x86_64.run`

## 5 部署交叉编译的算子包

将生成的算子包传输到目标平台并部署：

```bash
# 1. 传输到目标平台
scp build_out/custom_opp_ubuntu_aarch64.run user@target-host:/path/to/deploy/

# 2. 在目标平台执行安装
ssh user@target-host
cd /path/to/deploy/
./custom_opp_ubuntu_aarch64.run --install-path=/opt/custom_ops
```

安装后的使用方式与普通编译一致，参考[基本流程](基本流程.md#算子包部署)。

## 6 常见检查项

### 6.1 配置阶段报错 "Native host libs was not set for cross compile!"

**原因**：交叉编译开启了二进制编译，但没有通过 `HOST_NATIVE_TILING_LIB` 指定本机架构的 Tiling 动态库。

**解决**：按本文第 4.2 节先构建本机 Tiling 库，再重新 configure 交叉编译工程。

### 6.2 编译成功但目标平台运行时报错 "Exec format error"

**原因**：算子包架构与目标平台不匹配。

**解决**：
1. 确认编译时指定的目标架构正确
2. 确认目标平台的 CPU 架构：`uname -m`
3. 重新编译并部署
