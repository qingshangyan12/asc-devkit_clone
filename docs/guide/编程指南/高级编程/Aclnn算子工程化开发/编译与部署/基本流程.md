# 编译与部署基本流程

> 类型：基础

算子代码开发完成后，Host 侧包含算子原型定义、Shape 推导和 Tiling 实现，Kernel 侧包含 AscendC 计算逻辑。接下来要把这两侧代码编译成算子安装包并部署到运行环境。

编译过程主要做两件事：

- **编译 Kernel 侧代码**：分为源码发布（保留 .cpp 源码）和二进制发布（编译为 .o 二进制文件）两种方式
- **编译 Host 侧代码**：编译算子原型定义动态库、Tiling 动态库，并自动生成单算子 API 调用代码和动态库


![](../../../../figures/算子工程编译示意图.png "算子工程编译示意图")

### 基本流程

使用 msOpGen 生成的工程，已经包含完整CMake 结构，不需要单独编写CMakeLists.txt处理，如果需要自行编写CMakeLists.txt请参考[编译组织](#编译组织)。msOpGen 生成的算子工程编译部署只需三步：

1. 修改 `CMakePresets.json`，填写 `ASCEND_COMPUTE_UNIT`（AI 处理器型号）和 `vendor_name`（厂商名称）等编译配置选项；
2. 执行 `./build.sh`，生成 `custom_opp_*.run` 安装包；
3. 执行 `./custom_opp_*.run`，安装到运行环境。

以下各节详细介绍每一步的选项和细节。

## 1 编译配置

编译配置选项的必改参数有两个：

| 参数名称 | 参数描述 | 默认值 |
|---------|---------|--------|
| ASCEND_COMPUTE_UNIT | AI 处理器型号，参考 [soc_version 获取方法](../附录/soc_version获取方法.md) | "ascendxxx" |
| vendor_name | 自定义算子所属厂商名称，避免与其他厂商算子包冲突 | "customize" |

其他可选编译配置选项详情如下：

| 类型 | 选项名 | 默认值 | 说明 |
|------|--------|--------|------|
| STRING | CMAKE_BUILD_TYPE | Release | 编译类型，支持 Release 和 Debug |
| STRING | vendor_name | customize | 算子所属厂商标识 |
| STRING | ASCEND_COMPUTE_UNIT | - | AI 处理器型号，参考 [soc_version 获取方法](../附录/soc_version获取方法.md) |
| PATH | ASCEND_AUTOGEN_PATH | <CMAKE_BINARY_DIR>/autogen | 自动生成代码的存放路径 |
| PATH | ASCEND_CANN_PACKAGE_PATH | - | CANN 软件包路径 |
| BOOL | ENABLE_SOURCE_PACKAGE | TRUE | 是否开启源码编译 |
| BOOL | ENABLE_BINARY_PACKAGE | TRUE | 是否开启二进制编译 |
| BOOL | ENABLE_CROSS_COMPILE | FALSE | 是否启用交叉编译，参考[交叉编译](./交叉编译.md) |
| PATH | CMAKE_CROSS_PLATFORM_COMPILER | /your/cross/compiler/path | 交叉编译工具路径 |
| BOOL | ASCEND_SKIP_FAILED_COMPUTE_UNIT | FALSE | 部分型号编译失败时是否跳过 |

修改编译配置选项的方式有两种：

### 方式一：修改 CMakePresets.json

工程目录下有 `CMakePresets.json` 时，修改其中的 `cacheVariables` 即可。msOpGen 生成的工程默认使用此方式。

> [!NOTE] CMake 版本要求
> 直接执行 `cmake --preset=default` 要求 CMake >= 3.19。msOpGen 生成的 `build.sh` 会在低版本 CMake 环境下解析 `CMakePresets.json` 并转成普通 `cmake -D` 参数，因此优先建议使用工程自带的 `build.sh`。

**最小配置示例**：

```json
{
    "version": 1,
    "cmakeMinimumRequired": {
        "major": 3,
        "minor": 16,
        "patch": 0
    },
    "configurePresets": [
        {
            "name": "default",
            "cacheVariables": {
                "ASCEND_COMPUTE_UNIT": {
                    "type": "STRING",
                    "value": "ascend910b"
                },
                "vendor_name": {
                    "type": "STRING",
                    "value": "customize"
                }
            }
        }
    ]
}
```

### 方式二：在 CMakeLists.txt 中设置

直接在顶层 CMakeLists.txt 中设置变量，并通过 `npu_op_*` 接口配置编译行为，无需 CMakePresets.json 文件。

```cmake
# 设置必要变量
set(ASCEND_COMPUTE_UNIT "ascend910b")
set(vendor_name "customize")

# 配置编译产物包（通过 CONFIG 参数替代 ENABLE_SOURCE_PACKAGE / ENABLE_BINARY_PACKAGE 等变量）
npu_op_package(${vendor_name}
    TYPE RUN
    CONFIG
        ENABLE_SOURCE_PACKAGE True
        ENABLE_BINARY_PACKAGE True
        INSTALL_PATH ${CMAKE_BINARY_DIR}/
)
```

其他配置（如动态库编译、交叉编译等）也可在 CMakeLists.txt 中通过变量或 `npu_op_package` CONFIG 参数设置。完整参数说明请参考 [cmake 函数参考](../附录/cmake函数参考.md)。

需要注意如果 `npu_op_package(... CONFIG ...)` 中硬编码了 `ENABLE_SOURCE_PACKAGE` 或 `ENABLE_BINARY_PACKAGE` 的值（如本节样例直接写 True），命令行或 `CMakePresets.json` 中的同名变量将无法覆盖。要允许外部变量生效，CONFIG 中应使用 `${ENABLE_SOURCE_PACKAGE}`、`${ENABLE_BINARY_PACKAGE}` 变量形式

## 2 执行编译

有两种编译方法：

**方法一：使用 build.sh 脚本**

如果工程目录下有 `build.sh` 脚本（msOpGen 生成的工程默认提供），直接执行：

```bash
./build.sh
```

**方法二：执行 cmake 命令**

```bash
cmake -S . -B build_out --preset=default
cmake --build build_out --target binary package -j$(nproc)
```

- `cmake -S . -B build_out --preset=default` 是 CMake 的配置和生成阶段：从当前目录读取源码、`CMakeLists.txt` 和 `CMakePresets.json` 中的 `default` 配置，在 `build_out` 目录下生成后续编译需要的构建文件。

- `cmake --build build_out --target binary package -j$(nproc)` 是实际编译和打包阶段：使用 `build_out` 中已经生成的构建文件，执行 `binary` 和 `package` 目标；`binary` 负责编译算子二进制相关产物，`package` 负责生成算子安装包，`-j$(nproc)` 表示按当前机器 CPU 核数并行编译。

编译成功后，会在编译产物目录下生成自定义算子安装包 `custom_opp_<target os>_<target architecture>.run`。该 run 包包含算子原型库、Tiling 库、aclnn API 库和 Kernel 二进制，部署后框架会自动扫描并加载。

**编译日志存储**（可选）：

```bash
# 设置编译日志存储路径
export ASCENDC_BUILD_LOG_DIR=/home/build_log/
```

<a id="算子包部署"></a>
## 3 算子包部署

编译生成的算子安装包需要部署到运行环境。

### 3.1 安装算子包

在自定义算子包所在路径下，执行安装命令：

```bash
./custom_opp_<target os>_<target architecture>.run --install-path=<path>
```

`--install-path` 是可选参数，指定安装目录。支持绝对路径，要求对目标路径有读写权限。

#### 3.1.1 默认安装（不指定 --install-path）

安装到 `$ASCEND_OPP_PATH/vendors/<vendor_name>` 目录（`$ASCEND_OPP_PATH` 通常等于 `${CANN安装路径}/opp`，以 root 用户为例：`/usr/local/Ascend/cann/opp`）。

> **路径关系说明**：默认安装场景下，算子包直接部署到 `$ASCEND_OPP_PATH/vendors/<vendor_name>`，框架会自动扫描并加载该路径下的算子。

**表 3** 默认安装与指定目录安装对比

| 安装方式 | 安装命令 | 安装路径 | 是否需要额外配置 | 优先级 |
|---------|---------|---------|----------------|--------|
| 默认安装 | `./custom_opp_*.run` | `${ASCEND_OPP_PATH}/vendors/<vendor_name>` | 否，自动生效 | 较低 |
| 指定目录安装 | `./custom_opp_*.run --install-path=<path>` | `<path>/vendors/<vendor_name>` | 是，需要 source 环境变量 | 较高 |

> [!NOTE] 说明
> - 默认安装路径权限与 CANN 软件包安装用户和配置有关，如果因权限不足导致安装失败，可使用指定目录安装或联系 CANN 安装用户修改权限
> - 指定目录安装后，在使用算子前需要执行 `source <path>/vendors/<vendor_name>/bin/set_env.bash`，将安装路径追加到 `ASCEND_CUSTOM_OPP_PATH` 环境变量
> - 算子包要求架构与系统架构一致，且满足 glibc 版本依赖，否则可使用 `--force` 强制安装

<a id="配置自定义算子优先级"></a>
### 3.3 配置自定义算子优先级

多个算子包共存时，如果包含相同 OpType 的算子，优先级高的算子包中的版本生效。

#### 3.3.1 默认安装场景

配置 `opp/vendors/config.ini` 文件：

```ini
load_priority=vendor_name1,vendor_name2,vendor_name3
```

- `load_priority`：优先级配置关键字，不可修改
- `vendor_name1,vendor_name2,vendor_name3`：按优先级从高到低排列的厂商序列

#### 3.3.2 指定目录安装场景

分别执行各算子包安装路径下的 `set_env.bash` 脚本，脚本执行顺序越靠后，优先级越高。

```bash
source <path>/vendors/vendor_name1/bin/set_env.bash  # 先执行，优先级较低
source <path>/vendors/vendor_name2/bin/set_env.bash  # 后执行，优先级较高
```

执行后 `ASCEND_CUSTOM_OPP_PATH` 示例：

```
ASCEND_CUSTOM_OPP_PATH=<path>/vendors/vendor_name2:<path>/vendors/vendor_name1:
```

### 3.4 卸载与更新算子包

#### 3.4.1 卸载算子包

算子包安装目录中包含 `uninstall.sh` 脚本，执行该脚本即可完成卸载：

**默认安装场景**：

```bash
bash ${INSTALL_DIR}/opp/vendors/<vendor_name>/scripts/uninstall.sh
```

**指定目录安装场景**：

```bash
bash <path>/vendors/<vendor_name>/scripts/uninstall.sh
```

#### 3.4.2 更新算子包

**默认安装场景**：重新执行安装命令即可覆盖旧版本

```bash
./custom_opp_<target os>_<target architecture>.run
```

**指定目录安装场景**：先卸载旧版本，再安装新版本

```bash
# 1. 卸载旧版本
bash <path>/vendors/<vendor_name>/scripts/uninstall.sh

# 2. 安装新版本
./custom_opp_<target os>_<target architecture>.run --install-path=<path>
```

> [!NOTE] 说明
> - 更新算子包后，需要重新 source 环境变量（指定目录安装场景）
> - 如果需要回退到旧版本，建议先备份旧版本算子包

<a id="编译组织"></a>
## 4 编译组织（进阶）

算子工程通过 CMake 组织编译。如需自行组织工程或用 CANN 提供的 CMake modules 定制编译流程，可参考以下内容。

算子工程支持两种目录组织方式：

| 方式 | 特点 | 适用场景 |
|------|------|----------|
| 按 Host/Kernel 划分 | Host 和 Kernel 代码分目录，三层 CMakeLists | msopgen 默认生成，单算子或少量算子 |
| 按算子划分 | 每个算子一个独立目录，两层 CMakeLists | 多算子工程，算子间独立性高 |

msopgen 工具默认生成"按 Host/Kernel 划分"的结构。

### 4.1 按 Host/Kernel 划分的目录结构

所有算子的 Host 侧代码集中在 `op_host/` 目录下，Kernel 侧代码集中在 `op_kernel/` 目录下。工程包含三层 CMakeLists.txt：顶层定义算子包并添加子目录，`op_host/` 下编译 Host 侧库，`op_kernel/` 下编译 Kernel 侧库。

**1. 顶层 CMakeLists.txt**

顶层 CMakeLists.txt 设置编译环境、定义 package 形态，并添加子目录:

1.  使用**find\_package**找到对应的编译库。
2.  使用**npu\_op\_package**设置算子工程的编译产物形态，支持RUN/SHARED/STATIC,分别对应算子run包形式、算子动态库形式与算子静态库形式，同时，该接口还可配置package（即编译产物）的内容和package的安装位置。
3.  添加需要进行编译的子目录。

```cmake
cmake_minimum_required(VERSION 3.16.0)
project(opp)

# 1. 使用 find_package 查找 CANN 软件包提供的 ASC CMake modules
find_package(ASC REQUIRED HINTS ${ASCEND_CANN_PACKAGE_PATH}/compiler/tikcpp/ascendc_kernel_cmake)

# 2. 设置算子工程的编译产物形态
# vendor_name 在 CMakePresets.json 中配置，用于区分不同厂商的算子包
set(package_name ${vendor_name})
npu_op_package(${package_name}
    TYPE RUN                                       # 编译产物形态：RUN/STATIC/SHARED
    CONFIG
        ENABLE_SOURCE_PACKAGE True
        ENABLE_BINARY_PACKAGE True
        INSTALL_PATH ${CMAKE_BINARY_DIR}/
)

# 3. 添加 Host 和 Kernel 子目录进行编译
if(EXISTS ${CMAKE_CURRENT_SOURCE_DIR}/op_host)
    add_subdirectory(op_host)
endif()
if(EXISTS ${CMAKE_CURRENT_SOURCE_DIR}/op_kernel)
    add_subdirectory(op_kernel)
endif()
```

**TYPE 参数说明**：
- `RUN`：生成 run 包，用于算子部署
- `SHARED`：生成动态库，用于集成到应用
- `STATIC`：生成静态库，用于静态链接

**2. Host 侧 CMakeLists.txt**

`op_host/` 下的 CMakeLists.txt 生成 aclnn 调用代码，编译 Host 侧各类库:

1.  使用**npu\_op\_code\_gen**生成aclnn单算子调用代码、入图所需的原型定义代码等。
2.  单算子调用场景，使用**npu\_op\_library**编译aclnn单算子调用库。
3.  算子入图场景，使用**npu\_op\_library**编译算子入图所需的算子原型库。
4.  使用**npu\_op\_library**编译Tiling相关库。
5.  使用**npu\_op\_package\_add**添加上述Host侧库至对应package中。

```cmake
aux_source_directory(${CMAKE_CURRENT_SOURCE_DIR} ops_srcs)

# 1. 生成 aclnn 调用代码和原型定义代码
npu_op_code_gen(
    SRC ${ops_srcs}
    PACKAGE ${package_name}
    COMPILE_OPTIONS -g
    OUT_DIR ${ASCEND_AUTOGEN_PATH}
    JOIN_OP_DEF False
)

# 2. 编译 aclnn 单算子调用库
file(GLOB autogen_aclnn_src ${ASCEND_AUTOGEN_PATH}/aclnn_*.cpp)
set_source_files_properties(${autogen_aclnn_src} PROPERTIES GENERATED TRUE)
npu_op_library(cust_opapi ACLNN
    ${autogen_aclnn_src}
)
target_compile_options(cust_opapi PRIVATE -fvisibility=hidden)

# 3. 编译算子原型库（用于入图）
file(GLOB proto_src ${ASCEND_AUTOGEN_PATH}/op_proto.cc)
set_source_files_properties(${proto_src} PROPERTIES GENERATED TRUE)
npu_op_library(cust_op_proto GRAPH
    ${ops_srcs}
    ${proto_src}
)
target_compile_options(cust_op_proto PRIVATE -fvisibility=hidden)

# 4. 编译 Tiling 库
file(GLOB fallback_src ${ASCEND_AUTOGEN_PATH}/fallback_*.cpp)
set_source_files_properties(${fallback_src} PROPERTIES GENERATED TRUE)
npu_op_library(cust_optiling TILING
    ${ops_srcs}
    ${fallback_src}
)
target_compile_options(cust_optiling PRIVATE -fvisibility=hidden)

# 5. 添加 Host 侧库到 package
npu_op_package_add(${package_name}
    LIBRARY
        cust_optiling
        cust_opapi
        cust_op_proto
)
```

**3. Kernel 侧 CMakeLists.txt**

`op_kernel/` 下的 CMakeLists.txt 配置 Kernel 编译选项、指定源码，并编译 Kernel 库:

1.  使用**npu\_op\_kernel\_options**添加算子编译选项。支持的编译选项可参考[编译选项](算子包编译/算子工程编译.md#table151052168302)。
2.  使用**npu\_op\_kernel\_sources**指定算子特定目录与编译源文件。
    -   若算子的源码文件没有平铺在SRC\_BASE目录（通过npu\_op\_kernel\_library设置）下，可以通过KERNEL\_DIR指定特定目录。
    -   若算子的Kernel实现cpp文件需要自定义命名，需同时指定OP\_TYPE（算子类型）和KERNEL\_FILE（Kernel实现cpp文件名），以配置两者之间的对应关系。不配置时，Kernel实现cpp文件名和OpType之间需满足[转换规则](./算子原型定义.md)。

3.  使用**npu\_op\_kernel\_library**编译Kernel库。
4.  使用**npu\_op\_package\_add**添加上述Kernel侧库到对应package中。

```cmake
# 1. 设置 Kernel 编译选项
npu_op_kernel_options(ascendc_kernels ALL OPTIONS --save-temp-files -g)

# 2. 指定 Kernel 源码
npu_op_kernel_sources(ascendc_kernels
    OP_TYPE AddCustom                              # 算子类型
    COMPUTE_UNIT ascend910b1                       # AI 处理器型号
    KERNEL_FILE add_custom.cpp                     # kernel实现文件名
)

# 3. 编译 Kernel 库
npu_op_kernel_library(ascendc_kernels
    SRC_BASE ${CMAKE_SOURCE_DIR}/op_kernel/        # Kernel 源码根目录
    TILING_LIBRARY cust_optiling                   # 依赖的 Tiling 库
)

# 4. 添加 Kernel 库到 package
npu_op_package_add(${package_name}
    LIBRARY ascendc_kernels
)
```

示例中 Kernel 实现文件名为 `add_custom.cpp`，所以在 `npu_op_kernel_sources` 中同时指定了 `OP_TYPE` 和 `KERNEL_FILE`。如果想按目录扫描 Kernel 源码，可改用 `KERNEL_DIR ./`，此时 `KERNEL_DIR` 相对于后续 `npu_op_kernel_library` 中的 `SRC_BASE`。

### 4.2 按算子划分的目录结构

工程包含多个算子且各算子独立性较高时，按算子划分更方便维护——每个算子的 host、kernel、tiling 文件放在同一目录，新增算子只需添加一个独立子目录。

每个算子一个独立目录，目录内包含该算子的所有文件（host、kernel、tiling）。子目录声明本算子的 Host 和 Kernel 源文件；顶层 CMakeLists.txt 定义注册函数、添加子目录、统一生成 aclnn 调用代码和原型定义代码，并创建 Host/Kernel 侧库。

工程包含两层 CMakeLists.txt，一个是算子目录 CMakeLists.txt，另一个是顶层 CMakeLists.txt。


**1. 算子目录 CMakeLists.txt**

算子目录的 CMakeLists.txt 声明当前算子的 Host 和 Kernel 源文件。以 AddCustom 为例，目录结构如下：

```text
add_custom/
├── CMakeLists.txt
├── add_custom.cpp           # Host 侧原型定义、Shape 推导、Tiling 实现
├── add_custom_kernel.cpp    # Kernel 实现
└── add_custom_tiling.h      # Tiling 数据结构定义
```

对应的 `add_custom/CMakeLists.txt`：

```cmake
# 只登记当前算子的文件，由顶层统一处理
register_aclnn_op(
    OP_TYPE AddCustom               # 与 add_custom.cpp 中 OP_ADD(AddCustom) 的 OpType 保持一致
    HOST_SRC add_custom.cpp          # 当前算子目录下的 Host 侧实现文件
    KERNEL_FILE add_custom_kernel.cpp # 当前算子目录下的 Kernel 实现文件
)
```

**2. 顶层 CMakeLists.txt**

顶层 CMakeLists.txt 设置编译环境、定义 package 形态，提供算子注册函数，添加算子子目录，统一生成 Host 侧代码并完成打包。

```cmake
cmake_minimum_required(VERSION 3.16.0)
project(opp)

# 查找 CANN 提供的 ASC CMake modules。ASCEND_CANN_PACKAGE_PATH 通常在 CMakePresets.json 中配置。
find_package(ASC REQUIRED HINTS ${ASCEND_CANN_PACKAGE_PATH}/compiler/tikcpp/ascendc_kernel_cmake)

# Kernel 源码根目录。后续会把每个算子目录转换成相对于该目录的 KERNEL_DIR。
set(ACLNN_OP_SRC_BASE ${CMAKE_CURRENT_SOURCE_DIR})

# 子目录通过该函数登记本算子的 Host 源文件和 Kernel 源文件。
# 该函数只做信息收集，不直接触发代码生成或编译。
function(register_aclnn_op)
    # 支持的参数：
    #   OP_TYPE：算子类型，需要与 Host 侧 OP_ADD 注册的 OpType 一致。
    #   HOST_SRC：当前算子的 Host 侧实现文件，相对于当前算子目录。
    #   KERNEL_FILE：当前算子的 Kernel 实现文件，相对于当前算子目录。
    cmake_parse_arguments(OP "" "OP_TYPE;HOST_SRC;KERNEL_FILE" "" ${ARGN})
    if(NOT OP_OP_TYPE OR NOT OP_HOST_SRC OR NOT OP_KERNEL_FILE)
        message(FATAL_ERROR "register_aclnn_op requires OP_TYPE, HOST_SRC and KERNEL_FILE")
    endif()

    # CMAKE_CURRENT_LIST_DIR 在函数调用处展开为当前算子目录。
    # npu_op_kernel_library 的 SRC_BASE 指向工程根目录，因此这里把算子目录换算成相对路径。
    file(RELATIVE_PATH kernel_dir ${ACLNN_OP_SRC_BASE} ${CMAKE_CURRENT_LIST_DIR})

    # 使用 GLOBAL property 保存所有算子的登记信息。
    # 这几组列表按 append 顺序一一对应，后续通过相同下标取回 OP_TYPE、KERNEL_DIR 和 KERNEL_FILE。
    set_property(GLOBAL APPEND PROPERTY ACLNN_OP_HOST_SRCS ${CMAKE_CURRENT_LIST_DIR}/${OP_HOST_SRC})
    set_property(GLOBAL APPEND PROPERTY ACLNN_OP_TYPES ${OP_OP_TYPE})
    set_property(GLOBAL APPEND PROPERTY ACLNN_OP_KERNEL_DIRS ${kernel_dir})
    set_property(GLOBAL APPEND PROPERTY ACLNN_OP_KERNEL_FILES ${OP_KERNEL_FILE})
endfunction()

# vendor_name 在 CMakePresets.json 中配置，用作算子包的厂商标识。npu_op_package 定义一个算子包目标
set(package_name ${vendor_name})
npu_op_package(${package_name}
    TYPE RUN
    CONFIG
        INSTALL_PATH ${CMAKE_BINARY_DIR}/
)

# 1. 添加各算子子目录。
# add_subdirectory(add_custom2) 只执行 add_custom2/CMakeLists.txt，不会自动执行其他算子目录。
# 每个子目录只调用 register_aclnn_op 登记自身文件。
add_subdirectory(add_custom)
add_subdirectory(add_custom2)
add_subdirectory(add_custom3)
# add_subdirectory(new_op)

# 2. 读取所有子目录登记的 Host 源文件和 Kernel 源文件信息。
get_property(ALL_HOST_OPS_SRCS GLOBAL PROPERTY ACLNN_OP_HOST_SRCS)
get_property(ALL_KERNEL_OP_TYPES GLOBAL PROPERTY ACLNN_OP_TYPES)
get_property(ALL_KERNEL_DIRS GLOBAL PROPERTY ACLNN_OP_KERNEL_DIRS)
get_property(ALL_KERNEL_FILES GLOBAL PROPERTY ACLNN_OP_KERNEL_FILES)

# 3. 统一生成 aclnn 调用代码和原型定义代码。
# npu_op_code_gen 必须先于 npu_op_kernel_sources 调用，
# 因为 npu_op_kernel_sources 依赖这里设置的自动生成文件路径。
npu_op_code_gen(
    SRC ${ALL_HOST_OPS_SRCS}
    PACKAGE ${package_name}
    OUT_DIR ${ASCEND_AUTOGEN_PATH}
    JOIN_OP_DEF False
)

# 4. 编译 aclnn 单算子调用库。
# npu_op_code_gen 执行后，ASCEND_AUTOGEN_PATH 下会生成 aclnn_*.cpp/aclnn_*.h。
file(GLOB autogen_aclnn_src ${ASCEND_AUTOGEN_PATH}/aclnn_*.cpp)
set_source_files_properties(${autogen_aclnn_src} PROPERTIES GENERATED TRUE)
npu_op_library(cust_opapi ACLNN
    ${autogen_aclnn_src}
)
target_compile_options(cust_opapi PRIVATE -fvisibility=hidden)

# 5. 编译算子原型库（用于入图）。
# 原型库同时依赖各算子的 Host 源文件和自动生成的 op_proto 代码。
file(GLOB group_proto_src ${ASCEND_AUTOGEN_PATH}/group_op_proto/*.cc)
file(GLOB proto_src ${ASCEND_AUTOGEN_PATH}/op_proto.cc)
set_source_files_properties(${group_proto_src} PROPERTIES GENERATED TRUE)
set_source_files_properties(${proto_src} PROPERTIES GENERATED TRUE)
npu_op_library(cust_op_proto GRAPH
    ${ALL_HOST_OPS_SRCS}
    ${group_proto_src}
    ${proto_src}
)
target_compile_options(cust_op_proto PRIVATE -fvisibility=hidden)

# 6. 编译 Tiling 库。
# Tiling 实现位于各算子的 Host 源文件中；fallback_*.cpp 为 npu_op_code_gen 生成的辅助代码。
file(GLOB fallback_src ${ASCEND_AUTOGEN_PATH}/fallback_*.cpp)
set_source_files_properties(${fallback_src} PROPERTIES GENERATED TRUE)
npu_op_library(cust_optiling TILING
    ${ALL_HOST_OPS_SRCS}
    ${fallback_src}
)
target_compile_options(cust_optiling PRIVATE -fvisibility=hidden)

# 7. 注册各算子的 Kernel 源码信息。
# 这里统一调用 npu_op_kernel_sources，避免子目录在 npu_op_code_gen 之前调用导致 auto_gen_path 未设置。
list(LENGTH ALL_KERNEL_OP_TYPES kernel_count)
if(kernel_count EQUAL 0)
    message(FATAL_ERROR "No operator registered. Please call register_aclnn_op in operator subdirectories.")
endif()
math(EXPR kernel_last_index "${kernel_count} - 1")
foreach(kernel_index RANGE 0 ${kernel_last_index})
    list(GET ALL_KERNEL_OP_TYPES ${kernel_index} op_type)
    list(GET ALL_KERNEL_DIRS ${kernel_index} kernel_dir)
    list(GET ALL_KERNEL_FILES ${kernel_index} kernel_file)

    # KERNEL_DIR 相对于下面 npu_op_kernel_library 的 SRC_BASE。
    npu_op_kernel_sources(ascendc_kernels
        OP_TYPE ${op_type}
        KERNEL_DIR ${kernel_dir}
        KERNEL_FILE ${kernel_file}
    )
endforeach()

# 8. 编译 Kernel 库。
# SRC_BASE 是所有算子目录共同的源码根目录；TILING_LIBRARY 指向上面编译出的 Tiling 库。
npu_op_kernel_library(ascendc_kernels
    SRC_BASE ${CMAKE_CURRENT_SOURCE_DIR}/
    TILING_LIBRARY cust_optiling
)

# 9. 将 Host 侧库和 Kernel 库加入算子包，最终生成 run 包。
npu_op_package_add(${package_name}
    LIBRARY
        cust_optiling
        cust_opapi
        cust_op_proto
        ascendc_kernels
)
```


> [!NOTE] 说明
> - `register_aclnn_op` 使用 `GLOBAL property` 收集信息，是为了让各算子子目录维护自己的文件列表，同时让顶层在收集完成后统一调用 `npu_op_code_gen` 和 `npu_op_kernel_sources`。
> - 子目录不要直接调用 `npu_op_kernel_sources`。该接口依赖 `npu_op_code_gen` 设置的自动生成文件路径，因此需要由顶层在 `npu_op_code_gen` 之后统一调用。
> - `OP_TYPE` 需要与算子原型注册中的 OpType 一致；当 Kernel 文件名不是 OpType 默认转换后的文件名时，需要显式指定 `KERNEL_FILE`。
> - 新增算子时，只需要新增算子子目录，在顶层添加 `add_subdirectory(new_op)`，并在 `new_op/CMakeLists.txt` 中调用 `register_aclnn_op`。

**与"按 Host/Kernel 划分"的关键差异**：
- Host 侧源文件由各算子子目录登记，顶层统一调用 `npu_op_code_gen`
- Kernel 源码信息由各算子子目录登记，顶层在 `npu_op_code_gen` 后统一调用 `npu_op_kernel_sources`
- `SRC_BASE` 指向所有算子目录共同的源码根目录，`KERNEL_DIR` 指向具体算子子目录
- 各算子的 host/kernel/tiling 文件集中在同一目录下

> 详细 cmake 函数参数请参考 [cmake 函数参考](../附录/cmake函数参考.md)。

完成编译组织之后，可按照[基本流程](#基本流程)的三个步骤完成算子编译与部署。

## 5 自定义编译选项（进阶）

算子工程可以分别为 Host 侧和 Kernel 侧添加自定义编译选项。如需做选择性编译（按 TilingKey 或模板参数筛选编译）以加速调试，见[编译加速 — 选择性编译](./编译加速.md#选择性编译)。

### 5.1 Kernel 侧编译选项

在 CMakeLists.txt 中，用 `npu_op_kernel_options` 为 Kernel 侧代码添加编译选项：

```cmake
npu_op_kernel_options(<target_name> <op_type> [COMPUTE_UNIT <soc_version>] OPTIONS ...)
```

**表 4** 参数说明

| 参数名称 | 可选/必选 | 参数描述 |
|---------|----------|---------|
| target_name | 必选 | Kernel 库的目标名称（如 `ascendc_kernels`） |
| op_type | 必选 | 算子类型。如需对所有算子生效，配置为 `ALL` |
| COMPUTE_UNIT | 可选 | AI 处理器型号，不配置时对所有型号生效。获取方法参考 [附录](../附录/soc_version获取方法.md) |
| OPTIONS | 必选 | 自定义编译选项，多个选项用空格间隔。支持 `-Dname=value` 宏定义、`-g` 调试选项等 |

**常见示例**：

```cmake
# 为所有算子添加调试选项
npu_op_kernel_options(ascendc_kernels ALL OPTIONS -g)

    # 为特定算子在特定型号上添加调试宏
    npu_op_kernel_options(ascendc_kernels AddCustom COMPUTE_UNIT ascend910b OPTIONS -DDEBUG_MODE=1)
```

### 5.2 Host 侧编译选项

用 CMake 原生的 `target_compile_options` 为 Host 侧目标添加编译选项：

```cmake
# 为算子 API 库添加编译选项
target_compile_options(cust_opapi PRIVATE -fvisibility=hidden)

# 为 Tiling 库添加编译选项
target_compile_options(cust_optiling PRIVATE -fvisibility=hidden)
```

更多编译选项和用法说明，请参考 [cmake 函数参考](../附录/cmake函数参考.md)。
