# 命名转换规则对照表

算子工程中，同一个算子会同时出现算子类型、Kernel入口、配置项、生成文件和aclnn接口等多种名称。本文说明这些名称之间的转换关系。以下规则以算子类型（OpType）`AddCustom`为例，并以当前构建工具中的`ConvertToSnakeCase()`实现为准。

## 2. OpType命名要求

构建工具对OpType执行以下检查：

- 第一个字符必须是大写字母。
- 后续字符只能是字母或数字，不能包含下划线、连字符或其他特殊字符。

例如：

| OpType | 是否符合要求 | 说明 |
|---|---|---|
| `AddCustom` | 是 | 首字母大写，其余字符均为字母 |
| `Conv2DCustom` | 是 | 可以包含数字 |
| `addCustom` | 否 | 首字母不是大写字母 |
| `Add_Custom` | 否 | 包含下划线 |
| `Add-Custom` | 否 | 包含连字符 |

算子原型中的类名、构造函数名和`OP_ADD`参数通常使用同一个OpType：

```cpp
namespace ops {
class AddCustom : public OpDef {
public:
    explicit AddCustom(const char* name) : OpDef(name)
    {
        // 输入、输出和算子配置。
    }
};

OP_ADD(AddCustom);
} // namespace ops
```

## 3. OpType转换为小写下划线名称

构建工具通过`ConvertToSnakeCase()`将OpType转换为文件和Kernel使用的小写下划线名称。转换时从左向右处理字符：

1. 首字符转换为小写。
2. 当前字符是大写字母，且前一个字符不是大写字母时，在当前字符前插入下划线，再转换为小写。这里的“不是大写字母”包括小写字母和数字。
3. 当前字符和前一个字符都是大写字母，但下一个字符是小写字母时，在当前字符前插入下划线，再转换为小写。这条规则用于识别连续大写缩写与后续单词的边界。
4. 其他大写字母直接转换为小写；小写字母和数字保持不变。

常见转换结果如下。

| OpType | 小写下划线名称 |
|---|---|
| `AddCustom` | `add_custom` |
| `MatmulCustom` | `matmul_custom` |
| `ReduceMaxCustom` | `reduce_max_custom` |
| `BatchNormCustom` | `batch_norm_custom` |
| `LayerNormCustom` | `layer_norm_custom` |
| `OneHotCustom` | `one_hot_custom` |
| `TopKCustom` | `top_k_custom` |
| `GatherV2Custom` | `gather_v2_custom` |
| `Conv2DCustom` | `conv2_d_custom` |
| `GRUCell` | `gru_cell` |
| `HTTPServerCustom` | `http_server_custom` |
| `AbcAAc` | `abc_a_ac` |

### 3.1 连续大写字母

连续大写字母通常表示缩写。转换工具不会在缩写的每个字母前插入下划线，而是在缩写和后续单词的边界插入下划线。

例如`GRUCell`的转换过程为：

```text
GRU + Cell
 -> gru_cell
```

`HTTPServerCustom`转换为`http_server_custom`，不会转换为`h_t_t_p_server_custom`。

### 3.2 数字与大写字母相邻

数字本身保持不变。数字后的字符如果是大写字母，会触发下划线插入规则。

```text
GatherV2Custom -> gather_v2_custom
Conv2DCustom   -> conv2_d_custom
```

`GatherV2Custom`中的`V`位于小写字母`r`之后，因此转换为`_v`；数字`2`直接保留。`Conv2DCustom`中的`D`位于数字`2`之后，因此转换为`_d`。不能仅通过肉眼把`Conv2D`写成`conv2d`。

## 4. ACLNN文件和接口命名

默认配置下，aclnn代码生成器同时使用OpType和小写下划线名称：

- 文件名使用小写下划线名称：`aclnn_<op_name>.h`和`aclnn_<op_name>.cpp`。
- C接口保留OpType的大驼峰形式：`aclnn<OpType>GetWorkspaceSize`和`aclnn<OpType>`。

以`ReduceMaxCustom`为例：

```text
OpType                 ReduceMaxCustom
小写下划线名称         reduce_max_custom
aclnn头文件            aclnn_reduce_max_custom.h
第一段接口             aclnnReduceMaxCustomGetWorkspaceSize
第二段接口             aclnnReduceMaxCustom
Kernel入口             reduce_max_custom
```

工程修改了ACLNN工程名前缀或直调接口前缀时，生成文件和接口的前缀可能随配置变化。应用程序应以构建产物中的头文件声明为准，不要手工拼接接口名称。

输入、输出和属性在`GetWorkspaceSize`接口中的命名还有单输出`out`、多输出`Out`后缀、可选输入`Optional`后缀和同名输入输出`Ref`后缀等规则，详见[单算子API调用](../单算子API调用.md)。

## 5. 哪些名称必须一致

开发者手工编写或调整工程时，重点检查以下对应关系：

1. `OpDef`类名、构造函数名和`OP_ADD`参数使用同一个OpType。
2. 默认配置下，Kernel入口函数名使用OpType转换后的小写下划线名称。
3. Kernel入口被自定义配置覆盖时，`opInterface.value`应与实际Kernel入口一致。
4. 应用代码包含构建生成的aclnn头文件，并调用头文件中声明的接口。
5. 重命名Host或Kernel源文件后，需要同步修改构建脚本中的源文件列表；修改物理文件名不会自动修改OpType或接口符号。

使用msOpGen创建工程时，建议先确定OpType，再由工具生成初始目录和代码。对于包含缩写或数字的OpType，编译后可以检查生成的`ops-info.ini`中的`opFile.value`、`opInterface.value`以及`autogen`目录中的aclnn头文件，确认实际转换结果。
