# 算子原型定义

算子原型定义描述算子对外暴露的接口和支持范围。本文承接[算子功能设计](./算子功能设计.md)的结论，说明如何将功能设计中的输入输出、属性、dtype/format、shape/dtype推导、Tiling函数关联和AI处理器支持范围落地为`OpDef`代码。

## 1. 原型定义放在哪里

在AddCustom样例工程中，算子原型定义位于Host侧实现文件：

```text
op_host/add_custom/add_custom_host.cpp
```

该文件中同时包含三类内容：

| 内容 | 作用 |
|---|---|
| `TilingFunc` | Host侧Tiling函数，负责计算Kernel启动和分块参数 |
| `InferShape`、`InferDataType` | 输出shape和dtype推导函数 |
| `class AddCustom : public OpDef` | 算子原型定义，描述输入、输出、属性、Tiling关联和soc支持范围 |

本文重点讲`class AddCustom : public OpDef`中的原型定义内容，同时说明它和推导函数、Tiling函数之间的连接关系。

## 2. 定义OpDef类并注册算子

算子原型通过一个继承自`OpDef`的C++类承载。类名通常与算子类型保持一致。AddCustom的算子类型为`AddCustom`，因此定义`AddCustom`类。

```cpp
namespace ops {
class AddCustom : public OpDef {
public:
    explicit AddCustom(const char* name) : OpDef(name)
    {
        // 原型定义内容
    }
};
OP_ADD(AddCustom);
} // namespace ops
```

这里有两个关键点：

- 构造函数通过`OpDef(name)`初始化基类，后续的`Input`、`Output`、`Attr`、`AICore`等声明都写在构造函数中。
- 文件末尾通过`OP_ADD(AddCustom)`注册算子类型，编译工具据此识别算子原型，并生成aclnn接口、图模式原型等相关代码。

## 3. 定义输入和输出

输入输出定义来自功能设计阶段的结论。AddCustom有两个输入`x`、`y`，一个输出`z`，三个Tensor共同表达`z = x + y`的计算语义，因此都声明为`REQUIRED`。基础样例没有属性，输入输出声明就是原型定义中最先落地的接口内容。

```cpp
this->Input("x")
    .ParamType(REQUIRED)
    .DataType({ge::DT_FLOAT16})
    .Format({ge::FORMAT_ND});
this->Input("y")
    .ParamType(REQUIRED)
    .DataType({ge::DT_FLOAT16})
    .Format({ge::FORMAT_ND});
this->Output("z")
    .ParamType(REQUIRED)
    .DataType({ge::DT_FLOAT16})
    .Format({ge::FORMAT_ND});
```

输入输出参数说明如下：

| 原型项 | 参数 | 作用 | AddCustom写法 |
|---|---|---|---|
| `Input`/`Output` | 输入输出名称 | 声明输入输出名称，名称需要和功能设计中的参数名称一致。声明顺序会影响aclnn接口参数顺序和Kernel入口参数顺序。 | 输入为`x`、`y`，输出为`z` |
| `Input`/`Output` | `ParamType` | 声明参数提供方式。`REQUIRED`表示每次调用都必须提供，`OPTIONAL`表示部分场景可以省略，`DYNAMIC`表示数量随调用变化。 | `x`、`y`、`z`都使用`REQUIRED` |
| `Input`/`Output` | `DataType` | 声明输入输出支持的dtype。多个dtype按列表顺序和format列表一一对应。 | `ge::DT_FLOAT16` |
| `Input`/`Output` | `Format` | 声明输入输出支持的format。多个format按列表顺序和dtype列表一一对应。 | `ge::FORMAT_ND` |

同一个输入或输出支持多组dtype/format时，`DataType`和`Format`列表需要按位置对应。例如下面的写法表示支持`DT_FLOAT16 + FORMAT_ND`、`DT_FLOAT + FORMAT_ND`和`DT_INT32 + FORMAT_ND`三组组合。

```cpp
this->Input("x")
    .ParamType(REQUIRED)
    .DataType({ge::DT_FLOAT16, ge::DT_FLOAT, ge::DT_INT32})
    .Format({ge::FORMAT_ND, ge::FORMAT_ND, ge::FORMAT_ND});
```

- 如果某个输入或输出的dtype或format能够和其他输入输出的组合自由搭配，可以使用`DataTypeList`或`FormatList`减少重复列举。以下两种写法表达相同组合关系。

    ```cpp
    // 方式一：逐项列出所有一一对应的组合。
    this->Input("x")
        .ParamType(REQUIRED)
        .DataType({ge::DT_FLOAT16, ge::DT_FLOAT16, ge::DT_FLOAT16})
        .Format({ge::FORMAT_ND, ge::FORMAT_ND, ge::FORMAT_ND});
    this->Input("y")
        .ParamType(REQUIRED)
        .DataType({ge::DT_FLOAT16, ge::DT_FLOAT, ge::DT_INT32})
        .Format({ge::FORMAT_ND, ge::FORMAT_ND, ge::FORMAT_ND});
    this->Output("z")
        .ParamType(REQUIRED)
        .DataType({ge::DT_FLOAT16, ge::DT_FLOAT, ge::DT_INT32})
        .Format({ge::FORMAT_ND, ge::FORMAT_ND, ge::FORMAT_ND});

    // 方式二：`x`固定支持`DT_FLOAT16 + FORMAT_ND`时，使用`DataTypeList`和`FormatList`表达`x`的支持集合。
    this->Input("x")
        .ParamType(REQUIRED)
        .DataTypeList({ge::DT_FLOAT16})
        .FormatList({ge::FORMAT_ND});
    this->Input("y")
        .ParamType(REQUIRED)
        .DataType({ge::DT_FLOAT16, ge::DT_FLOAT, ge::DT_INT32})
        .Format({ge::FORMAT_ND, ge::FORMAT_ND, ge::FORMAT_ND});
    this->Output("z")
        .ParamType(REQUIRED)
        .DataType({ge::DT_FLOAT16, ge::DT_FLOAT, ge::DT_INT32})
        .Format({ge::FORMAT_ND, ge::FORMAT_ND, ge::FORMAT_ND});
    ```

- 通过Follow接口可以指定当前输入或输出的datatype、format和shape跟随前面已经定义过的输入。输出完全跟随某个输入时，Follow可以把“输出与输入一致”的关系直接写在原型里，省去单独编写shape推导函数的重复代码。使用Follow接口指定shape一致时通常比[shape推导](../../算子入图开发/基本开发流程.md)函数逻辑更加简单，能用Follow表达的逻辑，建议使用Follow接口，则无需再编写shape推导函数。

    例如输出`y1`跟随输入`x1`时，`y1`的datatype、format和shape都会与`x1`保持一致：

    ```cpp
    this->Input("x1")
        .ParamType(REQUIRED)
        .DataType({ge::DT_FLOAT, ge::DT_FLOAT})
        .Format({ge::FORMAT_ND, ge::FORMAT_ND});
    this->Input("x2")
        .ParamType(REQUIRED)
        .DataType({ge::DT_FLOAT, ge::DT_FLOAT})
        .Format({ge::FORMAT_ND, ge::FORMAT_ND});
    this->Output("y1")
        .ParamType(REQUIRED)
        .Follow("x1");
    ```

## 4. 定义属性

属性用于描述算子的配置项，例如维度、阈值、缩放系数、开关等。AddCustom基础样例只实现`z = x + y`，功能设计中已经确认没有额外属性，因此原型定义中没有`Attr`声明。

带属性的算子可以在构造函数中使用`Attr`定义。例如将AddCustom扩展为`z = x + alpha * y`时，可以增加`alpha`属性：

```cpp
this->Attr("alpha")
    .AttrType(OPTIONAL)
    .Float(1.0);
```

`AttrType`描述属性是否必须提供，常用取值为`REQUIRED`和`OPTIONAL`。`Bool`、`Float`、`Int`等接口用于声明属性数据类型和默认值。

属性在原型中声明后，Host侧Tiling函数可以通过`context->GetAttrs()`获取属性值。Kernel侧需要使用属性参与计算时，可以通过TilingData将属性值传递到Kernel。属性传递方法见[通过TilingData传递属性信息](../Host侧Tiling实现/通过TilingData传递属性信息.md)。

## 5. 注册输出shape和dtype推导函数

AddCustom的输出`z`与输入`x`具有相同shape，输出dtype也与输入`x`保持一致。这一关系来自功能设计中的逐元素加法语义，在原型定义中需要关联对应的推导函数。

```cpp
this->SetInferShape(ge::InferShape)
    .SetInferDataType(ge::InferDataType);
```

`SetInferShape`用于注册输出shape推导函数，`SetInferDataType`用于注册输出dtype推导函数。注册后，框架在需要推导输出shape或dtype时会调用对应函数。

本文只说明原型定义中如何关联推导函数。推导函数内部如何读取输入shape、设置输出shape、读取输入dtype和设置输出dtype，属于入图开发和Host侧实现细节，见[算子入图开发](../../算子入图开发/概述.md)。

## 6. 关联Host侧Tiling实现

算子原型还需要关联Host侧Tiling函数。AddCustom样例中，Tiling函数名为`optiling::TilingFunc`，通过`AICore().SetTiling(...)`注册。

```cpp
this->AICore()
    .SetTiling(optiling::TilingFunc);
```

`SetTiling`只负责建立原型和Tiling函数之间的调用关系。`TilingFunc`内部会读取输入shape等信息，计算Kernel需要的运行参数，并写入TilingData。AddCustom的`TilingFunc`会计算`totalLength`、设置`blockDim`、写入`tileNum`，并把workspace大小设置为0。

TilingData字段设计、Tiling函数写法、workspace设置和`blockDim`配置见[Host侧Tiling实现](../Host侧Tiling实现/基本流程.md)。

## 7. 配置AI处理器支持范围

`AddConfig`用于声明算子支持的AI处理器型号。接口原型如下，`soc`表示AI处理器型号，`aicore_config`表示该AI处理器型号上的差异化配置。

```cpp
void AddConfig(const char *soc);
void AddConfig(const char *soc, OpAICoreConfig &aicore_config);
```

AddCustom基础样例中的配置如下：

```cpp
this->AICore()
    .SetTiling(optiling::TilingFunc)
    .AddConfig("ascend310p")
    .AddConfig("ascend310b")
    .AddConfig("ascend910b")
    .AddConfig("ascend910_93")
    .AddConfig("ascend950");
```

算子至少需要配置一个soc。`ascendxxx`这类占位写法需要替换为实际AI处理器型号，通常可以参考算子工程目录下`CMakePresets.json`中的`ASCEND_COMPUTE_UNIT`字段；该字段在使用msOpGen创建工程时自动生成，具体方法见[创建算子工程](../创建算子工程.md)。

如果不同soc共享相同输入输出原型、Tiling函数和Kernel实现，可以连续调用多个`AddConfig`。如果某个soc的dtype、format或Kernel实现存在差异，需要使用差异化原型或差异化编译配置。

### 7.1 使用OpAICoreConfig注册差异化原型

当某个AI处理器型号支持的输入输出、dtype或format与默认原型存在差异时，可以新增`OpAICoreConfig`，并通过`AddConfig(soc, config)`注册到指定soc。

差异化原型的生效规则如下：

- `OpAICoreConfig`中没有配置的输入输出，会继承`OpDef`中的定义。
- `OpAICoreConfig`中重新配置的输入输出，会覆盖`OpDef`中同名参数的定义。

如下示例中，`ascendxxx1`和`ascendxxx2`共用`OpDef`中的原型；`ascendxxx3`新增`DT_BF16`支持，并通过`OpAICoreConfig`覆盖`x`、`y`、`z`的dtype/format定义。

```cpp
namespace ops {
class MyAdd : public OpDef {
public:
    explicit MyAdd(const char* name) : OpDef(name)
    {
        this->Input("x")
            .ParamType(REQUIRED)
            .DataType({ge::DT_FLOAT16})
            .Format({ge::FORMAT_ND});
        this->Input("y")
            .ParamType(REQUIRED)
            .DataType({ge::DT_FLOAT16})
            .Format({ge::FORMAT_ND});
        this->Output("z")
            .ParamType(REQUIRED)
            .DataType({ge::DT_FLOAT16})
            .Format({ge::FORMAT_ND});

        this->AICore()
            .SetTiling(optiling::TilingFunc)
            .AddConfig("ascendxxx1")
            .AddConfig("ascendxxx2");

        OpAICoreConfig config;
        config.Input("x")
            .ParamType(REQUIRED)
            .DataType({ge::DT_FLOAT16, ge::DT_BF16})
            .Format({ge::FORMAT_ND, ge::FORMAT_ND});
        config.Input("y")
            .ParamType(REQUIRED)
            .DataType({ge::DT_FLOAT16, ge::DT_BF16})
            .Format({ge::FORMAT_ND, ge::FORMAT_ND});
        config.Output("z")
            .ParamType(REQUIRED)
            .DataType({ge::DT_FLOAT16, ge::DT_BF16})
            .Format({ge::FORMAT_ND, ge::FORMAT_ND});
        this->AICore().AddConfig("ascendxxx3", config);
    }
};
OP_ADD(MyAdd);
} // namespace ops
```

如果只有少量参数在不同soc上存在差异，也可以只在`OpAICoreConfig`中配置这些参数，其他原型信息继续继承`OpDef`中的定义。

### 7.2 在独立文件中注册差异化原型

差异化原型也可以通过`REGISTER_OP_AICORE_CONFIG`宏放在独立文件中注册，便于按芯片或模块拆分维护。例如已有`op_host/add_custom.cpp`注册了基础原型，可以新增`op_host/add_custom_ascendxxx2.cpp`，单独注册`ascendxxx2`的差异化配置。

```cpp
#include "register/op_config_registry.h"

namespace ops {
REGISTER_OP_AICORE_CONFIG(AddCustom, ascendxxx2, []() {
    ops::OpAICoreConfig config("ascendxxx2");
    config.Input("x")
        .ParamType(REQUIRED)
        .DataType({ge::DT_FLOAT16, ge::DT_BF16})
        .Format({ge::FORMAT_ND, ge::FORMAT_ND});
    return config;
});
} // namespace ops
```

同一芯片型号同时通过`AddConfig`和`REGISTER_OP_AICORE_CONFIG`注册配置时，`AddConfig`的优先级更高，会覆盖`REGISTER_OP_AICORE_CONFIG`注册的信息。

## 8. 完整示例

以下代码展示AddCustom的原型定义主体。为突出原型定义逻辑，示例保留输入输出、推导函数注册、Tiling关联、soc配置和算子注册。

```cpp
namespace ops {
class AddCustom : public OpDef {
public:
    explicit AddCustom(const char* name) : OpDef(name)
    {
        this->Input("x")
            .ParamType(REQUIRED)
            .DataType({ge::DT_FLOAT16})
            .Format({ge::FORMAT_ND});
        this->Input("y")
            .ParamType(REQUIRED)
            .DataType({ge::DT_FLOAT16})
            .Format({ge::FORMAT_ND});
        this->Output("z")
            .ParamType(REQUIRED)
            .DataType({ge::DT_FLOAT16})
            .Format({ge::FORMAT_ND});

        this->SetInferShape(ge::InferShape)
            .SetInferDataType(ge::InferDataType);
        this->AICore()
            .SetTiling(optiling::TilingFunc)
            .AddConfig("ascend310p")
            .AddConfig("ascend310b")
            .AddConfig("ascend910b")
            .AddConfig("ascend910_93")
            .AddConfig("ascend950");
    }
};
OP_ADD(AddCustom);
} // namespace ops
```
