# 芯片型号获取方法

aclnn算子工程中会出现完整SoC型号、Short SoC型号、工程编译单元和NPU架构等名称。它们描述的层级不同，不能混用，本文主要说明各字段的获取方法。

## 1. 获取完整SoC型号

### 2.1 通过设备查询命令获取

- 针对如下产品：在安装AI处理器的服务器执行npu-smi info命令进行查询，获取Name信息。实际配置值为AscendName，例如Name取值为xxxyy，实际配置值为Ascendxxxyy。

    - Atlas A2 训练系列产品/Atlas A2 推理系列产品
    - Atlas 200I/500 A2 推理产品
    - Atlas 推理系列产品
    - Atlas 训练系列产品

- 针对Atlas A3 训练系列产品/Atlas A3 推理系列产品，在安装AI处理器的服务器执行npu-smi info -t board -i id -c chip_id命令进行查询，获取Chip Name和NPU Name信息，实际配置值为Chip Name_NPU Name。例如Chip Name取值为Ascendxxx，NPU Name取值为1234，实际配置值为Ascendxxx_1234。其中：

    - id：设备id，通过npu-smi info -l命令查出的NPU ID即为设备id。
    - chip_id：芯片id，通过npu-smi info -m命令查出的Chip ID即为芯片id。

- 针对Ascend 950PR/Ascend 950DT，在安装AI处理器的服务器执行npu-smi info -t board -i id命令进行查询，获取Chip Name和NPU Name信息，实际配置值为Chip Name_NPU Name。例如Chip Name取值为Ascendxxx，NPU Name取值为1234，实际配置值为Ascendxxx_1234。
其中，id为设备id，通过npu-smi info -l命令查出的NPU ID即为设备id。

## 4. 获取Short SoC和工程编译单元

从平台配置文件读取`Short_SoC_version`：

```bash
short_soc_version=$(
    awk -F= '$1 == "Short_SoC_version" { print $2; exit }' "${platform_file}"
)
```

`Short_SoC_version`是CANN平台配置中的原始字段，例如`Ascend910B`。aclnn工程中的`ASCEND_COMPUTE_UNIT`和`AddConfig`使用全小写形式：

```bash
compute_unit=$(
    printf '%s' "${short_soc_version}" | tr '[:upper:]' '[:lower:]'
)
printf '%s\n' "${compute_unit}"
# ascend910b
```

二者的使用位置如下：

```cmake
set(ASCEND_COMPUTE_UNIT ascend910b)
```

```cpp
this->AICore().AddConfig("ascend910b");
```

不要在上述位置填写`Ascend910B4`或`Ascend910B`。构建工具允许的工程编译单元是归一化后的系列名称，例如`ascend910b`、`ascend910_93`、`ascend310p`和`ascend950`。

## 5. 查询NPU Arch

__NPU_ARCH__是Device侧AI Core代码中的预处理宏，用于标识AI处理器的架构版本。产品型号和NPU架构版本的对应关系可查看[__NPU_ARCH__](../../../语言扩展层/SIMD-BuiltIn关键字.md#table65291052154114)。

## 7. 常见型号对照

以下值取自对应CANN平台配置文件：

| 完整`SoC_version` | `Short_SoC_version` | 工程编译单元 | `NpuArch` | Cube编译架构 | Vector编译架构 |
|---|---|---|---|---|---|
| `Ascend910B4` | `Ascend910B` | `ascend910b` | `2201` | `dav-c220-cube` | `dav-c220-vec` |
| `Ascend310P3` | `Ascend310P` | `ascend310p` | `2002` | `dav-m200` | `dav-m200-vec` |
| `Ascend950PR_9599` | `Ascend950` | `ascend950` | `3510` | `dav-c310-cube` | `dav-c310-vec` |

平台字段可能随新增芯片型号扩展。开发者应读取当前CANN安装包中的配置文件，不应把本表作为完整支持列表。

## 9. 使用约束

1. 芯片型号和工程配置值区分大小写，应按对应使用位置填写。
2. `SoC_version`描述具体型号，工程编译单元描述可复用二进制的芯片系列，二者不能混用。
3. 多设备服务器上可能存在不同型号的设备，需要针对实际运行设备获取`SoC_version`。
4. 交叉编译时应查询目标设备型号，不能使用编译服务器本机的设备型号。
5. Short SoC、NPU Arch和`dav-*`编译架构应从目标CANN软件包的平台配置文件获取。
6. 普通Kernel不需要使用`__NPU_ARCH__`；只有确实存在架构差异且公共API无法屏蔽时才增加条件编译。
