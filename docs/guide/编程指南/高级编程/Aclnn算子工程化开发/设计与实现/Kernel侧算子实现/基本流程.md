# 基本流程

本文介绍aclnn算子工程中Kernel侧算子实现的基本编写流程。Kernel侧算子运行在AICore上，负责执行实际计算；本文重点说明Kernel接入CANN框架时需要关注的函数格式、参数顺序、TilingData处理和信息获取方式。

Kernel侧的基础编程模型可以概括为“搬运-计算-搬运”：先通过`DataCopy`将输入数据从GlobalMemory搬运到UB，再在UB上调用AscendC计算API，最后把结果从UB写回GlobalMemory。逐元素算子、归约类算子、矩阵类算子都会围绕这条基本数据流组织代码，差异主要体现在TilingData字段、计算API选择和分块策略上。

## 1. Kernel函数格式

### 1.1命名规则

Kernel入口函数名需要和算子类型对应。算子类型采用大驼峰命名，Kernel入口函数采用小写下划线命名，框架在编译和运行时根据命名规则完成匹配。

| 算子类型 | Kernel入口函数名 |
|---|---|
| `AddCustom` | `add_custom` |
| `MatmulCustom` | `matmul_custom` |
| `ReduceMaxCustom` | `reduce_max_custom` |
| `Conv2DCustom` | `conv2d_custom` |
| `GatherV2Custom` | `gather_v2_custom` |

完整转换规则和更多示例请参考[命名转换规则对照表](../../附录/命名转换规则对照表.md)。

### 1.2函数形式

Kernel入口函数常见写法包括C风格和C++模板风格。

**C风格**使用`extern "C"`修饰，适用于单Kernel入口或通过`TilingKey`在同一入口内区分分支的场景。msOpGen生成的基础模板通常采用这种形式。

```cpp
extern "C" __global__ __aicore__ void add_custom(GM_ADDR x, GM_ADDR y, GM_ADDR z,
                                                  GM_ADDR workspace, GM_ADDR tiling)
{
    REGISTER_TILING_DEFAULT(AddCustomTilingData);
    GET_TILING_DATA(tilingData, tiling);

    KernelAdd op;
    op.Init(x, y, z, tilingData.totalLength, tilingData.tileNum);
    op.Process();
}
```

**C++模板风格**通过模板参数承载dtype、Tile数量或分支选择信息，适用于Kernel代码需要复用到基础算子开发方式（`<<<>>>`）和aclnn算子工程化场景的情况。

```cpp
template<typename D_T_X, typename D_T_Y, typename D_T_Z, int TILE_NUM>
__global__ __aicore__ void add_custom(GM_ADDR x, GM_ADDR y, GM_ADDR z,
                                      GM_ADDR workspace, GM_ADDR tiling)
{
    GET_TILING_DATA(tilingData, tiling);

    KernelAdd<D_T_X, D_T_Y, D_T_Z> op;
    op.Init(x, y, z, tilingData.totalLength, TILE_NUM);
    op.Process();
}
```

C++模板风格通常和多分支策略一起使用，具体的模板参数定义、实例化和编译期分支选择会在多分支策略章节展开。

### 1.3参数顺序

Kernel入口函数参数需要按照“输入、输出、workspace、tiling”的顺序排列。框架调用Kernel时，会先按照算子原型定义中的输入输出顺序传入Tensor地址，再追加workspace和tiling两个参数。

```cpp
extern "C" __global__ __aicore__ void add_custom(GM_ADDR x, GM_ADDR y, GM_ADDR z,
                                                  GM_ADDR workspace, GM_ADDR tiling);
```

参数含义如下：

| 参数 | 来源 | 作用 |
|---|---|---|
| `x`、`y` | 算子原型中的输入 | 指向输入Tensor的GlobalMemory地址 |
| `z` | 算子原型中的输出 | 指向输出Tensor的GlobalMemory地址 |
| `workspace` | 框架追加 | 指向workspace内存地址 |
| `tiling` | 框架追加 | 指向Host侧Tiling写入的数据 |

> **说明：输入输出同名场景**
>
> 如果算子原型中的输入和输出同名，msOpGen生成Kernel入口参数时会给输出参数增加`ref`后缀，用于区分输入和输出地址。
>
> ```cpp
> extern "C" __global__ __aicore__ void add_custom(GM_ADDR x, GM_ADDR y,
>                                                   GM_ADDR x_ref, GM_ADDR workspace,
>                                                   GM_ADDR tiling);
> ```

## 2. TilingData处理

Host侧Tiling函数会把Kernel运行需要的参数写入TilingData。Kernel侧需要先声明当前Kernel入口使用的TilingData类型，再从`tiling`参数中解析出结构体实例。

### 2.1注册TilingData

注册TilingData用于告知框架当前Kernel入口使用的TilingData结构体类型。根据TilingData定义方式不同，注册方式也不同。

**标准C++方式**在Kernel入口函数中使用`REGISTER_TILING_DEFAULT`注册。

```cpp
extern "C" __global__ __aicore__ void add_custom(GM_ADDR x, GM_ADDR y, GM_ADDR z,
                                                  GM_ADDR workspace, GM_ADDR tiling)
{
    REGISTER_TILING_DEFAULT(AddCustomTilingData);
    GET_TILING_DATA(tilingData, tiling);
    // ...
}
```

**宏定义方式**通常通过`REGISTER_TILING_DATA_CLASS`完成TilingData类型注册，Kernel侧可以直接使用`GET_TILING_DATA`获取数据。

```cpp
extern "C" __global__ __aicore__ void my_add(GM_ADDR x, GM_ADDR y, GM_ADDR z,
                                              GM_ADDR workspace, GM_ADDR tiling)
{
    GET_TILING_DATA(tilingData, tiling);
    // ...
}
```

**带TilingKey的场景**可以为不同`TilingKey`注册不同TilingData结构体。第一个参数通常采用`${OpType}_${TilingKey}`形式。

```cpp
REGISTER_TILING_DATA_CLASS(AddCustom, AddStruct)
REGISTER_TILING_DATA_CLASS(AddCustom_1, AddStructSample1)
```

如果Kernel运行时使用的`TilingKey`没有匹配到单独注册的TilingData类型，框架会回退使用默认TilingData类型。TilingData定义方式和使用约束请参考[Host侧Tiling实现](../Host侧Tiling实现/基本流程.md)。

### 2.2获取TilingData

Kernel入口函数中通过`GET_TILING_DATA`宏将框架传入的`tiling`参数解析为TilingData实例。

```cpp
extern "C" __global__ __aicore__ void add_custom(GM_ADDR x, GM_ADDR y, GM_ADDR z,
                                                  GM_ADDR workspace, GM_ADDR tiling)
{
    REGISTER_TILING_DEFAULT(AddCustomTilingData);
    GET_TILING_DATA(tilingData, tiling);

    KernelAdd op;
    op.Init(x, y, z, tilingData.totalLength, tilingData.tileNum);
    op.Process();
}
```

解析完成后，Kernel侧可以读取`tilingData`中的字段。字段含义来自Host侧Tiling设计，例如逐元素算子常见的`totalLength`表示总元素数，`tileNum`表示每个Block内部的Tile数量。

使用`TilingKey`区分多个Kernel分支时，可以在Kernel入口中通过`TILING_KEY_IS`选择执行路径。具体写法会在多分支策略章节展开。

## 3. 信息获取

Kernel侧除了输入输出地址和TilingData，还可以通过框架生成的宏获取输入输出的dtype和format信息。这些信息通常用于声明Tensor类型、选择计算路径或处理format差异。

### 3.1获取输入输出dtype和format

Kernel侧可以通过`DTYPE_<Arg>`、`ORIG_DTYPE_<Arg>`、`FORMAT_<Arg>`三类宏获取输入输出的数据类型和格式信息。`<Arg>`由Kernel入口参数名转换成全大写形式。

| 原型定义name | Kernel入口参数名 | dtype宏 | 原始dtype宏 | format宏 |
|---|---|---|---|---|
| `x` | `x` | `DTYPE_X` | `ORIG_DTYPE_X` | `FORMAT_X` |
| `y` | `y` | `DTYPE_Y` | `ORIG_DTYPE_Y` | `FORMAT_Y` |
| `z` | `z` | `DTYPE_Z` | `ORIG_DTYPE_Z` | `FORMAT_Z` |
| `input_data` | `input_data` | `DTYPE_INPUT_DATA` | `ORIG_DTYPE_INPUT_DATA` | `FORMAT_INPUT_DATA` |
| `output_result` | `output_result` | `DTYPE_OUTPUT_RESULT` | `ORIG_DTYPE_OUTPUT_RESULT` | `FORMAT_OUTPUT_RESULT` |

三类宏的含义如下：

| 宏 | 含义 | 常见用途 |
|---|---|---|
| `DTYPE_<Arg>` | Kernel侧可直接使用的C++数据类型，如`half`、`float`、`int32_t` | 声明变量、`GlobalTensor`、`LocalTensor`或模板参数 |
| `ORIG_DTYPE_<Arg>` | 算子原型中声明的dtype编号，如`DT_FLOAT16`、`DT_FLOAT` | 与dtype编号比较，选择不同计算路径 |
| `FORMAT_<Arg>` | 算子原型中声明的format编号，如`FORMAT_ND`、`FORMAT_NZ` | 根据format选择不同数据组织方式 |

`DTYPE_X`和`ORIG_DTYPE_X`关注点不同。以`x`为例，`DTYPE_X`可以直接作为Kernel侧C++类型使用；`ORIG_DTYPE_X`用于和dtype编号比较。`ORIG_DTYPE_<Arg>`和`FORMAT_<Arg>`由编译选项传入，通常用于预处理分支。

```cpp
extern "C" __global__ __aicore__ void add_custom(GM_ADDR x, GM_ADDR y, GM_ADDR z,
                                                  GM_ADDR workspace, GM_ADDR tiling)
{
    GET_TILING_DATA(tilingData, tiling);

    DTYPE_X temp;
    func<DTYPE_Z>();

    #if FORMAT_Y == FORMAT_ND
    // ND格式处理逻辑
    #endif

    #if ORIG_DTYPE_Y == DT_FLOAT
    // float类型处理逻辑
    #endif
}
```
