# 多分支策略

本文介绍aclnn算子工程中多分支Kernel实现的设计和编写方法。多分支策略承接[算子功能设计](./算子功能设计.md)中的扩展场景判断，用于处理不同dtype、shape、format或运行配置下Kernel实现路径不同的情况。

可以先用一句话理解这两个概念：

```text
Kernel模板负责生成多份专用Kernel，TilingKey负责运行时选中其中一份。
```

在基础算子中，一个Kernel入口可以覆盖所有场景。当不同场景需要不同计算路径时，就需要引入分支策略。常见触发条件如下：

- dtype不同：例如`float16`路径需要升精度计算，`float32`路径可以直接计算。
- shape大小不同：例如小shape使用单轮处理，大shape使用多轮Tile循环。
- format不同：例如`ND`和`NZ`的数据组织方式不同。
- 运行配置不同：例如确定性计算、性能优先路径、特殊workspace使用方式不同。

## 1.TilingKey：数字标识分支<a name="tilingkey数字标识分支"></a>

`TilingKey`是Host侧Tiling和Kernel侧之间约定的分支标识。Host侧Tiling根据输入shape、dtype、属性或运行配置选择一个数字，并通过`context->SetTilingKey(...)`写入上下文。Kernel侧通过`TILING_KEY_IS(...)`标识对应分支。

### 1.1适用场景

当分支数量较少，且每个分支可以用一个清晰数字表达时，可以直接使用`TilingKey`。例如AddCustom需要根据输入规模选择不同处理路径：

```text
小shape -> TilingKey=1 -> ProcessSmall
大shape -> TilingKey=2 -> ProcessLarge
```

这种方式适合先解决“运行时选哪条路径”的问题。数字含义建议在代码附近用常量或注释固定下来，避免后续维护时只看到`1`、`2`这类裸数字。

### 1.2Host侧设置TilingKey

Host侧Tiling函数负责选择分支。下面示例根据输入元素数量设置不同`TilingKey`：

```cpp
constexpr uint64_t TILING_KEY_SMALL = 1;
constexpr uint64_t TILING_KEY_LARGE = 2;
constexpr uint32_t MIN_LENGTH_FOR_SPLIT = 2048;

static ge::graphStatus TilingFunc(gert::TilingContext* context)
{
    uint32_t totalLength = context->GetInputShape(0)->GetOriginShape().GetShapeSize();
    AddCustomTilingData* tiling = context->GetTilingData<AddCustomTilingData>();

    tiling->totalLength = totalLength;
    if (totalLength < MIN_LENGTH_FOR_SPLIT) {
        tiling->tileNum = 1;
        context->SetTilingKey(TILING_KEY_SMALL);
    } else {
        tiling->tileNum = 8;
        context->SetTilingKey(TILING_KEY_LARGE);
    }

    context->SetBlockDim(8);
    size_t* workspaceSizes = context->GetWorkspaceSizes(1);
    workspaceSizes[0] = 0;
    return ge::GRAPH_SUCCESS;
}
```

这段代码完成两件事：

- 把Kernel运行需要的参数写入`TilingData`。
- 把当前输入命中的实现分支写入`TilingKey`。

### 1.3Kernel侧使用TILING_KEY_IS

Kernel侧通过`TILING_KEY_IS`标识不同分支。每个分支对应一条明确的处理路径：

```cpp
extern "C" __global__ __aicore__ void add_custom(GM_ADDR x, GM_ADDR y, GM_ADDR z,
                                                  GM_ADDR workspace, GM_ADDR tiling)
{
    REGISTER_TILING_DEFAULT(AddCustomTilingData);
    GET_TILING_DATA(tilingData, tiling);

    KernelAdd op;
    op.Init(x, y, z, tilingData.totalLength, tilingData.tileNum);

    if (TILING_KEY_IS(1)) {
        op.ProcessSmall();
    } else if (TILING_KEY_IS(2)) {
        op.ProcessLarge();
    }
}
```

`TILING_KEY_IS`用于标识Kernel分支。编译流程会识别这些分支，并为对应`TilingKey`生成可执行的Kernel代码。运行时Host侧写入的`TilingKey`会和Kernel侧分支对应起来。

### 1.4编译裁剪

多分支会增加编译产物和编译时间。调试或只验证部分`TilingKey`分支时，可以通过`--tiling_key`只编译指定分支：

```bash
--tiling_key=1,2
```

配置多个`TilingKey`时，使用英文逗号`,`分隔。

## 2.Kernel模板：生成多份专用Kernel

Kernel模板用于把dtype、Tile数量、是否切分等信息放到模板参数中，让编译阶段生成多份专用Kernel。模板参数确定后，Kernel内部可以使用`if constexpr`、模板类型和常量参数组织代码，减少运行时判断。

仍然以AddCustom为例，可以把下面这些差异作为模板参数：

```text
D_T_X:输入x的数据类型
D_T_Y:输入y的数据类型
D_T_Z:输出z的数据类型
TILE_NUM:每个Block内部的Tile数量
IS_SPLIT:是否使用切分路径
```

模板方式适合分支组合较多的场景。例如dtype有2种、`TILE_NUM`有2种、`IS_SPLIT`有2种时，手写数字分支会很快变得难维护。模板参数能把“有哪些组合”和“当前调用选哪个组合”拆开表达。

### 2.1定义模板参数和组合

模板参数和可用组合通常放在Kernel目录下的头文件中，例如：

```text
op_kernel/add_custom_template/tiling_key_add_custom_template.h
```

Kernel模板编程中常用宏可以按用途分为以下几类。各宏的完整参数说明请参考[模板参数定义](../../../../../api/Utils-API/Tiling模板编程/模板参数定义.md)。

| 类型 | 常用宏 | 作用 |
|---|---|---|
| 定义模板参数 | `ASCENDC_TPL_ARGS_DECL`、`ASCENDC_TPL_DATATYPE_DECL`、`ASCENDC_TPL_FORMAT_DECL`、`ASCENDC_TPL_UINT_DECL`、`ASCENDC_TPL_BOOL_DECL` | 声明当前算子有哪些模板参数及其取值范围 |
| 定义模板组合 | `ASCENDC_TPL_SEL`、`ASCENDC_TPL_ARGS_SEL`、`ASCENDC_TPL_DATATYPE_SEL`、`ASCENDC_TPL_FORMAT_SEL`、`ASCENDC_TPL_UINT_SEL`、`ASCENDC_TPL_BOOL_SEL` | 声明当前算子允许生成哪些模板参数组合 |
| 指定TilingData结构体 | `ASCENDC_TPL_TILING_STRUCT_SEL` | 为某组模板参数组合指定`TilingData`结构体 |
| 选择运行分支 | `ASCENDC_TPL_SEL_PARAM`、`GET_TPL_TILING_KEY` | Host侧根据本次输入选择模板参数，并生成对应`TilingKey` |

示例代码如下：

```cpp
#include "ascendc/host_api/tiling/template_argument.h"

ASCENDC_TPL_ARGS_DECL(
    AddCustomTemplate,
    ASCENDC_TPL_DATATYPE_DECL(D_T_X, C_DT_FLOAT16, C_DT_FLOAT),
    ASCENDC_TPL_DATATYPE_DECL(D_T_Y, C_DT_FLOAT16, C_DT_FLOAT),
    ASCENDC_TPL_DATATYPE_DECL(D_T_Z, C_DT_FLOAT16, C_DT_FLOAT),
    ASCENDC_TPL_UINT_DECL(TILE_NUM, ASCENDC_TPL_8_BW, ASCENDC_TPL_UI_LIST, 1, 8),
    ASCENDC_TPL_BOOL_DECL(IS_SPLIT, 0, 1),
);

ASCENDC_TPL_SEL(
    ASCENDC_TPL_ARGS_SEL(
        ASCENDC_TPL_DATATYPE_SEL(D_T_X, C_DT_FLOAT16),
        ASCENDC_TPL_DATATYPE_SEL(D_T_Y, C_DT_FLOAT16),
        ASCENDC_TPL_DATATYPE_SEL(D_T_Z, C_DT_FLOAT16),
        ASCENDC_TPL_UINT_SEL(TILE_NUM, ASCENDC_TPL_UI_LIST, 1, 8),
        ASCENDC_TPL_BOOL_SEL(IS_SPLIT, 0, 1),
    ),
    ASCENDC_TPL_ARGS_SEL(
        ASCENDC_TPL_DATATYPE_SEL(D_T_X, C_DT_FLOAT),
        ASCENDC_TPL_DATATYPE_SEL(D_T_Y, C_DT_FLOAT),
        ASCENDC_TPL_DATATYPE_SEL(D_T_Z, C_DT_FLOAT),
        ASCENDC_TPL_UINT_SEL(TILE_NUM, ASCENDC_TPL_UI_LIST, 1, 8),
        ASCENDC_TPL_BOOL_SEL(IS_SPLIT, 0, 1),
    ),
);
```

其中：

- `ASCENDC_TPL_ARGS_DECL`定义模板参数的名称、类型和取值范围。
- `ASCENDC_TPL_SEL`定义实际允许编译和选择的模板参数组合。
- 第一个参数`AddCustomTemplate`建议和算子`OpType`保持一致，便于工具链关联。

### 2.2Host侧选择模板参数

Host侧Tiling根据本次输入选择具体模板参数，并调用`ASCENDC_TPL_SEL_PARAM`自动生成和设置`TilingKey`：

```cpp
static ge::graphStatus TilingFunc(gert::TilingContext* context)
{
    uint32_t totalLength = context->GetInputShape(0)->GetOriginShape().GetShapeSize();
    ge::DataType dtypeX = context->GetInputDesc(0)->GetDataType();
    ge::DataType dtypeY = context->GetInputDesc(1)->GetDataType();
    ge::DataType dtypeZ = context->GetOutputDesc(0)->GetDataType();

    uint32_t dTypeX = static_cast<uint32_t>(dtypeX);
    uint32_t dTypeY = static_cast<uint32_t>(dtypeY);
    uint32_t dTypeZ = static_cast<uint32_t>(dtypeZ);
    uint32_t tileNum = 1;
    uint32_t isSplit = 0;

    if (totalLength >= 2048) {
        tileNum = 8;
        isSplit = 1;
    }

    TilingDataTemplate* tiling = context->GetTilingData<TilingDataTemplate>();
    tiling->totalLength = totalLength;

    context->SetBlockDim(8);
    ASCENDC_TPL_SEL_PARAM(context, dTypeX, dTypeY, dTypeZ, tileNum, isSplit);

    size_t* workspaceSizes = context->GetWorkspaceSizes(1);
    workspaceSizes[0] = 0;
    return ge::GRAPH_SUCCESS;
}
```

`ASCENDC_TPL_SEL_PARAM`的参数顺序需要和模板参数定义顺序一致。上例中的顺序为`D_T_X`、`D_T_Y`、`D_T_Z`、`TILE_NUM`、`IS_SPLIT`。

### 2.3Kernel侧声明模板入口

Kernel入口函数增加模板参数，模板参数顺序也需要和模板参数定义保持一致：

```cpp
template<typename D_T_X, typename D_T_Y, typename D_T_Z, int TILE_NUM, int IS_SPLIT>
__global__ __aicore__ void add_custom_template(GM_ADDR x, GM_ADDR y, GM_ADDR z,
                                                GM_ADDR workspace, GM_ADDR tiling)
{
    REGISTER_TILING_DEFAULT(TilingDataTemplate);
    GET_TILING_DATA_WITH_STRUCT(TilingDataTemplate, tilingData, tiling);

    KernelAdd<D_T_X, D_T_Y, D_T_Z> op;
    op.Init(x, y, z, tilingData.totalLength, TILE_NUM);

    if constexpr (IS_SPLIT == 0) {
        op.ProcessSmall();
    } else if constexpr (IS_SPLIT == 1) {
        op.ProcessLarge();
    }
}
```

模板参数在编译期确定。`D_T_X`、`D_T_Y`、`D_T_Z`可以直接作为Tensor类型使用，`TILE_NUM`和`IS_SPLIT`可以作为编译期常量参与分支选择。

### 2.4指定模板组合的TilingData结构体

如果不同模板组合需要使用不同`TilingData`结构体，可以在`ASCENDC_TPL_ARGS_SEL`中增加`ASCENDC_TPL_TILING_STRUCT_SEL(...)`：

```cpp
ASCENDC_TPL_ARGS_SEL(
    ASCENDC_TPL_DATATYPE_SEL(D_T_X, C_DT_FLOAT16),
    ASCENDC_TPL_DATATYPE_SEL(D_T_Y, C_DT_FLOAT16),
    ASCENDC_TPL_DATATYPE_SEL(D_T_Z, C_DT_FLOAT16),
    ASCENDC_TPL_UINT_SEL(TILE_NUM, ASCENDC_TPL_UI_LIST, 1),
    ASCENDC_TPL_BOOL_SEL(IS_SPLIT, 0),
    ASCENDC_TPL_TILING_STRUCT_SEL(SmallShapeTilingData),
)
```

该接口只用于为当前模板参数组合指定Tiling结构体，不参与Kernel模板参数传递，也不参与`TilingKey`编码。Kernel侧读取指定结构体时，可以使用`GET_TILING_DATA_WITH_STRUCT`。

### 2.5编译裁剪

调试或只验证部分模板参数组合时，可以通过`--kernel-template-input`只编译指定组合：

```bash
--kernel-template-input="D_T_X=half;D_T_Y=half;D_T_Z=half;TILE_NUM=8;IS_SPLIT=1"
```

模板参数名需要和模板参数定义以及Kernel入口模板参数名保持一致。多个参数之间使用英文分号`;`分隔，同一个参数配置多个值时使用英文逗号`,`分隔。

## 3.如何选择分支方式<a name="如何选择"></a>

写多分支策略时，可以按下面顺序判断。

第一步，判断分支数量。只有少量shape或属性分支时，直接使用`TilingKey`通常更清晰。分支由多个维度组合而成时，优先考虑Kernel模板。

第二步，判断分支差异类型。分支只影响执行哪个`Process`函数时，可以使用`TilingKey`。分支会影响C++类型、模板常量、编译期裁剪时，适合使用Kernel模板。

第三步，判断维护成本。数字`TilingKey`需要开发者维护含义和组合关系；Kernel模板需要先定义模板参数和组合，初始代码更多，后续扩展更规整。

常见选择如下：

- 小shape和大shape两条路径：优先使用`TilingKey`。
- dtype、Tile数量、是否切分共同决定实现：优先使用Kernel模板。
- 需要按dtype生成不同`GlobalTensor`或`LocalTensor`类型：优先使用Kernel模板。
- 只需要在Kernel中选择两个处理函数：优先使用`TilingKey`。
- 分支数量持续增长：把裸数字`TilingKey`收敛为模板参数组合。
