# 多分支策略

当同一个算子需要根据dtype、shape或属性选择不同计算路径时，可以使用TilingKey或Kernel模板组织多个Kernel分支。两种方式都由Host侧根据本次输入选择分支，并让编译工具只为允许的分支生成Kernel实例，避免把所有路径保留为普通运行时分支。

本文重点说明两种方式的职责边界和接入步骤。Host侧TilingData的基本写法见[Host侧Tiling实现](./Host侧Tiling实现/基本流程.md)，Kernel入口和TilingData解析见[Kernel侧算子实现](./Kernel侧算子实现/基本流程.md)。

## 1. 确定分支维度

增加分支前，需要先明确分支条件来自哪里，以及不同分支是否真的需要独立Kernel实现。

| 分支维度 | Host侧判断依据 | 典型差异 |
|---|---|---|
| dtype | `context->GetInputDesc()`、`context->GetOutputDesc()` | 计算类型、搬运粒度、精度策略 |
| shape | `context->GetInputShape()` | 小shape直算、大shape分块、尾块处理 |
| 属性 | `context->GetAttrs()` | 算法模式、维度、开关 |
| format | 输入输出描述 | 数据组织和搬运方式 |

如果不同场景只影响Tile大小、Block数量等运行参数，而Kernel计算流程不变，只需要在TilingData中传递不同参数，不必增加Kernel分支。只有计算流程、数据类型实例或代码体积确实不同，才需要使用TilingKey或Kernel模板。

## 2. 使用TilingKey选择分支

TilingKey使用非负整数标识Kernel分支。Host侧通过`SetTilingKey`选择本次执行的key，Kernel侧通过`TILING_KEY_IS(key)`声明与该key对应的分支。

### 2.1 Host侧设置TilingKey

以下示例由AddCustom多dtype分支样例精简而来。Host侧根据输入dtype设置TilingKey；shape、属性和format分支也采用相同模式，只是判断条件不同。

本示例让`float16`使用key 1、`float`使用key 2，并为两个分支分别获取匹配的TilingData类型：

```cpp
namespace optiling {
constexpr uint32_t NUM_BLOCKS = 8;
constexpr uint32_t FLOAT16_KEY = 1;
constexpr uint32_t FLOAT_KEY = 2;
constexpr uint32_t TILE_NUM = 8;

static ge::graphStatus TilingFunc(gert::TilingContext* context)
{
    uint32_t totalLength = context->GetInputShape(0)->GetOriginShape().GetShapeSize();
    ge::DataType dtype = context->GetInputDesc(0)->GetDataType();

    if (dtype == ge::DT_FLOAT16) {
        context->SetTilingKey(FLOAT16_KEY);
        AddCustomTilingData* tiling =
            context->GetTilingData<AddCustomTilingData>();
        tiling->totalLength = totalLength;
        tiling->tileNum = TILE_NUM;
    } else if (dtype == ge::DT_FLOAT) {
        context->SetTilingKey(FLOAT_KEY);
        AddCustomFloatTilingData* tiling =
            context->GetTilingData<AddCustomFloatTilingData>();
        tiling->totalLength = totalLength;
        tiling->tileNum = TILE_NUM;
    } else {
        return ge::GRAPH_FAILED;
    }

    context->SetBlockDim(NUM_BLOCKS);
    size_t* currentWorkspace = context->GetWorkspaceSizes(1);
    currentWorkspace[0] = 0;
    return ge::GRAPH_SUCCESS;
}
} // namespace optiling
```

TilingKey只是分支标识，不能代替TilingData。`totalLength`、`tileNum`等本次运行需要的数据仍然通过TilingData传递。

### 2.2 Kernel侧声明分支

Kernel入口通过`TILING_KEY_IS`匹配Host侧设置的key：

```cpp
extern "C" __global__ __aicore__ void add_custom(GM_ADDR x, GM_ADDR y, GM_ADDR z,
                                                  GM_ADDR workspace, GM_ADDR tiling)
{
    REGISTER_TILING_DEFAULT(AddCustomTilingData);
    REGISTER_TILING_FOR_TILINGKEY(
        "TILING_KEY_VAR == 2", AddCustomFloatTilingData);

    if (TILING_KEY_IS(1)) {
        GET_TILING_DATA(tilingData, tiling);
        KernelAdd<half> op;
        op.Init(x, y, z, tilingData.totalLength, tilingData.tileNum);
        op.Process();
    } else if (TILING_KEY_IS(2)) {
        GET_TILING_DATA_WITH_STRUCT(
            AddCustomFloatTilingData, tilingData, tiling);
        KernelAdd<float> op;
        op.Init(x, y, z, tilingData.totalLength, tilingData.tileNum);
        op.Process();
    }
}
```

`TILING_KEY_IS`只能用于`if`和`else if`条件。每个支持的key都需要显式写出一个`TILING_KEY_IS(key)`分支，不使用普通`else`承载另一个TilingKey分支。

Host侧必须保证写入的key能命中Kernel侧声明的分支。建议在Host侧为key定义具名常量，并在代码评审时同时检查Host和Kernel两侧的映射关系。

### 2.3 为不同分支使用不同TilingData

多个分支可以共用一个TilingData。只有字段集合确实不同，才需要为特定TilingKey注册单独的结构体。

使用标准C++语法定义TilingData时，Kernel侧先注册默认结构体，再为指定key注册结构体：

```cpp
REGISTER_TILING_DEFAULT(AddCustomTilingData);
REGISTER_TILING_FOR_TILINGKEY("TILING_KEY_VAR == 2", AddCustomFloatTilingData);

if (TILING_KEY_IS(1)) {
    GET_TILING_DATA(tilingData, tiling);
    // 使用AddCustomTilingData
} else if (TILING_KEY_IS(2)) {
    GET_TILING_DATA_WITH_STRUCT(AddCustomFloatTilingData, tilingData, tiling);
    // 使用AddCustomFloatTilingData
}
```

使用`REGISTER_TILING_FOR_TILINGKEY`时必须同时提供`REGISTER_TILING_DEFAULT`。Host侧也需要在对应分支中通过匹配的类型调用`GetTilingData<T>()`，保证两侧结构一致。

### 2.4 只编译指定TilingKey

开发调试时，可以通过`--tiling_key`仅编译指定key，减少重复编译：

```cmake
npu_op_kernel_options(ascendc_kernels AddCustom
    COMPUTE_UNIT Ascend910B
    OPTIONS --tiling_key=1)
```

该选项只影响本次生成的Kernel分支，不改变Host侧分支选择逻辑。发布构建需要覆盖所有可能由Host侧设置的key。编译选项的配置位置见[算子工程编译拓展](../算子工程编译拓展.md)。

## 3. 使用Kernel模板组织分支

TilingKey适合少量、含义稳定的数字分支。分支同时涉及dtype、Tile数量和布尔开关时，可以使用Kernel模板，把分支维度声明为具名模板参数。模板参数组合由头文件统一约束，Host侧通过`ASCENDC_TPL_SEL_PARAM`选择组合，Kernel入口直接接收对应模板参数。

### 3.1 定义模板参数和组合

在`op_kernel`目录新增模板参数头文件，例如`tiling_key_add_custom_template.h`：

```cpp
#ifndef TILING_KEY_ADD_CUSTOM_TEMPLATE_H
#define TILING_KEY_ADD_CUSTOM_TEMPLATE_H
#include "ascendc/host_api/tiling/template_argument.h"

ASCENDC_TPL_ARGS_DECL(
    AddCustomTemplate,
    ASCENDC_TPL_DATATYPE_DECL(D_T_X, C_DT_FLOAT16, C_DT_FLOAT),
    ASCENDC_TPL_DATATYPE_DECL(D_T_Y, C_DT_FLOAT16, C_DT_FLOAT),
    ASCENDC_TPL_DATATYPE_DECL(D_T_Z, C_DT_FLOAT16, C_DT_FLOAT),
    ASCENDC_TPL_UINT_DECL(TILE_NUM, ASCENDC_TPL_8_BW,
                          ASCENDC_TPL_UI_LIST, 1, 8),
    ASCENDC_TPL_BOOL_DECL(IS_SPLIT, 0, 1),
);

ASCENDC_TPL_SEL(
    ASCENDC_TPL_ARGS_SEL(
        ASCENDC_TPL_DATATYPE_SEL(D_T_X, C_DT_FLOAT16),
        ASCENDC_TPL_DATATYPE_SEL(D_T_Y, C_DT_FLOAT16),
        ASCENDC_TPL_DATATYPE_SEL(D_T_Z, C_DT_FLOAT16),
        ASCENDC_TPL_UINT_SEL(TILE_NUM, ASCENDC_TPL_UI_LIST, 1, 8),
        ASCENDC_TPL_BOOL_SEL(IS_SPLIT, 0, 1),
    ),
    ASCENDC_TPL_ARGS_SEL(
        ASCENDC_TPL_DATATYPE_SEL(D_T_X, C_DT_FLOAT),
        ASCENDC_TPL_DATATYPE_SEL(D_T_Y, C_DT_FLOAT),
        ASCENDC_TPL_DATATYPE_SEL(D_T_Z, C_DT_FLOAT),
        ASCENDC_TPL_UINT_SEL(TILE_NUM, ASCENDC_TPL_UI_LIST, 1, 8),
        ASCENDC_TPL_BOOL_SEL(IS_SPLIT, 0, 1),
    ),
);
#endif // TILING_KEY_ADD_CUSTOM_TEMPLATE_H
```

`ASCENDC_TPL_ARGS_DECL`声明参数及允许值，`ASCENDC_TPL_SEL`声明允许生成的参数组合。声明顺序会同时约束Host侧传参顺序和Kernel模板参数顺序，修改时需要三处同步。

### 3.2 Host侧选择模板参数

Host侧从输入描述和shape得到模板参数的具体值，然后按声明顺序传给`ASCENDC_TPL_SEL_PARAM`：

```cpp
#include "tiling_key_add_custom_template.h"

static ge::graphStatus TilingFunc(gert::TilingContext* context)
{
    uint32_t totalLength = context->GetInputShape(0)->GetOriginShape().GetShapeSize();
    uint32_t dtypeX = static_cast<uint32_t>(context->GetInputDesc(0)->GetDataType());
    uint32_t dtypeY = static_cast<uint32_t>(context->GetInputDesc(1)->GetDataType());
    uint32_t dtypeZ = static_cast<uint32_t>(context->GetOutputDesc(0)->GetDataType());
    uint32_t tileNum = totalLength < 2048 ? 1 : 8;
    uint32_t isSplit = totalLength < 2048 ? 0 : 1;

    TilingDataTemplate* tiling = context->GetTilingData<TilingDataTemplate>();
    tiling->totalLength = totalLength;
    context->SetBlockDim(8);
    ASCENDC_TPL_SEL_PARAM(context, dtypeX, dtypeY, dtypeZ, tileNum, isSplit);

    size_t* currentWorkspace = context->GetWorkspaceSizes(1);
    currentWorkspace[0] = 0;
    return ge::GRAPH_SUCCESS;
}
```

传入值必须落在模板参数头文件声明的允许范围内，并且能够命中一个`ASCENDC_TPL_ARGS_SEL`组合。

### 3.3 Kernel侧接收模板参数

Kernel入口的模板参数顺序与声明顺序保持一致：

```cpp
template <typename D_T_X, typename D_T_Y, typename D_T_Z,
          int TILE_NUM, int IS_SPLIT>
__global__ __aicore__ void add_custom_template(
    GM_ADDR x, GM_ADDR y, GM_ADDR z, GM_ADDR workspace, GM_ADDR tiling)
{
    REGISTER_TILING_DEFAULT(TilingDataTemplate);
    GET_TILING_DATA_WITH_STRUCT(TilingDataTemplate, tilingData, tiling);

    KernelAdd<D_T_X, D_T_Y, D_T_Z> op;
    op.Init(x, y, z, tilingData.totalLength, TILE_NUM);
    if constexpr (IS_SPLIT == 0) {
        op.Process1();
    } else if constexpr (IS_SPLIT == 1) {
        op.Process2();
    }
}
```

`TILE_NUM`和`IS_SPLIT`是编译期常量，适合用`if constexpr`组织分支。完整宏定义、编码规则和编译选项见[Tiling模板编程](../Host侧Tiling实现/Tiling模板编程.md)。

完整可编译样例见[AddCustomTemplate](https://gitcode.com/cann/asc-devkit/tree/master/examples/01_simd_cpp_api/02_features/99_acl_based/00_acl_compilation/custom_op)。

## 4. 选择策略

| 场景 | 建议方式 |
|---|---|
| 只有少量算法分支，key含义稳定 | TilingKey |
| 分支同时由dtype、整数参数和布尔参数组成 | Kernel模板 |
| Kernel需要在工程化算子和其他开发方式间复用 | Kernel模板 |
| 只是切分参数不同，Kernel流程相同 | 共用Kernel，仅调整TilingData |

无论选择哪种方式，都需要保持以下一致性：

1. Host侧选择条件覆盖算子原型声明的全部支持场景。
2. Host侧生成的key或模板参数能够命中Kernel侧分支。
3. 每个分支使用的TilingData类型和字段布局在Host、Kernel两侧一致。
4. 发布构建包含运行时可能选择的全部分支。
