# 异步执行
## 什么是异步执行
Ascend C 支持多任务并发执行，具体包括：
- 计算在主机侧
- 计算在设备侧
- 主机侧内存传输到设备侧
- 设备侧内存传输到主机侧
- 单个设备内的内存传输
- 多个设备之间的内存传输

这种并发能力是通过函数调用或核函数下发这些异步执行接口实现的。异步调用通常在被调度的任务完成前就返回，甚至可能在异步任务开始执行前就返回。此时应用程序可以与最初调度的任务同时执行其他工作。当需要获取最初调度任务的最终结果时，应用程序必须执行某种形式的同步操作，以确保目标任务已执行完毕。

并发执行的典型场景是：将主机与设备的内存传输与计算操作重叠执行，从而降低甚至消除内存传输带来的性能开销。
![ ](../../../figures/asynchronous_execution.png "Stream异步并发执行")

通常来说，异步接口主要有三种方式来完成同步操作：
- 阻塞式方式：应用程序调用一个阻塞函数，该函数会挂起线程、持续等待，直至操作执行完成。
- 非阻塞方式（轮询方式）：应用程序调用函数后立即返回，同时获取当前操作的运行状态信息。
- 回调方式：预先注册回调函数，待操作执行完成后，系统自动触发并执行该函数。

虽然编程接口是异步的，但同时执行各种操作的实际能力将取决于Ascend的版本和所用硬件的计算能力——这些细节将留给本指南的稍后部分。

在同步CPU和NPU中，引入了NPU运行时函数aclrtSynchronizeDevice()，这是一个等待所有先前发布的工作完成的阻塞调用。之所以需要aclrtSynchronizeDevice()调用，是因为内核启动是异步的，并且会立即返回。Ascend C为同步的阻塞和非阻塞方法提供了API，甚至支持使用主机端回调函数。用于Ascend C中异步执行的核心API组件是Stream和Event。在本节的其余部分，我们将解释如何使用这些元素来表示Ascend C中的异步执行



##  Stream管理
在最基本的层面上，AscendC 队列（Stream） 是一种抽象，它允许开发者表达一系列昇腾 AI 芯片操作。队列就像一个工作队列，程序可以在其中添加操作，如设备内存拷贝、数据搬运或算子 / 核函数启动，以便按顺序执行。对给定队列执行队列头部的操作，执行完成后移除，允许下一个入队的操作排到头部并进入执行调度。
队列中操作的执行顺序是严格顺序的，操作按照它们入队到队列中的顺序执行。一个应用程序可以同时使用多个队列。在这种情况下，CANN 运行时将根据昇腾 AI 芯片的计算资源、存储资源状态，从存在待执行任务的队列中选择要执行的任务。
队列可以被配置优先级，作为运行时调度任务的参考依据，但无法保证绝对固定的执行顺序。在队列中提交的内存操作 API 调用、核函数 / 算子调用相对于主机侧 CPU 线程是异步的，不会阻塞主机线程继续执行后续逻辑。
应用程序可以通过等待指定队列完成所有任务实现队列级同步，也可以执行设备级同步等待整个昇腾 AI 芯片上所有操作完成。
AscendC 存在默认队列，未显式指定队列的内存操作、核函数 / 算子启动都会自动提交到这个默认队列中。未指定队列的代码示例会隐式使用此默认队列。默认队列具备专属的调度语义，相关规则在 CANN 开发指南的「阻塞与非阻塞队列」「默认队列特性」章节中详细说明。
- Stream的创建与销毁
```c++
aclrtStream stream;         // Stream句柄
aclrtCreateStream(&stream); // 创建Stream
// Stream 的基本操作......
aclrtDestroyStream(stream); // 销毁Stream
```
- 使用Stream执行核函数
```c++
kernel<<<numBlocks, nullptr, stream>>>(...);
```
- 使用Stream拷贝
```c++
aclError aclrtMemcpy(void *dst, size_t destMax, const void *src, size_t count, aclrtMemcpyKind kind)

aclError aclrtMemcpyAsync(void *dst, size_t destMax, const void *src, size_t count, aclrtMemcpyKind kind, aclrtStream stream)
```

- 同步Stream
```c++
aclError aclrtSynchronizeStream(aclrtStream stream)
aclError aclrtStreamQuery(aclrtStream stream, aclrtStreamStatus *status)
```

## Event管理
- Event的创建与销毁
```c++
aclrtEvent event;         // Event句柄
aclrtCreateEvent(&event); // 创建Event
∕∕ do some work involving the event
∕∕ Once the work is done and the event is no longer needed
∕∕ we can destroy the event
aclrtDestroyEvent(event); // 销毁Event
```
- 在Stream插入Event
```c++
aclrtEvent event;
aclrtStream stream;
∕∕ Create the event
aclrtCreateEvent(&event);
∕∕ Insert the event into the stream
aclrtRecordEvent(event, stream);
```
- 统计Stream操作的时间
```c++
aclrtStream stream;
aclrtCreateStream(&stream);
aclrtEvent start;
aclrtEvent stop;
∕∕ create the events
aclrtCreateEvent(&start);
aclrtCreateEvent(&stop);
∕∕ record the start event
aclrtRecordEvent(start, stream);
∕∕ launch the kernel
kernel<<<numBlocks, nullptr, stream>>>(...);
∕∕ record the stop event
aclrtRecordEvent(stop, stream);
∕∕ wait for the stream to complete
∕∕ both events will have been triggered
aclrtSynchronizeStream(stream);
∕∕ get the timing
float elapsedTime;
aclrtEventElapsedTime(&elapsedTime, start, stop);
std::cout << "Kernel execution time: " << elapsedTime << " ms" << std::endl;
∕∕ clean up
aclrtDestroyEvent(start);
aclrtDestroyEvent(stop);
aclrtDestroyStream(stream);
```
- 检查Event状态
```c++
aclrtStream stream;
aclrtCreateStream(&stream);
aclrtEvent event;
∕∕ create the events
aclrtCreateEvent(&event);

∕∕ launch a kernel into the stream
kernel1<<<numBlocks, nullptr, stream>>>(...);

∕∕ record the event
aclrtRecordEvent(event, stream);

∕∕ launch a kernel into the stream
kernel2<<<numBlocks, nullptr, stream>>>(...);

∕∕ Wait for the event to complete
∕∕ Kernel 1 will be guaranteed to have completed
∕∕ and we can launch the dependent task.
aclrtSynchronizeEvent(event);
dependentCPUtask();

∕∕ Wait for the stream to be empty
∕∕ Kernel 2 is guaranteed to have completed
aclrtSynchronizeStream(stream);

∕∕ destroy the event
aclrtDestroyEvent(event);

∕∕ destroy the stream
aclrtDestroyStream(stream);
```

## Callback功能
 在Stream的任务队列中下发一个Host回调任务，系统内部在执行到该回调任务时，会在Stream上注册的线程（该线程在本接口内部创建并注册）中执行回调函数，并且回调任务默认阻塞本Stream上后续任务的执行。异步接口：
 ```c++
 aclError aclrtLaunchHostFunc(aclrtStream stream, aclrtHostFunc fn, void *args)
 ```
 
|参数名  |输入/输出  | 说明 |
|--|--|--|
| stream |输入  | 指定执行回调任务的Stream。类型定义请参见aclrtStream |
| fn |输入  |指定要增加的回调函数。回调函数的函数原型为：`typedef void (*aclrtHostFunc)(void *args)` |
| args |输入  | 待传递给回调函数的用户数据。 |
## 同步执行
核函数的调用是异步的，在核函数调用结束之后，控制权立刻返回给主机端，可以通过以下方式强制Host程序等待核函数执行完毕：
1.  `aclrtSynchronizeDevice()` 阻塞当前线程，直到与当前线程绑定的Context所对应的Device完成运算。
2. `aclrtSynchronizeStream(aclrtStream stream)` 阻塞Host侧当前线程直到指定Stream中的所有任务都完成

## 异步执行错误处理
```c++
//  Some work occurs in streams.
cudaStreamSynchronize(stream);
∕∕ Look at the last error but do not clear it
cudaError_t err = cudaPeekAtLastError();
if (err != cudaSuccess) {
printf("Error with name: %s\n", cudaGetErrorName(err));
printf("Error description: %s\n", cudaGetErrorString(err));
}
∕∕ Look at the last error and clear it
cudaError_t err2 = cudaGetLastError();
if (err2 != cudaSuccess) {
printf("Error with name: %s\n", cudaGetErrorName(err2));
printf("Error description: %s\n", cudaGetErrorString(err2));
}
if (err2 != err) {
printf("As expected, cudaPeekAtLastError() did not clear the error\n");
}
∕∕ Check again
cudaError_t err3 = cudaGetLastError();
if (err3 == cudaSuccess) {
printf("As expected, cudaGetLastError() cleared the error\n");
}
```
