# 异步执行
当开发者完成一个Kernel核函数的编写后，需要通过特定的下发/启动语法将其提交到指定的Stream（计算流）上执行。例如：
```c++
  kernel<<<numBlocks, ubufDynSize, stream>>>(参数列表);
   // 或使用对应的API：aclrtLaunchKernel*(...)
```
这些调用核函数过程都是通过CANN Runtime异步执行完成的。

## 什么是异步执行
CANN Runtime遵循“下发即返回”的异步执行策略，允许主机和设备任务并发，从而将算子编程模型中控制与计算加以解耦，最大化返回硬件能力，其并发能力具体包括：
- 在主机侧计算
- 在设备侧计算
- 主机侧内存传输到设备侧
- 设备侧内存传输到主机侧
- 单个设备内的内存传输
- 多个设备之间的内存传输

所有并发均通过异步函数调用或核函数下发统一接口暴露给开发者。异步调用通常在被调度的任务完成前就返回，甚至可能在异步任务开始执行前就返回。此时应用程序可以与最初调度的任务同时执行其他工作。当需要获取最初调度任务的最终结果时，应用程序必须执行某种形式的同步操作，以确保目标任务已执行完毕。

典型异步执行的场景是：将主机与设备的内存传输与计算操作重叠执行，从而降低甚至消除内存传输带来的性能开销。
![ ](../../figures/asynchronous_execution.png "Stream异步并发执行")

通常来说，异步接口主要有三种方式来完成同步操作：
- 阻塞式方式：应用程序调用一个阻塞函数，该函数会挂起线程、持续等待，直至操作执行完成。
- 非阻塞方式（轮询方式）：应用程序调用函数后立即返回，同时获取当前操作的运行状态信息。
- 回调方式：预先注册回调函数，待操作执行完成后，系统自动触发并执行该函数。

虽然编程接口是异步的，但同时执行各种操作的实际能力将取决于CANN Runtime的版本和所用AI处理器的计算能力。

在同步CPU和NPU中，通过aclrtSynchronizeDevice()等待所有先前下发的核函数执行完成。之所以需要aclrtSynchronizeDevice()调用，是因为内核启动是异步的，并且会立即返回。CANN Runtime 异步执行的核心抽象便是Stream和Event。在本节的其余部分，我们将解释如何使用这些元素来表示CANN Runtime中的异步执行。


##  Stream管理
Stream（计算流）本质上是一个有序的任务队列，为开发开发者 Stream的运行机制类似于任务队列，程序可向队列中提交各类操作，例如内存拷贝、核函数下发等，所有任务将按入队顺序依次执行。单个计算流内，队列头部任务优先执行，执行完成后自动出队；后续队列任务依次前移，等待调度执行。同一个计算流中的任务具备串行执行特性，严格遵循入队先后顺序运行。

应用程序可同时创建并使用多个计算流。多流场景下，运行时会根据AI 处理器的硬件资源占用状态，从存有待处理任务的计算流中择优调度任务执行。开发者可为计算流配置优先级，该优先级将作为运行时调度的参考依据，用以调整任务调度策略，但无法强制保证固定的执行顺序。

绑定在指定计算流内的API接口调用、核函数下发操作，相对于主机CPU线程均为异步执行。
应用程序可通过等待目标计算流清空所有任务完成流级同步，也可在整个设备维度完成全局同步。

CANN Runtime内置默认计算流，所有未显式指定计算流的运算操作、核函数下发任务，都会默认排入该流中执行。绝大多数未手动指定计算流的业务代码，都在隐式使用默认计算流。

- **创建与销毁Stream**： 创建Stream: `aclrtCreateStream(&stream)`；销毁Stream：`aclrtDestroyStream(stream)`
- **指定Stream执行核函数**： `kernel<<<numBlocks, 0, stream>>>(...);`
- **指定Stream拷贝**：  `aclrtMemcpyAsync(..., stream)`
- **指定Stream同步**：阻塞式等待接口：`aclrtSynchronizeStream(stream)`，非阻塞式轮询接口：`aclrtStreamQuery(stream, ...)`
- **同步Stream**：`aclrtSynchronizeStream(stream)`

## Event管理
Event是一种可以在Stream中插入标记的机制。其本质类似追踪粒子，可用来监控Stream内任务执行的进度。举个例子：在同一个流中提交两个核函数。如果没有这类追踪事件，我们仅能判断当前流是否为空。倘若某一操作需要依赖第一个核函数的输出结果，就只能等待整个流执行完毕后才能安全启动该操作，而此时两个核函数都已运行完成。借助 Event便能优化这一问题。在第一个核函数执行完毕后、第二个核函数开始执行前，向Stream中插入一个事件，我们只需等待该事件流转至队列头部。如此一来，便可确认第一个核函数已执行完成，在第二个核函数启动之前，安全执行依赖前者结果的后续操作。通过这种方式使用Event，能够构建出不同操作与计算流之间的依赖关系图。

Event还支持记录时间戳信息，可用于统计核函数执行耗时与内存拷贝传输耗时。

- **创建与销毁Event**：创建Event：`aclrtCreateEvent(&event)`；销毁Event：`aclrtDestroyEvent(event)`
- **在Stream插入Event**：`aclrtRecordEvent(event, stream)`
- **统计Stream操作的时间**：` aclrtEventElapsedTime(&elapsedTime, startEvent, stopEvent)`
- **等待Event执行完成**：`aclrtSynchronizeEvent(event)`

## Host侧回调函数
 CANN Runtime提供了在Stream中从主机端启动函数的机制，即：在Stream的任务队列中下发一个Host回调任务，系统内部在执行到该回调任务时，会在Stream启动线程中执行回调函数，并且回调任务默认阻塞本Stream上后续任务的执行。相关接口如下：
 ```c++
 aclError aclrtLaunchHostFunc(aclrtStream stream, aclrtHostFunc fn, void *args)
 ```
 
|参数名  |输入/输出  | 说明 |
|--|--|--|
| stream |输入  | 指定执行回调任务的Stream。类型定义请参见aclrtStream |
| fn |输入  |指定要增加的回调函数。回调函数的函数原型为：`typedef void (*aclrtHostFunc)(void *args)` |
| args |输入  | 待传递给回调函数的用户数据。 |

## 同步执行
核函数的调用是异步的，在核函数调用结束之后，控制权立刻返回给主机端，可以通过以下接口强制Host程序等待核函数执行完毕：
|同步接口|接口描述|
|-|-|
|`aclrtSynchronizeDevice()` | 阻塞Host侧当前线程，直到与当前线程绑定的Context所对应的Device中的所有操作都已完成|
|`aclrtSynchronizeStream()` |阻塞Host侧当前线程直到指定Stream中的所有操作都已完成 |
|`aclrtStreamWaitEvent()` | 阻塞Host侧当前线程，直到Event之前的所有操作都已完成 |
|`aclrtStreamQuery()`| 可以查询Stream中的操作是否都已完成 |
