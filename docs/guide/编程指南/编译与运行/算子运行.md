# 算子运行<a name="ZH-CN_TOPIC_0000002509833413"></a>
在完成算子编译之后, 需要执行算子，在算子执行中, 有几项关键实践能帮你快速验证正确性并定位问题:

## 始终检查 API 返回值
所有 ACL API 均返回 aclError 枚举状态。生产代码中应检查每一次调用的返回值，通常封装一个通用检查宏：
```c++
#define ASCENDC_CHECK(expr) do {               \
    aclError ret = (expr);                     \
    if (ret != ACL_SUCCESS) {                  \
        fprintf(stderr,                        \
            "Ascend Error: %s:%d code=%d %s\n",\
            __FILE__, __LINE__,                \
            ret, aclrtRecentErrMsg(ret));      \
    }                                          \
} while(0)
```

## 异步执行时API错误检查
核函数启动和大多数 Runtime API 都是异步的。异步错误不会在发生时立即暴露，而是在下一次查询错误状态时被报告。
- 获取并清除错误：调用 aclrtGetLastError 可获取并清空错误状态。
- 等待并检查：用 aclrtSynchronizeDevice/Stream 等待完成后立即检查返回值。

典型模式：
```c++
kernel<<<...>>>(args...);
ASCENDC_CHECK( aclrtGetLastError(ACL_RT_THREAD_LEVEL) ); // 捕获启动阶段错误
ASCENDC_CHECK( aclrtSynchronizeDevice() );               // 等待完成并捕获执行期错误
```
>[!WARNING] 注意
>错误状态被设置后会被后续所有 API 持续返回，直到调用 aclrtGetLastError 清空为止。

更多错误码详细信息可以参考[《Error Code用户手册》]()

## 利用日志定位问题
应用类日志默认落盘在 $HOME/ascend/log，分为 Host 侧与 Device 侧、调试日志 (debug) 与运行日志 (run) 等。常用配置：

- **修改日志路径**：ASCEND_PROCESS_LOG_PATH 或 ASCEND_WORK_PATH。

- **打印到屏幕**：`export ASCEND_SLOG_PRINT_TO_STDOUT=1`。

- **调整全局日志级别（默认 ERROR）**：` export ASCEND_GLOBAL_LOG_LEVEL=1 （0:DEBUG 1:INFO 2:WARNING 3:ERROR）`

- **开启 Event 日志**：`export ASCEND_GLOBAL_EVENT_ENABLE=1`

日志级别越低输出越详细，遇到算子执行异常时可临时设为 DEBUG 获取更多信息

更多详细信息可以参考[《日志参考》]()
