本文档针对AscendC C++类库开发人员，详细介绍类库中三种核心Tensor编程API（静态Tensor、带Layout Tensor、RegTensor）的定义、核心特性、编程流程、代码示例及适用场景，帮助开发人员根据实际需求（开发效率、性能要求、硬件适配）选择合适的编程模式，高效开发昇腾NPU算子及相关应用。

### 1.1 AscendC Tensor编程核心目标：面向Tensor编程

**AscendC Tensor编程的核心目标**是提供面向Tensor的编程抽象，让开发者能够高效地利用AI Core硬件能力。

**为什么面向Tensor编程？**

```
传统编程方式：
  指针 + 偏移量 → 手动计算地址 → 容易出错，难以维护

Tensor编程方式：
  Tensor抽象 → 自动管理数据和索引 → 高效、安全、可维护

核心价值：
  1. 抽象硬件存储层次（GM、UB、L1、L0、Reg）
  2. 管理数据布局（ND、NZ、ZN等格式）
  3. 自动处理索引计算（坐标→偏移）
  4. 简化数据搬运和计算流程
```

**AscendC的Tensor抽象体系**：

```
AscendC Tensor抽象体系
    │
    ├─ MemBase Tensor（存储区抽象）
    │   └─ LocalTensor：管理UB/L1/L0存储区数据
    │       ├─ 原始形态：数据指针 + 大小，偏移量访问
    │       └─ 扩展形态（TensorAPI）：Engine + Layout，坐标访问
    │   └─ GlobalTensor: 管理GM存储区数据
    │       ├─ 原始形态：数据指针 + 大小，偏移量访问
    │       └─ 扩展形态（TensorAPI）：Engine + Layout，坐标访问
    |
    └─ RegBase Tensor（寄存器抽象）
        └─ RegTensor：管理Vector寄存器数据
            └─ 特点：暂存数据，反复计算，性能优化
```

### 1.2 MemBase Tensor：LocalTensor（存储区抽象）

**什么是MemBase？**

MemBase指AI Core的存储区，包括：
- **UB（Unified Buffer）**：256KB，Vector计算存储区
- **L1 Buffer**：1MB，Cube计算数据缓存
- **L0A/L0B/L0C**：64KB/64KB/128KB，Cube计算输入输出

**LocalTensor定位**：

```
LocalTensor = MemBase存储区的数据视图

类比：
  LocalTensor = 仓库管理员
  MemBase存储区 = 仓库（UB、L1、L0）
  数据 = 仓库中的货物

LocalTensor职责：
  1. 指向存储区的一段数据（数据指针 + 地址）
  2. 管理数据的大小和形状
  3. 提供数据搬运接口（GM ↔ UB/L1/L0）
  4. 提供计算接口入口
```

**LocalTensor的两种形态**：

| 形态 | 特征 | 访问方式 | 适用场景 |
|------|------|---------|---------|
| **原始形态** | 数据指针 + 大小 | `tensor(offset)` 偏移量 | 简单算子、快速开发、性能优化 |
| **扩展形态（TensorAPI）** | Engine + Layout | `tensor[coord]` 坐标 | 复杂算子、矩阵计算、格式转换 |

**原始形态详解**：

```
LocalTensor<T>（原始形态）
    │
    │ 定义：template <typename T> class LocalTensor
    │ 成员：数据指针 + 大小（size）
    │ 访问：tensor(offset) 偏移量访问
    │ 特点：简单直接，手动计算偏移量
    │
    │ 底层接口：
    │   • DataCopy：数据搬运（GM ↔ UB/L1）
    │   • Add/Mul：Vector计算
    │   • Mmad：矩阵乘加
    │   • LoadData/Fixpipe：Cube数据流
```

**扩展形态（TensorAPI）详解**：

```
LocalTensor<TensorAttribute<Engine, Layout>>（扩展形态）
    │
    │ 定义：模板特化扩展
    │ 成员：Engine（数据指针封装） + Layout（布局抽象）
    │ 访问：tensor[coord] 坐标访问
    │ 特点：Layout自动计算索引，支持复杂布局
    │
    │ Layout类型：
    │   • ND Layout：行优先，适合GM/UB
    │   • NZ Layout：分块格式，适合L1/L0（Cube优化）
    │   • ZN Layout：列优先分块
    │   • L0C Layout：Cube输出格式
    │
    │ 底层接口（封装）：
    │   • Copy：封装DataCopy，自动格式转换
    │   • Mad：封装Mmad，自动参数配置
```

**两种形态的关系**：

```
原始形态和扩展形态共享同一个LocalTensor模板定义：

template <typename T>
class LocalTensor { /* 数据指针 + 大小 */ };  // 基础模板

template <typename Engine, typename Layout>
class LocalTensor<TensorAttribute<Engine, Layout>> { /* Engine + Layout */ };  // 特化扩展

统一性：
  • 共享模板定义
  • 调用相同底层接口（DataCopy、Add、Mmad等）
  • 映射到相同硬件通路
```

### 1.3 RegBase Tensor：RegTensor（寄存器抽象）

**什么是RegBase？**

RegBase指Vector计算单元内部的寄存器，用于暂存计算数据。

**RegTensor定位**：

```
RegTensor = Vector寄存器的数据抽象

RegTensor职责：
  1. 暂存数据在寄存器中（容量小，速度快）
  2. 支持数据反复计算（减少存储区访问）
  3. 提供高性能计算接口
```

**RegTensor特点**：

| 特性 | 说明 |
|------|------|
| **存储位置** | Vector计算单元寄存器 |
| **容量** | 小（单次迭代128元素/half） |
| **访问速度** | 快（寄存器直接访问） |
| **数据持久性** | 暂存，计算后需搬回UB |
| **主要用途** | 反复计算同一数据，性能优化 |

**RegTensor结构**：

```
RegTensor<T, RegTrait>（寄存器Tensor）
    │
    │ 定义：template <typename T, const RegTrait& regTrait> struct RegTensor
    │ 成员：RegType reg[REG_NUM]（寄存器数组）
    │ 访问：寄存器直接访问
    │ 特点：数据在Reg中可反复使用
    │
    │ 数据搬运接口：
    │   • LoadAlign：UB → Reg（对齐搬运）
    │   • LoadUnAlign：UB → Reg（非对齐搬运）
    │   • StoreAlign：Reg → UB（对齐搬运）
    │   • StoreUnAlign：Reg → UB（非对齐搬运）
    │
    │ 计算接口：
    │   • Add/Sub/Mul/Div：二元运算
    │   • Abs/Relu/Exp/Sqrt：单目运算
    │   • Reduce：归约运算（求和、最大值、最小值）
```

**RegTensor与LocalTensor的关系**：

```
数据流关系：

LocalTensor（UB存储区）
    │
    │ 数据需要从UB搬运到Reg
    │ LoadAlign：UB → Reg
    ▼
RegTensor（Vector寄存器）
    │
    │ 在Reg中反复计算
    │ 数据可多次使用，无需再次从UB读取
    ▼
计算完成后
    │
    │ 数据需要从Reg搬回UB
    │ StoreAlign：Reg → UB
    ▼
LocalTensor（UB存储区）

协同使用：
  • LocalTensor：管理存储区数据（仓库）
  • RegTensor：暂存计算数据（工作台）
  • 搬运接口：仓库 ↔ 工作台数据交换
```

### 1.4 MemBase与RegBase对比

**存储特性对比**：

| 特性 | MemBase（LocalTensor） | RegBase（RegTensor） |
|------|----------------------|---------------------|
| **存储位置** | UB/L1/L0存储区 | Vector寄存器 |
| **容量** | 大（UB 256KB） | 小（128元素） |
| **访问速度** | 中（需要从存储区读取） | 快（寄存器直接访问） |
| **数据持久性** | 持久存储 | 暂存，需搬回存储区 |
| **主要用途** | 数据存储、搬运、持久存储 | 反复计算、性能优化 |

**访问方式对比**：

| 特性 | LocalTensor（原始形态） | LocalTensor（扩展形态） | RegTensor |
|------|----------------------|----------------------|-----------|
| **访问方式** | 偏移量 `tensor(offset)` | 坐标 `tensor[coord]` | 寄存器直接访问 |
| **索引计算** | 手动计算 | Layout自动计算 | 无需计算 |
| **布局支持** | 无Layout | ND/NZ/ZN/L0C | 无Layout |

**适用场景对比**：

| 场景类型 | MemBase（LocalTensor） | RegBase（RegTensor） |
|---------|----------------------|---------------------|
| **数据存储** | ✓ 持久存储 | ✗ 暂存 |
| **数据搬运** | ✓ GM ↔ UB/L1 | ✓ UB ↔ Reg |
| **单次计算** | ✓ 直接计算 | ✓ 需搬运 |
| **反复计算** | ✗ 需反复读取UB | ✓ 数据复用 |
| **归约计算** | ✗ 不支持归约接口 | ✓ 支持Reduce |
| **非对齐地址** | ✗ 需32Byte对齐 | ✓ 支持非对齐搬运 |

### 1.5 价值点总结

**MemBase（LocalTensor）价值点**：

**原始形态价值点**：
1. **简单直观**：直接操作指针和偏移量，符合传统编程习惯
2. **学习成本低**：无需理解Layout抽象，快速上手
3. **精细控制**：参数结构体精确配置硬件行为，适合性能调优
4. **透明度高**：代码直接映射到硬件指令，易于调试和优化

**扩展形态（TensorAPI）价值点**：
1. **抽象层次高**：Layout自动管理索引，减少手动计算错误
2. **层次化布局**：支持ND/NZ/ZN/L0C等复杂分块布局，简化格式转换
3. **类型安全**：模板特化确保Engine和Layout类型匹配
4. **可扩展性**：通过Traits机制灵活配置硬件通路参数
5. **代码简洁**：Copy/Mad接口自动处理格式转换和分块计算

**RegBase（RegTensor）价值点**：
1. **访问速度快**：寄存器直接访问，无需从存储区读取
2. **数据复用**：数据在Reg中可反复使用，减少存储区访问次数
3. **性能优化**：适合反复计算同一数据，提升整体性能
4. **非对齐支持**：支持非对齐地址搬运，处理灵活
5. **归约支持**：支持Reduce归约接口，简化归约计算

### 1.6 应用场景与选择建议

**典型算子开发流程（MemBase + RegBase协同）**：

```
完整算子流程：

1. MemBase阶段：数据搬运到存储区
   └─ GM → UB搬运（LocalTensor管理）
   
2. RegBase阶段：反复计算
   └─ UB → Reg搬运（LoadAlign）
   └─ 在Reg中反复计算（Add → Mul → Relu）
   └─ Reg → UB搬运（StoreAlign）
   
3. MemBase阶段：结果输出
   └─ UB → GM搬运（LocalTensor管理）

优势：
  • MemBase管理持久数据
  • RegBase优化反复计算
  • 两者协同提升性能
```

**选择决策表**：

| 场景 | 推荐方案 | 原因 |
|------|---------|------|
| **简单算子（Element-wise）** | LocalTensor（原始形态） | 简单直接，无抽象层开销 |
| **复杂算子（MatMul、Attention）** | LocalTensor（扩展形态） | Layout自动管理索引和格式 |
| **反复计算同一数据** | RegTensor + LocalTensor | 数据在Reg中复用，减少UB访问 |
| **归约计算（求和、最大值）** | RegTensor | 支持Reduce接口 |
| **非对齐地址处理** | RegTensor | 支持非对齐搬运 |
| **性能极限优化** | LocalTensor（原始形态）+ RegTensor | 精细控制 + 数据复用 |

**学习路径建议**：

```
入门阶段：
  1. 学习LocalTensor（原始形态）
  2. 理解MemBase存储层次（UB、L1、L0）
  3. 掌握数据搬运（DataCopy）

进阶阶段：
  4. 学习LocalTensor（扩展形态）
  5. 理解Layout抽象（ND、NZ、ZN）
  6. 掌握格式转换（Copy接口）

高级阶段：
  7. 学习RegTensor
  8. 理解RegBase寄存器机制
  9. 掌握MemBase + RegBase协同优化
```
