AI Core采用多流水线并行执行架构，不同流水线可能操作相同数据，需要同步保证数据一致性。

### 7.1 为什么需要同步？

**AI Core流水线架构**：

```
AI Core流水线并行执行：
┌─────────────────────────────────────────────────────────────┐
│  PIPE_MTE2：GM → UB/L1搬运流水                                │
│  ├─ 执行：DataCopy、asc_copy_gm2ub                           │
│  ├─ 特点：异步执行，不阻塞其他流水                              │
└─────────────────────────────────────────────────────────────┘
┌─────────────────────────────────────────────────────────────┐
│  PIPE_V：Vector向量计算流水                                   │
│  ├─ 执行：Add、Mul、Exp、Relu等                               │
│  ├─ 特点：异步执行，不阻塞其他流水                              │
└─────────────────────────────────────────────────────────────┘
┌─────────────────────────────────────────────────────────────┐
│  PIPE_MTE3：UB → GM搬运流水                                   │
│  ├─ 执行：DataCopy、asc_copy_ub2gm                           │
│  ├─ 特点：异步执行，不阻塞其他流水                              │
└─────────────────────────────────────────────────────────────┘
┌─────────────────────────────────────────────────────────────┐
│  PIPE_M：Cube矩阵计算流水                                     │
│  ├─ 执行：Mmad、asc_mmad                                      │
│  ├─ 特点：异步执行，不阻塞其他流水                              │
└─────────────────────────────────────────────────────────────┘

流水线并行：
  • 多个流水线同时执行
  • 不同流水线可能操作相同数据
  • 如果不同步，可能导致数据竞争
```

**同步必要性示例**：

```cpp
// 错误示例：未同步，可能导致数据错误
DataCopy(ubData, gmData, params);   // 搬运（PIPE_MTE2流水）
Add(dst, ubData, ubData2, count);   // 计算（PIPE_V流水）
// 问题：Add可能在DataCopy完成前开始计算
//       导致读取未完成搬运的数据（数据错误）

// 正确示例：同步后计算
DataCopy(ubData, gmData, params);   // 搬运（PIPE_MTE2流水）
WaitFlag<HardEvent::MTE2_V>(eventID);  // 同步：等待搬运完成
Add(dst, ubData, ubData2, count);   // 计算（PIPE_V流水） ✓
// 同步确保：Add在DataCopy完成后才开始
```

### 7.2 同步机制类型

AscendC提供多种同步机制，满足不同场景需求：

| 同步类型 | 接口 | 作用 | 适用场景 |
|---------|------|------|---------|
| **流水线同步** | `PipeBarrier<PIPE>` | 单流水内同步 | 同一流水线内操作同步 |
| **事件同步** | `SetFlag/WaitFlag` | 跨流水线同步 | 不同流水线间数据同步 |
| **数据屏障** | `DataSyncBarrier` | 数据同步屏障 | 内存数据一致性保证 |
| **块同步** | `SyncAll` | 多核同步 | 多AI Core核心同步 |
| **Reg屏障** | `LocalMemBar` | Reg内存屏障 | Reg数据搬运同步 |

### 7.3 流水线同步：PipeBarrier

**什么是PipeBarrier？**

PipeBarrier用于同一流水线内的同步，确保流水线内操作按顺序执行。

**接口原型**：
```cpp
template <pipe_t pipe>
__aicore__ inline void PipeBarrier();
```

**流水线类型**：
```cpp
enum pipe_t {
    PIPE_MTE2,   // GM搬运流水
    PIPE_MTE3,   // UB输出流水
    PIPE_V,      // Vector计算流水
    PIPE_M,      // Cube计算流水
    PIPE_S,      // 标量流水
    PIPE_FIX,    // Fixpipe流水
};
```

**使用示例**：
```cpp
// 同步Vector流水线
Add(dst, src0, src1, count);     // Vector计算
PipeBarrier<PIPE_V>();           // 等待Vector计算完成
Mul(dst2, dst, src2, count);     // 下一步计算（确保Add完成）

// 同步GM搬运流水线
DataCopy(ubData0, gmData0, params);  // 搬运0
DataCopy(ubData1, gmData1, params);  // 搬运1
PipeBarrier<PIPE_MTE2>();            // 等待所有搬运完成
// 确保两个DataCopy都完成
```

**适用场景**：
- 同一流水线内多个操作需要顺序执行
- 流水线内数据依赖关系

### 7.4 事件同步：SetFlag/WaitFlag

**什么是事件同步？**

事件同步用于不同流水线之间的同步，通过SetFlag设置事件标志，WaitFlag等待事件完成。

**接口原型**：
```cpp
template <HardEvent event>
__aicore__ inline void SetFlag(int32_t eventID);

template <HardEvent event>
__aicore__ inline void WaitFlag(int32_t eventID);
```

**硬事件类型（HardEvent）**：

```
HardEvent表示两个流水线之间的同步关系：
格式：<源流水>_<目标流水>

常用事件类型：
  MTE2_V    GM搬运 → Vector计算同步
  V_MTE2    Vector计算 → GM搬运同步
  MTE3_V    UB输出 → Vector计算同步
  V_MTE3    Vector计算 → UB输出同步
  M_V       Cube计算 → Vector计算同步
  V_M       Vector计算 → Cube计算同步
  MTE2_M    GM搬运 → Cube计算同步
  M_MTE2    Cube计算 → GM搬运同步
```

**使用示例**：

```cpp
// ========== 场景1：GM搬运 → Vector计算同步 ==========
TPipe pipe;
TEventID eventID = pipe.AllocEventID<HardEvent::MTE2_V>();  // 分配事件ID

DataCopy(ubData, gmData, params);      // 搬运（PIPE_MTE2）
SetFlag<HardEvent::MTE2_V>(eventID);   // 设置事件标志

// 可以执行其他操作（流水线并行）...

WaitFlag<HardEvent::MTE2_V>(eventID);  // 等待搬运完成
Add(dst, ubData, src, count);          // 计算（PIPE_V） ✓

pipe.ReleaseEventID<HardEvent::MTE2_V>(eventID);  // 释放事件ID


// ========== 场景2：Vector计算 → UB输出同步 ==========
TEventID eventID2 = pipe.AllocEventID<HardEvent::V_MTE3>();

Add(dst, src0, src1, count);           // 计算（PIPE_V）
SetFlag<HardEvent::V_MTE3>(eventID2);  // 设置事件标志

// 可以执行其他操作...

WaitFlag<HardEvent::V_MTE3>(eventID2); // 等待计算完成
DataCopy(gmOutput, dst, params);       // 输出（PIPE_MTE3） ✓

pipe.ReleaseEventID<HardEvent::V_MTE3>(eventID2);
```

**事件同步流程图**：

```
时间线：

流水PIPE_MTE2：
  DataCopy → SetFlag → （继续其他操作）
                ↓ 设置事件标志

流水PIPE_V：
  （执行其他操作） → WaitFlag → Add
                      ↑ 等待事件完成

同步点：WaitFlag等待SetFlag设置的标志
        确保DataCopy完成后Add才开始
```

### 7.5 数据屏障：DataSyncBarrier

**什么是数据屏障？**

DataSyncBarrier用于确保内存数据一致性，防止数据竞争。

**接口原型**：
```cpp
template <MemDsbT arg0>
__aicore__ inline void DataSyncBarrier();
```

**使用示例**：
```cpp
// 数据屏障确保数据一致性
DataCopy(ubData, gmData, params);
DataSyncBarrier<MemDsbT::NSET>();  // 数据屏障

// 确保数据已写入UB
Add(dst, ubData, src, count);
```

### 7.6 Reg内存屏障：LocalMemBar

**什么是Reg内存屏障？**

LocalMemBar用于Reg数据搬运之间的同步，确保搬运完成后再进行下一步操作。

**接口原型**：
```cpp
namespace AscendC::Reg {
template <MemType src, MemType dst>
__simd_callee__ inline void LocalMemBar();
}
```

**内存类型**：
```cpp
enum MemType {
    UB,     // UB存储区
    REG,    // 寄存器
    // ...
};
```

**使用示例**：
```cpp
using namespace AscendC::Reg;

// UB → Reg搬运后同步
LoadAlign<half>(regSrc, ubSrc);
LocalMemBar<MemType::UB, MemType::REG>();  // 等待搬运完成

// 在Reg中计算
Add<half>(regDst, regSrc, regSrc, mask);

// Reg → UB搬运前同步
LocalMemBar<MemType::REG, MemType::UB>();  // 等待计算完成
StoreAlign<half>(ubDst, regDst, mask);
```

### 7.7 多核同步：SyncAll

**什么是多核同步？**

SyncAll用于多个AI Core核心之间的同步，确保所有核心完成各自任务后再继续。

**接口原型**：
```cpp
template <bool isAIVOnly = true>
__aicore__ inline void SyncAll();

template <bool isAIVOnly = true>
__aicore__ inline void SyncAll(const GlobalTensor<int32_t>& gmWorkspace, 
                               const LocalTensor<int32_t>& ubWorkspace,
                               const int32_t usedCores = 0);
```

**使用示例**：
```cpp
// 多核同步（简化版）
SyncAll();  // 等待所有核心完成

// 多核同步（带工作区）
GlobalTensor<int32_t> gmWorkspace;
LocalTensor<int32_t> ubWorkspace;
// 初始化工作区...

SyncAll(gmWorkspace, ubWorkspace, usedCores);  // 指定核心数量同步
```

### 7.8 同步机制选择指南

**同步类型选择表**：

| 场景 | 推荐同步方式 | 原因 |
|------|------------|------|
| **GM搬运 → 计算** | `SetFlag<HardEvent::MTE2_V>` + `WaitFlag` | 跨流水线同步，确保数据就绪 |
| **计算 → GM输出** | `SetFlag<HardEvent::V_MTE3>` + `WaitFlag` | 跨流水线同步，确保计算完成 |
| **同流水线内操作** | `PipeBarrier<PIPE>` | 流水线内同步，简单高效 |
| **Reg搬运同步** | `LocalMemBar` | Reg专用屏障，确保搬运完成 |
| **多核心同步** | `SyncAll` | 跨核心同步，确保所有核心完成 |
| **数据一致性保证** | `DataSyncBarrier` | 内存屏障，防止数据竞争 |

**最佳实践**：

```cpp
// ========== 完整算子同步流程 ==========

// 步骤1：GM → UB搬运
TEventID eventID1 = pipe.AllocEventID<HardEvent::MTE2_V>();
DataCopy(ubData, gmData, params);
SetFlag<HardEvent::MTE2_V>(eventID1);  // 设置搬运完成标志

// 步骤2：等待搬运完成
WaitFlag<HardEvent::MTE2_V>(eventID1);  // 等待搬运完成
pipe.ReleaseEventID<HardEvent::MTE2_V>(eventID1);

// 步骤3：Vector计算
TEventID eventID2 = pipe.AllocEventID<HardEvent::V_MTE3>();
Add(dst, ubData, src, count);
SetFlag<HardEvent::V_MTE3>(eventID2);  // 设置计算完成标志

// 步骤4：等待计算完成
WaitFlag<HardEvent::V_MTE3>(eventID2);  // 等待计算完成
pipe.ReleaseEventID<HardEvent::V_MTE3>(eventID2);

// 步骤5：UB → GM输出
DataCopy(gmOutput, dst, params);

// 确保输出完成
PipeBarrier<PIPE_MTE3>();  // 流水线同步
```
