# 内存模型

## 1. 概念体系

本节定义后续讨论中使用的核心概念。

### 1.1 Overlap

Overlap（地址重叠）描述两个内存访问范围在字节地址区间上存在交集。例如，源操作数覆盖`[addr, addr + 128)`，目的操作数覆盖`[addr + 64, addr + 192)`，则两者部分重叠。

地址重叠会影响正确性，因为一次计算或搬运可能在读取源数据之前改写目的区域，导致后续读取到已经被覆盖的数据。Ascend C API对地址重叠有通用约束：

- 对于基础API的Tensor高维切分计算接口，单次迭代内源操作数与目的操作数如果重叠，通常必须100%完全重叠，不支持部分重叠。
- 多次迭代间通常不支持前序迭代的目的操作数与后序迭代的源操作数重叠。
- 具体API如果声明了额外约束，应以具体API说明为准。
- API文档未描述地址重叠约束时，应按“不支持地址重叠”处理。

相关约束见[通用地址重叠约束](../../../../api/SIMD-API/通用说明和约束.md#section668772811100)。

### 1.2 Alias

Alias（别名）描述两个程序对象或两个Tensor视图可能指向同一段物理内存。Alias关注的是“两个名字是否可能访问同一存储对象”，Overlap关注的是“两个具体访问区间是否相交”。

例如，两个`LocalTensor`由同一块UB分配切分而来，或者源Tensor和目的Tensor通过不同接口传入但底层GM地址相同，都可能形成Alias。Alias本身不一定错误，但它会降低编译器和开发者对读写顺序的判断确定性。涉及Alias时需要明确：

- 两个对象是否指向同一内存空间，例如GM、UB、L1或Register。
- 两个对象的有效访问区间是否Overlap。
- 读写是否发生在同一流水、不同流水或不同核之间。
- 是否已经通过同步、Cache控制或API约束建立正确顺序。

在接口允许原地计算时，完全重叠的Alias可能是合法优化；在接口不允许地址重叠时，Alias可能导致结果不满足预期。

### 1.3 内存一致性

内存一致性指当多个处理器、核心或线程并发访问共享内存时，一个线程的读写操作以什么样的顺序被其他线程观察到。关注跨地址访问顺序和可见性。而缓存一致性是关注同一地址或同一 cache line 的值一致性。NPU SIMD编程中最常见的一致性边界包括：

- **片上流水一致性**：MTE写UB后，Vector何时能读取；Vector写UB后，MTE3何时能搬出。该类问题通常通过`PipeBarrier`或`SetFlag/WaitFlag`解决。
- **GM可见性**：UB或L0C中的计算结果只有搬出到GM后，其他核或后续Kernel才可能通过GM读取。
- **DCache与GM一致性**：Scalar写GM可能先写入本核DCache，GM中的值不会立即更新；其他核从GM或自己的DCache读取时，可能读到旧值。
- **多核顺序一致性**：多个核通过GM交换数据时，仅完成写操作本身不等于其他核已经可以安全读取；还需要同步和必要的Cache控制。

在DCache采用延迟写回策略的场景下，如果开发者希望Scalar写入立刻对GM可见，需要使用`DataCacheCleanAndInvalid`等接口把Dirty Cache Line写回GM，并结合核间同步保证读写先后关系。缓存行为可参考[系统缓存概述](../../../../api/SIMD-API/基础API/缓存控制/系统缓存概述.md)。

### 1.4 Cache Line

Cache Line是缓存加载、失效和写回的最小粒度。它不仅影响性能，也影响一致性风险。

Cache Line粒度带来的典型问题是“同一Cache Line内的不同地址并不总是完全独立”。例如，多个核经过DCache写同一条64B Cache Line中的不同字段，如果没有绕过DCache或显式写回/失效，可能出现随机覆盖或读到旧值。多个核同时访问连续512B范围内的GM地址，也可能因为一致性要求被串行处理，影响带宽。相关优化见[避免同地址访问](../../../算子实践参考/SIMD算子性能优化/内存访问/避免同地址访问.md)。

### 1.5 内存对齐

内存对齐描述访问起始地址或数据长度是否满足硬件粒度要求。对齐既影响正确性，也影响性能。

| 存储单元 | 通用对齐要求 |
| --- | --- |
| Global Memory | 通常无强制对齐要求，但满足Cache Line或512B粒度通常更利于带宽。 |
| Unified Buffer | 32B对齐。 |
| L1 Buffer | 32B对齐。 |
| L0A/L0B Buffer | 512B对齐。 |
| L0C Buffer | 64B对齐。 |
| BiasTable Buffer | 64B对齐。 |
| Fixpipe Buffer | 64B对齐。 |



搬运到UB的数据大小需要按照DataBlock对齐；搬运到其他存储单元的数据通常还要满足分形格式要求。若数据长度或地址不满足接口要求，可能需要使用支持非对齐场景的搬运接口或通过Padding补齐。
