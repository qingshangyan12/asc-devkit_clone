# 抽象硬件架构<a name="ZH-CN_TOPIC_0000001861989988"></a>

AI Core是AI处理器的计算核心，AI处理器内部有多个AI Core。本章节介绍AI Core的抽象硬件架构，作为理解[核函数](核函数.md)、语言扩展层C API、C++基础API和TPipe/TQue等编程接口的基础。

通过该抽象，开发者可以先了解AI Core中的计算、存储、搬运和同步关系，再阅读后续接口文档中Global Memory、Local Memory、计算API、数据搬运API和同步控制API等内容。如需了解更详细的硬件架构信息或者原理，请参考[硬件实现](../../高级编程/硬件实现/基本架构.md)。

## AI Core核心组件<a name="section_core_components"></a>

AI Core的抽象硬件架构可以分为**计算单元、存储单元、搬运单元**三类核心组件。计算单元负责执行标量、向量和矩阵计算，存储单元负责保存输入、输出和中间数据，搬运单元负责在不同存储层级之间转移数据。

理解这些组件时，可以同时关注它们在软件接口层的映射关系：计算单元对应计算API，搬运单元对应数据搬运API，存储单元对应GlobalTensor、LocalTensor等数据抽象。

## 编程模型中的三类流程<a name="section_programming_flow"></a>

理解抽象硬件架构时，不仅要知道AI Core包含哪些组件，还要知道这些组件如何协同完成一次数据块处理。可以从**异步指令流、同步信号流、计算数据流**三个视角理解这一过程：

-   **异步指令流**用于理解不同硬件单元如何接收任务并并行执行。Scalar计算单元读取指令序列，并把向量计算、矩阵计算、数据搬运指令发射给Vector、Cube、DMA等单元的指令队列。各单元收到指令后，可在各自流水上异步执行。该过程可以参考[图1](#fig1095152043812)中蓝色箭头所示的指令流。对应到编程层面，计算API、数据搬运API的调用会被映射到不同硬件单元，开发者需要关注任务编排和流水并行。
-   **同步信号流**用于理解异步执行的任务如何保证依赖关系正确。当不同指令队列之间存在数据依赖或顺序依赖时，Scalar计算单元会向相关单元下发同步指令，约束对应任务的执行先后。该过程可以参考[图1](#fig1095152043812)中的绿色箭头所示的同步信号流。对应到编程层面，同步控制API用于表达任务依赖；使用TPipe/TQue等框架时，部分同步关系可由框架自动管理。
-   **计算数据流**用于理解数据如何进入AI Core、参与计算并写回外部存储。DMA搬入单元将数据从Global Memory搬运到Local Memory，Vector/Cube计算单元基于Local Memory中的数据完成计算，并把结果写回Local Memory，DMA搬出单元再将结果搬运回Global Memory。该过程可以参考[图1](#fig1095152043812)中的红色箭头所示的数据流。对应到编程层面，GlobalTensor、LocalTensor等数据抽象对应不同存储层级；算子实现通常围绕CopyIn、Compute、CopyOut组织。

这三类流程描述的是同一次计算的不同侧面：异步指令流决定任务由哪个硬件单元执行，同步信号流决定存在依赖的任务按什么顺序执行，计算数据流决定数据在Global Memory、Local Memory和计算单元之间如何流转。后续接口文档中的API分类，也可以理解为这些硬件职责在软件接口层的映射。

![](../../../figures/抽象硬件架构NPU架构版本3510.png "抽象硬件架构[NPU架构版本3510](../../语言扩展层/SIMD-BuiltIn关键字.md#table65291052154114)")

与NPU架构版本2201的抽象硬件架构相比，NPU架构版本3510的抽象架构在Membase矢量计算的基础上新增了Regbase矢量计算。如[图2](#fig10951520438120)右侧所示，在Membase矢量计算中，所有操作均基于Local Memory（Unified Buffer）进行；在Regbase架构中，中间结果可暂存在寄存器中，节省数据搬出到Local Memory的开销。关于不同AI处理器型号和NPU架构版本的对应关系，请参考[__NPU_ARCH__](../../语言扩展层/SIMD-BuiltIn关键字.md#table65291052154114)。如需了解Regbase矢量计算的具体编程方式，请参考[Reg矢量计算编程](基于Tensor的C++编程/Reg矢量计算编程.md)。
