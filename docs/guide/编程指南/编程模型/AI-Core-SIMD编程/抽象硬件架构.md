# 抽象硬件架构<a name="ZH-CN_TOPIC_0000001861989988"></a>

AI Core是AI处理器的计算核心，一个处理器内部包含多个AI Core。本章节介绍AI Core的并行计算架构抽象，该抽象屏蔽了不同硬件（如达芬奇架构的2002、2201、3510等NPU型号）之间的差异，让你只需理解一套统一的抽象模型即可完成算子开发。想要了解真实硬件与抽象模型的对应关系，可参考[硬件实现](../../硬件实现/基本架构.md)。

AI Core中包含**计算单元、存储单元、搬运单元**三大类核心组件。

### 计算单元

AI Core内部有三个计算单元，分工如下：

| 单元 | 职责 |
|---|---|
| Scalar | 地址计算、循环控制、指令分派 |
| Vector | 向量运算（对一组数据同时执行相同操作） |
| Cube | 矩阵运算（高密度矩阵乘法） |

**Scalar计算单元** — 负责执行地址计算、循环控制等标量计算工作，同时将向量计算、矩阵计算、数据搬运和同步指令**分派**到对应单元的指令队列。Scalar的工作通常是隐式的——地址偏移计算、循环控制都由它完成。一个典型的使用场景是循环分块（Tiling）时的地址生成。

**Vector计算单元** — 负责执行向量运算，对一个数组中的所有元素同时执行相同的操作。逐元素运算（如加减乘除、比较、取最大值等）都由Vector单元完成。

> Tiling: 将大块数据分割成小块（Tile），以便能放入有限的片上内存中进行处理。这是AI Core性能优化的核心技术之一，初次接触时不必深究其全部细节。

**Cube计算单元** — 专门处理矩阵乘法等高密度运算，在涉及深度学习全连接层、卷积等计算时，Cube单元的吞吐量远高于Vector。

这三个计算单元的详细接口说明和完整示例，请参考后续编程接口与示例章节。

### 存储单元

一个核函数在运行过程中，数据在两个存储层级之间流动：

- **Global Memory（全局内存/GM）** — 所有AI Core都能访问的全局存储空间，容量大但访问延迟高。

- **Local Memory（本地内存/LM）** — 每个AI Core私有的片上存储空间，容量有限但访问速度快。其中最主要的部分是Unified Buffer（UB），Vector计算时数据暂存在UB中。

存储单元的详细类型定义和使用方法，请参考后续编程接口章节。

### 搬运单元

**DMA（Direct Memory Access）搬运单元** — 负责在Global Memory和Local Memory之间搬运数据，以及在不同层级的Local Memory之间搬运。DMA搬运数据不需要计算单元参与，可以与计算**异步并行**进行。

搬运单元的数据搬运接口支持不同内存层级间的数据传输，详细说明请参考后续编程接口章节。

### 三条核心数据流

理解上述组件后，你需要重点关注AI Core内部的**三个过程**，它们分别用[图1](#fig1095152043812)中蓝、绿、红三种箭头标注：

1. **异步指令流（蓝色箭头）**：Scalar计算单元读取指令序列，将向量计算、矩阵计算、数据搬运等指令发射到对应单元的**独立指令队列**中。Vector、Cube、DMA三个单元各自维护自己的队列，**异步并行**地执行接收到的指令。这是AI Core高性能的来源——DMA搬运数据的同时，Vector可以继续执行上一批数据的计算。

2. **同步信号流（绿色箭头）**：由于各单元异步执行，指令之间可能存在数据依赖——例如Vector必须等DMA将数据搬运到Local Memory后才能读取。Scalar单元会在依赖点插入**同步指令（Pipe Barrier）**，等待某条流水线上所有已发射的指令执行完毕后，再允许依赖方继续执行。详见本章[内存层级间的同步机制](#内存层级间的同步机制)。

3. **计算数据流（红色箭头）**：数据在AI Core内部的基本处理路径为DMA搬入→Vector/Cube计算→DMA搬出：
   - DMA将数据从Global Memory搬运到Local Memory（UB）
   - Vector/Cube单元从UB读取数据并执行计算，结果写回UB
   - DMA将处理结果从UB搬运回Global Memory

以上三个过程在完整核函数中的具体编排方式，请参考后续编程示例章节。

### 内存层级间的同步机制

在理解同步机制之前，需要先明确一个关键事实：AI Core内部的**搬运单元（DMA）**、**向量计算单元（Vector）**、**矩阵计算单元（Cube）**各自拥有独立的指令队列，由Scalar单元分派指令后**异步并行执行**。这意味着：

- DMA搬运数据到Local Memory的同时，Vector可能在执行上一次的计算
- 如果Vector在DMA尚未完成时就读取目标缓冲区，就会读到脏数据
- 同样，如果DMA在Vector尚未写回结果时就开始搬出，则会搬出旧值

**Pipe Barrier**是用来解决上述数据一致性问题的同步原语，由Scalar计算单元统一管理。其工作机制为：

1. **生产者就绪通知**：当某条流水线（如DMA）完成数据搬运/计算后，Scalar通过信号标记该流水线对应缓冲区的数据已就绪
2. **消费者等待校验**：依赖方（如Vector）在读取数据前，先校验对应信号标记，确认数据已就绪后再开始读取
3. **结果写回通知**：消费者完成计算并写回结果后，同样触发信号标记，通知下游流水线可以继续操作

这套信号标记机制确保了DMA搬运、Vector计算、Cube计算三条流水线之间按正确的顺序访问Local Memory。

三阶段同步的典型流程如下：

1. DMA从Global Memory搬运数据到Local Memory，完成后通过信号标记通知数据就绪
2. Vector校验信号标记后从Local Memory读取数据执行计算，完成后通过信号标记通知结果已写回
3. DMA校验信号标记后将结果从Local Memory搬运回Global Memory

在整个流程中，Scalar单元通过统计每条流水线上已发射的指令数量来决定同步点的释放时机——只有当一条流水线的指令队列全部执行完毕后，对应的同步指令才会被释放，后续依赖该流水线的单元才能继续执行。

> 以上为显式同步控制的主流程编程方式，每个同步点清晰可见，便于开发者精确控制数据流。要查看完整示例，请参考后续编程示例章节。想深入了解Pipe Barrier的硬件实现原理？请参考章节[同步机制说明](../../硬件实现/基本架构.md)。
