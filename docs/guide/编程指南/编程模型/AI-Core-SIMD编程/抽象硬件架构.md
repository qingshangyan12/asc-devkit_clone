# 抽象硬件架构<a name="ZH-CN_TOPIC_0000001861989988"></a>

AI Core是AI处理器的计算核心，AI处理器内部有多个AI Core。本章节将介绍AI Core的并行计算架构抽象，该抽象架构屏蔽了不同硬件之间的差异。使用Ascend C进行编程时，基于抽象硬件架构，可以简化硬件细节，显著降低开发门槛。如需了解更详细的硬件架构信息或者原理，请参考[硬件实现](../../高级编程/硬件实现/基本架构.md)。

## 概览<a name="section_core_components"></a>

AI Core的抽象硬件架构可以分为**计算单元、存储单元、搬运单元**三类核心组件。计算单元负责执行标量、向量和矩阵计算，存储单元负责保存输入、输出和中间数据，搬运单元负责在不同存储层级之间转移数据。下图以NPU架构版本2201为例，展示三类组件在AI Core中的位置关系和协同方式。

结合前述三类组件和[图1](#fig1095152043812)，Host侧下发的算子指令序列进入AI Core后，由Scalar计算单元负责控制逻辑和指令发射；Vector、Cube等计算单元分别执行矢量计算和矩阵计算，DMA搬运单元执行数据搬运。计算数据通常在Global Memory和Local Memory之间流转；当计算和搬运存在依赖时，需要通过同步信号约束不同单元的执行顺序。

![](../../../figures/抽象硬件架构NPU架构版本3510.png "抽象硬件架构[NPU架构版本3510](../../语言扩展层/SIMD-BuiltIn关键字.md#table65291052154114)")

与NPU架构版本2201相比，NPU架构版本3510的主要差异如下：

-   数据搬运能力有所调整，部分存储之间的数据流转路径与NPU架构版本2201不同。
-   新增Regbase矢量计算方式，支持直接使用寄存器参与计算。
-   计算和存储能力有所扩展，部分数据类型支持范围和片上存储结构发生变化。
-   编程方式更加丰富，除SIMD编程外，还支持SIMT编程以及SIMD与SIMT混合编程。

## 存储单元和搬运单元<a name="section_memory_units"></a>

AI Core计算过程中既需要访问外部输入输出数据，也需要保存计算过程中的临时数据。因此，存储单元可以从使用位置上分为Local Memory和Global Memory。

-   **Local Memory**：AI Core内部存储的统称，用于缓存计算输入、输出和中间结果，减少对Global Memory的频繁访问。常用存储单元包括Unified Buffer、L1 Buffer、L0A Buffer、L0B Buffer、L0C Buffer等，编程接口中通常通过LocalTensor等对象使用。
-   **Global Memory**：Device侧全局存储，用于保存核函数输入、输出、workspace等数据，是Local Memory中数据搬入和搬出的主要来源或目的位置，编程接口中通常通过GlobalTensor或`__gm__`指针使用。

**DMA（Direct Memory Access）搬运单元**负责数据搬运，包括Global Memory和Local Memory之间的数据搬运，以及不同层级Local Memory之间的数据搬运。常见搬运单元包括MTE1、MTE2、MTE3和FixPipe，具体介绍请参考[搬运单元](../../高级编程/硬件实现/基本架构.md#table288493152012)。

## 执行流程与同步机制<a name="section_programming_flow"></a>

理解抽象硬件架构时，还需要关注不同单元如何协同完成一次数据块处理。可以从**异步指令流、同步信号流、计算数据流**三个视角理解：

-   **异步指令流**：Scalar计算单元读取指令序列，并将计算、搬运等任务发射到对应单元的指令队列中，各单元可在各自流水上异步执行。该过程可以参考[图1](#fig1095152043812)中蓝色箭头所示的指令流。
-   **计算数据流**：数据通常先从Global Memory搬入Local Memory，再由Vector/Cube等计算单元完成计算，最后将结果写回Global Memory。该过程可以参考[图1](#fig1095152043812)中的红色箭头所示的数据流。
-   **同步信号流**：由于计算和搬运可以异步执行，当不同任务之间存在数据依赖或顺序依赖时，需要通过同步信号约束执行先后。该过程可以参考[图1](#fig1095152043812)中的绿色箭头所示的同步信号流。

因此，开发者不仅要关注数据如何搬入、计算和搬出，还需要理解同步机制如何保证异步任务按正确的依赖关系执行。后续介绍同步控制相关接口时，将进一步说明这类依赖关系在编程中的表达方式。
