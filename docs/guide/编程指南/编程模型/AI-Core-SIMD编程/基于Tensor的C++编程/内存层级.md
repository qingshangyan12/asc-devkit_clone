## 引言
Ascend C基于Tensor进行编程，将物理内存地址抽象为Tensor对象。Tensor携带数据类型、形状信息、内存位置等属性，开发者通过Tensor进行数据搬运、计算操作，接口调用时自动推断操作参数。
本章旨在帮助开发者建立对Ascend C内存管理体系的系统化认知，理解物理存储层级到Tensor抽象再到接口定义的递进关系。全文遵循「物理层级—Tensor抽象层级—接口定义方式」的逻辑展开。

## 物理层级：三级存储架构
AI Core采用三级存储架构，各层级分工明确、协同联动。Ascend 950PR/Ascend 950DT架构进一步开放寄存器层可编程能力，形成「Global Memory → Local Memory → Register」的三级内存层级。

### 三级存储层级
**表 1**  AI Core三级存储架构
| 存储层级 | 存储类型 | 名称 | 用途 | 特点 |
|----------|----------|------|------|------|
| **全局内存** | Global Memory | GM | 存放算子输入/输出数据 | 大容量、低带宽、高延迟 |
| **片上存储** | Local Memory | UB | Vector输入/输出 | 中等容量、中等带宽 |
| | | L1 | Cube数据中转 | Cube计算中转站 |
| | | L0A/L0B | Cube矩阵输入 | Cube专用缓冲区 |
| | | L0C | Cube矩阵输出 | Cube结果缓冲区 |
| **寄存器** | Register | Reg | Vector计算寄存器 | 小容量、极高带宽、极低延迟 |

> 📌 **提示**：寄存器层从**Ascend 950PR/Ascend 950DT**开始支持，提供寄存器级精细控制与极致性能场景。

### 数据流转路径
Vector算子基于三级存储架构支持两种数据流转模式：
**Memory模式（通用模式）**：全程基于UB完成数据缓存与计算。数据流为Global Memory→UB→Global Memory，矢量计算在UB上执行，适用于通用场景，开发门槛低、适配性强。
**Reg模式（高性能模式）** ：利用寄存器低延迟、高带宽优势提升性能。数据流为Global Memory→UB→寄存器→UB→Global Memory，矢量计算在寄存器上执行，适用于性能敏感场景，需要开发者精细管理寄存器生命周期。

### 各存储层级分工
**Vector算子数据流**：`GM → UB → Vector计算 → UB → GM`
- UB是Vector计算单元的主缓冲区，承载输入、输出、中间数据
- Reg是Vector计算单元的寄存器，直接参与计算（Ascend 950PR/Ascend 950DT）

**Cube算子数据流**：`GM → L1 → L0A/L0B → Cube计算 → L0C → GM`
- L1是Cube数据中转站，暂存待计算矩阵。位于Cube单元内部，承接来自Global Memory的矩阵数据，作为L0A/L0B的上游数据源。L1缓冲区容量较大，可同时暂存多块矩阵数据，避免频繁访问Global Memory带来的带宽瓶颈，提升Cube计算效率。
- L0A/L0B是Cube左/右矩阵输入缓冲区。分别存储矩阵乘法运算的左矩阵（A矩阵）和右矩阵（B矩阵），直接为Cube计算单元提供输入数据。L0A/L0B容量较小，采用分块加载策略，每次从L1搬运固定大小的矩阵块到L0A/L0B，完成一轮计算后再加载下一块，实现流水式矩阵乘法。
- L0C是Cube结果输出缓冲区。存储矩阵乘法的计算结果，作为Cube单元的输出缓存。L0C中的结果数据可选择两种流向：一是搬运到Global Memory供后续使用，二是搬运到UB参与Vector单元的后续计算（如激活函数、归一化等）。L0C的设计实现了Cube与Vector单元的数据衔接。

## Tensor抽象层级：物理存储到编程抽象
Ascend C将物理存储层级抽象为Tensor对象，每个Tensor对应特定物理存储位置，携带数据类型、形状等属性。

### Tensor抽象层级
**表 2**  Tensor抽象与物理存储对应关系
| Tensor类型 | 对应物理存储 | 位置标识 | 主要用途 |
|-----------|-------------|---------|---------|
| **GlobalTensor** | Global Memory | GM | 全局输入/输出数据 |
| **LocalTensor** | Local Memory | UB/L1/L0A/L0B/L0C | 片上存储数据 |
| **RegTensor** | Register | Reg | 寄存器数据（Ascend 950PR/Ascend 950DT） |

### GlobalTensor抽象
GlobalTensor对应全局内存（GM），抽象GM地址为Tensor对象，携带数据类型、形状信息、L2缓存配置等属性。
```cpp
// GlobalTensor抽象示例
GlobalTensor<half> gmTensor;
gmTensor.SetGlobalBuffer((__gm__ half*)gmBuffer, bufferSize);
gmTensor.SetL2CacheHint(CacheMode::READ_ONLY);  // 配置L2缓存
```

### LocalTensor抽象
LocalTensor对应片上存储（UB、L1、L0A、L0B、L0C），抽象片上内存地址为Tensor对象，携带数据类型、大小信息、内存位置等属性。
```cpp
// LocalTensor抽象示例（基础能力）
AscendC::LocalMemAllocator<AscendC::Hardware::UB> ubAllocator;
AscendC::LocalTensor<half> ubTensor = ubAllocator.Alloc<half, 256>();
// LocalTensor抽象示例（扩展能力）
auto ubTensor = MakeTensor(ubPointer, MakeShape(128, 64));
```

### RegTensor抽象
> 📌 **提示**：RegTensor从**Ascend 950PR/Ascend 950DT**开始支持。
RegTensor对应寄存器（Reg），抽象寄存器为Tensor对象，提供对Vector计算单元内部寄存器的直接操作能力。Vector计算单元只能访问寄存器，无法直接读写UB数据，因此需要先将UB数据加载到寄存器，计算完成后再将结果写回UB。
**RegTensor类型抽象**：
| RegTensor类型 | 对应寄存器 | C++类型定义 | 主要用途 |
|--------------|-----------|------------|---------|
| **MaskReg** | 掩码寄存器 | vector_bool | 控制参与计算的元素 |
| **AddrReg** | 地址寄存器 | vector_address | 存储地址偏移量 |
| **RegTensor\<T\>** | 矢量数据寄存器 | RegTensor\<half\>、RegTensor\<float\>等 | 存储计算数据 |

```cpp
// RegTensor抽象示例
using namespace AscendC::Reg;
MaskReg mask;               // 掩码寄存器抽象
RegTensor<half> srcReg;     // half数据寄存器抽象
RegTensor<float> dstReg;    // float数据寄存器抽象
AddrReg ubAddr;             // 地址寄存器抽象
```

## 接口定义方式：Tensor创建与初始化
Ascend C提供多套接口定义Tensor，覆盖基础能力、扩展能力、RegTensor三个层次。

### GlobalTensor定义方式
GlobalTensor对应GM，通过SetGlobalBuffer设置地址，通过传入bufferSize设置Tensor的大小，SetL2CacheHint配置L2缓存。
```cpp
// GlobalTensor定义
GlobalTensor<half> gmTensor;
gmTensor.SetGlobalBuffer((__gm__ half*)gmBuffer, bufferSize);
// 配置L2缓存模式
gmTensor.SetL2CacheHint(CacheMode::READ_ONLY);   // 只读模式
gmTensor.SetL2CacheHint(CacheMode::READ_WRITE);  //读写模式
```

### LocalTensor定义方式
#### 基础能力接口
基础能力接口通过LocalMemAllocator分配或构造函数指定地址，buffer大小信息运行期设置。
**方式1：LocalMemAllocator分配**
```cpp
constexpr uint32_t TILE_LENGTH = 256;  // 示意性参数
AscendC::LocalMemAllocator<AscendC::Hardware::UB> ubAllocator;
AscendC::LocalTensor<half> ubTensor = ubAllocator.Alloc<half, TILE_LENGTH>();
```

#### 扩展能力接口（Tensor API）
扩展能力接口通过内存修饰符定义数组申请内存，再通过MakeMemPtr创建内存指针、MakeTensor创建Tensor对象，引入Layout概念实现编译期类型安全。
**方式1：数组定义 + 最简化Tensor定义**
通过内存修饰符`__ubuf__`/`__gm__`等定义数组申请内存，Shape自动推导Stride：
```cpp
__ubuf__ half ubBuffer[256];                                   // 申请UB内存
auto ubPtr = MakeMemPtr<Location::UB>(ubBuffer);                // 创建内存指针
auto ubTensor = MakeTensor(ubPtr, MakeShape(128, 64));          // 创建Tensor
```

**方式2：数组定义 + 带Stride的Tensor定义**
自定义Stride实现特定内存排列（如行主序、列主序）：
```cpp
__ubuf__ half ubBuffer[256];
auto shape = MakeShape(128, 64);
auto stride = MakeStride(64, 1);                                // 行主序：每行64个元素，元素间步长1
auto ubTensor = MakeTensor(MakeMemPtr<Location::UB>(ubBuffer), MakeLayout(shape, stride));
```

**方式3：数组定义 + 分形布局Tensor定义**
用于Cube矩阵乘场景，通过MakeFrameLayout自动生成分形布局：
```cpp
__cb__ float l0aBuffer[1024];                                  // 申请L0A内存
auto nzLayout = MakeFrameLayout<NZLayoutPtn>(128, 32);         // NZ分形布局
auto l0aTensor = MakeTensor(MakeMemPtr<Location::L0A>(l0aBuffer), nzLayout);
```

**适用场景**：
- 编译期类型安全，Shape/Stride编译期确定，减少运行期开销
- 复杂内存布局管理，如自定义Stride实现非连续数据排列
- Cube矩阵乘场景，自动生成分形布局（NZ、ZN等）简化配置
- 多存储层级协同场景，通过Location模板参数明确指定存储位置

### RegTensor定义方式
> 📌 **提示**：RegTensor从**Ascend 950PR/Ascend 950DT**开始支持。
RegTensor定义寄存器类型的变量，支持掩码寄存器、地址寄存器、数据寄存器三类。
**直接定义寄存器变量**
```cpp
using namespace AscendC::Reg;
// 直接定义寄存器变量
MaskReg mask;                   // 掩码寄存器
RegTensor<half> srcReg0;        // half数据寄存器
RegTensor<half> srcReg1;        // half数据寄存器
RegTensor<half> dstReg;         // half数据寄存器
// ===== Load：UB→寄存器 =====
AddrReg ubAddr0 = ubIn0.GetAddress();
AddrReg ubAddr1 = ubIn1.GetAddress();
LoadAlign(srcReg0, ubAddr0);  // 加载UB数据到寄存器
LoadAlign(srcReg1, ubAddr1);
// ===== Compute：寄存器计算 =====
Add(dstReg, srcReg0, srcReg1, mask);  // 寄存器加法
// ===== Store：寄存器→UB =====
AddrReg ubDstAddr = ubOut.GetAddress();
StoreAlign(ubDstAddr, dstReg, mask);  // 结果写回UB
```

**适用场景**：
- 极致性能场景，利用寄存器极低延迟、极高带宽特性
- 多次重复计算场景，数据驻留寄存器避免频繁UB访问
- 精细控制场景，通过MaskReg控制参与计算的元素

## 小结
本章系统阐述了Ascend C内存管理体系的递进逻辑：
- **物理层级**：AI Core采用三级存储架构（Global Memory → Local Memory → Register），Ascend 950PR/Ascend 950DT开放寄存器层可编程能力，形成Memory模式和Reg模式两种数据流转路径
- **Tensor抽象层级**：将物理存储抽象为GlobalTensor（对应GM）、LocalTensor（对应片上存储）、RegTensor（对应寄存器），每个Tensor携带数据类型、形状、位置等属性
- **接口定义方式**：基础能力接口通过LocalMemAllocator分配或构造函数指定地址；扩展能力接口通过MakeTensor工厂函数创建，引入Layout概念实现类型安全；RegTensor定义掩码寄存器、地址寄存器、数据寄存器三类变量
后续章节将详细展开数据搬运与计算接口、同步机制、编程示例，帮助开发者熟练掌握Ascend C的核心操作能力。
