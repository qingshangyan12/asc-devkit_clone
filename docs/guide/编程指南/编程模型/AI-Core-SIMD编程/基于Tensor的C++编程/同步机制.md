## 引言
同步机制是Ascend C算子开发的关键技术，AI Core采用多条流水线异步并行架构，不同流水线之间独立执行，存在数据依赖关系时需要通过同步机制协调执行顺序，避免数据读写冲突，确保算子正确执行。
本章旨在帮助开发者建立对Ascend C同步机制的系统化认知，理解流水线同步的原理、接口分类、使用场景。全文遵循「同步原理—同步接口—同步场景」的递进逻辑展开，完整覆盖同步机制全链路核心内容：阐述多条流水线异步执行的硬件原理、拆解同步接口的分类与功能定位、并逐层讲解典型场景的同步模式。

## 同步原理：多条流水线异步执行架构
AI Core内部包含多条流水线，各流水线独立异步执行，通过同步机制协调数据依赖关系，确保正确执行顺序。

### AI Core流水线架构
**表 1**  AI Core流水线类型
| 流水线类型 | 编号 | 功能描述 | 操作示例 |
|------------|------|----------|----------|
| **PIPE_S** | Scalar流水线 | 标量计算、控制流 | SetValue、条件判断 |
| **PIPE_V** | Vector流水线 | 向量计算 | Add、Sub、Mul、Div |
| **PIPE_MTE2** | MTE2流水线 | Global Memory → Local Memory搬运 | DataCopy（GM→UB） |
| **PIPE_MTE3** | MTE3流水线 | Local Memory → Global Memory搬运 | DataCopy（UB→GM） |
| **PIPE_MTE1** | MTE1流水线 | Local Memory内部搬运（L1→L0A/L0B） | LoadData、Copy（L1→L0A） |
| **PIPE_C** | Cube流水线 | 矩阵乘计算 | Mmad |

> 📌 **提示**：流水线类型编号用于标识同步事件的流向，如MTE2→V表示从MTE2流水线到Vector流水线的同步。

### 流水线异步执行与数据依赖
多条流水线异步并行执行带来性能优势，但也引入数据依赖问题：
**数据依赖场景**：
- **搬运→计算依赖**：DataCopy（GM→UB）完成后，Add才能执行，否则读取未就绪数据
- **计算→搬运依赖**：Add完成后，DataCopy（UB→GM）才能执行，否则输出不完整数据
- **计算→计算依赖**：Add输出是Mul输入，Add完成后Mul才能执行

**解决方案**：通过同步机制协调流水线执行顺序，确保数据依赖关系正确处理。

## 同步接口：分类与功能定位
Ascend C同步接口按同步范围分为流水线同步（核内同步）和核间同步（跨核协作）两大类。

### 同步接口分类
**表 2**  同步接口分类
| 同步类型 | 接口 | 功能描述 | 同步范围 | 使用场景 |
|----------|------|----------|----------|----------|
| **流水线同步** | SetFlag/WaitFlag | 流水线间同步事件 | 核内 | 数据搬运→计算、计算→搬运 |
| **流水线同步** | PipeBarrier | 流水线内同步阻塞 | 核内 | 计算→计算（相同流水线） |
| **流水线同步** | SyncAll | 全流水线同步 | 核内 | 全核同步点 |
| **核间同步** | CrossCoreSetFlag/CrossCoreWaitFlag | 跨核同步事件 | 核间 | 多核协作算子 |

### SetFlag/WaitFlag接口
SetFlag/WaitFlag实现同一核内不同流水线之间的同步，具有数据依赖的不同流水线指令之间需要插入此同步。
**表 3**  SetFlag/WaitFlag接口参数说明
| 参数名 | 类型 | 描述 | 必选 |
|--------|------|------|------|
| **id** | TEventID (int8_t) | 事件ID，用户指定或通过AllocEventID获取 | 是 |

**函数原型**：
```cpp
template <PipeType pipe1, PipeType pipe2>
__aicore__ inline void SetFlag(TEventID id)
template <PipeType pipe1, PipeType pipe2>
__aicore__ inline void WaitFlag(TEventID id)
```
**工作原理**：
- **SetFlag**：前序指令的所有读写操作完成后，当前指令开始执行，并将硬件中的对应标志位设置为1
- **WaitFlag**：执行到该指令时，如果对应标志位为0，后续指令阻塞等待；标志位为1时，清零标志位并继续执行

> 📌 **提示**：SetFlag/WaitFlag必须成对出现，使用相同的eventID。eventID范围：Atlas A2/A3系列为0-7。

**常用同步类型**：
**表 4**  常用同步类型
| 同步类型 | 描述 | 使用场景 |
|----------|------|----------|
| **HardEvent::MTE2_V** | MTE2 → Vector同步 | DataCopy（GM→UB）完成后执行Add |
| **HardEvent::V_MTE3** | Vector → MTE3同步 | Add完成后执行DataCopy（UB→GM） |
| **HardEvent::MTE2_MTE1** | MTE2 → MTE1同步 | DataCopy（GM→L1）完成后执行LoadData |
| **HardEvent::MTE1_C** | MTE1 → Cube同步 | LoadData完成后执行Mmad |
| **HardEvent::C_MTE3** | Cube → MTE3同步 | Mmad完成后执行DataCopy（L0C→GM） |

**使用示例**：
```cpp
// ===== Vector算子同步流程 =====
constexpr TEventID eventID = 0;
// 1. 数据搬入：GM→UB
DataCopy(ubBuffer, gmInput, size);
// 2. 同步：等待MTE2完成
SetFlag<HardEvent::MTE2_V>(eventID);
WaitFlag<HardEvent::MTE2_V>(eventID);
// 3. 计算：Add
Add(ubOut, ubIn0, ubIn1, size);
// 4. 同步：等待Vector完成
SetFlag<HardEvent::V_MTE3>(eventID);
WaitFlag<HardEvent::V_MTE3>(eventID);
// 5. 数据搬出：UB→GM
DataCopy(gmOutput, ubOut, size);
```

### PipeBarrier接口
PipeBarrier实现流水线内部的同步阻塞，具有数据依赖的相同流水线指令之间需要插入此同步。
**表 5**  PipeBarrier接口参数说明
| 参数名 | 类型 | 描述 | 必选 |
|--------|------|------|------|
| **pipe** | pipe_t（模板参数） | 阻塞的流水类别，支持PIPE_V、PIPE_MTE2、PIPE_MTE3、PIPE_MTE1、PIPE_C等 | 是 |

**函数原型**：
```cpp
template <pipe_t pipe>
__aicore__ inline void PipeBarrier()
```
**使用场景**：相同流水线内，前序指令输出是后续指令输入时，需要插入PipeBarrier。
**使用示例**：
```cpp
// ===== Vector流水线内同步 =====
LocalTensor<half> src0, src1, src2, dst0, dst1;
// Add输出是Mul输入，需要PipeBarrier同步
Add(dst0, src0, src1, 512);          // Vector计算
PipeBarrier<PIPE_V>();               // Vector流水线内同步
Mul(dst1, dst0, src2, 512);          // Vector计算（依赖Add输出）
```

> 📌 **提示**：开启自动同步（Kernel直调算子工程和自定义算子开发工程已默认开启）时，编译器自动插入PIPE_V同步，无需开发者手动调用PipeBarrier<PIPE_V>()。Scalar流水线同步由硬件自动保证，调用PipeBarrier<PIPE_S>()会引发硬件错误。

### TPipe同步管理接口
TPipe提供同步事件ID管理接口，用于申请和释放eventID。
**表 6**  TPipe同步管理接口
| 接口 | 功能描述 | 参数 |
|------|----------|------|
| **AllocEventID** | 申请事件ID | 无参数，返回可用eventID |
| **ReleaseEventID** | 释放事件ID | eventID：待释放的事件ID |
| **FetchEventID** | 获取指定事件ID | eventID：指定的事件ID（0-7） |

**使用示例**：
```cpp
TPipe pipe;
TEventID eventID = pipe.AllocEventID();  // 申请事件ID
SetFlag<HardEvent::MTE2_V>(eventID);
WaitFlag<HardEvent::MTE2_V>(eventID);
pipe.ReleaseEventID(eventID);  // 释放事件ID
```

### 核间同步接口
核间同步接口用于多核协作场景，实现跨核的同步协调。
**表 7**  核间同步接口
| 接口 | 功能描述 | 同步范围 | 使用场景 |
|------|----------|----------|----------|
| **CrossCoreSetFlag** | 设置跨核同步标志 | 核间 | 多核协作同步点设置 |
| **CrossCoreWaitFlag** | 等待跨核同步标志 | 核间 | 多核协作同步点等待 |

> 📌 **提示**：核间同步接口适用于多核协作算子（如大矩阵分块计算），单核算子无需使用核间同步。

## 同步场景：典型模式与实践
根据算子类型和数据流特点，同步机制分为Vector算子同步模式、Cube算子同步模式、Double Buffer同步模式三种典型场景。

### Vector算子同步模式
Vector算子遵循「搬运→同步→计算→同步→搬运」同步模式，需要在数据搬运和计算之间插入同步。
**表 8**  Vector算子同步流程
| 步骤 | 操作 | 同步类型 | 同步时机 |
|------|------|----------|----------|
| **1** | DataCopy（GM→UB） | 无 | 数据搬入开始 |
| **2** | SetFlag/WaitFlag（MTE2_V） | 流水线间同步 | 确保数据就绪 |
| **3** | Add/Sub/Mul | 无 | 计算执行 |
| **4** | SetFlag/WaitFlag（V_MTE3） | 流水线间同步 | 确保计算完成 |
| **5** | DataCopy（UB→GM） | 无 | 数据搬出开始 |

**完整示例**：
```cpp
extern "C" __global__ __aicore__ void add_kernel(
    __gm__ half* gmIn0, __gm__ half* gmIn1, __gm__ half* gmOut,
    const uint32_t totalLength) {
    TPipe pipe;
    TQue<UB, 1> queIn, queOut;
    pipe.InitBuffer(queIn, 1, TILE_LENGTH * sizeof(half));
    pipe.InitBuffer(queOut, 1, TILE_LENGTH * sizeof(half));
    GlobalTensor<half> gmTensorIn0, gmTensorIn1, gmTensorOut;
    gmTensorIn0.SetGlobalBuffer(gmIn0, totalLength);
    gmTensorIn1.SetGlobalBuffer(gmIn1, totalLength);
    gmTensorOut.SetGlobalBuffer(gmOut, totalLength);
    constexpr TEventID eventID = 0;
    while (offset < totalLength) {
        LocalTensor<half> ubIn0 = queIn.AllocTensor<half>();
        LocalTensor<half> ubIn1 = queIn.AllocTensor<half>();
        LocalTensor<half> ubOut = queOut.AllocTensor<half>();
        // ===== 数据搬入 =====
        DataCopy(ubIn0, gmTensorIn0[offset], curLength);
        DataCopy(ubIn1, gmTensorIn1[offset], curLength);
        // ===== 同步：MTE2_V =====
        SetFlag<HardEvent::MTE2_V>(eventID);
        WaitFlag<HardEvent::MTE2_V>(eventID);
        // ===== 计算 =====
        Add(ubOut, ubIn0, ubIn1, curLength);
        // ===== 同步：V_MTE3 =====
        SetFlag<HardEvent::V_MTE3>(eventID);
        WaitFlag<HardEvent::V_MTE3>(eventID);
        // ===== 数据搬出 =====
        DataCopy(gmTensorOut[offset], ubOut, curLength);
        queIn.FreeTensor(ubIn0);
        queIn.FreeTensor(ubIn1);
        queOut.FreeTensor(ubOut);
    }
}
```

### Cube算子同步模式
Cube算子涉及多级搬运，需要在每级搬运和计算之间插入同步，形成多级同步链。
**表 9**  Cube算子同步流程
| 步骤 | 操作 | 同步类型 | 同步时机 |
|------|------|----------|----------|
| **1** | DataCopy（GM→L1） | 无 | 矩阵数据加载 |
| **2** | SetFlag/WaitFlag（MTE2_MTE1） | 流水线间同步 | 确保GM→L1完成 |
| **3** | LoadData（L1→L0A/L0B） | 无 | 分块加载 |
| **4** | SetFlag/WaitFlag（MTE1_C） | 流水线间同步 | 确保L1→L0完成 |
| **5** | Mmad | 无 | 矩阵乘计算 |
| **6** | SetFlag/WaitFlag（C_MTE3） | 流水线间同步 | 确保Mmad完成 |
| **7** | DataCopy（L0C→GM） | 无 | 结果输出 |

> 📌 **提示**：Cube算子的多级同步确保数据在各存储层级间正确流转，避免读写冲突。

### Double Buffer同步模式
Double Buffer通过Ping-Pong交替实现搬运与计算并行，同步机制控制两个Buffer之间的切换。
**Double Buffer同步原理**：
- Ping Buffer正在计算时，Pong Buffer并行搬运下一块数据
- 计算完成后切换Buffer，无需等待搬运完成（已并行搬运）

**同步要点**：
- 预加载阶段：第一个Tile先搬运
- 循环阶段：当前Tile计算与下一Tile搬运并行
- 同步点：确保当前Tile数据就绪后再计算

**示例片段**：
```cpp
// ===== 预加载第一个Tile =====
LocalTensor<half> ubIn0Ping = queIn0.AllocTensor<half>();
DataCopy(ubIn0Ping, gmTensorIn0[0], TILE_LENGTH);
for (uint32_t i = 0; i < tileNum; i++) {
    // 当前Tile索引
    uint32_t curOffset = i * TILE_LENGTH;
    // ===== Ping-Pong切换 =====
    LocalTensor<half> ubIn0 = ubIn0Ping;
    // ===== 预加载下一个Tile（并行）=====
    if (i + 1 < tileNum) {
        ubIn0Ping = queIn0.AllocTensor<half>();
        DataCopy(ubIn0Ping, gmTensorIn0[(i + 1) * TILE_LENGTH], TILE_LENGTH);
    }
    // ===== 同步：确保当前Tile数据就绪 =====
    SetFlag<HardEvent::MTE2_V>(eventID);
    WaitFlag<HardEvent::MTE2_V>(eventID);
    // ===== 计算 =====
    Add(ubOut, ubIn0, ubIn1, curLength);
    // ===== 同步：确保计算完成 =====
    SetFlag<HardEvent::V_MTE3>(eventID);
    WaitFlag<HardEvent::V_MTE3>(eventID);
    // ===== 输出 =====
    DataCopy(gmTensorOut[curOffset], ubOut, curLength);
}
```

## 扩展能力隐式同步
扩展能力通过Atom驱动隐式同步，Copy Atom和Mmad Atom内部自动插入同步，开发者无需显式调用SetFlag/WaitFlag。

### 隐式同步原理
Atom内部维护同步状态，自动识别数据依赖并插入同步指令：
- **Copy Atom**：GM→UB搬运后，自动插入MTE2→V同步（如有后续Vector计算）
- **Mmad Atom**：L1→L0A/L0B搬运后，自动插入MTE1→C同步；Mmad后自动插入C→MTE3同步

### 显式同步 vs 隐式同步对比
**表 10**  显式同步与隐式同步对比
| 对比维度 | 基础能力（显式同步） | 扩展能力（隐式同步） |
|----------|----------------------|----------------------|
| **同步控制** | 手动调用SetFlag/WaitFlag | Atom内部自动插入 |
| **灵活性** | 高，精确控制同步时机 | 中，依赖Atom内部逻辑 |
| **开发复杂度** | 高，需要理解同步流程 | 低，简化开发 |
| **适用场景** | Double Buffer、多算子协作 | 简单算子、快速原型 |

**对比示例**：
```cpp
// ===== 基础能力：显式同步（5行同步代码）=====
DataCopy(ubBuffer, gmInput, size);
SetFlag<HardEvent::MTE2_V>(eventID);   // 显式同步
WaitFlag<HardEvent::MTE2_V>(eventID);
Add(ubOut, ubIn0, ubIn1, size);
SetFlag<HardEvent::V_MTE3>(eventID);
WaitFlag<HardEvent::V_MTE3>(eventID);
DataCopy(gmOutput, ubOut, size);
// ===== 扩展能力：隐式同步（无需同步代码）=====
auto copyGM2UB = MakeCopy<CopyGM2UB>();
auto copyUB2GM = MakeCopy<CopyUB2GM>();
Copy(copyGM2UB, gmTensor, ubTensor);   // 隐式同步
Add(ubOutTensor, ubIn0Tensor, ubIn1Tensor);
Copy(copyUB2GM, ubTensor, gmTensor);   // 隐式同步
```

> 📌 **提示**：隐式同步适用于简单场景，复杂场景（Double Buffer、多算子协作）仍需使用显式同步精确控制。
