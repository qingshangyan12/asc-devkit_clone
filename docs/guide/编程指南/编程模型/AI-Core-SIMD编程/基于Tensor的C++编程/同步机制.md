AI Core采用多条流水线异步并行架构，同步机制协调流水线协作、确保数据依赖关系满足。本章重点阐述C++ Tensor编程同步接口，流水线异步原理详见[基于指针的C语言编程 > 同步机制](../基于指针的C语言编程/同步机制.md)。

> 📌 通常情况下，开发者基于编程模型进行编程时不需要关注同步，编程模型帮助开发者完成了同步控制。自行同步控制可能带来一定编程复杂度。

---

## 为什么需要同步（摘要）

AI Core多条流水线异步并行执行，带来性能收益但引入数据依赖风险。同步的核心目的是在数据依赖节点插入等待，确保数据搬运完成后再让计算开始执行。

> 📌 流水线架构、异步并行原理详见[基于指针的C语言编程 > 同步机制](../基于指针的C语言编程/同步机制.md)。


## 同步机制概述

Ascend C Tensor编程同步机制按**同步范围**分为两大类：**核内同步**、**核间同步**. 核内同步解决单个AI Core内部的流水线协作与资源保护问题。核间同步解决多AI Core协作场景的执行进度协调问题。

## 核内同步
### Mutex（共享资源访问保护）

> 📌 **提示**：Mutex机制仅**Ascend 950PR/Ascend 950DT**芯片支持，用于核内多流水线共享资源场景。

Mutex用于核内异步流水指令之间的同步处理，其功能类似于传统CPU中的锁机制。通过锁定指定流水线再释放流水线来完成流水线间的同步。每个锁有固定的一个MutexID，该ID可通过用户自定义（范围为0-27）或者通过AllocMutexID/ReleaseMutexID进行申请释放。
该同步主要适用于当核内多条流水线需要访问同一共享资源时（如共享UB区域），存在并发冲突风险：Vector流水线正在写入共享缓冲区时MTE3流水线同时读取可能导致数据不一致，多条流水线并发修改同一内存区域可能产生数据覆盖或损坏。Mutex互斥锁通过互斥访问机制确保共享资源的安全性，保障并发场景下的数据完整性。

#### 关键接口说明
- **Mutex::Lock(MutexID id)**: 根据MutexID获取Mutex，并阻塞当前流水指令队列，直到对应的MutexID被Unlock。
- **Mutex::Unlock(MutexID id)**: 直到前置当前流水指令退出后，根据MutexID释放对应Mutex。
```cpp
// 锁定 Vector 流水线互斥锁，确保当前线程独占向量计算资源
AscendC::Mutex::Lock<PIPE_V>(mutexId);
AscendC::Add(zLocal, xLocal, yLocal, TILE_LENGTH);
// 解锁 Vector 流水线，释放计算资源供其他线程使用
AscendC::Mutex::Unlock<PIPE_V>(mutexId);
```

### SetFlag/WaitFlag（流水线间数据依赖同步）

SetFlag/WaitFlag采用**信号通知-阻塞等待**模式，通过流水线间的主动通知与被动等待实现执行顺序的严格约束。源流水线完成任务后主动发出"就绪信号"，告知目标流水线数据已准备好；目标流水线在收到信号前保持阻塞状态、暂停执行，收到信号后解除阻塞继续推进。这种机制确保了数据依赖关系的严格满足：生产者流水线（如MTE2搬运）完成数据准备后发出通知，消费者流水线（如Vector计算）等待通知后再开始消费数据，避免异步并行执行中的错误执行顺序。
该同步主要适用于同一核内不同流水之间的同步指令。具有数据依赖的不同流水指令之间需要插入此类同步。

#### 关键接口说明
- **SetFlag(int32_t eventID)**：前序指令的所有读写操作完成后，将硬件标志位设置为1，表示数据已就绪
- **WaitFlag(int32_t eventID)**：执行到该指令时，若标志位为0则阻塞等待，为1则清零并继续执行
同一核内不同流水之间的同步处理，具有数据依赖的不同流水指令之间需要插入此类同步。
```cpp
AscendC::GlobalTensor<half> dstGlobal;
AscendC::LocalTensor<half> dstLocal;
dstLocal.SetValue(0, 0);
uint32_t dataSize = 512;
// 基于TPipe和TQue编程场景中，eventID需要通过AllocEventID或FetchEventID获取
int32_t eventIDSToMTE3 = static_cast<int32_t>(GetTPipePtr()->FetchEventID(AscendC::HardEvent::S_MTE3));
AscendC::SetFlag<AscendC::HardEvent::S_MTE3>(eventIDSToMTE3);
AscendC::WaitFlag<AscendC::HardEvent::S_MTE3>(eventIDSToMTE3);
AscendC::DataCopy(dstGlobal, dstLocal, dataSize);
```

### PipeBarrier（内存访问顺序控制）

采用**阻塞等待**模式，保证前序指令中所有数据的读写工作全部完成，后序指令才能执行。用于在同一流水线内部约束执行顺序。

#### 关键接口说明
- **PipeBarrier()**: 阻塞相同流水线，具有数据依赖的相同流水线之间需要插入此同步。
```cpp
Add(dst0, src0, src1, 512);    // Add输出是Mul输入
PipeBarrier<PIPE_V>();         // Vector流水线内同步
Mul(dst1, dst0, src2, 512);    // Mul依赖Add输出
```

## 核间同步

### 核间同步（多AI Core协作）
核间同步采用**计数器递增/递减**模式，通过flag_id对应的计数器协调多核执行进度。每个flag_id对应一个初始值为0的计数器，arrive指令递增计数器表示"当前核到达同步点"，wait指令检测计数器大于0则递减并继续执行、等于0则阻塞等待。这种机制实现了"多核到达同步点后才继续执行"的协调效果，适用于跨核数据交换、多核矩阵乘等协作场景。

#### 关键接口说明
- **CrossCoreSetFlag(uint16_t flagId)**: 和CrossCoreWaitFlag配合使用（通过flagId关联），用于向核间同步寄存器发送同步信号，标识当前pipeline已到达flagId对应的同步点。每个flagId对应一个初始值为0的计数器，执行CrossCoreSetFlag后flagID对应的计数器增加1；执行CrossCoreWaitFlag时如果对应的计数器数值为0则阻塞不执行；如果对应的计数器大于0，则计数器减一，同时后续指令开始执行。
- **CrossCoreWaitFlag(uint16_t flagId)**:  和CrossCoreSetFlag配合使用（通过flagID关联），用于等待所有同步对象到达flagId对应的同步点。如果flagId所对应的计数器数值为0则阻塞不执行；如果对应的计数器大于0，则计数器减一，同时后续指令开始执行。
```cpp
// 使用模式0的方式同步所有的AIV核
if (g_coreType == AscendC::AIV) {
    AscendC::CrossCoreSetFlag<0x0, PIPE_MTE3>(0x8);
    AscendC::CrossCoreWaitFlag(0x8);
}

// 使用模式1的方式同步当前AICore内的所有AIV子核
if (g_coreType == AscendC::AIV) {
    AscendC::CrossCoreSetFlag<0x1, PIPE_MTE3>(0x8);
    AscendC::CrossCoreWaitFlag(0x8);
}

// 注意：如果调用高阶API,无需开发者处理AIC和AIV的同步
// 以Matmul为例：AIC侧做完Matmul计算后通知AIV进行后处理
if (g_coreType == AscendC::AIC) {
    // Matmul处理
    AscendC::CrossCoreSetFlag<0x2, PIPE_FIX>(0x8);
}

// AIV侧等待AIC Set消息, 进行Vector后处理
if (g_coreType == AscendC::AIV) {
    AscendC::CrossCoreWaitFlag(0x8);
    // Vector后处理
}
```
---

同步机制协调流水线协作，确保数据依赖关系正确处理。核内同步包括SetFlag/WaitFlag（多流水同步）和PipeBarrier（单流水同步）。核间同步采用计数器机制协调多核执行进度。
