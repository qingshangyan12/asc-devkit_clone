## 引言

AscendC是面向LocalTensor与GlobalTensor的编程范式，核心设计理念是将内存地址抽象为Tensor对象，开发者通过Tensor进行数据搬运、计算操作、同步管理。相比C指针编程的直接地址操作，Tensor编程隐藏内存地址细节，提供更高级的抽象层次，降低开发复杂度。

AscendC提供基础能力接口，支持LocalTensor/GlobalTensor定义、数据搬运、向量计算、矩阵乘、同步等核心功能。在此基础上，对LocalTensor进行扩展，引入Layout概念描述数据布局，实现类型安全、编译期确定的张量操作，并提供Copy/Mmad Atom、零开销切片等扩展能力。

本章旨在帮助开发者建立对AscendC编程范式的整体认知，理解Tensor编程的设计理念、基础能力与扩展能力、接口选择建议。全文遵循「设计理念—Tensor抽象—基础能力—扩展能力—接口选择」的递进逻辑展开。

## 设计理念：面向Tensor的编程抽象

### Tensor编程的核心思想

Tensor编程将内存地址抽象为Tensor对象，开发者不再直接操作地址，而是通过Tensor进行数据管理。LocalTensor对应片上内存（UB、L1、L0A、L0B、L0C等），GlobalTensor对应全局内存（GM），Tensor携带数据类型、形状信息、内存位置等属性，接口调用时自动推断操作参数。

```cpp
// Tensor编程：通过Tensor对象操作
LocalTensor<half> ubTensor;  // UB上的half类型Tensor
GlobalTensor<half> gmTensor; // GM上的half类型Tensor

DataCopy(ubTensor, gmTensor, size);  // Tensor对象传递
Add(dstTensor, src0Tensor, src1Tensor);  // Tensor计算
```

### Tensor编程的优势

- **降低开发复杂度**：隐藏内存地址细节，Tensor携带数据类型和形状信息，接口自动推断操作参数。
- **提升代码可读性**：Tensor命名表达数据语义，接口调用直观，参数通过Tensor对象传递。
- **扩展能力优化**：Layout编译期确定实现类型安全，Slice/Tile零开销切片，Atom设计简化参数配置。

## 接口体系：基础能力与扩展能力

AscendC的Tensor编程分为基础能力与扩展能力两个层次，共同支撑算子开发：

### 基础能力接口

基础能力接口提供Tensor编程的核心功能：Tensor定义（LocalTensor对应片上存储，GlobalTensor对应全局存储）、数据搬运（DataCopy、Copy、DataCopyPad等）、向量计算（Add、Sub、Mul、Div、Reduce等）、矩阵乘（LoadData、Mmad、Fill等）、同步机制（PipeBarrier、SetFlag/WaitFlag等）、内存管理（TPipe、TQue队列管理）。

**接口特点**：参数通过结构体传递，内存位置通过TPosition枚举表达，形状信息运行期设置，同步时机显式控制。

### LocalTensor扩展能力

在基础能力基础上，对LocalTensor进行扩展，引入Layout概念将数据布局抽象为类型，Shape和Stride编译期确定实现类型安全；引入Copy/Mmad Atom通过Operation类型显式表达内存路径，简化参数配置；提供零开销切片（Slice/Tile）布局变换，无数据拷贝；采用Operation驱动隐式同步，减少手动同步调用。

**扩展特点**：类型安全（编译期Layout校验）、零开销抽象（Slice/Tile无拷贝）、Atom-Traits设计（编译期+运行期混合配置）、隐式同步简化开发。

## 基础能力：Tensor定义与核心接口

### Tensor定义

**LocalTensor定义**：对应片上内存（UB、L1、L0A等），通过TPipe/TQue队列管理或显式地址构造。

```cpp
// 通过TPipe队列管理
TPipe pipe;
TQue<UB, 1> que;
pipe.InitBuffer(que, 1, 256 * sizeof(half));
LocalTensor<half> ubTensor = que.AllocTensor<half>();

// 显式地址构造
LocalTensor<half> ubTensor(UB, ubAddress);
ubTensor.SetShapeInfo({128, 64});
```

**GlobalTensor定义**：对应全局内存（GM），通过SetGlobalBuffer设置地址。

```cpp
GlobalTensor<half> gmTensor;
gmTensor.SetGlobalBuffer((__gm__ half*)gmBuffer, bufferSize);
```

### 数据搬运接口

数据搬运通过DataCopy接口实现GM与UB之间的数据流转，支持连续搬运和非连续搬运两种模式。

```cpp
// 连续搬运：直接搬运count个元素
DataCopy(ubTensor, gmTensor, 256);

// 非连续搬运：通过参数结构体配置块切分和间隙
DataCopyParams params = {8, 256, 0, 0};
DataCopy(ubTensor, gmTensor, params);
```

### 计算接口

**向量计算**：支持Add、Sub、Mul、Div、Reduce等算术、逻辑、规约运算。

```cpp
// 简化模式：连续计算count个元素
Add(dstTensor, src0Tensor, src1Tensor, 256);
```

**矩阵乘**：LoadData加载矩阵到L0A/L0B，Mmad执行矩阵乘累加操作。

```cpp
// 加载矩阵到L0A/L0B
LoadData(l0aTensor, l1Tensor, loadDataParams);

// 执行矩阵乘
Mmad(l0cTensor, l0aTensor, l0bTensor, mmadParams);
```

### RegTensor：寄存器层计算

> 📌 **提示**：RegTensor从**Ascend 950RT**开始支持，用于寄存器级精细控制与极致性能场景。

RegTensor是寄存器层Tensor抽象，Reg表示Register（寄存器），提供对Vector计算单元内部寄存器的直接操作能力。Vector计算单元只能访问寄存器，无法直接读写UB数据，因此需要先将UB数据加载到寄存器，计算完成后再将结果写回UB。

**RegTensor类型**：
- **MaskReg**：掩码寄存器（vector_bool），控制参与计算的元素
- **AddrReg**：地址寄存器（vector_address），存储地址偏移量
- **数据寄存器**：矢量数据寄存器（vector_half、vector_float等），存储计算数据

**RegTensor使用流程**遵循「Load-Compute-Store」三阶段：

```cpp
using namespace AscendC::Reg;

// ===== Load：UB→寄存器 =====
vector_half srcReg0, srcReg1;
MaskReg mask;  // 掩码寄存器
LoadAlign(srcReg0, ubAddr0);  // 加载UB数据到寄存器
LoadAlign(srcReg1, ubAddr1);

// ===== Compute：寄存器计算 =====
vector_half dstReg;
Add(dstReg, srcReg0, srcReg1, mask);  // 寄存器加法

// ===== Store：寄存器→UB =====
StoreAlign(ubDstAddr, dstReg, mask);  // 结果写回UB
```

RegTensor适用于需要精细控制计算过程、追求极致性能的场景，通过LoadAlign/StoreAlign实现UB与寄存器之间的数据搬运，Add/Mul/Div等计算接口在寄存器上执行。

## 扩展能力：Layout抽象与Tensor定义

### Layout核心概念

Layout是扩展能力的核心抽象，解决多维数据访问的索引计算问题。Layout将Shape（描述"元素在哪里"，逻辑坐标）和Stride（描述"内存在哪里"，物理偏移）分离，自动完成坐标到索引的转换，开发者只需关注逻辑坐标，无需手动计算地址偏移。

**Layout的核心价值**：
- 抽象内存排列细节，让开发者专注于逻辑描述而非地址计算
- 支持层次化表达，自然描述分块计算的数据布局
- 编译期类型安全，Shape和Stride在编译时确定，避免运行期布局错误

### Tensor定义与使用

扩展能力的Tensor通过MakeTensor工厂函数创建，Shape和Stride编译期确定：

```cpp
// 最简化Tensor定义：Shape自动推导Stride
auto tensor = MakeTensor(ubPointer, MakeShape(128, 64));

// 带Stride的Tensor定义：自定义内存排列
auto shape = MakeShape(128, 64);
auto stride = MakeStride(64, 1);  // 行主序
auto tensor = MakeTensor(ubPointer, MakeLayout(shape, stride));
```

### Layout布局模式

Layout支持多种布局模式，通过Shape和Stride组合表达：

**平铺布局**：最基础的布局形式，适用于连续数据排列。

**层次化布局**：通过嵌套Shape和Stride描述分块数据，外层描述块级结构，内层描述块内结构，自然表达分块计算的数据组织。

**分形布局**：通过MakeFrameLayout接口自动生成NZ、ZZ等分形布局，简化Cube矩阵乘的分形参数配置。

```cpp
// 分形布局示例：NZ布局用于Cube矩阵乘
auto nzLayout = MakeFrameLayout<NZLayoutPtn>(128, 64);
auto tensor = MakeTensor(l1Pointer, nzLayout);
```

## 接口选择建议

基础能力适用于运行期灵活性需求、细粒度同步控制、快速原型开发场景；扩展能力适用于编译期类型安全、多种布局格式、切片分块操作、Cube算子开发场景，复杂同步场景可配合基础能力同步接口使用。

## 小结

本章阐述了AscendC编程范式的整体体系：AscendC是面向LocalTensor与GlobalTensor的编程范式，将内存地址抽象为Tensor对象，隐藏地址细节；基础能力接口提供Tensor定义、数据搬运、计算、同步、内存管理等核心功能；扩展能力引入Layout概念，提供编译期类型安全、LayoutPattern分形布局、Copy/Mmad Atom、零开销切片等能力；开发者可根据场景选择基础能力或扩展能力，复杂场景可混合使用。
