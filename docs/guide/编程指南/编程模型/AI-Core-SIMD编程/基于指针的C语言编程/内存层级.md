# 内存层级

内存层级是C指针编程的底层基石，直接映射AI Core硬件存储结构。合理的内存布局与数据流转策略，是实现高性能算子的核心前提。本章系统阐述存储架构定位、内存申请方式、寄存器体系，帮助开发者建立对硬件存储资源的完整认知，掌握内存资源管控与数据搬运优化的核心方法论。
> 📌 寄存器可编程能力从**Ascend 950PR/Ascend 950DT**引入。

---

## 存储结构

Ascend 950PR/Ascend 950DT新一代架构在传统UB缓存体系的基础上，开放寄存器（Register）可编程能力，构建出「Global Memory → UB → Register」的三级内存层级，衍生出两套适配不同性能诉求的矢量计算模式，实现通用场景与极致性能场景的全覆盖。其内存层级结构如下图所示：

![AI Core存储层次结构](<../../../../figures/AI Core存储层次结构.png>)

### 存储层级功能定位

**外部存储（Global Memory）**：存放算子输入/输出数据。容量大但延迟高，需通过MTE2流水线搬运到片上存储后参与计算并通过MTE3流水搬出。
**片上存储（Local Memory）**：包括L1 Buffer、L0系列Buffer和Unified Buffer（UB）。UB是Vector算子的数据枢纽，数据需从Global Memory搬运至UB后才能参与矢量计算。L1 Buffer、L0A/L0B Buffer、L0C Buffer服务于矩阵计算：输入数据从GM搬运至L1 Buffer，再分发至L0A/L0B Buffer供Cube单元计算，结果暂存于L0C Buffer。
**寄存器（Ascend 950PR/950DT引入）**：位于Vector计算单元最内层，具备最低访存延迟与最高带宽。开放寄存器可编程能力，可充分释放硬件峰值性能。Vector计算单元仅访问寄存器，数据需从UB加载至寄存器后方可参与计算。

### 地址限定符

每种存储层级通过**地址限定符**标识，编译器据此将数据分配到对应物理存储空间。地址限定符是C指针编程的核心语法要素，明确告知编译器数据的存储位置，确保数据访问与硬件存储层级精准映射。使用方式包括：声明变量时指定限定符，或对指针进行强制类型转换。

## 内存申请方式

基于C API编程时，开发者需要自行通过显式的内存管理来控制内存，不同层级的内存申请介绍如下：

### 静态数组申请

数组长度需编译期常量，编译器自动分配地址空间、自动对齐。语法简洁、不易出错，适用于内存布局简单场景。
```cpp
constexpr uint32_t ub_size = 256;
__ubuf__ half ub_buffer[ub_size];  // 申请UB，编译器自动32字节对齐

constexpr uint32_t l1_size = 4096;
__cbuf__ half l1_buffer[l1_size];  // 申请L1

constexpr uint32_t l0a_size = 128;
__ca__ half l0a_buffer[l0a_size];  // 申请L0A，编译器自动512字节对齐
```
> 📌 **约束**：不支持动态数组、多维数组、嵌套数组。

### 动态内存申请

对于动态内存的诉求, 通常通过静态数组分配一块大的内存然后通过偏移获取物理地址，手动管理地址分配和对齐。

```cpp
constexpr uint32_t ub_size = 1024;
__ubuf__ half ub_buffer[ub_size];  // 申请UB，编译器自动32字节对齐

// 基于通过数组申请出来的ub_buffer地址进行offset偏移获取tmp_ub_buffer地址, 需要保证offset保证32字节对齐
__ubuf__ half* tmp_ub_buffer = (__ubuf__ half*)ub_buffer + offset;
```

## 寄存器体系（Ascend 950PR/950DT）

寄存器是Vector计算单元的工作存储，延迟最低、带宽最高，数据需从UB加载至寄存器参与计算。包含四类专用寄存器：

### 矢量数据寄存器

矢量数据寄存器用于矢量计算，寄存器位宽为 VL(Vector Length)。常见类型：`vector_half`（128个half）、`vector_float`（64个float）、`vector_int8_t`（256个int8）、`vector_bfloat16_t`（128个bf16）。
```cpp
vector_half src_reg;   // 声明half类型矢量寄存器
vector_float dst_reg;  // 声明float类型矢量寄存器
```

### 掩码寄存器

掩码寄存器用于指示在计算过程中哪些元素参与计算，宽度为RegTensor的八分之一（VL/8）。支持静态模式（PAT_ALL/PAT_H/PAT_Q等）和动态创建。
```cpp
vector_bool mask = asc_create_mask_b16(PAT_ALL);      // 静态掩码：所有元素参与
vector_bool mask = asc_update_mask_b16(remain_count); // 动态掩码：按实际元素数创建
```

### 地址寄存器

地址寄存器存储地址偏移量，循环中根据设置的stride自动自增。类型为`iter_reg`，通过`asc_create_iter_reg_b16`初始化。
```cpp
iter_reg addr_reg = asc_create_iter_reg_b16(one_repeat_size);
for (uint16_t i = 0; i < repeat_time; ++i) {
    asc_loadalign(src_reg, src_addr, addr_reg);  // addr_reg自动累加步长
    asc_add(dst_reg, src_reg, src_reg, mask);
    asc_storealign(dst_addr, dst_reg, addr_reg, mask);
}
```

### 非对齐寄存器

类型为`vector_load_unalign`/`vector_store_unalign`，处理起始地址未32字节对齐的数据搬运。
非对齐寄存器用作缓冲区来优化UB和寄存器之间连续不对齐地址访问的开销。常见类型为`vector_load_unalign`和`vector_store_unalign`。在读不对齐地址前，应该通过`asc_loadunalign_pre`接口出事化初始化，然后使用`asc_loadunalign`读取数据。在写不对齐地址时，先使用`asc_storeunalign`，再使用`asc_storeunalign_post`进行后处理。
```cpp
vector_load_unalign ureg;                       // 声明非对齐加载缓存
asc_loadunalign_pre(ureg, src_addr);            // 初始化
asc_loadunalign(src_reg, ureg, src_addr);       // 加载
vector_store_unalign ureg_dst;                  // 声明非存起存储缓存
asc_storeunalign(dst_addr, ureg_dst, dst_reg);  // 存储
asc_storeunalign_post(dst_addr, ureg_dst, 0);   // 处理尾块
```

---

内存层级构建「Global Memory → 片上存储（UB服务矢量计算，L1/L0A/L0B/L0C服务矩阵计算）→ 寄存器」的存储架构，各层级通过__gm__/__ubuf__/__cbuf__等地址限定符精准映射并遵循严格对齐约束。Vector计算单元仅访问寄存器，数据需经GM搬运至UB再加载至寄存器参与计算，开发者需掌握静态数组与偏移量两种内存申请方式，合理利用掩码寄存器、地址寄存器处理尾部数据与循环迭代。
