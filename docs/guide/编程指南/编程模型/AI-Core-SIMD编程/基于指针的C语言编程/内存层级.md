## 引言

AI Core采用三级存储架构，数据搬运遵循层级流转原则。本章将详细阐述存储层级定位、内存申请方式、寄存器体系、数据流协作机制。

> 📌 寄存器可编程能力从**Ascend 950PR/Ascend 950DT**引入，构建三级内存架构，可获得接近峰值的计算性能。

## 三级存储架构

AI Core采用「外部存储—片上存储—寄存器」三级架构，各层级分工明确、协同联动。数据流转遵循「就近计算」原则，数据需搬运到距离计算单元最近的存储层级，减少搬运开销。

**数据流转路径**：
- **Vector算子**：Global Memory → UB → 寄存器 → 计算 → UB → Global Memory
- **Cube算子**：Global Memory → L1 → L0A/L0B → 计算 → L0C → Global Memory

### 存储层级功能定位

**外部存储（Global Memory）**：存放算子输入/输出数据。容量大但延迟高，需通过MTE2/MTE3流水线搬运到片上存储后才能参与计算。

**片上存储（Local Memory）**：包括L1 Buffer、L0系列Buffer和Unified Buffer（UB）。L1承接GM数据供给L0，L0A/L0B直接供给Cube计算单元，L0C存储计算结果。UB是Vector算子的数据枢纽，数据从GM搬运到UB后需加载到寄存器才能被Vector计算单元访问。容量有限但延迟低，采用分块迭代策略完成全域计算。

**寄存器（Ascend 950PR/950DT引入）**：计算单元内部高速存储，延迟最低、带宽最高。Vector计算单元只能访问寄存器，不直接读取UB。

### 地址限定符

每种存储层级通过地址限定符标识，编译器据此将数据分配到对应物理存储。使用限定符声明变量或强制转换指针类型。

**地址限定符与存储对应**：
- `__gm__`：Global Memory，全局内存
- `__cbuf__`：L1 Buffer，Cube数据中转区
- `__ca__`：L0A Buffer，左矩阵输入
- `__cb__`：L0B Buffer，右矩阵输入
- `__cc__`：L0C Buffer，矩阵乘结果
- `__ubuf__`：Unified Buffer，Vector数据枢纽

**使用方式**：声明变量时指定限定符（如`__ubuf__ half buffer[256]`），或强制转换指针类型（如`(__ubuf__ half*)addr`）。

> 📌 片内存储有限，采用「分块搬运、迭代计算、结果累加」策略。UB容量约数十KB~数百KB，L1约数百KB~1MB，需据此规划分块大小。

## 内存申请方式

C指针编程提供两种内存申请方式：静态数组（编译器自动管理）和偏移量申请（手动管理地址）。开发者需根据场景选择一种方式，统一使用以避免冲突。

### 静态数组申请

数组长度需编译期常量，编译器自动分配地址空间、自动对齐。语法简洁、不易出错，适用于内存布局简单场景。

**约束**：不支持动态数组、多维数组、嵌套数组。

```cpp
constexpr uint32_t ub_size = 256;
__ubuf__ half ub_buffer[ub_size];  // 申请UB，编译器自动32字节对齐

constexpr uint32_t l1_size = 4096;
__cbuf__ half l1_buffer[l1_size];  // 申请L1

constexpr uint32_t l0a_size = 128;
__ca__ half l0a_buffer[l0a_size];  // 申请L0A，编译器自动512字节对齐
```

### 偏移量申请

通过偏移量获取物理地址，手动管理地址分配和对齐。适用于精细控制内存布局、多buffer顺序分配场景。

**基本流程**：从偏移量0开始，累加已申请buffer大小，调用`asc_get_phy_buf_addr`获取地址，强制转换为对应限定符类型。

```cpp
uint64_t offset = 0;
__ubuf__ half* src0 = (__ubuf__ half*)asc_get_phy_buf_addr(offset);
offset += 64 * sizeof(half);  // 手动累加偏移量
__ubuf__ half* src1 = (__ubuf__ half*)asc_get_phy_buf_addr(offset);
offset += 64 * sizeof(half);
__ubuf__ half* dst = (__ubuf__ half*)asc_get_phy_buf_addr(offset);
```

> 📌 静态数组与偏移量方式不能混用，会导致地址重叠。选择一种后统一使用。

## 寄存器体系（Ascend 950PR/950DT）

寄存器是计算单元内部的高速存储，Vector计算单元只能访问寄存器，不直接读取UB。数据需从UB加载到寄存器，计算后写回UB。寄存器延迟最低、带宽最高，可获得接近峰值的计算性能。

### 矢量数据寄存器

矢量数据寄存器存储计算输入/输出数据，位宽固定为VL=256字节。根据数据类型位宽，单次可存储VL/sizeof(T)个元素。
**常用矢量类型**：
- `vector_half`：128个half元素（256B/2B=128）
- `vector_float`：64个float元素（256B/4B=64）
- `vector_int8_t`：256个int8元素（256B/1B=256）
- `vector_bfloat16_t`：128个bf16元素

**使用方式**：声明寄存器变量，通过Load接口加载UB数据，计算接口操作寄存器，Store接口写回UB。
```cpp
vector_half src_reg;     // 存储128个half
vector_float dst_reg;    // 存储64个float
vector_int8_t data_reg;  // 存储256个int8
```

### 掩码寄存器

掩码寄存器类型为`vector_bool`，控制矢量计算中部分元素参与计算。每个bit控制一个元素：True参与计算、False跳过。用于尾部数据处理、条件计算场景。
**掩码创建模式**：
- `PAT_ALL`：所有元素参与
- `PAT_VL1/VL2/VL4/VL8/VL16/VL32/VL64/VL128`：最低N个元素参与
- `PAT_H`：最低一半元素参与
- `PAT_Q`：最低四分之一元素参与
- `PAT_ALLF`：所有元素不参与

**动态掩码**：根据实际元素数动态创建，处理尾部数据。
```cpp
vector_bool mask = asc_create_mask_b16(PAT_ALL);      // 全参与
vector_bool mask = asc_update_mask_b16(remain_count); // 动态创建
```

### 地址寄存器

地址寄存器类型为`iter_reg`，循环中自动管理地址偏移。初始化时设置步长，每次循环自动累加，避免手动计算偏移量。
**使用场景**：迭代搬运数据、迭代计算，循环中地址自动更新。
```cpp
iter_reg addr_reg = asc_create_iter_reg_b16(one_repeat_size);
for (uint16_t i = 0; i < repeat_time; ++i) {
    asc_loadalign(src_reg, src_addr, addr_reg);  // addr_reg自动累加步长
    asc_add(dst_reg, src_reg, src_reg, mask);
    asc_storealign(dst_addr, dst_reg, addr_reg, mask);
}
```

### 非对齐寄存器

处理起始地址未32字节对齐的数据搬运。包括`vector_load_align`（加载缓冲）和`vector_store_align`（存储缓冲）两类。
**使用流程**：
- 加载：`asc_loadunalign_pre`初始化 → `asc_loadunalign`加载
- 存储：`asc_storeunalign`存储 → `asc_storeunalign_post`处理尾块

```cpp
vector_load_unalign ureg;                      // 非对齐加载缓冲
asc_loadunalign_pre(ureg, src_addr);           // 初始化
asc_loadunalign(src_reg, ureg, src_addr);      // 加载
asc_storeunalign(dst_addr, ureg_dst, dst_reg); // 存储
asc_storeunalign_post(dst_addr, ureg_dst, 0);  // 处理尾块
```

## 片上存储与寄存器数据流协作

Vector计算依赖片上存储（UB）与寄存器的协同工作。数据从UB加载到寄存器（Load），计算单元在寄存器中执行运算（Compute），结果写回UB（Store）。这形成了Load-Compute-Store三阶段流程，确保计算单元通过寄存器高效访问数据。
### 基本流程
```cpp
// Load：UB→寄存器
constexpr uint32_t length = 128;
__ubuf__ half src_buffer[length];
vector_half src_reg;
asc_loadalign(src_reg, src_buffer);

// Compute：寄存器计算
vector_half dst_reg;
vector_bool mask = asc_create_mask_b16(PAT_ALL);
asc_add(dst_reg, src_reg, src_reg, mask);

// Store：寄存器→UB
__ubuf__ half dst_buffer[length];
asc_storealign(dst_buffer, dst_reg, mask);
```

### 迭代循环流程
实际算子数据量远超单次VL容量（128个half或64个float），需迭代循环处理。每次迭代加载VL大小数据块，计算后写回，循环直至全部完成。尾部数据用掩码控制实际参与元素数。
```cpp
constexpr uint32_t one_repeat = 256 / sizeof(half);  // 单次128元素
uint32_t total = 1024;
uint32_t repeats = total / one_repeat;

vector_half src_reg, dst_reg;
vector_bool mask;
iter_reg addr = asc_create_iter_reg_b16(one_repeat);

for (uint16_t i = 0; i < repeats; ++i) {
    uint32_t remain = total - i * one_repeat;  // 剩余元素数
    mask = asc_update_mask_b16(remain);        // 动态掩码
    asc_loadalign(src_reg, src, addr);
    asc_add(dst_reg, src_reg, src_reg, mask);
    asc_storealign(dst, dst_reg, addr, mask);
}
```

## 小结
三级存储架构支撑数据流转，各层级有明确的对齐约束。静态数组和偏移量两种内存申请方式需统一使用以避免冲突。寄存器是计算单元工作存储，Vector只能访问寄存器，通过Load-Compute-Store与UB协作。迭代循环使用掩码处理尾部，地址寄存器自动偏移。
