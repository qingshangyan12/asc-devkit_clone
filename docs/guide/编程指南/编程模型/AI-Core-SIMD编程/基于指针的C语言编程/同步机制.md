## 引言

AI Core采用多条流水线异步并行架构，数据搬入、计算、数据搬出分别由MTE2、Vector/Cube、MTE3流水线承载。流水线异步执行带来天然并行优势，但也引入数据依赖风险。同步机制是协调流水线协作、确保数据依赖关系得到满足的关键技术。

本章旨在帮助开发者建立对C指针编程同步机制的核心认知。全文遵循「问题—原理—接口—实践—高级扩展」的递进逻辑展开，帮助开发者理解为什么需要同步、同步如何工作、如何正确使用同步接口。

## 为什么需要同步：异步执行带来的数据依赖风险

### 流水线异步执行的好处与风险

**表 1**  AI Core流水线分类

| 流水线 | 功能 | 典型指令 |
|--------|------|----------|
| **MTE2** | 数据搬入（GM→Local Memory） | `asc_copy_gm2ub`、`asc_copy_gm2l1` |
| **MTE3** | 数据搬出（Local Memory→GM） | `asc_copy_ub2gm`、`asc_copy_l0c2gm` |
| **Vector** | 向量计算 | `asc_add`、`asc_mul` |
| **Cube** | 矩阵计算 | `asc_mmad` |

AI Core的多条流水线**异步并行执行**，各自独立推进指令序列。这种设计带来显著优势：

**并行优势**：数据搬入（MTE2）和计算可以同时进行，搬入下一块数据时，计算单元正在处理上一块数据，大幅提升吞吐率。

**潜在风险**：异步执行意味着流水线之间没有自动协调。如果Vector流水线在MTE2搬运完成前就开始计算，会读取到未就绪的数据，导致结果错误。

### 数据依赖关系：同步的本质需求

流水线之间存在明确的数据依赖关系：

- **MTE2 → Vector/Cube**：计算依赖搬入的数据，数据未就绪时计算会出错
- **Vector/Cube → MTE3**：搬出依赖计算的结果，计算未完成时搬出会输出错误数据

**举例说明**：

```c
// 错误示例：缺少同步
asc_copy_gm2ub(x_local, x_gm, 256);  // MTE2开始搬运
asc_add(z_local, x_local, y_local);   // Vector立即开始计算（可能读取未就绪数据）
asc_copy_ub2gm(z_gm, z_local, 256);   // MTE3立即搬出（可能输出错误结果）
```

> 📌 **提示**：同步的核心目的是在数据依赖节点插入等待，确保"生产者"完成后再让"消费者"开始。

## 同步的基本原理：notify/wait工作机制

### 同步的本质：流水线间的"握手"

C指针编程的同步机制采用**notify/wait**模式，类似流水线之间的"握手"：

- **notify（通知）**：源流水线完成任务后，向目标流水线发送"就绪信号"
- **wait（等待）**：目标流水线收到信号前阻塞等待，收到信号后继续执行

**类比理解**：

```
传统串行程序：做饭时，洗菜→切菜→炒菜依次进行，自动等待前一步完成
异步并行程序：多人协作，洗菜人、切菜人、炒菜人各自独立工作
同步机制：洗菜人洗完后喊"菜洗好了"，切菜人听到后才开始切
```

## 核心同步接口：notify/wait与自动同步

### 手动同步接口

**表 2**  流水线同步接口

| 接口 | 功能 |
|------|------|
| `asc_sync_notify(pipe, tpipe, id)` | 发送同步信号：源流水线通知目标流水线数据已就绪 |
| `asc_sync_wait(pipe, tpipe, id)` | 等待同步信号：目标流水线等待源流水线的通知 |

**参数说明**：
- **pipe**：源流水线标识（PIPE_MTE2、PIPE_MTE3、PIPE_V等）
- **tpipe**：目标流水线标识
- **id**：事件ID（EVENT_ID0~EVENT_ID7），用于区分不同同步事件

### 自动同步接口

数据搬运接口提供自动同步版本（`_sync`后缀），接口内部自动等待完成：

```c
// ===== 自动同步版本：内部自动等待 =====
asc_copy_gm2ub_sync(x_local, x_gm, 256);

// ===== 手动同步版本：需显式调用同步接口 =====
asc_copy_gm2ub(x_local, x_gm, 256);  // 搬入数据
asc_sync_notify(PIPE_MTE2, PIPE_V, EVENT_ID0);  // MTE2通知V
asc_sync_wait(PIPE_MTE2, PIPE_V, EVENT_ID0);    // V等待MTE2
```

### Mutex互斥锁

> 📌 **提示**：Mutex互斥锁从**Ascend 950PR/Ascend 950DT**开始支持，用于核内多流水线共享资源场景。

当核内多条流水线需要访问同一共享资源时（如共享UB区域），需要互斥锁保护资源访问，避免并发冲突。

**表 3**  Mutex接口

| 接口 | 功能 |
|------|------|
| `asc_lock(pipe, mutex_id, mode)` | 获取共享资源访问权 |
| `asc_unlock(pipe, mutex_id, mode)` | 释放共享资源访问权 |

```c
asc_lock(PIPE_V, MUTEX_ID0, ASC_LOCK_BLOCK);  // 获取锁
asc_add(shared_buffer, x_local, y_local);     // 访问共享资源
asc_unlock(PIPE_V, MUTEX_ID0, ASC_LOCK_BLOCK);  // 释放锁
```

## 标准同步模式：Vector算子实践

### 同步流程五步骤

Vector算子的标准同步模式遵循「搬入 → 同步 → 计算 → 同步 → 搬出」流程：

```c
// ===== 第一步：数据搬入 =====
asc_copy_gm2ub(x_local, x_gm, 256);  // MTE2搬运数据

// ===== 第二步：搬入同步 =====
asc_sync_notify(PIPE_MTE2, PIPE_V, EVENT_ID0);  // MTE2通知V：数据就绪
asc_sync_wait(PIPE_MTE2, PIPE_V, EVENT_ID0);    // V等待MTE2

// ===== 第三步：计算执行 =====
asc_add(z_local, x_local, y_local);  // Vector计算

// ===== 第四步：计算同步 =====
asc_sync_notify(PIPE_V, PIPE_MTE3, EVENT_ID0);  // V通知MTE3：计算完成
asc_sync_wait(PIPE_V, PIPE_MTE3, EVENT_ID0);    // MTE3等待V

// ===== 第五步：数据搬出 =====
asc_copy_ub2gm(z_gm, z_local, 256);  // MTE3搬出结果
```

### 同步要点总结

| 同步节点 | 同步方向 | 目的 |
|----------|----------|------|
| 搬入后 | MTE2 → Vector | 确保计算使用已就绪数据 |
| 计算后 | Vector → MTE3 | 确保搬出使用正确结果 |

**正确性检查**：
- 每个数据依赖节点是否都有对应的notify/wait
- notify和wait是否成对出现、参数一致
- EVENT_ID是否正确区分不同同步事件

## 高级同步场景：核间同步

多AI Core协作场景（如跨核数据交换、多核矩阵乘），需要核间同步协调执行进度。

**表 4**  核间同步接口

| 接口 | 功能 |
|------|------|
| `asc_sync_block_arrive(pipe, flag_id)` | 当前核到达同步点 |
| `asc_sync_block_wait(pipe, flag_id)` | 等待其他核到达同步点 |

> 📌 **提示**：大多数算子在SPMD模型下各核独立处理数据分片，无需核间同步。仅跨核协作场景需要使用。

## 小结

本章阐述了C指针编程同步机制：异步并行执行带来效率优势，但也引入数据依赖风险，必须在依赖节点插入同步确保正确性；同步采用notify/wait机制，开发者可选择自动同步或手动同步；核内共享资源场景可使用Mutex互斥锁保护；标准同步模式遵循「搬入→同步→计算→同步→搬出」流程；核间协作场景可使用核间同步接口。
