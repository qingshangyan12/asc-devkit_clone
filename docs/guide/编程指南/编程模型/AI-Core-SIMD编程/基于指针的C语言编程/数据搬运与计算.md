数据搬运与计算是AI Core算子开发的两大核心操作，共同构成算子执行的数据流转与计算处理闭环。数据搬运解决「数据从哪里来、到哪里去」的问题，计算解决「数据如何处理」的问题，二者协同配合完成算子功能实现。本章旨在帮助开发者建立对C指针编程搬运与计算接口的系统化认知，重点阐述C指针编程的特点与优势，以及接口的分类体系与使用方法。全文遵循「编程特点—主要接口分类」的递进逻辑展开。

## C指针编程接口的特点与核心特征

C指针编程是直接操作NPU硬件的C语言函数接口，提供指令级透明可控的底层编程能力。相比高抽象层次的API，C指针编程具有以下核心优势：

- **指令级透明可控**: 函数与硬件指令一一对应，调用即执行。调用`asc_add()`执行向量加法指令，调用`asc_copy_gm2ub()`执行数据搬运指令，调用`asc_mmad()`执行矩阵乘指令。无抽象封装和运行时判断、无中间转换。同步位置、内存分配、分块策略完全由开发者决定，算子性能可达硬件峰值。
- **编程习惯无缝适配**: 函数命名直观（`asc_add`、`asc_copy_gm2ub`、`asc_mmad`），参数风格C化（指针、地址、长度），无需学习新对象类型，直接用C的方式写算子。开发者可直接操作内存地址、显式管理数据流转，符合C语言编程习惯。
- **精准问题定位**: 每条指令可见，可逐条追踪定位问题指令。同步是否到位、数据搬运是否越界、计算指令是否正确执行，均可追溯至具体指令，调试效率大幅提升。

## 硬件底层支撑：流水线与存储架构

AI Core采用多流水线并行架构与多层级存储架构，数据搬运与计算指令由不同流水线承载，协同完成数据处理。

**流水线分工**：
- **MTE2**：数据搬入（GM→Local Memory），承载DataCopy（GM→UB/L1）搬运指令
- **MTE3**：数据搬出（Local Memory→GM），承载DataCopy（UB/L0C→GM）搬运指令
- **MTE1**：L1搬运（L1→L0A/L0B），承载LoadData搬运指令
- **FIX**：L0C搬运（L0C→GM/UB），承载Fixpipe搬运指令
- **Vector**：向量计算，承载Add、Mul等计算指令
- **Cube**：矩阵计算，承载Mmad矩阵乘指令

**数据流转路径**：
- **Vector算子数据流**：`GM → UB → Vector计算 → UB → GM`
- **Cube算子数据流**：`GM → L1 → L0A/L0B → Cube计算 → L0C → GM`

> 📌 数据搬运遵循「就近计算」原则，将数据搬运到距离计算单元最近的存储层级，最大限度减少搬运开销。

## C指针编程数据搬运与计算接口

C指针编程开放芯片完备编程能力，支持以数组形式分配内存，一般基于指针编程。提供与业界一致的C语言编程体验。包含asc_simd.h文件来调用C API相应接口。如无特殊说明，包含该头文件即可满足接口调用需求。 若API文档中有特殊说明，则应遵循API的具体说明。
```c
#include "c_api/asc_simd.h" 
```
对于C指针编程接口，主要分为**Vector搬运接口**、**Cube搬运接口**、**Vector计算接口**、**Cube计算接口**等；

### Vector搬运接口

Vector搬运接口支撑GM与UB之间的数据流转，是Vector算子开发的基础。接口命名遵循「源→目标」格式（如`asc_copy_gm2ub`表示GM到UB搬运），参数简洁直观（dst、src、size）, 主要包含如下接口定义:
- **GM2UB搬运**: `asc_copy_gm2ub`加载输入数据到UB
- **UB2GM搬运**: `asc_copy_ub2gm`输出计算结果到GM
- **GM2UB多维搬运**: `asc_ndim_copy_gm2ub`进行多维度带填充搬运

同时对于同一类接口，提供了不同的接口形式来应对不同的应用场景：
- **常规接口**：`asc_copy_gm2ub(dst, src, size)`，异步执行，需配合同步接口
- **高维切分接口**：`asc_copy_gm2ub(dst, src, n_burst, len_burst, src_gap, dst_gap)`，支持复杂搬运模式
- **同步接口**：`asc_copy_gm2ub_sync(dst, src, size)`，内部自动等待搬运完成

**详细接口说明**：参见 [Vector搬运接口](../../../../../api/context/c_api/vector_datamove/)

### Cube搬运接口

Cube搬运接口支撑矩阵乘法的数据供给，涵盖GM→L1、L1→L0A/L0B、L0C→GM的完整路径。接口支持2D格式搬运、转置搬运、3D格式搬运等多种模式, 主要包含如下接口定义:
- **GM2L1搬运**: `asc_copy_gm2l1`加载矩阵数据到L1
- **L12L0A搬运**: `asc_copy_l12l0a`加载左矩阵到L0A
- **L12L0B搬运**: `asc_copy_l12l0b`加载右矩阵到L0B
- **L0C2GM搬运**: `asc_copy_l0c2gm`输出矩阵乘结果到GM

**详细接口说明**：参见 [Cube搬运接口](../../../../../api/context/c_api/cube_datamove/)

### Vector计算接口

Vector计算接口覆盖算术运算、比较运算、类型转换、规约运算、激活函数等场景，是算子开发的核心工具集。接口命名直观（`asc_add`表示向量加法），参数简洁（dst、src、count）, 主要包含如下接口定义:

- **算术运算**：`asc_add`、`asc_sub`、`asc_mul`、`asc_div`等逐元素算术运算接口
- **比较运算**：`asc_eq`、`asc_lt`、`asc_gt`等逐元素比较运算接口
- **类型转换**：`asc_float2half`、`asc_half2float`等类型转换（支持舍入模式）接口
- **规约运算**：`asc_reduce_max`、`asc_reduce_min`、`asc_reduce_sum`等规约计算接口
- **激活函数**：`asc_relu`、`asc_leakyrelu`、`asc_exp`、`asc_log`等激活函数接口
- **其他运算**：`asc_duplicate`、`asc_sqrt`、`asc_abs`，其他常用运算

同时对于同一类接口，提供了不同的接口形式来应对不同的应用场景：
- **常规接口**：`asc_add(dst, src0, src1, count)`，异步执行
- **高维切分接口**：支持repeat、block_stride、repeat_stride参数，适用于复杂数据布局
- **同步接口**：`asc_add_sync(dst, src0, src1, count)`，内部自动等待计算完成

**详细接口说明**：参见 [Cube计算接口](../../../../../api/context/c_api/vector_compute/)

### 矩阵计算接口

矩阵计算接口以`asc_mmad`为核心，支持多种数据类型与计算模式。接口参数直观（c_matrix、a_matrix、b_matrix、M、K、N），开发者可精细控制矩阵计算过程, 主要包含如下接口定义:

- **标准矩阵乘加**：`asc_mmad`，输入half/bf16/float/int8，输出float/int32
- **4-bit量化矩阵乘**：`asc_mmad_s4`，输入int4b_t，输出int32
- **MX格式矩阵乘**：`asc_mmad_mx`，输入fp8/fp4，输出float（950PR/950DT专用）

**详细接口说明**：参见 [Cube搬运接口](../../../../../api/context/c_api/cube_compute/)

本章系统阐述了C指针编程数据搬运与计算接口。C指针编程提供指令级透明可控的底层编程能力，函数与硬件指令一一对应、调用即执行，参数简洁直观。同步位置、内存分配、分块策略完全由开发者控制。数据搬运接口分为Vector搬运与Cube搬运两类，分别支撑向量算子与矩阵算子的数据流转。计算接口分为向量计算与矩阵计算两类，覆盖算术、比较、转换、规约、激活、矩阵乘等主流场景。Vector算子遵循「加载→计算→存储」三阶段模式，Cube算子遵循四阶段模式，开发者可按需选择同步接口简化同步控制。
