## 引言

数据搬运与计算是AI Core算子开发的两大核心操作，共同构成算子执行的数据流转与计算处理闭环。数据搬运解决「数据从哪里来、到哪里去」的问题，计算解决「数据如何处理」的问题，二者协同配合完成算子功能实现。本章旨在帮助开发者建立对C指针编程搬运与计算接口的系统化认知，重点阐述C指针编程的特点与优势，以及接口的分类体系与使用方法。全文遵循「编程特点—硬件架构—接口分类—标准流程」的递进逻辑展开。

## C指针编程接口的特点与核心优势

C指针编程是直接操作NPU硬件的C语言函数接口，提供指令级透明可控的底层编程能力。相比高抽象层次的API，C指针编程具有以下核心优势：

- **指令级透明可控**: 函数与硬件指令一一对应，调用即执行。调用`asc_add()`执行向量加法指令，调用`asc_copy_gm2ub()`执行数据搬运指令，调用`asc_mmad()`执行矩阵乘指令。无抽象封装、无运行时判断、无中间转换。同步位置、内存分配、分块策略完全由开发者决定，算子性能可达硬件峰值。
- **编程习惯无缝适配**: 函数命名直观（`asc_add`、`asc_copy_gm2ub`、`asc_mmad`），参数风格C化（指针、地址、长度），无需学习新对象类型，直接用C的方式写算子。开发者可直接操作内存地址、显式管理数据流转，符合C语言编程习惯。
- **精准问题定位**: 每条指令可见，可逐条追踪定位问题指令。同步是否到位、数据搬运是否越界、计算指令是否正确执行，均可追溯至具体指令，调试效率大幅提升。
- **类型支持丰富**: 支持half、float、bfloat16、int8、int16、int32等主流数据类型，以及fp8、fp4等新兴低精度格式（Ascend 950PR/950DT专用），覆盖AI算子开发的主流场景。
- **接口形式灵活**: 每类接口提供三种形式：常规接口（异步执行）、高维切分接口（支持复杂搬运模式）、同步接口（`_sync`后缀，内部自动等待），开发者可按需选择。

## 硬件底层支撑：流水线与存储架构
AI Core采用多流水线并行架构与多层级存储架构，数据搬运与计算指令由不同流水线承载，协同完成数据处理。
**流水线分工**：
- **MTE2**：数据搬入（GM→Local Memory），承载`asc_copy_gm2ub`、`asc_copy_gm2l1`等搬运指令
- **MTE3**：数据搬出（Local Memory→GM），承载`asc_copy_ub2gm`、`asc_copy_l0c2gm`等搬运指令
- **Vector**：向量计算，承载`asc_add`、`asc_mul`等计算指令
- **Cube**：矩阵计算，承载`asc_mmad`矩阵乘指令

**数据流转路径**：
- **Vector算子数据流**：`GM → UB → Vector计算 → UB → GM`
- **Cube算子数据流**：`GM → L1 → L0A/L0B → Cube计算 → L0C → GM`

> 📌 **提示**：数据搬运遵循「就近计算」原则，将数据搬运到距离计算单元最近的存储层级，最大限度减少搬运开销。

## 数据搬运接口：分类体系

数据搬运接口按计算单元分为**Vector搬运**与**Cube搬运**两大类，每类接口覆盖特定数据流转场景。

### Vector搬运接口
Vector搬运接口支撑GM与UB之间的数据流转，是Vector算子开发的基础。接口命名遵循「源→目标」格式（如`asc_copy_gm2ub`表示GM到UB搬运），参数简洁直观（dst、src、size）。
**接口分类**：
- **GM→UB搬运**：`asc_copy_gm2ub`，加载输入数据到UB
- **UB→GM搬运**：`asc_copy_ub2gm`，输出计算结果到GM
- **UB→UB搬运**：`asc_copy_ub2ub`，UB内部拷贝
- **UB→L1搬运**：`asc_copy_ub2l1`，为Cube准备数据
- **多维搬运**：`asc_ndim_copy_gm2ub`，多维度带填充搬运

**接口形式**：
- **常规接口**：`asc_copy_gm2ub(dst, src, size)`，异步执行，需配合同步接口
- **高维切分接口**：`asc_copy_gm2ub(dst, src, n_burst, len_burst, src_gap, dst_gap)`，支持复杂搬运模式
- **同步接口**：`asc_copy_gm2ub_sync(dst, src, size)`，内部自动等待搬运完成

**对齐要求**：UB地址需32字节对齐，GM地址需按数据类型对齐

---

### Cube搬运接口

Cube搬运接口支撑矩阵乘法的数据供给，涵盖GM→L1、L1→L0A/L0B、L0C→GM的完整路径。接口支持2D格式搬运、转置搬运、3D格式搬运等多种模式。

**接口分类**：
- **GM→L1搬运**：`asc_copy_gm2l1`，加载矩阵数据到L1
- **L1→L0A搬运**：`asc_copy_l12l0a`，加载左矩阵到L0A
- **L1→L0B搬运**：`asc_copy_l12l0b`，加载右矩阵到L0B
- **L0C→GM搬运**：`asc_copy_l0c2gm`，输出矩阵乘结果到GM
- **常量填充**：`asc_fill_l0a`、`asc_fill_l0b`，L0A/L0B常量填充

**接口特点**：
- 支持2D格式搬运（常规）、转置搬运（`_transpose`后缀）、3D格式搬运（卷积场景）
- 提供同步版本（`_sync`后缀）
- L0A/L0B地址需512字节对齐

> 📌 **提示**：同步接口（`_sync`后缀）在搬运完成后阻塞等待，确保数据就绪后再执行后续计算；非同步接口需配合`asc_sync_notify`/`asc_sync_wait`使用。

## 计算接口：向量与矩阵计算

计算接口分为向量计算和矩阵计算两类，分别由Vector流水线和Cube流水线执行。

### 向量计算接口

向量计算接口覆盖算术运算、比较运算、类型转换、规约运算、激活函数等场景，是算子开发的核心工具集。接口命名直观（`asc_add`表示向量加法），参数简洁（dst、src、count）。

**接口分类**：
- **算术运算**：`asc_add`、`asc_sub`、`asc_mul`、`asc_div`，逐元素算术运算
- **比较运算**：`asc_eq`、`asc_lt`、`asc_gt`，逐元素比较运算
- **类型转换**：`asc_float2half`、`asc_half2float`，类型转换（支持舍入模式）
- **规约运算**：`asc_reduce_max`、`asc_reduce_min`、`asc_reduce_sum`，规约计算
- **激活函数**：`asc_relu`、`asc_leakyrelu`、`asc_exp`、`asc_log`，激活函数
- **其他运算**：`asc_duplicate`、`asc_sqrt`、`asc_abs`，其他常用运算

**接口形式**：
- **常规接口**：`asc_add(dst, src0, src1, count)`，异步执行
- **高维切分接口**：支持repeat、block_stride、repeat_stride参数，适用于复杂数据布局
- **同步接口**：`asc_add_sync(dst, src0, src1, count)`，内部自动等待计算完成
- **标量接口**：`asc_add_scalar(dst, src, value, count)`，向量与标量运算

**类型支持**：half、float、int16、int32等主流类型

**对齐要求**：操作数地址需32字节对齐

---

### 矩阵计算接口

矩阵计算接口以`asc_mmad`为核心，支持多种数据类型与计算模式。接口参数直观（c_matrix、a_matrix、b_matrix、M、K、N），开发者可精细控制矩阵计算过程。

**接口分类**：
- **标准矩阵乘加**：`asc_mmad`，输入half/bf16/float/int8，输出float/int32
- **4-bit量化矩阵乘**：`asc_mmad_s4`，输入int4b_t，输出int32
- **MX格式矩阵乘**：`asc_mmad_mx`，输入fp8/fp4，输出float（950PR/950DT专用）
- **稀疏矩阵乘**：`asc_mmad_sparse`，输入int8_t，输出int32

**核心参数**：
- **c_matrix**：输出矩阵（L0C）
- **a_matrix**：左矩阵（L0A）
- **b_matrix**：右矩阵（L0B）
- **left_height**：左矩阵高度（M）
- **n_dim**：左矩阵宽度/右矩阵高度（K）
- **right_width**：右矩阵宽度（N）

**控制参数**：
- **c_matrix_init_val**：true时C=C+A×B，false时C=A×B
- **c_matrix_source**：配置C矩阵初始值来源（L0C或C2）
- **unit_flag**：分形级并行控制（计算完一个分形立即搬出）

**fp8支持**（Ascend 950PR/950DT专用）：
支持float8_e4m3、float8_e5m2等fp8格式输入，输出为float类型，适用于低精度推理场景。

## 标准流程：数据搬运与计算实践

### Vector算子标准流程

Vector算子遵循「加载→计算→存储」三阶段模式，数据在GM与UB之间流转：

```c
// ===== 第一步：加载输入 =====
asc_copy_gm2ub_sync(ub_in0, gm_in0, size);  // 搬入输入数据1
asc_copy_gm2ub_sync(ub_in1, gm_in1, size);  // 搬入输入数据2

// ===== 第二步：执行计算 =====
asc_add(ub_out, ub_in0, ub_in1, size);  // 向量加法

// ===== 第三步：存储结果 =====
asc_copy_ub2gm_sync(gm_out, ub_out, size);  // 搬出结果数据
```

> 📌 **提示**：同步接口（`_sync`后缀）简化了同步控制，内部自动等待操作完成。若使用非同步接口，需在搬运/计算后插入`asc_sync_notify`/`asc_sync_wait`确保数据依赖关系。

---

### Cube算子标准流程

Cube算子遵循「加载矩阵→搬运到L0→执行矩阵乘→输出结果」四阶段模式，数据在GM、L1、L0A/L0B、L0C之间流转：

```c
// ===== 第一步：加载矩阵到L1 =====
asc_copy_gm2l1_sync(l1_a, gm_a, size_a);  // 搬入矩阵A
asc_copy_gm2l1_sync(l1_b, gm_b, size_b);  // 搬入矩阵B

// ===== 第二步：搬运到L0A/L0B =====
asc_copy_l12l0a_sync(l0a, l1_a, m_start, k_start, m_step, k_step, src_stride, dst_stride);
asc_copy_l12l0b_sync(l0b, l1_b, m_start, k_start, m_step, k_step, src_stride, dst_stride);

// ===== 第三步：执行矩阵乘 =====
asc_mmad_sync(l0c, l0a, l0b, m, k, n, unit_flag, k_align, c_source, c_init);

// ===== 第四步：输出结果 =====
asc_copy_l0c2gm_sync(gm_c, l0c, size_c);  // L0C→GM
```
