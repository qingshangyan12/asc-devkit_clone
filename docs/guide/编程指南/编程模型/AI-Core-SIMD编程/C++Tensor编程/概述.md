## 引言

AscendC是面向LocalTensor与GlobalTensor的编程范式，核心设计理念是将内存地址抽象为Tensor对象，开发者通过Tensor进行数据搬运、计算操作、同步管理。相比C指针编程的直接地址操作，Tensor编程隐藏内存地址细节，提供更高级的抽象层次，降低开发复杂度。

AscendC提供基础能力接口，支持LocalTensor/GlobalTensor定义、数据搬运、向量计算、矩阵乘、同步等核心功能。在此基础上，对LocalTensor进行扩展，引入Layout概念描述数据布局，实现类型安全、编译期确定的张量操作，并提供Copy/Mmad Atom、零开销切片等扩展能力。

本章旨在帮助开发者建立对AscendC编程范式的整体认知，理解Tensor编程的设计理念、基础能力与扩展能力、接口选择建议。全文遵循「设计理念—Tensor抽象—基础能力—扩展能力—接口选择」的递进逻辑展开。

## 设计理念：面向Tensor的编程抽象

### Tensor编程的核心思想

Tensor编程将内存地址抽象为Tensor对象，开发者不再直接操作地址，而是通过Tensor进行数据管理。LocalTensor对应片上内存（UB、L1、L0A、L0B、L0C等），GlobalTensor对应全局内存（GM），Tensor携带数据类型、形状信息、内存位置等属性，接口调用时自动推断操作参数。

```cpp
// Tensor编程：通过Tensor对象操作
LocalTensor<half> ubTensor;  // UB上的half类型Tensor
GlobalTensor<half> gmTensor; // GM上的half类型Tensor

DataCopy(ubTensor, gmTensor, size);  // Tensor对象传递
Add(dstTensor, src0Tensor, src1Tensor);  // Tensor计算
```

### Tensor编程的优势

- **降低开发复杂度**：隐藏内存地址细节，Tensor携带数据类型和形状信息，接口自动推断操作参数。
- **提升代码可读性**：Tensor命名表达数据语义，接口调用直观，参数通过Tensor对象传递。
- **扩展能力优化**：Layout编译期确定实现类型安全，Slice/Tile零开销切片，Atom设计简化参数配置。

## 接口体系：基础能力与扩展能力

AscendC的Tensor编程分为基础能力与扩展能力两个层次，共同支撑算子开发：

### 基础能力接口

基础能力接口提供Tensor编程的核心功能：Tensor定义（LocalTensor对应片上存储，GlobalTensor对应全局存储）、数据搬运（DataCopy、Copy、DataCopyPad等）、向量计算（Add、Sub、Mul、Div、Reduce等）、矩阵乘（LoadData、Mmad、Fill等）、同步机制（PipeBarrier、SetFlag/WaitFlag等）、内存管理（TPipe、TQue队列管理）。

**接口特点**：参数通过结构体传递，内存位置通过TPosition枚举表达，形状信息运行期设置，同步时机显式控制。

### LocalTensor扩展能力

在基础能力基础上，对LocalTensor进行扩展，引入Layout概念将数据布局抽象为类型，Shape和Stride编译期确定实现类型安全；引入Copy/Mmad Atom通过Operation类型显式表达内存路径，简化参数配置；提供零开销切片（Slice/Tile）布局变换，无数据拷贝；采用Operation驱动隐式同步，减少手动同步调用。

**扩展特点**：类型安全（编译期Layout校验）、零开销抽象（Slice/Tile无拷贝）、Atom-Traits设计（编译期+运行期混合配置）、隐式同步简化开发。

## 基础能力：Tensor定义与核心接口

### Tensor定义方式

**LocalTensor定义**：通过TPosition枚举表达内存位置（UB、L1、L0A等），形状信息通过ShapeInfo运行期设置。

```cpp
LocalTensor<half> ubTensor;  // UB上的half类型Tensor
```

**GlobalTensor定义**：通过SetGlobalBuffer设置GM指针，形状信息同样运行期设置。

```cpp
GlobalTensor<half> gmTensor;
gmTensor.SetGlobalBuffer((__gm__ half*)gmBuffer, bufferSize);
```

### 数据搬运接口

数据搬运接口提供连续搬运和非连续搬运两种接口形式。连续搬运模式通过count计数直接搬运连续数据，适用于简单场景；非连续搬运模式通过DataCopyParams参数结构体配置块数量、块长度、块间隙等参数，适用于高维切分、带间隙搬运等复杂场景。

```cpp
// 连续搬运模式：直接搬运count个元素
template <typename T>
__aicore__ inline void DataCopy(const LocalTensor<T>& dst, const GlobalTensor<T>& src, 
                                 const uint32_t count);

// 非连续搬运模式：参数结构体配置块切分和间隙
template <typename T>
__aicore__ inline void DataCopy(const LocalTensor<T>& dst, const GlobalTensor<T>& src, 
                                 const DataCopyParams& repeatParams);

// 参数结构体
struct DataCopyParams {
    uint16_t blockCount;    // 块数量
    uint16_t blockLen;      // 块长度
    uint16_t srcGap;        // 源块间隙
    uint16_t dstGap;        // 目标块间隙
};
```

### 计算接口

**向量计算**：支持Add、Sub、Mul、Div、Reduce等算术、逻辑、规约运算，提供简化模式（count计数）和高维切分模式（mask掩码+repeatParams参数）两种形式，简化模式适用于连续计算场景，高级模式适用于高维切分、带掩码的复杂计算场景。

```cpp
// 简化模式：连续计算count个元素
template <typename T>
__aicore__ inline void Add(const LocalTensor<T>& dst, const LocalTensor<T>& src0, 
                            const LocalTensor<T>& src1, const int32_t& count);

// 高级模式：带掩码的高维切分计算
template <typename T>
__aicore__ inline void Add(const LocalTensor<T>& dst, const LocalTensor<T>& src0, 
                            const LocalTensor<T>& src1, uint64_t mask[], const uint8_t repeatTime,
                            const BinaryRepeatParams& repeatParams);
```

**矩阵乘**：LoadData将矩阵数据从L1加载到L0A/L0B供Cube计算单元使用，Mmad执行矩阵乘累加操作，参数结构体指定矩阵维度（M、N、K）和累加模式（cmatrixInitVal控制是否初始化为0）。

```cpp
// LoadData: 加载矩阵到L0A/L0B
template <typename T>
__aicore__ inline void LoadData(const LocalTensor<T>& dst, const LocalTensor<T>& src, 
                                 const LoadData2DParams& loadDataParams);

// Mmad: 矩阵乘累加
template <typename T, typename U, typename S>
__aicore__ inline void Mmad(const LocalTensor<T>& dst, const LocalTensor<U>& fm, 
                              const LocalTensor<S>& filter, const MmadParams& mmadParams);

// 参数结构体
struct MmadParams {
    int32_t m;              // 左矩阵行数
    int32_t n;              // 右矩阵列数
    int32_t k;              // 左矩阵列数
    bool cmatrixInitVal;    // C矩阵初始值（true:初始化为0，false:累加模式）
};
```

## 扩展能力：Layout抽象与Atom设计

### LocalTensor扩展方式

扩展LocalTensor采用Engine-Layout分离设计：Shape和Stride编译期确定，通过MakeTensor工厂函数创建。

```cpp
auto tensor = MakeTensor(ubPointer, MakeShape(128, 64));  // Shape编译期确定
```

### Layout核心概念

Layout是扩展能力的核心抽象，解决多维数据访问的索引计算问题。当开发者访问一个多维数组元素时，需要知道两个信息：元素在哪个位置（坐标），以及该位置对应哪个内存地址（索引）。Layout将这两个问题分离——Shape描述"元素在哪里"（逻辑坐标），Stride描述"内存在哪里"（物理偏移），Layout自动完成坐标到索引的转换，开发者只需关注逻辑坐标，无需手动计算地址偏移。

**Layout的核心价值**：抽象内存排列细节，让开发者专注于逻辑描述而非地址计算；支持层次化表达，自然描述分块计算的数据布局；编译期类型安全，Shape和Stride在编译时确定，避免运行期布局错误。

### Layout布局表达示例

**平铺布局**：Layout最基础的表达形式，通过单一层次的Shape和Stride描述任意维度的连续数据排列，支持行主序、列主序等多种排列模式，坐标直接线性映射到索引。

```cpp
// 平铺布局：128×64矩阵，行主序
auto shape = MakeShape(128, 64);      // 坐标空间：(m, n)
auto stride = MakeStride(64, 1);      // 索引映射：m*64 + n
auto layout = MakeLayout(shape, stride);

// 坐标到索引映射
layout(10, 20);  // 索引 = 10*64 + 20 = 660
layout(660);     // 1-D坐标也可接受，自动转换为等效的(m,n)坐标
```

**层次化布局**：通过嵌套的Shape和Stride实现多层次的布局描述，外层描述块级结构（块的数量和块间步长），内层描述块内结构（块内维度和块内步长），自然表达分块计算中带有分形的矩阵块排列。

```cpp
// 层次化布局：128×64矩阵分为8×4个16×16的块
auto shape = MakeShape(MakeShape(8, 16), MakeShape(4, 16));
// 坐标空间：(块坐标, 块内坐标) = ((block_m, elem_m), (block_n, elem_n))

auto stride = MakeStride(MakeStride(64, 1), MakeStride(16, 1));
// 外层步长：块间排列，内层步长：块内排列

auto layout = MakeLayout(shape, stride);

// 层次化坐标访问
layout(MakeCoord(2, 5), MakeCoord(3, 10));  
// 索引 = (块偏移) + (块内偏移) = (2*64+3*16) + (5*1+10*1) = 178

// 也可使用2-D坐标，自动转换为层次化坐标
layout(37, 58);  // 等效于 ((37/16, 37%16), (58/16, 58%16))
```

**分形布局**：为简化AscendC编程中遇到的特有分型布局（如NZ、ZZ等），提供MakeFrameLayout接口自动生成符合硬件要求的Shape和Stride，避免手动配置复杂分形参数，减少配置错误。

```cpp
// NZ布局：列分块行连续，Cube矩阵乘标准输入布局
auto nzLayout = MakeFrameLayout<NZLayoutPtn>(128, 64);
// 自动生成分形Shape和Stride，无需手动计算分形块排列

// LayoutPattern优势：自动适配硬件分形要求，减少配置错误
```

### Copy/Mmad Atom

引入Copy/Mmad Atom，通过Operation类型显式表达内存路径：

```cpp
// 扩展能力：Copy Atom
auto copyAtom = MakeCopy<CopyGM2UB>();  // Operation显式表达内存路径
Copy(copyAtom, gmTensor, ubTensor);
```

**CopyOperation类型**：CopyGM2UB（GM→UB）、CopyUB2GM（UB→GM）、CopyGM2L1（GM→L1）、CopyL12L0A（L1→L0A）等。


### 零开销切片

Slice和Tile是Layout提供的零开销数据视图操作，通过调整Shape和Stride实现数据切分，无需实际数据拷贝。Slice从指定起始坐标切取子张量，Tile将张量均匀切分为多个块，两者仅改变Layout的坐标映射关系，底层内存指针保持不变，实现真正的零开销抽象。

**零开销原理**：Slice/Tile操作只创建新的Layout对象，新Layout的Shape表示切分后的维度，Stride调整坐标偏移，原Tensor的内存指针被复用，无任何数据移动或拷贝开销。

```cpp
auto tensor = MakeTensor(ubPointer, MakeShape(128, 64));

// Slice：从坐标(10,20)开始切取32×16的子张量
auto sliceTensor = tensor.Slice(MakeCoord(10, 20), MakeShape(32, 16));  
// 新Layout的起始偏移自动调整为(10,20)，Shape变为(32,16)

// Tile：将张量均匀切分为多个块
auto tiledTensor = tensor.Tile(MakeShape(2, 4));  
// 将128×64张量切分为2×4个块，每块大小为64×16
```

## 接口选择建议

基础能力适用于运行期灵活性需求、细粒度同步控制、快速原型开发场景；扩展能力适用于编译期类型安全、多种布局格式、切片分块操作、Cube算子开发场景，复杂同步场景可配合基础能力同步接口使用。

## 小结

本章阐述了AscendC编程范式的整体体系：AscendC是面向LocalTensor与GlobalTensor的编程范式，将内存地址抽象为Tensor对象，隐藏地址细节；基础能力接口提供Tensor定义、数据搬运、计算、同步、内存管理等核心功能；扩展能力引入Layout概念，提供编译期类型安全、LayoutPattern分形布局、Copy/Mmad Atom、零开销切片等能力；开发者可根据场景选择基础能力或扩展能力，复杂场景可混合使用。
