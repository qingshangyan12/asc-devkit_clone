## 引言

AscendC采用流水线异步并行架构，数据搬入、计算、数据搬出分别由MTE2、Vector/Cube、MTE3流水线承载，流水线之间需要同步协调确保数据依赖关系得到满足。基础能力提供显式同步接口（PipeBarrier、SetFlag/WaitFlag），开发者精确控制同步时机；扩展能力采用隐式同步设计，通过Copy/Mmad Operation类型隐式表达同步需求。

本章旨在帮助开发者建立对AscendC同步机制的系统化认知，理解流水线异步原理，掌握显式同步与隐式同步的使用方法。全文遵循「硬件原理—数据依赖风险—基础能力显式同步—扩展能力隐式同步—混合使用」的递进逻辑展开。

## 硬件底层支撑：流水线异步执行

AI Core采用多条流水线异步并行架构，各流水线独立推进指令序列：

**表 1**  AI Core流水线分类

| 流水线 | 功能 | 典型操作 |
|--------|------|----------|
| **MTE2** | 数据搬入（GM→Local Memory） | DataCopy(GM→UB/L1) |
| **MTE3** | 数据搬出（Local Memory→GM） | DataCopy(UB/L0C→GM) |
| **MTE1** | L1→L0搬运 | LoadData(L1→L0A/L0B) |
| **Vector** | 向量计算 | Add、Mul、Reduce |
| **Cube** | 矩阵计算 | Mmad |

### 异步执行的并行优势

多条流水线异步并行执行带来显著优势：

**并行优势**：数据搬入（MTE2）和计算可以同时进行，搬入下一块数据时，计算单元正在处理上一块数据，大幅提升吞吐率。

### 数据依赖风险

异步执行引入数据依赖风险：

- **MTE2 → Vector/Cube**：计算依赖搬入的数据，数据未就绪时计算会出错
- **Vector/Cube → MTE3**：搬出依赖计算的结果，计算未完成时搬出会输出错误数据

**举例说明**：

```cpp
// 错误示例：缺少同步
DataCopy(ubTensor, gmTensor, size);  // MTE2开始搬运
Add(dstTensor, srcTensor, size);     // Vector立即开始计算（可能读取未就绪数据）
DataCopy(gmTensor, ubTensor, size);  // MTE3立即搬出（可能输出错误结果）
```

> 📌 **提示**：同步的核心目的是在数据依赖节点插入等待，确保"生产者"完成后再让"消费者"开始。

## basic_api显式同步：精确控制同步时机

### PipeBarrier流水线屏障

PipeBarrier在流水线内部插入屏障，确保该流水线前序指令完成：

```cpp
template <pipe_t pipe>
__aicore__ inline void PipeBarrier();

// 使用示例
PipeBarrier<PIPE_MTE2>();  // MTE2流水线屏障
PipeBarrier<PIPE_V>();     // V流水线屏障
PipeBarrier<PIPE_MTE3>();  // MTE3流水线屏障
```

**适用场景**：同一流水线内部指令依赖，确保前序指令完成。

### SetFlag/WaitFlag事件同步

SetFlag/WaitFlag实现流水线间的事件同步，类似流水线之间的"握手"：

- **SetFlag**：源流水线完成任务后，向目标流水线发送"就绪信号"
- **WaitFlag**：目标流水线收到信号前阻塞等待，收到信号后继续执行

```cpp
template <HardEvent event>
__aicore__ inline void SetFlag(int32_t eventID);

template <HardEvent event>
__aicore__ inline void WaitFlag(int32_t eventID);
```

**HardEvent事件类型**：

| HardEvent | 含义 |
|-----------|------|
| MTE2_S | MTE2通知Scalar |
| S_MTE2 | Scalar等待MTE2 |
| MTE2_V | MTE2通知Vector |
| V_MTE2 | Vector等待MTE2 |
| V_MTE3 | Vector通知MTE3 |
| MTE3_V | MTE3等待Vector |
| S_V | Scalar通知Vector |
| V_S | Vector等待Scalar |

### 标准同步模式：Vector算子

Vector算子遵循「搬入 → 同步 → 计算 → 同步 → 搬出」流程：

```cpp
// ===== 第一步：数据搬入 =====
DataCopy(ubIn, gmIn, size);  // MTE2搬运

// ===== 第二步：搬入同步 =====
SetFlag<HardEvent::MTE2_V>(eventID);  // MTE2通知V：数据就绪
WaitFlag<HardEvent::MTE2_V>(eventID); // V等待MTE2

// ===== 第三步：计算执行 =====
Add(ubOut, ubIn0, ubIn1, size);  // Vector计算

// ===== 第四步：计算同步 =====
SetFlag<HardEvent::V_MTE3>(eventID);  // V通知MTE3：计算完成
WaitFlag<HardEvent::V_MTE3>(eventID); // MTE3等待V

// ===== 第五步：数据搬出 =====
DataCopy(gmOut, ubOut, size);  // MTE3搬出
```

### 标准同步模式：Cube算子

Cube算子遵循「搬入 → 同步 → L1搬运 → 同步 → Mmad → 同步 → 搬出」流程：

```cpp
// ===== 第一步：GM→L1搬运 =====
DataCopy(l1A, gmA, sizeA);
DataCopy(l1B, gmB, sizeB);
SetFlag<HardEvent::MTE2_MTE1>(eventID0);
WaitFlag<HardEvent::MTE2_MTE1>(eventID0);

// ===== 第二步：L1→L0A/L0B搬运 =====
LoadData(l0a, l1A, loadDataParams);
LoadData(l0b, l1B, loadDataParams);
SetFlag<HardEvent::MTE1_C>(eventID1);
WaitFlag<HardEvent::MTE1_C>(eventID1);

// ===== 第三步：Mmad =====
Mmad(l0c, l0a, l0b, mmadParams);
SetFlag<HardEvent::C_MTE3>(eventID2);
WaitFlag<HardEvent::C_MTE3>(eventID2);

// ===== 第四步：L0C→GM =====
DataCopy(gmC, l0c, sizeC);
```

### 跨核同步

多核协作场景使用跨核同步接口：

```cpp
// 跨核设置标志
template <uint8_t modeId, pipe_t pipe>
__aicore__ inline void CrossCoreSetFlag(uint16_t flagId);

// 跨核等待标志
template <uint8_t modeId = 0, pipe_t pipe = PIPE_S>
__aicore__ inline void CrossCoreWaitFlag(uint16_t flagId);

// 全核同步
template <bool isAIVOnly = true>
__aicore__ inline void SyncAll(const GlobalTensor<int32_t>& gmWorkspace, 
                                const LocalTensor<int32_t>& ubWorkspace, 
                                const int32_t usedCores = 0);
```

### 同步要点总结

| 同步节点 | 同步方向 | 目的 |
|----------|----------|------|
| 搬入后 | MTE2 → Vector/Cube | 确保计算使用已就绪数据 |
| L1搬运后 | MTE1 → Cube | 确保Mmad使用已就绪矩阵 |
| 计算后 | Vector/Cube → MTE3 | 确保搬出使用正确结果 |

**正确性检查**：
- 每个数据依赖节点是否都有对应的SetFlag/WaitFlag
- SetFlag和WaitFlag是否成对出现、参数一致
- eventID是否正确区分不同同步事件

## 扩展能力隐式同步：Operation驱动同步推断

扩展能力通过Copy/Mmad Operation类型隐式表达同步需求：

- **CopyOperation**：携带内存路径信息（GM→L1、L1→UB等），编译器推断流水线依赖
- **MmadOperation**：携带计算单元信息，编译器推断计算完成时机
- **编译器调度**：根据Operation类型和内存路径，自动插入同步指令

**隐式同步原理**：

```cpp
// CopyOperation携带内存路径
CopyGM2UB  // GM→UB：MTE2流水线
CopyL12L0A // L1→L0A：MTE1流水线

// 编译器根据Operation类型推断同步
auto copyAtom = MakeCopy<CopyGM2UB>();
Copy(copyAtom, gmTensor, ubTensor);  // 编译器自动处理MTE2→V同步
```

### CopyOperation与内存路径

**Vector CopyOperation**：

| Operation | 内存路径 | 流水线 |
|----------|---------|--------|
| `CopyGM2UB` | GM → UB | MTE2 |
| `CopyUB2GM` | UB → GM | MTE3 |
| `CopyUB2L1` | UB → L1 | MTE2 |

**Cube CopyOperation**：

| Operation | 内存路径 | 流水线 |
|----------|---------|--------|
| `CopyGM2L1` | GM → L1 | MTE2 |
| `CopyL12L0A` | L1 → L0A | MTE1 |
| `CopyL12L0B` | L1 → L0B | MTE1 |
| `CopyL0C2GM` | L0C → GM | MTE3 |
| `CopyL0C2UB` | L0C → UB | MTE3 |

### Vector算子隐式同步

扩展能力的Vector算子同步由编译器自动处理：

```cpp
// ===== 创建Copy Atom =====
auto copyGM2UB = MakeCopy<CopyGM2UB>();
auto copyUB2GM = MakeCopy<CopyUB2GM>();

// ===== 数据搬入（隐式同步）=====
Copy(copyGM2UB, gmTensor, ubTensor);  // 编译器自动处理MTE2→V同步

// ===== Vector计算 =====
Add(ubDstTensor, ubSrc0Tensor, ubSrc1Tensor);

// ===== 数据搬出（隐式同步）=====
Copy(copyUB2GM, ubTensor, gmTensor);  // 编译器自动处理V→MTE3同步
```

### Cube算子隐式同步

扩展能力的Cube算子同步由编译器根据Operation类型自动处理：

```cpp
// ===== 创建Copy Atom =====
auto copyGM2L1 = MakeCopy<CopyGM2L1>();
auto copyL12L0A = MakeCopy<CopyL12L0A>();
auto copyL12L0B = MakeCopy<CopyL12L0B>();
auto copyL0C2GM = MakeCopy<CopyL0C2GM>();

// ===== GM → L1（隐式同步）=====
Copy(copyGM2L1, gmTensorA, l1TensorA);
Copy(copyGM2L1, gmTensorB, l1TensorB);

// ===== L1 → L0A/L0B（隐式同步）=====
Copy(copyL12L0A, l1TensorA, l0aTensor);
Copy(copyL12L0B, l1TensorB, l0bTensor);

// ===== Mmad =====
auto mmadAtom = MakeMmad<MmadOperation>();
Mmad(mmadAtom, l0aTensor, l0bTensor, l0cTensor);

// ===== L0C → GM（隐式同步）=====
Copy(copyL0C2GM, l0cTensor, gmTensorC);
```

### 隐式同步的优势与局限

**优势**：
- **简化开发**：无需手动调用SetFlag/WaitFlag
- **编译器优化**：编译器可根据Operation依赖关系优化同步时机
- **类型安全**：Operation类型编译期确定，避免路径错误

**局限**：
- **控制粒度**：无法精确控制同步时机（如提前通知、延迟等待）
- **复杂场景**：多流水线交叉依赖场景可能需要显式同步
- **跨核同步**：核间同步仍需basic_api接口

## 混合使用：扩展能力配合基础能力同步

复杂场景下，扩展能力可配合基础能力显式同步接口：

**场景一：提前通知优化**

```cpp
// 扩展能力搬运
auto copyAtom = MakeCopy<CopyGM2UB>();
Copy(copyAtom, gmTensor, ubTensor);

// basic_api提前通知（不等MTE2完全完成）
SetFlag<HardEvent::MTE2_V>(eventID);

// Vector等待通知后开始
WaitFlag<HardEvent::MTE2_V>(eventID);

// 计算依赖已搬运数据
Add(ubDstTensor, ubSrc0Tensor, ubSrc1Tensor);
```

**场景二：多流水线交叉依赖**

```cpp
// 流水线1：搬入A
auto copyGM2UB = MakeCopy<CopyGM2UB>();
Copy(copyGM2UB, gmTensorA, ubTensorA);
SetFlag<HardEvent::MTE2_V>(eventID0);

// 流水线2：搬入B（并行）
Copy(copyGM2UB, gmTensorB, ubTensorB);
SetFlag<HardEvent::MTE2_V>(eventID1);

// Vector等待两个搬入完成
WaitFlag<HardEvent::MTE2_V>(eventID0);
WaitFlag<HardEvent::MTE2_V>(eventID1);

// 计算依赖A和B
Add(ubDstTensor, ubTensorA, ubTensorB);
```

**场景三：跨核同步**

跨核同步需使用basic_api接口：

```cpp
// 扩展能力数据搬运
auto copyAtom = MakeCopy<CopyGM2UB>();
Copy(copyAtom, gmTensor, ubTensor);

// basic_api跨核同步
CrossCoreSetFlag<MODE_ID>(flagId);
CrossCoreWaitFlag<MODE_ID>(flagId);
```

## 同步最佳实践

### 最佳实践一：简单场景优先使用隐式同步

扩展能力的隐式同步已覆盖大多数简单场景：

```cpp
// 推荐：隐式同步
auto copyAtom = MakeCopy<CopyGM2UB>();
Copy(copyAtom, gmTensor, ubTensor);
Add(ubDstTensor, ubSrc0Tensor, ubSrc1Tensor);
auto copyUB2GM = MakeCopy<CopyUB2GM>();
Copy(copyUB2GM, ubTensor, gmTensor);
```

### 最佳实践二：复杂场景配合显式同步

多流水线交叉依赖、提前通知优化等场景使用显式同步：

```cpp
// 复杂场景：显式同步
auto copyAtom = MakeCopy<CopyGM2UB>();
Copy(copyAtom, gmTensorA, ubTensorA);
SetFlag<HardEvent::MTE2_V>(eventID0);
Copy(copyAtom, gmTensorB, ubTensorB);
SetFlag<HardEvent::MTE2_V>(eventID1);
WaitFlag<HardEvent::MTE2_V>(eventID0);
WaitFlag<HardEvent::MTE2_V>(eventID1);
Add(ubDstTensor, ubTensorA, ubTensorB);
```

### 最佳实践三：核间同步使用basic_api

核间协作场景使用basic_api跨核同步接口：

```cpp
// 核间同步
CrossCoreSetFlag<MODE_ID>(flagId);
CrossCoreWaitFlag<MODE_ID>(flagId);
```

## 小结

本章阐述了AscendC同步机制：AI Core采用流水线异步并行架构，异步执行带来并行优势但也引入数据依赖风险；基础能力提供显式同步接口（PipeBarrier、SetFlag/WaitFlag），开发者精确控制同步时机；扩展能力采用隐式同步设计，通过Copy/Mmad Operation类型隐式表达同步需求，编译器自动推断；复杂场景下扩展能力可配合基础能力显式同步接口使用。
