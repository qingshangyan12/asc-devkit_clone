## 引言

AI Core采用多条流水线异步并行架构，数据搬入、计算、数据搬出分别由MTE2、Vector/Cube、MTE3流水线承载。流水线异步执行带来天然并行优势，但也引入数据依赖风险：计算必须在数据就绪后执行，搬出必须在计算完成后进行。同步机制是协调流水线协作、确保数据依赖关系得到满足的关键技术。

本章旨在帮助开发者建立对C指针编程同步机制的核心认知，理解流水线异步执行原理、掌握同步接口的使用方法、遵循标准同步模式。

## 硬件原理：多条流水线异步执行

AI Core内部包含多条流水线，各流水线并行执行、异步协作：

**表 1**  AI Core流水线分类

| 流水线 | 功能 | 典型指令 |
|--------|------|----------|
| **MTE2** | 数据搬入（GM→Local Memory） | `asc_copy_gm2ub`、`asc_copy_gm2l1` |
| **MTE3** | 数据搬出（Local Memory→GM） | `asc_copy_ub2gm`、`asc_copy_l0c2gm` |
| **Vector** | 向量计算 | `asc_add`、`asc_mul` |
| **Cube** | 矩阵计算 | `asc_mmad` |

流水线之间**异步并行执行**，各自独立推进指令序列。异步执行带来效率优势，但也引入数据依赖风险：如果Vector在MTE2搬运完成前开始计算，会使用未就绪数据，导致结果错误。

### 数据依赖关系

流水线之间存在明确的数据依赖：

- **MTE2 → Vector/Cube**：计算依赖搬入的数据，必须同步确保数据就绪
- **Vector/Cube → MTE3**：搬出依赖计算的结果，必须同步确保计算完成

> 📌 **提示**：同步的核心目的是确保数据依赖关系得到满足。同步缺失会导致结果错误，同步冗余会降低并行效率。

## 同步接口：流水线协作机制

C指针编程提供流水线同步接口，用于协调两条流水线之间的数据依赖。

### 核心同步接口

**表 1**  流水线同步接口

| 接口 | 功能 |
|------|------|
| `asc_sync_notify(pipe, tpipe, id)` | 发送同步信号：源流水线通知目标流水线数据已就绪 |
| `asc_sync_wait(pipe, tpipe, id)` | 等待同步信号：目标流水线等待源流水线的通知 |
| `asc_sync()` | 全局同步：等待所有流水线指令完成 |

**参数说明**：
- **pipe**：源流水线标识（PIPE_MTE2、PIPE_MTE3、PIPE_V等）
- **tpipe**：目标流水线标识
- **id**：事件ID（EVENT_ID0~EVENT_ID7），用于区分不同同步事件

### 自动同步接口

数据搬运接口提供自动同步版本（_sync后缀），接口内部自动等待完成：

```c
// ===== 自动同步版本：内部自动等待 =====
asc_copy_gm2ub_sync(x_local, x_gm, 256);

// ===== 手动同步版本：需显式调用同步接口 =====
asc_copy_gm2ub(x_local, x_gm, 256);  // 搬入数据
asc_sync_notify(PIPE_MTE2, PIPE_V, EVENT_ID0);  // MTE2通知V
asc_sync_wait(PIPE_MTE2, PIPE_V, EVENT_ID0);    // V等待MTE2
```

> 📌 **提示**：自动同步接口简化开发，但会引入冗余等待。性能敏感场景建议使用手动同步。

### 核间同步接口

多AI Core协作场景（如跨核数据交换、多核矩阵乘），需要核间同步协调多个AI Core的执行进度。

**表 2**  核间同步接口

| 接口 | 功能 |
|------|------|
| `asc_sync_block_arrive(pipe, flag_id)` | 核间到达信号：当前核到达同步点 |
| `asc_sync_block_wait(pipe, flag_id)` | 核间等待信号：等待其他核到达同步点 |
| `asc_sync_intra_arrive(pipe, sync_id)` | 核内到达信号（Ascend 3510） |
| `asc_sync_intra_wait(pipe, sync_id)` | 核内等待信号（Ascend 3510） |

> 📌 **提示**：大多数算子在SPMD模型下各核独立处理数据分片，无需核间同步。仅跨核协作场景需要使用。

### Mutex接口

多核共享资源场景（如共享L1区域），需要互斥锁保护资源访问（Ascend 3510）。

**表 3**  Mutex接口

| 接口 | 功能 |
|------|------|
| `asc_lock(pipe, mutex_id, mode)` | 互斥锁锁定：获取共享资源访问权 |
| `asc_unlock(pipe, mutex_id, mode)` | 互斥锁解锁：释放共享资源访问权 |

**执行模式**：
- `ASC_LOCK_BLOCK`：阻塞模式，等待锁释放（默认）
- `ASC_LOCK_NON_BLOCK`：非阻塞模式，立即返回锁定状态

```c
// ===== 阻塞模式获取锁 =====
asc_lock(PIPE_V, MUTEX_ID0, ASC_LOCK_BLOCK);  // 获取互斥锁

// ===== 访问共享资源 =====
asc_add(shared_buffer, x_local, y_local);  // 向量加法

// ===== 释放锁 =====
asc_unlock(PIPE_V, MUTEX_ID0, ASC_LOCK_BLOCK);  // 释放互斥锁
```

## 同步模式：标准流程

Vector算子的标准同步模式遵循「搬入 → 同步 → 计算 → 同步 → 搬出」流程：

```c
// ===== 数据搬入 =====
asc_copy_gm2ub(x_local, x_gm, 256);  // 搬入输入数据

// ===== 搬入同步：MTE2通知Vector，Vector等待MTE2 =====
asc_sync_notify(PIPE_MTE2, PIPE_V, EVENT_ID0);  // MTE2通知V
asc_sync_wait(PIPE_MTE2, PIPE_V, EVENT_ID0);    // V等待MTE2

// ===== Vector计算 =====
asc_add(z_local, x_local, y_local);  // 向量加法

// ===== 计算同步：Vector通知MTE3，MTE3等待Vector =====
asc_sync_notify(PIPE_V, PIPE_MTE3, EVENT_ID0);  // V通知MTE3
asc_sync_wait(PIPE_V, PIPE_MTE3, EVENT_ID0);    // MTE3等待V

// ===== 数据搬出 =====
asc_copy_ub2gm(z_gm, z_local, 256);  // 搬出结果数据
```

### 同步要点

- **同步位置**：搬入完成后通知计算流水线，计算完成后通知搬出流水线
- **同步缺失**：计算使用未就绪数据，结果错误
- **同步冗余**：增加不必要的等待，降低性能

## 小结

本章阐述了C指针编程同步机制的核心要点：AI Core多条流水线异步并行执行，必须在数据依赖节点插入同步确保数据就绪；核心同步接口为`asc_sync_notify/wait`，开发者需遵循标准同步模式；同步缺失导致错误，同步冗余降低性能。
