# AscendC CAPI编程概述<a name="ZH-CN_TOPIC_0000002554090610"></a>

如[编程模型概述](../编程模型概述.md)章节所述，Ascend C 为 AI Core 提供了 SIMD 编程路径。**AscendC CAPI** 是 SIMD 编程的底层接口，直接映射 NPU 硬件指令，提供对向量处理单元、矩阵运算单元、本地存储等硬件资源的精细控制能力。本章节从背景、概念、价值、入门四个维度，帮助新员工快速理解 CAPI 的核心要点。

## 背景：为什么需要 CAPI？

CAPI 采用 C 语言函数接口设计，具有底层接口的天然优势：

**优势一：直接映射硬件指令**

CAPI 函数与硬件指令一一对应：
- `asc_add()` → 单条向量加法指令 `vadd`
- `asc_copy()` → 单条数据搬运指令 `copy_gm2ub`
- `asc_matmul()` → 矩阵乘指令

每条 CAPI 函数调用，直接执行对应的硬件指令，无中间转换开销。

**优势二：零抽象层开销**

CAPI 是 C 语言函数接口，天然零抽象层：
- **无运行时决策**：编译期确定执行路径
- **无中间转换**：函数调用直接映射硬件指令
- **零开销抽象**：函数调用直接执行硬件指令，无额外开销

**优势三：精细硬件控制**

CAPI 提供对硬件资源的精细控制：
- **硬件事件同步**：通过`asc_sync_notify`、`asc_sync_wait` 支持细粒度同步
- **内存地址控制**：通过数组的方式静态分配 UB/L1/L0 地址，精确控制内存布局

## 什么是 CAPI？

### 一句话定义

**CAPI**是 **直接操作 NPU 硬件的 C 语言函数接口**。

### CAPI 的定位

CAPI 是底层 C 语言函数接口，核心定位：

- **硬件指令级接口**：函数直接映射硬件指令
- **C 语言封装**：封装成 C 函数，接口清晰易用
- **精细控制能力**：直达硬件，精细控制硬件资源

### CAPI 是什么样子？

```
// 通过数组的方式分配内存
__ubuf__ float x_local[C_API_TILE_LENGTH];
__ubuf__ float y_local[C_API_TILE_LENGTH];
__ubuf__ float z_local[C_API_TILE_LENGTH];
// GM->UB的搬运流水
asc_copy_gm2ub(); 
// 同步: Vector计算需要等待搬运结束
asc_sync_notify(PIPE_MTE2, PIPE_V, EVENT_ID0);
asc_sync_wait(PIPE_MTE2, PIPE_V, EVENT_ID0);
// 矢量计算流水
asc_add(); 
// 同步: 搬出处理需要等待Add计算结束
asc_sync_notify(PIPE_V, PIPE_MTE3, EVENT_ID0);
asc_sync_wait(PIPE_V, PIPE_MTE3, EVENT_ID0);
// 搬出到GM
asc_copy_ub2gm(); 
```

**关键特点**：
- 函数名以 `asc_` 开头，表示 Ascend C API
- 参数直接是内存地址或数据指针
- 每个函数对应一条或多条硬件指令

### CAPI 解决了什么问题？


**达到硬件峰值性能**

CAPI 让您完全掌控性能优化：
- 显式同步控制：开发者控制每个同步的位置，按算子特性精简同步，减少等待开销
- 静态内存申请：通过数组的方式申请内存，简化了用户对片上内存的申请

**精准调试硬件问题**

CAPI 提供指令级可见性：
- 显式控制可见：每个同步指令、数据搬运、计算指令明确可见，便于追踪执行流程
- 指令级问题定位：直接对应硬件指令，精准定位具体问题指令

## CAPI 关键概念速查

| 概念 | 解释 | 容量/特性 |
|------|------|----------|
| **NPU** | Neural Processing Unit，神经网络处理器 | 专为深度学习设计 |
| **AI Core** | NPU的计算核心 | 每芯片多个，并行工作 |
| **SIMD** | Single Instruction Multiple Data，单指令多数据 | 一条指令处理多个数据 |
| **UB** | Unified Buffer，统一缓存 | ~1MB，向量计算用 |
| **L1** | Level 1本地存储 | ~1MB，矩阵计算用 |
| **L0A/L0B/L0C** | 矩阵计算输入/输出 | 矩阵乘中间结果 |
| **GM** | Global Memory，全局内存 | 几十GB，所有Core共享 |
| **MTE2** | Memory Transfer Engine 2，数据搬入流水线 | GM → UB/L1 |
| **MTE3** | Memory Transfer Engine 3，数据搬出流水线 | UB/L1 → GM |
| **V** | Vector，向量计算流水线 | 向量运算 |
| **C** | Cube，矩阵计算流水线 | 矩阵乘 |
| **Barrier** | 流水线同步指令 | 确保前序流水线完成 |
| **FP8/FP4** | 8-bit/4-bit浮点格式 | 新精度格式，吞吐量更高 |
| **SPMD** | Single Program Multiple Data | 同一程序，多数据并行 |

## CAPI 编程四步法

CAPI 编程遵循 SIMD 编程的 SPMD 模型（Single Program Multiple Data），即同一份程序运行在每个 AI Core 上，每个 AI Core 负责处理不同的数据块。具体步骤如下：

### 第一步：内存规划与地址分配

**核心任务**：静态分配 UB/L1/L0 内存地址

**关键要点**：
- 静态地址分配：编译期确定，零运行时开销
- 根据算子数据规模、分块策略规划
- 确保无地址冲突

**示例**：
```
constexpr uint32_t C_API_TILE_LENGTH = 256;
__ubuf__ float x_local[C_API_TILE_LENGTH];
__ubuf__ float y_local[C_API_TILE_LENGTH]
```

**详细方法**：参见 [内存层级](./内存层级.md)

---

### 第二步：数据搬入与流水线同步

**核心任务**：将数据从 GM 搬运到 UB/L1，并确保数据就绪

**示例**：
```
asc_copy_gm2ub(x_local, x_gm + i * tileLength, 0, 1, burst_len, 0, 0);    
asc_sync_notify(PIPE_MTE2, PIPE_V, EVENT_ID0);
asc_sync_wait(PIPE_MTE2, PIPE_V, EVENT_ID0);
```

**详细方法**：参见 [数据搬运与计算](./数据搬运与计算.md)、[同步机制](./同步机制.md)

---

### 第三步：计算执行与类型转换

**核心任务**：调用向量/矩阵计算接口

**关键要点**：
- 同类型计算可连续执行，无需中间同步
- 计算完成后需同步

**示例**：
```
asc_add(dst, src1, src2);    	 // 向量加法
asc_sync(PIPE_V);     				// 计算完成后同步
asc_mul(dst, dst, src1);   		 // 向量乘法（可连续）
```

**详细方法**：参见 [数据搬运与计算](./数据搬运与计算.md)、[接口](./接口.md)

---

### 第四步：结果搬出与资源清理

**核心任务**：将结果搬回 GM

**关键要点**：
- 搬出前确保计算完成
- 清理临时资源

**示例**：
```c
asc_sync_notify(PIPE_V, PIPE_MTE3, EVENT_ID0);
asc_sync_wait(PIPE_V, PIPE_MTE3, EVENT_ID0);
asc_copy_ub2gm(output_gm, output_ub, 0, 1, burst_len, 0, 0);
```

**详细方法**：参见 [数据搬运与计算](./数据搬运与计算.md)

---

>  **关键提示**：CAPI 编程需特别注意流水线同步的正确性！
> - 同步缺失 → 计算使用未就绪数据 → 结果错误
> - 同步冗余 → 降低性能（不影响正确性）
> - 同步规则详见 [同步机制](./同步机制.md)

## CAPI 编程小结

AscendC CAPI 通过 **硬件指令级接口** 的设计，提供直达 NPU 硬件的控制能力，核心价值体现在：
- **极致性能**：零抽象开销，直接执行硬件指令，达到峰值性能；
- **精细控制**：显式同步、静态内存、自定义分块，精细控制硬件资源；
- **新能力第一时间开放**：FP8/FP4 等新精度格式率先支持，快速适配硬件新特性；
- **底层调试**：显式控制、指令级映射，精准定位问题与分析瓶颈。

开发者在实际开发中，应根据 **性能需求**（峰值性能 vs 快速开发）、**硬件新能力需求**（新精度格式第一时间支持）、**算子复杂度**（复杂流水线同步策略），选择是否使用 CAPI。
