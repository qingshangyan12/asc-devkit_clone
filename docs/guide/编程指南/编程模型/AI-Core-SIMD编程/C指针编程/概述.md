# AscendC CAPI编程概述<a name="ZH-CN_TOPIC_0000002554090610"></a>

如[编程模型概述](../编程模型概述.md)章节所述，Ascend C 为 AI Core 提供了 SIMD 编程路径。**AscendC CAPI** 是 SIMD 编程的底层接口，直接映射 NPU 硬件指令，提供对向量处理单元、矩阵运算单元、本地存储等硬件资源的精细控制能力。本章节重点讲解 CAPI 的核心特征、适用场景及编程范式，帮助开发者理解 CAPI 的能力范围与应用价值。

## CAPI 核心特征

CAPI（C Application Programming Interface）是 Ascend C 提供的底层 C 语言函数接口，核心特征包括：

- **指令级映射**：CAPI 函数与硬件指令一一对应，如 `asc_add()` 直接映射向量加法指令 `vadd`，`asc_copy()` 直接映射数据搬运指令 `copy_gm2ub`，零中间层开销；
- **显式同步控制**：流水线同步（Barrier）、硬件事件同步（SetFlag/WaitFlag）均需开发者显式调用，精确控制并行执行时序，确保数据就绪与计算正确；
- **静态内存规划**：UB/L1/L0 内存地址需开发者静态分配，避免动态分配的开销与内存碎片，提升内存利用效率；
- **新精度第一时间开放**：FP8/FP4 等新精度格式，CAPI 率先提供接口支持，第一时间开放硬件新能力；
- **完整硬件能力覆盖**：支持向量计算、矩阵计算、数据搬运、流水线同步、类型转换，覆盖 AI Core 所有核心硬件单元。

## CAPI 适用场景

CAPI 主要适配以下典型场景：

**场景一：极致性能算子**
- **典型算子**：MatMul、FlashAttention、LayerNorm、Softmax
- **场景特征**：数据量大（GB级）、计算密集、延迟敏感、性能目标达到硬件峰值 95%+
- **CAPI 能力支撑**：
  - 精细同步控制：显式管理每个 Barrier，减少同步开销
  - 自定义分块策略：根据算子特性优化分块，适配硬件容量
  - 双Buffer并行：Ping-Pong模式实现计算与搬运并行，减少流水线停顿
  - 静态内存规划：避免动态分配开销，提升内存利用效率

**场景二：新精度格式算子**
- **典型算子**：FP8 MatMul、FP4 量化算子、精度转换算子
- **场景特征**：硬件新能力第一时间适配、降低精度提升吞吐量
- **CAPI 能力支撑**：
  - 新精度第一时间开放：FP8/FP4 精度格式在 CAPI 中率先提供接口
  - 精度转换接口：`asc_float2fp8`、`asc_bfloat162fp4` 等转换接口，支持精度降级
  - 吞吐量提升：FP8 相比 FP32 吞吐量提升 2-4倍，存储占用减少 75%

**场景三：复杂流水线算子**
- **典型算子**：Mix算子（Cube+Vector融合）、多阶段流水线算子
- **场景特征**：多流水线并行（MTE2/MTE3/V/C）、自定义同步策略、计算搬运深度耦合
- **CAPI 能力支撑**：
  - 多流水线同步控制：`asc_pipe_barrier` 支持 MTE2/MTE3/V/C 等多流水线同步
  - 硬件事件同步：`asc_set_flag`、`asc_wait_flag` 支持细粒度同步
  - 自定义同步策略：显式控制每个同步点，精简冗余 Barrier

## CAPI [核函数Kernel](./核函数.md)编程四步法

CAPI 编程遵循 SIMD 编程的 SPMD 模型（Single Program Multiple Data），即同一份程序运行在每个 AI Core 上，每个 AI Core 负责处理不同的数据块。具体步骤如下：

1. **内存规划与地址分配**：静态分配 UB/L1/L0 内存地址，避免动态分配开销。需根据算子数据规模、分块策略，合理规划各层级内存布局，确保无地址冲突。详细方法参见 [内存层级](./内存层级.md)。

2. **数据搬入与流水线同步**：调用 CAPI 搬运接口（如 `asc_copy_gm2ub`），将计算数据从 Device Memory 搬运到 AI Core 本地存储（UB/L1）；搬运完成后，必须调用同步接口（如 `asc_pipe_barrier`），确保数据就绪后再开始计算。详细方法参见 [数据搬运与计算](./数据搬运与计算.md)、[同步机制](./同步机制.md)。

3. **计算执行与类型转换**：调用向量计算接口（如 `asc_add`、`asc_mul`）或矩阵计算接口（如 `asc_matmul`），处理数据；同类型计算可连续执行，无需中间同步；计算完成后，调用同步接口确保结果就绪。详细方法参见 [数据搬运与计算](./数据搬运与计算.md)、[接口](./接口.md)。

4. **结果搬出与资源清理**：调用搬运接口（如 `asc_copy_ub2gm`），将计算结果搬运回 Device Memory；搬出前需确保计算完成；若使用了临时内存，需清理资源避免影响后续计算。详细方法参见 [数据搬运与计算](./数据搬运与计算.md)。

> 📌 **提示**：CAPI 编程需特别注意流水线同步的正确性，同步缺失会导致计算使用未就绪数据，同步冗余会降低性能。同步规则详见 [同步机制](./同步机制.md)。

## CAPI 编程小结

AscendC CAPI 通过 **硬件指令级接口** 的设计，提供直达 NPU 硬件的控制能力，核心价值体现在：
- **极致性能**：零抽象开销，直接执行硬件指令，达到峰值性能；
- **精细控制**：显式同步、静态内存、自定义分块，精细控制硬件资源；
- **新能力第一时间开放**：FP8/FP4 等新精度格式率先支持，快速适配硬件新特性；
- **底层调试**：显式控制、指令级映射，精准定位问题与分析瓶颈。

开发者在实际开发中，应根据 **性能需求**（峰值性能 vs 快速开发）、**硬件新能力需求**（新精度格式第一时间支持）、**算子复杂度**（复杂流水线同步策略），选择是否使用 CAPI。
