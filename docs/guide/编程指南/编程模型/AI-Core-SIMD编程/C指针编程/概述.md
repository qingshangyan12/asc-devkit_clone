# AscendC CAPI编程概述<a name="ZH-CN_TOPIC_0000002554090610"></a>

如[编程模型概述](../编程模型概述.md)章节所述，Ascend C 为 AI Core 提供了 SIMD 编程路径。**AscendC CAPI** 是 SIMD 编程的底层接口，直接映射 NPU 硬件指令，提供对向量处理单元、矩阵运算单元、本地存储等硬件资源的精细控制能力。本章节从背景、概念、价值、入门四个维度，帮助新员工快速理解 CAPI 的核心要点。

## 背景：为什么需要 CAPI？

### CAPI 作为底层 C API 的天然优势

CAPI 采用 C 语言函数接口设计，具有底层接口的天然优势：

**优势一：直接映射硬件指令**

CAPI 函数与硬件指令一一对应：
- `asc_add()` → 单条向量加法指令 `vadd`
- `asc_copy()` → 单条数据搬运指令 `copy_gm2ub`
- `asc_matmul()` → 矩阵乘指令

每条 CAPI 函数调用，直接执行对应的硬件指令，无中间转换开销。

**优势二：零抽象层开销**

CAPI 是 C 语言函数接口，天然零抽象层：
- **无运行时决策**：编译期确定执行路径
- **无中间转换**：函数调用直接映射硬件指令
- **零开销抽象**：函数调用直接执行硬件指令，无额外开销

**优势三：精细硬件控制**

CAPI 提供对硬件资源的精细控制：
- **流水线同步**：`asc_pipe_barrier` 精确控制 MTE2/MTE3/V/C 流水线同步
- **硬件事件同步**：`asc_set_flag`、`asc_wait_flag` 支持细粒度同步
- **内存地址控制**：静态分配 UB/L1/L0 地址，精确控制内存布局

## 什么是 CAPI？

### 一句话定义

**CAPI**（C Application Programming Interface）是 **直接操作 NPU 硬件的 C 语言函数接口**。

### CAPI 的定位

CAPI 是底层 C 语言函数接口，核心定位：

- **硬件指令级接口**：函数直接映射硬件指令
- **C 语言封装**：封装成 C 函数，接口清晰易用
- **精细控制能力**：直达硬件，精细控制硬件资源

### CAPI 是什么样子？

```c
// CAPI 函数直接对应硬件指令

// 数据搬运指令
asc_copy_gm2ub(dstUB, srcGM, size);  // GM → UB
asc_copy_ub2gm(dstGM, srcUB, size);  // UB → GM

// 向量计算指令
asc_add(dst, src1, src2);            // 向量加法
asc_mul(dst, src1, src2);            // 向量乘法

// 矩阵计算指令
asc_matmul(dst, src1, src2);         // 矩阵乘法

// 流水线同步指令
asc_pipe_barrier(PIPE_MTE2);         // 同步数据搬运流水线
asc_pipe_barrier(PIPE_V);            // 同步向量计算流水线
```

**关键特点**：
- 函数名以 `asc_` 开头，表示 Ascend C API
- 参数直接是内存地址或数据指针
- 每个函数对应一条或多条硬件指令

### CAPI 解决了什么问题？

CAPI 提供了三个核心能力：

**能力一：达到硬件峰值性能**

CAPI 让您完全掌控性能优化：
- 显式同步：您控制每个 Barrier，按需精简同步
- 静态内存：编译期分配，零运行时开销
- 自定义策略：根据算子特性优化分块

**能力二：第一时间适配硬件新能力**

CAPI 直接对应硬件指令，快速适配新特性：
- 硬件发布即支持，无需等待
- FP8/FP4 等新精度格式第一时间开放
- 快速适配硬件新特性

**能力三：精准调试硬件问题**

CAPI 提供指令级可见性：
- 每个指令可见，精准定位问题指令
- 显式控制，易于追踪数据流
- 指令级映射，白盒分析执行过程

## CAPI 核心价值

CAPI 的核心价值体现在四个维度：

### 价值一：极致性能——让代码跑得更快

**您关心的问题**：算子代码能跑多快？能达到硬件峰值吗？

硬件有理论峰值速度，实际代码往往达不到峰值，原因可能是：
- 中间有转换开销，花费额外时间
- 同步指令插入过多，等待时间过长

**CAPI 怎么解决**：直接操作硬件，消除中间开销

CAPI 函数直接对应硬件指令，没有中间转换：
- 调用 `asc_add()` → 立即执行硬件的向量加指令
- 调用 `asc_copy()` → 立即执行硬件的数据搬运指令
- 调用 `asc_matmul()` → 立即执行硬件的矩阵乘指令

没有中间转换，代码直接执行，速度更快。

**实测对比**（Add 算子，数据量 1M）：
| 实现方式 | 执行时间 | 性能表现 |
|---------|---------|---------|
| 理论峰值 | 100μs | 硬件极限速度 |
| CAPI 实现 | 100μs | 达到100%峰值 |

### 价值二：精细控制——让您掌控每一个细节

**您关心的问题**：想根据算子特性，定制最优方案，怎么做？

硬件有很多控制细节，这些细节影响性能：
- 同步时机：何时插入 Barrier？插入多少？
- 内存分配：UB/L1 地址怎么分配？静态还是动态？
- 分块策略：数据怎么分块？分多大合适？

**CAPI 怎么解决**：您可以控制每一个细节

CAPI 让您完全掌控：
- **同步时机**：您决定在哪里插入 Barrier，精简冗余同步
- **内存分配**：编译期静态分配地址，避免运行时分配开销
- **分块策略**：您根据算子数据规模，自定义最优分块方案

您可以根据算子特性，定制最优方案，提升性能。

### 价值三：新能力第一时间开放——第一时间用上新硬件特性

**您关心的问题**：硬件发布新特性（如 FP8 精度），想第一时间用上，怎么办？

新硬件特性发布时，需要接口支持才能使用。高层接口需要时间适配，可能滞后一段时间。

**CAPI 怎么解决**：直接映射硬件指令，第一时间开放

CAPI 直接对应硬件指令，硬件发布新特性时：
- CAPI 立即提供接口
- FP8、FP4 等新精度格式，第一时间可用
- 快速适配硬件演进

您可以在硬件发布时，第一时间用上新特性。

**FP8 精度示例**：
- FP8 相比 FP32：吞吐量提升 2-4 倍，存储减少 75%
- CAPI 第一时间开放 FP8 接口

### 价值四：底层调试——精准定位问题

**您关心的问题**：算子性能不如预期，怎么找出问题在哪里？

性能问题原因很多：同步问题、内存问题、指令执行问题。需要精准定位。

**CAPI 怎么解决**：每个指令明确可见，精准定位问题

CAPI 提供指令级可见性：
- 每个同步指令明确可见：Barrier 在哪？是不是多余的？
- 每个数据搬运指令明确可见：搬运了多少？搬运到哪里？
- 每个计算指令明确可见：执行了什么计算？

您可以追踪每个指令的执行，精准定位问题。

**实际案例**：
- 某 Add 算子性能比预期低 20%
- 通过 CAPI 分析：发现同步指令比需要的多 30%
- 精简同步指令后，性能恢复

## CAPI 关键概念速查

| 概念 | 解释 | 容量/特性 |
|------|------|----------|
| **NPU** | Neural Processing Unit，神经网络处理器 | 专为深度学习设计 |
| **AI Core** | NPU的计算核心 | 每芯片多个，并行工作 |
| **SIMD** | Single Instruction Multiple Data，单指令多数据 | 一条指令处理多个数据 |
| **UB** | Unified Buffer，统一缓存 | ~1MB，向量计算用 |
| **L1** | Level 1本地存储 | ~1MB，矩阵计算用 |
| **L0A/L0B/L0C** | 矩阵计算输入/输出 | 矩阵乘中间结果 |
| **GM** | Global Memory，全局内存 | 几十GB，所有Core共享 |
| **MTE2** | Memory Transfer Engine 2，数据搬入流水线 | GM → UB/L1 |
| **MTE3** | Memory Transfer Engine 3，数据搬出流水线 | UB/L1 → GM |
| **V** | Vector，向量计算流水线 | 向量运算 |
| **C** | Cube，矩阵计算流水线 | 矩阵乘 |
| **Barrier** | 流水线同步指令 | 确保前序流水线完成 |
| **FP8/FP4** | 8-bit/4-bit浮点格式 | 新精度格式，吞吐量更高 |
| **SPMD** | Single Program Multiple Data | 同一程序，多数据并行 |

## CAPI 编程入门

### 最小示例：一个简单的向量加算子

```c
#include "ascendc_kernel.h"

extern "C" __global__ void MyAddKernel(float* output, float* input1, float* input2, int size) {
    // ============ 第一步：内存规划 ============
    // 假设 UB 容量 1MB，分配输入、输出各占一半
    // 静态地址分配（编译期确定，零开销）
    constexpr int UB_SIZE = 1024 * 1024;        // 1MB
    constexpr int INPUT1_ADDR = 0;               // 输入1起始地址
    constexpr int INPUT2_ADDR = UB_SIZE / 4;     // 输入2起始地址
    constexpr int OUTPUT_ADDR = UB_SIZE / 2;     // 输出起始地址
    
    // ============ 第二步：数据搬入 + 同步 ============
    // 将数据从 GM 搬运到 UB
    asc_copy_gm2ub(input1UB, input1 + offset, TILE_SIZE);  // 搬入输入1
    asc_copy_gm2ub(input2UB, input2 + offset, TILE_SIZE);  // 搬入输入2
    
    // ⚠️ 关键：必须同步，确保数据就绪！
    asc_pipe_barrier(PIPE_MTE2);  // 等待搬运完成
    
    // ============ 第三步：计算 + 同步 ============
    // 执行向量加法
    asc_add(outputUB, input1UB, input2UB);
    
    // 同步，确保计算完成
    asc_pipe_barrier(PIPE_V);     // 等待计算完成
    
    // ============ 第四步：数据搬出 ============
    // 将结果搬回 GM
    asc_copy_ub2gm(output + offset, outputUB, TILE_SIZE);
    
    // 可选：同步，确保搬出完成（如果后续有其他操作）
    asc_pipe_barrier(PIPE_MTE3);
}
```

**关键理解**：
- 每步都有同步：数据搬入后同步、计算后同步
- 同步缺失：计算可能使用未就绪数据 → 结果错误
- 同步冗余：降低性能，但不影响正确性

## CAPI 编程四步法

CAPI 编程遵循 SIMD 编程的 SPMD 模型（Single Program Multiple Data），即同一份程序运行在每个 AI Core 上，每个 AI Core 负责处理不同的数据块。具体步骤如下：

### 第一步：内存规划与地址分配

**核心任务**：静态分配 UB/L1/L0 内存地址

**关键要点**：
- 静态地址分配：编译期确定，零运行时开销
- 根据算子数据规模、分块策略规划
- 确保无地址冲突

**示例**：
```c
constexpr int INPUT_ADDR = 0;
constexpr int OUTPUT_ADDR = UB_SIZE / 2;
```

**详细方法**：参见 [内存层级](./内存层级.md)

---

### 第二步：数据搬入与流水线同步

**核心任务**：将数据从 GM 搬运到 UB/L1，并确保数据就绪

**关键要点**：
- 调用搬运接口：`asc_copy_gm2ub`
- **必须同步**：`asc_pipe_barrier(PIPE_MTE2)`
- 确保数据就绪后再计算

**示例**：
```c
asc_copy_gm2ub(inputUB, inputGM, size);
asc_pipe_barrier(PIPE_MTE2);  // ⚠️ 必须同步！
```

**详细方法**：参见 [数据搬运与计算](./数据搬运与计算.md)、[同步机制](./同步机制.md)

---

### 第三步：计算执行与类型转换

**核心任务**：调用向量/矩阵计算接口

**关键要点**：
- 同类型计算可连续执行，无需中间同步
- 计算完成后需同步

**示例**：
```c
asc_add(dst, src1, src2);     // 向量加法
asc_mul(dst, dst, scalar);    // 向量乘法（可连续）
asc_pipe_barrier(PIPE_V);     // 计算完成后同步
```

**详细方法**：参见 [数据搬运与计算](./数据搬运与计算.md)、[接口](./接口.md)

---

### 第四步：结果搬出与资源清理

**核心任务**：将结果搬回 GM

**关键要点**：
- 搬出前确保计算完成
- 清理临时资源

**示例**：
```c
asc_pipe_barrier(PIPE_V);     // 确保计算完成
asc_copy_ub2gm(outputGM, outputUB, size);
```

**详细方法**：参见 [数据搬运与计算](./数据搬运与计算.md)

---

> 📌 **关键提示**：CAPI 编程需特别注意流水线同步的正确性！
> - 同步缺失 → 计算使用未就绪数据 → 结果错误
> - 同步冗余 → 降低性能（不影响正确性）
> - 同步规则详见 [同步机制](./同步机制.md)

## CAPI 编程小结

AscendC CAPI 通过 **硬件指令级接口** 的设计，提供直达 NPU 硬件的控制能力，核心价值体现在：
- **极致性能**：零抽象开销，直接执行硬件指令，达到峰值性能；
- **精细控制**：显式同步、静态内存、自定义分块，精细控制硬件资源；
- **新能力第一时间开放**：FP8/FP4 等新精度格式率先支持，快速适配硬件新特性；
- **底层调试**：显式控制、指令级映射，精准定位问题与分析瓶颈。

开发者在实际开发中，应根据 **性能需求**（峰值性能 vs 快速开发）、**硬件新能力需求**（新精度格式第一时间支持）、**算子复杂度**（复杂流水线同步策略），选择是否使用 CAPI。
