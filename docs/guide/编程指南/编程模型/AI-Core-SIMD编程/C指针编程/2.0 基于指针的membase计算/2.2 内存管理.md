# Membase API 内存管理

本章介绍 AI Core 存储单元架构、内存申请方式、地址对齐要求及内存使用最佳实践，帮助开发者合理规划片上内存资源，实现高性能算子开发。

---

## 1. 存储单元概述

### 1.1 存储层次架构

AI Core 内部存储单元采用分层架构，从外部 Global Memory 到内部计算单元缓冲区：

```
Global Memory (GM)        ← 外部大容量存储，DDR/HBM（容量最大，延迟最高）
    ↓ ↑                   ← PIPE_MTE2 搬运
L1 Buffer                 ← 中间缓存，用于矩阵计算数据暂存
    ↓ ↑                   ← PIPE_MTE1 搬运
L0A/L0B Buffer            ← 矩阵计算单元输入缓冲区
    ↓ ↑                   ← 矩阵计算单元内部搬运
L0C Buffer                ← 矩阵计算结果缓冲区
    ↓ ↑                   ← PIPE_MTE3 搬运
Unified Buffer (UB)       ← 向量计算单元缓冲区（最常用）
```

### 1.2 各存储单元用途

| 存储单元 | 主要用途 | 典型容量 | 延迟特性 |
|---------|---------|---------|---------|
| Global Memory | 外部数据存储，存储输入数据和计算结果 | GB 级别 | 高延迟 |
| L1 Buffer | 矩阵计算中间数据暂存 | ~1MB | 中等延迟 |
| L0A Buffer | 矩阵计算左矩阵输入 | ~64KB | 低延迟 |
| L0B Buffer | 矩阵计算右矩阵输入 | ~64KB | 低延迟 |
| L0C Buffer | 矩阵计算结果输出 | ~128KB | 低延迟 |
| Unified Buffer | 矢量计算数据输入输出 | ~1MB | 低延迟 |
| BiasTable Buffer | 矩阵计算偏置数据 | ~64KB | 低延迟 |
| Fixpipe Buffer | 量化参数存储 | ~64KB | 低延迟 |

### 1.3 存储单元选择策略

| 计算类型 | 推荐存储单元 | 原因 |
|---------|-------------|------|
| 矢量计算 | Unified Buffer | 矢量计算单元直接访问 |
| 矩阵计算 | L1 → L0A/L0B → L0C | 矩阵计算单元专用缓冲区 |
| 数据暂存 | L1 Buffer | 容量较大，适合暂存 |
| 最终结果 | Global Memory | 外部输出 |

## 2. 地址对齐要求

### 2.1 各存储单元对齐要求

各存储单元的起始地址对齐要求：

| 存储单元 | 对齐要求 | 原因 |
|---------|---------|------|
| Global Memory | 无对齐要求 | 外部存储，硬件支持任意地址访问 |
| Unified Buffer | 32 字节对齐 | UB 内部带宽优化，32B 为最小访问单位 |
| L1 Buffer | 32 字节对齐 | 与 UB 相同，硬件优化要求 |
| L0A Buffer/L0B Buffer | 512 字节对齐 | 矩阵计算单元硬件要求 |
| L0C Buffer | 64 字节对齐 | 矩阵计算结果输出要求 |
| BiasTable Buffer | 64 字节对齐 | 偏置数据访问要求 |
| Fixpipe Buffer | 64 字节对齐 | 量化参数访问要求 |

> **注意**: 如果具体 API 中已明确说明操作数起始地址对齐要求，则以 API 中的说明为准。

### 2.2 对齐检查方法

```cpp
__ubuf__ half src[128];  // 数组方式自动对齐

__ubuf__ half* ptr = (__ubuf__ half*)asc_get_phy_buf_addr(0);
uint64_t addr = (uint64_t)ptr;
bool is_aligned = (addr % 32 == 0);  // 检查是否 32B 对齐
```

### 2.3 非对齐处理

当数据地址未满足对齐要求时：

**方案一**：使用非对齐搬运接口
```cpp
asc_copy_gm2ub_align(dst, src_gm, size, src_offset);
asc_copy_ub2gm_align(dst_gm, src, size, dst_offset);
```

**方案二**：使用数组方式申请（自动对齐）
```cpp
__ubuf__ half buffer[128];  // 自动 32B 对齐
```

## 3. 内存申请方式

### 3.1 方式对比

| 方式 | 特点 | 适用场景 | 对齐保证 |
|-----|------|---------|---------|
| 数组方式（推荐） | 编译期常量长度，自动对齐 | 大多数场景 | 自动保证 |
| 结构体封装 | 便于管理多个缓冲区 | 复杂算子 | 自动保证 |
| 指针方式 | 灵活地址控制 | 特殊场景 | 需手动检查 |

### 3.2 方式一：数组方式（推荐）

使用数组方式申请 UB/L1 等片上内存，数组长度必须为编译期常量。

```cpp
constexpr uint32_t src_len = 1024;
constexpr uint32_t dst_len = 128;

__ubuf__ float src[src_len];
__ubuf__ float dst[dst_len];
```

**优势**：
- 编译器自动保证地址对齐
- 语法简洁，易于理解
- 无需手动管理地址偏移

**约束说明**：
- 数组长度必须为编译期常量（constexpr）
- 当前仅支持 Atlas A3/A2 系列产品
- 不支持多维数组和嵌套数组
- 不支持动态数组
- 不支持与 `asc_get_phy_buf_addr` 混用

### 3.3 方式二：封装到结构体

将内存申请封装到结构体中使用：

```cpp
struct UbBuff {
    float src[1024];
    float dst[128];
};

__ubuf__ UbBuff buff{};  // 必须加 {}，不支持隐式构造
```

**优势**：
- 便于管理多个缓冲区
- 代码结构清晰

**约束说明**：
- 必须显式初始化（加 `{}`）
- 结构体内不支持嵌套数组

### 3.4 方式三：指针方式

通过偏移量获取物理地址：

```cpp
__ubuf__ float* src = (__ubuf__ float*)asc_get_phy_buf_addr(0);
__ubuf__ float* dst = (__ubuf__ float*)asc_get_phy_buf_addr(src_len * sizeof(float));
```

**约束说明**：
- 不能与数组方式混用，否则可能导致地址重叠
- 需手动确保地址对齐
- 需手动计算偏移量

## 4. 内存申请示例

### 4.1 矢量计算内存申请

```cpp
__aicore__ void vector_compute_demo()
{
    constexpr uint32_t length = 256;
    
    __ubuf__ half src0[length];
    __ubuf__ half src1[length];
    __ubuf__ half dst[length];
    
    asc_copy_gm2ub(src0, src_gm, length * sizeof(half));
    asc_copy_gm2ub(src1, src1_gm, length * sizeof(half));
    asc_sync_pipe(PIPE_MTE2);
    
    asc_add(dst, src0, src1, length);
    asc_sync_pipe(PIPE_V);
    
    asc_copy_ub2gm(dst_gm, dst, length * sizeof(half));
    asc_sync_pipe(PIPE_MTE3);
}
```

### 4.2 矩阵计算内存申请

```cpp
__aicore__ void matmul_demo()
{
    constexpr uint32_t l1_size = 4096;
    constexpr uint32_t l0_size = 512;
    constexpr uint32_t l0c_size = 256;
    
    __cbuf__ half a_l1[l1_size];
    __cbuf__ half b_l1[l1_size];
    __ca__ half a_l0a[l0_size];
    __cb__ half b_l0b[l0_size];
    __cc__ float c_l0c[l0c_size];
    
    asc_copy_gm2l1(a_l1, matrix_a, M * K * sizeof(half));
    asc_copy_gm2l1(b_l1, matrix_b, K * N * sizeof(half));
    asc_sync_pipe(PIPE_MTE2);
    
    asc_copy_l12l0a(a_l0a, a_l1, 0, 1, 1, 0);
    asc_copy_l12l0b(b_l0b, b_l1, 0, 1, 1, 0);
    asc_sync_pipe(PIPE_MTE1);
    
    asc_mmad(c_l0c, a_l0a, b_l0b, M, K, N, 0, false, false, true);
    asc_sync_pipe(PIPE_M);
    
    asc_copy_l0c2gm(matrix_c, c_l0c, M * N * sizeof(float));
    asc_sync_pipe(PIPE_MTE3);
}
```

### 4.3 多缓冲区管理

## 5. 不支持的内存申请方式

以下方式**不支持**：

```cpp
// 不支持多维数组
__ubuf__ float buff[src_len][dst_len];

// 不支持数组嵌套
struct UbBuff {
    float src[1024];
};
__ubuf__ UbBuff buff[32];  // UbBuff 中已有数组，不能再嵌套

// 不支持动态数组
uint32_t result_len = compute_length();  // 运行时计算
__ubuf__ float buff[result_len];         // 不支持

// 不支持两种申请方式混用
__ubuf__ float* src0 = (__ubuf__ float*)asc_get_phy_buf_addr(0);
__ubuf__ float src1[src_len];            // src0 和 src1 起始位置可能相同
```

## 6. 地址重叠约束

使用高维切分计算接口时，源操作数与目的操作数可以共享内存空间，但需遵循以下约束：

### 6.1 单次迭代内

| 约束 | 说明 |
|-----|------|
| 源操作数与目的操作数必须 100% 完全重叠 | 不支持部分重叠 |
| 不支持部分重叠 | 部分重叠会导致数据竞争 |

### 6.2 多次迭代间

| 约束 | 说明 |
|-----|------|
| 不支持前序迭代的目的操作数与后序迭代的源操作数重叠 | 会导致数据依赖问题 |

### 6.3 例外情况

对于双目计算类 API（`asc_add`, `asc_sub`, `asc_mul` 等）：
- 当数据类型为 half、int32_t、float 时
- 支持目的操作数与**第二个源操作数**重叠
- 条件：`src1RepStride` 或 `dstRepStride` 必须为 0

### 6.4 地址重叠示意图

**不支持的情况**：
```
迭代N: src → dst
迭代N+1: dst → result (dst 是迭代 N 的结果，也是迭代 N+1 的源)
          ↑ 不支持！
```

**支持的情况（双目计算特例）**：
```
迭代N: src0, src1 → dst
迭代N+1: src0', dst → result' (dst 与 src1 重叠，且 stride 为 0)
          ↑ 支持
```

## 7. 内存容量规划

### 7.1 典型容量参考

各存储单元的典型容量（具体容量因产品型号不同可能有差异）：

| 存储单元 | 典型容量 | 实际容量获取方式 |
|---------|---------|----------------|
| Unified Buffer | ~1MB | 参考具体产品规格文档 |
| L1 Buffer | ~1MB | 参考具体产品规格文档 |
| L0A Buffer | ~64KB | 参考具体产品规格文档 |
| L0B Buffer | ~64KB | 参考具体产品规格文档 |
| L0C Buffer | ~128KB | 参考具体产品规格文档 |

> **注意**: 实际容量请参考具体产品规格文档。

### 7.2 UB 空间规划建议

| 算子类型 | UB 规划建议 |
|---------|------------|
| 单输入单输出 | 输入 buffer + 输出 buffer + 临时 buffer |
| 多输入单输出 | 多个输入 buffer + 输出 buffer |
| 复杂算子 | 合理规划临时 buffer，避免频繁搬运 |

### 7.3 内存使用计算示例

```cpp
constexpr uint32_t input_len = 1024;    // 输入数据长度
constexpr uint32_t output_len = 1024;   // 输出数据长度
constexpr uint32_t temp_len = 512;      // 临时数据长度

constexpr uint32_t total_ub_size = 
    input_len * sizeof(half) + 
    output_len * sizeof(half) + 
    temp_len * sizeof(half);  // 总 UB 使用量

__ubuf__ half input[input_len];
__ubuf__ half output[output_len];
__ubuf__ half temp[temp_len];
```

## 8. 性能优化要点

### 8.1 内存布局优化

| 优化点 | 说明 | 效果 |
|-------|------|------|
| 数据复用 | 尽量复用 UB 中已有的数据 | 减少搬运次数 |
| 地址对齐 | 确保数据地址满足对齐要求 | 提升搬运效率 |
| 合理分配 | 根据算子特点分配 UB 空间 | 避免空间浪费 |

### 8.2 双缓冲技术

```cpp
constexpr uint32_t buffer_len = 512;
__ubuf__ half buffer0[buffer_len];
__ubuf__ half buffer1[buffer_len];

asc_copy_gm2ub(buffer0, src_gm + 0 * buffer_len, buffer_len * sizeof(half));
asc_copy_gm2ub(buffer1, src_gm + 1 * buffer_len, buffer_len * sizeof(half));
asc_sync_pipe(PIPE_MTE2);

asc_add(dst0, buffer0, buffer0, buffer_len);
asc_add(dst1, buffer1, buffer1, buffer_len);
asc_sync_pipe(PIPE_V);
```

### 8.3 内存碎片避免

| 问题 | 解决方案 |
|-----|---------|
| 内存碎片 | 使用数组方式申请，连续分配 |
| 地址重叠 | 不混用多种申请方式 |
| 空间不足 | 合理规划 UB 使用，必要时分块处理 |

## 9. 常见问题

### 9.1 地址重叠错误

**问题**：两种内存申请方式混用导致地址重叠。

**解决**：
- 同一算子内使用统一的内存申请方式
- 推荐使用数组方式申请

### 9.2 数组长度非编译期常量

**问题**：数组长度使用运行时变量导致编译失败。

**解决**：
```cpp
uint32_t length = compute_length();  // 错误
__ubuf__ half buffer[length];        // 不支持

constexpr uint32_t length = 1024;    // 正确
__ubuf__ half buffer[length];        // 支持
```

### 9.3 地址未对齐

**问题**：数据地址未满足对齐要求导致搬运失败。

**解决**：
- 使用数组方式申请内存
- 使用非对齐搬运接口
- 手动调整数据布局

### 9.4 UB 空间不足

**问题**：申请内存超过 UB 容量导致编译失败。

**解决**：
- 合理规划 UB 使用
- 分块处理数据
- 使用 L1 Buffer 暂存
