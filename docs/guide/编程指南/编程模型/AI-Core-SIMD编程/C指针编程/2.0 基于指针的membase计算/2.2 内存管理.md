# Membase API 内存管理

## 1. 存储单元概述

AI Core内部存储单元层次结构如下：

```
Global Memory (GM)        ← 外部大容量存储，DDR/HBM
    ↓ ↑
L1 Buffer                 ← 中间缓存，用于矩阵计算数据暂存
    ↓ ↑
L0A/L0B Buffer            ← 矩阵计算单元输入缓冲区
    ↓ ↑
L0C Buffer                ← 矩阵计算结果缓冲区
    ↓ ↑
Unified Buffer (UB)       ← 向量计算单元缓冲区
```

### 1.1 各存储单元用途

| 存储单元 | 主要用途 |
|---------|---------|
| Global Memory | 外部数据存储，存储输入数据和计算结果 |
| L1 Buffer | 矩阵计算中间数据暂存 |
| L0A Buffer | 矩阵计算左矩阵输入 |
| L0B Buffer | 矩阵计算右矩阵输入 |
| L0C Buffer | 矩阵计算结果输出 |
| Unified Buffer | 矢量计算数据输入输出 |
| BiasTable Buffer | 矩阵计算偏置数据 |
| Fixpipe Buffer | 量化参数存储 |

## 2. 地址对齐要求

各存储单元的起始地址对齐要求：

| 存储单元 | 对齐要求 |
|---------|---------|
| Global Memory | 无对齐要求 |
| Unified Buffer | 32字节对齐 |
| L1 Buffer | 32字节对齐 |
| L0A Buffer/L0B Buffer | 512字节对齐 |
| L0C Buffer | 64字节对齐 |
| BiasTable Buffer | 64字节对齐 |
| Fixpipe Buffer | 64字节对齐 |

> **注意**: 如果具体API中已明确说明操作数起始地址对齐要求，则以API中的说明为准。

## 3. 内存申请方式

### 3.1 方式一：数组方式（推荐）

使用数组方式申请UB/L1等片上内存，数组长度必须为编译期常量。

```cpp
constexpr uint32_t src_len = 1024;
constexpr uint32_t dst_len = 128;

// 直接使用
__ubuf__ float src[src_len];
__ubuf__ float dst[dst_len];
```

**约束说明**：
- 数组长度必须为编译期常量
- 当前仅支持Atlas A3/A2系列产品
- 不支持多维数组和嵌套数组
- 不支持动态数组
- 不支持与`asc_get_phy_buf_addr`混用

### 3.2 方式二：封装到结构体

将内存申请封装到结构体中使用：

```cpp
struct UbBuff {
    float src[1024];
    float dst[128];
};

__ubuf__ UbBuff buff{};  // 必须加{}，不支持隐式构造
```

**约束说明**：
- 必须显式初始化（加`{}`）
- 结构体内不支持嵌套数组

### 3.3 方式三：指针方式

通过偏移量获取物理地址：

```cpp
__ubuf__ float* src = (__ubuf__ float*)asc_get_phy_buf_addr(0);
```

**约束说明**：
- 不能与数组方式混用，否则可能导致地址重叠

## 4. 内存申请示例

### 4.1 矢量计算内存申请

```cpp
__aicore__ void vector_compute_demo()
{
    constexpr uint32_t length = 256;
    
    __ubuf__ half src0[length];
    __ubuf__ half src1[length];
    __ubuf__ half dst[length];
    
    // 使用内存进行计算
    asc_copy_gm2ub(src0, src_gm, length * sizeof(half));
    asc_copy_gm2ub(src1, src1_gm, length * sizeof(half));
    asc_sync_pipe(PIPE_MTE2);
    
    asc_add(dst, src0, src1, length);
}
```

### 4.2 矩阵计算内存申请

```cpp
__aicore__ void matmul_demo()
{
    constexpr uint32_t l1_size = 4096;
    constexpr uint32_t l0_size = 512;
    constexpr uint32_t l0c_size = 256;
    
    __cbuf__ half a_l1[l1_size];
    __cbuf__ half b_l1[l1_size];
    __ca__ half a_l0a[l0_size];
    __cb__ half b_l0b[l0_size];
    __cc__ float c_l0c[l0c_size];
    
    // 矩阵乘加计算
    asc_copy_gm2l1(a_l1, matrix_a, M * K * sizeof(half));
    asc_copy_gm2l1(b_l1, matrix_b, K * N * sizeof(half));
    asc_sync_pipe(PIPE_MTE2);
    
    asc_copy_l12l0a(a_l0a, a_l1, ...);
    asc_copy_l12l0b(b_l0b, b_l1, ...);
    asc_sync_pipe(PIPE_MTE1);
    
    asc_mmad(c_l0c, a_l0a, b_l0b, M, K, N, ...);
}
```

## 5. 不支持的内存申请方式

以下方式**不支持**：

```cpp
// 不支持多维数组
__ubuf__ float buff[src_len][dst_len];

// 不支持数组嵌套
struct UbBuff {
    float src[1024];
};
__ubuf__ UbBuff buff[32];  // UbBuff中已有数组，不能再嵌套

// 不支持动态数组
uint32_t result_len = compute_length();  // 运行时计算
__ubuf__ float buff[result_len];         // 不支持

// 不支持两种申请方式混用
__ubuf__ float* src0 = (__ubuf__ float*)asc_get_phy_buf_addr(0);
__ubuf__ float src1[src_len];            // src0和src1起始位置可能相同
```

## 6. 地址重叠约束

使用高维切分计算接口时，源操作数与目的操作数可以共享内存空间，但需遵循以下约束：

### 6.1 单次迭代内

- 源操作数与目的操作数必须**100%完全重叠**
- **不支持部分重叠**

### 6.2 多次迭代间

- **不支持**前序迭代的目的操作数与后序迭代的源操作数重叠
- 例如：第N次迭代的目的操作数是第N+1次的源操作数 → 不支持

**例外情况**：
- 对于双目计算类API（`asc_add`, `asc_sub`, `asc_mul`等）
- 当数据类型为half、int32_t、float时
- 支持目的操作数与**第二个源操作数**重叠
- 条件：`src1RepStride`或`dstRepStride`必须为0

### 6.3 地址重叠示意图

**不支持的情况**：
```
迭代N: src → dst
迭代N+1: dst → result (dst是迭代N的结果，也是迭代N+1的源)
         ↑ 不支持！
```

**支持的情况（双目计算特例）**：
```
迭代N: src0, src1 → dst
迭代N+1: src0', dst → result' (dst与src1重叠，且stride为0)
         ↑ 支持
```

## 7. 内存容量参考

各存储单元的典型容量（具体容量因产品型号不同可能有差异）：

| 存储单元 | 典型容量 |
|---------|---------|
| Unified Buffer | ~1MB |
| L1 Buffer | ~1MB |
| L0A Buffer | ~64KB |
| L0B Buffer | ~64KB |
| L0C Buffer | ~128KB |

> **注意**: 实际容量请参考具体产品规格文档。
