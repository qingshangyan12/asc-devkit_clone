# Regbase API 编程概述

本章介绍 Regbase API 的核心概念、编程模型、寄存器类型体系及与 Membase API 的对比。Regbase API 是基于矢量数据寄存器的编程风格，需要显式执行数据加载和存储操作，适合需要精细控制计算流程的场景。

---

## 1. Regbase API 简介

### 1.1 核心定位

Regbase API 是 AscendC C API 的寄存器编程风格，基于矢量数据寄存器进行显式操作。与 Membase API 的「指针自动读取」不同，Regbase API 要求开发者手动执行数据加载和存储，提供更精细的计算控制能力。

**核心特点**：
- 数据以寄存器类型（如 `vector_half`）表示
- 显式数据搬运（`asc_loadalign` + `asc_storealign`）
- 局部掩码控制（每次计算可使用不同掩码）
- 支持高级特性（非对齐处理、交织/解交织、上采样/下采样）

### 1.2 核心特点

| 特性 | 说明 | 优势 |
|-----|------|------|
| 寄存器编程 | 数据以 `vector_half` 等寄存器类型表示 | 精细控制计算流程 |
| 显式搬运 | 需手动调用 `asc_loadalign` 加载、`asc_storealign` 存储 | 完全控制数据流 |
| 局部掩码 | Mask 作为参数传递，每次计算可使用不同掩码 | 灵活的元素级控制 |
| 精细控制 | 支持非对齐搬运、交织/解交织等高级特性 | 适配复杂数据布局 |

### 1.3 适用产品

| 产品系列 | 支持状态 | 典型应用 |
|---------|---------|---------|
| Ascend 950PR | ✓ | 端侧推理、边缘计算 |
| Ascend 950DT | ✓ | 数据处理、推理场景 |

## 2. 与 Membase API 对比

### 2.1 编程风格对比

| 特性 | Membase API | Regbase API |
|-----|-------------|-------------|
| 数据表示 | `__ubuf__ half*` 指针 | `vector_half` 寄存器 |
| 数据加载 | 计算时自动读取 | 显式 `asc_loadalign` |
| 数据存储 | 计算后自动写入 | 显式 `asc_storealign` |
| 掩码控制 | 全局 Mask 寄存器 | 参数传递局部掩码 |
| 计算粒度 | 支持高维切分迭代 | 单次 VL 长度计算 |
| 非对齐支持 | 有专门接口 | 完整非对齐流程 |
| 交织操作 | 不支持 | 支持 DEINTLV/INTLV |
| 适用产品 | Atlas A3/A2 | Ascend 950 |

### 2.2 适用场景对比

| 场景 | 推荐 API | 原因 |
|-----|---------|------|
| 连续数据处理 | Membase | 自动读取，编程简单 |
| 非连续数据、复杂数据布局 | Regbase | 显式搬运，灵活控制 |
| 交织数据处理 | Regbase | 支持 DEINTLV/INTLV |
| 非对齐数据处理 | Regbase | 完整非对齐流程 |
| 快速开发 | Membase | 参数简洁 |
| 精细控制 | Regbase | 寄存器级控制 |

## 4. 寄存器类型体系

### 4.1 矢量数据寄存器

矢量数据寄存器用于存储矢量数据，位宽为 VL（Vector Length）= 256B。

**按位宽分类**：

| 位宽 | 数据类型 | 元素数量 |
|-----|---------|---------|
| b8 | `vector_int8_t`, `vector_uint8_t`, `vector_fp8_e4m3fn_t`, `vector_fp8_e5m2_t` 等 | 256 |
| b16 | `vector_int16_t`, `vector_uint16_t`, `vector_half`, `vector_bfloat16_t` | 128 |
| b32 | `vector_int32_t`, `vector_uint32_t`, `vector_float` | 64 |
| b64 | `vector_int64_t`, `vector_uint64_t` | 32 |

**元素数量计算公式**：
```
元素数量 = VL / sizeof(T) = 256B / sizeof(T)
```

### 4.2 掩码寄存器

掩码寄存器类型为 `vector_bool`，用于控制矢量计算中参与计算的元素。

**位宽**：VL / 8 = 256B / 8 = 32字节

**位宽与数据类型对应**：
- 8 位数据：掩码有 256 位（每个元素对应 1 位）
- 16 位数据：掩码有 128 位（每个元素对应 1 位）
- 32 位数据：掩码有 64 位（每个元素对应 1 位）

### 4.3 地址寄存器

地址寄存器类型为 `iter_reg`，用于存储地址偏移量，在循环中自动自增。

**使用场景**：
- 循环搬运数据
- 自动更新地址偏移

### 4.4 非对齐寄存器

| 寄存器类型 | 说明 | 使用场景 |
|----------|------|---------|
| `vector_load_unalign` | 非对齐数据加载缓冲区 | 非对齐加载 |
| `vector_store_unalign` | 非对齐数据存储缓冲区 | 非对齐存储 |

## 5. API 分类概览

### 5.1 数据加载 API

| API | 功能 | 对齐要求 |
|-----|------|---------|
| `asc_load` | 从 UB 加载 VL 量数据到寄存器 | 支持非 32B 对齐 |
| `asc_loadalign` | 对齐加载（多种模式） | 32B 对齐 |
| `asc_loadunalign` | 非对齐加载 | 非对齐地址 |
| `asc_gather` | 按索引收集元素 | - |
| `asc_gather_datablock` | 按 DataBlock 收集 | - |

### 5.2 数据存储 API

| API | 功能 | 对齐要求 |
|-----|------|---------|
| `asc_store` | 从寄存器存储到 UB | 不区分对齐 |
| `asc_storealign` | 对齐存储（多种模式） | 32B 对齐 |
| `asc_storeunalign` | 非对齐存储 | 非对齐地址 |

### 5.3 矢量计算 API

| API 类型 | 接口示例 | 说明 |
|---------|---------|------|

| 激活函数 | `asc_relu`, `asc_leakyrelu` | ReLU 系列 |
| 比较运算 | `asc_eq`, `asc_gt`, `asc_lt` | 生成掩码结果 |
| 归约运算 | `asc_reduce_sum`, `asc_reduce_max` | 全量/DataBlock 归约 |

### 5.4 掩码操作 API

| API | 功能 |
|-----|------|
| `asc_create_mask_b8/b16/b32` | 创建掩码寄存器 |
| `asc_update_mask_b8/b16/b32` | 更新掩码寄存器 |

## 6. 基本编程流程

### 6.1 标准流程

```cpp
__simd_vf__ inline void compute_demo(__ubuf__ half* dst_addr, __ubuf__ half* src_addr)
{
    // 1. 定义寄存器
    vector_half src, dst;
    vector_bool mask;
    iter_reg addr_reg;
    
    // 2. 初始化地址寄存器
    addr_reg = asc_create_iter_reg_b16(128);  // 每次偏移 128 个元素
    
    // 3. 创建掩码
    mask = asc_create_mask_b16(PAT_ALL);
    
    // 4. 加载数据
    asc_loadalign(src, src_addr, addr_reg);
    
    // 5. 执行计算
    asc_add(dst, src, src, mask);
    
    // 6. 存储结果
    asc_storealign(dst_addr, dst, addr_reg, mask);
}
```

### 6.2 循环处理

```cpp
__simd_vf__ inline void loop_compute(__ubuf__ half* dst_addr, __ubuf__ half* src_addr,
                                      uint32_t total_length)
{
    constexpr uint32_t one_repeat_size = 128;  // VL / sizeof(half)
    uint32_t repeat_time = total_length / one_repeat_size;
    
    vector_half src, dst;
    vector_bool mask;
    iter_reg addr_reg;
    
    for (uint32_t i = 0; i < repeat_time; ++i) {
        addr_reg = asc_create_iter_reg_b16(one_repeat_size);
        mask = asc_create_mask_b16(PAT_ALL);
        
        asc_loadalign(src, src_addr, addr_reg);
        asc_add(dst, src, src, mask);
        asc_storealign(dst_addr, dst, addr_reg, mask);
    }
}
```

## 7. 特殊特性

### 7.1 非对齐数据处理

Regbase API 提供完整的非对齐数据处理流程：

```cpp
vector_load_unalign ureg0;
vector_store_unalign ureg1;

asc_loadunalign_pre(ureg0, src_addr);
asc_loadunalign(src, ureg0, src_addr);
asc_neg(dst, src, mask);
asc_storeunalign(dst_addr, ureg1, dst);
asc_storeunalign_post(dst_addr, ureg1, 0);
```

### 7.2 交织/解交织

**解交织加载**：
```cpp
asc_loadalign_deintlv(dst0, dst1, src_addr);
// 输入(交织): [a0 b0 a1 b1 a2 b2 ...]
// 输出dst0:   [a0 a1 a2 ...]
// 输出dst1:   [b0 b1 b2 ...]
```

**交织存储**：
```cpp
asc_storealign_intlv(dst0_addr, dst1_addr, src0, src1);
// 输入src0: [a0 a1 a2 ...]
// 输入src1: [b0 b1 b2 ...]
// 输出:     [a0 b0 a1 b1 a2 b2 ...]
```

### 7.3 上采样/下采样

**上采样加载**：
```cpp
asc_loadalign_upsample(dst, src_addr);
// 64元素 → 128元素（每个元素扩展为两个）
```

**下采样加载**：
```cpp
asc_loadalign_downsample(dst, src_addr);
// 128元素 → 64元素
```

## 9. 性能优化要点

### 9.1 数据加载优化

| 优化点 | 说明 | 效果 |
|-------|------|------|
| 对齐加载 | 使用 `asc_loadalign` 对齐加载 | 提升加载效率 |
| 模式选择 | 根据场景选择合适的加载模式 | 适配数据布局 |
| 并行加载 | 多个加载操作可并行执行 | 减少总加载时间 |

### 9.2 掩码优化

| 优化点 | 说明 | 效果 |
|-------|------|------|
| 掩码复用 | 相同掩码可复用，避免重复创建 | 减少指令开销 |
| 掩码预计算 | 循环前预计算掩码 | 减少循环内开销 |

### 9.3 循环优化

| 优化点 | 说明 | 效果 |
|-------|------|------|
| 循环展开 | 手动展开循环 | 减少分支开销 |
| 地址寄存器 | 使用 `iter_reg` 自动更新地址 | 简化地址计算 |

## 10. 常见问题

### 10.1 数据类型与掩码不匹配

**问题**：掩码创建接口与数据类型不匹配。

**解决**：
```cpp
vector_half src;           // 16位数据
vector_bool mask = asc_create_mask_b16(PAT_ALL);  // 使用 b16 掩码

vector_float src_f;        // 32位数据
vector_bool mask_f = asc_create_mask_b32(PAT_ALL); // 使用 b32 掩码
```

### 10.2 地址未对齐

**问题**：使用对齐加载接口但地址未对齐。

**解决**：
- 检查地址是否满足 32B 对齐
- 使用非对齐加载接口

### 10.3 掩码未传递

**问题**：计算接口未传递掩码参数。

**解决**：
```cpp
asc_add(dst, src0, src1);            // 错误：缺少掩码
asc_add(dst, src0, src1, mask);      // 正确：传递掩码
```
