## 引言

AI Core采用「外部全局存储+片上分级存储+计算单元内部寄存器」的三级存储架构，是C指针编程实现高性能算子的物理根基。存储层次的设计直接决定数据搬运路径、内存分配策略、同步时机等关键技术决策。

> 📌 **提示**：寄存器可编程能力从**Ascend 950**开始引入，在传统「Global Memory → UB」二级存储基础上，新增寄存器层级，构建三级内存架构，开发者可获得接近峰值的计算性能。

本章旨在帮助开发者建立对AI Core存储体系的系统化认知，掌握片上内存规划方法，理解各级存储单元的功能定位与协作机制。全文遵循「物理架构—内存管理—寄存器体系—数据流协作」的递进逻辑展开。

## 硬件底层支撑：AI Core三级存储架构

AI Core采用三级存储架构，各层级分工明确、协同联动。数据搬运遵循存储层级逐级流转原则：
- **Vector算子数据流**：Global Memory → UB → 寄存器（可选） → 计算 → UB → Global Memory
- **Cube算子数据流**：Global Memory → L1 → L0A/L0B → 计算 → L0C → Global Memory/L1

**表 1**  AI Core存储单元与寄存器层级

| 存储层级 | 存储类型 | 名称 | 地址限定符 | 用途 | 访问单元 |
|----------|----------|------|-----------|------|----------|
| **外部存储** | Global Memory | Global Memory | `__gm__` | 存放算子输入/输出数据 | 所有单元通过总线访问 |
| **片上存储** | Local Memory | L1 Buffer | `__cbuf__` | Cube数据中转区 | MTE1、MTE2、FixPipe |
| | | L0A Buffer | `__ca__` | Cube左矩阵输入 | Cube、MTE1 |
| | | L0B Buffer | `__cb__` | Cube右矩阵输入 | Cube、MTE1 |
| | | L0C Buffer | `__cc__` | Cube输出结果 | Cube、FixPipe |
| | | Unified Buffer | `__ubuf__` | Vector输入/输出 | Vector、MTE2、MTE3 |
| **计算单元内部** | 寄存器（Ascend 950引入） | 矢量数据寄存器 | 无 | Vector计算的工作存储 | Vector计算单元 |
| | | 掩码寄存器 | 无 | 选择参与计算的元素 | Vector计算单元 |
| | | 地址寄存器 | 无 | 存储地址偏移量 | Scalar单元 |

## 内存管理核心机制：地址限定符与申请方式

C指针编程通过地址限定符描述不同层级内存，编译器根据限定符将数据分配到对应物理存储单元。每种限定符对应特定存储层级与访问权限。

### 静态数组申请方式

数组长度必须为编译期常量，编译器自动分配地址空间。语法简洁、编译器自动管理地址、不易出错，适用于大多数场景。不支持动态数组、多维数组和嵌套数组。

```cpp
constexpr uint32_t ub_size = 256;
__ubuf__ half ub_buffer[ub_size];  // 申请UB内存

constexpr uint32_t l1_size = 4096;
__cbuf__ half l1_buffer[l1_size];  // 申请L1内存
```

### 偏移量申请方式

通过偏移量获取物理地址，需手动管理地址分配和32字节对齐。适用于需要灵活控制内存布局、偏移量需运行时计算的场景。

```cpp
constexpr uint32_t buffer0_size = 1024;
__ubuf__ half* buffer0 = (__ubuf__ half*)asc_get_phy_buf_addr(0);
__ubuf__ half* buffer1 = (__ubuf__ half*)asc_get_phy_buf_addr(buffer0_size * sizeof(half));
```

> 📌 **提示**：静态数组方式与偏移量方式不能混用，否则会导致地址重叠。

## 寄存器变量类型体系：计算单元工作存储

寄存器是计算单元内部的高速存储，直接参与计算过程。根据功能差异，分为矢量数据寄存器、掩码寄存器、地址寄存器三类。

**表 2**  矢量数据寄存器类型

| 位宽 | 数据类型 | 元素数量 | 说明 |
|------|----------|----------|------|
| b8 | `vector_int8_t` / `vector_uint8_t` | 256个 | 8位整型 |
| b16 | `vector_half` / `vector_bfloat16_t` | 128个 | 16位浮点 |
| b32 | `vector_float` / `vector_int32_t` | 64个 | 32位数据 |
| b64 | `vector_int64_t` / `vector_uint64_t` | 32个 | 64位整型 |

**表 3**  寄存器类型使用场景

| 寄存器类型 | 使用时机 | 使用场景 |
|-----------|----------|----------|
| **矢量数据寄存器** | Vector计算时 | 存储计算输入/输出数据（向量加法、乘法、激活函数） |
| **掩码寄存器** | 选择性计算时 | 部分元素参与计算（尾部数据处理、条件计算） |
| **地址寄存器** | 循环访问内存时 | 循环加载/存储数据，自动管理地址偏移 |

```cpp
vector_half dst;
vector_bool mask = asc_create_mask_b16(PAT_ALL);  // 创建掩码
iter_reg addr_reg = asc_create_iter_reg_b8(offset);  // 创建地址寄存器
```

## Local Memory与寄存器协作模型：Load-Compute-Store数据流

**Local Memory是数据存储空间，寄存器是计算单元的工作台。** Vector计算单元只能访问寄存器，不直接读取Local Memory，数据必须先从UB加载到寄存器，计算完成后写回UB。

**图 2**  Local Memory与寄存器数据流

![Local Memory与寄存器数据流](../../../../figures/Local%20Memory与寄存器数据流.png)

```cpp
// ===== Load：UB→寄存器 =====
constexpr uint32_t length = 128;
__ubuf__ half src_buffer[length];
vector_half src_reg;
asc_loadalign(src_reg, src_buffer);

// ===== Compute：寄存器计算 =====
vector_half dst_reg;
vector_bool mask = asc_create_mask_b16(PAT_ALL);
asc_add(dst_reg, src_reg, src_reg, mask);

// ===== Store：寄存器→UB =====
__ubuf__ half dst_buffer[length];
asc_storealign(dst_buffer, dst_reg, mask);
```
