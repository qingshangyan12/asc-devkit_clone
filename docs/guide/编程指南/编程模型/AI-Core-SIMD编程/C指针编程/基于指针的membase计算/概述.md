# Membase API 编程概述

本章介绍 Membase API 的核心概念、编程模型、API 分类及最佳实践。Membase API 是 AscendC C API 的指针编程风格，基于内存地址指针进行操作，适合需要高性能、高可控性算子开发的场景。

---

## 1. Membase API 简介

### 1.1 核心定位

Membase API 是一套完全基于标准 C 语言指针操作的 Ascend 芯片底层编程接口，为开发者提供「指针直连硬件」的编程方式，核心是通过原生 C 语言指针，实现软件代码与芯片硬件的直接联动。

与传统高层封装 API 不同，Membase API：
- 无冗余封装，直接操作内存地址
- 计算接口内部自动读取指针指向的数据
- 提供三种计算模式满足不同场景需求
- 通过全局 Mask 寄存器实现精细控制

### 1.2 核心特点

| 特性 | 说明 | 优势 |
|-----|------|------|
| 指针编程 | 数据以 `__ubuf__ half*` 形式传递 | 与传统 C 语言编程习惯一致 |
| 自动数据读取 | 计算接口内部自动从指定地址读取数据 | 无需手动搬运，简化编程 |
| 高维切分支持 | 支持设置迭代次数、数据步长 | 灵活处理非连续数据 |
| 全局 Mask 控制 | 通过设置全局 Mask 寄存器控制参与计算的元素 | 精细化元素级控制 |
| 三种计算模式 | 前n个数据计算、高维切分计算、同步计算 | 适配不同复杂度场景 |

### 1.3 适用产品

| 产品系列 | 支持状态 | 典型应用 |
|---------|---------|---------|
| Atlas A3 训练系列产品 | ✓ | 大模型训练、高性能推理 |
| Atlas A3 推理系列产品 | ✓ | 高吞吐推理场景 |
| Atlas A2 训练系列产品 | ✓ | 通用训练场景 |
| Atlas A2 推理系列产品 | ✓ | 端侧推理场景 |

## 2. 关键字说明

Membase API 使用地址空间修饰符和执行空间限定符：

### 2.1 地址空间修饰符

| 关键字 | 地址空间 | 主要用途 |
|-------|---------|---------|
| `__gm__` | Global Memory | 外部数据存储，存储输入数据和计算结果 |
| `__ubuf__` | Unified Buffer | 矢量计算数据输入输出 |
| `__cbuf__` | L1 Buffer | 矩阵计算中间数据暂存 |
| `__ca__` | L0A Buffer | 矩阵计算左矩阵输入 |
| `__cb__` | L0B Buffer | 矩阵计算右矩阵输入 |
| `__cc__` | L0C Buffer | 矩阵计算结果输出 |

### 2.2 执行空间限定符

| 关键字 | 说明 |
|-------|------|
| `__aicore__` | 表示函数只能在 AI Core 上执行 |

### 2.3 使用示例

```cpp
extern __gm__ half* input_gm;

__ubuf__ half src_buffer[128];
__ubuf__ half dst_buffer[128];

__aicore__ void my_kernel()
{
    asc_copy_gm2ub(src_buffer, input_gm, 128 * sizeof(half));
}
```

## 3. API 分类概览

### 3.1 矢量计算 API

矢量计算通过 Vector 计算单元完成，源操作数和目的操作数存储在 Unified Buffer 中。

| API 类型 | 接口示例 | 说明 |
|---------|---------|------|
| 算术运算 | `asc_add`, `asc_sub`, `asc_mul`, `asc_div` | 基础四则运算 |
| 标量运算 | `asc_add_scalar`, `asc_mul_scalar` | 矢量与标量运算 |
| 数学函数 | `asc_exp`, `asc_log`, `asc_sqrt` | 指数、对数、开方等 |
| 激活函数 | `asc_relu`, `asc_leakyrelu` | ReLU 系列 |
| 比较运算 | `asc_eq`, `asc_gt`, `asc_lt` | 比较并生成比特掩码 |
| 归约运算 | `asc_datablock_reduce_sum` | DataBlock/Repeat 内归约 |
| 类型转换 | `asc_half2float`, `asc_float2int32` | 数据类型转换 |
| 数据填充 | `asc_duplicate`, `asc_brcb` | 数据复制填充 |
| 数据选择 | `asc_select` | 根据掩码选择数据 |

### 3.2 数据搬运 API

数据搬运负责在不同存储单元之间传输数据。

**矢量数据搬运**：

| API | 功能 | 流水线 |
|-----|------|--------|
| `asc_copy_gm2ub` | GM → UB | PIPE_MTE2 |
| `asc_copy_ub2gm` | UB → GM | PIPE_MTE3 |
| `asc_copy_ub2ub` | UB → UB | PIPE_V |
| `asc_copy_ub2l1` | UB → L1 | PIPE_MTE3 |
| `asc_copy_gm2ub_align` | GM → UB（非对齐） | PIPE_MTE2 |
| `asc_copy_ub2gm_align` | UB → GM（非对齐） | PIPE_MTE3 |

**矩阵数据搬运**：

| API | 功能 | 流水线 |
|-----|------|--------|
| `asc_copy_gm2l1` | GM → L1 | PIPE_MTE2 |
| `asc_copy_gm2l0a` | GM → L0A | PIPE_MTE2 |
| `asc_copy_gm2l0b` | GM → L0B | PIPE_MTE2 |
| `asc_copy_l12l0a` | L1 → L0A | PIPE_MTE1 |
| `asc_copy_l12l0b` | L1 → L0B | PIPE_MTE1 |
| `asc_copy_l0c2gm` | L0C → GM | PIPE_MTE3 |
| `asc_copy_l0c2ub` | L0C → UB | PIPE_MTE3 |

### 3.3 矩阵计算 API

矩阵计算通过 Cube 计算单元完成。

| API | 功能 |
|-----|------|
| `asc_mmad` | 矩阵乘加运算 C = A × B + C |
| `asc_mmad_sparse` | 稀疏矩阵乘加 |
| `asc_set_mmad_direction_m` | 设置 M 方向优先 |
| `asc_set_mmad_direction_n` | 设置 N 方向优先 |
| `asc_enable_hf32` | 开启 HF32 模式 |
| `asc_set_fp32_mode` | 开启 FP32 模式 |

### 3.4 同步控制 API

| API | 功能 |
|-----|------|
| `asc_sync` | 等待所有流水线完成 |
| `asc_sync_pipe` | 等待指定流水线完成 |
| `asc_sync_vec` | 同步所有流水线 |
| `asc_sync_mte2` | 等待 PIPE_MTE2 完成 |
| `asc_sync_mte3` | 等待 PIPE_MTE3 完成 |
| `asc_sync_data_barrier` | 内存访问屏障 |
| `asc_sync_block_arrive` | 核间同步发送信号 |
| `asc_sync_block_wait` | 核间同步等待信号 |

### 3.5 系统变量 API

| API | 功能 |
|-----|------|
| `asc_get_block_num` | 获取总核数 |
| `asc_get_block_idx` | 获取当前核索引 |
| `asc_get_core_id` | 获取当前核编号 |
| `asc_get_system_cycle` | 获取系统 cycle 数 |
| `asc_get_vf_len` | 获取向量长度 VL |
| `asc_get_phy_buf_addr` | 获取物理地址 |
| `asc_set_ffts_base_addr` | 设置核间同步基地址 |

### 3.6 原子操作 API

| API | 功能 |
|-----|------|
| `asc_set_atomic_add_xxx` | 开启原子累加 |
| `asc_set_atomic_max_xxx` | 开启原子取最大值 |
| `asc_set_atomic_min_xxx` | 开启原子取最小值 |
| `asc_set_atomic_none` | 清空原子操作状态 |

## 4. 计算模式详解

Membase API 提供三种计算模式，适配不同复杂度场景。

### 4.1 模式对比

| 模式 | 特点 | 适用场景 | 参数复杂度 |
|-----|------|---------|-----------|
| 前 n 个数据计算 | 紧密排布读取，从第 0 位置顺序取 N 个数据 | 连续数据处理、简单场景 | 低 |
| 高维切分计算 | 支持设置迭代次数和数据步长 | 非连续数据、带步长计算、复杂场景 | 高 |
| 同步计算 | 内部自动插入同步操作 | 快速开发、原型验证 | 低 |

### 4.2 前n个数据计算

**函数原型**：
```cpp
__aicore__ inline void asc_add(__ubuf__ half* dst, __ubuf__ half* src0, 
                               __ubuf__ half* src1, uint32_t count)
```

**特点**：
- 参数简洁，仅需指定元素个数
- 紧密排布读取，从第 0 位置顺序取 N 个数据
- 适合连续数据处理场景

**示例**：
```cpp
asc_add(dst, src0, src1, 128);  // 连续处理 128 个元素
```

### 4.3 高维切分计算

**函数原型**：
```cpp
__aicore__ inline void asc_add(__ubuf__ half* dst, __ubuf__ half* src0, 
                               __ubuf__ half* src1, uint8_t repeat,
                               uint8_t dst_block_stride, uint8_t src0_block_stride,
                               uint8_t src1_block_stride, uint8_t dst_repeat_stride,
                               uint8_t src0_repeat_stride, uint8_t src1_repeat_stride)
```

**特点**：
- 支持设置迭代次数（repeat）
- 支持设置单次迭代内 DataBlock 步长（block_stride）
- 支持设置迭代间 DataBlock 步长（repeat_stride）
- 适合非连续数据、带步长计算场景

**参数说明**：

| 参数 | 说明 | 单位 |
|-----|------|------|
| repeat | 迭代次数 | 次数 |
| dst_block_stride | 目的 DataBlock 步长 | DataBlock（32字节） |
| src0_block_stride | 源0 DataBlock 步长 | DataBlock（32字节） |
| src1_block_stride | 源1 DataBlock 步长 | DataBlock（32字节） |
| dst_repeat_stride | 目的迭代间步长 | DataBlock（32字节） |
| src0_repeat_stride | 源0 迭代间步长 | DataBlock（32字节） |
| src1_repeat_stride | 源1 迭代间步长 | DataBlock（32字节） |

**示例**：
```cpp
asc_add(dst, src0, src1, 2, 1, 2, 2, 8, 16, 16);  // 2次迭代，源数据间隔读取
```

### 4.4 同步计算

**函数原型**：
```cpp
__aicore__ inline void asc_add_sync(__ubuf__ half* dst, __ubuf__ half* src0,
                                    __ubuf__ half* src1, uint32_t count)
```

**特点**：
- 内部自动插入同步等待
- 易用性强，适合快速开发
- 性能略低于手动同步版本

**示例**：
```cpp
asc_add_sync(dst, src0, src1, 128);  // 自动同步的加法
```

## 5. 流水线类型

AI Core 上的操作被分配到不同流水线执行，理解流水线对于性能优化至关重要。

### 5.1 流水线分类

| 流水线 | 类型标识 | 功能描述 |
|-------|---------|---------|
| PIPE_S | 标量流水线 | 指令分发和标量计算 |
| PIPE_V | 矢量计算流水线 | 向量计算单元执行 |
| PIPE_M | 矩阵计算流水线 | 矩阵乘加计算 |
| PIPE_MTE1 | 数据搬运流水线1 | L1 → L0A/L0B、L1 → UB 搬运 |
| PIPE_MTE2 | 数据搬运流水线2 | GM → L1、GM → L0A/L0B、GM → UB 搬运 |
| PIPE_MTE3 | 数据搬运流水线3 | UB → GM、UB → L1 搬运 |
| PIPE_FIX | Fixpipe 流水线 | 结果处理与量化 |
| PIPE_ALL | 所有流水线 | 全流水线同步 |

### 5.2 流水线执行顺序

**矢量计算典型流程**：
```
数据搬运(GM→UB):  PIPE_MTE2
向量计算:         PIPE_V
数据搬运(UB→GM):  PIPE_MTE3
```

**矩阵计算典型流程**：
```
数据搬运(GM→L1):  PIPE_MTE2
数据搬运(L1→L0A): PIPE_MTE1
矩阵计算:         PIPE_M
结果搬运(L0C→GM): PIPE_MTE3
```

### 5.3 流水线并行与同步

不同流水线可以并行执行，但需要正确同步：

```cpp
asc_copy_gm2ub(src0, src0_gm, size);
asc_copy_gm2ub(src1, src1_gm, size);
asc_sync_pipe(PIPE_MTE2);

asc_add(dst, src0, src1, count);
asc_sync_pipe(PIPE_V);

asc_copy_ub2gm(dst_gm, dst, size);
asc_sync_pipe(PIPE_MTE3);
```

## 6. 性能优化要点

### 6.1 数据搬运优化

| 优化点 | 说明 | 建议 |
|-------|------|------|
| 搬运对齐 | 32 字节对齐搬运性能最优 | 尽量使用对齐搬运接口 |
| 搬运粒度 | 大块搬运效率高于小块搬运 | 合理设置搬运块大小 |
| 双缓冲 | 利用流水线并行隐藏搬运延迟 | 使用双缓冲技术 |

### 6.2 计算模式选择

| 场景 | 推荐模式 | 原因 |
|-----|---------|------|
| 连续数据、简单逻辑 | 前 n 个数据计算 | 参数简洁，易于使用 |
| 非连续数据、带步长 | 高维切分计算 | 支持灵活步长设置 |
| 快速开发、原型验证 | 同步计算 | 自动同步，减少错误 |

### 6.3 流水线并行

```cpp
asc_copy_gm2ub(src0, src0_gm, size);
asc_copy_gm2ub(src1, src1_gm, size);
asc_copy_gm2ub(src2, src2_gm, size);
asc_sync_pipe(PIPE_MTE2);

asc_add(dst0, src0, src1, count);
asc_add(dst1, src1, src2, count);
asc_sync_pipe(PIPE_V);
```

**优化要点**：
- 多个搬运操作可并行执行
- 多个计算操作可并行执行
- 同类操作只需一次同步

### 6.4 内存布局优化

| 优化点 | 说明 |
|-------|------|
| UB 空间规划 | 合理分配 UB 空间，避免频繁搬运 |
| 数据复用 | 尽量复用 UB 中已有的数据 |
| 地址对齐 | 确保数据地址满足对齐要求 |

## 7. 最佳实践

### 7.1 初始化规范

```cpp
__aicore__ void kernel_entry()
{
    asc_init();  // 必须先初始化
    
    asc_set_mask_count();  // 设置默认 Mask 模式
    asc_set_vector_mask(0, 0xFFFFFFFFFFFFFFFF);  // 设置默认 Mask 值
    
    // 业务逻辑
}
```

### 7.2 同步点设置

```cpp
// 搬入后同步
asc_copy_gm2ub(src, src_gm, size);
asc_sync_pipe(PIPE_MTE2);

// 计算后同步
asc_add(dst, src0, src1, count);
asc_sync_pipe(PIPE_V);

// 搬出后同步
asc_copy_ub2gm(dst_gm, dst, size);
asc_sync_pipe(PIPE_MTE3);
```

### 7.3 多核协同

```cpp
uint32_t block_idx = asc_get_block_idx();
uint32_t block_num = asc_get_block_num();

__gm__ half* my_input = input + block_idx * block_length;
```

### 7.4 原子操作使用

```cpp
asc_set_atomic_add_float();
asc_copy_ub2gm(dst_gm, partial_sum, sizeof(float));
asc_set_atomic_none();  // 必须关闭原子操作
```

## 8. 常见问题

### 8.1 地址未对齐

**问题**：数据地址未满足 32 字节对齐要求。

**解决**：
- 使用数组方式申请内存，自动对齐
- 使用 `asc_copy_gm2ub_align` 非对齐搬运接口

### 8.2 同步点缺失

**问题**：缺少必要的同步操作导致数据竞争。

**解决**：
- 搬入操作后同步 PIPE_MTE2
- 计算操作后同步 PIPE_V
- 搬出操作后同步 PIPE_MTE3

### 8.3 Mask 未设置

**问题**：高维切分计算未设置 Mask 导致计算错误。

**解决**：
```cpp
asc_set_mask_norm();
asc_set_vector_mask(mask1, mask0);
asc_add(dst, src0, src1, repeat, ...);
```

### 8.4 内存申请方式混用

**问题**：数组方式和指针方式混用导致地址重叠。

**解决**：
- 同一算子内使用统一的内存申请方式
- 推荐使用数组方式申请

## 9. 最简示例

```cpp
#include "c_api/asc_simd.h"

extern __gm__ half* src0_gm;
extern __gm__ half* src1_gm;
extern __gm__ half* dst_gm;

__aicore__ void simple_add_kernel()
{
    asc_init();
    
    constexpr uint32_t total_length = 128;
    
    __ubuf__ half src0[total_length];
    __ubuf__ half src1[total_length];
    __ubuf__ half dst[total_length];
    
    asc_copy_gm2ub(src0, src0_gm, total_length * sizeof(half));
    asc_copy_gm2ub(src1, src1_gm, total_length * sizeof(half));
    
    asc_sync_pipe(PIPE_MTE2);
    
    asc_add(dst, src0, src1, total_length);
    
    asc_sync_pipe(PIPE_V);
    
    asc_copy_ub2gm(dst_gm, dst, total_length * sizeof(half));
    
    asc_sync_pipe(PIPE_MTE3);
}
```
