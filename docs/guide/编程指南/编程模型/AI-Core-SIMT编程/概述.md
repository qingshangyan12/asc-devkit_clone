# AI Core SIMT编程模型概述

## 引言

SIMT（Single Instruction Multiple Thread，单指令多线程）编程模型是Vector Core编程方式的一种重要补充，特别适用于离散数据访问、复杂控制逻辑和分支发散等场景。与SIMD编程模型采用SPMD并行编程模型不同，SIMT通过线程级并行实现数据并行计算，每个线程允许指令对数据进行独立寻址于计算，从而实现了更高的编程灵活性。本章将以**SIMT编程模型**为核心主线，遵循「宏观架构—线程调度—代码落地」的递进逻辑，完整覆盖SIMT算子开发全链路：阐述多线程并行架构的执行机制，拆解线程块内Warp调度的底层逻辑，并完成[算子Kernel](./核函数.md)计算逻辑的开发。

## 异构并行计算核心模型：SIMT编程范式

昇腾NPU异构并行体系中，SIMT编程采用**Grid-Block-Thread三级线程层次结构**，以线程作为最小执行单元，通过大规模线程并发实现数据并行计算。所有SIMT算子的并行逻辑、数据拆分策略、线程调度机制，均基于该编程范式实现。

**线程层级架构遵循三级层次结构**：
- **线程块网格（Grid）**：由多个线程块（Thread Block）组成，使用内置变量[gridDim](../../语言扩展层/SIMT-BuiltIn关键字.md)表示启用的线程块个数。同一时刻一个AIV核只执行一个线程块任务，Grid维度通过dim3三维结构表示(三维乘积总数不超过65535)。
- **线程块（Thread Block）**：由若干线程组成，使用内置变量[blockDim](../../语言扩展层/SIMT-BuiltIn关键字.md)表示一个线程块启用的线程个数(一个线程块最多可启用2048个线程)。各线程块通过线程块索引[blockIdx](../../语言扩展层/SIMT-BuiltIn关键字.md)进行标识。
- **线程（Thread）**：最小执行单位，每个线程拥有独立的寄存器、栈空间，可通过线程索引[threadIdx](../../语言扩展层/SIMT-BuiltIn关键字.md)标识，负责完成特定的数据计算任务。

**底层调度层面依托Warp机制**：每个线程块被切分成多个Warp依次调度执行，Warp是执行相同指令的线程集合，每个Warp包含32个线程。每个AIV核包含多个Warp调度器（Warp Scheduler），当某个Warp因全局内存访问处于阻塞状态时，Warp调度器会立刻切换到就绪的Warp，确保计算单元处于busy状态，从而掩盖访存的延迟并达到最大化硬件利用率的目的。

> 📌 **提示**：基于SIMT编程模型的程序，在AIV核上执行多个结构相同的线程块，执行的总线程数等于gridDim × blockDim。每个线程执行相同的代码逻辑，但处理不同的数据片段，实现数据并行。

## 硬件底层支撑：Vector Core SIMT单元架构与内存层级

Vector Core是SIMT编程的核心硬件载体，采用「Warp调度器 + 计算单元 + 分级存储体系」的架构，下文详细介绍Vector Core核心硬件组件以及SIMT编程的内存层级体系。

### 核心硬件组件

- **Warp调度器（Warp Scheduler）**：每个Vector Core包含多个Warp调度器，负责线程块的切分与调度。Warp调度器将线程块划分为多个Warp（每个Warp 32个线程），依次发射执行，实现高效的线程级并行调度。
- **计算单元**：Vector Core内的向量计算单元，负责执行各类向量运算指令。同一Warp内的32个线程执行相同指令，但对不同数据地址进行操作，实现单指令多线程并行计算。
- **寄存器文件（Register File）**：每个线程拥有独立的寄存器空间，用于存储局部变量和计算中间结果。寄存器数量受线程块内线程数量影响，线程数量越多，每个线程可用的寄存器数量越少（详见[内存层级](./内存层级.md)）。
- **共享内存（Unified Buffer）**：线程块内所有线程共享的内存空间，位于Vector Core内部，具有高带宽、低延迟特性，可作为用户管理的高速缓存，支持线程间数据交互。
- **栈空间（Stack）**：每个线程独立的栈空间，用于存储局部变量以及寄存器溢出时的临时变量。

### SIMT编程内存层级体系

SIMT线程可访问多种内存空间，形成「全局内存-共享内存-寄存器」三级内存层级，各层级作用域、生命周期与物理位置差异如下：

| 内存类型 | 线程作用域 | 生命周期 | 物理位置 | 特点 |
|----------|-----------|----------|---------|------|
| **全局内存** | Grid | 应用程序 | Device | 所有线程可直接访问，持久化存储 |
| **共享内存（Unified Buffer）** | Block | 核函数 | Vector Core | 线程块内共享，高带宽低延迟，Data Cache占用UB空间 |
| **寄存器** | Thread | 核函数 | Vector Core | 线程私有，编译器管理，数量受blockDim影响 |
| **栈** | Thread | 核函数 | Device | 线程私有，存储局部数据 |

> 📌 **提示**：与SIMD编程的显式分层访存不同，SIMT编程通过Data Cache自动完成全局内存数据的缓存中转，数据流经由Global Memory到Data Cache，再从Data Cache到寄存器，简化了开发者的内存管理复杂度。Data Cache是Unified Buffer中预留的一部分空间，最大容量128KB，最小容量32KB，实际大小由用户自主分配。


## SIMT编程接口体系

### SIMT编程接口特点

SIMT编程采用单一C语言接口层级，开发者通过Ascend C提供的操作符和接口操作全局内存与共享内存，实现对硬件能力的完全操作。同时SIMT编程也提供部分高阶特性用于特定的应用场景。

SIMT编程接口核心特点：
- **基于指针编程**：采用C语言裸指针编程，可直接通过指针寻址操作设备内存
- **内置关键字扩展**：提供`__global__`、`__aicore__`等修饰符，`blockIdx`、`threadIdx`、`blockDim`、`gridDim`等线程索引变量，简化线程并行编程
- **共享内存管理**：通过`__ubuf__`修饰符静态或动态申请共享内存，由开发者自主管理
- **同步接口支持**：提供`asc_syncthreads`、`asc_threadfence`等同步机制，确保线程间数据访问正确性
- **高阶特性支持**：当前提供协作组特性，用于需要灵活控制分组的业务场景

## 小结

本章系统梳理了AI Core SIMT算子从线程架构、硬件调度到代码落地的全链路技术体系：计算任务依托Grid-Block-Thread三级线程层次结构分发至Vector Core并行执行，通过线程索引自动映射数据范围，实现大规模线程并发计算；开发者基于C语言编程接口，通过指针操作全局内存与共享内存，配合同步机制确保线程间数据访问正确性。

SIMT编程模型以线程作为最小执行单位，特别适用于离散数据访问、复杂控制逻辑与分支发散场景。后续章节将逐层深入地详解[抽象硬件架构](./抽象硬件架构.md)、[线程架构](./线程架构.md)、[核函数](./核函数.md)定义与调用、[内存层级](./内存层级.md)管理机制、[同步机制](./同步机制.md)原理、[编程示例](./编程示例.md)实战流程，帮助开发者快速理解核心技术，熟练掌握高性能、高可用的SIMT算子开发能力。
