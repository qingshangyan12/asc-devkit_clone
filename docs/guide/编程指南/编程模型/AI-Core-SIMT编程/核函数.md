# 核函数<a name="ZH-CN_TOPIC_0000002554438935"></a>

正如在[概述](./概述.md)中所介绍的，能够在AI处理器（NPU）上并行执行、并由主机端（Host）发起调用的函数被称为核函数（Kernel）。核函数被设计为由大量线程（Threads）同时并行运行。每个线程都拥有独立的寄存器和栈，它们协同工作以完成海量的数据计算任务。

## 核函数的定义<a name="section962384613331"></a>

Ascend C支持开发者自定义核函数来扩展C++。定义核函数时，通过引入特定的函数限定符，编译器能够识别该函数需要在设备端（Device）编译，并允许其从主机端被发起调用。

核函数的定义示例如下：

```
// 核函数定义示例
__global__ void vec_add(float* x, float* y, float* z) 
{
    // 具体的计算逻辑
}
```

定义核函数时需要遵循以下规则：

-   使用函数类型限定符\_\_global\_\_， 标识它是一个核函数。
-   核函数必须具有void返回类型。
-   核函数参数列表需遵循[函数参数列表限制](../../../技术附录/CPP标准支持/语法限制/函数.md#section_kernel_function_argument_list)。

## 核函数的调用<a name="section33493239410"></a>

算子程序中的函数可以分为三类：host侧执行函数、核函数（device侧执行）、device侧执行函数（除核函数之外）。下图以Kernel直调算子开发方式为例，描述三者的调用关系：

-   host侧执行函数可以调用其它host执行函数，也就是通用C/C++编程中的函数调用；也可以通过<<<...\>\>\>调用核函数。
-   核函数可以调用除核函数之外的其它device侧执行函数。
-   device侧执行函数（除核函数之外）使用类型限定符\_\_aicore\_\_标识，可以调用同类的其它device侧执行函数。

**图 1**  算子程序中三种函数间的调用关系<a name="fig14484835135913"></a>  
![](../../../figures/算子程序中三种函数间的调用关系.png "算子程序中三种函数间的调用关系")

Host侧通过内核调用符<<<...\>\>\>的语法形式调用核函数，如下所示：

```
kernel_name<<<blocks_per_grid, threads_per_block, dynamic_ubuf_bytes, stream>>>(args...)
```

执行配置由4个参数决定，详细用法说明参考[核函数配置](../../语言扩展层/SIMT-BuiltIn关键字.md#section97005415463)：

-   blocks\_per\_grid：int或dim3类型，用于指定网格（grid）的维度与规模，blocks_per_grid.x * gblocks_per_grid.y * blocks_per_grid.z等于启动的线程块总数。
-   threads\_per\_block：int或dim3类型，用于指定每个线程块（block）的维度与规模，threads\_per\_block.x \* threads\_per\_block.y \* threads\_per\_block.z等于每个线程块包含的线程数，需要小于等于\_\_launch\_bounds\_\_配置。
-   dynamic\_ubuf\_bytes：size_t类型，该参数指定除静态分配的内存外，本次调用为每个线程块动态分配的共享内存字节数，单位为Byte，默认设置为0。具体用法请参考[共享内存](./内存层级.md#共享内存unified-buffer)中的“动态申请”方式；
-   stream：aclrtStream类型指针，指定关联的流，用于维护异步操作的执行顺序。

## 线程与网格索引

在核函数内，Ascend C提供了[内部变量](../../语言扩展层/SIMT-BuiltIn关键字.md#内置变量)来获取执行配置的参数以及线程或线程块的索引。

常用的内置索引变量说明如下：
-   threadIdx：获取当前线程在其所属线程块内的索引。线程块中的每个线程都有不同的索引。
-   blockDim：获取线程块的尺寸，该尺寸在内核启动的执行配置中指定，对应核函数配置中的threads_per_block参数。
-   blockIdx: 获取当前线程块在其所属网格中的索引。网格中的每个线程块都有不同的索引。
-   gridDim： 获取网格的尺寸，该尺寸在内核启动的执行配置中指定。对应核函数配置中的blocks_per_grid参数。

这些内置变量均为包含.x、.y、.z 三个成员的三维向量（[内置结构体dim3](../../语言扩展层/SIMT-BuiltIn关键字.md#内置变量)）。在未显式配置多维网格或线程块的场景下，未指定的维度成员取值默认为 1。例如，在一维配置中，threadIdx.x 的取值范围严格落在[0, blockDim.x - 1]之间，.y 和 .z 的值则恒为 0。

开发者可通过组合上述变量，计算出当前线程在整个庞大计算网格空间中的全局唯一数据索引（Work Index）。这使得成千上万个执行相同代码的线程能够精准地定位并处理属于自己的特定数据分片。

## 典型应用示例：带边界检查的矢量加法

在实际一维并行处理开发中，待处理的数据总长度往往无法被单一线程块的尺寸完美整除。因此，通常需要分配多余的物理线程，并在核函数内部引入边界检查机制，以防止内存越界。

一维全局索引的标准计算公式为：
int work_index = blockIdx.x * blockDim.x + threadIdx.x;

以下代码片段展示了如何结合索引机制与边界检查实现动态长度的矢量相加：

```
// 1. 核函数实现
__global__ void vec_add(float* x, float* y, float* z, int vector_length) 
{
    // 推导当前线程对应的全局元素索引
    int work_index = blockIdx.x * blockDim.x + threadIdx.x;

    // 边界检查：约束计算范围，防止多余线程非法越界访问内存
    if (work_index < vector_length) 
    {
        // 只有索引在有效范围内的线程才会执行具体的加法运算
        z[work_index] = x[work_index] + y[work_index];
    }
}

// 2. Host 侧调用示例
int main() 
{
    // 假定 Host 侧及 Device 侧内存已完成分配与初始化
    int vector_length = 1000;
    
    // 经验配置：指定每个 Block 包含 256 个线程
    int threads = 256; 
    
    // 计算参数：按向上取整原则，计算所需的 Block 数量
    // 算法：(长度 + 线程数 - 1) / 线程数
    int blocks = (vector_length + threads - 1) / threads; // 结果为 4

    // 执行调用：启动 4 个 Block，每个 Block 256 个线程（共计下发 1024 个物理线程）
    vec_add<<<blocks, threads, 0, stream>>>(dev_x, dev_y, dev_z, vector_length);
    
    // ... 后续流同步与资源释放逻辑 ...
    return 0;
}
```
在本示例中，目标处理元素总数为1000个。按单块256线程的策略划分，Host侧实际向硬件下发了4个线程块，总计启动了$4 \times 256 = 1024$个物理线程。当程序运行至最后一个线程块（即blockIdx.x == 3时，该块内末尾的24个线程（从索引1000到1023）推导出的work_index 将落在[1000, 1023]区间。此时，通过if (work_index < vector_length) 这道边界拦截，这部分超出有效数据范围的“多余”线程将直接结束任务并安全退出。该机制在保证计算结果完备性的同时，有效规避了内存越界访问的风险。
