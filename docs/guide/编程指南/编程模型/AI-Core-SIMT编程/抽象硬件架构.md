# 抽象硬件架构<a name="ZH-CN_TOPIC_0000002556525479"></a>

AI Core上的SIMT（Single Instruction Multiple Thread，单指令多线程）编程允许指令对数据进行独立寻址，从而支持线程级并行计算。这种方式特别适用于离散访问和复杂控制逻辑等场景，目前仅支持Atlas 350 加速卡。

SIMT编程能够简化复杂算子和不规则控制流的开发，通过SIMT编程可以有效缓解包含分支等的发散计算，同时控制程序复杂度。

## SIMT关键硬件单元介绍<a name="section_hardware_components"></a>

- **Vector Core**<a name="section_vector_core"></a>
Vector Core是AI处理器内部的核心计算单元，每个AI Core包含多个Vector Core。每个Vector Core是一个独立的执行单元，能够执行线程块（Thread Block）任务。同一时刻，一个Vector Core只能执行一个线程块任务，多个Vector Core可以并行执行不同的线程块。

- **计算单元**<a name="section_compute_unit"></a>
计算单元位于Vector Core内部，负责执行各类算术运算和逻辑运算。计算单元支持多种数据类型的运算，是SIMT线程执行计算操作的核心硬件资源。

- **Global Memory**<a name="section_global_memory"></a>
Global Memory位于Vector Core外部，是所有Vector Core共享的全局内存空间。其作用类似于CPU系统中的随机存取存储器（RAM），用于存储核函数处理所需的输入数据和计算结果。Global Memory具有持久性，分配的空间及其中存储的数据将持续保留，直至该内存空间被释放或应用程序终止。

- **Unified Buffer**<a name="section_unified_buffer"></a>
Unified Buffer位于每个Vector Core内部，是一块高速片上内存空间，总大小为256KB。相比Global Memory，Unified Buffer虽然容量较小，但具有更高的带宽和更低的访问延迟。Unified Buffer在SIMT编程模式下按功能划分为多个区域：

  - **Share Memory（共享内存）**：用于线程块内所有线程的数据交互和共享。
  - **Data Cache（数据缓存）**：用于SIMT线程访问Global Memory时的数据中转。
  - **预留空间**：编译器和Ascend C预留空间。

- **寄存器**<a name="section_register"></a>
寄存器是Vector Core内部最快的存储资源，用于存储线程的局部变量和中间计算结果。SIMT架构下，每个线程都拥有独立的寄存器资源，生命周期与核函数一致。

- **堆栈空间**<a name="section_stack"></a>
堆栈空间是每个线程独立的存储区域，用于函数调用时的上下文保存和局部数据存储。当寄存器资源不足时，部分数据会被临时存放到堆栈空间中。

## 寄存器资源分配<a name="section_register_allocation"></a>

每个Vector Core的寄存器资源总量是固定的，需要在线程块内的所有线程之间进行分配。因此，每个线程可用的寄存器数量与线程块维度密切相关：

- 配置线程块内的线程数量越多，每个线程拥有的寄存器数量越少。
- 配置线程块内的线程数量越少，每个线程拥有的寄存器数量越多。

当用户设置的线程数量过大，而每个线程的计算复杂度又较高时，编译器可能因寄存器资源不足而将数据临时存放到堆栈空间，导致寄存器溢出（Stack Spill），影响算子性能。因此，用户需要根据实际的算子复杂度，合理配置线程块维度大小。

## 数据流路径<a name="section_data_flow"></a>

SIMT架构下，不同存储层级之间的数据流动路径直接影响程序的性能表现。理解数据流路径有助于开发者编写高效的并行程序。

- **Global Memory访问路径**<a name="section_gm_access_path"></a>
  Global Memory作为容量最大但延迟最高的存储资源，其数据访问遵循以下路径：
  - 读取路径（Load Path）：
    ```
    Global Memory → Data Cache → 寄存器
    ```
    1. 底层硬件将数据从Global Memory加载到Data Cache；
    2. 底层硬件将数据从Data Cache传输到线程寄存器；
    3. 计算单元从寄存器获取数据进行运算。
  - 写入路径（Store Path）：
    ```
    寄存器 → Data Cache → Global Memory
      ```
    1. 底层硬件将数据从寄存器写入Data Cache；
    2. 底层硬件将数据从Data Cache写回Global Memory。

- **Share Memory访问路径**<a name="section_sm_access_path"></a>
  Share Memory（位于Unified Buffer中）的访问路径与Global Memory不同，无需Data Cache中转：
  ```
  寄存器 ↔ Share Memory
  ```
  Share Memory的内存访问有以下特点：
    - 直接访问：线程块内的线程可直接访问Share Memory，无需经过Data Cache中转；
    - 低延迟：Share Memory位于Vector Core内部片上存储，访问延迟远低于Global Memory；
    - 高带宽：Share Memory带宽远高于Global Memory带宽；
    - 线程可见性：Share Memory对线程块内所有线程可见，支持高效的线程间数据交互。

  基于以上特点，Share Memory比较常见的使用场景如下：
  - 线程间数据交换和协作计算；
  - 存储需要频繁重用的中间结果；
  - 作为用户管理的缓存，减少对Global Memory的访问。

### 数据流路径对比<a name="section_path_comparison"></a>

| 特性 | Global Memory路径 | Share Memory路径 |
|------|------------------|-----------------|
| 访问路径 | Global Memory ↔ Data Cache ↔ 寄存器 | Share Memory ↔ 寄存器 |
| 延迟 | 高 | 低 |
| 带宽 | 较低 | 高 |
| 容量 | 大（GB级别） | 小（受限于Unified Buffer） |
| 作用域 | Grid内所有线程 | Block内线程 |
| 缓存机制 | 通过Data Cache | 无缓存，直接访问 |
