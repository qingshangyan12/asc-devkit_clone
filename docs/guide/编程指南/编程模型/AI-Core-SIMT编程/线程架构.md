# 线程架构<a name="ZH-CN_TOPIC_0000002554358977"></a>

SIMT（Single Instruction Multiple Thread，单指令多线程）是一种并行计算架构，它允许每个线程维护独立的状态和控制流。从功能角度来看，每个线程可以执行独立的代码路径。然而，当同一Warp中的线程采用不同的代码路径时，硬件需要串行执行各个分支路径，这会影响性能。因此，合理组织线程结构对于充分发挥SIMT架构的性能优势至关重要。

本章将深入介绍SIMT编程模型的线程架构，包括线程层次结构、Warp执行机制、线程索引计算以及线程调度原理。

## 线程层次结构概述<a name="section_thread_hierarchy_overview"></a>

SIMT编程模型采用分层的线程组织结构，从顶层到底层依次为：Grid（线程块网格）、Thread Block（线程块）、Warp（线程束）和Thread（线程）。这种层次化的设计使得开发者可以方便地将并行计算问题映射到硬件资源上。

### Grid（线程块网格）<a name="section_grid"></a>

Grid是SIMT线程层次结构的最顶层，由多个Thread Block组成。使用内置变量[gridDim](../../语言扩展层/SIMT-BuiltIn关键字.md#li20760123812911)来表示Grid中启用的线程块数量。

**特点：**
- Grid可以是一维、二维或三维结构，便于将线程映射到不同维度的数据结构
- Grid中的所有Thread Block具有相同的尺寸和维度配置
- Grid的维度配置在核函数启动时确定，核函数执行期间不可更改
- 同一Grid中的Thread Block相互独立，可按任意顺序执行

**限制：**
- Grid中Thread Block的总数（gridDim.x × gridDim.y × gridDim.z）不超过65535

### Thread Block（线程块）<a name="section_thread_block"></a>

Thread Block是Grid的组成单元，由若干线程（Thread）组成。使用内置变量[blockDim](../../语言扩展层/SIMT-BuiltIn关键字.md#li076017381191)表示一个Thread Block启用的线程数量。

**特点：**
- Thread Block可以是一维、二维或三维结构，便于映射多维数据
- 同一Thread Block内的线程可以访问共享内存（Share Memory），实现高效的数据交互
- Thread Block内的线程可以通过同步机制进行协调
- 同一Thread Block内的所有线程在同一个Vector Core上执行

**限制：**
- 一个Thread Block最多可以启用2048个线程（blockDim.x × blockDim.y × blockDim.z ≤ 2048）
- Thread Block内的线程数量影响每个线程可用的寄存器数量

## 线程索引与标识<a name="section_thread_indexing"></a>

在SIMT编程模型中，每个线程都有唯一的标识，开发者可以通过内置变量获取线程的身份信息，从而确定每个线程负责处理的数据。

### 内置索引变量<a name="section_builtin_variables"></a>

| 内置变量 | 说明 | 维度表示 |
|---------|------|---------|
| gridDim | Grid的维度大小 | gridDim.x, gridDim.y, gridDim.z |
| blockDim | Thread Block的维度大小 | blockDim.x, blockDim.y, blockDim.z |
| blockIdx | 当前Thread Block在Grid中的索引 | blockIdx.x, blockIdx.y, blockIdx.z |
| threadIdx | 当前线程在Thread Block内的索引 | threadIdx.x, threadIdx.y, threadIdx.z |

### 线程索引计算<a name="section_thread_index_calculation"></a>

gridDim和blockDim均由三维结构[dim3](../../语言扩展层/SIMT-BuiltIn关键字.md#li1136665405)表示，\{x, y, z\}用于指定三个不同维度的大小。各Thread Block可通过线程块索引[blockIdx](../../语言扩展层/SIMT-BuiltIn关键字.md#li1676053814914)进行标识，各线程可通过线程块内线程索引[threadIdx](../../语言扩展层/SIMT-BuiltIn关键字.md#li7760123814919)进行标识。

**线程线性化规则：**

Thread Block中的线程按可预测的方式线性化排列：x维度索引变化最快，其次是y维度，最后是z维度。这意味着：
- 连续的threadIdx.x值表示连续的线程
- threadIdx.y的步长为blockDim.x
- threadIdx.z的步长为blockDim.x × blockDim.y

**一维Grid和Block的索引计算：**

```
全局线程索引 = blockIdx.x * blockDim.x + threadIdx.x
```

**多维Grid和Block的索引计算示例：**

![](../../../figures/线程架构-8.png)

对于二维布局，全局线程索引计算如下：
```
全局线程索引 = blockIdx.y * gridDim.x * blockDim.x * blockDim.y 
             + blockIdx.x * blockDim.x * blockDim.y
             + threadIdx.y * blockDim.x 
             + threadIdx.x
```

### 线程索引使用示例<a name="section_thread_index_example"></a>

以下代码展示了如何在核函数中使用线程索引处理数据：

```
__global__ void vectorAdd(float* A, float* B, float* C, int n) {
    // 计算全局线程索引
    int idx = blockIdx.x * blockDim.x + threadIdx.x;
    
    // 边界检查，防止越界访问
    if (idx < n) {
        C[idx] = A[idx] + B[idx];
    }
}
```

## Warp执行模型<a name="section_warp_model"></a>

### Warp概念<a name="section_warp_concept"></a>

Warp是SIMT架构中基本的调度和执行单位。每个Warp包含32个线程，这些线程：
- 从相同的程序地址开始执行
- 拥有各自的指令地址计数器和寄存器状态
- 可以自由分支并独立执行

Warp一词源于纺织技术，是最早的并行线程技术。Half-Warp（半束）指Warp的前16个或后16个线程；Quarter-Warp（四分之一束）指Warp的前、中前、中后或后8个线程。

### Warp调度机制<a name="section_warp_scheduling"></a>

底层调度过程中，每个Vector Core（AIV）包含4个Warp调度器（Warp Scheduler）。调度规则如下：

- 同一时刻，一个Vector Core只能执行一个Thread Block任务
- 每个Thread Block被切分成多个Warp依次调度执行
- 调度器编号scheduler_id = warp_id % 4
- 不同Warp相互独立执行，无论它们执行的是相同还是不同的代码路径

**Thread Block到Warp的划分：**

当Thread Block启动时，硬件将其中的线程划分为多个Warp：
1. 按线程线性化顺序，每32个线程组成一个Warp
2. Thread Block中的线程数通常应为32的整数倍，以充分利用硬件资源
3. 非整数倍时，最后一个Warp包含不足32个线程，可能影响执行效率

### SIMT执行特性<a name="section_simt_execution"></a>

Warp中的所有线程在同一时刻执行相同指令，这是SIMT架构的核心特征：

**最佳执行效率：**
- 当Warp中的32个线程都执行相同的执行路径时，硬件利用率最高
- 这是SIMT编程追求的理想状态

**分支发散（Branch Divergence）：**
- 当Warp中的线程通过数据相关的条件分支进入不同执行路径时，发生分支发散
- 硬件会串行执行每个分支路径，禁用不在当前路径上的线程
- 分支发散仅在同一Warp内发生，不同Warp之间相互独立

**性能影响：**
- 分支发散会导致Warp执行效率下降
- 开发者应尽量减少Warp内的分支发散，或确保线程按照Warp边界组织分支路径

### Warp执行示例<a name="section_warp_example"></a>

假设一个Thread Block包含128个线程，其Warp划分如下：

| Warp ID | 线程范围 | 调度器ID |
|---------|---------|---------|
| 0 | 线程0~线程31 | 0 |
| 1 | 线程32~线程63 | 1 |
| 2 | 线程64~线程95 | 2 |
| 3 | 线程96~线程127 | 3 |

## 线程块执行规则<a name="section_block_execution_rules"></a>

### 独立性原则<a name="section_independence_principle"></a>

SIMT编程模型要求Thread Block之间没有数据依赖关系，这意味着：

1. **执行顺序无关：** Thread Block可以按任意顺序执行，可以并行执行，也可以串行执行
2. **无跨Block同步：** 一个Thread Block不应依赖其他Thread Block的计算结果
3. **无跨Block通信：** Thread Block之间无法直接进行数据交换和同步

### 资源分配<a name="section_resource_allocation"></a>

Thread Block的资源分配规则：

1. **绑定执行：** Thread Block的所有线程在同一个Vector Core上执行，直至完成
2. **资源占用：** Thread Block所需的寄存器和共享内存在执行期间持续占用
3. **并发限制：** Vector Core可容纳的Thread Block数量受限于每个Block的资源占用

## 编程建议<a name="section_programming_guidelines"></a>

### Thread Block大小选择<a name="section_block_size_selection"></a>

选择合适的blockDim对性能有重要影响：

1. **Warp对齐：** blockDim应为32的整数倍（如32、64、128、256、512、1024）
2. **资源平衡：** 线程数过多会减少每个线程可用的寄存器数量
3. **占用率优化：** 合理的blockDim可以提高硬件占用率

### 减少分支发散<a name="section_reduce_divergence"></a>

1. **分支对齐：** 组织数据使得同一Warp内的线程尽可能执行相同路径
2. **分支重构：** 使用条件优化技术减少Warp内的分支数量

### 线程索引优化<a name="section_index_optimization"></a>

1. **数据访问对齐：** 合理设计线程索引以优化内存访问模式
2. **边界处理：** 始终进行边界检查，防止数组越界访问
