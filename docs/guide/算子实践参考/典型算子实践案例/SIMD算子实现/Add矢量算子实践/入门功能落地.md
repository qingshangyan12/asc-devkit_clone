# 入门功能落地

本节使用基础API进行向量加法的编程指导，介绍基于Ascend C编程模型和Vector计算单元实现向量算子的基本方法，算子中数据搬运和计算流水线通过事件同步进行协调，降低编程复杂度。

## 详细内容

详细内容请参考 [Add入门样例](../../../../../examples/01_simd_cpp_api/00_introduction/01_vector/add/README.md)，该样例涵盖：

- 算子实现：Global Tensor与Local Tensor的使用、DataCopy数据搬运、向量Add计算
- 功能调试：printf格式化输出、DumpTensor张量数据打印
- 编译运行：bisheng编译与执行
- 性能调试：msprof工具上板性能采集

### 可优化方向分析

上述实现正确完成了向量加法功能，但在性能层面存在以下几类可优化的空间。

| 可优化方向 | 当前实现的问题 | 预期优化收益 |
|-----------|---------------|-------------|
| **标量→向量** | 标量循环逐元素计算，无法利用[Vector](../../../../编程指南/编程模型/AI-Core-SIMD编程/抽象硬件架构.md)引擎并行能力 | 使用Add向量指令，单次处理多个元素，获得数量级性能提升 |
| **单核→多核** | 单核时[GM](../../../../编程指南/高级编程/硬件实现/基本架构.md)→[UB](../../../../编程指南/高级编程/硬件实现/基本架构.md)数据搬运请求量不足，带宽未用满 | 多核并行，提高GM带宽利用率 |
| **搬运粒度小** | DataCopy每次搬运小块数据，[MTE2](../../../../编程指南/高级编程/硬件实现/基本架构.md)指令发射密集 | 增大搬运粒度，减少指令开销，提高带宽利用率 |
| **搬运与计算串行** | [MTE2](../../../../编程指南/高级编程/硬件实现/基本架构.md)/[MTE3](../../../../编程指南/高级编程/硬件实现/基本架构.md)搬运与[Vector](../../../../编程指南/编程模型/AI-Core-SIMD编程/抽象硬件架构.md)计算串行执行，存在等待空闲 | [双缓冲](../../../../技术附录/概念原理和术语/性能优化技术原理/DoubleBuffer.md)Ping-Pong机制，搬运与计算流水并行 |
| **L2 Cache污染** | Add输入数据只读一次，经过L2 Cache反而占用空间、污染其他可复用数据 | [SetL2CacheHint](../../../../../api/SIMD-API/基础数据结构/GlobalTensor/SetL2CacheHint.md)(CACHE_MODE_DISABLE)绕过L2 Cache，减少开销 |
| **UB Bank Conflict** | Vector指令一拍访存数据可能落在同一Bank Group，导致访存串行化 | 调整地址布局和搬运长度，避免[Bank Conflict](../../../../算子实践参考/SIMD算子性能优化/内存访问/避免UB的bank冲突/避免UB的bank冲突.md) |

> 以上各优化方向的详细实现方案，请参见[中级性能优化](./中级性能优化.md)。
