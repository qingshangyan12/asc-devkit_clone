# 入门功能落地<a name="ZH-CN_TOPIC_000000_ADD_ENTRY"></a>

本节使用基础API Matmul进行矩阵乘法的编程指导，介绍基于Ascend C编程模型和Cube计算单元实现矩阵算子的基本方法，算子中数据搬运和计算流水线通过事件同步进行协调，降低编程复杂度。

## 算子概述

Matmul计算公式：
$$
C_{M, N} = A_{M, K} \times B_{K, N}
$$

- A：左矩阵，形状[M, K]，数据类型half
- B：右矩阵，形状[K, N]，数据类型half
- C：结果矩阵，形状[M, N]，数据类型half

本样例中 M=256, K=64, N=256，使用2个核并行计算。

> **说明**  
> 在矩阵乘法中，**M方向**指矩阵的行方向，**K方向**指矩阵乘法的内维（累加维度）。后续实现中将沿M方向切分矩阵到多核并行计算。

## 算子实现

矩阵乘算子的计算逻辑遵循"搬入-格式转换-计算-搬出"的四级流水结构：

1. 将输入数据从Global Memory搬入L1 Buffer，同步完成[ND](../../../../技术附录/概念原理和术语/神经网络和算子/数据排布格式.md)→[NZ](../../../../技术附录/概念原理和术语/神经网络和算子/数据排布格式.md)格式转换；
2. 将数据从L1 Buffer搬入L0 Buffer，同步完成NZ→ZZ/ZN格式转换；
3. 在L0上执行矩阵乘计算，结果暂存于L0C；
4. 将计算结果从L0C搬出到Global Memory，同步完成NZ→ND格式转换和FP32→FP16精度转换。

![Cube计算单元数据访问](../../../../figures/Cube计算单元数据访问.png)

> **说明**  
> Cube计算单元要求矩阵以特定的数据排布格式才能高效计算，而输入数据通常为标准ND格式。因此在各级数据搬运时需同步完成格式转换。关于各数据排布格式的详细说明，请参见[数据排布格式](../../../../技术附录/概念原理和术语/神经网络和算子/数据排布格式.md)。

完整样例代码请参见[matmul样例](https://gitcode.com/cann/asc-devkit/tree/master/examples/01_simd_cpp_api/00_introduction/02_matrix/matmul)。算子实现代码如下：

```cpp
constexpr uint32_t CUBE_BLOCK = 16;

template <
    uint32_t M, uint32_t K, uint32_t N, uint32_t singleCoreM, uint32_t baseM, uint32_t baseK, uint32_t baseN>
__global__ __cube__ void mmad_custom(__gm__ uint8_t* a, __gm__ uint8_t* b, __gm__ uint8_t* c)
{
    AscendC::GlobalTensor<half> aGM;
    AscendC::GlobalTensor<half> bGM;
    AscendC::GlobalTensor<half> cGM;
    uint32_t mIterIdx = AscendC::GetBlockIdx() % (M / singleCoreM);
    aGM.SetGlobalBuffer((__gm__ half*)a + mIterIdx * singleCoreM * K);
    bGM.SetGlobalBuffer((__gm__ half*)b);
    cGM.SetGlobalBuffer((__gm__ half*)c + mIterIdx * singleCoreM * N);
    AscendC::LocalMemAllocator<AscendC::Hardware::L1> l1Allocator;
    AscendC::LocalMemAllocator<AscendC::Hardware::L0A> l0aAllocator;
    AscendC::LocalMemAllocator<AscendC::Hardware::L0B> l0bAllocator;
    AscendC::LocalMemAllocator<AscendC::Hardware::L0C> l0cAllocator;
    // 使用LocalMemAllocator按申请顺序分配片上内存，避免手动维护LocalTensor地址偏移。
    AscendC::LocalTensor<half> a1Local = l1Allocator.Alloc<AscendC::TPosition::A1, half>(baseM * baseK);
    AscendC::LocalTensor<half> b1Local = l1Allocator.Alloc<AscendC::TPosition::B1, half>(baseK * baseN);
    AscendC::LocalTensor<half> a2Local = l0aAllocator.Alloc<AscendC::TPosition::A2, half>(baseM * baseK);
    AscendC::LocalTensor<half> b2Local = l0bAllocator.Alloc<AscendC::TPosition::B2, half>(baseK * baseN);
    AscendC::LocalTensor<float> cLocal = l0cAllocator.Alloc<AscendC::TPosition::CO1, float>(baseM * baseN);
    // A矩阵GM->L1调用DataCopy接口 + Nd2NzParams结构体参数
    AscendC::DataCopy(a1Local, aGM, AscendC::Nd2NzParams{1, baseM, baseK, 0, K, baseM, 1, 0});
    // B矩阵GM->L1调用DataCopy接口 + Nd2NzParams结构体参数
    AscendC::DataCopy(b1Local, bGM, AscendC::Nd2NzParams{1, baseK, baseN, 0, N, baseK, 1, 0});
    // GM->L1的DataCopy由MTE2流水完成，后续L1->L0的LoadData由MTE1流水读取L1数据；
    // 使用MTE2_MTE1事件，使MTE1等待MTE2，避免LoadData读取到尚未搬运完成的数据。
    AscendC::SetFlag<AscendC::HardEvent::MTE2_MTE1>(EVENT_ID0);
    AscendC::WaitFlag<AscendC::HardEvent::MTE2_MTE1>(EVENT_ID0);
    // A矩阵L1->L0A调用LoadData接口 + LoadData2DParams结构体参数
#if defined(__NPU_ARCH__) && (__NPU_ARCH__ == 2201)
    // A矩阵L1->L0A（Nz->Zz）
    for (int i = 0; i < baseM / CUBE_BLOCK; ++i) {
        AscendC::LoadData(a2Local[i * baseK * CUBE_BLOCK], a1Local[i * 512 / sizeof(half)],
            AscendC::LoadData2DParams{0, baseK / CUBE_BLOCK, baseM / CUBE_BLOCK, 0, 0, false, 0});
    }
#elif defined(__NPU_ARCH__) && (__NPU_ARCH__ == 3510)
    // A矩阵L1->L0A（Nz->Nz）
    for (int i = 0; i < baseM / CUBE_BLOCK; ++i) {
        AscendC::LoadData(a2Local[i * 512 / sizeof(half)], a1Local[i * 512 / sizeof(half)],
            AscendC::LoadData2DParams{0, baseK / CUBE_BLOCK, baseM / CUBE_BLOCK, 0, (baseM / CUBE_BLOCK - 1), false, 0});
    }
#endif
    // B矩阵L1->L0B调用LoadData接口 + LoadData2DParams结构体参数（ifTranspose=true，NZ->ZN转置）
    for (int i = 0; i < baseK / CUBE_BLOCK; ++i) {
        AscendC::LoadData(b2Local[i * baseN * CUBE_BLOCK], b1Local[i * 512 / sizeof(half)],
            AscendC::LoadData2DParams{0, baseN / CUBE_BLOCK, baseK / CUBE_BLOCK, 0, 0, true, 0});
    }
    // L1->L0的LoadData由MTE1流水完成，后续Mmad由M流水读取L0A/L0B数据；
    // 使用MTE1_M事件，使M流水等待MTE1，避免Mmad读取到尚未搬运完成的数据。
    AscendC::SetFlag<AscendC::HardEvent::MTE1_M>(EVENT_ID0);
    AscendC::WaitFlag<AscendC::HardEvent::MTE1_M>(EVENT_ID0);
    // 矩阵乘调用Mmad接口 + MmadParams结构体参数
    AscendC::Mmad(cLocal, a2Local, b2Local, AscendC::MmadParams{baseM, baseN, baseK, 0, false, true});
    // Mmad由M流水完成并写入L0C，后续Fixpipe由FIX流水读取L0C并搬运到GM；
    // 使用M_FIX事件，使FIX流水等待M流水，避免Fixpipe读取到尚未计算完成的数据。
    AscendC::SetFlag<AscendC::HardEvent::M_FIX>(EVENT_ID0);
    AscendC::WaitFlag<AscendC::HardEvent::M_FIX>(EVENT_ID0);
    // L0C->GM搬运调用Fixpipe+FixpipeParamsV220结构体参数
    AscendC::Fixpipe(cGM, cLocal,
        AscendC::FixpipeParamsV220{baseN, baseM, baseM, N, false, QuantMode_t::F322F16, 0, 1, 0, 0, 0});
    AscendC::PipeBarrier<PIPE_ALL>();
}
```

### 实现流程

下面按步骤说明各环节的做法和原因。

| 阶段 | 数据流动 | 实现 | 目的 |
|------|----------|-----------|------|
| **初始化和分核处理** | — | 通过[GetBlockIdx](https://gitcode.com/cann/asc-devkit/blob/master/docs/api/SIMD-API/%E5%9F%BA%E7%A1%80API/%E7%B3%BB%E7%BB%9F%E5%8F%98%E9%87%8F%E8%AE%BF%E9%97%AE/GetBlockIdx.md)获取当前核编号，通过模板参数`singleCoreM`计算M方向起始偏移`mIterIdx`，每个核负责singleCoreM=128行。A矩阵按行切分，B矩阵每个核使用完整数据 | 将矩阵沿M方向切分到多核并行，各核独立计算、各自写回GM的不同区域，无需跨核通信，可实现算力的线性扩展 |
| Stage 1<br>Memory数据搬运 | GM → L1 | 调用[DataCopy](https://gitcode.com/cann/asc-devkit/blob/master/docs/api/SIMD-API/%E5%9F%BA%E7%A1%80API/Memory%E6%95%B0%E6%8D%AE%E6%90%AC%E8%BF%90/DataCopy/DataCopy.md)将A和B从GM搬运到L1，随路完成ND→NZ格式转换 | Cube计算单元要求数据以NZ分形格式（16×16分形、列优先）组织，可直接读取完整分形送入计算，而输入数据为ND行优先格式，因此首次搬运时同步完成转换 |
| Stage 2<br>矩阵数据搬运 | L1 → L0A/L0B | 调用[LoadData](https://gitcode.com/cann/asc-devkit/blob/master/docs/api/SIMD-API/基础API/矩阵计算（ISASI）/数据搬运/LoadData/LoadData.md)将数据从L1搬运到L0A/L0B，A矩阵循环逐分形搬运（dav-2201为NZ→ZZ转换，dav-3510保持NZ格式），B矩阵双架构统一使用循环逐分形搬运且ifTranspose=true完成NZ→ZN转置 | Mmad要求左矩阵为ZZ格式（dav-2201）或NZ格式（dav-3510）、右矩阵为ZN格式（分形内列优先且整体转置），与L1中的NZ格式不同，因此搬运时同步转换 |
| Stage 3<br>Cube矩阵乘 | L0A×L0B → L0C | 调用[Mmad](https://gitcode.com/cann/asc-devkit/blob/master/docs/api/SIMD-API/基础API/矩阵计算（ISASI）/矩阵计算/Mmad.md)在L0上执行C\[baseM, baseN\] += A\[baseM, baseK\] × B\[baseK, baseN\]，结果以float32存入L0C | 本样例baseK=64不分块，单次Mmad即可完成 |
| Stage 4<br>计算结果矩阵数据搬运 | L0C → GM | 调用[Fixpipe](https://gitcode.com/cann/asc-devkit/blob/master/docs/api/SIMD-API/%E5%9F%BA%E7%A1%80API/%E7%9F%A9%E9%98%B5%E8%AE%A1%E7%AE%97%EF%BC%88ISASI%EF%BC%89/%E6%95%B0%E6%8D%AE%E6%90%AC%E8%BF%90/Fixpipe.md)将结果搬运到Global Memory中当前核对应的输出区域，同步完成NZ→ND格式转换和FP32→FP16精度转换 | Mmad输出为NZ分形格式且精度float32，而最终输出需要ND行优先格式和half精度，Fixpipe在搬出时同步完成这两个变换 |
| **流水同步** | — | DataCopy、LoadData、Mmad和Fixpipe由不同硬件流水线（MTE2、MTE1、M、FIX）执行。代码使用SetFlag/WaitFlag配合HardEvent按数据依赖进行精确流水线同步：DataCopy后通过`MTE2_MTE1`事件使MTE1等待MTE2；LoadData后通过`MTE1_M`事件使M等待MTE1；Mmad后通过`M_FIX`事件使FIX等待M；Fixpipe后使用`PipeBarrier<PIPE_ALL>`全局收尾 | SetFlag在生产者流水完成后写入同步事件，WaitFlag让消费者流水等待对应事件。相比全同步屏障，这种按流水线间数据依赖的精确同步允许不同流水线在无依赖的阶段并行执行，提升整体吞吐 |

### 可优化方向分析

上述实现正确完成了矩阵乘功能，但在性能层面存在以下几类可优化的空间。

| 可优化方向 | 当前实现的问题 | 预期优化收益 |
|-----------|---------------|-------------|
| **流水线串行执行** | 当前实现中使用PipeBarrier和SetFlag/WaitFlag进行流水线同步，但未采用双缓冲机制，MTE2、MTE1、M、FIX各硬件单元无法充分流水并行 | 通过双缓冲和硬件事件同步，使四个单元流水并行，显著提升吞吐 |
| **L1/L0 单缓冲区** | A、B 矩阵在 L1 和 L0 中各只有一份缓冲区，下一轮数据必须等上一轮消费完才能搬入 | 改为 Ping-Pong 双缓冲，让数据搬运和计算重叠执行 |
| **MTE2 搬运粒度小** | 每次 DataCopyIn 搬入一个 baseM×baseK 小块，MTE2 指令发射密集 | 增大搬运粒度，减少 MTE2 指令次数，提高带宽利用率 |
| **MTE1 指令队列压力** | dav-2201 下 LoadData2D 需 for 循环多次发射，MTE1 指令队列深度有限 | 使用更高效的 Load 方式，降低 MTE1 队列压力 |
| **K 方向不切分** | 当前 baseK=64 只有一个 K 块，当 K 很大时 Matrix 无法一次性装入 L1 | K 方向分块循环，适配更大矩阵 |
| **B 矩阵搬运顺序** | A、B 数据依次等量搬运，较大的矩阵场景下 B 数据到位晚可能成为流水线瓶颈 | 优先搬运 B 矩阵，缓解数据紧张 |
| **Tiling 参数运行时计算** | 核内使用 Scalar 逐级计算各维度参数，引入额外指令开销 | 编译期确定参数，减少运行时开销 |
| **多核切分固定** | 硬编码 `M / singleCoreM` 计算核数分配，仅适用于固定矩阵规模和核数场景 | 通用切分策略，支撑任意核数和矩阵规模的自动分配 |
| **Fixpipe 与 Cube 串行** | L0C 写回必须等 Mmad 全部完成后才开始，写回期间 Cube 空闲 | 细粒度 Fixpipe 发射，令写回与计算流水重叠 |

> 以上各优化方向的详细实现方案，请参见[中级性能优化](./中级性能优化.md)和[高级极限打磨](./高级极限打磨.md)。

## 功能调试

### printf

该接口提供CPU域或NPU域调试场景下的格式化输出功能。

在算子kernel侧实现代码中需要输出日志信息的地方调用printf接口打印相关内容。

示例如下：

```cpp
AscendC::printf("matmul blockIdx=%d\n", AscendC::GetBlockIdx());
```

> [!CAUTION]注意 
>printf（PRINTF）接口打印功能会对算子实际运行的性能带来一定影响，通常在调测阶段使用。开发者可以按需通过设置ASCENDC\_DUMP=0的方式关闭打印功能。

### DumpTensor

基于算子工程开发的算子，可以使用该接口Dump指定Tensor的内容。同时支持打印自定义的附加信息（仅支持uint32\_t数据类型的信息），比如打印当前行号等。

在算子kernel侧实现代码中需要打印Tensor数据的地方调用DumpTensor接口打印相关内容。样例如下：

```cpp
AscendC::DumpTensor(cLocal, baseM * baseN);
```

> [!CAUTION]注意 
>DumpTensor接口打印功能会对算子实际运行的性能带来一定影响，通常在调测阶段使用。开发者可以按需通过设置ASCENDC\_DUMP=0来关闭打印功能。

## 性能调试

### msProf工具介绍
msProf工具是单算子性能分析工具。包含msprof op和msprof op simulator两种使用方式。该工具协助用户定位算子内存、算子代码以及算子指令的异常，实现全方位的算子调优。当前支持基于不同运行模式（上板或仿真）和不同文件形式（可执行文件或算子二进制.o文件）进行性能数据的采集和自动解析。

- 上板性能采集

    通过上板性能采集，可以直接测定算子在昇腾AI处理器上的运行时间。该方式适合上板环境中快速定位算子性能问题。

    基于可执行文件demo通过msprof op执行算子调优：
    ```
    msprof op ./demo
    ```

- 性能数据说明  
    命令完成后，会在默认目录下生成以“OPPROF_{timestamp}_XXX”命名的文件夹,性能数据文件夹结构示例如下：

    ```bash
    ├──dump                       # 原始的性能数据，用户无需关注
    ├──ArithmeticUtilization.csv  # cube/vector指令cycle占比
    ├──L2Cache.csv                # L2 Cache命中率，影响MTE2，建议合理规划数据搬运逻辑，增加命中率
    ├──Memory.csv                 # UB，L1和主存储器读写带宽速率
    ├──MemoryL0.csv               # L0A，L0B，和L0C读写带宽速率
    ├──MemoryUB.csv               # Vector和Scalar到UB的读写带宽速率
    ├──OpBasicInfo.csv            # 算子基础信息
    ├──PipeUtilization.csv        # 采集计算单元和搬运单元耗时和占比
    ├──ResourceConflictRatio.csv  # UB上的 bank group、bank conflict和资源冲突率在所有指令中的占比
    └──visualize_data.bin         # MindStudio Insight呈现文件
    ```

更多msProf工具使用方式请参考[MindStudio工具](https://www.hiascend.com/document/redirect/CannCommercialToolOpDev)算子调优（msOpProf）中的内容。
