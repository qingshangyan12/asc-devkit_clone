# 入门功能落地<a name="ZH-CN_TOPIC_000000_GELU_REG_ENTRY"></a>

本节以Gelu算子为例，介绍基于Ascend C静态Tensor编程模型实现多核向量算子的基本方法，重点说明Gelu公式的化简策略与基础API的实现方式，帮助开发者快速入门Reg矢量算子开发。

## 算子概述

Gelu近似公式计算为：

$$
GELU(x) \approx 0.5 \cdot x \cdot \left(1 + \tanh\left(\sqrt{\frac{2}{\pi}} \cdot \left(x + 0.044715 \cdot x^3\right)\right)\right)
$$

tanh的计算公式为：

$$
\tanh(u) = \frac{e^{2u} - 1}{e^{2u} + 1}
$$

其中，$u = \sqrt{\frac{2}{\pi}} \cdot (x + 0.044715 \cdot x^3)$。

将tanh公式代入Gelu公式并化简，得到：

$$
GELU(x) \approx \frac{x}{1 + e^{-2 \cdot \sqrt{\frac{2}{\pi}} \cdot (x + 0.044715 \cdot x^3)}}
$$

其中，$-2 \cdot \sqrt{\frac{2}{\pi}} \approx -1.595769$。

本样例以化简后的公式进行编程计算。用户在设计向量算子时，需要考虑对原始计算进行化简，可以有效减少计算步骤和内存占用。

- x：输入，形状为[8192, 8192]，数据类型为float；
- y：输出，形状为[8192, 8192]，数据类型为float；

Gelu算子的计算逻辑遵循"搬入-计算-搬出"三段式流水结构：

1. 将输入数据x从Global Memory搬运到Unified Buffer；
2. 在Unified Buffer上执行Gelu计算（8步向量运算）；
3. 将计算结果从Unified Buffer搬运到Global Memory。


## 计算步骤分析

为说明公式化简对算子性能的影响，对比三种不同的Gelu计算实现方式。

**方式1**：

$$
GELU(x) \approx 0.5 \cdot x \cdot \left(1 + \frac{e^{2 \cdot \sqrt{\frac{2}{\pi}} \cdot (x + 0.044715 \cdot x^3)} - 1}{e^{2 \cdot \sqrt{\frac{2}{\pi}} \cdot (x + 0.044715 \cdot x^3)} + 1}\right)
$$

**方式2**：

$$
GELU(x) \approx \frac{x}{1 + e^{-1.595769 \cdot x - 0.071405 \cdot x^3}}
$$

**方式3**：

$$
GELU(x) \approx \frac{x}{1 + e^{-1.595769 \cdot (x + 0.044715 \cdot x^3)}}
$$

| 计算方式 | 计算指令数 | Unified Buffer（UB）内存份数 |
|:---|:---:|:---:|
| 方式1 | 13 | 5 |
| 方式2 | 8 | 3 |
| 方式3 | 8 | 2 |

令输入UB内存为xLocal，输出UB内存为yLocal，临时UB内存统一用tmp0、tmp1、tmp2等表示。

**方式1计算步骤分解**（共13条指令，需5份内存）：

| 步骤 | 计算内容 | 计算指令 | 内存占用 |
|:---:|:---|:---:|:---|
| 1 | yLocal = x² | Mul | xLocal, yLocal |
| 2 | yLocal = x³ | Mul | xLocal, yLocal |
| 3 | yLocal = 0.044715 * x³ | Muls | yLocal |
| 4 | yLocal = x + 0.044715 * x³ | Add | xLocal, yLocal |
| 5 | yLocal = √(2/π) * (x + 0.044715 * x³) | Muls | yLocal |
| 6 | yLocal = 2u | Muls | yLocal |
| 7 | tmp0 = e^(2u) | Exp | tmp0, yLocal |
| 8 | tmp1 = e^(2u) - 1 | Adds | tmp1, yLocal |
| 9 | tmp2 = e^(2u) + 1 | Adds | tmp2, yLocal |
| 10 | tmp1 = tanh(u) = (e^(2u) - 1) / (e^(2u) + 1) | Div | tmp1, tmp2 |
| 11 | yLocal = 1 + tanh(u) | Adds | yLocal, tmp1 |
| 12 | yLocal = x * (1 + tanh(u)) | Mul | xLocal, yLocal |
| 13 | yLocal = 0.5 * x * (1 + tanh(u)) | Muls | yLocal |

**方式2计算步骤分解**（共8条指令，需3份内存）：

| 步骤 | 计算内容 | 计算指令 | 内存占用 |
|:---:|:---|:---:|:---|
| 1 | yLocal = x² | Mul | xLocal, yLocal |
| 2 | yLocal = x³ | Mul | xLocal, yLocal |
| 3 | yLocal = -0.071405 * x³ | Muls | yLocal |
| 4 | tmp0 = -1.595769 * x | Muls | tmp0, xLocal |
| 5 | yLocal = -1.595769 * x + (-0.071405 * x³) | Add | yLocal, tmp0 |
| 6 | yLocal = e^(-1.595769 * x - 0.071405 * x³) | Exp | yLocal |
| 7 | yLocal = 1 + e^(...) | Adds | yLocal |
| 8 | yLocal = x / (1 + e^(...)) | Div | yLocal, xLocal |

**方式3计算步骤分解**（共8条指令，需2份内存）：

| 步骤 | 计算内容 | 计算指令 | 内存占用 |
|:---:|:---|:---:|:---|
| 1 | yLocal = x² | Mul | yLocal, xLocal |
| 2 | yLocal = x³ | Mul | yLocal, xLocal |
| 3 | yLocal = 0.044715 * x³ | Muls | yLocal |
| 4 | yLocal = x + 0.044715 * x³ | Add | yLocal |
| 5 | yLocal = -1.595769 * (x + 0.044715 * x³) | Muls | yLocal |
| 6 | yLocal = e^(-1.595769 * (x + 0.044715 * x³)) | Exp | yLocal |
| 7 | yLocal = 1 + e^(...) | Adds | yLocal |
| 8 | yLocal = x / (1 + e^(...)) | Div | yLocal, xLocal |

**对比总结**：

- **计算指令数**：方式2和方式3均比方式1减少 **5条指令**
- **内存份数**：方式2比方式1减少 **1份内存**，方式3比方式1减少 **3份内存**
- **实现选择**：方式3是最优实现，计算指令数最少，内存占用最低，本样例采用方式3实现

## 算子分析

### 明确分核与分块策略

本样例中输入数据shape为[8192, 8192]，总数据量为8192 × 8192 = 67108864个float元素。采用64核并行处理，M方向切分2份，N方向切分32份，每个核处理的数据块大小为4096 × 4096。

样例配置：
- 核数：64（M方向2份，N方向32份）
- `tileLen = 8192`，单次搬运数据量为 8192 × 4B = 32768 Byte
- 使用双缓冲（Ping-Pong），UB需容纳4份tileLen数据（xPing, xPong, yPing, yPong）

### Kernel类定义

定义`KernelGelu`模板类，模板参数包括`totalM`（矩阵行数）、`totalN`（矩阵列数）、`singleCoreM`（每个核处理的行数）、`singleCoreN`（每个核处理的列数）和`tileLen`（单次搬运数据量）：

```cpp
template <uint32_t totalM, uint32_t totalN, uint32_t singleCoreM, uint32_t singleCoreN, uint32_t tileLen>
class KernelGelu {
public:
    __aicore__ inline KernelGelu() {}
    __aicore__ inline void Init(GM_ADDR x, GM_ADDR y);
    __aicore__ inline void Process();
private:
    __aicore__ inline void GeluCompute(
        const AscendC::LocalTensor<float>& xLocal,
        const AscendC::LocalTensor<float>& yLocal, uint32_t n);

    // 双缓冲地址布局
    static constexpr uint32_t xAddrPing = 0;
    static constexpr uint32_t xAddrPong = tileLen * sizeof(float);
    static constexpr uint32_t yAddrPing = xAddrPong + tileLen * sizeof(float);
    static constexpr uint32_t yAddrPong = yAddrPing + tileLen * sizeof(float);

    AscendC::GlobalTensor<float> xGm;
    AscendC::GlobalTensor<float> yGm;
    uint32_t actualSingleCoreM;
    uint32_t actualSingleCoreN;
};
```

UB地址布局如下（双缓冲，4块）：

```
UB内存分配（双缓冲）：
┌──────────────┐
│  xPing       │  0x00000
│  8192*4B     │
├──────────────┤
│  xPong       │  tileLen*4
│  8192*4B     │
├──────────────┤
│  yPing       │  2*tileLen*4
│  8192*4B     │
├──────────────┤
│  yPong       │  3*tileLen*4
│  8192*4B     │
└──────────────┘
```

### Init函数实现

Init函数完成Global Memory地址初始化，根据核ID和切分策略计算当前核应处理的数据偏移：

```cpp
__aicore__ inline void InitGMOffsets()
{
    uint32_t blockIdx = AscendC::GetBlockIdx();
    constexpr uint32_t mIndex = (totalM + singleCoreM - 1) / singleCoreM;
    constexpr uint32_t nIndex = (totalN + singleCoreN - 1) / singleCoreN;
    constexpr uint32_t tailSingleCoreM = totalM - (mIndex - 1) * singleCoreM;
    constexpr uint32_t tailSingleCoreN = totalM - (nIndex - 1) * singleCoreN;

    uint32_t mIterIdx = blockIdx % mIndex;
    uint32_t nIterIdx = blockIdx / mIndex;
    actualSingleCoreM = (mIterIdx == (mIndex - 1)) ? tailSingleCoreM : singleCoreM;
    actualSingleCoreN = (nIterIdx == (nIndex - 1)) ? tailSingleCoreN : singleCoreN;

    uint64_t gmOffset = mIterIdx * singleCoreM * totalN + nIterIdx * singleCoreN;
    xGm = xGm[gmOffset];
    yGm = yGm[gmOffset];
}
```

### 核函数定义与调用

```cpp
template <uint32_t totalM, uint32_t totalN, uint32_t singleCoreM, uint32_t singleCoreN, uint32_t tileLen>
__global__ __vector__ void gelu_custom(GM_ADDR x, GM_ADDR y)
{
    KernelGelu<totalM, totalN, singleCoreM, singleCoreN, tileLen> op;
    op.Init(x, y);
    op.Process();
    AscendC::PipeBarrier<PIPE_ALL>();
}
```

在Host侧使用内核调用符`<<<>>>`调用核函数：

```cpp
constexpr uint32_t totalM = 8192;
constexpr uint32_t totalN = 8192;
constexpr uint32_t singleCoreM = 4096;
constexpr uint32_t singleCoreN = 256;
constexpr uint32_t tileLen = 2 * singleCoreN;
constexpr uint32_t mTileNum = (totalM + singleCoreM - 1) / singleCoreM;
constexpr uint32_t nTileNum = (totalN + singleCoreN - 1) / singleCoreN;
uint32_t numBlocks = mTileNum * nTileNum;

gelu_custom<totalM, totalN, singleCoreM, singleCoreN, tileLen>
    <<<numBlocks, nullptr, stream>>>(inputDevice, outputDevice);
```

## 数据搬入

数据搬入阶段将输入数据从Global Memory搬运到Unified Buffer。本样例通过静态地址分配UB空间，使用双缓冲（Ping-Pong）机制实现搬运与计算的流水线并行，并使用`DataCopyPad`接口处理非连续内存搬运。

### UB内存初始化

使用静态地址创建LocalTensor，指定位置为`VECCALC`：

```cpp
AscendC::LocalTensor<float> xPing(AscendC::TPosition::VECCALC, xAddrPing, tileLen);
AscendC::LocalTensor<float> yPing(AscendC::TPosition::VECCALC, yAddrPing, tileLen);
AscendC::LocalTensor<float> xPong(AscendC::TPosition::VECCALC, xAddrPong, tileLen);
AscendC::LocalTensor<float> yPong(AscendC::TPosition::VECCALC, yAddrPong, tileLen);
```

### DataCopyPad搬入

由于每个核处理的数据块在Global Memory中可能不连续（N方向切分时存在stride），使用`DataCopyPad`接口进行带步幅的数据搬运：

```cpp
AscendC::WaitFlag<AscendC::HardEvent::V_MTE2>(eventID);

uint32_t blockLen = actualSingleCoreN * sizeof(float);
uint32_t srcStride = (totalN - actualSingleCoreN) * sizeof(float);
uint32_t dstStride = 0;
AscendC::DataCopyExtParams copyParams = {
    static_cast<uint16_t>(copyRows), blockLen, srcStride, dstStride, 0};
AscendC::DataCopyPadExtParams<float> padParams = {false, 0, 0, 0};
AscendC::DataCopyPad<float>(xLocal, xGm[loopIdx * tileRow * totalN], copyParams, padParams);
```

其中`srcStride`表示GM中相邻行之间的跳跃字节数，`dstStride=0`表示UB中数据连续存放。`DataCopyPad`相比`DataCopy`支持更灵活的搬运参数，适用于非连续内存场景。

## 数据计算

数据计算阶段在Unified Buffer上执行Gelu运算。本样例采用方式3（化简后的公式）实现8步向量计算，使用基础API完成每次运算。

### GeluCompute函数实现

```cpp
__aicore__ inline void GeluCompute(
    const AscendC::LocalTensor<float>& xLocal,
    const AscendC::LocalTensor<float>& yLocal, uint32_t n)
{
    // yLocal = x * x = x²
    AscendC::Mul(yLocal, xLocal, xLocal, n);
    AscendC::PipeBarrier<PIPE_V>();
    // yLocal = x² * x = x³
    AscendC::Mul(yLocal, yLocal, xLocal, n);
    AscendC::PipeBarrier<PIPE_V>();
    // yLocal = x³ * 0.044715 = 0.044715 * x³
    AscendC::Muls(yLocal, yLocal, COEFF_A, n);
    AscendC::PipeBarrier<PIPE_V>();
    // yLocal = x + 0.044715 * x³
    AscendC::Add(yLocal, xLocal, yLocal, n);
    AscendC::PipeBarrier<PIPE_V>();
    // yLocal = -1.595769 * (x + 0.044715 * x³)
    AscendC::Muls(yLocal, yLocal, COEFF_B, n);
    AscendC::PipeBarrier<PIPE_V>();
    // yLocal = e^(-1.595769 * (x + 0.044715 * x³))
    AscendC::Exp(yLocal, yLocal, n);
    AscendC::PipeBarrier<PIPE_V>();
    // yLocal = 1 + e^(-1.595769 * (x + 0.044715 * x³))
    AscendC::Adds(yLocal, yLocal, (float)1.0, n);
    AscendC::PipeBarrier<PIPE_V>();
    // yLocal = x / (1 + e^(-1.595769 * (x + 0.044715 * x³)))
    AscendC::Div(yLocal, xLocal, yLocal, n);
}
```

关键点：
- 每次向量运算后使用`PipeBarrier<PIPE_V>()`确保向量指令执行完成，避免数据依赖错误
- 方式3仅需2份UB内存（xLocal和yLocal），中间结果复用yLocal
- `COEFF_A = 0.044715f`、`COEFF_B = -1.595769f`为编译期常量

### 事件同步机制

双缓冲模式下，搬入、计算、搬出三个阶段使用两个Event ID（EVENT_ID0和EVENT_ID1）交替同步，实现Ping-Pong流水线并行：

```
时间 ──────────────────────────────────────────────────────▶
Ping:  [搬入x] [计算Gelu] [搬出y] [搬入x] [计算Gelu] [搬出y] ...
Pong:            [搬入x] [计算Gelu] [搬出y] [搬入x] [计算Gelu] ...
                     ▲ 流水并行，隐藏搬运延迟
```

## 数据搬出

数据搬出阶段将计算结果从Unified Buffer写回Global Memory，同样使用`DataCopyPad`处理非连续内存写出：

```cpp
AscendC::SetFlag<AscendC::HardEvent::V_MTE3>(eventID);
AscendC::WaitFlag<AscendC::HardEvent::V_MTE3>(eventID);

copyParams.srcStride = 0;
copyParams.dstStride = srcStride;
AscendC::DataCopyPad<float>(yGm[loopIdx * tileRow * totalN], yLocal, copyParams);
AscendC::SetFlag<AscendC::HardEvent::MTE3_V>(eventID);
```

写出时`srcStride=0`（UB中数据连续），`dstStride`为GM中相邻行之间的跳跃字节数，与搬入时的`srcStride`一致。

### Process函数完整实现

将数据搬入、数据计算、数据搬出三个阶段组合起来，`Process`函数的完整实现如下：

```cpp
__aicore__ inline void Process()
{
    AscendC::LocalTensor<float> xPing(AscendC::TPosition::VECCALC, xAddrPing, tileLen);
    AscendC::LocalTensor<float> yPing(AscendC::TPosition::VECCALC, yAddrPing, tileLen);
    AscendC::LocalTensor<float> xPong(AscendC::TPosition::VECCALC, xAddrPong, tileLen);
    AscendC::LocalTensor<float> yPong(AscendC::TPosition::VECCALC, yAddrPong, tileLen);

    constexpr uint32_t tileRow = tileLen / singleCoreN;
    uint32_t loopNum = (actualSingleCoreM + tileRow - 1) / tileRow;
    uint32_t tailRow = actualSingleCoreM - (loopNum - 1) * tileRow;

    AscendC::SetFlag<AscendC::HardEvent::V_MTE2>(EVENT_ID0);
    AscendC::SetFlag<AscendC::HardEvent::V_MTE2>(EVENT_ID1);
    AscendC::SetFlag<AscendC::HardEvent::MTE3_V>(EVENT_ID0);
    AscendC::SetFlag<AscendC::HardEvent::MTE3_V>(EVENT_ID1);

    for (uint32_t loopIdx = 0; loopIdx < loopNum; loopIdx++) {
        uint32_t copyRows = (loopIdx == (loopNum - 1)) ? tailRow : tileRow;

        int32_t eventID = ((loopIdx & 1) == 0 ? EVENT_ID0 : EVENT_ID1);
        AscendC::LocalTensor<float>& xLocal = ((loopIdx & 1) == 0 ? xPing : xPong);
        AscendC::LocalTensor<float>& yLocal = ((loopIdx & 1) == 0 ? yPing : yPong);

        // === 数据搬入 ===
        AscendC::WaitFlag<AscendC::HardEvent::V_MTE2>(eventID);
        uint32_t blockLen = actualSingleCoreN * sizeof(float);
        uint32_t srcStride = (totalN - actualSingleCoreN) * sizeof(float);
        uint32_t dstStride = 0;
        AscendC::DataCopyExtParams copyParams = {
            static_cast<uint16_t>(copyRows), blockLen, srcStride, dstStride, 0};
        AscendC::DataCopyPadExtParams<float> padParams = {false, 0, 0, 0};
        AscendC::DataCopyPad<float>(xLocal, xGm[loopIdx * tileRow * totalN], copyParams, padParams);

        AscendC::SetFlag<AscendC::HardEvent::MTE2_V>(eventID);
        AscendC::WaitFlag<AscendC::HardEvent::MTE2_V>(eventID);
        AscendC::WaitFlag<AscendC::HardEvent::MTE3_V>(eventID);

        // === 数据计算 ===
        GeluCompute(xLocal, yLocal, copyRows * singleCoreN);
        AscendC::SetFlag<AscendC::HardEvent::V_MTE2>(eventID);

        // === 数据搬出 ===
        AscendC::SetFlag<AscendC::HardEvent::V_MTE3>(eventID);
        AscendC::WaitFlag<AscendC::HardEvent::V_MTE3>(eventID);
        copyParams.srcStride = 0;
        copyParams.dstStride = srcStride;
        AscendC::DataCopyPad<float>(yGm[loopIdx * tileRow * totalN], yLocal, copyParams);
        AscendC::SetFlag<AscendC::HardEvent::MTE3_V>(eventID);
    }

    AscendC::WaitFlag<AscendC::HardEvent::V_MTE2>(EVENT_ID0);
    AscendC::WaitFlag<AscendC::HardEvent::V_MTE2>(EVENT_ID1);
    AscendC::WaitFlag<AscendC::HardEvent::MTE3_V>(EVENT_ID0);
    AscendC::WaitFlag<AscendC::HardEvent::MTE3_V>(EVENT_ID1);
}
```
