# 入门功能落地

本节使用基础API进行Matmul+LeakyRelu融合算子的编程指导，介绍基于Ascend C编程模型和Cube-Vector协同计算单元实现融合算子的基本方法，Cube核完成Matmul矩阵乘法、Vector核完成LeakyRelu激活计算，通过核间同步协调两者执行顺序。

## 详细内容

详细内容请参考 [Matmul和LeakyRelu融合计算样例](../../../../../examples/01_simd_cpp_api/00_introduction/03_fusion_operation/matmul_leakyrelu_basic_api/README.md)，该样例涵盖：

- 算子实现：Cube核Matmul计算（DataCopy + LoadData + Mmad + Fixpipe）、Vector核LeakyRelu计算（DataCopyPad + LeakyRelu）、核间同步（CrossCoreSetFlag/CrossCoreWaitFlag）
- 功能调试：printf格式化输出、DumpTensor张量数据打印
- 编译运行：cmake编译与执行
- 性能调试：msProf工具上板性能采集

### 可优化方向分析

上述实现正确完成了Matmul+LeakyRelu融合功能，但在性能层面存在以下几类可优化的空间。

| 可优化方向 | 当前实现的问题 | 预期优化收益 |
|-----------|---------------|-------------|
| **L1/L0单缓冲区** | A、B矩阵在L1和L0中各只有一份缓冲区，下一轮数据必须等上一轮消费完才能搬入 | 改为Ping-Pong双缓冲，让数据搬运和计算重叠执行 |
| **MTE2搬运粒度小** | 每次[DataCopy](../../../../../api/SIMD-API/基础API/Memory数据搬运/DataCopy/DataCopy.md)搬入一个baseM×baseK小块，[MTE2](../../../../编程指南/高级编程/硬件实现/基本架构.md)指令发射密集 | 增大搬运粒度，减少MTE2指令次数，提高带宽利用率 |
| **流水线串行执行** | 当前实现中使用[PipeBarrier](../../../../../api/SIMD-API/基础API/同步控制/核内同步/PipeBarrier(ISASI).md)进行流水线同步，但未采用双缓冲机制，MTE2、MTE1、M、FIX各硬件单元无法充分流水并行 | 通过双缓冲和硬件事件同步，使四个单元流水并行，显著提升吞吐 |
| **MTE1指令队列压力** | [LoadData2D](../../../../../api/SIMD-API/基础API/矩阵计算（ISASI）/数据搬运/LoadData/LoadData.md)需for循环多次发射，MTE1指令队列深度有限 | 使用[LoadData3D](../../../../../api/SIMD-API/基础API/矩阵计算（ISASI）/数据搬运/LoadData/Load3D.md)替代，单条指令完成搬运 |
| **多核切分固定** | 硬编码核数分配，仅适用于固定矩阵规模和核数场景 | 通用切分策略，支撑任意核数和矩阵规模的自动分配 |
| **Tiling参数运行时计算** | 核内使用Scalar逐级计算各维度参数，引入额外指令开销 | 常量Tiling，编译期确定参数 |
| **Fixpipe与Cube串行** | L0C写回必须等[Mmad](../../../../../api/SIMD-API/基础API/矩阵计算（ISASI）/矩阵计算/Mmad.md)全部完成后才开始，写回期间Cube空闲 | UnitFlag细粒度Fixpipe发射，令写回与计算流水重叠 |
| **CV融合-GM中转开销** | [Fixpipe](../../../../../api/SIMD-API/基础API/矩阵计算（ISASI）/数据搬运/Fixpipe.md)将L0C结果写入[GM](../../../../编程指南/高级编程/硬件实现/基本架构.md)，AIV再从GM读回[UB](../../../../编程指南/高级编程/硬件实现/基本架构.md)，增加MTE2搬运开销 | UB直通，Fixpipe直接写入UB，省去GM中转（仅Ascend 950PR支持） |
| **B矩阵搬运顺序** | A、B数据依次等量搬运，较大矩阵场景下B数据到位晚可能成为流水线瓶颈 | 优先搬运B矩阵，缓解数据紧张 |
| **L2Cache未充分利用** | B矩阵每次均从GM读取，多核反复访问GM导致MTE2带宽压力大 | 沿M方向切分A矩阵，使B矩阵跨轮驻留L2Cache，减少GM访问次数 |

> 以上各优化方向的详细实现方案，请参见[中级性能优化](./中级性能优化.md)。
