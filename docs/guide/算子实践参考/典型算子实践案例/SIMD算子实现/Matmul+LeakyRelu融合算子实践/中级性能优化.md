# 中级性能优化

本节基于[Tensor的C++编程](../../../../编程指南/编程模型/AI-Core-SIMD编程/基于Tensor的C++编程/基于Tensor的C++编程.md)范式，介绍Matmul+LeakyRelu融合算子的性能调优方法。为更好展示VF融合的性能优化手段，本章节以Matmul+Gelu融合算子作为讲解样例。GELU相比LeakyRelu计算逻辑更复杂，能更充分地体现各类优化手段的效果。

## 优化路径：

| 编号 | 优化手段 | 等级 | 定位 |
|------|---------|------|------|
| **1** | **CV融合-GM中转** | **中级** | **融合架构** |
| **2** | **CV融合-UB直通** | **中级** | **融合架构** |
| **3** | **L1/L0双缓冲Ping-Pong** | **中级** | **流水线骨架** |
| **4** | **大包搬运** | **中级** | **带宽压榨** |
| **5** | **细粒度流水同步** | **中级** | **MMAD-FIXPIPE流水重叠** |
| **6** | **RegBase计算** | **中级** | **向量计算优化** |
| 7 | DataCopyIn优先搬运B矩阵 | 高级 | 调度策略 |
| 8 | L2Cache优化 | 高级 | MTE2带宽压榨 |

## 从入门到优化

[入门功能落地](./入门功能落地.md)实现了Matmul+LeakyRelu融合算子的基本功能：[Cube](../../../../编程指南/编程模型/AI-Core-SIMD编程/抽象硬件架构.md)核完成Matmul计算（[DataCopy](../../../../../api/SIMD-API/基础API/Memory数据搬运/DataCopy/DataCopy.md) GM→L1 + [LoadData](../../../../../api/SIMD-API/基础API/矩阵计算（ISASI）/数据搬运/LoadData/LoadData.md) L1→L0A/L0B + [Mmad](../../../../../api/SIMD-API/基础API/矩阵计算（ISASI）/矩阵计算/Mmad.md) L0A/L0B→L0C + [Fixpipe](../../../../../api/SIMD-API/基础API/矩阵计算（ISASI）/数据搬运/Fixpipe.md) L0C→GM），[Vector](../../../../编程指南/编程模型/AI-Core-SIMD编程/抽象硬件架构.md)核通过[CrossCoreSetFlag](../../../../../api/SIMD-API/基础API/同步控制/核间同步/CrossCoreSetFlag(ISASI).md)/[CrossCoreWaitFlag](../../../../../api/SIMD-API/基础API/同步控制/核间同步/CrossCoreWaitFlag(ISASI).md)等待Cube核完成后执行[LeakyRelu](../../../../../api/SIMD-API/基础API/Memory矢量计算/基础算术/LeakyRelu.md)计算。

入门实现存在以下**性能瓶颈**——这也是中级优化的起点：

| 瓶颈 | 入门实现的问题 | 对应的中级优化 |
|------|---------------|---------------|
| **L1/L0单缓冲区** | A、B矩阵在L1和L0中各只有一份缓冲区，下一轮数据必须等上一轮消费完才能搬入 | 改为Ping-Pong双缓冲，让数据搬运和计算重叠执行 |
| **MTE2搬运粒度小** | 每次DataCopyIn搬入一个baseM×baseK小块，MTE2指令发射密集 | 大包搬运→一次搬入stepKa个block |
| **流水线串行执行** | 当前使用PipeBarrier进行同步，MTE2、MTE1、M、FIX各硬件单元无法充分流水并行 | 通过双缓冲和硬件事件同步，使四个单元流水并行 |
| **Fixpipe与Cube串行** | [Fixpipe](../../../../../api/SIMD-API/基础API/矩阵计算（ISASI）/数据搬运/Fixpipe.md)必须等[Mmad](../../../../../api/SIMD-API/基础API/矩阵计算（ISASI）/矩阵计算/Mmad.md)全部完成，写回期间Cube空闲 | UnitFlag→512B粒度MMAD-FIXPIPE重叠 |
| **CV融合-GM中转开销** | Fixpipe将L0C结果写入[GM](../../../../编程指南/高级编程/硬件实现/基本架构.md)，AIV再从GM读回[UB](../../../../编程指南/高级编程/硬件实现/基本架构.md) | UB直通，Fixpipe直接写入UB（仅Ascend 950PR） |
| **MTE1指令队列压力** | LoadData2D需for循环多次发射，MTE1指令队列深度有限 | LoadData3D替代，单条指令完成搬运 |
| **多核切分固定** | 硬编码核数分配，仅适用于固定矩阵规模和核数场景 | 通用切分策略，支撑任意核数和矩阵规模 |
| **Tiling参数运行时计算** | 核内用Scalar计算各维度参数，增加流水线停顿 | 常量Tiling→编译期确定 |
| **向量计算链较长** | GELU等复杂激活函数涉及多次UB读写，增加访存开销 | RegBase计算→中间结果在寄存器完成，减少UB交互 |
