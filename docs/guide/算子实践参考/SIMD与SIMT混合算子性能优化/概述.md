# SIMD与SIMT混合算子性能优化概述

为提升向量计算在复杂控制流、离散访存等场景下的编程灵活性，Ascend 950PR/Ascend 950DT采用SIMD与SIMT深度融合的新同构架构：矩阵计算单元延续SIMD设计，向量计算单元则在SIMD基础上引入SIMT能力。这一设计确立了以SIMD为主、SIMT为辅的新同构编程模型。

在该模型下，SIMD承担连续、密集计算的主要性能路径，为矩阵计算和向量计算提供高性能与高算力利用率；向量计算单元引入的SIMT能力则作为灵活性补充，专门应对复杂控制流、离散访存等不规则场景，提升此类场景下算法开发与优化的效率。因此，在SIMD与SIMT混合编程中，SIMT不用于替代SIMD处理连续、密集的计算任务，而是用于处理算子中的局部不规则逻辑。典型方式是在核函数中通过SIMT VF处理分支判断、索引映射、离散访存等局部片段，再由SIMD继续处理向量或矩阵计算，从而兼顾灵活性和高吞吐。

本节主要介绍SIMD与SIMT混合编程中SIMT VF的性能优化方法，帮助开发者基于性能数据判断SIMT VF片段的优化程度，并进一步选择合适的优化方向。优化时应先明确SIMT VF的计算和访存特征，再通过性能数据确认瓶颈，最后针对性地从内存访问、指令执行、执行配置等方面进行优化。

## 分析性能数据

性能分析的核心，是先建立理论基准，再用实测数据观察当前实现与理论预期之间的差距。

1. 理论性能评估

   理论性能评估用于建立算子的理想访存规模和设备GM（Global Memory）带宽上限。分析时应先根据算子语义、数据量和数据类型，估算算子完成一次计算所需的理论读数据量和理论写数据量，计算方式通常为访问元素个数乘以数据类型字节数。该数据量表示算法本身必须处理的数据规模，是后续判断实际读写是否合理的基准。在得到理论读写数据量后，还需要结合产品文档中的硬件规格获取设备GM理论带宽。理论带宽代表访存通路的理想上限，它可以帮助开发者判断当前实现距离设备能力还有多大差距。

2. 实际数据度量

   实际数据度量用于观察算子运行时的GM访问情况，以及SIMT VF在AI Vector Core（AIV）执行时间中的占比。可使用[msprof op](https://www.hiascend.com/document/redirect/CannCommercialToolOpDev)采集性能数据：通过`Memory.csv`查看AIV整体GM读写带宽和读写数据量，例如`aiv_main_mem_read_bw`、`aiv_main_mem_write_bw`、`read_main_memory_datas`、`write_main_memory_datas`；通过`ArithmeticUtilization.csv`查看SIMT VF类型指令的cycle占比，例如`aiv_vec_simt_vf_ratio`。

   在SIMD与SIMT混合编程中，`aiv_time`覆盖整个AIV执行区间。分析SIMT VF自身性能时，应使用`aiv_vec_simt_vf_ratio`折算SIMT VF时间：

   ```text
   SIMT VF时间 = aiv_time * aiv_vec_simt_vf_ratio
   ```

   其中，`aiv_vec_simt_vf_ratio`表示SIMT VF类型指令cycle数占AIV total cycle的比例；`aiv_vec_ratio`表示全部Vec类型指令cycle数占比，不能替代`aiv_vec_simt_vf_ratio`作为SIMT VF占比。

   `read_main_memory_datas`和`write_main_memory_datas`是AIV整体GM读写数据量，不一定全部来自SIMT VF。只有能够从代码结构确认GM访问主要发生在SIMT VF中，或能够划分出SIMT VF相关GM读写数据量时，才建议估算SIMT VF实际带宽：

   ```text
   SIMT VF实际带宽 = SIMT VF相关GM读写数据量 / SIMT VF时间
   ```

   如果同一个Kernel中还存在明显的SIMD VF、MTE搬运或其他阶段GM读写，无法判断GM读写量是否属于SIMT VF，则不要将AIV整体GM读写量直接除以SIMT VF时间。此时应将`read_main_memory_datas`、`write_main_memory_datas`以及`aiv_main_mem_read_bw`、`aiv_main_mem_write_bw`作为AIV整体GM通路压力参考，再结合代码结构、`aiv_vec_simt_vf_ratio`、`aiv_vec_ratio`和MTE占比判断瓶颈来源。若SIMT VF读GM经过Data Cache并命中，实测GM读数据量可能小于理论读数据量，这通常表示部分读访问被缓存复用。

## 选择优化方法

完成理论性能评估和实际数据度量后，应优先分析GM读写带宽和实际读写数据量，再决定优化方向。对于SIMD与SIMT混合算子，优化通常可从内存访问、执行控制和指令三个方面展开。

- 内存访问优化

  内存访问优化是最高优先级的优化方向。混合编程中的SIMT VF常用于处理离散访存、索引映射等不规则逻辑，内存访问优化的作用，是在SIMT VF中减少无效GM访问，提升访存合并效果，提高有效带宽和数据复用率。

  SIMT访问GM的粒度为128B，在随机访问GM中的数据时，访存效率较低，优化时应优先让同一个Warp内相邻线程在同一条访存指令上访问连续GM地址，提高带宽的有效利用率。当所需访问的数据量远小于最大可用Unified Buffer空间时，可以考虑先使用SIMD搬运接口将数据从GM搬运到UB，再让SIMT从UB读取，降低离散GM访问开销。分析过程中还应关注Data Cache命中带来的读数据量变化，以及UB访问是否引入新的冲突。

- 执行控制优化

  执行控制优化的目标，是让线程、线程块、核数和SIMT VF任务量与真实工作量匹配。开发者应根据输入输出规模和线程映射关系，合理设置`asc_vf_call`的线程数、`__launch_bounds__`、核数和数据切分方式，使线程覆盖真实输出规模，并尽量保证核间负载均衡。

  在SIMD与SIMT混合算子中，还需要合理配置SIMD VF和SIMT VF的任务切分。SIMT VF适合承载分支判断、索引映射、离散访存等不规则逻辑，连续搬运和规整向量计算仍应优先使用SIMD VF处理。如果不规则逻辑被拆分成过多SIMT VF调用，或SIMD VF与SIMT VF之间频繁切换，会引入不必要的调度开销，影响整体执行效率。

- 指令优化

  指令优化通常在计算瓶颈，或内存访问已经较充分但性能仍未达到预期时重点考虑。它的作用是减少SIMT VF内部的高开销指令、分支发散和冗余计算，提升线程级计算逻辑的执行效率。

  对复杂分支、离散索引等逻辑，可使用SIMT表达线程级控制流，但SIMT内部仍需控制分支发散，通过优化计算逻辑减少除法、取模等高开销指令的使用，并避免在线程内重复执行可提前计算或可复用的逻辑。
