# SIMD与SIMT混合算子性能优化概述

为提升向量计算在复杂控制流、离散访存等场景下的编程灵活性，Ascend 950PR/Ascend 950DT采用SIMD与SIMT深度融合的新同构架构：矩阵计算单元延续SIMD设计，向量计算单元则在SIMD基础上引入SIMT能力。这一设计确立了以SIMD为主、SIMT为辅的新同构编程模型。

在该模型下，矩阵计算和向量计算中的SIMD配置超过了90%的算力，为密集计算提供高性能与高算力利用率；向量计算中的SIMT则作为灵活性补充，专门应对复杂控制流、离散访存等不规则场景，提升此类场景下算法开发与优化的效率。

因此，在SIMD与SIMT混合编程中，SIMT不用于替代SIMD处理规整密集计算，而是将不规则逻辑局部化、规整化。典型方式是在SIMD Kernel中通过SIMT VF处理分支判断、索引映射、离散访存等局部片段，再由SIMD继续处理规整的向量或矩阵计算，从而兼顾灵活性和高吞吐。

SIMD与SIMT混合算子性能优化的目标，是帮助开发者基于性能数据判断当前算子的优化程度，并进一步选择合适的优化方向。优化时应先明确算子的计算和访存特征，再通过性能数据确认瓶颈，最后针对性地从内存访问、指令执行、执行配置等方面进行优化。

## 如何看性能

性能分析的核心，是通过统一的度量口径判断当前实现是否接近硬件能力，并进一步定位下一步应优化哪一类瓶颈。吞吐和带宽不是孤立的计算结果，而是判断算子优化程度的依据。建议按照以下流程分析SIMD与SIMT混合算子的性能。

1. 明确算子工作量。

   先根据算子语义、输入输出shape和数据类型，估算每个线程块（Thread Block）需要完成的有效读数据量、有效写数据量和核心计算量。该数据量表示算法本身必须处理的数据规模，是后续判断有效带宽和优化程度的基准。

2. 了解理论带宽。

   带宽即数据传输速率，是影响访存密集型算子性能的重要因素。理论带宽可根据产品文档中的硬件规格获得，用于作为性能上限参考。当有效带宽远低于理论带宽时，通常说明访存模式、数据切分或实现细节限制了带宽利用率，后续优化应优先分析这些因素。

3. 计算有效带宽。

   有效带宽用于衡量算子完成业务必要读写的效率。计算时使用第1步中按算子语义估算的有效读写数据量，以及`msprof op`采集到的AIV执行耗时：

   ```text
   有效带宽 = (有效读数据量 + 有效写数据量) / aiv_time
   ```

   其中，`aiv_time`可从`Memory.csv`等性能数据中获取。有效读写数据量应来自算子语义和shape，而不是直接使用硬件实际访问事务数。有效带宽越接近对应通路的可达带宽，说明当前实现对硬件资源的利用越充分；如果有效带宽明显偏低，需要继续结合实测通路数据判断瓶颈来源。

4. 对比实测通路数据。

   使用`msprof op`采集性能数据后，可查看`Memory.csv`中的`aiv_main_mem_read_bw`、`aiv_main_mem_write_bw`、`read_main_memory_datas`、`write_main_memory_datas`等字段，分析GM读写带宽和实际读写数据量。这些字段反映的是硬件通路上的实际访问情况，可用于判断GM通路是否已经成为瓶颈。

   若有效带宽低且GM实测带宽也低，通常需要优先检查Warp内访存是否连续、线程映射是否合理、分支发散是否严重、SIMT VF是否引入过多额外指令。若有效带宽低但GM实测带宽较高，则说明算子可能已经受GM通路限制，下一步应优先减少读写量、提升数据复用，或将离散GM访问转换为UB更友好的访问路径。

   需要注意，SIMT读取GM时会经过Data Cache。若访问存在缓存命中，`msprof op`统计到的GM读数据量可能小于按算子语义估算的理论读数据量，这通常表示部分数据被缓存复用，不应直接判断为统计错误。若`read_main_memory_datas`明显大于按语义估算的有效读数据量，则需要进一步检查是否存在访存不合并、重复访问或非预期的数据加载。

## 如何优化性能

完成性能判断后，可从如下方面考虑性能优化手段：

- 内存访问优化

  优先让同一个Warp内相邻线程在同一条访存指令上访问连续GM地址，提高访存合并效果。对于离散输入、索引访问或数据规模较小且可复用的场景，可以考虑先使用SIMD搬运接口将数据从GM搬运到UB，再让SIMT从UB读取，降低离散GM访问开销。分析时应关注有效吞吐、GM实际读写带宽、Data Cache命中带来的读数据量变化，以及UB访问是否引入新的冲突。

- 指令优化

  对复杂分支、离散索引等逻辑，可使用SIMT表达线程级控制流，避免在SIMD中使用大量mask、select或多段计算拼接复杂分支。但SIMT内部仍需控制分支发散，减少除法、取模等高开销指令，并避免在线程内重复执行可提前计算或可复用的逻辑。

- 执行配置优化

  根据输出规模和线程映射关系，合理设置`asc_vf_call`的线程数、`__launch_bounds__`、核数和数据切分方式，使线程覆盖真实输出规模，并尽量保证核间负载均衡。线程数不足会导致并行度不够，线程数过多则可能增加调度、寄存器、Data Cache或同步相关开销。

- 头尾开销优化

  对于耗时较短或SIMT VF粒度较细的算子，头尾开销和VF调度开销可能在总耗时中占比较高。此时应结合Task Duration、核数配置和SIMT VF数量，评估是否可以调整Kernel类型、合并过细的SIMT片段，或减少不必要的VF切换。
