# 短向量应用

【优先级】高

【描述】SIMT编程模式下，外围访存的Cacheline为128字节。当处理小数据类型（如half类型）时，单个Warp同时发射写指令的总宽度仅为64字节，不满足128字节Cacheline的完整写回要求。此时硬件会启动低效的RMW（Read-Modify-Write）机制，导致写入阻塞和性能下降。通过使用向量化类型（如half2类型，4字节）进行计算，可以使单次Warp写访问覆盖整个Cacheline，避免RMW操作，从而显著提升写Cache命中率和整体访存效率。


- half类型计算

  【样例介绍】以向量加法算子为例，输入数据为half类型，计算公式为 `z_i = x_i + y_i`。数据规模为64×256×1024个元素，使用64个线程块、每块1024个线程，总线程数65536，每个线程处理32个元素。

  【反例】使用half类型逐元素计算，导致写Cache命中率低。
   
   **图 1** half类型计算触发RMW示意图

   ![img](../../../figures/短向量RMW.png "短向量RMW示意图")

  ```cpp
  template<typename T>
  __global__ void add(T* x, T* y, T* z, uint64_t size)
  {
      int32_t stride = gridDim.x * blockDim.x;
      for (int32_t idx = blockIdx.x * blockDim.x + threadIdx.x; idx < size; idx += stride) {
          z[idx] = x[idx] + y[idx];
      }
  }
  ```

  上述实现中，单个Warp（32线程）同时发射指令时，在空间上连续拼出的总宽度仅为 `32 * 2B = 64B`，仅占Cacheline（128字节）的半行。L2 Cache为了保护相邻的64B不被改写，硬件被迫启动RMW机制：

    1. **Read（读）**：从存储中将整行128B的旧数据读进L2 Cache
    2. **Modify（修改）**：在缓存内部，把64B新数据缝合进去
    3. **Write（写）**：把一整行128B写回

  这种机制导致写操作被阻塞超过50%，触发额外的内存回读，被判定位写未命中。

  在Ascend 950芯片上，该实现的性能数据如下：

  | Task Duration(μs) | aiv_time(μs) | aiv_total_cycles | aiv_vec_time(μs) | aiv_vec_ratio | aiv_scalar_time(μs) | aiv_scalar_ratio | aiv_read_hit_rate | aiv_write_hit_rate | aiv_main_mem_read_bw(GB/s) | aiv_main_mem_write_bw(GB/s) |

  从性能数据可以看出，写Cache命中率仅为49.3%，读带宽为7.77 GB/s，写带宽为6.24 GB/s。这说明RMW操作严重影响了写入效率。

  【正例】使用half2类型向量化计算，提升写入效率和带宽利用率。

  **图 2** half2类型计算示意图

  ![img](../../../figures/短向量.png "短向量示意图")
  ```cpp
  template<typename T, typename U>
  __global__ void add2(T* x, T* y, T* z, uint64_t size)
  {
      // 转为向量类型
      const U* x2 = reinterpret_cast<const U*>(x);
      const U* y2 = reinterpret_cast<const U*>(y);
      U* z2 = reinterpret_cast<U*>(z);

      uint64_t vectorSize = size / 2;
      int32_t stride = gridDim.x * blockDim.x;

      // 向量化循环处理偶数对
      for (int32_t idx = blockIdx.x * blockDim.x + threadIdx.x; idx < vectorSize; idx += stride) {
          z2[idx] = x2[idx] + y2[idx];
      }
      // 最后一个奇数元素处理
      if (blockIdx.x == 0 && threadIdx.x == 0 && (size % 2 != 0)) {
          uint64_t lastIdx = size - 1;
          z[lastIdx] = x[lastIdx] + y[lastIdx];
      }
  }
  ```

  上述实现将half类型提升为half2类型（4字节进行计算），单个Warp（32线程）单次发射写入的总宽度达到 `32 * 4B = 128B`，恰好覆盖一整行物理Cacheline的边界。这避免了Read-Modify的代价，写Cache命中率因此显著提升。

  在Ascend 950芯片上，使用half2类型后的性能数据如下：

  | Task Duration(μs) | aiv_time(μs) | aiv_total_cycles | aiv_vec_time(μs) | aiv_vec_ratio | aiv_scalar_time(μs) | aiv_scalar_ratio | aiv_read_hit_rate | aiv_write_hit_rate | aiv_main_mem_read_bw(GB/s) | aiv_main_mem_write_bw(GB/s) |

  **优化效果分析**：

    - **端到端耗时**：从86.478 μs降至45.371 μs，减少47.5%，整体性能提升1.91倍
    - **CPU总周期数**：从8,832,432减至4,584,309，降幅达48.1%，证明指令发射密度得到精简
    - **写Cache命中率**：从49.3%提升到89.1%，有效避免写阻塞
    - **主存读写带宽**：读带宽从7.77 GB/s提升至14.51 GB/s（提升86.7%），写带宽从6.24 GB/s提升至7.25 GB/s（提升16.2%）

  **适用场景扩展**

  短向量类型不局限于half2，还可扩展bfloat16x2_t类型进行[基本运算](../../../../docs/guide/编程指南/语言扩展层/SIMT-BuiltIn关键字.md#运算符)

【总结】SIMT算子中，当处理小数据类型（如half类型）的访存密集型计算时，应优先考虑使用向量化类型（如half2类型）。通过向量化，可以使单个Warp的写访问宽度匹配硬件Cacheline粒度（128字节），避免低效的RMW机制，从而显著提升写Cache命中率和整体访存效率。
