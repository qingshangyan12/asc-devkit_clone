# 访存合并

【优先级】高

【描述】SIMT编程模式下，一个warp内的相邻线程通常同时发起GM访问请求，如果这些请求访问地址连续，这些请求会被合并从而提高带宽使用率。对于转置、重排、gather/scatter等算子，如果直接按照数学公式写回GM，很容易出现连续线程访问跨行地址的情况，导致访存无法合并，成为主要性能瓶颈。

## 优化数据切分方法

【样例介绍】以Gather算子为例，输入shape为 `20001 x 1023`，index长度为 `12288`，输出shape为 `12288 x 1023`。Gather按行从输入中取数，计算公式可以表示为 `output[row, col] = input[index[row], col]`。输出矩阵每一行内部的列方向数据在GM上连续，优化切分时应让同一个warp内相邻线程尽量访问同一行内的相邻列，而不是只保证单个线程内部连续。

【反例】按thread切分数据，每个thread处理连续的一行数据

```
template <typename type_data, typename type_idx>
__global__ __launch_bounds__(MAX_THREAD_COUNT) void gather_custom(
    type_data* input,
    type_idx* index,
    type_data* gather_output,
    uint32_t in_width,
    uint32_t index_total_length)
{
    int32_t out_row = blockIdx.x * blockDim.x + threadIdx.x;

    if (out_row >= index_total_length) {
        return;
    }

    uint32_t in_row = index[out_row];
    int input_idx = in_row * in_width;
    int output_idx = out_row * in_width;
    for (int32_t col = 0; col < in_width; col++) {
        gather_output[output_idx] = input[input_idx];
        input_idx += 1;
        output_idx += 1;
    }
}
```

上述实现把输出行分配给不同thread，每个thread在 `for` 循环内连续处理一整行数据。从单个thread视角看，`input_idx`和 `output_idx` 都是连续递增的；但SIMT访存合并关注的是同一个warp内相邻thread在同一条访存指令上访问的地址是否连续。

在该实现中，同一个warp内的相邻thread分别处理不同的 `out_row`，虽然单个thread内部访问连续，但warp内访问不连续，GM访存难以合并。其性能数据如下：

【正例】按block切分输出数据，warp内相邻thread访问连续地址

```
template <typename type_data, typename type_idx>
__global__ __launch_bounds__(MAX_THREAD_COUNT) void gather_custom(
    type_data* input,
    type_idx* index,
    type_data* gather_output,
    uint32_t in_width,
    uint32_t output_total_size)
{
    uint32_t start = blockIdx.x * blockDim.x + threadIdx.x;
    uint32_t stride = blockDim.x * gridDim.x;

    for (uint32_t idx = start; idx < output_total_size; idx += stride) {
        uint32_t out_row = idx / in_width;
        uint32_t out_col = idx - out_row * in_width;
        uint32_t in_row = index[out_row];
        uint32_t input_i = in_row * in_width + out_col;
        gather_output[idx] = input[input_i];
    }
}
```

上述实现将输出矩阵按一维线性地址组织，并让每个block覆盖一段连续的输出元素。对于同一次循环迭代，block内thread的 `idx` 连续递增，同一个warp内相邻thread会访问连续的 `gather_output[idx]`。当这些 `idx` 位于同一个输出行内时，`out_col` 也连续递增，且 `in_row = index[out_row]` 相同，因此输入访问 `input[in_row * in_width + out_col]` 也是连续的，能够形成更好的GM访存合并。

该写法中，每个thread并不是独占一段连续数据，而是以 `blockDim.x * gridDim.x` 为步长处理多个元素。也就是说，单个thread多次迭代访问的数据是跳跃的；但在每一次迭代中，warp内相邻thread访问的是连续地址。SIMT访存合并优先收益来自warp维度的连续访问，因此这种切分方式通常比“每个thread处理一整段连续数据”更适合发挥GM带宽。

配套的block切分也从按 `index_total_length` 切分调整为按 `output_total_size` 切分，使线程数量覆盖真实输出元素规模：

```

bool block_split(uint32_t output_total_size, uint32_t &numBlocks, uint32_t &thread_num_per_block)
{
    uint32_t real_core_num = 0;
    const auto& platformInfoMgr = platform_ascendc::PlatformAscendCManager::GetInstance();
    if (platformInfoMgr == nullptr) {
        std::cout << "[ERROR] Get platform info failed, please check device status." << std::endl;
        return false;
    }
    real_core_num = platformInfoMgr->GetCoreNumAiv();
    thread_num_per_block = std::min(output_total_size, MAX_THREAD_COUNT);
    numBlocks = (output_total_size + thread_num_per_block - 1) / thread_num_per_block;
    if (numBlocks > real_core_num) {
        numBlocks = real_core_num;
        thread_num_per_block = MAX_THREAD_COUNT;
    }
    return true;
}
```

## 引入UB中转

【样例介绍】以矩阵转置为例，输入矩阵shape为 `1024 x 1024`，数据类型为 `float`。将矩阵切分为 `32 x 32`的tile，grid配置为 `(matrix_width / 32, matrix_height / 32, 1)`，block配置为 `(32, 32, 1)`，每个线程处理tile中的1个元素。该切分方式下，`threadIdx.x`方向的32个线程对应tile内同一行的32个连续元素，适合形成连续GM读访问。

【反例】直接按照转置公式写回GM

```
constexpr int TILE_DIM = 32;

__global__ void transpose_naive_kernel(float *output, const float *input, int width, int height)
{
    int x_index = blockIdx.x * TILE_DIM + threadIdx.x;
    int y_index = blockIdx.y * TILE_DIM + threadIdx.y;

    int index_in = x_index + width * y_index;
    int index_out = y_index + height * x_index;

    output[index_out] = input[index_in];
}
```

上述实现中，同一个warp内的线程从输入矩阵的一行读取数据，`index_in`连续，因此GM读访问可以合并。但写回时，`threadIdx.x`相邻的线程对应不同的 `x_index`，`index_out = y_index + height * x_index`会让相邻线程写到输出矩阵的不同行，地址间隔为 `height`个元素。此时GM写访问不连续，难以形成高效合并访存。

在 `1024 x 1024`矩阵转置样例中，直接索引转置版本的性能数据如下：

| Task Duration(us) | aiv_time(us) | aiv_total_cycles | aiv_vec_time(us) | aiv_vec_ratio | aiv_scalar_time(us) | aiv_scalar_ratio |
| :---------------: | :----------: | :--------------: | :--------------: | :-----------: | :-----------------: | :--------------: |
|      60.477      |    3.516    |     5801.925     |      3.357      |     0.955     |        0.147        |      0.041      |

【正例】使用UB中转，将非连续GM写转换为UB内转置读

```
constexpr int TILE_DIM = 32;

__global__ void transpose_coalesced_kernel(float *output, const float *input, int width, int height)
{
    __ubuf__ float tile[TILE_DIM][TILE_DIM];

    int x_index = blockIdx.x * TILE_DIM + threadIdx.x;
    int y_index = blockIdx.y * TILE_DIM + threadIdx.y;
    int index_in = x_index + y_index * width;

    tile[threadIdx.y][threadIdx.x] = input[index_in];
    asc_syncthreads();

    x_index = blockIdx.y * TILE_DIM + threadIdx.x;
    y_index = blockIdx.x * TILE_DIM + threadIdx.y;
    int index_out = x_index + y_index * height;

    output[index_out] = tile[threadIdx.x][threadIdx.y];
}
```

上述实现先让每个线程按原始布局从GM读取数据，并写入UB中的 `tile[threadIdx.y][threadIdx.x]`。同步后，交换block坐标定位到转置后的输出tile，再从UB中读取 `tile[threadIdx.x][threadIdx.y]`写回GM。这样处理后，同一个warp在GM侧读取输入的一行，也写回输出的一行，GM读写都保持连续；转置造成的非连续访问被转移到UB内部完成。

在 `1024 x 1024`矩阵转置样例中，使用UB中转后的性能数据如下：

| Task Duration(us) | aiv_time(us) | aiv_total_cycles | aiv_vec_time(us) | aiv_vec_ratio | aiv_scalar_time(us) | aiv_scalar_ratio |
| :---------------: | :----------: | :--------------: | :--------------: | :-----------: | :-----------------: | :--------------: |
|      35.945      |    1.814    |     2993.315     |      1.646      |     0.910     |        0.156        |      0.083      |

与直接索引转置相比，Task Duration从 `60.477us`降低到 `35.945us`，耗时下降约 `40.6%`。aiv_time从 `3.516us`降低到 `1.814us`，说明GM访存合并对SIMT转置类算子有明显优化收益。

【总结】SIMT算子进行访存优化时，应优先检查同一个warp内相邻thread在同一条访存指令下访问的GM地址是否连续。常用优化方法包括：一是调整数据切分方式，将连续的数据区域分配给block和warp，使每次迭代中warp内相邻thread访问连续地址，单个thread可通过stride处理后续数据以覆盖完整输出；二是引入UB等片上存储进行数据中转和布局重排，将原本不连续的GM访问转换为片上存储内的重排访问，从而尽量保证GM读写都沿连续方向进行。
