# 通过类型对齐提升搬运效率

【优先级】中

【描述】SIMT编程模式下，编译器为结构体类型访存生成指令时，单次访存宽度 = min(64-bit, alignof允许的最大宽度)。若结构体`alignof`较小（如1或4），编译器只能使用窄宽度访存指令（8-bit或32-bit），搬运一个元素需多条指令，效率降低。通过`alignas`将结构体对齐属性提升到与元素大小或硬件访存宽度（64-bit）匹配，可减少访存指令条数，提升搬运效率。

本样例以不同大小的结构体逐元素搬运为例，对比非对齐与使用`alignas`对齐后的访存指令条数和耗时差异。所有用例使用同一搬运核函数，总搬运量均为512 MiB，性能差异仅由`alignof`影响编译器生成的访存指令宽度决定。

【反例】结构体未设置显式对齐，默认`alignof`导致窄宽度访存指令。

```
struct Misalign4 {
    unsigned char r, g, b, a;
}; // sizeof=4,  alignof=1 → 4 × 8-bit
```

上述结构体因字段类型使`alignof`偏小，单次访存宽度受限，每元素指令条数多于对齐版本。

搬运核函数如下：

```
constexpr uint32_t THREAD_COUNT = 2048;
constexpr size_t MEM_BYTES = 512ULL * 1024ULL * 1024ULL;

template <class TData>
__global__ __launch_bounds__(THREAD_COUNT) void aligned_copy_kernel(
    TData* d_odata, TData* d_idata, uint32_t num_elements)
{
    const uint32_t tid = blockIdx.x * blockDim.x + threadIdx.x;
    const uint32_t num_threads = blockDim.x * gridDim.x;
    for (uint32_t pos = tid; pos < num_elements; pos += num_threads) {
        d_odata[pos] = d_idata[pos];
    }
}
```

核函数对所有结构体类型执行逐元素赋值，逻辑不随类型变化。

【正例】使用`alignas`提升对齐属性，编译器生成更宽访存指令。

```
struct alignas(4) Align4 {
    unsigned char r, g, b, a;
}; // sizeof=4,  alignof=4 → 1 × 32-bit
```

Align4每元素1条指令（vs 反例中Misalign4的4条），访存指令条数减少了四倍。

对齐与非对齐性能对比（总搬运量512 MiB）：

| 对照组 | Task Duration(对齐) | Task Duration(非对齐) | 非对齐/对齐 | 说明 |
| :---: | :-----------------: | :-------------------: | :---------: | :--- |
| 4 B | 27889.33 us | 81223.02 us | 2.91x | alignof=1退化为8-bit访存，差距最大 |
| 8 B | 17417.23 us | 17415.04 us | 1.00x | 编译器合并为64-bit指令，无差异 |
| 16 B | 32983.77 us | 38353.60 us | 1.16x | 32-bit×4条/元素 vs 64-bit×2条/元素 |
| 32 B | 60901.24 us | 77790.93 us | 1.28x | 绝对指令数更多，差距更大 |

【总结】SIMT算子使用结构体搬运数据时，应关注`alignof`是否限制编译器使用较宽访存指令。结构体对齐能减少搬运所需的访存指令条数，从而降低 Task Duration。8 B 组因编译器合并加载例外；其余三组中，`alignof` 越小（访存宽度越窄），性能差距越明显。
