# 通过类型对齐提升搬运效率

【优先级】中

【描述】SIMT 编程模式下，结构体对齐会影响Global Memory的访存效率。当前本平台支持1B、2B、4B、8B四种位宽的访存指令位宽。在数据总量不变时，可通过类型对齐到更大的位宽，匹配更宽的访存指令，降低整体耗时，提升数据搬运效率。

【样例实现】设置总搬运量`MEM_BYTES`为 512 MiB，构造多组不同大小、不同对齐方式的结构体`TData`，依次将长度为`num_elements`的输入数组`d_idata`整体复制到输出数组`d_odata`进行测试，对比非对齐与使用`alignas`类型对齐后的耗时差异。核函数实现如下：

```
constexpr uint32_t THREAD_COUNT = 2048;                  // threads per block
constexpr size_t MEM_BYTES = 512ULL * 1024ULL * 1024ULL; // 总数据量 512 MiB
uint32_t num_elements = static_cast<uint32_t>(MEM_BYTES / sizeof(TData));

template <class TData>
__global__ __launch_bounds__(THREAD_COUNT) void aligned_type_kernel(
    TData* d_odata, TData* d_idata, uint32_t num_elements)
{
    const uint32_t tid = blockIdx.x * blockDim.x + threadIdx.x;
    const uint32_t num_threads = blockDim.x * gridDim.x;
    for (uint32_t pos = tid; pos < num_elements; pos += num_threads) {
        d_odata[pos] = d_idata[pos];
    }
}
```

【样例规格】

按sizeof分4/8/16/32B五组等字段类型对照，其中4B组覆盖`alignof=1`与`alignof=2`两档窄对齐，再补充2组字段类型不一致的混合结构体对照。具体的规格如下：

| 名称        | 字段     | sizeof | alignof | num_elements  |
|-------------|----------|--------|---------|-----------|
| `Align4`    | 4 × u8   |  4 B   |   4 B   | 134217728 |
| `Misalign4` | 4 × u8   |  4 B   | **1 B** | 134217728 |
| `Align2U16`    | 2 × u16  |  4 B   |   4 B   | 134217728 |
| `Misalign2U16` | 2 × u16  |  4 B   | **2 B** | 134217728 |
| `Align8`    | 2 × u32  |  8 B   |   8 B   | 67108864  |
| `Misalign8` | 2 × u32  |  8 B   | **4 B** | 67108864  |
| `Align16`   | 4 × u32  | 16 B   |  16 B   | 33554432  |
| `Misalign16`| 4 × u32  | 16 B   | **4 B** | 33554432  |
| `Align32`   | 8 × u32  | 32 B   |  32 B   | 16777216  |
| `Misalign32`| 8 × u32  | 32 B   | **4 B** | 16777216  |
| `AlignU8U16`      | 2 × u8 + u16    |  4 B   |   4 B   | 134217728 |
| `MisalignU8U16`   | 2 × u8 + u16    |  4 B   | **2 B** | 134217728 |
| `AlignU8PadU16`   | u8 (1B padding) + u16    |  4 B   |   4 B   | 134217728 |
| `MisalignU8PadU16`| u8 (1B padding) + u16    |  4 B   | **2 B** | 134217728 |

下面以`Align4/Misalign4`这两个结构体作为典型代表展示对照场景。

【反例】`Misalign4`未设置显式对齐，默认`alignof`受字段类型限制，编译器只能选用窄带宽的访存指令。

```
struct Misalign4 {
    unsigned char r, g, b, a;
}; // sizeof=4, alignof=1
```

上述结构体由字段类型决定`alignof=1`，编译器只能用8-bit档位搬运每个元素，访存流水耗费的cycle数偏高，搬运耗时显著增加。

性能数据如下：

| Task Duration(us) | aiv_total_cycles |
| :---------------: |:--------------: |
|     81223.02      | 134028903.60    |

【正例】使用`alignas`提升对齐属性，编译器可以选用更宽带宽的访存指令。

```
struct alignas(4) Align4 {
    unsigned char r, g, b, a;
}; // sizeof=4, alignof=4
```

性能数据如下：

| Task Duration(us) | aiv_total_cycles |
| :---------------: | :--------------: |
|     27889.33      |  46005213.32    |

`Align4`将`alignof`从1B提升到4B，编译器可以选用32-bit档位完成单元素搬运，aiv_total_cycles和Task Duration都显著减小。

【性能分析】

对比多组样例对齐前后耗时差异如下（总搬运量均为512 MiB）：

| 结构体大小                   | Task Duration(对齐) | Task Duration(非对齐) | 非对齐/对齐 |
| :-------------------------: | :-----------------: | :-------------------: | :---------: |
| 4 B (4×u8)                  | 27889.33 us         | 81223.02 us           | **2.91x**   |
| 4 B (2×u16)                 | 27833.56 us         | 46656.61 us           | **1.68x**   |
| 4 B (2×u8 + u16)            | 27854.56 us         | 46666.11 us           | **1.68x**   |
| 4 B (u8 + 1B padding + u16) | 27809.72 us         | 46664.42 us           | **1.68x**   |
|  8 B                        | 17417.23 us         | 17415.04 us           | **1.00x**   |
| 16 B                        | 32983.77 us         | 38353.60 us           | **1.16x**   |
| 32 B                        | 60901.24 us         | 77790.93 us           | **1.28x**   |

测试结果表明：在数据总量不变的时候，相同大小的结构体，类型对齐可以提升搬运效率。以 4B 结构体为例，随着对齐位宽从 1B 提升至 4B，非对齐相对对齐的耗时倍数逐步下降。8B 结构体受编译器自动优化影响，无论是否对齐，均以 8B 带宽完成搬运。此外，同大小的 4B 结构体，字段组合形式、有无填充位，都不会对搬运效率产生影响。

【总结】SIMT算子使用结构体搬运数据时，结构体类型对齐能让访存指令以更大带宽合并完成搬运，降低搬运耗时。当前平台支持1B、2B、4B、8B位宽的访存指令，因此建议使用时在不超过结构体大小的情况下，尽量选择更高的位宽。
