# 通过类型对齐提升搬运效率

【优先级】中

【描述】SIMT 编程模式下，线程访问 Global Memory 的带宽由数据类型的 alignof 对齐属性决定。本平台访存指令支持 1 B、2 B、4 B、8 B 四种带宽。借助 alignas 提升结构体的对齐值，便可选用更宽的访存指令，减少访存流水占用的时钟周期，进而提升数据搬运效率。

> 此外需注意：若结构体`sizeof`等于 8 B，但`alignof`小于 8 B 时，编译器会自动合并，按照 8 B 带宽完成数据搬运。

【样例介绍】以不同大小的结构体逐元素搬运为例，对比非对齐与使用`alignas`对齐后的耗时差异。所有用例共用同一段逐元素搬运核函数，总搬运量均为512 MiB，性能差异仅由类型对齐决定。

下面以`sizeof=4`的结构体作为典型代表展示对照场景；其他`sizeof`（8 B / 16 B / 32 B）以及混合字段对照的结构体定义详见[类型对齐优化搬运效率最佳实践样例](../../../../../examples/03_simt_api/03_best_practices/02_simt_aligned_type/README.md)。

【反例】结构体未设置显式对齐，默认`alignof`受字段类型限制，编译器只能选用窄带宽的访存指令。

```
struct Misalign4 {
    unsigned char r, g, b, a;
}; // sizeof=4, alignof=1
```

上述结构体由字段类型决定`alignof=1`，编译器只能用8-bit档位搬运每个元素，访存流水耗费的cycle数偏高，搬运耗时显著增加。

反例算子在512 MiB总搬运量下的性能数据如下：

| Task Duration(us) | aiv_total_cycles |
| :---------------: |:--------------: |
|     81223.02      | 134028903.60    |

【正例】使用`alignas`提升对齐属性，编译器可以选用更宽带宽的访存指令。

```
struct alignas(4) Align4 {
    unsigned char r, g, b, a;
}; // sizeof=4, alignof=4
```

`Align4`将`alignof`从1 B提升到4 B，编译器可以选用32-bit档位完成单元素搬运，访存流水耗费的cycle显著减少。

正例算子在512 MiB总搬运量下的性能数据如下：

| Task Duration(us) | aiv_total_cycles |
| :---------------: | :--------------: |
|     27889.33      |  46005213.32    |

从Task Duration看，未对齐时的执行耗时为81223.02us，类型对齐后下降到27889.33us，非对齐耗时是对齐耗时的**2.91x**倍。这说明`alignof`偏小会限制编译器只能选用窄带宽访存，提升对齐属性后，单次访存指令以更宽带宽搬运数据，访存流水cycle数明显减少，搬运效率得到显著改善。

除`sizeof=4 alignof=1`这一典型对照外，结构体的`sizeof`和字段构成也会影响实际收益。将对照范围扩展到不同`sizeof`（4 B / 8 B / 16 B / 32 B）以及含混合字段的4 B结构体，对齐前后耗时差异如下（总搬运量均为512 MiB）：

| 对照组          | Task Duration(对齐) | Task Duration(非对齐) | 非对齐/对齐 |
| :-------------: | :-----------------: | :-------------------: | :---------: |
| 4 B (alignof=1) | 27889.33 us         | 81223.02 us           | **2.91x**   |
| 4 B (alignof=2) | 27833.56 us         | 46656.61 us           | **1.68x**   |
|  8 B            | 17417.23 us         | 17415.04 us           | **1.00x**   |
| 16 B            | 32983.77 us         | 38353.60 us           | **1.16x**   |
| 32 B            | 60901.24 us         | 77790.93 us           | **1.28x**   |
| 4 B (2×u8 + u16)            | 27854.56 us         | 46666.11 us           | **1.68x**   |
| 4 B (u8 + 1B padding + u16) | 27809.72 us         | 46664.42 us           | **1.68x**   |

从上表可以看出：

1. **类型对齐可以提升搬运效率，且`alignof`越严效率越高（上限8 B）**：4 B组随`alignof`由1 → 2 → 4，差距从2.91x → 1.68x → 1.00x。其中 8 B 对照组例外，编译器会主动优化，都按照 8 B 带宽完成数据搬运。
2. **`sizeof`与`alignof`一致时，搬运效率与字段构成无关**：三组4 B结构体（2×u16、2×u8 + u16、u8 + 1B padding + u16）加速比统一为1.68x，说明字段是同类型还是混合类型、padding是隐式还是显式声明，均不影响编译器生成的访存指令序列。

【总结】SIMT算子使用结构体搬运数据时，应关注`alignof`是否限制了编译器选用更宽带宽的访存指令。结构体对齐能让访存指令以更大带宽合并完成搬运，降低Task Duration；性能完全由整体`sizeof`与`alignof`决定，与字段构成无关。因此建议在数据搬运为主的场景下，对结构体使用`alignas`加严对齐，使`alignof`至少匹配`sizeof`（且不超过硬件单次访存上限8 B），让单条访存指令尽可能覆盖整个元素，避免窄带宽访存导致的耗时膨胀。
