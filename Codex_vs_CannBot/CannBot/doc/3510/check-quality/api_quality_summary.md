## 三、各 API 评估摘要

### 3.1 asc_addc（84分）

- **文档类型：** API参考手册
- **头文件：** `c_api/reg_compute/compute/reg_arith.h`
- **主要优点：** 函数原型与头文件声明完全一致；产品支持情况完整（9个产品）；调用示例包含完整的 Vector Function 和 kernel 代码结构；关联API表提供了选择指引。
- **主要问题：** 缺少地址重叠约束和元素数量约束；"待补充"徽章标签为模板残留；缺少 Minimal 最小可运行示例；中英文之间多余空格（多处）。
- **修复建议：** 移除未使用的"待补充"徽章；补充地址对齐和重叠约束；精简示例为最小可运行版本。

### 3.2 asc_prelu（82分）

- **文档类型：** API参考手册
- **头文件：** `c_api/reg_compute/compute/reg_fused.h`
- **主要优点：** 函数原型与头文件 `reg_fused.h:110-116` 完全一致；示例代码包含完整的流水同步逻辑；约束说明覆盖了非AIV返回、VF内调用、mask预赋值、负零处理等场景。
- **主要问题：** 缺少"返回值说明"章节（有2个返回值重载）；公式中参数名 `src1` 与原型中 `alpha` 不一致；`PAT_ALL` 常量在公开头文件中未定义；地址对齐和重叠约束缺失。
- **修复建议：** 新增返回值说明章节；统一公式与原型参数名；补充地址对齐约束说明。

### 3.3 asc_exp_sub（76分）

- **文档类型：** API参考手册（已废弃接口）
- **头文件：** `c_api/reg_compute/compute/reg_fused.h`
- **主要优点：** 已废弃状态标注清晰；提供了 asc_exp_sub_half2float 替代方案；数据类型支持表包含位置参数列；调用示例覆盖 float 和 half 两种输入场景。
- **主要问题：** `> **已废弃**` 标注误导（仅 half 输入版本废弃，float 版本未废弃）；缺少"返回值说明"章节（有3个返回值重载）；缺少地址重叠约束和特殊值处理约束；`[适用版本：950]` 标注重复7次；示例中 `PAT_ALL` 和 `ASC_POSITION_EVEN` 在公开头文件中未找到定义。
- **修复建议：** 修正废弃标注范围（仅 half 不带 src_pos 版本废弃）；新增返回值说明章节；减少重复版本标注。

### 3.4 asc_half2float（79分）

- **文档类型：** API参考手册
- **头文件：** `c_api/reg_compute/reg_convert.h`
- **主要优点：** 函数原型与头文件 `reg_convert.h:2867-2879` 完全一致；src_pos 参数说明详细（EVEN/ODD 两种位置）；数据类型支持表清晰；调用示例包含完整的 kernel 结构。
- **主要问题：** 缺少"返回值说明"章节（有2个返回值重载）；缺少地址对齐约束和地址重叠约束；缺少互斥API警告框；缺少前置知识引用；术语 AIV、VL 未解释。
- **修复建议：** 新增返回值说明章节；补充地址对齐和重叠约束；添加术语首次出现时的解释。

### 3.5 asc_pair_reduce_sum（85分）

- **文档类型：** API参考手册
- **头文件：** `c_api/reg_compute/compute/reg_reduce.h`
- **主要优点：** 函数原型与头文件 `reg_reduce.h:100-106` 完全一致；约束说明详细覆盖了 mask 不参与计算时的三种情况；调用示例覆盖了 void 返回值版本和返回值版本。
- **主要问题：** 缺少"返回值说明"章节（有2个返回值重载）；"相加示意图如下"引用了不存在的图片；缺少特殊值处理（inf/nan）约束说明。
- **修复建议：** 新增返回值说明章节；补充实际图片或移除图片引用；补充 inf/nan 特殊值处理说明。

## 五、整体改进建议

### 5.1 优先修复项（影响内容正确性）

1. **新增"返回值说明"章节**：asc_prelu、asc_exp_sub、asc_half2float、asc_pair_reduce_sum 均有返回值重载，须补充返回值说明章节，描述返回值类型和含义。
2. **修正废弃标注**：asc_exp_sub 的 `> **已废弃**` 标注应限定为仅 half 输入不带 src_pos 的版本，float 输入版本不应被标记为废弃。
3. **统一公式参数名**：asc_prelu 的数学公式中 `src1` 应改为 `alpha`，与函数原型保持一致。

### 5.2 结构优化项（影响文档完整性）

1. **规范产品顺序**：所有5个文档的产品支持情况应按规范顺序排列（Kirin X90/9030 应在 Atlas 推理/训练系列产品之前）。
2. **补充约束说明**：矢量计算类API应补充地址对齐约束、地址重叠约束、特殊值处理约束。
3. **移除模板残留**：移除所有文档中未实际使用的"待补充"徽章标签。

### 5.3 格式规范项（影响文档可读性）

1. **规范 `#include` 展示**：头文件路径应使用代码块格式展示。
2. **修正中英文空格**：检查并修正中英文/数字之间的多余空格。
3. **补充术语解释**：AIV 等缩写首次出现时应括号注释全称。

## 六、评估方法说明

- **评估标准**：遵循《Ascend C 资料设计规范》三维度（可获取性、可读性、完备性）和《Ascend C 资料贡献指南》五类文档编写规范
- **评分维度**：结构完整性（20分）、语言通顺性（25分）、规范性（25分）、准确性（30分），满分100分
- **评估流程**：5阶段逐项检查（标记扫描→API结构检查→设计规范合规→格式规范→准确性检查）+ 4维度评分
- **评级标准**：优秀（90-100）、良好（75-89）、中等（60-74）、较差（40-59）、需改进（<40）
- **数据来源**：asc-devkit 仓库本地代码（include/c_api/reg_compute/ 头文件声明、impl/c_api/instr_impl/npu_arch_3510/ 实现、docs/zh/vitepress/docs/public/api-source/files/ 官方文档）
- **评估范围**：仅评估 3510（Ascend 950PR/Ascend 950DT）版本文档
