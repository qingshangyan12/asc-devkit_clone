### 改进优先级

1. **优先修复（强制规则违反，影响内容正确性与关键结构完整性）**：
   - **API-PROD-01（行15-16）**：产品支持列表中 Kirin X90 和 Kirin 9030 排列位置错误，应按规范顺序 `950 → A3 → 910b → 310b → x90 → 9030 → 310p → 910` 排列，将 Kirin X90 和 Kirin 9030 移至 Atlas 200I/500 A2 推理产品之后、Atlas 推理系列产品之前。
   - **API-CHECK-023 / API-FUNC-01（行20）**：头文件 `#include` 语句以行内代码（反引号）呈现，须改为带语言标记的代码块（` ```cpp `）呈现。
   - **API-CHECK-012 / API-SOFTWARE-01（行67-68）**：数据类型支持表中 uint32_t 排在 int32_t 之前，应按"有符号整数→无符号整数→浮点数"顺序排列，将 int32_t 行移至 uint32_t 行之前。
   - **API-CHECK-007 / API-EXAMPLE-01（行134, 136）**：调用示例缺少完整样例的相对路径链接（仅以注释"参考 asc-devkit 仓库"代替），且缺少对调用结果的说明，须补充样例链接和结果描述。
   - **API-CHECK-008（行74, 148-149）**：约束说明中 `asc_set_ctrl` 首次出现未提供超链接；关联API表中 `asc_add`、`asc_subc` 未提供超链接，须补充相对路径链接。
   - **API-CHECK-035 / API-PROTO-00（行30-46）**：两个函数原型以连续代码块呈现，未按功能分支使用无序列表分组列出，须改为列表形式分组并配文字说明。
   - **API-CHECK-036（行55-59）**：参数表中 dst、src0、src1、carry_src、mask 缺少地址对齐要求说明（carry 参数已标注"起始地址需按照32字节对齐"），须为其余操作数参数补充对齐信息或说明无需对齐。
   - **API-PROD-00（行3-4）**：一级标题与"产品支持情况"章节之间存在标签说明引用块，产品支持情况未紧接一级标题之下，须将引用块移至文档末尾或删除。

2. **次要修复（建议规则违反，影响文档规范性与阅读体验）**：
   - **API-CHECK-045（行22, 54, 59, 72, 73, 74, 75, 79, 138）**：多处中文与英文单词/数字之间存在多余空格（如"32 位"、"非 AIV"、"mask 需"、"NPU 架构"等），须删除中英文/数字间的多余空格。
