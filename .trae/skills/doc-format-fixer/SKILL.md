# 文档典型问题检查与修复技能

## 技能用途

检查 Markdown 文档中的典型格式问题，包括标点符号、空格规范、行文逻辑、错别字和语法等方面的问题，并执行修复。适用于文档定稿前的质量检查。

## 检查项目清单（一定不能遗漏）

### 1. 标点符号规范
- [ ] 中文描述或者中英文混用时都要使用中文标点（，。：；？！""），不能使用英文标点符号。
- [ ] 句子末尾必须有句号，以下情况例外（不加句号）：
  - 表格单元格内的短语（如表头、参数名、简要描述）
  - 列表项为短语时（仅一个名词或简短说明）
  - 标题末尾
  - 代码块内的内容

### 2. 行文逻辑检查
- [ ] 检查文档中是否存在逻辑错误，如前后矛盾、因果倒置、概念混淆等
- [ ] 检查是否存在口语化的描述，应使用书面化、专业的表达方式

### 3. 错别字与语病检查
检查文档中是否存在错别字或语病，重点关注以下常见问题：

**常见错别字**：
- 的/得/地 混用（"正确的使用" → "正确地使用"）
- 其他/其它（统一用"其他"，不用"其它"）
- 示例/实例（"调用示例" / "代码示例"，注意不要写成"实例"）
- 即/既混淆（"即使" / "既然"）
- 与/于混淆、以/已混淆
- 重叠字（"的的"、"了了"等）
- 拼音遗留（如 ing → "进行"误写为"jinxing"）

**常见语病**：
- 谓语/宾语残缺（如"通过...，使..."缺少主语）
- 搭配不当（如"提高...水平"而不是"提高...质量"本身）
- 虚词滥用（多余的"的"、"了"、"进行"等）
- 语序混乱（修饰语位置错误导致歧义）
- 前后矛盾（如"必须...也可以不"）
- 结构杂糅（如"是由于...导致的" → "是由于..."或"是...导致的"）

**检查原则**：代码块内的内容不检查错别字与语病。

### 4. 空格规范
- [ ] 中英文或者是中文和数字混用，英文前后面不能加空格（Atlas A3 训练系列产品、Atlas A2 训练系列产品等固定的标准产品名称不需要修改），数字前后也不能加空格。
典型错误示范1：向 GM 中写入数据（问题：“GM”前后不要加空格！）
典型错误示范2：表 1介绍了数据类型支持情况（问题：“1”前面不要加空格！）
- [ ] 单位与数字之间不加空格（如：50m、10kg、64Kbit/s）

## 使用流程

1. **读取文件**：使用 `Read` 工具读取用户指定的 Markdown 文件
2. **逐项检查**：按照上述检查清单逐项核对文档内容，每条都不能遗漏！
3. **输出报告**：列出所有发现的问题，格式如下：
   ```
   ## 文档典型问题检查报告

   文件：xxx.md

   ### 发现的问题

   | # | 检查项 | 位置 | 问题描述 | 修改建议 |
   |---|--------|------|----------|----------|
   | 1 | **[标点符号]** | [第 XX 行](file:///绝对路径:XX) | 中文内容使用了英文逗号 | 将 `,` 改为 `，` |
   | 2 | **[空格规范]** | [第 XX 行](file:///绝对路径:XX) | 英文"GM"前后多余空格 | 删除"GM"前后的空格 |
   ...

   ### 合格项

   - [x] 标点符号正确
   - [x] 行文逻辑清晰
   ...
   ```
4. **跳转功能**：报告中每个问题的"位置"列提供可点击链接，格式为 `[第 XX 行](file:///绝对路径:XX)`，用户点击后可直接跳转到文档对应行。绝对路径从读取文件时获取。
5. **修改建议与确认**：报告输出后，使用 `AskUserQuestion` 工具将所有问题逐项（或分批）列出，每项包含：
   - 问题描述
   - 原文内容
   - 建议修改为的内容
   - 选项：`全部接受` / `全部拒绝` / `逐项确认`
   
   若用户选择"逐项确认"，则对每项单独询问"接受/拒绝"；若选择"全部接受"，则批量执行所有修改；若选择"全部拒绝"，则不修改。
   
   用户确认后，使用 `SearchReplace` 工具逐项执行修改。
