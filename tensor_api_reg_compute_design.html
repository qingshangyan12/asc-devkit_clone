TensorAPI 优化设计 · reg_compute 重构

将 basic_api/reg_compute 从「指令手册式扁平 API」重构为 Tag × Trait × Verb × Operand 的嵌入式 DSL，与全局 Copy/Mmad 同构。 本文档为 设计 + 已实现代码 的权威说明；详细问题评审见同目录 tensor_api_optimization_roadmap.html。

namespace AscendC::Te arch / atom / algorithm / reg 256B RegTensor CuTe-inspired

1设计公理

公理含义对旧 API 的回应
正交性指令族 / 配置 / 操作数 / 动词 四维独立组合消灭 39 个 LoadAlign 重载式组合爆炸
统一访问全栈 Verb(MakeXxx(tag[,trait]), operands...)Load/LoadAlign/DataCopy 多入口合一
标签分发空 struct tag + 编译期特化路由到 Inst消灭 LoadAlign(RegTensor) vs LoadAlign(MaskReg) 同名异义
策略对象MakeVec/MakeLoad 产出可复用 Atom配置与执行分离，可 hoist 到循环外
开闭原则扩展 = 新 tag + REGISTER 宏，不改动词签名不再改 intf 头堆重载
零成本抽象内联后 = 一条 asc_* 指令不牺牲性能换结构

5Compute 域（已实现）

using namespace AscendC::Te;

auto atom = MakeVec(vec::Add{});
Compute(atom, dst, a, b, mask);                              // 可复用 atom
Compute(MakeVec(vec::Add{}, VecTrait{MaskMergeMode::MERGING}), dst, a, b, mask);
Add(dst, a, b, mask);                                         // 语义糖（宏生成）

已注册 tag：Add, Sub, Mul, Div, Max, Min, Abs, Exp, Sqrt, Ln, Not。扩展配方：

// vec_op.h 声明 struct Xxx;
ASCENDC_TE_REGISTER_VEC_OP(Xxx, InstName, arity);

MERGING 在 atom 层统一经 Select 合并，默认 ZEROING。

6Load/Store 域

6.1 已实现（MVP）

Load(MakeLoad(load::UbAlign{}), dst, ubPtr);
Store(MakeStore(load::UbStoreAlign{}), ubPtr, src, mask);

6.2 Trait 契约（load_trait.h）

正交维度不进函数名，而进 RegLoadTrait / RegStoreTrait：

  • dist ← 旧 LoadDist / StoreDist
  • post ← PostLiteral
  • width ← 单/双寄存器
  • addr ← DIRECT / OFFSET / POST_UPDATE_PTR / ADDR_REG

6.3 旧 39 接口映射策略

旧族新动词新 tag

vsldb / vsstbLoad / Storeload::UbBlockStride + BlockStrideTrait
pld / pst / pstsLoadMask / StoreMaskload::MaskAlign + MaskMoveTrait
vldas / vstus …LoadUnalign / StoreUnalignload::UbUnalign + UnalignTrait
vgather / vscatterGather / Scatterload::Gather, store::Scatter

7完整示例：dst = a + b - c

using namespace AscendC::Te;

auto vA   = MakeRegTensor<half>();
auto vB   = MakeRegTensor<half>();
auto vC   = MakeRegTensor<half>();
auto vDst = MakeRegTensor<half>();
auto mask = MakeMaskReg<half>(elemCount);

Load(MakeLoad(load::UbAlign{}), vA, ubA);
Load(MakeLoad(load::UbAlign{}), vB, ubB);
Load(MakeLoad(load::UbAlign{}), vC, ubC);

Compute(MakeVec(vec::Add{}), vDst, vA, vB, mask);
Compute(MakeVec(vec::Sub{}), vDst, vDst, vC, mask);

Store(MakeStore(load::UbStoreAlign{}), ubDst, vDst, mask);

8理论问题 → 新设计解决度

理论问题状态说明
正交性 / 组合爆炸✓ Compute 域Load 域 trait 已定义，实现进行中
同名异义 LoadAlign△ 设计完成待 LoadMask/StoreMask 动词落地
统一访问 UAP✓ 已迁移子集Verb+MakeXxx 全栈一致
默认语义不一致✓VecTrait 显式 ZEROING；MERGING 显式传
RegTensor 抽象泄漏✗仍 alias Reg::RegTensor，长期需新抽象
层次坍塌✓ 改善四层分离；public 仍 include impl（与 Copy 同）
架构碎片化△Inst 层 if constexpr；多 arch 待验证
弱类型 DefaultType✓ Te 层从 RegTensor / T* 推导
规范缺失△vector_compute/reg_load 有文档；全模块待补
开闭原则 OCP✓ vec 域REGISTER 宏扩展
结论新 TensorAPI 在公理和结构上解决了问题；在覆盖范围上仍是 MVP，旧 reg_compute 主体尚未替换。
