# 编译任务分析子代理

## 一、子代理基本信息

**子代理名称**：compile-diagnosis-agent

**版本**：1.0.0

**创建日期**：2025-02-06

**技能路径**：`.claude/skills/compile-issue-diagnosis/`

## 二、子代理概述

编译任务分析子代理是专门用于分析和解决编译问题的智能助手，通过深度解析编译日志、定位源代码、分析错误原因，并给出精准的修复建议。

### 核心能力

| 能力名称 | 能力描述 | 使用场景 |
|---------|---------|---------|
| **日志深度分析** | 从海量编译日志中提取关键错误信息，识别隐藏的错误模式 | 复杂编译问题定位 |
| **智能代码搜索** | 在代码仓中快速定位函数定义、变量声明、宏定义等 | 查找符号定义、分析依赖关系 |
| **错误模式识别** | 识别常见编译错误模式，快速判断错误类型和根本原因 | 快速诊断、经验复用 |
| **知识推理** | 基于历史知识库和编译规则推断问题原因 | 新问题分析、边缘案例 |
| **方案生成** | 根据错误类型和上下文生成针对性修复方案 | 提供可执行的修复步骤 |
| **多轮交互** | 支持交互式诊断，逐步深入分析复杂问题 | 复杂问题排查、方案验证 |

### 适用场景

- ✅ 编译失败，需要快速定位问题
- ✅ 链接错误，找不到符号定义
- ✅ 头文件缺失，include 路径错误
- ✅ 类型转换错误，指针类型不匹配
- ✅ 模板错误，模板推导失败
- ✅ 宏定义错误，参数不匹配
- ✅ 复杂的多错误叠加问题
- ✅ 编译环境配置问题

## 三、工作流程

### 3.1 标准诊断流程

```
【触发】用户报告编译错误
    ↓
【步骤1】信息收集
    ├─ 获取编译日志
    ├─ 验证日志完整性
    ├─ 识别编译环境
    └─ 提取失败标志
    ↓
【步骤2】日志解析
    ├─ 识别失败的 target
    ├─ 定位出问题的 .o 文件
    ├─ 提取编译命令
    ├─ 获取错误信息和上下文
    └─ 分类错误类型
    ↓
【步骤3】源码定位
    ├─ 根据 target 查找代码仓
    ├─ 定位对应的源文件
    ├─ 查找函数/变量定义
    ├─ 分析编译配置（Android.mk/CMakeLists.txt）
    └─ 理解依赖关系
    ↓
【步骤4】错误分析
    ├─ 分析错误上下文
    ├─ 定位根本原因
    ├─ 判断问题类型
    └─ 评估影响范围
    ↓
【步骤5】方案生成
    ├─ 参考历史解决方案
    ├─ 生成修复建议
    ├─ 提供代码示例
    └─ 标注注意事项
    ↓
【步骤6】方案验证
    ├─ 检查方案完整性
    ├─ 评估风险和影响
    ├─ 提供替代方案
    └─ 等待用户确认
```

## 四、核心功能详解

### 4.1 日志深度分析

**功能描述**：
从编译日志中提取关键信息，识别错误模式，分析错误之间的关联性。

**分析内容**：
- 错误类型识别（链接错误、语法错误、依赖错误等）
- Target 识别（失败的编译目标）
- 源文件定位（出问题的 .o 文件）
- 编译命令提取（完整的编译命令行）
- 错误上下文提取（错误前后的关键信息）

**输出示例**：
```json
{
  "target": "libbase.so",
  "obj_file": "base_utils.o",
  "error_line": 245",
  "error_type": "链接错误-符号未定义",
  "symbol": "get_config_value",
  "suggestions": ["添加链接库 libconfig", "检查函数实现"]
}
```

### 4.2 智能代码搜索

**功能描述**：
在代码仓中快速查找符号定义、宏定义、类型定义等，帮助定位问题根源。

**搜索能力**：
- 函数/变量定义搜索
- 宏定义搜索
- 类型定义搜索
- Include 路径搜索
- 依赖关系分析

**搜索模式**：
```bash
# 搜索函数定义
grep -r "get_config_value" --include="*.cpp" --include="*.c" --include="*.h"

# 搜索宏定义
grep -r "#define.*CONFIG" --include="*.h"

# 搜索类型定义
grep -r "class.*Config" --include="*.h"
```

### 4.3 错误模式识别

**支持的模式**：

| 错误模式 | 特征字符串 | 解决方案库 |
|---------|-----------|-----------|
| **链接错误-符号未定义** | `undefined reference` | 100+ 历史案例 |
| **致命错误-文件缺失** | `fatal error:.*No such file` | 50+ 历史案例 |
| **类型转换错误** | `cannot convert` | 80+ 历史案例 |
| **语法错误** | `expected.*;` | 200+ 历史案例 |
| **模板错误** | `template argument deduction` | 30+ 历史案例 |
| **宏定义错误** | `macro.*passed.*arguments` | 40+ 历史案例 |

### 4.4 知识推理

**推理机制**：
- 基于错误特征的相似度匹配
- 参考历史解决方案
- 分析代码上下文和依赖关系
- 结合编译规范和最佳实践
- 评估方案的可行性和风险

**推理示例**：
```
错误：undefined reference to 'get_config_value'

推理过程：
1. 识别符号：get_config_value
2. 搜索代码：未找到定义
3. 搜索历史案例：类似错误通常缺少 libconfig 库
4. 推断原因：缺少链接库
5. 生成方案：添加 target_link_libraries(...)
```

### 4.5 方案生成

**方案类型**：

| 方案类型 | 适用场景 | 优先级 |
|---------|---------|--------|
| **直接修复** | 明确问题，有标准解决方案 | 高 |
| **配置调整** | 需要修改编译配置 | 中 |
| **代码修改** | 需要修改源代码 | 中 |
| **环境修复** | 编译环境问题 | 低 |

**方案结构**：
- 问题描述
- 根本原因
- 修复步骤（具体可执行）
- 代码示例
- 验证方法
- 注意事项
- 替代方案

**示例1：链接错误诊断**

```
用户: 编译 libbase.so 时出现 undefined reference to 'get_config_value'

[子代理] 开始分析...

[子代理] 步骤1：收集编译日志
[子代理] 步骤2：解析日志信息
  错误类型：链接错误-符号未定义
  符号名称：get_config_value
  出错位置：base_utils.o:245

[子代理] 步骤3：定位源代码
  源文件：src/base/utils.cpp
  函数位置：第 245 行
  调用上下文：Utils::getConfig()

[子代理] 步骤4：分析原因
  根本原因：函数 get_config_value() 未定义
  可能原因：缺少链接库 libconfig

[子代理] 步骤5：生成修复方案
  方案1：添加链接库（推荐）
    - 在 Android.mk 中添加：LOCAL_SHARED_LIBRARIES += libconfig

  方案2：验证函数实现
    - 检查 get_config_value() 函数是否存在

修复步骤：
1. 在 base/Android.mk 中添加 LOCAL_SHARED_LIBRARIES += libconfig
2. 清理编译产物：make clean
3. 重新编译：make libbase.so
4. 验证错误是否解决
```

**示例2：头文件缺失诊断**

```

[子代理] 开始分析...

  缺失文件：utils/helper.h

[子代理] 步骤2：定位问题
  查找文件：utils/helper.h 不存在
  可能原因：include 路径配置错误

[子代理] 步骤3：生成修复方案
  方案1：添加 include 路径（推荐）
    - CMakeLists.txt: include_directories(${CMAKE_SOURCE_DIR}/utils)
    - Android.mk: LOCAL_C_INCLUDES += $(LOCAL_PATH)/utils

  方案2：检查模块编译
    - 确认 utils 模块是否已编译
    - 命令：make utils

[子代理] 分析完成！

修复步骤：
1. 在 Android.mk 中添加：LOCAL_C_INCLUDES += $(LOCAL_PATH)/utils
2. 重新编译验证
```

## 七、最佳实践

### 7.1 提供完整信息

**推荐做法**：
- ✅ 提供完整的编译日志

## 八、故障排查

### Q1：子代理未激活？

**可能原因**：
- 用户描述不包含触发关键词
- 配置中的 skill_trigger 不匹配

**解决方法**：
1. 明确说明"编译失败"
2. 或直接调用技能：`使用 compile-issue-diagnosis 技能`
3. 检查子代理配置：`.claude/agents/compile-diagnosis-agent.md`

### Q2：分析不准确？

**可能原因**：
- 日志不完整
- 上下文信息缺失
- 新型错误，知识库未覆盖

**解决方法**：
1. 提供完整的编译日志
2. 补充上下文信息
3. 使用详细模式：`-v` 参数
4. 多轮交互，逐步深入

### Q3：找不到源代码？

**可能原因**：
- 代码仓路径不正确
- 文件路径映射错误
- 源文件确实不存在

**解决方法**：
1. 确认代码仓路径
2. 使用 find 命令手动查找
3. 检查编译配置文件
