# aclnn 算子 API 说明文档质检 Skill

本 skill 用于对算子 API 说明文档进行质量检查，基于预设规则检测文档中的规范性、完备性、可读性、正确性问题。

## 重要原则（必须严格遵守，防止幻觉）

### 1. 仅使用给定规则

- **只能**使用 `reference/aclnn-rules-{1,2,3,4}.md` 中明确定义的规则
- **严禁**创造新规则、修改规则名称或规则级别
- 规则名称必须与规则文件中的完全一致（如"产品型号命名规范"）

### 2. 代码即真相（正确性检查）

- 对于"正确性"类别的检查，**必须**先读取代码文件再进行判断
- **禁止**仅根据文档内容推测代码行为
- 如果无法从代码中找到明确证据，**不要报告该问题**

### 3. 每项检查后追加写入 JSON 文件

- **每项检查完成后**：立即将结果追加写入 JSON 文件
- **质检期间**：禁止输出任何解释性文字、总结、表格
- **最终输出时**：保证输出到文件，无需输出到控制台
- 输出格式**只能**是标准 JSON

### 4. 输出前验证最终质检结果

- **只报告**真实存在问题的检查项
- 无问题，文档与代码一致的检查项**严禁报告**

## 输入

1. **`-doc` 待检查的文档**：用户输入需要检查质量的 API 文档文件（.md 格式）
2. **`-type` 质检类别**：指定需要执行的质检类别
   - `1` 规范性检查
   - `2` 完备性检查
   - `3` 可读性检查
   - `4` 正确性检查
   - `all` 全部检查（默认）
   - 多类别用逗号分隔，如 `-type 1,2,4`

### 示例

```
# 全部检查
/api-doc-qc-aclnn -doc "doc.md" -type all
或
/api-doc-qc-aclnn -doc "doc.md"

# 仅规范性
/api-doc-qc-aclnn -doc "doc.md" -type 1

# 规范性 + 完备性
/api-doc-qc-aclnn -doc "doc.md" -type 1,2
```

### 质检类别说明

| 类别     | 说明                     | 是否需要代码 |
| -------- | ------------------------ | ------------ |
| 1-规范性 | 检查文档格式、命名规范等 | 否           |
| 2-完备性 | 检查文档内容是否完整     | 否           |
| 3-可读性 | 检查文档表达是否清晰易懂 | 否           |
| 4-正确性 | 检查文档与代码一致性     | 是           |

## 输出

输出一个质检结果JSON文件

### 注意
- 默认输出目录：`/Users/zhizhang/HW/results/`
- 如果目录不存在则自动创建
- 文件命名规则：`{被检查文档名}-qc-result.json`
- 例如：
  - 待检查的文档 -doc：`/Users/aclnn/docs/aclnnAbs.md`
  - 结果文件：`/Users/zhizhang/HW/results/aclnnAbs-qc-result.json`

## 执行流程

### 第 1 步：读取文档结构 & 初始化输出文件

1. 打印进度：`[CHECKPOINT: 开始质检]`
2. 读取[文档结构参考](./reference/aclnn-doc-structure.md)了解基本结构
3. 读取用户提供的待检查文档文件
4. 创建空 JSON 结果文件：
   - 路径：`/Users/zhizhang/HW/results/{被检查文档名}-qc-result.json`
   - 初始内容：`{"result": "pending", "details": []}`
   - 如果目录不存在则先创建目录

### 第 2 步：解析类别并创建动态任务列表

打印进度：`[CHECKPOINT: 前置条件处理完成]`
根据 `-type` 参数解析需要执行的质检类别：

| 类型参数           | 对应任务     |
| ------------------ | ------------ |
| `1` 或包含 `1` | 规范性检查   |
| `2` 或包含 `2` | 完备性检查   |
| `3` 或包含 `3` | 可读性检查   |
| `4` 或包含 `4` | 正确性检查   |
| `all`或未提供    | 全部四项检查 |

**创建动态任务（Todo）列表**：

根据解析结果创建对应的任务项，展示任务列表和进展。

检查项规则级别说明

| 级别 | 说明                             |
| ---- | -------------------------------- |
| 严重 | 必须修复，否则会导致用户使用错误 |
| 一般 | 建议修复，影响文档质量和用户体验 |
| 提示 | 可选修复，属于优化建议           |

#### 动态执行任务

根据选择的类别顺序执行对应的检查任务：

##### 如果包含类别 1（规范性检查）

- Task #1 规范性检查
  a. 打印进度：`[CHECKPOINT: 开始规范性检查]`
  b. 读取规则文件: `reference/aclnn-rules-1.md`
  c. 执行全面规范性检查
  d. 将检查结果追加写入 JSON 文件：读取当前文件内容，合并新发现的问题后重新写入
  e. 打印进度：`[CHECKPOINT: 完成规范性检查]`
- 要求：仅检查文档格式，不需要读代码

##### 如果包含类别 2（完备性检查）

- Task #2 完备性检查
  a. 打印进度：`[CHECKPOINT: 开始完备性检查]`
  b. 读取规则文件: `reference/aclnn-rules-2.md`
  c. 执行全面完备性检查
  d. 将检查结果追加写入 JSON 文件：读取当前文件内容，合并新发现的问题后重新写入
  e. 打印进度：`[CHECKPOINT: 完成完备性检查]`
- 要求：仅检查文档格式，不需要读代码

##### 如果包含类别 3（可读性检查）

- Task #3 可读性检查
  a. 打印进度：`[CHECKPOINT: 开始可读性检查]`
  b. 读取规则文件: `reference/aclnn-rules-3.md`
  c. 执行全面可读性检查
  d. 将检查结果追加写入 JSON 文件：读取当前文件内容，合并新发现的问题后重新写入
  e. 打印进度：`[CHECKPOINT: 完成可读性检查]`
- 要求：仅检查文档格式，不需要读代码

##### 如果包含类别 4（正确性检查）

- Task #4 正确性检查
  a. 打印进度：`[CHECKPOINT: 开始正确性检查]`
  b. 查找**文档对应算子的代码目录**：检测待检查的文档同级目录下是否有对应算子同名文件目录，如有就检测，没有就跳过正确性检查，直接打印进度结束。
  c. 读取规则文件: `reference/aclnn-rules-4.md`
  d. 读取[代码结构参考](./reference/aclnn-code-structure.md)
  e. 读取用户提供的代码目录下的相关代码文件
  f. 执行全面正确性检查
  g. 将检查结果追加写入 JSON 文件：读取当前文件内容，合并新发现的问题后重新写入
  h. 打印进度：`[CHECKPOINT: 完成正确性检查]`
- 要求：必须有文档对应算子的代码目录才能读取代码文件，从而验证文档与代码的一致性。

### 第 3 步：输出最终质检结果

打印进度：`[CHECKPOINT: 质检结束]`

## JSON 文件操作说明

- **准备阶段**：创建空 JSON 文件 `{"result": "pending", "details": []}`
- **每项检查后**：读取当前文件，追加新发现的问题，重新写入
- **全部检查结束后**：打印进度：`[CHECKPOINT: 质检结束]`

### 质检结果统一 JSON 格式

**有问题时输出：**

```json
{
  "result": "fail",
  "details":[
    {
      "issue_id": 1,
      "rule_name": "产品型号命名规范",
      "rule_type": "规范性",
      "file_name": "docs/aclXxx.md",
      "line_number": 10,
      "snippet": "| Ascend 950PR/Ascend 950DT |    √     |",
      "description": "产品名称缺少 term 标记",
      "suggestion": "| </term>Ascend 950PR/Ascend 950DT</term> |    √     |",
      "rule_level": "严重"
    }
  ]
}
```

**无问题时输出：**

```json
{
  "result": "pass",
  "details":[]
}
```

#### 输出字段说明

| 字段名              | 类型   | 描述                                                     | 要求                     |
| ------------------- | ------ | -------------------------------------------------------- | ------------------------ |
| result              | string | 质检结果：pass（通过）/ fail（未通过）                   | 必须                     |
| details             | object | 问题详情对象，无问题时为空对象 {}                        | 必须                     |
| details.issue_id    | number | 问题索引号                                               | 必须准确，不重复         |
| details.rule_name   | string | 规则名称                                                 | 必须与规则文件中完全一致 |
| details.rule_type   | string | 规则类别：规范性、完整性、正确性、可读性                 | 必须与规则文件中一致     |
| details.file_name   | string | 带被测文档路径文件名，从根目录开始，例如：docs/aclXxx.md | 必须准确                 |
| details.line_number | number | 问题所在文档的行号                                       | 必须准确                 |
| details.snippet     | string | 问题在文档中的具体片段                                   | 直接引用文档内容         |
| details.description | string | 问题的具体描述                                           | 清晰说明问题             |
| details.suggestion  | string | 问题的具体修改建议                                       | 直接给出正确形式         |
| details.rule_level  | string | 规则严重等级：提示、一般、严重                           | 必须与规则文件中一致     |

## 常见幻觉陷阱（避免！）

| 陷阱           | 错误做法                     | 正确做法                               |
| -------------- | ---------------------------- | -------------------------------------- |
| 未读代码下结论 | 根据文档推测函数原型         | 读取 `aclnn_xxx.h` 头文件确认        |
| 规则名称错误   | 使用"函数原型格式"           | 使用规则文件中的"API 函数原型格式规范" |
| 创造规则       | 添加规则文件中不存在的检查项 | 仅使用规则文件中明确定义的规则         |
| 输出多余内容   | 输出总结、表格、解释         | TL;DR, 仅输出 JSON                     |

## 注意事项

1. 本 skill 只关注文档内容的质量检查，默认代码是正确的
2. 用户必须提供代码目录，才能进行正确性检查
3. 输出报告要具体到文档的行号，便于用户定位和修改
4. **仅使用给定规则文件的范围进行检查，严禁增删改规则条目**
5. **对于任何正确性问题，必须先读取代码验证才能报告**
