# 阶段0验收约定

## 规范检查

- 每个 front matter 只能使用 `OKF字段规范.md` 定义的 10 个顶层字段。
- `type` 必须是 `reference.api.Cpp`、`reference.arch.Cpp` 或 `reference.index.Cpp`。
- `resource` 必须是仓库根目录相对路径，并位于两个范围根目录内。
- `status` 必须是 `unconfirmed`、`confirmed` 或 `stale`。
- `products` 只能包含 `A5`、`A3`、`A2`，状态只能是 `supported` 或 `unsupported`。
- `signatures` 中的声明、dtype、头文件和架构必须能在正文对应章节找到依据；未知信息省略，不猜测。
- 关联关系必须有 Markdown 链接或正文条件作为依据，不能把相关文档写成固定调用顺序。
- 日期若出现在后续维护记录中，统一使用 `YYYY-MM-DD`；阶段0示例不使用无效日期。

## 覆盖检查

阶段3使用本约定检查全部目标文档。阶段0只检查规范示例，至少覆盖：

- `asc_div` 普通计算 API
- 一个 dtype 转换 API
- 一个 mask/config API
- 一个 datamove API
- 一个 `arch_2201` 或 `arch_3510` 架构变体页
- 一个 compute 分类页
- 一个 `asc_copy_gm2ub` 架构索引页

规范必须能表达连续计算、高维/stride、scalar、mask、reduce、conversion 等调用模式。

## 范围检查

范围清单必须与当前仓库实际文件一致：总数 140，datamove 28，compute 112；普通 API 页 115，架构变体页 8，分类/索引页 17。阶段0不得修改这些 Markdown 文档。
