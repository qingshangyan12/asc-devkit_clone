# OKF 知识检索项目：后续实施计划

## 1. 计划目标

将[流程与架构说明书](流程与架构说明书.md)分阶段转化为可复用的 skills 与知识资产。实施范围始终限于 `docs/zh/api/SIMD-API/c_api/vector_datamove` 和 `docs/zh/api/SIMD-API/c_api/vector_compute` 及其子目录内的 Markdown 文件。

本计划只确定实施顺序、目标、产物和完成条件，不规定具体技术实现。

## 2. 实施顺序与阶段目标

| 阶段 | 实施对象 | 实现目标 | 交付产物 | 完成条件 |
| --- | --- | --- | --- | --- |
| 0：约定与范围 | 项目共用规则 | 明确 OKF 字段语义、文档角色与任务边界；调研参考 PR，确定适合算子检索的描述约定 | 独立字段说明、范围清单、验收约定 | 每个拟用字段都有明确含义；分类页、API 页和架构差异页均有适用约定 |
| 1：先建立评测基线 | `okf-evaluate` 第一阶段 | 在改动文档前构造代表性测试集，明确正确结果的判断依据，建立完全无 OKF 的基线 | 评测 skill 初版、测试集、基线结果、评测口径 | 基线未接触增强资产；任务覆盖算子阶段检索、关联查找与知识缺口 |
| 2：形成标签体系 | `okf-tag-research` | 依据范围内 API 与算子场景，形成可直接选用的统一候选 tags | 标签调研 skill、持久化候选 tags 及说明 | 标签覆盖目录分类、阶段、流水和关键使用特征；含义及使用条件清晰 |
| 3：生成知识描述 | `okf-frontmatter` | 按字段规范与候选 tags，为范围内所有 Markdown 文件生成可靠的 OKF 头 | YAML 头生成 skill、文档 YAML 头、检查结果 | 无范围外改动；范围内无漏项；标签来自候选集合；描述可追溯到依据 |
| 4：组织关联知识 | `okf-index` | 首次建立可复用的检索索引，关联相关 C API 文档 | 索引建设 skill、持久化索引及关系资产 | 能定位相关分类与文档，关系有依据，日常使用无需重建 |
| 5：打通算子检索 | `okf-retrieve` | 从用户算子需求出发，经已有索引发现分阶段候选文档 | 检索 skill、代表性任务检索结果 | MSELoss 等任务可获得候选文档与简短用途；缺口明确；默认不展开接口细节和代码 |
| 6：建立维护能力 | `okf-maintain` | 支持错误纠正、范围内新增知识及文档变动，协调既有 skills 更新资产 | 维护 skill、维护流程与验证记录 | YAML、tags 和索引能够一致更新；范围外扩展不会被自动纳入 |
| 7：完成效果验收 | `okf-evaluate` 第二阶段 | 使用同一测试集完成增强方案对照，验证维护后的检索质量 | 完整评测 skill、对比报告、问题清单 | 质量与效率分别报告；建设成本单列；未达标问题有明确回流环节 |

评测 skill 分两次完成：先锁定基线与判断标准，再在检索链路就绪后补齐增强方案对照。其余 skills 按标签调研 → YAML 头生成 → 索引建设 → 知识检索 → 知识维护的顺序实施。

## 3. 阶段依赖与推进原则

- 字段说明与候选 tags 稳定后，再批量生成 YAML 头；发现描述不足时先完善共用规则。
- YAML 头检查通过后，再将其纳入正式索引，避免错误信息扩散到检索结果。
- 索引可复用后，再验收检索 skill，确认查询过程真正使用已有资产。
- 检索链路打通后，验证维护对新增、纠错、移动和删除的处理效果。
- 最终评测若发现质量问题，先修正对应知识或检索环节，再判断效率收益。

## 4. 最终交付与验收

后续完整交付包括六个 skills、独立 YAML 字段说明、持久化候选 tags、范围内所有 Markdown 文件的 OKF 头、持久化索引与文档关系，以及测试集和对照评测报告。

验收围绕三项结果展开：用户能从算子需求快速发现相关 C API 文档；知识资产能被后续检索直接复用并随变化维护；相较完全无 OKF 的基线，检索质量不降低且效率收益有可复核证据。具体阈值在阶段 0 和阶段 1 确定。

本计划不承诺未经评测的加速比例，也不包含具体 API 推荐列表、YAML 字段设计、标签枚举、索引结构或 skill 实现指令。
