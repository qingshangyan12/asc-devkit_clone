# 头字段与标注规范

本规范是 asc-knowledge-create 写入面的字段契约唯一事实源：三类头各由哪条管线写入、文档头固定字段与顺序、
version 推导方式、标注证据规则。索引侧如何消费三类头，由 asc-search 的
`references/index_derivation_contract.md` 自描述，本 skill 不复制推导规则。
存量头的漂移体检与修复入口是建设侧 asc-knowledge-update（`.agent/skills/asc-knowledge-update/`）；
当前适配范围为 `docs/zh/api/SIMD-API/c_api`（C API）。

## 1. 三类头与设计原则

| 头类型 | 载体 | 承载信息 | 写入方 |
| --- | --- | --- | --- |
| 文档头 | Markdown front matter | 语义信息（脚本不可推导） | asc-knowledge-create 文档标注管线写入（5 字段） |
| include 头 | 头文件 Doxygen（`@ingroup/@brief/@override_id/@archs/@param`）与声明 | 重载功能摘要与结构事实（原型、架构、参数） | 仓内既有；缺口由 `scripts/annotate_sources.py include` 修复，修复内容属源码维护；brief 写法见 [源码标注契约](source-annotation-contract.md) |
| examples 头 | 每源文件共同范围首尾的 `//! [id1, id2, ...]` marker | 同一展示范围与多个重载的关联 | 仓内既有；缺口由 `scripts/annotate_sources.py examples` 修复 |

原则：

1. 文档头只放脚本推不出来的语义信息；可推导的检索维度由索引侧在推导期由脚本生成，不写入头。
2. 标注管线以确定性脚本为主，validate 未通过不得写入。
3. 不为可推导事实建标签（词表调研与标注共同遵守）。

## 2. 文档头（5 字段）

字段与顺序固定：`okftype, description, tag, dependencies, version`。

| 字段 | 类型 | 必填性 | 说明 |
| --- | --- | --- | --- |
| `okftype` | string | 必填 | 文档族.页面种类，如 `reference.api`；index 页仅有此字段 |
| `description` | string | 实体页必填 | 中文单段摘要，8–180 字 |
| `tag` | ns→values | 见下 | 仅 `roles/operations/traits` 三个 namespace |
| `dependencies` | object[] | 必填（可为 `[]`） | `path/kind/condition?`；kind 取 `requires/configures/constrained_by/related/replaced_by` |
| `version` | string | 实体页必填 | CANN 生命周期区间：`>=9.0.0`（及以后）或 `>=9.0.0,<=9.2.0`（闭区间）；写入时加引号 |

### tag namespace（仅 3 个）

| namespace | 必填规则 | 说明 |
| --- | --- | --- |
| `roles` | 实体页必填 | 调用/执行流程中的角色 |
| `operations` | roles 含 `compute/data_movement/data_initialization` 时必填 | 直接执行或配置的操作 |
| `traits` | 选填 | 影响检索的稳定行为特征（对齐/连续性/量化/填充等语义特征） |

不适用 namespace 省略，不写空数组。okftype 页面种类沿用既有注册表
（api/constant/enum/macro/union/type/index/concept/catalog/release）。

tag 合法值以 `config/tag-taxonomy.json`（冻结词表）为准；词表的生产与扩充由
`references/tag-research.md` 的调研流程负责，标注不得临时创造未定义值。

## 3. version 字段产生方式（标注期推导，落头）

- 值由脚本从 `docs/zh/api/appendix/Release_Notes/` 推导（线上 release_notes.html 与本地同源，
  本地为唯一构建输入）：`CANN_9_0_0.md` 全量清单 → floor 9.0.0；
  `CANN_9_1_0/9_2_0.md`「新增特性」→ floor 抬升；「接口废弃」→ 区间闭合。
- 脚本写入头，证据为 Release Notes 逐字摘录；规则无法裁决的个案登记
  `config/version-overrides.yaml`（附依据摘录，人工核对后维护）。
- 索引期只读头做门控，不重复解析。

## 4. 证据规则（标注期）

- `description`：1–3 条目标 Markdown 正文逐字摘录。
- `tag`：每个 `namespace:value` 一条正文逐字摘录；不能凭名称、目录、dtype、架构、头文件、
  样例注释或相邻 API 推断。
- `dependencies`：每条依赖 `{source_path, excerpt}` 正文逐字摘录。
- `version`：Release Notes 逐字摘录。
- 正文证据不足以确定必填概念时阻断写入，进入补证/词表修订流程；不得用空数组、`unknown`、
  临时值绕过。

## 5. 旧字段弃用清单

| 旧字段 | 去向 |
| --- | --- |
| `title/resource` | 推导（H1 / 文件路径），不写入 |
| `signature/archs/header/declaration/type_catalog` | 推导（include Doxygen + 声明 + defs），不写入 |
| `examples/navigation` | 推导（marker / 正文链接），不写入 |
| `timestamp` | 删除 |
| `tag.api_surfaces/execution_models/source_locations/destination_locations/families/objects` | 推导或删除 |
| `tag.traits: masked/deprecated` | 推导（mangling `_vb` / `ASC_DEPRECATED`） |
