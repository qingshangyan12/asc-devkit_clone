# OKF 检索评测口径（阶段1基线版）

> 本口径服务于独立评测功能，不参与建设/接入流程编排。

## 1. 目的与适用范围

本口径定义检索评测功能的测量方法，供两处复用：

- 阶段1：在完全无 OKF、无新增索引的原始文档上建立基线。
- 阶段7：使用同一测试集、同一口径、同一运行条件完成增强方案对照。

两组条件采用相同文档正文、相同任务、相同模型与提示模板，基线不得接触任何增强知识资产。

## 2. 评测对象定义

| 要素 | 定义 |
| --- | --- |
| 检索执行者 | explore 类型 subagent，逐任务单独派发，并行度 = 1 |
| 计分语料 | 仅限 `docs/zh/api/SIMD-API/c_api/vector_datamove` 与 `docs/zh/api/SIMD-API/c_api/vector_compute` 及其子目录（140 个 Markdown，基线提交 `6011b4a62f`，已验证 0/140 含 YAML 头）；gold 与误报判定均以此为准 |
| 源码辅助语料 | `include/` 与 `impl/` 整棵目录树（v2 起），用于核实 API 声明、参数与重载；候选答案允许给出源码路径 |
| 任务集 | `testset/tasks.yaml`，20 个任务（A 完整算子检索 8、B 单项能力定位 5、C 关联查找 2、D 条件不完整 2、E 范围外缺口 3） |
| 答案格式 | 固定格式：候选（文档或源码路径 + API 名 + 一句话用途）+ 文档范围内未覆盖说明 |

## 3. 隔离约束

- 任务提示为用户算子需求口吻，不出现样例目录名、样例算子名或 gold API 名。
- 子代理提示中明确：语料仅限计分语料两个目录 + 源码辅助语料（impl/、include/）；禁止访问 `examples/`、`.agent/skills/`、docs 下其他目录（如 sync/、reg_compute/ 文档）。
- 子代理不得修改任何文件（只读检索）。
- 合规审计：任务结束后从 opencode 会话存储的 part 表提取该子会话全部工具调用，按白名单（计分语料 ∪ 源码辅助语料 ∪ /tmp）逐条检查目标路径；违规分两级：
  - **扫描越界（scan_breach）**：以仓库根等白名单外路径为搜索起点（grep/glob/ls/rg），但返回结果不含白名单外内容；
  - **泄漏（leakage）**：任何工具的输入直接指向 examples/、.agent/skills/，或搜索输出中返回了白名单外路径/内容。
- 处置：出现任一级违规即复测一次（模板 v2.1 起含搜索路径限定约束）；复测仍泄漏则该任务结果单列、不计入有效基线统计；扫描越界若无泄漏，结果保留并在报告中标注。

## 4. 核心效率指标（用户指定，对照主指标）

| 指标 | 定义 | 采集方式 |
| --- | --- | --- |
| 任务耗时 | 单任务从派发到子代理返回的 wall-clock 秒数 | 派发前后记录时间戳 |
| token 消耗 | 子会话 `tokens_input` + `tokens_output` + `tokens_reasoning` 之和；`tokens_cache_read/write` 单列展示不计入合计（缓存读取成本特性不同） | 任务结束后查询 opencode.db `session` 表，按 agent=explore 且创建时间落在任务时间窗内定位子会话 |

基线为单次运行：每任务运行 1 次，不做重复取中位数；报告中必须注明单次测量的波动性。若某任务出现明显异常（工具报错、超时、子代理失败），允许复测一次并在报告中标注"复测"及原因。

## 5. 质量门槛指标（保证阶段7"质量不降低"）

| 指标 | 定义 | 计分 |
| --- | --- | --- |
| 文档必选查全率（主门槛） | 答案命中的 `required` gold 文档数 / `required` 总数 | 自动，路径归一化后精确匹配 |
| 能力覆盖（辅助） | `required` 中每个 API，文档命中 或 候选行中该 API 名伴随源码（include/impl）路径，均记覆盖；单列展示，不作门槛 | 自动 |
| 替代组覆盖 | `alternative_groups` 中被覆盖的组数 / 组数；组内命中任一成员（文档或对应源码路径）即视为该组覆盖 | 自动 |
| 误报数 | 答案报告的计分语料文档中，不属于 required ∪ optional ∪ 替代组成员 ∪ 范围内分类/索引页 的数量；源码路径不自动判误报，仅记录供人工复核 | 自动列出，人工复核确认 |
| 缺口正确性 | E 类任务及各任务 `expected_gap` 的标注行为，三档：正确（明确说明文档范围内未覆盖，可附源码或范围外线索）、部分（含糊，未明确下结论）、错误（声称文档范围内存在该文档或编造路径） | 关键词初筛 + 人工终审 |

分类/索引页（范围清单中 17 个，如 `vector_arith.md`）视为合法导航命中，不计误报；架构变体页按任务相关性计入 optional 或替代组。

**家族展开规则**：`required` 中的搬运家族主页（`asc_copy_*` 主页面本质为索引页）被命中时，其 `_arch_2201` / `_arch_3510` 兄弟页出现在答案中视为等价命中；`required` 本身是架构变体页（如 B2）时保持严格匹配。

## 6. 辅助观测量（不设阈值，仅记录）

- 读取文档数量与累计字节数（计分语料内的 md 文件）。
- 读取源码文件数量与累计字节数（include/impl 内的 .h/.cpp 等）。
- 工具调用次数（按工具类型统计）。
- 答案报告的候选总数（文档与源码分列）。

## 7. 测量流程

1. 运行前记录：git commit、模型名、日期、提示模板版本。
2. 逐任务执行：记录起始时间戳 → 派发 explore 子代理 → 记录结束时间戳。
3. 每任务完成后：查询 session 表采集 token；查询 part 表审计工具调用合规性。
4. 全部任务完成后：`scripts/score.py` 自动评分，E 类与误报项人工终审。
5. 汇总产出 `baseline/基线报告.md`：逐任务指标表、分组统计、异常与复测标注、审计结论。

## 8. 阶段7对照判据（预告，阶段1不设绝对阈值）

- 质量不降低：增强组各任务文档必选查全率、替代组覆盖不低于基线；缺口正确性正确率不下降。
- 效率收益：逐任务及分组报告耗时差值、token 差值，建设与维护成本单列，不与查询成本混算。

## 9. gold 判定原则

- A/D 类组合任务：gold 必选项以样例算子 kernel 源码实际调用（`examples/02_simd_c_api/**`，file:line 记录于 tasks.yaml 的 `evidence`）反查文档；样例中范围外 API（reg 寄存器族、sync 族等）转化为 `expected_gap`。
- B/C 类单点与关联任务：gold 以文档正文为直接依据（标题、功能说明、正文链接），有样例处附样例佐证。
- 替代组表达"同一能力存在多条合理路径"（如对齐/非对齐搬运变体），命中任一即覆盖。
