# 中文技术文档格式规范

## 适用范围

适用仓内中文 Markdown 技术资料：编程指南、技术附录、样例 README 等正文表述类文档。
不改变技术事实，只约束表达形式。英文版（`README_en.md`）参照执行对应英文惯例。

## 总原则

1. **书面化**：避免口语化表述和临时性用语，改为书面语句。
2. **一致性**：同一概念全文统一称谓，不混用简称与全称。
3. **单一结构**：一句话只承载一种结构（列举、展开、举例），不叠加修辞符号。
4. **保留中英互译**：概念名首次出现时的中英对照括号（如“核函数（Kernel）”）是合法的，不属于要删除的括号。

## 规则清单

### 1. 称谓统一

- 编程模式称谓统一为全称：**SIMD与SIMT混合编程**，不使用“混合编程”“混编”等简称（标题、表格、正文、注释均适用；正文中同一文件多次出现时，标题与首次出现用全称，行文中距离较远处可用“SIMD与SIMT混合编程”重复或按语义组织）。
- 场景列表列举时用顿号分隔：`SIMT编程场景、SIMD与SIMT混合编程场景下……`，避免“A和B与C”连词碰撞。
- 芯片型号写法与仓上惯例一致：`Ascend 950PR&950DT系列产品`，不用 `Ascend 950PR/Ascend 950DT`。

### 2. 斜杠并列改顿号/连词

中文描述中 `名词A/名词B` 形式的并列，按语义改为以下之一：

- 平级罗列：用顿号 —— `alignas、alignof`、`char16_t、char32_t`、`new、delete、malloc、free`。
- 强调配对/选择关系：用“与”或“或” —— `SIMT VF与SIMD VF`、`按\`__gm__\`或\`__ubuf__\`限定传入`。
- 带动宾展开：重组语句 —— “支持移动构造/移动赋值的定义与使用”→“支持移动构造与移动赋值的定义、使用”。

保留不动的斜杠：`C/C++`（语言名）、`ISO/IEC`（标准组织）、代码内路径与命令、表格中的 `是/否`。

### 3. 中文语境标点

- 中文描述一律使用中文标点；行内代码、表格内公式、命令除外。
- 句末引导代码块/命令时用句号或中文冒号，不用英文冒号（`执行如下命令:` → `执行如下命令。`）。
- 括号成对完整；中文后接英文括号且括号内为中文时，改中文括号。

### 4. 括号中文补充改书面化

中文描述后用括号补充**中文说明**的（非中英互译），将括号内容融入句子：

- 载体类：`样例（LeakyReLU-Affine融合与Clamp算子）` → `以LeakyReLU-Affine融合与Clamp算子为载体的样例`。
- 限定类：`框架（Device侧模板函数）` → `框架是Device侧模板函数` 或前置定语。
- 展开类：`值捕获（拷贝进闭包）` → `值捕获，即拷贝进闭包`。
- 表格单元格内：改逗号衔接 —— `闭包（引用捕获X）注入Y` → `闭包引用捕获X，注入Y`。

保留不动的括号：中英互译（`Unified Buffer（UB）`）、公式（`(x*7) % 11 - 5`）、型号（`（Ascend 950PR&950DT系列产品）`）、表格内数值推导（`（\`x[5]=-3\`被\`lo=-2\`截断）`）、默认值（`（默认）`）。

### 5. 破折号表述书面化

`——` 不用于正文修辞，按语义改为：

- 插入语：调整语序消除，或用“即”引出 —— `载体——A与B——展示` → `以A与B为载体，展示`。
- 展开/说明：逗号或“比如/例如” —— `只负责线程映射——新增算子不需要…` → `只负责线程映射，新增算子不需要…`。
- 小标题引导：冒号 —— `**框架**——签名不含参数：` → `**框架**：签名不含参数，例如：`。
- 结论强调：改“这是/实现了” —— `裁剪——“标准数据流”` → `裁剪，这是“标准数据流”`。

### 6. 措辞具体化

- 表格说明列不用“同上”“——”等占位，写完整说明。
- 语义模糊短语改精确表述：`使用同样可用` → 删去或改写为明确结论；`无需（也不能）` → `无需标记，也不支持标记`。
- 避免自问式重复：`省略参数列表的lambda如\`[v]…\`是C++2b特性` → `省略参数列表的写法，如\`[v]…\`，是C++2b特性；当前默认按C++17编译…`。

### 7. 结构与排版

- 标题层级与导航名保持一致（一级标题 ↔ 索引/目录中的节点名）。
- 代码块缩进与所在列表层级对齐；独立代码块不缩进。
- 引用外部文档用仓上标准长链（如毕昇编译器文档 `…/BishengCompiler/atlas_bisheng_10_0001.html`），章节路径写实际存在的章节名。
- 新增 md 不引入无引用的 HTML 锚点（`<a name>`）；被引用的锚点保留。

## 检查流程

1. 确定文件类型与读者（指南正文 / 样例 README / 表格密集页），表格单元格可用逗号衔接，正文段落优先重组语序。
2. 全文扫描六类问题：称谓、斜杠、标点、括号、破折号、占位词。逐类处理，不要一次混合改动。
3. 每处修改先判语义（并列/选择/举例/限定），再选对应改法；改完通读一句确认书面化。
4. 英文版同步：斜杠并列改 `and`/`or`，em dash（` — `）改逗号/分号/`For example,`，称谓与中文版对齐。
5. 输出修改清单（文件:行号:原句→改句），批量提交前抽读上下文。

## 常见误报提示

- `模板模板参数` 是合法术语（template template parameter），不是重复词。
- 代码块、行内代码、链接目标、URL 内的标点不检查。
- 存量文件（非本次 PR 新增行）的问题单独列出，不混入本次修改。
