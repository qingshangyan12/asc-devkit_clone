# Ascend C API 自然语言查询

本 skill 包装相邻 [asc-search](../asc-search/SKILL.md)，没有另一套引擎或索引。
用户问答使用本入口；Agent 执行任务的中间检索直接使用 asc-search。

1. 保留用户目标，提取操作、数据流、数据类型、API、版本和产品条件。显式条件优先；缺失时使用
   asc-search 的 `detect_context.py` 懒探测，本机不代表已明确的远端目标。无法确认时仅澄清影响候选集的条件。
2. 知识仓调用相邻 asc-devkit-prepare；原生 devkit 使用对应 root 和已准备索引。
   准备错误交回 knowledge-query 的增强失败处理，原查询继续，不能猜测接口。
3. 将问题拆成短关键词和结构化条件，调用 `asc-search/scripts/search.py`。多阶段需求分次查询；
   主条件过宽时收窄，空结果只放松有依据的可选词，保留明确的版本、平台和技术范围。
4. 按候选相关性选文档，读取支撑答案的章节；按需读取具体声明、参数、依赖和 marker 样例。
   区分 Memory/Reg 同名接口，不把页面首次支持版本应用于后加重载。版本演进用 `--changed-in`。
5. 先回答用户问题，再给实际已读的来源路径、必要约束和未确认项。版本变化、废弃替代和样例只说明已核对内容。
   候选不能证明全量覆盖；不得只转发 JSON、堆候选或把零命中当成接口不存在。

knowledge-query 中这是补充链：原知识库结果保留，devkit 提供接口、版本、声明和样例事实；
机制、算子实践和故障经验可由原知识库补证。两种来源的排序分数和审计证据不能混用。
查询只读，资源准备/插件同步是独立前置阶段，不修改知识卡、SDK 或业务代码。
