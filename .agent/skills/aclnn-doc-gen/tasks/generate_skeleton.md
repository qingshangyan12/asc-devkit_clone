# aclnn 算子 API 参考手册骨架生成任务

## 任务目标

为指定的算子生成不含公式正文、函数原型正文、第二段执行接口固定章节的 aclnn API 技术参考手册骨架，输出 `4_generate_skeleton.md`。文档骨架必须严格遵循昇腾社区文档模板结构和格式要求；公式正文由外部程序在最后从 `3_formula.md` 拼入，函数原型正文由外部程序在最后从 `0_prototype.md` 拼入，第二段执行接口固定章节由外部程序按目标接口名拼入。

## 输入输出约定

### 输入

读取以下阶段产出文件：
1. `{算子目录}/outputs/{目标接口名}/1_extract.md` — 算子信息提取报告（含产品支持情况、芯片差异分析和 `## 文档生成语义基准`）
2. `{算子目录}/outputs/{目标接口名}/2_compare.md` — 接口差异分析报告（如存在）
3. `{算子目录}/outputs/{目标接口名}/0_prototype.md` — 函数原型，只用于参数表、接口章节和返回值与真实原型对齐；本阶段不得输出原型正文

不得读取 `3_formula.md` 作为本阶段生成依据；不得在本阶段推导、改写或补写公式。

本阶段禁止读取源码或主动探索算子目录（包括 op_api/、op_host/、op_kernel/）。所有可生成结论必须来自 `1_extract.md`、`2_compare.md`、`0_prototype.md` 和参考配置；若这些阶段产物信息不足，不得回源码补充，应保守使用 `<span style="color:#dc2626;">【需用户补齐】</span>` 或在失败文件中说明上游提取不足。

### 输出

生成文档骨架写入：`{算子目录}/outputs/{目标接口名}/4_generate_skeleton.md`

## 核心要求

### 1. 静态算子名称与目标接口名

- 算子名称固定为系统提取的 `{static_aclnn_operator_name}`
- 目标接口名固定为 `{static_aclnn_target_api_name}`

- 禁止根据 `REG_OP(...)`、提取报告正文、目录名等重新提取算子名称

### 2. 信息来源

所有内容必须从 `1_extract.md`、`2_compare.md` 与 `0_prototype.md` 中提取，禁止臆测。本阶段禁止读取源码、禁止重新分析代码上下文；本任务中的示例仅用于说明格式和结构，禁止照搬示例中的算子名、参数名、数据类型等。

### 3. 前后自洽

- 参数说明中的变量描述必须与 `1_extract.md` 的 `## 文档生成语义基准` 严格对应；公式正文由外部合成阶段拼入
- 功能说明、参数说明、约束说明之间不能出现前后矛盾

### 4. 骨架阶段覆盖规则（强制）

- 本阶段只生成正文骨架，不生成公式正文、函数原型正文，也不生成第二段执行接口固定章节。
- 本阶段禁止读取 `3_formula.md`，禁止重新推导、改写、合并、重排或补写公式语义内容。
- `## 功能说明` 的 `- 计算公式：` 条目必须保留，但正文只能输出占位符 `{{ACLNN_FORMULA_BLOCK_PLACEHOLDER}}`。
- `## 函数原型` 章节必须保留，但正文只能输出占位符 `{{ACLNN_PROTOTYPE_BLOCK_PLACEHOLDER}}`。`## aclnn{OperatorName}` 第二段执行接口章节不得由模型生成，必须只输出占位符 `{{ACLNN_EXECUTE_INTERFACE_BLOCK_PLACEHOLDER}}`。
- 参数说明表“描述”列必须使用 `1_extract.md` 的 `## 文档生成语义基准` 中的参数描述和公式变量映射建议。
- 若本文件后续规则与本节冲突，以本节为准。
- 本阶段输出的是对外文档骨架，严禁输出 `## 代码分析清单`、源码路径、分析原因、证据摘要、内部文件名或任何分析痕迹。

- 空指针参数例外：若该参数符合“仅支持空指针”特殊规则，本列必须填写 `-`。

### 返回值行规则（强制）

- 返回值表只允许出现以下 4 个错误码，数值优先读取 `config/error_codes.yml`：
  - `ACLNN_ERR_PARAM_NULLPTR` / `161001`
  - `ACLNN_ERR_PARAM_INVALID` / `161002`
  - `ACLNN_ERR_INNER_INFERSHAPE_ERROR` / `561001`
  - `ACLNN_ERR_INNER_TILING_ERROR` / `561002`
- `ACLNN_ERR_PARAM_NULLPTR` 描述固定为 `传入的xx参数是空指针。`，`xx` 必须替换为真实参数名；多个参数用顿号连接，最后一个参数前用“或”。
- `ACLNN_ERR_PARAM_INVALID` 描述只能使用以下三种句式之一：`xx参数的dtype属性不在支持的范围内。`、`xx参数的format属性不在支持的范围内。`、`xx参数的shape属性不满足上述要求。` 或 `xx参数的取值或取值范围不满足上述要求。`
- `ACLNN_ERR_INNER_INFERSHAPE_ERROR` 描述固定为 `内部异常：API内部进行输出shape推导发生错误。`
- `ACLNN_ERR_INNER_TILING_ERROR` 描述固定为 `内部异常：API内部进行tiling计算发生错误。`
- 同类行合并规则（强制）：同一错误码下，句式相同、仅参数名不同的多行必须合并为一行，用顿号连接参数名。禁止逐参数拆行。例如：
  - `161001`：若 x、weight、out、workspaceSize、executor 都可能触发空指针错误，合并为一行：`传入的x、weight、out、workspaceSize或executor参数是空指针。`
  - `161002`：若 x、weight、out 的 dtype 都可能不在范围内，合并为一行：`x、weight或out参数的dtype属性不在支持的范围内。`；同理 format、shape 各合并一行
  - 合并后不同句式的行仍然分行（如 dtype 一行、format 一行、shape 一行、取值范围一行）
- 返回值章节严禁出现芯片、产品、场景差异描述；差异只写入 `## 约束说明`。

## 约束说明

**审阅提示**：在 `## 约束说明` 标题的紧下方（约束内容之前），必须插入一行独立的橙色审阅提示：`<span style="color:#d97706;">【需用户确认】</span>`。该提示仅出现一次，**不得**出现在约束说明内部的任何其他位置。

**基本原则：**
- 参数说明表格中使用说明列已写的单参数约束不要重复
- 对于算子原生语义就存在的约束（竞品也存在）一律不写
- 若无约束填写"无"，不允许空章节
- 参数说明表格中的数据类型/格式/shape/非连续支持必须写并集结果，芯片或产品差异不得出现在表格中

**【强制】产品支持情况决定约束说明内容**：
- 在产品支持情况中标记为 `×` 的产品，**不得**在约束说明中出现任何约束内容
- 只有在产品支持情况中标记为 `√` 的产品，才会在约束说明中按产品分组显示约束
- 约束说明中的产品分组必须与产品支持情况表格中 `√` 的产品严格对应

**确定性计算说明**（**必须包含，不可省略**，固定占位）：必须作为约束说明章节的第一条出现，该条内容必须严格输出为：`确定性说明：<span style="color:#dc2626;">【需用户补齐】</span>`

**层级结构**（按需添加）：

确定性计算说明之后，约束说明按以下四层层级组织，**第2、3层使用 `<details>`/`<summary>` 标签折叠展示**：

**`<details>`/`<summary>` 格式硬性要求：**
1. 第2层（产品区分）的 `<details>` 标签必须**顶格书写**
2. 第3层（场景区分）的 `<details>` 标签必须**缩进两格**（2个空格）
3. `</summary>` 结束标签之后必须紧跟一个**空行**
4. `</details>` 结束标签之前必须有一个**空行**

**第1层：跨产品公共约束**（所有产品通用，直接以无序列表写在确定性说明之后，不使用折叠标签）
- 若不存在，则**整层直接省略**，禁止输出任何说明性占位文本

**第2层：区分产品型号**（每个产品或产品组一个 `<details>` 块）
- 块内先写 `- **公共约束**`（该产品组内跨场景通用约束），并加锚点 `<a id="公共约束"></a>`
- 若不存在跨场景公共约束，则禁止输出 `- **公共约束**` 标题、锚点

**第3层：区分场景/模式**（产品块内按计算场景细分）
- **场景来源（强制）**：**必须直接读取 `1_extract.md` 中"按产品/场景区分的约束"章节**，以其中列出的场景作为第3层 `<details>` 块的唯一依据，不得在构造子任务 prompt 时将场景内容预先归纳、平铺或改写——子任务必须被明确要求直接读取 `1_extract.md` 原文中的场景划分。若 `1_extract.md` 的"按产品/场景区分的约束"章节为空或不存在，则整个第3层省略。

**第4层：场景内的复杂约束**
- 先写 `- **数据类型要求**`，采用 Markdown 表格的形式。表格列覆盖该场景下有差异的关键参数（如主要输入输出及相关量化参数），列选取依据场景特征决定
- 再写 `- **约束说明**`；若存在公共约束锚点，使用固定引用："除[公共约束](#公共约束)外，xxx场景其余约束如下："
- 场景约束的全部内容**直接来自 `1_extract.md` 对应场景节**，不得重新分析代码；若 `1_extract.md` 中某场景的约束信息不足，不得补充读取代码，应保守标注 `<span style="color:#dc2626;">【需用户补齐】</span>` 或省略无法确认的场景增量约束
- 场景约束说明必须按以下6个维度组织（有则写，无则省略）：
  - **空Tensor支持关联**：本场景中哪些参数允许/禁止传空Tensor，以及与其他参数的联动关系
  - **dtype组合约束**：本场景支持的数据类型组合及跨参数一一对应关系
  - **format组合约束**：本场景支持的数据格式及其组合限制
  - **shape关联约束**：参数 shape 公式、维度数限制、TensorList 长度限制、对齐整除要求
  - **非连续性关联**：哪些参数支持/不支持非连续Tensor，以及非连续条件触发的限制
  - **取值关联约束**：枚举参数在本场景的合法取值及跨参数取值联动
- 在上述6个维度之外，还可补充：

  - **转置约束**：哪些参数支持/禁止/要求转置

**文件路径**：`{算子目录}/outputs/{目标接口名}/4_generate_skeleton_FAILED.md`

- `0_prototype.md` 缺失、为空或无法确认目标接口的两段式函数原型
