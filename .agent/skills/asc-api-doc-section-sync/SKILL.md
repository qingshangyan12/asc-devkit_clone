# AscendC API文档章节同步

将源文档的指定二级章节同步到正式API文档，默认处理“功能说明”“函数原型”“参数说明”。“约束说明”必须由用户显式指定，并按语义映射流程处理。只修改明确指定的章节或目录范围，并验证接口事实、目录归属和链接完整性。

## 输入

执行前解析以下信息：

- asc-devkit仓库根目录。
- 源Markdown文档路径。
- 正式API文档路径。若用户给出的旧路径不存在，按文件名在`docs/zh/api`中搜索当前位置；仅允许唯一匹配。
- 待替换章节。未指定时使用“功能说明”“函数原型”“参数说明”。
- 同步“约束说明”时，确认作为基准的API族、目标C API目录和产品/架构范围。用户重复给出同一路径时按一个目录处理，不擅自扩展到名称相近但未指定的API族。

先读取源文件、目标文件和`git status --short`。保留工作区已有修改，不覆盖用户在目标章节之外的变更。

## 同步流程

1. 对照当前仓库的公开声明、实现和相关样例，确认源文档中的函数名、重载、参数类型和参数含义仍然有效。发现冲突时停止替换并报告证据，不以需求稿覆盖当前接口事实。
2. 预览章节替换：

   ```bash
   python3 .agent/skills/asc-api-doc-section-sync/scripts/sync_sections.py \
     --source <源文档> \
     --target <正式文档>
   ```

3. 检查预览差异仅覆盖指定章节。默认不得修改“产品支持情况”“数据类型”“返回值说明”“流水类型”“约束说明”和“调用示例”；用户显式指定“约束说明”时除外。
4. 执行替换：

   ```bash
   python3 .agent/skills/asc-api-doc-section-sync/scripts/sync_sections.py \
     --source <源文档> \
     --target <正式文档> \
     --write
   ```

5. 只替换部分章节时，显式传入章节名：

   ```bash
   python3 .agent/skills/asc-api-doc-section-sync/scripts/sync_sections.py \
     --source <源文档> \
     --target <正式文档> \
     --sections 功能说明 参数说明 \
     --write
   ```

脚本按Markdown二级标题边界解析章节，并忽略代码块中的伪标题。源文件或目标文件缺少章节、章节重复、三个默认章节顺序错误、目标为软链接时必须失败，不得降级为字符串替换。

## 约束说明同步

“约束说明”通常不是一对一复制。一个Basic API可能对应多个C API入口，同一个C API也可能承载连续、2D、3D或带转换的多个模式。先完成语义映射，再编辑目标文档。

1. 按功能、数据通路、源/目的存储位置、模式、参数结构和产品支持建立`Basic API -> C API文档 -> C API声明/实现`映射。不得仅凭文件名相似建立对应关系。
2. 以指定Basic API文档的公开行为为描述基准，以当前仓库的C API声明和目标架构实现确认C API入口、参数名、位域和接口拆分。Basic API与代码冲突时停止并报告，不自行选择一方；Basic API没有直接C API入口时不猜测对应关系。
3. 逐项核对并同步以下约束：
   - 源、目的地址对齐和存储空间要求。
   - 0值语义、NOP（空操作）行为及参数范围。
   - 地址重叠、写入顺序和流水同步要求。
   - 数据通路、转置、稀疏、padding、repeat及步长约束。
   - 配套setter的调用顺序、作用范围和默认值。
   - 产品差异、支持的数据类型和模式限制。
4. Basic API使用结构体参数而C API使用独立参数或寄存器字段时，按语义转换为C API参数名，不直接复制Basic API参数名、类型或范围。C API特有的字段截断等约束仅在声明或实现能够确认时保留。
5. C API将普通搬运、转置搬运或不同Feature Map配置拆为独立入口时，约束必须写入对应入口。例如普通2D入口不能描述为执行转置；3D到L0B Buffer的自动转置要求应只写入对应3D模式。
6. Basic API明确0值为NOP时，C API文档同步描述为“不执行搬运，本接口被视为NOP（空操作）”，不得改写为报错或异常。Basic API的约束为“无”且代码没有额外公开约束时，目标章节写“无”，删除推导出的位域后果。

多源文档需要合并到多个目标文档，或约束需要按C API入口重写时，不使用`sync_sections.py`强行复制；使用`apply_patch`进行受控编辑。只有源、目标“约束说明”能够一对一替换时，才执行：

```bash
python3 .agent/skills/asc-api-doc-section-sync/scripts/sync_sections.py \
  --source <源文档> \
  --target <正式文档> \
  --sections 约束说明 \
  --write
```

### 约束措辞

- 将“按位宽截断处理”统一改为“截断处理”。不要删除后续实际生效值、数据缺失或地址错位等有效结果说明。
- 删除“硬件不报错”及“不报告告警和错误”“不返回警告或错误”“不会产生警告或错误”“不触发异常码”等同义描述。保留“数据可能不完整”等有效行为，并修复删除后的标点和语句衔接。
- 目的地址重叠的同步约束统一写为“如果本指令与其他指令存在目的地址重叠，需要插入同步指令（[asc_sync_notify](相对路径)和[asc_sync_wait](相对路径)），保证多个指令串行化，防止出现异常数据。”两个接口必须链接到`c_api/sync`目录下的正式文档，并按目标文档层级换算相对路径：`cube_data_move`顶层文档通常使用`../sync/asc_sync_notify.md`和`../sync/asc_sync_wait.md`，架构子目录文档通常使用`../../sync/asc_sync_notify.md`和`../../sync/asc_sync_wait.md`。删除“如果需要执行多条本接口指令”以及“目的地址存在重叠时不保证重叠数据的写入顺序”“重叠写入时不保证写入顺序”等附加描述。
- 存储位置的地址对齐描述不使用“端口”。例如将“L1 Buffer端口对齐要求”“Global Memory端口对齐要求”分别写为“L1 Buffer对齐要求”“Global Memory对齐要求”；L0A Buffer、L0B Buffer、L0C Buffer、Unified Buffer（或UB）、GM、BiasTable Buffer、Fixpipe Buffer、L0B MX等同类描述按此处理。
- C API搬运或L2 Cache能力描述中，存储在Global Memory中的数据统一写为“GM的数据”，不写“Global Tensor的数据”或“GlobalTensor的数据”。不要机械替换Basic API中的`GlobalTensor`类名、类型名、接口名及其对象语义。
- 将“否则搬运异常”统一改为“否则会导致搬运异常”，使条件和结果之间的因果关系完整。
- 连续的已定义模式使用闭区间描述。例如写为“pad_func_mode取值范围为[0, 8]，未定义值会导致结果异常”，不再枚举未定义值或描述具体硬件异常类型。
- 不单独创建“字段截断约束”或“字段位宽截断约束”三级标题。将每条截断约束按参数语义并入“通用约束”、对应模式约束或对应参数约束；例如n_size并入“n_size组合约束”，量化字段并入“随路量化激活参数约束”。
- 同一参数的有效范围和截断结果存在重复时合并为一条。对于dtype决定上限的padding参数，写明`left_padding_count`和`right_padding_count`在各dtype下的取值范围，并统一说明“超出取值范围会导致搬运填充结果不符合预期”；删除字段位宽、截断示例、旧数据残留等重复展开。
- n_burst、len_burst、src_stride、dst_stride、m_step、k_step及其派生stride参数的超范围截断约束写为“参数名取值范围为[下限, 上限]，超出取值范围的值会被截断，导致搬运结果不符合预期”。取值范围必须依据用户指定值、Basic API公开范围及C API声明/实现确定，不得直接用位域宽度推导。删除截断示例、实际生效值、部分数据未搬运和截断后NOP等展开描述；参数为0时的NOP或异常行为作为独立约束保留。
- l2_cache_ctl等离散模式参数只保留合法枚举集合，写为“参数名支持值列表，未定义值会导致结果异常”。若参数表已完整列出合法模式，约束说明无需重复。删除“l2_cache_ctl取值范围为[0, 15]，超出取值范围的值会被截断”等字段范围描述；产品支持差异紧随合法枚举说明保留。
- 若“数据类型”章节已完整说明dtype支持范围，约束说明不再重复罗列任何dtype列表，包括按1字节、2字节、4字节分类或列举`void`、`bfloat16_t`、`half`等具体类型；也不补充“不支持8字节类型”“其他取值触发指令未定义异常”等推导描述。
- 处理保留字段时直接描述“传入非0值不生效”或“行为未定义”，不补充无依据的报错行为。
- 术语替换可在用户指定的整个目标子树内统一执行；Basic API语义合并只修改已建立对应关系的C API文档，不扩展到无对应关系的store方向或相邻API族。

## 目录迁移

章节同步本身不改变文档路径。若工作区已将目标文档迁移到其他分类目录：

1. 修改当前位置的文档，不恢复旧路径，也不自行创建兼容软链接。
2. 从旧分类索引移除条目，并加入新分类索引。例如检查：
   - `cube_data_move/cube_data_move.md`
   - `vector_data_move/vector_data_move.md`
   - `sys_var/system_variables.md`
3. 同步`docs/zh/api/SIMD-API/c_api/c_api.md`和`docs/zh/api/README.md`。
4. 用`rg`确认接口在分类索引中只出现一次，且不存在旧路径残留。

## 文档规范

- 同时使用仓库内`doc-checker`技能检查正式文档；不要在本技能中复制其完整规则。
- 保持二级章节顺序、代码块语言、表格语法、NPU标签、术语和中英文标点符合仓库规范。
- 功能说明、参数说明、约束说明及表格正文中的接口参数名、结构体字段名和代码字面量使用行内代码格式，包括参数表首列以及`true`、`false`、`nullptr`等字面量。只包裹标识符或字面量本身，不把比较运算符、数值和中文标点放入同一代码span；例如写为“`smallc0_en`传入`true`时`d_value`必须≤4”，不写“smallc0_en传入true时d_value必须≤4”或“`d_value ≤ 4`”。函数原型、调用示例等代码块已处于代码上下文，不重复添加反引号。
- 参数说明中的地址类操作数统一写为“目的操作数，存储位置为<存储单元>。目的地址需<要求>对齐。”和“源操作数，存储位置为<存储单元>。源地址需<要求>对齐。”；没有已确认对齐要求时省略第二句。存储位置必须由公开原型的地址空间限定符、实现或现有有效描述确认，使用GM、L1 Buffer、L0A Buffer、L0B Buffer、L0C Buffer、UB、L0A MX Buffer、L0B MX Buffer等规范术语，不写“目的/源缓冲（...）的起始地址”“目的/源地址（...）的起始地址”“目的/源操作数在...的起始地址”或“目的/源操作数（矢量）的起始地址”。数据类型关系已由函数原型和数据类型章节覆盖时，删除“dtype由重载决定”“dtype与dst一致”等重复说明；保留固定数据类型、随模式或数据类型变化的对齐、矩阵角色、容量限制和特殊寻址规则。
- 取值范围的下限已大于0时，不再追加“不可为0”或“不能为0”等重复描述。例如写为“取值范围[1, 2^17-1]。”，不写“取值范围[1, 2^17-1]，不可为0。”。若0在所列范围内但被明确禁止，保留0值限制；若0具有NOP、按默认值处理等实际行为，将该行为写成范围后的独立句，不通过“不可为0（……）”承载。
- 参数表和字段表的单元格存在多个分项时，将每个分项单独换行并以`<br>&nbsp;&nbsp;&bull;`开头；普通条件分支、重载差异和补充说明等非枚举分项也使用相同的换行与项目符号格式。
- 不使用裸`•`、`<br>•`、`<br>&bull;`、`<br/>`、`<br>-`以及不带项目符号的`<br>true:`、`<br>0：`等变体。保留分项原有语义，不把普通说明文字误识别为枚举值。
- 介绍枚举值时，先用完整句子说明参数作用。代码、声明或基准文档明确给出默认值时，紧接着写“默认值为`枚举值`。”；没有依据时不得补写默认值。
- 在项目符号后依次写行内代码格式的枚举值、中文冒号和说明。布尔值、单个数值、数值组合或范围、非0值及带参数名的模式均按此处理，例如`true`、`0`、`2/3`、`5~7`、`非0`、`rpt_mode=0`；不要只处理`true`和`false`。
- 保持引导说明句末的句号或冒号。多个分项之间，除最后一项使用句号外，其余项使用分号。例如：“是否开启某功能。默认值为`true`。<br>&nbsp;&nbsp;&bull; `true`：开启该功能；<br>&nbsp;&nbsp;&bull; `false`：关闭该功能。”
- 用户要求全局排查时，扫描指定目标目录的全部Markdown文件，不得只修改用户举例的接口；同时搜索项目符号、HTML换行、短横线列表、无项目符号枚举和英文冒号等旧格式变体。
- 矩阵排布术语统一写为“Nz矩阵”和“Nz格式”，不写“NZ矩阵”或“NZ格式”。只修改自然语言术语和Markdown链接显示文本；保留接口名、函数名、参数名、代码标识符以及`ND2NZ`、`DN2NZ`、`NZ2ND`、`NZ2DN`等转换模式名中的大写`NZ`。
- 数据类型名称必须与当前公开声明和实现中的写法一致。并列类型按以下固定顺序排列：`bool`、`int4b_t`、`int8_t`、`uint8_t`、`fp4x2_e2m1_t`、`fp4x2_e1m2_t`、`hifloat8_t`、`fp8_e8m0_t`、`fp8_e5m2_t`、`fp8_e4m3fn_t`、`int16_t`、`uint16_t`、`half`、`bfloat16_t`、`int32_t`、`uint32_t`、`float`、`complex32`、`int64_t`、`uint64_t`、`double`、`complex64`。多个类型使用中文顿号分隔。
- src/dst等有方向的类型组合先按src类型顺序排列分支，再按固定顺序排列每个dst类型集合；保留类型转换方向，不为排序改变转换语义。`void`等固定序列之外的特殊实际类型放在序列内类型之后。
- 约束仅由位宽决定，且对该位宽下接口支持的全部类型一致生效、没有具体重载、类型转换、产品或模式例外时，按`b8`、`b16`、`b32`、`b64`表达并按位宽递增排列。存在任一例外时列出实际C类型，不得用位宽表达掩盖差异。
- 不为满足类型顺序改变函数参数顺序、公开重载签名或典型示例的类型语义；仅整理函数原型之间的展示顺序和正文中的并列类型集合。
- 替换“函数原型”时按下述“函数原型占位符”规则合并仅数据类型不同的重载；替换“参数说明”时确保所有原型参数都有说明，且没有无对应原型的遗留参数。
- 修改“约束说明”时检查同一文档内不同模式之间是否矛盾或重复，并确保参数名、配套接口链接与当前C API声明一致。
- 功能说明、参数说明和约束说明等正文中提到配套setter、同步接口或其他API，且接口名能够唯一映射到仓内正式文档时，使用接口名作为链接文本并添加相对文档链接，不仅使用行内代码或普通文本。当前文档自身的接口名不添加自链接；函数原型、调用示例及其他代码块中的接口名保持代码格式，不添加Markdown链接；结构体和参数类型不按接口规则处理。
- 多架构接口引用指向该接口的入口文档，不直接链接某个`_arch_xxx.md`实现页。链接路径必须从当前文档位置计算：同目录接口使用文件名，架构子目录引用`cube_data_move`顶层接口通常使用`../接口名.md`，跨分类接口按实际层级换算。不得仅凭接口名前缀猜测路径，写入前确认目标文件存在。
- 每篇包含“约束说明”的搬运指令文档均在该章节开头添加“- 各存储单元的空间大小和对齐要求请参考[存储单元说明](相对路径#存储单元说明)。”。仅检查实际指令文档，不要求无“约束说明”的多架构入口索引重复添加。相对路径必须按文档层级计算：`cube_data_move`顶层文档通常使用`../general_description_and_constraints.md`，架构子目录文档通常使用`../../general_description_and_constraints.md`。
- “约束说明”存在“通用约束”三级标题时，将其作为本章节第一个三级标题，放在填充、搬运、计算等接口能力约束之前；二级标题后的公共参考链接或总述可保留在该标题之前。
- 模式约束三级标题的名称和顺序必须与“参数说明”中的模式参数三级标题一一对应。例如“填充模式参数”“2D搬运模式参数”对应“填充模式约束”“2D搬运模式约束”。将参数说明中不存在的模式约束合并到实际对应模式，不保留无对应关系的独立标题。
- 检查被替换章节中的相对链接和锚点。源文档相对路径不能未经换算直接带入目标目录。

### 函数原型占位符

1. 编辑前扫描目标目录和当前公开声明，建立重载矩阵。每条记录至少包含函数名、非dtype参数列表、src/dst/value dtype、普通或同步、是否转置及所属功能模式。不得只依据来源文档列出的重载确定范围。
2. 仅合并函数名、非dtype参数列表、参数语义和功能模式相同，且仅数据类型不同的重载。以下任一项不同时必须保留为独立模板或模式：
   - 函数名，包括普通接口、`_sync`接口和transpose接口。
   - 参数个数、顺序、名称、类型或地址空间限定符。
   - 2D、3D、连续搬运、高维切分、分形搬运、通用搬运等功能语义。
3. 固定类型接口保留实际类型，使用“固定类型原型”而非伪造占位符；仍需补充“dtype支持的数据类型”和“典型示例”。`void`是实际声明的数据类型，不表示任意类型：只有与其他类型重载共用同一签名形态时才能纳入`<dtype>`列表，单独的`void*`签名保持固定类型原型。
4. src与dst的数据类型必须一致时，两者统一使用`<dtype>`；支持类型转换时分别使用`<src_dtype>`和`<dst_dtype>`。填充值等其他参数类型独立变化时，使用`<value_dtype>`等能够体现参数语义的占位符。
5. src与dst类型不一致时，按重载矩阵逐项列出合法的`src_dtype -> dst_dtype`组合；不得只分别列出src、dst类型集合，也不得据此推导笛卡尔积。value dtype等多类型参数采用相同规则。
6. 同一功能模式的普通接口与同步接口签名形态、类型集合完全相同时，可以在一个模板代码块和一组类型说明中并列展示。同步接口只支持部分类型或参数列表不同时，必须拆分说明，不得沿用普通接口的完整类型集合。
7. 单一签名族依次使用“模板原型（占位符形式）”“dtype支持的数据类型”“典型示例”三级标题。存在多种参数列表或功能模式时，先以三级标题区分模式，再在每个模式下按相同顺序使用四级标题；模式名称和顺序应与“参数说明”对应。固定类型原型不使用“模板原型（占位符形式）”标题。
8. “模板原型（占位符形式）”和“典型示例”代码块中的每个函数声明均将首个参数紧跟左括号，后续参数各占一行并与首个参数的起始列对齐；末个参数后紧跟右括号。普通、`_sync`、transpose及各功能模式全部执行相同格式。无参数或单参数声明保持单行。只调整换行和缩进，不改变函数名、参数类型、名称、顺序、占位符或示例的具体数据类型。例如：

   ```cpp
   __aicore__ inline void api(__cbuf__ <dtype>* dst,
                              __gm__ <dtype>* src,
                              uint32_t count)
   ```

9. 每个模板或固定类型模式均需列出支持类型并至少给出一个当前代码中实际存在的具体重载示例。代码块统一使用`cpp`；dtype列表及组合按`doc-checker`规定的类型顺序排列，多个类型使用中文顿号。
10. 典型示例必须将所有占位符替换为一组合法具体类型，并完整保留对应模板的函数名、地址空间限定符、参数顺序和参数类型；示例注释说明具体类型和模式，不得改写成缺少参数的调用片段。示例函数声明按第8条逐参数换行并对齐。
11. 以当前公开声明、实现和修改前正式文档中的有效重载交叉确认类型集合。来源草稿遗漏`_sync`、transpose或其他模式，包含无声明类型，或将固定类型写成通配类型时，不采用冲突内容。

完成编辑后执行以下语义核对：

- 按函数名和非dtype参数列表归一化修改前后的原型，确认每个原有签名形态都被一个模板或固定类型原型覆盖。
- 将每个典型示例按空白归一化后与公开声明或修改前的有效具体重载比对，必须能够唯一匹配。
- 人工核对每个“模板原型（占位符形式）”后均存在对应的“dtype支持的数据类型”和“典型示例”，多模式文档不得跨模式共用类型集合。
