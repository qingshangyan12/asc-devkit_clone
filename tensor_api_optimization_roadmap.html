核心诊断 reg_compute 的问题不是「函数不够多」，而是缺少稳定的抽象边界——函数太多、语义太散、配置太乱、文档太少。

1reg_compute API 问题分析（开发者视角）

1.1 零文档 + 声明与实现脱节

22 个 intf 文件的 \brief 几乎全部为空。更糟的是：测试用的名字和 intf 声明的名字不一致。

intf 声明

// kernel_reg_compute_datacopy_intf.h
LoadAlign(dstReg, srcAddr);
StoreAlign(dstAddr, srcReg, mask);

测试实际调用

// test_operator_reg_compute_binary.cpp
Reg::DataCopy(vSrcReg0, src0Ptr + ...);
Reg::DataCopy(dst + ..., vreg0, preg);

DataCopy 只出现在 impl，intf 未声明 → IDE 补全/文档/新人上手全错位。

类似地，Exp/Div/Sqrt 的 auto mode 在 impl 中可接受 const ExpSpecificMode*，但 intf 完全没有声明。

1.2 模板参数风格严重不统一

同一层 API 至少存在 4 种 mode 表达方式，无法形成肌肉记忆：

算子mode 写法文件
Add/Sub/MulMaskMergeMode modebinary_intf
Div/Exp/Sqrt/Ln/Log*auto mode（可扩成 SpecificMode*）binary/unary_intf
Castconst CastTrait& traitvconv_intf
ReduceReduceType + MaskMergeMode 顺序不一reduce_intf
 
// 同文件内就不一致 —— kernel_reg_compute_vec_binary_intf.h
template <typename T = DefaultType, MaskMergeMode mode = MaskMergeMode::ZEROING, typename U>
void Add(U& dst, U& s0, U& s1, MaskReg& mask);

template <typename T = DefaultType, auto mode = MaskMergeMode::ZEROING, typename U>
void Div(U& dst, U& s0, U& s1, MaskReg& mask);

T = DefaultType 占位符遍布全局；auto mode 让编译错误变成深层 SFINAE。

1.3 默认值语义相反

大多数计算算子默认 MaskMergeMode::ZEROING，但 Move 默认却是 MERGING：

// kernel_reg_compute_copy_intf.h
template <..., MaskMergeMode mode = MaskMergeMode::MERGING, ...>
void Move(U& dst, U& src, MaskReg mask);

习惯 Add 的开发者对 Move 不写 mode，会得到完全不同的 mask 语义，且无任何注释提示。

1.4 mask 传参不一致

APImask 传递
Add/Sub/Mul...MaskReg& mask（引用）
Reduce/ReduceDataBlockMaskReg mask（值传递）
MoveMaskReg mask（值传递）

UpdateMask(uint32_t& scalarValue) 还会原地消耗标量计数——尾块循环顺序写错就 silently 错。

1.5 扁平命名空间 + 同名重载地狱

所有能力堆在 AscendC::Reg:: 一个平面下，大量函数同名但含义完全不同：

名字出现位置含义
Addbinary_intf向量加法 / 带 carry 加法（首参不同）
Addsbinary_scalar_intf向量 + 标量
And/Or/Xor/Notbinary_intf + maskreg_intf向量位运算 vs mask 位运算
Movecopy_intf + maskreg_intf向量搬运 vs mask 搬运
Selectcmpsel_intf + maskreg_intf向量选择 vs mask 选择
Gatherdatacopy_intf + gather_mask_intfUB 基址 gather vs 寄存器 gather
Interleave/Packduplicate/pack + maskreg_intf向量 vs mask 操作

1.6 RegTensor 抽象泄漏

template <typename T, const RegTrait& regTrait = RegTraitNumOne>
struct RegTensor {
    RegType reg[trait.REG_NUM];
    operator RegType&() { return reg[0]; }  // 仅单寄存器
};
  • 双寄存器（REG_NUM=2，如 Mull、B64）必须手动 reg[0]/reg[1]
  • ActualT vs RegType（TypeGet<T>::T）两层类型，混合精度/复数时需同时理解
  • 非支持架构上 RegType = int——编译能过但语义完全错误，没有 #error

1.7 DataCopy 接口爆炸

kernel_reg_compute_datacopy_intf.h 单文件 20+ 重载，涉及 LoadDist（20+ 值）、StoreDist、PostLiteral、AddrReg、非对齐 UnalignReg 状态机、mask 专用 load/store……

  • StoreDist 末尾有重复的 DIST_NORM
  • MaskDist::DIST_PACK = 1 与 DIST_US 同值
  • 没有决策树文档：开发者必须知道「数据排布 → dist → postUpdate → AddrReg」

1.8 架构可移植性碎片

  • struct 层支持 2103/3103/3113/3510/5102…
  • 绝大多数算子 impl 只在 3510 || 5102 || 3003 || 3113 时 include
  • ExpSpecificMode 在 3510 有 algo 字段，其他架构只有 precisionMode
  • 不支持组合常静默空操作，而非 intf 层提前拒绝

1.9 MERGING/ZEROING 语义陷阱

  • intf 暴露 MaskMergeMode，但 impl 大量算子 static_assert 只支持 ZEROING（如 Abs、Exp）
  • 支持 MERGING 的算子走「先算临时寄存器再 CopyMerging」——性能与行为都不同，intf 无说明
  • Move 默认 MERGING 与计算算子默认 ZEROING 形成对比陷阱

1.10 配置/枚举设计粗糙

struct CastTrait {
    RegLayout layoutMode = RegLayout::UNKNOWN;
    SatMode satMode = SatMode::UNKNOWN;
    MaskMergeMode mrgMode = MaskMergeMode::UNKNOWN;
    RoundMode roundMode = RoundMode::UNKNOWN;
};

四字段全是 UNKNOWN 默认值；Histograms 的 mode/type 是无默认值的 template 非类型参数，调用极不友好。

1.11 头文件 metadata 瑕疵

  • gather_mask_intf.h 末尾 #endif 注释写成 COPY_INTERFACE
  • fused_intf.h 文件头注释写的是 vec_fused_impl.h
  • unary guard 名 VEC_SINGLE_INTERFACE（历史遗留）
  • 标 internal 却是算子开发主入口（经 kernel_operator_intf.h）

1.12 缺少高层辅助 — 样板代码重复

每次向量循环的标准套路（来自官方测试）：

uint32_t sreg = (uint32_t)mask;
Reg::MaskReg maskReg = Reg::UpdateMask<T>(sreg);
for (i = 0; i < rep; i++) {
    Reg::DataCopy(vSrc, srcPtr + i * one_rep_size);
    Reg::Add(vDst, vSrc0, vSrc1, maskReg);
    Reg::DataCopy(dstPtr + ..., vDst, maskReg);
}

API 不提供 loop/tile 辅助——repeat、one_rep_size、UpdateMask 递减全部手写。

2TensorAPI 总原则：三层分离，一条调用形状

algorithm
动词：Copy / Mmad / Compute / Transform  +  工厂：MakeCopy / MakeVec / MakeMmad
▼
atom
XxxAtom + XxxTraits + Trait 结构体（配置 + arity 校验 + 分派）
▼
arch
算子标签：CopyGM2UB / vec::Add / MmadOperation（纯类型，无逻辑）
优化目标 开发者永远只记 动词(atom, 操作数…)，配置进 Trait，算子多样性进标签目录——不再面对 100+ 个风格各异的自由函数。

已在 Copy/Mmad 验证；寄存器级 Compute/MakeVec 是同一套路的延伸。

3十条优化路线

3.1 统一「动词表」——消灭同名重载地狱

reg_computeTensorAPI
Reg::Add / Adds / Add(carry,...)Compute(MakeVec(vec::Add{}), …)；标量 vec::Adds；进位 vec::AddC
LoadAlign + 隐藏 DataCopy统一 Copy(MakeCopy(copy::LoadUb{}), …)
Move（向量）vs mask MoveCopy(MakeCopy(reg::Move{}), …) vs mask::Move
两种 Gathercopy::GatherFromUb vs reg::Gather——标签区分，动词统一

关键规则：算法层动词 ≤ 10 个；语义糖由单宏生成；禁止 intf 不声明、impl 偷偷提供的影子 API。

3.2 Trait 收敛配置——消灭 4 套 template 参数风格

struct VecTrait {
    MaskMergeMode mrg = MaskMergeMode::ZEROING;  // 全局统一默认
    ExpAlgo algo = ExpAlgo::INTRINSIC;            // 替代 auto mode + SpecificMode*
};
struct CastTrait {
    RoundMode round = RoundMode::CAST_RINT;
    SatMode sat = SatMode::NO_SAT;
    MaskMergeMode mrg = MaskMergeMode::ZEROING;
    RegLayout layout = RegLayout::ZERO;
};
  • 禁止 auto mode 接受指针/枚举双形态
  • 所有 mrg 默认一律 ZEROING；MERGING 必须显式
  • 废弃 DefaultType 占位符，dtype 从操作数推导
  • Trait 用 wrapper 携带 constexpr 值（Copy 已有 CopyGM2UBTraitDefault{ value } 模式）

3.3 集中 Op 目录 + 一行注册

// arch/vector/vec_op.h — 纯标签
namespace vec { struct Add; struct Abs; }

// impl — 一行接线
ASCENDC_TE_REGISTER_VEC_OP(Add, Add, 2);

// 未接线 → 友好 static_assert

推广到 Load/Cast/Reduce 等域；附带机器可读支持矩阵与 constexpr bool supports<Op, Dtype, Arch>。

3.4 分域命名空间

AscendC::Te::           // 主入口
AscendC::Te::vec::      // 算子标签
AscendC::Te::copy::     // 搬运标签
AscendC::Te::mask::     // 谓词运算（And/Or/Create/Update）
AscendC::Te::reg::      // 寄存器类型

同名函数绝不跨域出现。老代码可用 using Reg = Te::reg 兼容。

3.5 双粒度 API，边界清晰

路径何时用动词
A · 寄存器级内循环体、已握 regCompute(MakeVec(op), dst, src…, mask)
B · UB Tensor 级整段 element-wiseTransform(MakeVec(op), dstTensor, srcTensor…)
GM/L1/L0多级流水Copy + Mmad（已有）

两条路共用同一套 vec::Op 标签和 Trait。

3.6 搬运 API 降维

// 1) 语义标签  copy::LoadUb{}  /  copy::StoreUb{}
// 2) Trait       LoadUbTrait { LoadDist dist; PostUpdate post; bool aligned; }
// 3) 动词        Copy(MakeCopy(copy::LoadUb{}, trait), reg, ubPtr);

进阶：Layout 推导 dist；Recipe 预设 LoadUbTrait::broadcast_b16()；UnalignedLoader 封装 ureg 状态机。

3.7 编译期友好报错 + 能力矩阵前置

  • 未接线 op → 友好 static_assert（告诉加哪一行宏）
  • 元数错误 → arity static_assert
  • 不支持组合 → supports<vec::Exp, half> 编译期拒绝
  • arch 不支持 ≠ 空函数，而是 #error 或 static_assert

3.8 谓词/mask 收敛

namespace mask {
    MaskReg Create(MaskPattern::ALL);
    MaskReg Update(uint32_t& remaining);  // 文档标明 in-out
}
// 计算层：mask 永远最后一个参数，永远传引用
Compute(atom, dst, src0, src1, mask);
// MERGING 只在 Trait 开启，Unpack 内统一 select 合并

3.9 文档即 API 的一部分

每个公开头必须包含：三种用法、操作数约定、扩展配方、支持矩阵链接。vec_op.h 即算子清单。

3.10 兼容与迁移

namespace Reg {
  template<typename... Args>
  [[deprecated("use Te::Compute(MakeVec(vec::Add{}), ...)")]]
  void Add(Args&... a) {
    Te::Compute(Te::MakeVec(Te::vec::Add{}), a...);

6需要守住的设计底线

要做

  • 贴硬件的零成本抽象（内联后 = 一条指令）
  • dst 优先约定（与 Copy/Mmad 一致）
  • 糖层宏生成，永不手写漂移
  • 编译期能力前置校验

不做

  • 不隐藏硬件（流水/buffer/同步仍由 Pipe/Tiling 管）
  • 不照搬 CuTe src 优先
  • 不过度抽象（1-2 行 helper 不如内联）
  • 不保留影子 API（DataCopy 式分裂）
一句话 reg_compute 的问题 = 函数太多、语义太散、配置太乱、文档太少。
TensorAPI 的优化 = 动词收敛 + Trait 收敛 + 标签目录 + 分域命名 + 能力前置校验，在 Copy/Mmad 已验证的分层上，把寄存器级算子与 UB 搬运纳入同一套形状。
