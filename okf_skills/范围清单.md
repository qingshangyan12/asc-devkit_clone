## 角色判定规则（可机械执行，按顺序应用）

1. 文件在 YAML front matter 内行首已有 `okftype:` 头则跳过（当前 140 篇，均为 vector 双目录）。
2. 文件名（basename）匹配 `.*_arch_[0-9]+(_deprecated)?\.md$`（当前 ID 仅 2201/3510）→ reference.api（架构变体）。
   注意：通配 `*_arch_*` 会在 utils 命中假阳性 asc_get_arch_ver.md（"arch"是函数语义），必须用数字 ID 收紧；arch 判定必须先于函数原型判定（arch 变体页也含 `## 函数原型`）。
3. 位于 `defs/{constant,enum,macro,type,union}/` 下、无行首 `## 函数原型`、且文件名不是分类页（constant.md/enum.md/macro.md/type.md/union.md，顶层 defs.md 同为分类页）→ reference.type。
   该口径不依赖各定义页标题措辞一致性（存在"枚举具体定义"缺"类"字、data_type_definition.md 无关键词章节等变体，已全量验证 defs 30 篇判定正确）。
4. 存在行首 `## 函数原型` 章节 → reference.api。
5. 无 `## 函数原型`、去掉 H1 后正文以子文档链接列表为主体 → reference.index。
   注意：分类页命名不统一（reg_gather/ub_gather 下叫 gather.md、scatter 下叫 scatter.md），不能用"文件名==目录名"判定。
6. 兜底：无函数原型、非链接列表的讲解性页面（13 篇概念页：顶层 README.md、general_description_and_constraints.md、reg_compute 的 overview/reg_load_overview/reg_store_overview/rounding_mode、sync 的 3 个 overview 与 key_features、atomic 的 atomic_operations_overview 与 key_features、cache_ctrl 的 system_cache_overview）→ reference.index，并填写 description（概念页有丰富语义内容，description 提升关键词检索命中）。规则 5 与 6 产出角色相同，混合型页面（链接表格+讲解）的编号归属不影响判定结果。

对账依据：行首 `## 函数原型` 章节共 691 篇 = 631 api + 60 arch，精确吻合；无原型页 109 = 85 index + 24 type。
