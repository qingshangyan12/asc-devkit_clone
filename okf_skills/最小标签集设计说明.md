# OKF 最小标签集设计说明

## 1. 为什么这样设计

最小集采用“全局导航字段 + 条件语义字段 + 按需扩展字段”：

```yaml
tag:
  - api_surfaces: [c_api]
  - roles: [compute]
  - operations: [add]
  - execution_models: [memory_vector]
```

- `api_surfaces`：说明 API 属于哪个公开接口体系，由稳定资源路径确定。
- `roles`：说明 API 是计算、搬运、配置、查询还是控制入口。
- `operations`：说明 API 直接执行的操作；计算、搬运、初始化 API 必须填写。
- `execution_models`：计算 API 必须填写，用于区分内存矢量、寄存器矢量等同名接口。
- `source_locations`、`destination_locations`：搬运 API 按需填写，用于表达 GM→UB、UB→GM 等方向。
- `traits`：只有会改变检索结果的稳定特征才填写，例如 `unaligned_transfer`、`padding`、`elementwise`。

`api_surfaces` 和 `roles` 是全局最小必填字段；`operations`、`execution_models` 按角色条件必填。`families`、`objects` 暂不进入最小集，避免每篇文档填写大量低收益或重复信息。

## 2. 以后扩展规则

1. 先复用已有字段、已有值或查询别名。GM、Global Memory、全局内存属于同一概念，不新增多个标签值。
2. 只有真实检索需求无法由现有字段、正文、signature 或 dependencies 表达时，才新增字段或新值。
3. 新候选必须记录定义、正文证据、适用范围、查询入口和对照结果；批准前不能写入生产 YAML。
4. 新字段通常需要两个独立 API 和两个查询场景证明收益；单个 API 的特殊属性先留在候选池。
5. 新增、删除或重新定义标签必须生成新的冻结 taxonomy 版本，保留旧版本用于回退，不能直接改写旧 frozen 文件。
6. 不适用字段直接省略，不使用空数组、`unknown` 或 `other` 伪造信息；配置 API 不因下游 API 行为被强加 `operations`。

## 3. 标注示例

### 内存矢量 `asc_add`

```yaml
tag:
  - api_surfaces: [c_api]
  - roles: [compute]
  - operations: [add]
  - execution_models: [memory_vector]
```

### 寄存器矢量 `asc_add`

```yaml
tag:
  - api_surfaces: [c_api]
  - roles: [compute]
  - operations: [add]
  - execution_models: [register_vector]
```

两个接口名称和操作相同，`execution_models` 决定最终候选。

### 非对齐 GM→UB 搬运

```yaml
tag:
  - api_surfaces: [c_api]
  - roles: [data_movement]
  - operations: [copy]
  - source_locations: [global_memory]
  - destination_locations: [unified_buffer]
  - traits: [unaligned_transfer, padding]
```

`asc_set_copy_pad_val` 是配置接口，只写 `api_surfaces` 和 `roles: [data_movement_configuration]`，再通过 `dependencies` 指向被配置的搬运接口，不虚构 `operations: [copy]`。

## 4. 相比其他方案的收益

| 方案 | 主要问题 | 最小集的收益 |
| --- | --- | --- |
| 九个字段全部必填 | 配置页、定义页出现大量空数组 | 只要求适用字段，降低标注和校验负担 |
| 只保留 `operations` | 无法区分接口体系、配置接口、搬运方向和执行模型 | `api_surfaces`、`roles` 和条件字段保留必要消歧能力 |
| 只依赖 description | 同义词、缩写和表达顺序导致查询不稳定 | 受控字段提供稳定、可组合的检索维度 |
| 使用复合值，如 `copy_gm2ub` | 操作、路径、模型组合导致标签值数量快速膨胀 | 使用独立字段组合，避免枚举乘法增长 |

真实 A1 向量加法查找中，推荐字段覆盖 3/3 必需 API，初始候选为 10 个；只使用 `operations` 得到 13 个，简单文本关键词得到 19 个。140 篇已标注文档的保守投影显示，非空字段减少 35.48%，标签值记录减少 31.41%。

这些收益来自维护量下降、接口体系明确和组合查询稳定，不把候选数量直接等同于最终误报率。
