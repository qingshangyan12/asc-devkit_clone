# 字段与推导规范

本规范是 OKF 头字段与索引推导契约的唯一事实源。各 SKILL.md 只引用本文件，不复述字段定义与规则。
当前适配范围为 `docs/zh/api/SIMD-API/c_api`（C API）。

## 1. 三类头与设计原则

| 头类型 | 载体 | 承载信息 | 现状 |
| --- | --- | --- | --- |
| 文档头 | Markdown front matter | 语义信息（脚本不可推导） | okf-yaml-generate 写入（5 字段） |
| include 头 | 头文件 Doxygen（`@ingroup/@override_id/@archs/@param`）与声明 | 结构事实（原型、架构、参数） | 仓内既有（6550 声明 98% 已注解）；缺口由 okf-index 构建期报告并进 unresolved，修复属源码维护 |
| examples 头 | 样例源码 `//! [override_id]` marker | 样例与重载的关联 | 仓内既有；缺口同上 |

原则：

1. 文档头只放脚本推不出来的语义信息；可推导的检索维度一律在索引推导期由脚本生成。
2. 索引构建以脚本为主，少量 LLM 兜底（见第 5 节）；构建保持确定性。
3. 不为可推导事实建标签（词表调研与标注共同遵守）。

## 2. 文档头（5 字段）

字段与顺序固定：`okftype, description, tag, dependencies, version`。

| 字段 | 类型 | 必填性 | 说明 |
| --- | --- | --- | --- |
| `okftype` | string | 必填 | 文档族.页面种类，如 `reference.api`；index 页仅有此字段 |
| `description` | string | 实体页必填 | 中文单段摘要，8–180 字 |
| `tag` | ns→values | 见下 | 仅 `roles/operations/traits` 三个 namespace |
| `dependencies` | object[] | 必填（可为 `[]`） | `path/kind/condition?`；kind 取 `requires/configures/constrained_by/related/replaced_by` |
| `version` | string | 实体页必填 | CANN 生命周期区间：`9.0.0-` 或 `9.0.0-9.2.0` |

### tag namespace（仅 3 个）

| namespace | 必填规则 | 说明 |
| --- | --- | --- |
| `roles` | 实体页必填 | 调用/执行流程中的角色 |
| `operations` | roles 含 `compute/data_movement/data_initialization` 时必填 | 直接执行或配置的操作 |
| `traits` | 选填 | 影响检索的稳定行为特征（对齐/连续性/量化/填充等语义特征） |

不适用 namespace 省略，不写空数组。okftype 页面种类沿用既有注册表
（api/constant/enum/macro/union/type/index/concept/catalog/release）。

## 3. 推导契约（索引推导期，脚本执行）

下表全部由 okf-index 的推导引擎从三类头与仓内数据生成，禁止写入文档头或标签：

| 推导维度 | 来源 | 规则 |
| --- | --- | --- |
| `title` | 文档 H1 | 一级标题 |
| `api_class` | include 路径 / `@ingroup` | `include/c_api/<子目录>` 即 API 分类（vector_compute/reg_compute/cube_compute/cube_datamove/scalar_compute/atomic/cache_ctrl/sync/spr/utils/defs/composite/…） |
| `execution_model` | include 路径 + 原型 mangling | vector_compute→memory_vector；reg_compute→register_vector；scalar_compute→scalar；cube_*→matrix_compute；mangling 形态佐证（`Rv*` 寄存器侧、`PU*` 内存侧） |
| `source/destination_locations` | 原型 mangling 地址空间码 | `G`=GM、`U`=UB、`L1`=L1、`FB`=fixpipe、`CA/CB/CC`=L0A/L0B/L0C；`v`=矢量寄存器（vreg）、`vb`=掩码寄存器（preg）；mangling 权威定义见 okf-yaml-generate `scripts/prototype_id.py` |
| `signature/override_id/dtype` | include Doxygen + 声明 | `@override_id` 逐重载枚举；dtype 从 mangling 类型码还原 |
| `archs` | include `@archs` + `__NPU_ARCH__` 守卫 | 逐重载架构，文档级取并集 |
| `header` | include 声明位置 | 唯一声明头文件路径 |
| `masked` | mangling `_vb` 后缀 | 任一重载含掩码参数即支持掩码模式 |
| `deprecated` | include `ASC_DEPRECATED(v,date,replacement)` + 文档声明 | 替代目标同步推导 |
| `params`（参数反查） | include 声明 + `@param` | 参数名/类型（含枚举类型形参）→ API 反查视图 |
| `enums/macros 目录` | `include/c_api/defs/*.h` | 枚举值、常量、宏、union、类型别名全量目录 |
| `examples` | 样例 `//! [override_id]` marker | marker↔重载关联 |
| `navigation` | 正文链接 | 仓内相对链接保序去重 |
| `products` | 正文 `<!-- npu="X" -->` 标记 × `config/product-map.yaml` | 产品级支持/不支持矩阵 |
| `feature 视图` | dtype 家族 × roles/operations | 低精度（fp8_*/hifloat8/fp4x2_*）、int4 等特性族 |
| `api_surfaces` | 文档路径 | `SIMD-API/<surface>/` 即层级 |

## 4. version 字段产生方式（标注期推导，落头）

- 值由脚本从 `docs/zh/api/appendix/Release_Notes/` 推导（线上 release_notes.html 与本地同源，本地为唯一构建输入）：
  `CANN_9_0_0.md` 全量清单 → floor 9.0.0；`CANN_9_1_0/9_2_0.md`「新增特性」→ floor 抬升；「接口废弃」→ 区间闭合。
- okf-yaml-generate 写入头，证据为 Release Notes 逐字摘录；索引期只读头做门控，不重复解析。
- 索引构建可用 Release Notes 复核头内 version，漂移计入 unresolved。

## 5. LLM 辅助边界（索引构建）

1. 确定性脚本管线承载第 3 节全部主推导。
2. 脚本无法裁决的残留（复杂模板声明、Release Notes 歧义条目、文档与 include 冲突、缺口归类）写入 `unresolved.json`。
3. 单轮 LLM 裁决残留，结果固化为 `derive-overrides/<surface>.json`（落盘、可审查、可回放）。
4. 构建确定性消费 overrides；同输入两次构建字节一致；构建过程不内联调用 LLM。

## 6. 索引门控（CANN 版本 × 架构 × 层级）

- CANN 版本检测链：`--cann-version` 显式参数 > `$ASCEND_HOME_PATH` 安装目录版本 > 仓 `version.cmake`。
- 构建参数：`--level`（默认 c_api）、`--arch`（默认 A5，经 `config/product-map.yaml` 映射架构号）。
- 只索引同时满足三条件的 API：version 区间覆盖本地 CANN 版本 ∧ archs 含目标架构 ∧ 属于目标 level；
  被过滤 API 计入 `meta.filtered_by_version/arch` 供核对。
- 检索前置（okf-index `ensure_index.py`，okf-retrieve 步骤 0）：按同一检测链得出目标门控，
  committed 索引门控匹配且指纹新鲜（build-meta 哈希 + scope 文档数；`--strict` 全量重建比对）
  才直接使用，否则原地重建后再检索。

## 7. 证据规则（标注期）

- `description`：1–3 条目标 Markdown 正文逐字摘录。
- `tag`：每个 `namespace:value` 一条正文逐字摘录；不能凭名称、目录、dtype、架构、头文件、样例注释或相邻 API 推断。
- `dependencies`：每条依赖 `{source_path, excerpt}` 正文逐字摘录。
- `version`：Release Notes 逐字摘录。
- 正文证据不足以确定必填概念时阻断写入，进入补证/词表修订流程；不得用空数组、`unknown`、临时值绕过。
