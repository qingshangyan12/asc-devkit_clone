核心结论：各业务仓普遍存在内网地址泄漏、AI 工具链配置误提交、CI 产物桶依赖、破损模板字符串、制品源多版本分裂五类问题。需按 P0（本版本清零）→ P1（下版本收敛）→ P2（白名单机制常态化）三批次整改。

一、业界规范基线（对标 openEuler / OpenHarmony / 国内商业组织）

社区 / 组织核心实践对 CANN 的启示
openEuler 三方件全部收入 src-openeuler/<pkg> 仓托管，spec 描述构建来源，禁止构建期直连上游，版本固定 tag + 校验 收敛到单一制品源（cann-src-third-party 或 cann-3rd.obs 二选一），禁止 GitHub / 上游直链
OpenHarmony 三方源码 vendoring 进 third_party/，npm/pip 走统一镜像 + lock 文件，社区门禁拦截未审批 URL 语言生态依赖由 lock 文件解析，URL 白名单改为域名级而非 URL 枚举
商业组织（字节 / 阿里） 内网 Artifactory 代理 + 构建机不出公网 + SBOM（SPDX）出证 开源仓中内网地址零容忍；发布仓与 CI 仓隔离（dev → release 桶晋升）
SLSA / Linux 基金会 来源固定（commit/tag）、完整性校验（SHA256）、可追溯（provenance） 禁用 latest / Daily / newest 可变路径，全部版本化 + 哈希

二、通用整改规则（全仓适用）

R1必清零（P0，发布阻断项）

  1. 内网 / 私有泄漏：10.0.0.x、127.0.0.1、*.devcloud.huaweicloud.com、codehub-y.huawei.com、mirrors.tools.huawei.com、km.sankuai.com（外部公司内网！）、superkernel.local、openlibing.com（若为内部流水线）
  2. AI 工具链配置：obra/superpowers、opencode.ai/config.json、cann-agent/skills.git（产品仓与 AI 辅助配置分离）
  3. 破损 / 残缺字符串（扫描器抓到的源码脏数据）：${obs_path、http://x、https://[^、https://）不检查、中文混入 URL（...pull/1437，发现问题后...）、access_token=${TOKEN} 模板、.insteadOf= 误抓 —— 这些同时说明源码注释 / 文档质量缺陷
  4. 个人 / 临时仓：funna2000/kirin_cann_test、zhupc158/CheckerL2、zhangstevenunity/*、obs-9be7、GitHub_Trending/*（来源不明镜像）
  5. 第三方代理：ghfast.top（GitHub 加速代理，供应链劫持高危）、hf-mirror.com（非官方 HF 镜像，模型许可合规风险）

R2供应链收敛（P1）

  1. 制品源统一：同一组件（gtest / json / makeself / mockcpp）现存 2 个托管源 + 多版本分裂（json 3.11.3 / 3.12.0 并存、mockcpp h1~h5 五种变体、makeself 两种打包），应统一版本并只保留 cann-src-third-party releases 或 cann-3rd.obs 之一
  2. CI 桶与发布桶隔离：ascend-ci（无 SLA）、msprof_daily、pta/Daily、20260729_newest 等每日构建产物不得出现在商业仓引用中；统一为版本化制品 + SHA256
  3. 禁止 curl | sh 模式：cargo-binstall、deb.nodesource.com、micro.mamba.pm/.../latest
  4. 上游直链迁移（github.com/google/googletest/...、cmake.org、ccache releases 等）至 cann-src-third-party 托管

R3白名单制（P2，长效机制）

  1. URL 门禁由“精确 URL 枚举”升级为 5 类域名规则：①构建制品源 ②官方文档（hiascend / pytorch.org / gcc.gnu.org / tensorflow.org）③许可证（apache.org / opensource.org）④论文引用（arxiv.org / doi.org）⑤语言包 registry（pypi / npm 镜像域名，lock 文件解析，不枚举 tgz 直链）
  2. XML 命名空间（w3.org/2000/svg、json-schema.org）属协议标识，从 URL 扫描中排除
  3. github.com/sponsors/*、opencollective.com/*（lock 解析产物噪音）按域名整体豁免

四、落地机制建议

  1. 单一事实源：各仓删除自带的 cann-src-third-party 硬编码 URL，统一通过 CANN_CMAKE_TAG + add_cann_third_party() 引用 cmake 仓（asc-devkit scripts/download_third_party_offline.sh 固化整改方向，向 ops-* / ge / metadef 推广）
  2. 门禁升级：SBOM 扫描（oss_dep_security_gate_master.json 即产物）从 URL 精确匹配改为域名规则匹配 + P0 黑名单（内网段、.local、代理域名、明文 http），新增 URL 需 PR 审批
  3. 分批出仓：P0 项（约 60 条）本版本清零 → P1 制品源收敛（约 300 条）下版本 → P2 白名单机制常态化
  4. 发布验收：对齐 openEuler 出包标准 —— 全部构建制品有 SHA256、SBOM 出证、离线构建可复现
