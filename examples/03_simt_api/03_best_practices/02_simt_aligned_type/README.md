# SIMT 类型对齐优化搬运效率最佳实践样例

## 概述

本样例展示 **结构体类型对齐对 Global Memory 访存的影响**：对 8 种结构体（4 组"对齐 / 非对齐"对照）做逐元素数据搬运，对比类型对齐的差异。

## 支持的产品

- Ascend 950PR/Ascend 950DT

## 支持的 CANN 软件版本

- \>= CANN 9.0.0


## 样例描述

本样例选取 8 个结构体（按 sizeof 分 4 / 8 / 16 / 32 B 四组，每组各含一对"对齐 / 非对齐"对照），依次将长度为 `numElements` 的输入数组 `d_idata` 整体复制到 `d_odata`：`d_odata[i] = d_idata[i]`，对比搬运效率。

### 关键参数

  | 参数 | 值 | 说明 |
  |------|-----|------|
  | `MEM_BYTES`      | **512 MiB** | 输入/输出 buffer 字节数 |
  | `THREAD_COUNT`   | 2048   | 单核2048线程，grid固定<<<1, 2048>>> |
  | `numElements`    | `MEM_BYTES / sizeof(TData)` | 每个用例的元素数，随结构体大小自动伸缩 |

### 样例规格

  | 名称        | 字段     | sizeof | alignof | numElements  | 单次访存     | 次数 |
  |-------------|----------|--------|---------|-----------|--------------|------|
  | `Align4`    | 4 × u8   |  4 B   |   4 B   | 134217728 | 4 B (32-bit) |  1   |
  | `Misalign4` | 4 × u8   |  4 B   | **1 B** | 134217728 | 1 B  (8-bit) |  4   |
  | `Align8`    | 2 × u32  |  8 B   |   8 B   | 67108864  | 8 B (64-bit) |  1   |
  | `Misalign8` | 2 × u32  |  8 B   | **4 B** | 67108864  | 8 B (64-bit) |  1   |
  | `Align16`   | 4 × u32  | 16 B   |  16 B   | 33554432  | 8 B (64-bit) |  2   |
  | `Misalign16`| 4 × u32  | 16 B   | **4 B** | 33554432  | 4 B (32-bit) |  4   |
  | `Align32`   | 8 × u32  | 32 B   |  32 B   | 16777216  | 8 B (64-bit) |  4   |
  | `Misalign32`| 8 × u32  | 32 B   | **4 B** | 16777216  | 4 B (32-bit) |  8   |

  - **单次访存**：编译器为本结构体每次访存实际选择的指令宽度。  
  - **次数**：搬运一个元素需要发射的访存指令条数，等于 `sizeof / 单次访存字节数`。

## 性能分析

  ### 性能指标说明

  | 指标                | 说明                                                                                      |
  | ------------------- | ----------------------------------------------------------------------------------------- |
  | Task Duration(us)   | Task整体耗时，包含调度到加速器的时间、加速器上的执行时间以及响应结束时间                  |
  | aiv_time(us)        | Task在AI Vector Core上的理论执行时间，单位为us                                            |
  | aiv_total_cycles    | 该Task被分配到每个AI Vector Core计算单元上后，每个AI Vector Core计算单元上的执行cycle总数 |
  | aiv_vec_time(us)    | vec类型指令（向量类运算指令）耗时，单位为us                                               |
  | aiv_vec_ratio       | vec类型指令（向量类运算指令）的cycle数在total cycle数中的占用比                           |
  | aiv_scalar_time(us) | scalar类型指令（标量类运算指令）耗时，单位为us                                            |

  ### 综合分析

  所有用例搬运的总字节数相同（`MEM_BYTES = 512 MiB`），vec_ratio 均接近 1.0，说明搬运全部由向量访存指令完成，scalar 占比可忽略。性能差异完全来自访存指令条数的不同。

  | 对照组 | Task Duration(对齐) | Task Duration(非对齐) | 非对齐/对齐 | 说明 |
  | :----: | :-----------------: | :-------------------: | :---------: | :--- |
  |  4 B   | 27889.33 us         | 81223.02 us           | **2.91x**   | `alignof=1` 退化为 8-bit 访存，指令数 4 倍，差距最大 |
  |  8 B   | 17417.23 us         | 17415.04 us           | **1.00x**   | 编译器合并加载，无差异 |
  | 16 B   | 32983.77 us         | 38353.60 us           | **1.16x**   | 32-bit vs 64-bit 访存，每元素 4 条 vs 2 条 |
  | 32 B   | 60901.24 us         | 77790.93 us           | **1.28x**   | 32-bit vs 64-bit 访存，每元素 8 条 vs 4 条，累积差距更大 |

  - **4 B 组**（差距最大）：`Align4` 使用 32-bit 访存（1 条/元素），`Misalign4` 因 `alignof=1` 退化为 8-bit 访存（4 条/元素），指令条数之比 ≈ 4，实测耗时比 2.91 基本吻合
  - **8 B 组**（无差异）：`Misalign8` 虽然 `alignof=4`，但结构体大小恰好等于硬件最大访存宽度（8 B），编译器会自动合并为单条 64-bit 访存指令，与 `Align8` 的指令序列完全相同，因此性能一致
  - **16 B / 32 B 组**（中等差距）：两组非对齐版本的指令条数均为对齐版本的 2 倍，但 32 B 组的绝对指令数更多（对齐 4 条、非对齐 8 条 vs 16 B 的 2 条 vs 4 条），32-bit 访存的吞吐劣势累积更显著，因此 Task Duration 差距更大（32 B 增加 28% vs 16 B 增加 16%）

  **综合结论**：结构体对齐能减少搬运所需的访存指令条数，从而降低 Task Duration。8 B 组因编译器合并加载例外；其余三组中，`alignof` 越小（访存宽度越窄），性能差距越明显。

  ### 原理分析

  编译器为每次访存挑选指令宽度时，同时受两个上界约束：

  - **硬件最大单次访存宽度**：本平台为 8 B（64-bit），所以即便 `Align16` / `Align32` 也看不到单条 128-bit 访存，只能拆成多条 64-bit 指令完成；
  - **alignof**：`alignof=4` 把单次宽度封顶到 32-bit，`alignof=1` 封顶到 8-bit。`Misalign4` / `Misalign16` / `Misalign32` 都是被这一条压住的。

  编译器实际选用的访存宽度（上表「单次访存」列） = 上述两条约束取更紧的一个，即 min(64-bit, alignof 允许的最大宽度)；元素剩下的字节按该宽度切片，即搬运一个元素需要发射的访存指令条数（上表「次数」列）。**指令条数越少，搬运效率越高**。
  
  其中，`Misalign8` 比较特殊，编译器会把整个结构体合并成一条访存指令，单次访存 8 B（64-bit），不受 `alignof=4` 的限制。

## 编译运行

  在本样例根目录下执行如下步骤，编译并执行样例。

  - 配置环境变量

    请根据当前环境上 CANN 开发套件包的[安装方式](../../../../docs/quick_start.md#prepare&install)，选择对应配置环境变量的命令。

    - 默认路径，root 用户安装 CANN 软件包

      ```bash
      source /usr/local/Ascend/cann/set_env.sh
      ```

    - 默认路径，非 root 用户安装 CANN 软件包

      ```bash
      source $HOME/Ascend/cann/set_env.sh
      ```

    - 指定路径 `install_path`，安装 CANN 软件包

      ```bash
      source ${install_path}/cann/set_env.sh
      ```

  - 样例执行

    ```bash
    mkdir -p build && cd build;   # 创建并进入 build 目录
    cmake ..; make -j;            # 编译工程
    ./demo                        # 执行样例
    ```

  - 执行结果  

    执行结果如下，说明样例运行成功。
    
    ```bash
    [aligned_type] -> Test Results: 0 failures.
    ```
