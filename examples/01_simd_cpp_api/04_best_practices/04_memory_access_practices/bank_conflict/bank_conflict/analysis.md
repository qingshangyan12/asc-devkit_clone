# Mul指令验证及分析

包含bank冲突、地址重叠等场景的验证和分析。输入数据类型是float，输入数据长度是4096，以连续读写为例

- 地址完全重叠场景
    以`case7`为例，性能表现与`case1`（地址不重叠且无bank冲突）接近，原因分析：
    - 无读读冲突：硬件做了优化，只会读1个。2读1写相当于1读1写，故不会有读读冲突；
    - 无读写冲突：硬件会自动错开1拍，不会有读写冲突；
        - 示例1. 硬件不错开1拍场景

            | 第1拍 | 第2拍 | 第3拍 |
            | --- | --- | --- |
            | 读bg 0-7 | 读bg 8-15 | ... |
            | 写bg 0-7 | 写bg 8-15 | ... |
        
        - 示例2. 硬件错开1拍（有效场景）

            | 第1拍 | 第2拍 | 第3拍 |
            | --- | --- | --- |
            | 读bg 0-7 | 读bg 8-15 | ... |
            | - | 写bg 0-7 | 写bg 8-15 |

        - 示例3. 硬件错开1拍（无效场景）

            | 第1拍 | 第2拍 | 第3拍 |
            | --- | --- | --- |
            | 读bg 0-7 | 读bg 0-7 | ... |
            | - | 写bg 0-7 | 写bg 8-15 |

        - 示例4. 读写冲突严重场景

            | 第1拍 | 第2拍 | 第3拍 |
            | --- | --- | --- |
            | 读bg 0-7 | 读bg 0-7 | ... |
            | 写bg 0-7 | 写bg 0-7 | ... |


    - 相比case1性能接近，但稍差一点的原因：读写是同一个地址，为了让读写错开1拍，可能读或写或晚1拍（最差情况，每条指令差1拍）。

- 地址不重叠场景  
    主要考虑bank冲突
    - 同一个bank_group只有1组读口和1组写口，同一个bank_grou两读一写会出现读读冲突，如`case8`；
    - 同一个bank 1拍只能1读或者1写，如果硬件自动错开1拍有效，则不会读写bank冲突，如`case4/case5`；否则会出现读写bank冲突。
