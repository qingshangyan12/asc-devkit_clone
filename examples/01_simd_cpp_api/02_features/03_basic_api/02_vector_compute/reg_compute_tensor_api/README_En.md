# Reg Compute Basic Compute Direct Call Sample (Tensor API)

## Overview

This sample uses the return-value-style Reg Compute APIs to implement the register computation functions described in the Basic Compute chapter of the Vector Compute manual. It covers 28 basic compute APIs across unary arithmetic, activation, binary arithmetic, logical, bitwise, shift, and comparison operations, including register, scalar-right-operand, and scalar-left-operand overloads.

The sample implements Reg Compute basic computation in Ascend C and uses the `<<<>>>` kernel call operator to run the kernel on the NPU, providing an end-to-end implementation. The kernel uses Tensor API for data movement between GM and UB, loads `reg_tensor` values with `local_tensor::load`, and writes the computed values back to UB with `local_tensor::store`.

## Supported Products

- Ascend 950PR/Ascend 950DT

> **Note:** This sample depends on the Reg Compute APIs added by this repository. Build and install a matching development kit package from an asc-devkit revision that contains these APIs. The headers from a standard CANN 9.2.0 installation do not contain them.

## Operator Description

- Operator function:

  This sample performs Reg Compute basic computations on 64 `float` elements and 64 `int32_t` elements. The floating-point computation produces 38 result rows, and the integer computation produces 14 result rows. The verification script compares every output element with golden data generated by NumPy.

- Operator implementation:

  - Kernel implementation

    The kernel flow consists of four steps: creating GM/UB tensors, CopyIn, Compute, and CopyOut. CopyIn transfers the input tensors from Global Memory to Unified Buffer. Compute performs the Reg Compute operations through `ComputeFloat` and `ComputeInt`. CopyOut transfers the results from Unified Buffer to Global Memory.

    A register on the dav-3510 architecture contains 64 `float` or `int32_t` elements. The sample creates a full-lane mask with `ones<T>()` and attaches the mask to loaded values with `with_mask`. Row 37 additionally uses `a > 0.0f` as a partial mask to validate mask propagation through computation and storage.

    The rows in `float_output` are ordered as follows.

    | Rows | API calls |
    | :--- | :--- |
    | 0-7 | `abs(a)`, `exp(a)`, `sqrt(positive)`, `log(positive)`, `log2(positive)`, `log10(positive)`, `-a`, `relu(a)` |
    | 8-12 | `prelu(a, slope)`, `prelu(a, 0.2f)`, `prelu(a)`, `leaky_relu(a, 0.1f)`, `leaky_relu(a)` |
    | 13-15 | `a + b`, `a + 1.0f`, `1.0f + a` |
    | 16-18 | `a - b`, `a - 1.0f`, `1.0f - a` |
    | 19-21 | `a * b`, `a * 2.0f`, `2.0f * a` |
    | 22-24 | `a / b`, `a / 2.0f`, `2.0f / positive` |
    | 25-27 | `max(a, b)`, `max(a, 0.0f)`, `max(0.0f, a)` |
    | 28-30 | `min(a, b)`, `min(a, 0.0f)`, `min(0.0f, a)` |
    | 31-36 | `a == b`, `a != 0.0f`, `0.0f < a`, `a <= 0.0f`, `0.0f > a`, `a >= b` |
    | 37 | `a + 1.0f` on lanes selected by `a > 0.0f`; inactive lanes remain `0.0f` |

    The rows in `int_output` are ordered as follows.

    | Rows | API calls |
    | :--- | :--- |
    | 0 | `!a` |
    | 1-3 | `a & b`, `a & 15`, `15 & a` |
    | 4-6 | `a \| b`, `a \| 16`, `16 \| a` |
    | 7-9 | `a ^ b`, `a ^ 7`, `7 ^ a` |
    | 10-11 | `a << shift`, `a << 2` |
    | 12-13 | `a >> shift`, `a >> 2` |

    Comparison APIs return `reg_tensor<bool>`. The sample first stores a full zero register, then uses the comparison result as the mask for storing a full one register. This materializes each predicate as `0.0f` or `1.0f` for host-side validation.

  - Invocation implementation

    The kernel is invoked with the `<<<>>>` kernel call operator. After kernel execution, the host writes `float_output.bin` and `int_output.bin`. `verify_result.py` compares them with `golden_float.bin` and `golden_int.bin`. The `exp`, `sqrt`, and logarithm rows use combined absolute and relative tolerances of `5e-3`; other floating-point rows use `1e-4`. Integer and comparison outputs must match exactly.

## Build and Run

Run the following steps in the root directory of this sample to build and run the operator.

- Configure environment variables

  First follow the [installation method](https://gitcode.com/cann/asc-devkit/blob/master/docs/quick_start.md#prepare&install) to build and install an asc-devkit package containing these APIs, then select the appropriate environment configuration command.

  - Default path for a CANN package installed by the root user

    ```bash
    source /usr/local/Ascend/cann/set_env.sh
    ```

  - Default path for a CANN package installed by a non-root user

    ```bash
    source $HOME/Ascend/cann/set_env.sh
    ```

  - CANN package installed in a specified `install_path`

    ```bash
    source ${install_path}/cann/set_env.sh
    ```

- Run the sample

  ```bash
  mkdir -p build && cd build
  cmake .. -DCMAKE_ASC_ARCHITECTURES=dav-3510
  cmake --build . -j
  python3 ../scripts/gen_data.py
  ./demo
  python3 ../scripts/verify_result.py \
    output/float_output.bin output/golden_float.bin \
    output/int_output.bin output/golden_int.bin
  ```

  The following verification output indicates that all API results pass accuracy validation.

  ```text
  Float results passed, max absolute error: <value>
  Int32 results passed.
  test pass!
  ```

- Build option description

  | Option | Values | Description |
  | :--- | :--- | :--- |
  | `CMAKE_ASC_RUN_MODE` | `npu` (default) | NPU run mode |
  | `CMAKE_ASC_ARCHITECTURES` | `dav-3510` (default) | NPU architecture corresponding to Ascend 950PR/Ascend 950DT |
