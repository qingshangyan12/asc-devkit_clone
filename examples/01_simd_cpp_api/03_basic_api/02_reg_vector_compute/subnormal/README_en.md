# Subnormal Example

## Overview

This example demonstrates using the DivAlgo::DIFF_COMPENSATION difference compensation algorithm for division in Ascend C Reg vector computation, verifying its 0ulp precision characteristic. By selecting normal-value divisions that cannot be exactly represented in float32, it shows that the difference compensation algorithm output matches the IEEE 754 correctly rounded result exactly.

## Supported Products and CANN Versions

| Product | CANN Version |
|---------|-------------|
| Ascend 950PR/Ascend 950DT | >= CANN 9.1.0 |

## Example Description

- Example functionality:

  The example computes float type data, using the DivAlgo::DIFF_COMPENSATION difference compensation algorithm to configure DivSpecificMode as the precision algorithm parameter for the Div operation, performing division on normal values. Golden data is generated by rounding the float64 high-precision division result to float32 (simulating IEEE 754 correct rounding), used to verify 0ulp precision. The computation formula is as follows:
  $$z_i = \frac{x_i}{y_i}$$

- Example implementation
    - Implementation flow:
        1. Allocate memory on the Host side and initialize input data
        2. Transfer data from Host memory to Device global memory
        3. Call the kernel function to execute computation on the Vector core
        4. Inside the kernel function: transfer input data from Global Memory to Unified Buffer via DataCopy
        5. Call the VF (Vector Function) function via asc_vf_call on the Unified Buffer
        6. Inside the VF function, use the DivSpecificMode template parameter to perform LoadAlign, Div, and StoreAlign operations
        7. Transfer computation results from Unified Buffer back to Global Memory
        8. Perform precision verification and golden data comparison on the Host side

  - 0ulp precision description:
      - Difference compensation algorithm (DIFF_COMPENSATION): After computing a preliminary quotient, uses the remainder to perform difference compensation correction, eliminating the rounding error of single-instruction division. The output matches the IEEE 754 correctly rounded result exactly, with a maximum precision error of 0ulp.
      - Default algorithm (INTRINSIC): Uses a single instruction to compute, with a maximum precision error of 1ulp. Division results that cannot be exactly represented may have a 1ulp rounding deviation.

  - Scenario description:
      - Implementation function: SubnormalDivVF<T>
      - Implementation:
        ```cpp
        static constexpr AscendC::Reg::DivSpecificMode mode = {ZEROING, false, DIFF_COMPENSATION};
        AscendC::Reg::Div<T, &mode>(zReg, xReg, yReg, mask);
        ```
      - Description: Uses the difference compensation algorithm to perform division on normal values, with a maximum precision error of 0ulp. The output matches golden (IEEE 754 correct rounding) exactly.
      - Application scenarios: Scientific computing, numerical simulation, and high-precision computation scenarios with strict division precision requirements.

    - Computation data examples:

      | No. | Dividend | Divisor | float32 Exact Rounded Result (golden) | Description |
      |:---:|:---:|:---:|:---:|:---|
      | 1 | 1.0 | 3.0 | 0.33333334 (0x3EAAAAAB) | 1/3 cannot be exactly represented in float32, requires rounding |
      | 2 | 1.0 | 7.0 | 0.14285715 (0x3E124925) | 1/7 cannot be exactly represented in float32, requires rounding |
      | 3 | 2.0 | 3.0 | 0.6666667 (0x3F2AAAAB) | 2/3 cannot be exactly represented in float32, requires rounding |
      | 4 | 1.0 | 10.0 | 0.100000001 (0x3DCCCCCD) | 1/10 cannot be exactly represented in float32, requires rounding |
      | 5 | 3.0 | 7.0 | 0.42857143 (0x3EDB6DB7) | 3/7 cannot be exactly represented in float32, requires rounding |

      - DIFF_COMPENSATION output matches golden exactly (0ulp error).

  - Constraints:
      - Input data length must be a multiple of GetVecLen()
      - The divisor cannot be 0. In practical applications, a check for zero divisors is required
      - The example currently only supports the float data type

## Build and Run

- Configure environment variables
  Configure environment variables based on the [installation method](../../../../../docs/en/quick_start.md#prepare&install) of the CANN development kit on the current environment.
  ```bash
  source ${install_path}/cann/set_env.sh
  ```

  > **Note:** `${install_path}` is the CANN package installation directory. When no installation directory is specified, the default installation path is `/usr/local/Ascend`.

- Run the example

  Run the following commands in the example directory.
  ```bash
  mkdir -p build && cd build;                                               # Create and enter the build directory
  cmake ..; make -j;                                                        # Build the project
  python3 ../scripts/gen_data.py;                                           # Generate test input data
  ./demo                                                                    # Run the example
  ```

  To use CPU debug or NPU simulation mode, add the `-DCMAKE_ASC_RUN_MODE=cpu` or `-DCMAKE_ASC_RUN_MODE=sim` parameter.

  Examples:
  ```bash
  cmake -DCMAKE_ASC_RUN_MODE=cpu -DCMAKE_ASC_ARCHITECTURES=dav-3510 ..;make -j; # CPU debug mode
  cmake -DCMAKE_ASC_RUN_MODE=sim -DCMAKE_ASC_ARCHITECTURES=dav-3510 ..;make -j; # NPU simulation mode
  ```

  > **Notice:** Clear the cmake cache before switching build modes. Run `rm CMakeCache.txt` in the build directory and re-run cmake.
- Build option description

  | Option | Values | Description |
  |:--------------------------|:----------------------|:---------------------------------------------|
  | `CMAKE_ASC_RUN_MODE`      | `npu` (default), `cpu`, `sim` | Run mode: NPU execution, CPU debug, NPU simulation                      |
  | `CMAKE_ASC_ARCHITECTURES` | `dav-3510`            | NPU architecture: dav-3510 corresponds to Ascend 950PR/Ascend 950DT |

- Execution result
  The following execution result indicates that the precision comparison is successful.
