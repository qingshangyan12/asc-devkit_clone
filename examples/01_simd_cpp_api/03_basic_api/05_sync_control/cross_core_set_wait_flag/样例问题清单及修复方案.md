# CrossCoreSetFlag和CrossCoreWaitFlag样例问题清单及修复方案

## 检查结论

原样例覆盖了模式0、模式1和模式2的典型同步关系，场景选择具有业务含义，但非零输入验证、Ascend 950适配、参数校验和资料衔接存在缺口。本次修复补充`SCENARIO_NUM=3`演示模式4，并修复检查中发现的正确性和易用性问题。

## 修复方案

### P01 融合场景测试数据退化为全零

**问题：** 原脚本使用`np.random.uniform(0, 1).astype(np.uint8)`生成矩阵，转换后所有元素均为0。Kernel即使存在矩阵布局或地址错误，结果仍可能通过。

**修复：** 在[gen_data.py](scripts/gen_data.py)中改用`np.random.randint(0, 10, dtype=np.uint8)`，为场景2和场景3生成可区分错误的非零整数输入。

### P02 UB地址重叠导致扩宽Cast覆盖输入

**问题：** `aLocal`与`castALocal`、`bLocal`与`castBLocal`使用相同物理UB地址。`uint8`转换为`half`时目的数据更宽，会覆盖尚未读取的源数据；该问题在统一UB的Ascend 950上可复现。

**修复：** 在[cross_core_set_wait_flag.h](cross_core_set_wait_flag.h)中重新规划UB空间：Cast输出复用后续C输入区域，LeakyRelu输出放到另一段独立区域，确保每次计算的源、目的地址不重叠。

### P03 L1静态Tensor地址单位使用错误

**问题：** 静态`LocalTensor`构造函数的`addr`单位为字节，原`b1LocalAddr`只增加了A矩阵元素数。

**修复：** B矩阵起始地址改为`A_SIZE_ALIGN_L1 * sizeof(half)`，避免A、B矩阵在L1中重叠。

### P04 Ascend 950矩阵搬入搬出参数不匹配

**问题：** dav-3510的L0A数据排布和Fixpipe参数类型与dav-2201不同，直接复用`LoadData2DParams`和`FixpipeParamsV220`不能保证结果正确。

**修复：** dav-3510分支使用`LoadData2DParamsV2`完成Nz到Nz搬入，使用`FixpipeParamsArch3510`搬出；dav-2201保留原实现。接口依据见[LoadData（2D矩阵搬运V2）](../../../../../docs/zh/api/SIMD-API/basic_api/cube_compute_ISASI/cube_compute_load/LoadData_2D_V2.md)和[Fixpipe（L0C Buffer到UB数据搬运）](../../../../../docs/zh/api/SIMD-API/basic_api/cube_compute_ISASI/cube_compute_store/Fixpipe_L0CToUB.md)。

### P05 缺少模式4调用场景

**问题：** 原样例仅覆盖模式0、模式1、模式2，无法帮助开发者理解AIC与指定单个AIV同步时的flagId映射。

**修复：** 新增`SCENARIO_NUM=3`：仅启动1个AI Core，AIV0/AIV1分别转换A/B矩阵并通过模式4通知AIC；AIC将结果一半直达AIV0的UB，另一半经GM送至AIV1，再分别完成LeakyRelu。

### P06 场景和架构参数缺少校验

**问题：** CMake未限制场景编号，也未阻止在不支持模式4的架构上构建场景3。

**修复：** 在[CMakeLists.txt](CMakeLists.txt)中限制`SCENARIO_NUM`为0~3，并要求场景3配置`CMAKE_ASC_ARCHITECTURES=dav-3510`。

### P07 精度校验脚本的异常处理不足

**问题：** 输出长度不一致时可能产生误导结果；NaN可能被`equal_nan=True`接受；真值为0时相对误差输出会除零。

**修复：** 在[verify_result.py](scripts/verify_result.py)中增加元素数量和有限值检查，并使用绝对容差作为相对误差分母下限。

### P08 README与接口约束脱节

**问题：** 开发者只阅读样例时无法获知模式4产品范围、Kernel类型、AIV1 flagId映射、接口配对及模式0并发死锁风险。

**修复：** 在[README.md](README.md)和[README_en.md](README_en.md)中补充模式4流程、编译参数和注意事项，并跳转到[CrossCoreSetFlag接口约束](../../../../../docs/zh/api/SIMD-API/basic_api/sync_control/inter_core_sync/CrossCoreSetFlag_ISASI.md#section633mcpsimp)及[CrossCoreWaitFlag接口约束](../../../../../docs/zh/api/SIMD-API/basic_api/sync_control/inter_core_sync/CrossCoreWaitFlag_ISASI.md#section633mcpsimp)。

### P09 LeakyRelu对当前输入不产生实际效果

**问题：** A、B矩阵均为`uint8`类型，转换为`half`后仍为非负数，矩阵乘累加结果也不会小于0。因此LeakyRelu对当前数据等价于恒等操作，不能验证激活函数的负数分支。

**处理建议：** 该问题不影响模式4同步关系、L0C到UB/GM搬运路径及最终结果正确性，优先级较低，本次暂不修改Kernel。后续可将Vector阶段替换为能够改变非负结果的运算，并同步调整真值计算，以增强样例的可验证性。

### P10 UB静态Tensor地址表达不明确

**问题：** `LocalTensor`静态构造函数的`addr`参数单位为字节，原代码中的`bAddr`和`cAddr`直接使用元素数量表达偏移。由于对应输入类型是`uint8_t`，当前数值碰巧正确，但容易误导后续修改，并掩盖不同数据类型下的地址错误。

**修复：** 在[cross_core_set_wait_flag.h](cross_core_set_wait_flag.h)中显式使用`sizeof(uint8_t)`计算`bAddr`和`cAddr`字节偏移；各`LocalTensor`的`tileSize`仍保持元素数量。

### P11 不同架构下pipe模板参数使用不一致

**问题：** `CrossCoreWaitFlag`的`pipe`模板参数在Atlas A2/A3上不影响硬件指令，但在Ascend 950（dav-3510）上会作为硬件指令输入。样例原先省略该参数，使用默认值`PIPE_S`；而dav-3510的模式0、模式1和模式2不支持`PIPE_S`，无法体现两个架构的参数生效差异。

**修复：** 在`cross_core_set_wait_flag.h`中增加架构适配封装。dav-3510显式传入与后续流水匹配的`PIPE_MTE2`或`PIPE_FIX`，dav-2201继续省略`pipe`并使用原有默认行为。具体支持范围参见[CrossCoreWaitFlag模板参数默认值及生效情况](../../../../../docs/zh/api/SIMD-API/basic_api/sync_control/inter_core_sync/CrossCoreWaitFlag_ISASI.md#template-parameter-defaults)。
