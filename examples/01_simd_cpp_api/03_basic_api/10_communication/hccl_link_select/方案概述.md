# HCCL OnePath链路选择样例方案

## 1. 样例目标

本样例在一次运行中筛选`COMM_PROTOCOL_UB_MEM`链路，在同一个通信域中批量创建
`pathMode=2`和`pathMode=3`两条Channel，通过两个Stream分片搬运并验证单机或跨机Device之间的DataCopy。

```text
对端HCCL Buffer -> UB_MEM链路 -> Ascend C DataCopy -> 本端校验Buffer -> Host校验
```

`main.cpp`负责Host控制面，`ubmem_data_copy.asc`只负责Kernel数据搬运。样例不直接调用
`aclrtIpcMemSetAttr`，OnePath链路属性由HCCL/HCOMM根据`pathMode`在内部处理。

## 2. 代码主线

`main.cpp`中的`TestDualPath`按HCCL样例常见方式顺序展示核心API，不再拆成多个阶段类或辅助源码文件：

```text
HcclCommInitRootInfo
  -> HcclGetHcclBuffer
  -> HcclCommMemReg
  -> RankGraph查询并选择链路
  -> HcclChannelAcquire
  -> HcclChannelGetHcclBuffer
  -> LaunchUbmemDataCopy
  -> Host校验
```

`main`只生成一份`HcclRootInfo`并调用一次`TestDualPath`：

```text
新RootInfo -> 单通信域 -> 批量创建两条Channel -> 双Stream分片搬运 -> 校验 -> 销毁通信域
```

每个peer对应的两个`HcclChannelDesc`必须按`pathMode=2`、`pathMode=3`的固定顺序放入同一次
`HcclChannelAcquire`。HCOMM批量创建时会为同一peer和Endpoint递增Channel索引，从而返回两条不同的
Channel Handle。

### 2.1 初始化通信域和数据

各rank使用同一份`HcclRootInfo`初始化通信域，再获取本端HCCL Buffer并写入rank ID：

```text
HcclCommInitRootInfo
HcclGetHcclBuffer
aclrtMemset(localHcclBuffer, rank)
```

其他rank读取这块HCCL Buffer后，可以根据内容是否等于对端rank ID判断DataCopy是否正确。

### 2.2 选择链路并创建Channel

样例先通过`HcclCommMemReg`注册Channel创建所需的本端内存，然后为每个对端rank查询链路：

```text
HcclRankGraphGetLayers
  -> HcclRankGraphGetTopoTypeByLayer
  -> HcclRankGraphGetLinks
  -> 筛选COMM_PROTOCOL_UB_MEM
  -> 填充HcclChannelDesc
```

RankGraph拓扑只用于日志展示链路的实际来源，不参与`pathMode`选择。Channel顺序和分片映射如下：

| Channel顺序 | 链路筛选 | `pathMode` | 数据范围 |
| --- | --- | --- | --- |
| 1 | `COMM_PROTOCOL_UB_MEM` | `2` | 前2 KB |
| 2 | `COMM_PROTOCOL_UB_MEM` | `3` | 后2 KB |

Channel描述的核心字段为：

```cpp
HcclChannelDescInit(&desc, 1);
desc.remoteRank = peerRank;
desc.channelProtocol = COMM_PROTOCOL_UB_MEM;
desc.memHandles = &memHandle;
desc.memHandleNum = 1;
desc.ubMemAttr.pathMode = pathMode;
```

两条描述的Endpoint信息来自同一个`CommLink`，只有`pathMode`不同。为支持8卡、16卡等多rank场景，
样例使用分轮配对算法执行`rankSize - 1`轮建链。每轮每个rank只与一个peer调用一次
`HcclChannelAcquire`，全部轮次覆盖所有rank对，同时避免一次批量申请过多Channel。

### 2.3 获取对端Buffer并搬运

Channel创建完成后，样例分别获取两条Channel对应的远端HCCL Buffer地址：

```text
Channel(pathMode=2) -> LaunchUbmemDataCopy(offset=0, size=2 KB, stream0)
Channel(pathMode=3) -> LaunchUbmemDataCopy(offset=2 KB, size=2 KB, stream1)
  -> 两个Kernel均下发后同步stream0和stream1
  -> aclrtMemcpy到Host
  -> 校验每个字节是否等于对端rank ID
```

`ubmem_data_copy.asc`没有额外类封装。Kernel直接创建GlobalTensor和LocalTensor，按tile执行
`DataCopy(remote GM -> LocalTensor -> local GM)`。

## 3. 启动模型

样例采用“一进程一Device”。`run.sh`负责启动当前机器上的rank进程，rank 0通过TCP分发一份
`HcclRootInfo`：

```text
rank 0生成并分发RootInfo -> 所有rank分轮创建到每个peer的两条Channel -> 完成分片验证
```

TCP仅用于样例启动，不参与HCCL数据链路选择。相关辅助函数统一放在`main.cpp`末尾，避免干扰
`TestDualPath`中的控制面主线，也不增加额外C++源码文件。

## 4. 资源生命周期

双Channel验证结束后，`TestDualPath`通过`CleanupCommRes`集中清理该通信域的资源：

```text
aclrtDestroyStream(stream0)
aclrtDestroyStream(stream1)
HcclCommDestroy
aclrtFree(verifyBuffer)
aclrtFree(channelMemory)
```

通信域清理后，`main`再清理Device和ACL Runtime：

```text
aclrtResetDevice
aclFinalize
```

`channelMemory`已注册到通信域，因此只有在`HcclCommDestroy`成功后才单独释放。

## 5. 成功判据

默认2-rank场景应输出两条Channel和分片验证结果：

```text
rank 0/2: device=0, channels_per_peer=2, acquire_rounds=1
rank 0: peer=1, rank_graph_topo=5, protocol=UB_MEM, path_modes=2/3
rank 0: dual-path data copy from remote rank 1 passed, bytes=4096
rank 0: dual-path validation passed
```

所有rank均取得两条不同的Channel Handle、完成分片数据校验且脚本返回0，表示样例运行成功。rank之间缺少目标链路时，
样例输出`no UB_MEM link found`并返回失败。
