# L2 Cache 读写模式说明

L2 Cache 的读写各有 Normal 和 Not-alloc 两种模式，Normal 下又分 First Victim、Last Victim、Persistent 三种替换策略。以下逐一说明。

---

## 一、读模式

### 1. Normal 模式

**行为**：从 GM 读取数据并**分配 L2 Cache Line**，数据被缓存后可供后续重复访问命中。

**替换策略对比**：

| 策略 | 英文描述 | 中文描述 | 替换优先级 |
|------|---------|---------|-----------|
| **First Victim** | allocate local share, high priority for replacement | 分配 L2 缓存行，具有**最高**被替换优先级。当 L2 空间不足时，此类缓存行**最先**被换出。 | 高（优先被逐出） |
| **Last Victim** | allocate local share, low priority for replacement | 分配 L2 缓存行，具有**最低**被替换优先级。当 L2 空间不足时，此类缓存行**最后**才被换出。 | 低（尽量保留） |
| **Persistent** | allocate local share, only replaced by persistent | 分配 L2 缓存行，**只能被其他 Persistent 缓存行替换**。普通 (First/Last Victim) 缓存行无法将其逐出。 | 最低（仅 Persistent 可替换） |

**伪代码**：

```
// 读 Normal 模式通用流程
read_normal_with_policy(address, policy):
    cacheline = l2_cache.lookup(address)
    if cacheline != MISS:
        return cacheline.data                    // 命中，直接返回
    else:
        data = gm.read(address)                  // 未命中，从 GM 读取
        victim = select_victim(policy)            // 根据策略选择被替换的缓存行

        select_victim(policy):
            switch policy:
                case FIRST_VICTIM:
                    return find_first_evictable()         // 优先选择可换出的
                case LAST_VICTIM:
                    return find_last_evictable()          // 尽量选择不重要的
                case PERSISTENT:
                    return find_persistent_evictable()    // 仅替换 Persistent 行

        l2_cache.replace(victim, address, data)   // 写入 L2
        return data
```

**使用场景**：

| 策略 | 适用场景 | 示例 |
|------|---------|------|
| **First Victim** | 可能复用的数据，但不关键，优先给其他数据让位 | 中间计算结果、临时缓冲区 |
| **Last Victim** | 需要多次复用的热点数据，希望尽可能保留在 L2 中 | 模型权重、卷积核、频繁访问的查找表 |
| **Persistent** | 极其关键的常驻数据，绝对不能被意外逐出 | 关键常量表、高频访问的控制参数 |

> **Ascend C 中对应**：`SetL2CacheHint(CACHE_MODE_NORMAL)`，硬件默认行为，通常结合数据分片策略使工作集落在 L2 容量内以获得高命中率。

---

### 2. Not-alloc 模式（keep）

**行为**：**不分配新 Cache Line**，保持现有缓存状态不变。

| 子模式 | 英文描述 | 中文描述 |
|--------|---------|---------|
| **keep** | non-allocate, preserve cacheline state | 不分配缓存行，保持已有缓存行的状态不变 |

**伪代码**：

```
// 读 Not-alloc (keep) 模式
read_not_alloc_keep(address):
    cacheline = l2_cache.lookup(address)
    if cacheline != MISS:
        return cacheline.data                    // 命中直接返回（不改缓存状态）
    else:
        data = gm.read(address)                  // 未命中，直接从 GM 读
        // 不分配新的 Cache Line，不替换任何现有数据
        // L2 Cache 状态与读取前完全一致
        return data
```

**使用场景**：

- **流式数据**（只读取一次，不会复用）：避免写入 L2 浪费空间和带宽
- **大块数据搬运**：数据量远超 L2 容量，缓存无意义
- **不希望污染 L2 的任何读操作**

> **Ascend C 中对应**：`SetL2CacheHint(CACHE_MODE_DISABLE)`，数据从 GM 直通到 UB，不经过 L2。

---

## 二、写模式

### 1. Normal 模式

**行为**：写入 L2 Cache，后续相同地址的读可以命中。

**替换策略对比**：

| 策略 | 英文描述 | 中文描述 | 替换优先级 |
|------|---------|---------|-----------|
| **First Victim** | write back local modified, high priority for replacement | 写入 L2 本地缓存，标记为 modified，具有**最高**被替换优先级 | 高（优先被逐出） |
| **Last Victim** | write back local modified, low priority for replacement | 写入 L2 本地缓存，标记为 modified，具有**最低**被替换优先级 | 低（尽量保留） |
| **Persistent** | write back local modified, only replaced by persistent | 写入 L2 本地缓存，标记为 modified，**只能被 Persistent 替换** | 最低（仅 Persistent 可替换） |

**伪代码**：

```
// 写 Normal 模式通用流程
write_normal_with_policy(address, data, policy):
    cacheline = l2_cache.lookup(address)
    if cacheline != MISS:
        cacheline.data = data                    // 命中：更新数据
        cacheline.state = MODIFIED               // 标记为已修改（脏）
    else:
        victim = select_victim(policy)            // 根据策略选择被替换的缓存行
        // select_victim 逻辑与读模式相同
        l2_cache.replace(victim, address, data)
        l2_cache.set_state(victim, MODIFIED)
    // 注意：写回 GM 的时机由硬件写回策略决定（write-back）
```

**使用场景**：

| 策略 | 适用场景 | 示例 |
|------|---------|------|
| **First Victim** | 写出的数据可能被后续读回，但不关键 | 算子中间输出 |
| **Last Victim** | 写出的数据会被后续算子频繁读取 | 前序算子的输出作为后序算子的输入 |
| **Persistent** | 写出的关键数据必须常驻 L2 | 频繁被下游消费的计算结果 |

---

### 2. Not-alloc 模式（clean-invalid）

**行为**：**不分配新 Cache Line**。若地址恰好已在 L2 中有缓存行，则清理并使该缓存行失效，同时合并写入数据。

| 子模式 | 英文描述 | 中文描述 |
|--------|---------|---------|
| **clean-invalid** | non-allocate, clean and invalidate cacheline merged with wdata if allocated | 不分配新缓存行；若地址已有缓存行，则清理、失效并将写入数据合并进去 |

**伪代码**：

```
// 写 Not-alloc (clean-invalid) 模式
write_not_alloc_clean_invalid(address, data):
    cacheline = l2_cache.lookup(address)
    if cacheline != MISS:
        // 地址恰好已缓存：清理 + 失效 + 合并写数据
        cacheline.data = merge(cacheline.data, data)   // 合并写入数据
        cacheline.state = INVALID                       // 标记失效
        // 后续对该地址的读将 MISS，不会命中这个被失效的行
    // 无论如何，直接写 GM
    gm.write(address, data)
    // 不分配新 Cache Line
```

**使用场景**：

- **流式写出**：数据只写一次，不会被读回，无需占用 L2
- **大块数据写出**：如算子输出结果，后续算子读取的是不同区域
- **避免写污染**：不希望写操作占据 L2 空间影响其他缓存数据

> **Ascend C 中对应**：对写出的 `GlobalTensor` 调用 `SetL2CacheHint(CACHE_MODE_DISABLE)`。

---

## 三、总结对比

| 模式 | 读/写 | 是否分配 Cache Line | L2 命中受益 | 适用数据类型 | 关键场景 |
|------|------|--------------------|------------|-------------|---------|
| Normal + Last Victim | 读 | 是 | 高 | 复用数据（小工作集） | 权重、高频访问缓冲区 |
| Normal + First Victim | 读 | 是 | 中 | 可能复用数据 | 中间结果 |
| Normal + Persistent | 读/写 | 是 | 最高 | 关键常驻数据 | 不能被逐出的关键数据 |
| Normal (写) + Last Victim | 写 | 是 | 高（后续读） | 会被下游算子读取的输出 | 算子间数据传递 |
| **Not-alloc** | 读 | **否** | **无** | **流式数据（只读/写一次）** | **Add 输入、逐元素运算** |
| **Not-alloc** | 写 | **否** | **无** | **流式写出** | **算子一次性输出** |

> **核心原则**：复用数据用 Normal 模式并控制工作集 < L2 容量；流式数据（只访问一次）用 Not-alloc 模式避免无效的缓存管理开销和污染。
