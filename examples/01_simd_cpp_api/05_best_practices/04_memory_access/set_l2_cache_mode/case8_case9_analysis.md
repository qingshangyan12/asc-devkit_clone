## 三、关键发现：Repeat L2 命中率被 Add 的 L2 写入干扰

| 对比 | Repeat L2 命中率 |
|------|------------------|
| Case 1 (48核独立 Repeat) | **75.0%** |
| Case 9 (双流并行，Add bypass) | **75.0%** |
| Case 8 (双流并行，Add L2开) | **72.7%** |

Case 9 的 Repeat 命中率恢复到与独立 Case 1 完全一致的 75.0%，而 Case 8 下降了 2.3 个百分点。这是本样例中第一次观察到**跨 kernel 的 L2 带宽竞争**。

### 根因分析

Add kernel 的 L2 访问量对比：

| Add L2 指标 | Case 8 (L2开) | Case 9 (L2 bypass) |
|-------------|--------------|-------------------|
| 总读访问 | ~2.10M/核 | ~240/核 |
| write_cache_miss | 262,144/核 | 262,144/核 |

- **Case 8**：Add 的 x/y 读产生 ~2.1M read miss + 262K write miss（每核），全部走 L2 控制器
- **Case 9**：x/y bypass 后读访问几乎消失，仅输出 z 的 writeback 涉及 L2

在双流并行下，Case 8 的 Add 和 Repeat 同时竞争 L2 控制器端口/Bank 带宽：
- Add 的大量 read miss 占用 L2 读端口
- Repeat 的部分命中的读请求因时序竞争被延迟或计为 miss
- 命中率从 75.0% → 72.7%

Case 9 bypass 后，Add 的 x/y 读不再经过 L2，L2 控制器带宽完全释放给 Repeat，命中率恢复至 75.0%。

## 四、Add Kernel 自身的 Bypass 收益

| 指标 | Case 4 (48核独立) | Case 8 (24核, L2开) | Case 9 (24核, L2 bypass) |
|------|-------------------|---------------------|--------------------------|
| Duration | 304.7 μs | 403.5 μs | 281.4 μs |
| aiv_cycles | 16.19M | 17.24M | 11.20M |

- Case 4→5（独立 48 核）：cycles 降幅 **-25.6%**
- Case 8→9（双流 24 核）：cycles 降幅 **-35.0%**

双流场景下的 bypass 收益比独立场景更显著（-35% vs -26%）。原因是 24 核场景下每核处理数据量翻倍（512 行 vs 256 行），L2 写入开销的占比更大，bypass 省的更多。

---

## 五、Repeat Kernel 的间接受益

Repeat 不仅 L2 命中率恢复（72.7%→75.0%），cycles 也下降了 7.6%（25.77M→23.82M）。这部分收益来自：
1. L2 命中率提升 2.3pp，减少 GM 回读
2. L2 控制器不再被 Add 的 2.1M read miss 抢占，Repeat 的缓存访问延迟更低

---

## 六、Add Bypass 后为何仍有少量 L2 访问

Case 9 中 Add kernel 仅对 x、y 设置了 `SetL2CacheHint(CACHE_MODE_DISABLE)`，输出 z 未经 bypass。每次写回 z 时，硬件可能产生少量 L2 操作（如 cache line 的 read-for-ownership 或写分配时的 tag 查询）。

实际残留访问仅 **240 次**（vs Case 8 的 ~2.1M 次），占比 **0.01%**，属于硬件内部元数据/控制流量，不影响性能分析结论。

## 七、与 Case 6/7（融合算子）的对比

| 维度 | Case 6→7 (融合串行) | Case 8→9 (双流并行) |
|------|---------------------|---------------------|
| Add/Repeat 执行顺序 | 同一 kernel 内顺序 | 不同 stream 并行 |
| Repeat L2 命中率变化 | 无变化（均为 75%） | **72.7%→75.0%（+2.3pp）** |
| L2 竞争 | 无（时间错开） | **有（同时访问）** |
| 总 wall time 改善 | -5.2% | -4.7% |
| 核数利用 | 48核共享 | 24核+24核独立 |

融合算子（Case 6/7）中 Add 和 Repeat 在时间上完全错开，L2 替换策略自然隔离两者，未触发竞争。

双流并行（Case 8/9）中两者同时运行，首次观察到 **L2 带宽竞争的真实效应**。但降幅仅 2.3pp，说明 Add 流式数据对 Repeat 缓存内容的破坏有限——Set-Associative 结构 + 流式访问的替换策略自发隔离了大部分地址冲突。

---

## 八、结论

1. **L2 带宽竞争被验证**：双流并行下，Add L2 开启会导致 Repeat 命中率下降 2.3pp；Add bypass 后命中率恢复至独立 Case 1 水平（75.0%）
2. **Bypass 收益在双流场景更显著**：Add cycles 降 35%，大于独立场景的 26%
3. **Repeat 间接受益**：L2 带宽释放后 cycles 降低 7.6%
4. **融合算子未触发竞争**：Case 6/7 的串行执行在时间上隔离了两阶段数据，与本 Case 形成对照
5. **命中率降幅小的原因**：Add 的流式数据一次性访问，不会长时间驻留在 L2 中与 Repeat 数据产生严重的 Set 冲突。同时活跃的数据总量有限，Set-Associative 结构吸收了大部分地址冲突
